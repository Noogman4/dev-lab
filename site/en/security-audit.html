Scope and method

The review followed a staged process: diff inspection, candidate extraction, focused security validation, and false-positive filtering. The audit focused on subprocess usage, file/path handling, privilege boundaries, configuration flow, service logic, and API-connected components.

  • Command execution and subprocess safety
  • Path handling and traversal-related risks
  • Privilege escalation via sudo-using workflows
  • Security-sensitive service and controller logic
  • AI-connected file and prompt handling

Reviewed candidate classes

The German full report lists candidate classes in detail. For the English web mirror, the outcome is summarized: reviewed candidates did not cross the threshold for a confirmed exploit path in the audited scope.

  • Git subprocess passthrough patterns
  • WireGuard endpoint handling in firewall workflows
  • Firewall rule forms with intentionally broad options
  • Predictable temporary-path handling in AV-related logic
  • Image/file path use in AI-connected helper functions

Issues already fixed during the audit period

  • Mountpoint path validation hardening in HDD-related workflows
  • Removal of risky current-working-directory fallback in Linux help import flow
  • PID lock handling fix for EPERM-related false stale-lock behavior
  • DNS token validation edge-case fix
  • Startup Guard baseline visibility fix for newly introduced files

Hardening recommendations

  • Add a stricter subcommand allowlist if LLM output ever reaches command execution paths.
  • Validate WireGuard endpoint host values more aggressively before embedding them in UFW-related workflows.
  • Optionally narrow AI image helper inputs to known file classes and expected directories.
  • Further harden temporary-directory handling against symlink-based local misuse.

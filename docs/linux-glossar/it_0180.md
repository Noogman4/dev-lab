# JavaScript

## 1. Kurzbeschreibung

JavaScript ist eine Programmiersprache, die häufig im Browser und auch in anderen Laufzeitumgebungen eingesetzt wird. Sie kann Daten verarbeiten und auf bereitgestellte Ereignisse reagieren. Die Sprache allein enthält jedoch nicht automatisch jede Browser-, Datei- oder Netzwerkschnittstelle. Welche Fähigkeiten vorhanden sind, hängt zusätzlich von der Umgebung ab.

## 2. Was bedeutet der Begriff?

Der Sprachkern wird als ECMAScript standardisiert. Die [ECMAScript-Spezifikation](https://tc39.es/ecma262/) beschreibt unter anderem Werte, Ausdrücke, Funktionen und eingebaute Objekte. JavaScript ist nicht mit Java gleichzusetzen; der ähnliche Name bedeutet keine allgemeine Austauschbarkeit des Codes.

Das Katalogbeispiel einer Reaktion auf einen Klick ist im Browserkontext passend. Die [DOM-Spezifikation zu Ereignissen](https://dom.spec.whatwg.org/#introduction-to-dom-events) beschreibt das Registrieren von Reaktionen auf Ereignisse. Solche Dokument- und Ereignisschnittstellen ergänzen den Sprachkern. Ein reines Sprachbeispiel beweist deshalb noch keine funktionierende Browseroberfläche.

## 3. Einfacher Vergleich aus dem Alltag

Eine Arbeitssprache kann in unterschiedlichen Werkstätten verwendet werden. Die Anweisungen folgen derselben Grundsprache, aber die verfügbaren Maschinen und Aufgaben unterscheiden sich. Nicht jede Werkstatt besitzt automatisch einen Bildschirmknopf oder einen Dateizugriff.

Die Grenze: Laufzeitumgebungen stellen konkrete Programmierschnittstellen bereit und verstehen keine freien Wünsche. Selbst gültige Syntax kann scheitern, wenn ein benötigtes Objekt in der gewählten Umgebung fehlt. Sprache, Umgebung und Anwendungsaufbau müssen daher getrennt betrachtet werden.

## 4. Wie funktioniert das?

Ein Programm verwendet Werte, Variablen, Funktionen und Kontrollstrukturen. Die Laufzeit verarbeitet den Code nach den geltenden Sprachregeln. Eingebaute Objekte bieten zusätzliche Operationen. Beispielsweise beschreibt [Array.prototype.map](https://tc39.es/ecma262/#sec-array.prototype.map), wie eine Funktion auf vorhandene Arrayelemente angewendet und daraus ein neues Array gebildet wird.

Ein Callback ist dabei eine übergebene Funktion. Er kann selbst Nebenwirkungen besitzen; aus der Wahl von `map` folgt keine allgemeine Garantie unveränderter Eingaben. Das unten verwendete Beispiel multipliziert nur Zahlen und prüft die Ausgangswerte ausdrücklich.

Ereignisverarbeitung und asynchrone APIs benötigen außerdem den jeweiligen Umgebungskontext. Ein Browserklick, ein Timer und ein gewöhnlicher direkter Funktionsaufruf sind nicht allein deshalb identische Abläufe, weil überall JavaScript beteiligt ist.

## 5. Wo begegnet mir das unter Linux?

Browser unter Linux können JavaScript für Webanwendungen ausführen. Node.js stellt eine andere Laufzeit mit eigenen Schnittstellen bereit. Die [Node.js-Dokumentation zu globalen Objekten](https://nodejs.org/api/globals.html) erläutert solche Umgebungsangebote.

Hier ist Node.js 24.22.1 bereits vorhanden. Das folgende Beispiel verwendet nur Sprachoperationen und das eingebaute Assertionsmodul. Es installiert kein Paket und greift weder auf Browserdokumente noch auf Dateien oder Netzwerkdienste zu. Die online dokumentierte Node-Version und die tatsächlich ausgeführte Version sind dabei zu unterscheiden.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses vollständige JavaScript-Beispiel wurde mit Node.js 24.22.1 in einem temporären Ordner ausgeführt. Alle Eingaben sind selbst gewählt.

```javascript
const assert = require("node:assert/strict");

const eingabe = [2, 0, -1];
const doppelt = eingabe.map((wert) => wert * 2);
assert.deepEqual(doppelt, [4, 0, -2]);
assert.deepEqual(eingabe, [2, 0, -1]);
assert.notStrictEqual(doppelt, eingabe);

function beschreibe(wert) {
  return wert > 0 ? "positiv" : "nicht positiv";
}

assert.equal(beschreibe(0), "nicht positiv");
assert.equal(beschreibe(2), "positiv");
console.log(doppelt.join(", "));
console.log(beschreibe(0));
```

Geprüfte Ausgabe:

```text
4, 0, -2
nicht positiv
```

Die Assertions prüfen Ergebnis, unveränderte Ausgangswerte und ein eigenständiges Ergebnisarray. Die Funktion behandelt die Null ausdrücklich nicht als positive Zahl. Das ist ein Sprach- und Laufzeitversuch. Ein Klickhandler, eine DOM-Veränderung oder eine Netzverbindung wurde nicht ausgeführt.

## 7. Abgrenzung zu ähnlichen Begriffen

HTML beschreibt Dokumentstruktur, CSS Darstellung. JavaScript kann programmatisches Verhalten ergänzen. JSON ist ein Datenformat und kein beliebiges auszuführendes JavaScript-Programm. Eine API stellt bestimmte Funktionen bereit; sie kann zum Sprachkern oder zu einer Umgebung gehören.

## 8. Häufige Missverständnisse

JavaScript läuft nicht ausschließlich im Browser. Ein Node-Beispiel beweist umgekehrt keine identischen Browserfunktionen. Eine vorhandene Variable bedeutet auch nicht automatisch einen passenden Datentyp für jede Operation. Schließlich ist ein korrektes Rechenergebnis kein allgemeiner Nachweis einer sicheren Anwendung.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Nenne Laufzeit und Version bei reproduzierbaren Beispielen. Prüfe Eingaben und die tatsächlich verfügbaren APIs. Dieser Versuch verwendet nur eigene Werte und eingebaute Module; Browser, Anwendung, Abhängigkeiten und Netzwerk bleiben unverändert.

## 10. Verwandte Begriffe

[HTML](it_0178.md) und [CSS](it_0179.md) erfüllen andere Webaufgaben. Eine [Funktion](it_0017.md) beschreibt Verhalten. Ein [Callback](it_0078.md) wird übergeben. [JSON](it_0175.md) ist eine Datenrepräsentation. Die [Runtime](it_0031.md) stellt den Ausführungskontext bereit.

# chmod

## 1. Kurzbeschreibung

`chmod` ändert die klassischen Modusbits einer Datei oder eines Verzeichnisses. Damit lassen sich beispielsweise Lese-, Schreib- oder Ausführungsrechte anpassen. Der Befehl verändert nicht automatisch den Eigentümer und macht aus ungeeignetem Inhalt kein funktionierendes Programm. Wichtig ist, welche Einträge und Benutzerklassen tatsächlich gemeint sind.

## 2. Was bedeutet der Begriff?

Der Name steht für „change mode“, also Modus ändern. Die [offizielle GNU-Beschreibung von chmod](https://www.gnu.org/software/coreutils/manual/html_node/chmod-invocation.html) erläutert Syntax und Wirkung. Ändern darf die Rechte normalerweise der Eigentümer oder ein Prozess mit entsprechenden besonderen Berechtigungen. Für eigene Dateien wird deshalb nicht automatisch `sudo` benötigt.

Es gibt zwei verbreitete Schreibweisen: Eine numerische Angabe beschreibt einen Modus, während eine symbolische Angabe ausgewählte Änderungen ausdrückt. Für den Einstieg ist eine gezielte Änderung wie `u+x` oft leichter nachzuvollziehen als eine pauschale Freigabe aller Rechte. Welche Wirkung passend ist, hängt vom Zweck der Datei ab.

## 3. Einfacher Vergleich aus dem Alltag

An einer Zugangsliste ergänzt du für eine bestimmte Person eine einzelne Erlaubnis. Alternativ könntest du die gesamte Liste durch eine neue Fassung ersetzen. Beide Arbeitsweisen verändern Regeln, aber nicht unbedingt dieselben Teile.

Das entspricht dem Unterschied zwischen einer gezielten symbolischen Änderung und einem vollständiger beschriebenen Modus. Die Grenze: Dateirechte sind technisch definierte Bits für Benutzerklassen, keine individuell formulierten Verträge. Außerdem können weitere Sicherheitsregeln beeinflussen, ob ein Zugriff tatsächlich gelingt. Eine neue Erlaubnis beseitigt nicht jeden anderen Hinderungsgrund.

## 4. Wie funktioniert das?

Die [GNU-Dokumentation symbolischer Modi](https://www.gnu.org/software/coreutils/manual/html_node/Symbolic-Modes.html) beschreibt das Muster aus Benutzerklasse, Operator und Rechten. `u` bezeichnet den Eigentümer, `g` die Gruppe und `o` andere Benutzer. `+` ergänzt, `-` entfernt und `=` setzt die genannten Rechte für die ausgewählte Klasse.

`u+x` ergänzt also das Ausführungsbit des Eigentümers. Das Quellbeispiel `chmod +x start.sh` lässt die Benutzerklasse weg; dabei können Regeln der aktuellen `umask` die betroffenen Klassen beeinflussen. Wenn eine konkrete Klasse gemeint ist, macht ihre ausdrückliche Angabe die Absicht klarer. Verzeichnisse haben bei `x` eine Such- beziehungsweise Zugriffssemantik statt der Ausführung eines Programminhalts.

## 5. Wo begegnet mir das unter Linux?

Du triffst `chmod` etwa bei einem eigenen Skript, das direkt gestartet werden soll, oder beim Begrenzen des Zugriffs auf eigene Daten. Ein fehlendes Ausführungsbit ist aber nicht die einzige mögliche Ursache eines Startfehlers. Auch Interpreter, Inhalt und Einbindung des Dateisystems können relevant sein.

`chmod` ist nicht auf Linux beschränkt; hier wird die GNU-Ausführung unter Linux betrachtet. Das Verhalten bei symbolischen Links und rekursiven Verzeichnisdurchläufen muss zur konkreten Option passen, wie die Befehlsreferenz erläutert. Der folgende Versuch verwendet weder Links noch rekursive Aufrufe.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Der vorhandene lokale `chmod`-Befehl ändert nur eine selbst angelegte Datei. Deren Inhalt wird nicht als Programm gestartet.

```python
from pathlib import Path
import stat
import subprocess
import tempfile

with tempfile.TemporaryDirectory() as ordner:
    datei = Path(ordner) / "probe.sh"
    datei.write_text("# Eigene Testdatei, nicht ausführen\n", encoding="utf-8")
    datei.chmod(0o640)
    subprocess.run(["/usr/bin/chmod", "u+x", str(datei)], check=True)
    danach = stat.S_IMODE(datei.stat().st_mode)
    assert danach == 0o740
    subprocess.run(["/usr/bin/chmod", "u-x", str(datei)], check=True)
    wieder = stat.S_IMODE(datei.stat().st_mode)
    assert wieder == 0o640
    print(f"{danach:03o}")
    print(f"{wieder:03o}")
```

Geprüfte Ausgabe:

```text
740
640
```

Ausgehend von `640` ergänzt `u+x` ausschließlich das Eigentümer-Ausführungsbit. `u-x` entfernt es wieder. Die Assertions prüfen beide tatsächlich gespeicherten Zustände. Das beweist die Modusänderung an dieser Datei, keinen erfolgreichen Skriptstart und keinen Zugriff unter einer anderen Benutzeridentität.

## 7. Abgrenzung zu ähnlichen Begriffen

Dateieigentümerschaft bestimmt, wem ein Eintrag zugeordnet ist. `chmod` verändert dagegen seine Modusbits. Ein Interpreter kann außerdem ein lesbares Skript als Eingabe verarbeiten, ohne dass dies derselbe Vorgang wie ein direkter Start des Skriptpfads ist. Rechte und Programmbedeutung sind getrennte Fragen.

## 8. Häufige Missverständnisse

`chmod` repariert keine beliebigen Programmfehler. Eine pauschale Rechtefreigabe ist kein Ersatz für Diagnose. Auch ein erfolgreich gesetztes Bit garantiert weder einen vorhandenen Interpreter noch die Unterstützung durch jede Umgebung. Bei Verzeichnissen muss die andere Bedeutung der Bits berücksichtigt werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Ändere gezielt die benötigte Benutzerklasse und kontrolliere das Ergebnis. Verwende keine weitreichenden rekursiven Aufrufe, wenn nur eine einzelne eigene Datei gemeint ist. Der Test bleibt vollständig innerhalb des temporären Ordners und verändert keine vorhandenen System- oder Projektdateirechte.

## 10. Verwandte Begriffe

[Dateirechte](it_0112.md) erklären die einzelnen Bits. [Root](it_0111.md) betrifft besondere Benutzerrechte. Die [Shell](it_0107.md) verarbeitet den eingegebenen Aufruf; die Modusänderung übernimmt anschließend das gestartete Programm.

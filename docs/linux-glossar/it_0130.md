# Pipe

## 1. Kurzbeschreibung

Eine Pipe ist ein Kanal, über den Daten von einer schreibenden zu einer lesenden Seite gelangen. Unter Linux verbindet sie häufig die Ausgabe eines Programms mit der Eingabe eines anderen. Der Datenstrom muss dabei nicht erst vollständig als gewöhnliche Datei gespeichert werden. Eine Pipe allein legt allerdings nicht fest, was ihre Daten fachlich bedeuten.

## 2. Was bedeutet der Begriff?

„Pipe“ bedeutet Rohr. Die [Linux-Übersicht zu Pipes](https://man7.org/linux/man-pages/man7/pipe.7.html) beschreibt einen unidirektionalen Kommunikationskanal mit Lese- und Schreibende. Im üblichen Modell fließen Daten in eine Richtung.

In einer Shell steht `|` für den Aufbau einer Pipeline. Das Katalogbeispiel `ls | grep py` verbindet die normale Ausgabe des ersten Befehls mit der normalen Eingabe des zweiten. `grep` verarbeitet dabei die übergebenen Textdaten; die Pipe versteht weder Dateinamen noch die Bedeutung von „Python-Datei“. Eine solche fachliche Auswahl muss durch die beteiligten Programme passend definiert werden.

## 3. Einfacher Vergleich aus dem Alltag

An einer Arbeitslinie gibt die erste Station Material direkt an die nächste weiter. Diese kann schon mit empfangenem Material arbeiten, während weiteres nachkommt. Sie braucht dafür nicht zwingend erst einen vollständig gefüllten Zwischenlagerraum.

Das erklärt die Weitergabe zwischen Verarbeitungsschritten. Die Grenze: Eine Pipe transportiert Bytes und besitzt nur einen begrenzten Puffer. Wenn die nächste Station nicht liest, kann die schreibende Seite warten müssen. Sie ist außerdem keine unbegrenzte Aufzeichnung, aus der später beliebig viele Leser denselben alten Inhalt erneut abrufen können.

## 4. Wie funktioniert das?

Die beteiligten Programme erhalten passende Dateideskriptoren für Lesen und Schreiben. Die Shell kann diese mit Standardeingabe und Standardausgabe verbinden. Die Regeln dafür gehören zur [POSIX-Shell-Befehlssprache](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html). Die Standardfehlerausgabe wird durch eine gewöhnliche solche Verbindung nicht automatisch ebenfalls weitergeleitet.

Pipes liefern einen Bytestrom ohne garantierte Anwendungsnachrichtengrenzen. Das Ende wird beim Lesen sichtbar, wenn keine schreibende Referenz mehr offen ist und verbleibende Daten verbraucht sind. Unnötig offen gehaltene Enden können deshalb verhindern, dass ein Programm das erwartete Ende erkennt. Die Linux-Übersicht erklärt diese Lebensdauerregeln.

## 5. Wo begegnet mir das unter Linux?

Pipelines sind in der Shell für hintereinander geschaltete Auswertungen verbreitet. Auch Programme können sie direkt aufbauen, ohne einen Shell-Befehlsstring auszuwerten. Python zeigt dafür ein Beispiel im Abschnitt [Shell-Pipelines mit subprocess ersetzen](https://docs.python.org/3.13/library/subprocess.html#replacing-shell-pipeline).

Eine benannte Pipe, auch FIFO genannt, besitzt zusätzlich einen Namen im Dateisystem. Das ist von einer gewöhnlichen Datei und einer unbenannten Pipe zu unterscheiden. In diesem Eintrag wird keine FIFO eingerichtet. Der praktische Versuch verwendet nur die von Python angelegten unbenannten Kanäle für eigene Kindprozesse.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Zwei kurze eigene Programme geben ausschließlich die selbst gewählte Meldung weiter und wandeln sie um. Es werden keine Verzeichnisse aufgelistet und keine fremden Dateien gelesen.

```python
import subprocess
import sys

with subprocess.Popen(
    [sys.executable, "-c", "print('Probe')"],
    stdout=subprocess.PIPE,
    text=True,
) as erzeuger:
    with subprocess.Popen(
        [sys.executable, "-c", "import sys; print(sys.stdin.read().upper(), end='')"],
        stdin=erzeuger.stdout,
        stdout=subprocess.PIPE,
        stderr=subprocess.PIPE,
        text=True,
    ) as verarbeiter:
        erzeuger.stdout.close()
        ausgabe, fehler = verarbeiter.communicate(timeout=5)
        assert verarbeiter.returncode == 0
        assert erzeuger.wait(timeout=5) == 0
        assert fehler == ""
        assert ausgabe == "PROBE\n"
        print(ausgabe, end="")
```

Geprüfte Ausgabe:

```text
PROBE
```

Der Verarbeiter liest die Eingabe bis zum Ende und schreibt Großbuchstaben. Die Elternreferenz am ersten Ausgabeende wird nach dem Aufbau geschlossen. Beide eigenen Prozesse enden erfolgreich. Das Beispiel prüft diese kleine Pipeline, nicht das Verhalten bei großen Datenmengen oder vorzeitig abbrechenden Gegenstellen.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Umleitung in eine gewöhnliche Datei speichert einen Inhalt an einem Dateipfad. Eine Pipe verbindet Kommunikationsenden. Ein Socket kann je nach Typ andere Kommunikationsmodelle und bidirektionalen Austausch unterstützen. Ein Funktionsaufruf übergibt dagegen Werte innerhalb eines Programmablaufs und ist kein automatisch eigener Prozesskanal.

## 8. Häufige Missverständnisse

`|` bedeutet nicht allgemein, dass jedes Ergebnis aller beteiligten Programme erfolgreich ist. Ein normaler Pipeline-Ausgangsstatus hängt zudem von Shell und Einstellungen ab. Auch garantiert ein einzelner Schreibvorgang nicht, dass die lesende Anwendung genau einen gleich großen Datenblock erhält.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Kläre Datenformat und Fehlerkanäle der beteiligten Programme. Schließe nicht benötigte Enden und plane Warte- beziehungsweise Fehlerfälle. Der Versuch verwendet nur kleine eigene Daten und verändert keine Dienste, Benutzerdateien oder Systemkonfigurationen.

## 10. Verwandte Begriffe

Die [Shell](it_0107.md) kann Pipelines aufbauen. [subprocess](it_0101.md) ermöglicht entsprechende Verbindungen aus Python. Ein [Prozess](it_0115.md) kann einen Verarbeitungsschritt ausführen. Ein [Socket](it_0129.md) bietet ein anderes Kommunikationsmodell.

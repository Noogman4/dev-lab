# Preinst

## 1. Kurzbeschreibung

`preinst` ist ein optionales Debian-Paketbetreuerskript. Das Paketwerkzeug kann es aufrufen, bevor es die neuen Dateien des Pakets entpackt. Dadurch kann das Paket bestimmte Voraussetzungen prüfen oder gezielte Vorbereitungen für ein Upgrade treffen.

## 2. Was bedeutet der Begriff?

„Vor der Installation“ bezeichnet hier eine konkrete Stelle innerhalb des Paketablaufs. Das [Debian Policy Manual zu Paketbetreuerskripten](https://www.debian.org/doc/debian-policy/ch-maintainerscripts.html) beschreibt Aufrufe für Erstinstallation, Upgrade und Wiederherstellung. Die Argumente geben Auskunft darüber, in welchem Fall das Skript läuft.

## 3. Einfacher Vergleich aus dem Alltag

Bevor ein neuer Boden verlegt wird, prüft ein Handwerker den Untergrund. Er kann seine Arbeit nur mit Dingen durchführen, die bereits im Raum vorhanden sind. Entsprechend kann das neue `preinst` aufgerufen werden, bevor die übrigen Dateien seiner neuen Paketversion verfügbar sind.

## 4. Wie funktioniert das?

Laut [dpkg-Handbuch](https://manpages.debian.org/stable/dpkg/dpkg.1.en.html) liegt der Aufruf des neuen Preinst vor dem Entpacken neuer Dateien. Bei einem Upgrade können Dateien oder Zustände der bisherigen Version vorhanden sein. Bei einer Erstinstallation fehlen sie möglicherweise ganz.

Die Debian-Regeln unterscheiden normale Abhängigkeiten und speziell deklarierte Vorabhängigkeiten. Ein Skript darf daher nicht einfach voraussetzen, dass jede gewöhnliche Abhängigkeit zu diesem Zeitpunkt in ihrem endgültigen Zustand vorliegt. Außerdem muss sein Rückgabestatus verständlich machen, ob das Paketwerkzeug fortfahren kann.

## 5. Wo begegnet mir das unter Linux?

In Debian-Paketen kann ein solches Skript beispielsweise feststellen, ob eine Änderung mit vorhandenen paketverwalteten Dateien vereinbar ist. Die genaue Aufgabe steht im konkreten Paket. Ein Paket braucht nicht für jede Vorbereitung ein eigenes Skript.

## 6. Konkretes Beispiel Schritt für Schritt

Gedankenbeispiel ohne Ausführung. Eine erfundene Notizanwendung soll bei einer Aktualisierung ihren eigenen Datenpfad anders verwenden.

1. Eine neue Version würde aus dem Aufruf erkennen, ob es sich um ein Upgrade handelt.
2. Das Skript würde prüfen, welchen Zustand der paketbezogene Pfad hat und ob der geplante Wechsel damit vereinbar ist.
3. Ein unklarer Zustand würde früh gemeldet. Ein Fehlerstatus würde vermeiden, dass der Vorgang einfach wie geplant weiterläuft.
4. Da das neue Programm noch nicht bereitsteht, würde das Beispiel weder einen Start der neuen Version noch einen erfolgreichen Abschluss annehmen.

## 7. Abgrenzung zu ähnlichen Begriffen

[Postinst](it_0279.md) kann später bei der Konfiguration laufen. `preinst` arbeitet mit dem Zustand vor dem Entpacken der neuen Dateien. Die Wahl der Phase bestimmt, mit welchen Dateien und Paketabhängigkeiten das Skript rechnen darf.

## 8. Häufige Missverständnisse

„Pre“ bedeutet keinen uneingeschränkten Zugriff auf die zukünftige Installation. Eine neu mitgelieferte Bibliothek kann noch fehlen. Dieselbe Paketversion kann abhängig vom bisherigen Zustand mit unterschiedlichen Argumenten aufgerufen werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Bei einem Fehler helfen Phase, Argumente und die konkrete Meldung. Ein allgemeiner Installationsneustart erklärt die Ursache nicht. Paketbetreuerskripte können weitreichende Rechte besitzen und sollten ihre Operationen eng auf paketbezogene Zustände begrenzen.

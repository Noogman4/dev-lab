# Hostname

## 1. Kurzbeschreibung

Ein Hostname ist eine Bezeichnung für einen Rechner beziehungsweise Host in einem bestimmten Namenszusammenhang. Er kann Menschen die Arbeit mit Adressen erleichtern. Ein lokaler Rechnername, ein vollständiger DNS-Name und eine IP-Adresse sind jedoch unterschiedliche Angaben. Ein eingestellter Name wird nicht allein dadurch überall auflösbar oder eindeutig.

## 2. Was bedeutet der Begriff?

„Host“ bezeichnet hier ein beteiligtes System, „name“ dessen Bezeichnung. Die [Linux-Handbuchseite zu Hostnamen](https://man7.org/linux/man-pages/man7/hostname.7.html) beschreibt hierarchische Namen und deren Auflösung. Ein vollständiger Name kann mehrere durch Punkte getrennte Bestandteile besitzen.

Das Katalogbeispiel `laptop-sven` ist eine mögliche kurze Bezeichnung, keine Abfrage eines realen Rechners. Ob dieser Name in einer konkreten Umgebung aufgelöst wird und welche Adresse dabei herauskommt, hängt von Einrichtung und Auflösungsweg ab. Die Schreibweise allein veröffentlicht keinen passenden DNS-Eintrag.

## 3. Einfacher Vergleich aus dem Alltag

Eine Person kann im kleinen Team unter einem kurzen Namen bekannt sein. Außerhalb des Teams reicht diese Bezeichnung möglicherweise nicht aus; dort werden weitere Angaben benötigt. Auch können mehrere Teams denselben Kurznamen verwenden.

Das erklärt den Gültigkeitsbereich. Die Grenze: Hostnamen folgen technischen Regeln und werden durch bestimmte Auflösungsverfahren verarbeitet. Ein Name ist kein verlässlicher persönlicher Identitätsnachweis. Er kann geändert werden oder auf mehrere Adressen führen, ohne dass daraus allein die Zahl physischer Geräte feststeht.

## 4. Wie funktioniert das?

Eine Anwendung kann einen Namen an eine Auflösungsschnittstelle übergeben. Unter Linux können dabei verschiedene Namensquellen beteiligt sein. Die Hostnamen-Handbuchseite erläutert die Einbindung über die glibc-Namensauflösung. Eine erfolgreiche Auflösung muss deshalb nicht immer aus einer neuen entfernten DNS-Anfrage stammen.

Für gewöhnliche Internet-Hostnamen gelten Regeln zur Labelschreibweise. [RFC 1123](https://www.rfc-editor.org/rfc/rfc1123.html) ergänzt insbesondere die Zulässigkeit einer Ziffer am Anfang. Daraus darf aber nicht abgeleitet werden, dass beliebiger Text eine geeignete Hostbezeichnung ist. Andere DNS-Namen für spezielle Diensteinträge besitzen wiederum eigene Konventionen.

Ein vollständiger Name kann in bestimmten Darstellungen mit einem abschließenden Punkt ausdrücklich absolut geschrieben werden. Kurze Namen können dagegen abhängig von Suchregeln unterschiedlich behandelt werden. Diese Regeln sind Teil der Umgebung, nicht allein eine Eigenschaft des Textes.

## 5. Wo begegnet mir das unter Linux?

Namen erscheinen in Netzwerkprogrammen, Anzeigen und Protokollen. Ein Programm kann den lokal eingestellten Rechnernamen anzeigen, während ein anderer Name für einen bestimmten Dienst verwendet wird. Diese Angaben müssen nicht identisch sein.

Für lokale Namensräume beschreibt [RFC 6762](https://www.rfc-editor.org/rfc/rfc6762.html) Multicast DNS und die besondere Verwendung von `.local.`. Ein solcher Name darf nicht pauschal als weltweit über öffentliche DNS-Server auflösbar verstanden werden. Welche Verfahren ein System tatsächlich einsetzt, wird hier nicht abgefragt.

## 6. Konkretes Beispiel Schritt für Schritt

Die Tabelle enthält ausschließlich erfundene Bezeichnungen. Sie ist keine Ausgabe einer Namensabfrage.

| Angabe | Einordnung |
| --- | --- |
| laptop-sven | Möglicher kurzer Hostname |
| hilfe.beispiel.invalid. | Vollständig dargestellter Beispielname |
| 192.0.2.20 | Numerische IPv4-Adresse |
| https://hilfe.beispiel.invalid/status | Webadresse mit Schema und Pfad |

Die letzte Zeile ist nicht als ganze Zeichenkette ein Hostname. Für eine Verbindung müssten Zielname, Schema und weitere Bestandteile passend verarbeitet werden. Auch aus der zweiten Zeile folgt keine reale Erreichbarkeit; der Name ist ausdrücklich fiktiv.

Ein tatsächlicher Test müsste festhalten, über welchen Auflösungsweg und in welchem Kontext er erfolgt. Der Text liest weder den lokalen Rechnernamen noch Systemdateien und sendet keine DNS- oder mDNS-Anfrage. Es wird kein Name gesetzt oder geändert.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Domainname bezeichnet eine Position im hierarchischen Namensraum; nicht jede Verwendung bezeichnet unmittelbar einen einzelnen Host. Eine IP-Adresse ist ein Adresswert. Eine URL kann einen Hostnamen als Teil enthalten. Ein Anzeigename einer Oberfläche ist nochmals eine andere Bezeichnung.

## 8. Häufige Missverständnisse

Ein kurzer Hostname ist nicht automatisch weltweit eindeutig. Umbenennen veröffentlicht keine neue Adresse. Gleiche Namen in verschiedenen Kontexten beweisen nicht dasselbe Gerät. Eine fehlgeschlagene Namensauflösung bedeutet außerdem nicht zwangsläufig, dass ein Ziel unter seiner numerischen Adresse unerreichbar ist.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Nenne bei Problemen die genaue Bezeichnung und den verwendeten Kontext. Vermeide Rückschlüsse allein aus einem Anzeigenamen. Dieser Eintrag verändert weder lokale Rechnernamen noch Namensdienste, Suchregeln oder Netzwerkprofile und greift auf keine tatsächlichen Benutzerdaten zu.

## 10. Verwandte Begriffe

[DNS](it_0148.md) verwaltet strukturierte Namensinformationen. Ein [Resolver](it_0149.md) beschafft Ergebnisse. Die [IP-Adresse](it_0139.md) ist ein möglicher aufgelöster Wert. [HTTPS](it_0146.md) benötigt zusätzlich eine passende geschützte Dienstidentität.

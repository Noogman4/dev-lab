# Checkbox

## 1. Kurzbeschreibung

Eine Checkbox ist ein Auswahlfeld für eine typischerweise unabhängige An/Aus-Entscheidung. Die Markierung zeigt den gewählten Zustand. Die Quelle nennt das Aktivieren von DNS Guard als Anwendung. Eine sichtbare Auswahl allein beweist jedoch nicht, dass eine entsprechende Systemänderung bereits erfolgreich ausgeführt wurde.

## 2. Was bedeutet der Begriff?

Mehrere Checkboxen können verschiedene Optionen unabhängig repräsentieren. Ihre Beschriftungen sollten erkennen lassen, was eine aktivierte Auswahl bedeutet. Ein ausgewählter Wunsch, ein gespeicherter Einstellungswert und ein tatsächlich wirksamer Zustand können dabei unterschiedliche Ebenen sein.

Das [offizielle Tk-Handbuch zum ttk::checkbutton](https://raw.githubusercontent.com/tcltk/tk/core-8-6-branch/doc/ttk_checkbutton.n) beschreibt eine gebundene Variable sowie die Werte für ausgewählt und nicht ausgewählt. Diese Werte müssen nicht in jeder Schnittstelle wörtlich `True` und `False` heißen. Manche Zustandsmodelle kennen zusätzlich eine unbestimmte oder gemischte Darstellung.

## 3. Einfacher Vergleich aus dem Alltag

Auf einer Bestellliste kann jede Zusatzoption ein eigenes Kästchen besitzen. Mehrere Kästchen dürfen gleichzeitig markiert sein, wenn die Optionen unabhängig sind. Die Markierung beschreibt zunächst die Auswahl, nicht die bereits erfolgte Lieferung.

Die Grenze des Vergleichs: Eine Software kann beim Umschalten sofort Code ausführen oder Änderungen erst beim späteren Anwenden übernehmen. Diese Arbeitsweise muss die Oberfläche vermitteln. Ein Kästchen kann außerdem deaktiviert sein oder einen nicht eindeutig bestimmten Datenbestand anzeigen.

## 4. Wie funktioniert das?

Ein Toolkit verbindet die Markierung mit einem gespeicherten Wert. Eine vorgesehene Aktivierung ändert diesen Zustand und kann einen Callback auslösen. Die Anwendung entscheidet, ob daraus eine unmittelbare Aktion oder lediglich ein geänderter Einstellungswunsch wird.

Pythons `ttk.Checkbutton.invoke` schaltet den Auswahlzustand um, ruft die zugehörige Aktion auf und liefert deren Ergebnis. Das beschreibt die [offizielle Python-Referenz](https://docs.python.org/3.13/library/tkinter.ttk.html#tkinter.ttk.Checkbutton.invoke). Direkte Variablenänderungen und eine vollständige Benutzeraktivierung sind deshalb nicht pauschal dieselbe Operation.

Für fachliche Wirkung braucht es zusätzliche Verarbeitung und Rückmeldung. Scheitert eine Änderung, sollte nicht stillschweigend eine erfolgreiche Konfiguration behauptet werden. Auch bestehende Einstellungen und angezeigte Auswahl müssen nachvollziehbar zusammengeführt werden.

## 5. Wo begegnet mir das unter Linux?

Einstellungsfenster verwenden Checkboxen für unabhängige Optionen wie Anzeigeverhalten oder zusätzliche Prüfungen. Manche Aktionen betreffen nur die Darstellung, andere können Dateien oder Systemzustände verändern. Die Beschriftung und Rückmeldung sollten diese Wirkung erkennbar machen.

Das DNS-Guard-Beispiel der Quelle wird hier nicht praktisch ausgeführt. Eine Auswahl könnte einen Wunsch ausdrücken, während die tatsächliche DNS-Konfiguration gesonderte Prüfungen und geeignete Rechte benötigt. Die Checkbox selbst stellt diesen Nachweis nicht her.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel prüft ausschließlich eine eigene lokale Auswahl unter dem virtuellen Bildschirm:

```python
# GUI-Prüfung im virtuellen Bildschirm
import tkinter as tk
from tkinter import ttk

root = tk.Tk()
root.withdraw()
try:
    auswahl = tk.BooleanVar(master=root, value=False)
    beobachtet = []
    feld = ttk.Checkbutton(root, text="Beispieloption", variable=auswahl,
                           command=lambda: beobachtet.append(auswahl.get()))
    assert auswahl.get() is False
    feld.invoke()
    assert auswahl.get() is True and feld.instate(["selected"])
    feld.invoke()
    assert auswahl.get() is False
    assert beobachtet == [True, False]
    print(beobachtet)
finally:
    root.destroy()
```

Die Ausgabe lautet:

```text
[True, False]
```

Die beiden programmgesteuerten Aktivierungen schalten die eigene Option ein und aus. Der Callback beobachtet jeweils den zugehörigen Variablenwert. Es wird keine reale Einstellung angewendet und kein DNS-Zustand verändert.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Button vermittelt eine Aktion. Eine Checkbox stellt typischerweise eine unabhängige Auswahl dar. Eine Gruppe exklusiver Auswahlmöglichkeiten benötigt ein anderes Modell. Ein Boolean ist ein Datenwert; die Checkbox ist ein Oberflächenelement mit zusätzlicher Darstellung und Bedienung.

## 8. Häufige Missverständnisse

Ein Haken beweist keine erfolgreich angewandte Systemkonfiguration. Mehrere Checkboxen sind nicht automatisch gegenseitig ausschließend. Ein deaktiviertes Auswahlfeld ist nicht notwendigerweise ausgeschaltet. Eine voreingestellte Markierung ersetzt außerdem keine Ermittlung des aktuellen tatsächlichen Zustands.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Beschrifte die Bedeutung eindeutig und kläre, wann Änderungen wirksam werden. Prüfe Rückmeldung bei Fehlschlag. Das Beispiel testet nur lokale Werte und Callback-Aufrufe; echte Eingaben, gemischte Zustände und NetMons Schutzfunktionen wurden nicht praktisch geprüft.

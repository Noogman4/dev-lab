# Responsive Design

## 1. Kurzbeschreibung

Responsive Design bezeichnet eine Gestaltung, die auf veränderte verfügbare Größen und Darstellungsbedingungen reagiert. Inhalte und Bedienelemente sollen weiterhin sinnvoll verwendbar bleiben. Die Quelle nennt ein bei kleiner Breite nutzbares Fenster. Das ist ein Ziel, aber keine automatisch erfüllte Eigenschaft jedes skalierbaren Layouts.

## 2. Was bedeutet der Begriff?

Eine Oberfläche kann Platz anders verteilen, Texte umbrechen oder Bereiche anders anordnen. Dabei sollen wichtige Informationen und Aktionen erreichbar bleiben. Nur alles gleichmäßig kleiner zu zeichnen wäre nicht für jede Aufgabe eine brauchbare Anpassung.

Der Begriff ist besonders im Web verbreitet. Die [informative W3C-Erläuterung zu Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) beschreibt für Webinhalte den Erhalt von Information und Funktion bei veränderten Darstellungsbedingungen. Ihre konkreten CSS-Maße sind keine automatisch identischen physikalischen Größen eines Desktopfensters.

## 3. Einfacher Vergleich aus dem Alltag

Auf einer kleineren Arbeitsfläche können Unterlagen anders gruppiert werden, damit die wichtigen Dinge weiterhin erreichbar bleiben. Eine sinnvolle Neuordnung ist etwas anderes, als denselben übervollen Aufbau nur enger zusammenzudrücken.

Die Grenze des Vergleichs: Software muss Größen, Inhalt und Eingaben technisch behandeln. Lange Übersetzungen, größere Schrift oder andere Skalierung können neue Anforderungen erzeugen. Eine gelungene Anpassung für einen einzigen kurzen Text belegt nicht die Eignung aller späteren Inhalte.

## 4. Wie funktioniert das?

Layouts können zusätzlichen Platz verteilen und bei weniger Platz andere Anordnungen vorsehen. Manche Oberflächen verwenden Schwellenwerte, ab denen sich die Struktur ändert. Andere lassen Inhalte innerhalb eines flexiblen Aufbaus umbrechen.

Für Desktop-Widgets beschreibt die [offizielle Qt-Dokumentation zum Layoutmanagement](https://doc.qt.io/qt-6/layout.html) automatische Positionierung und Größenanpassung. Das ist ein konkretes Werkzeug, nicht die vollständige Definition responsiver Gestaltung. Auch Mindestgrößen, Scrollbereiche und der fachliche Vorrang einzelner Elemente brauchen eine passende Entscheidung.

Anpassung darf notwendige Informationen nicht einfach verstecken. Wenn eine Tabelle zweidimensionale Beziehungen benötigt, kann ihre Behandlung anders ausfallen als die eines gewöhnlichen Absatzes. Die W3C-Erläuterung benennt solche Unterschiede und Ausnahmen ausdrücklich.

## 5. Wo begegnet mir das unter Linux?

Desktopanwendungen werden auf unterschiedlich großen Bildschirmen und mit verschiedenen Schriftgrößen verwendet. Auch ein auf einem großen Monitor entwickeltes Diagnosefenster kann später nur einen Teil der Fläche erhalten. Die Darstellung sollte diesen Alltag berücksichtigen.

Das Quellbeispiel ist daher sinnvoll, benötigt aber echte Prüfung. Eine variable Fenstergröße allein beweist weder vollständige Sichtbarkeit noch Tastaturerreichbarkeit oder Lesbarkeit. Für NetMon und seinen Reader stehen solche Abnahmen gesondert aus.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel zeigt ein eigenes Fenster nur auf dem virtuellen Bildschirm und misst ein wachsendes Eingabefeld:

```python
# GUI-Prüfung im virtuellen Bildschirm
import tkinter as tk
from tkinter import ttk

root = tk.Tk()
try:
    root.columnconfigure(0, weight=1)
    root.rowconfigure(0, weight=1)
    rahmen = ttk.Frame(root)
    rahmen.grid(sticky="nsew")
    rahmen.columnconfigure(1, weight=1)
    ttk.Label(rahmen, text="Name").grid(row=0, column=0)
    feld = ttk.Entry(rahmen)
    feld.grid(row=0, column=1, sticky="ew")
    root.geometry("320x120")
    root.update()
    klein = feld.winfo_width()
    root.geometry("520x120")
    root.update()
    gross = feld.winfo_width()
    assert gross > klein > 1
    print(gross > klein)
finally:
    root.destroy()
```

Die Ausgabe lautet:

```text
True
```

Die eigene Feldbreite wächst bei mehr Fensterplatz tatsächlich. Geprüft wird dieser begrenzte Layoutfall. Es erfolgen weder eine WCAG-Abnahme noch Tests langer Texte, anderer Sprachen oder aller Größen. Das Beispiel ist kein Nachweis vollständigen Responsive Designs.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Layout ordnet Elemente an. Responsive Design betrachtet ihre Anpassung unter wechselnden Bedingungen. Eine Mindestgröße begrenzt einen Bereich. Ein Scrollbalken kann Inhalte erreichbar machen, ersetzt aber nicht automatisch eine passende gesamte Gestaltung.

## 8. Häufige Missverständnisse

Skalierbar bedeutet nicht automatisch gut bedienbar. Zwei bestandene Größen beweisen keine allgemeine Eignung. Versteckte Elemente sind nicht zwangsläufig eine gelungene Vereinfachung. Pixelangaben verschiedener Darstellungsmodelle dürfen außerdem nicht ohne Weiteres gleichgesetzt werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe Größen, Inhalte und Schriftbedingungen gemeinsam. Bewahre wichtige Aktionen und Kontext. Das Beispiel testet nur zwei eigene Tk-Größen; sichtbare NetMon-/Reader-Bedienbarkeit und Zugänglichkeit wurden nicht abgenommen.

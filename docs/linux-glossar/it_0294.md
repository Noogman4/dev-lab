# IDE

## 1. Kurzbeschreibung

Eine integrierte Entwicklungsumgebung bündelt Werkzeuge zum Bearbeiten, Ausführen und Untersuchen von Programmen. Sie kann Quelltexte, Laufzeit, Tests und Debugger in einer Oberfläche verbinden. Welche Möglichkeiten vorhanden sind, hängt von der Umgebung und ihren Erweiterungen ab.

## 2. Was bedeutet der Begriff?

IDE steht für „Integrated Development Environment“. [PyCharms Einstiegsanleitung](https://www.jetbrains.com/help/pycharm/quick-start-guide.html) zeigt eine auf Python ausgerichtete Umgebung. Ein erweiterbarer Editor wie VS Code kann mit installierter Sprachunterstützung ähnliche Arbeitsabläufe ermöglichen. Das [Python-Tutorial für VS Code](https://code.visualstudio.com/docs/python/python-tutorial) behandelt die dazugehörige Erweiterung und den ausgewählten Interpreter.

## 3. Einfacher Vergleich aus dem Alltag

Eine Werkbank mit fest eingerichteten Werkzeugen spart Wege zwischen mehreren Räumen. Die IDE bringt mehrere Entwicklungsschritte zusammen. Bei einem Projekt ist zusätzlich wichtig, welche Werkzeuge im Hintergrund ausgewählt sind. Der sichtbare Startknopf bestimmt ihre Einstellungen nicht allein.

## 4. Wie funktioniert das?

Eine IDE kann aus Projektstruktur und Sprachdienst erkennen, wo Funktionen deklariert sind. Damit ermöglicht sie Navigation, Vervollständigung und manche automatischen Umbenennungen. Ein Laufprofil legt beispielsweise Arbeitsverzeichnis, Programmargumente und Interpreter fest. Ein Debugger kann denselben Prozess mit geeigneten Haltepunkten starten.

Die Anzeige eines Problems kann von mehreren Komponenten stammen. Eine Syntaxmeldung der IDE, ein Formatierungsvorschlag und der Rückgabestatus des Testprogramms bedeuten jeweils etwas anderes.

## 5. Wo begegnet mir das unter Linux?

Unter Linux liegen Python-Systemversion und projektspezifische Umgebung oft nebeneinander. Ein IDE-Projekt kann den Interpreter separat wählen. Der Interpreter in einem bereits geöffneten Terminal kann von der IDE-Auswahl abweichen. Das ist besonders wichtig, wenn ein Paket nur in einer der Umgebungen vorhanden ist.

## 6. Konkretes Beispiel Schritt für Schritt

Gedankenbeispiel für ein erfundenes Projekt mit einer Notizfunktion.

1. Öffne den vorgesehenen Projektordner und wähle die dokumentierte Python-Umgebung.
2. Prüfe die Startkonfiguration. Eine relative Eingabedatei wird ausgehend vom Arbeitsverzeichnis gesucht.
3. Starte im Modell einen kleinen Test mit einer erfundenen Notiz.
4. Wenn der Test nur im Terminal funktioniert, vergleiche zuerst Interpreter, Verzeichnis und Argumente. Danach kannst du gezielt eine Stelle im Ablauf untersuchen.

Dieser Ablauf setzt kein bestimmtes Menü und keine installierte IDE voraus.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Editor verändert Textdateien. Eine IDE verbindet die Bearbeitung mit weiteren Projektaktionen. Die Grenze ist fließend, weil Plugins und Sprachdienste um einen Editor herum eine integrierte Umgebung bilden können.

## 8. Häufige Missverständnisse

Grüne Editorhinweise ersetzen keinen Testlauf. Eine IDE kann Abhängigkeiten erkennen oder anbieten, sie zu installieren. Welche Pakete tatsächlich verfügbar sind, entscheidet die verwendete Umgebung.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe Startprofile und Projektvertrauen, bevor du unbekannte Projekte öffnest oder Aufgaben startest. Halte gemeinsam benötigte Einstellungen nachvollziehbar, ohne persönliche Pfade oder Zugangsdaten zu veröffentlichen.

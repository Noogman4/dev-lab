# Docstring

## 1. Kurzbeschreibung

Ein Docstring ist ein Dokumentationstext an einer festgelegten Stelle im Python-Code. Er beschreibt beispielsweise den Zweck einer Funktion, ihre Eingaben und ihr Ergebnis. Anders als ein gewöhnlicher Kommentar kann ein regulärer Docstring über ein Attribut des dokumentierten Objekts abgefragt und von Hilfswerkzeugen angezeigt werden.

## 2. Was bedeutet der Begriff?

„Docstring“ steht für „documentation string“, also Dokumentationszeichenkette. Bei einer Funktion, Klasse oder einem Modul steht ein entsprechendes Stringliteral als erste Anweisung im jeweiligen Rumpf. Python stellt diesen Text grundsätzlich als `__doc__` bereit. Die Konventionen und die genaue Begriffsbestimmung beschreibt [PEP 257](https://peps.python.org/pep-0257/#what-is-a-docstring).

Dreifache doppelte Anführungszeichen sind die übliche Schreibweise. Entscheidend für den normalen Funktionsdocstring ist jedoch die Position, nicht allein die Art der Anführungszeichen. Ein beliebiger Text mitten in einer Funktion wird dadurch nicht zu ihrem `__doc__`. Zusätzliche Dokumentationsformen, die einzelne Werkzeuge erkennen, sind davon zu unterscheiden.

## 3. Einfacher Vergleich aus dem Alltag

Eine Bedienungsanleitung liegt direkt beim Gerät. Wer das Gerät benutzen möchte, findet dort seine Aufgabe, die nötigen Eingaben und Grenzen der Anwendung. Man muss dafür nicht jede Schraube untersuchen.

So hilft ein Docstring beim Verwenden einer Funktion, ohne deren Implementierung vollständig lesen zu müssen. Der Vergleich hat eine wichtige Grenze: Die Anleitung beweist nicht, dass das Gerät wie beschrieben arbeitet. Ebenso kann ein Docstring veraltet oder falsch sein. Er ist eine Beschreibung und keine automatische Kontrolle des Codes.

## 4. Wie funktioniert das?

Beim Erzeugen einer gewöhnlichen dokumentierten Funktion wird ihr Docstring dem Funktionsobjekt zugeordnet. `funktion.__doc__` liefert diesen Text; ohne regulären Docstring kann der Wert `None` sein. Hilfswerkzeuge können Namen, Signaturen und Dokumentation gemeinsam darstellen.

Eine gute erste Zeile fasst den Zweck knapp zusammen. Bei längeren Erklärungen trennt eine Leerzeile diese Zusammenfassung vom Rest. Danach passen Informationen zu Argumenten, Rückgabewerten, Nebenwirkungen und relevanten Fehlern. Das [Python-Tutorial zu Dokumentationsstrings](https://docs.python.org/3.13/tutorial/controlflow.html#documentation-strings) erläutert diese Empfehlungen. Eine bestimmte aufwendige Parameterformatierung schreibt Python selbst dafür nicht vor.

## 5. Wo begegnet mir das unter Linux?

In Python-Modulen auf Linux findest du Docstrings in Bibliotheken, Hilfsskripten und GUI-Code. Entwicklungsumgebungen können sie beim Aufrufen einer Funktion als Hilfe einblenden. Dokumentationswerkzeuge können daraus Teile einer Referenz erstellen, sofern das Projekt sie entsprechend eingerichtet hat.

Das passiert nicht allein deshalb, weil eine Datei unter Linux gespeichert ist. Die Konvention gehört zum Python-Programm. Ein ausführliches Benutzerhandbuch, Installationshinweise und eine Erklärung des gesamten Arbeitsablaufs können zusätzlich nötig sein.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 ohne Optimierungsoption in einem temporären Ordner ausgeführt. Es dokumentiert und prüft eine selbst geschriebene Funktion.

```python
def restmenge(vorrat, verbrauch):
    """Berechne die verbleibende Menge.

    Beide Angaben werden in derselben Einheit erwartet.
    Das Ergebnis kann bei zu hohem Verbrauch negativ sein.
    """
    return vorrat - verbrauch


def ohne_text():
    return 1


assert restmenge(10, 3) == 7
assert restmenge(2, 5) == -3
assert "derselben Einheit" in restmenge.__doc__
assert ohne_text.__doc__ is None
print(restmenge.__doc__.splitlines()[0])
print(restmenge(10, 3))
```

Geprüfte Ausgabe:

```text
Berechne die verbleibende Menge.
7
```

Die erste ausgegebene Zeile stammt wirklich aus `__doc__`. Die weiteren Assertions prüfen die beschriebene negative Restmenge und den fehlenden Docstring einer zweiten Funktion. Die Funktion kontrolliert weder Einheiten noch die Datentypen ihrer Argumente. Dass die Einheiten zusammenpassen sollen, ist hier eine dokumentierte Anforderung an die Benutzung.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Kommentar mit `#` erläutert Code für Leser des Quelltexts, wird aber nicht als Funktionsdocstring bereitgestellt. Ein Test prüft konkrete erwartete Eigenschaften. Ein Docstring erklärt dagegen die beabsichtigte Verwendung. Beispiele im Docstring werden ohne ein zusätzlich eingesetztes Testwerkzeug nicht automatisch ausgeführt.

## 8. Häufige Missverständnisse

Dreifache Anführungszeichen sind kein allgemeiner Kommentarmechanismus. Sie begrenzen einen String. Docstrings müssen außerdem nicht jeden einzelnen Implementierungsschritt nacherzählen. Wichtiger ist, was Aufrufende wissen müssen. Auch ein langer Text kann ungeeignet sein, wenn er eine entscheidende Einschränkung auslässt.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Aktualisiere Dokumentation zusammen mit Verhaltensänderungen. Beschreibe relevante Fehler und Nebenwirkungen konkret. Programme sollten sich nicht darauf verlassen, dass Docstrings für notwendige Berechnungen vorhanden sind: In Python können sie bei Ausführung mit der [Optimierungsoption `-OO`](https://docs.python.org/3.13/using/cmdline.html#cmdoption-OO) entfernt werden. Dieser Modus wurde im Beispiel nicht ausgeführt.

## 10. Verwandte Begriffe

Der [String](it_0007.md) ist der zugrunde liegende Texttyp. Eine [Funktion](it_0017.md) kann ihren Aufrufvertrag dokumentieren. Bei einem [Modul](it_0086.md) kann der Docstring einen Überblick über die enthaltenen Aufgaben geben.

# Datenbank

## 1. Kurzbeschreibung

Eine Datenbank hält Daten nach einem bestimmten Modell bereit, damit sie geordnet gespeichert, verändert und abgefragt werden können. Die Verwaltung übernimmt ein Datenbankmanagementsystem. Im Alltag werden beide Begriffe oft zusammengefasst. Eine Datenbank muss weder ein entfernter Server noch eine Sammlung von Tabellen sein; unterschiedliche Systeme organisieren Daten auf verschiedene Weise.

## 2. Was bedeutet der Begriff?

Das Katalogbeispiel einer Anwendung mit gespeicherten Einstellungen beschreibt einen möglichen Einsatz. Die Datenbank kann etwa dafür sorgen, dass Werte nach dem Beenden wieder verfügbar sind. Welche Struktur und Regeln gelten, hängt vom gewählten System und Datenmodell ab.

Die [PostgreSQL-Einführung zu Grundkonzepten](https://www.postgresql.org/docs/current/tutorial-concepts.html) beschreibt ein relationales System und grenzt Tabellen von anderen Organisationsformen ab. Relationale Datenbanken sind verbreitet, definieren aber nicht sämtliche Datenbanken. Auch muss zwischen dem gespeicherten Bestand und der Software zu seiner Verwaltung unterschieden werden.

## 3. Einfacher Vergleich aus dem Alltag

Ein geordnetes Archiv hat Ablageregeln und eine Verwaltung, über die bestimmte Unterlagen gefunden oder ergänzt werden können. Die Ordnung ermöglicht gezielte Fragen, statt jedes Blatt einzeln zu durchsuchen.

Die Grenze: Ein Datenbanksystem arbeitet mit genau definierten Strukturen und Operationen. Es erkennt nicht automatisch, ob ein eingegebener Wert fachlich sinnvoll ist. Auch muss eine Datenbank nicht wie ein physischer Karteikasten aussehen. Beziehungen, Regeln und gleichzeitige Zugriffe können technisch anders organisiert werden.

## 4. Wie funktioniert das?

Eine Anwendung verwendet die vorgesehene Schnittstelle, um Daten zu lesen oder zu ändern. Das System verarbeitet die Operation nach seinen Regeln. Dabei können etwa Datentypen, eindeutige Werte oder andere Bedingungen geprüft werden. Welche Zusagen tatsächlich gelten, muss dokumentiert sein.

Eine Änderung und ihre dauerhafte Übernahme sind außerdem nicht immer derselbe Schritt. Transaktions- und Speicherregeln bestimmen, wann eine Operation bestätigt wird. Ein korrekt berechneter Wert im Arbeitsspeicher ist deshalb noch kein Nachweis seiner späteren Verfügbarkeit.

Die [offizielle SQLite-Beschreibung](https://www.sqlite.org/about.html) zeigt ein anderes Bereitstellungsmodell als ein eigener Datenbankserver: Die Bibliothek kann in eine Anwendung eingebettet werden. Das macht die gespeicherten Daten nicht zu einer bloßen gewöhnlichen Textkonfiguration, sondern verwendet weiterhin die Regeln des Datenbanksystems.

## 5. Wo begegnet mir das unter Linux?

Desktopprogramme, Dienste und Entwicklungswerkzeuge können Datenbanken verwenden. Manche laufen mit einer lokalen Datei, andere verbinden sich mit einem eigenständigen Dienst. Der Begriff allein verrät weder Speicherort noch Zugriffsrechte oder Sicherungsverfahren.

Python bietet mit [sqlite3.connect](https://docs.python.org/3.13/library/sqlite3.html#sqlite3.connect) einen Zugang zu SQLite. Das folgende Beispiel verwendet ausschließlich eine neu erzeugte Datei in einem temporären Ordner. Keine vorhandene Anwendung oder Konfiguration wird geöffnet.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 ausgeführt. Nach dem Schreiben wird die Verbindung geschlossen. Eine neue Verbindung liest den eigenen Wert wieder ein.

```python
from contextlib import closing
from pathlib import Path
import sqlite3
import tempfile

with tempfile.TemporaryDirectory() as ordner:
    pfad = Path(ordner) / "probe.sqlite"
    with closing(sqlite3.connect(pfad)) as db:
        db.execute("CREATE TABLE einstellungen (schluessel TEXT PRIMARY KEY, wert TEXT NOT NULL)")
        db.execute("INSERT INTO einstellungen VALUES (?, ?)", ("ansicht", "liste"))
        db.commit()
    assert pfad.is_file()
    with closing(sqlite3.connect(pfad)) as db:
        zeile = db.execute(
            "SELECT wert FROM einstellungen WHERE schluessel = ?", ("ansicht",)
        ).fetchone()
        assert zeile == ("liste",)
        print(zeile[0])
```

Geprüfte Ausgabe:

```text
liste
```

Damit ist das Wiederlesen dieses Werts aus der eigenen Datei geprüft. Der Versuch ist kein Test von Stromausfall, Mehrbenutzerbetrieb oder Datensicherung. Die Datei wird anschließend mit dem temporären Ordner aufgeräumt. Eine echte Einstellungsdatenbank bleibt unverändert.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Datenbank ist nicht automatisch eine einzelne Tabelle. SQL ist eine Sprache für bestimmte Datenbankoperationen. JSON kann Daten darstellen, legt aber allein keine Datenbankverwaltung fest. Eine Sicherung verfolgt wiederum das Ziel der Wiederherstellung und wird nicht durch bloße Speicherung im laufenden System ersetzt.

## 8. Häufige Missverständnisse

Nicht jede Datenbank braucht einen eigenen Serverprozess. Eine bestätigte Speicherung bedeutet auch nicht automatisch, dass falsche Fachwerte ausgeschlossen sind. Ein Datenbankname garantiert schließlich keine bestimmte Sicherheit, Geschwindigkeit oder unbegrenzte Belastbarkeit.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Kläre Datenmodell, Zuständigkeit und Sicherungsbedarf. Übe mit eigenen Beständen statt mit Anwendungsdateien. Das Beispiel legt nur temporäre Testdaten an und verändert weder installierte Software, Dienste, Konten noch bestehende Daten.

## 10. Verwandte Begriffe

Das [Backend](it_0182.md) kann Datenzugriffe organisieren. Eine [API](it_0169.md) bietet einen Zugang. Ein [Datentyp](it_0006.md) beeinflusst die Verarbeitung. [JSON](it_0175.md) ist eine Darstellungsform. Der [Server](it_0184.md) ist ein mögliches, aber nicht zwingendes Bereitstellungsmodell.

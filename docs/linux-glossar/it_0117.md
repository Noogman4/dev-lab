# Daemon

## 1. Kurzbeschreibung

Ein Daemon ist ein Dienstprozess, der ohne fortlaufende direkte Bedienung durch einen Menschen arbeitet. Er stellt beispielsweise anderen Programmen eine Funktion bereit oder überwacht bestimmte Ereignisse. Unter Unix und Linux läuft er typischerweise im Hintergrund. Das bedeutet nicht, dass er ständig rechnet oder zwingend besondere Administratorrechte benötigt.

## 2. Was bedeutet der Begriff?

Das Wort bezeichnet eine Rolle im System, keine einzelne Programmiersprache oder einen bestimmten Befehl. Ein Daemon kann beispielsweise auf Anfragen warten und bei Bedarf reagieren. Seine Arbeit kann unabhängig von einem sichtbaren Anwendungsfenster organisiert sein.

Die [offizielle systemd-Handbuchseite zu Daemons](https://www.freedesktop.org/software/systemd/man/latest/daemon.html) beschreibt sie als Hintergrund-Dienstprozesse und unterscheidet traditionelle von modernen Vorgehensweisen. Das Katalogbeispiel „systemd startet und verwaltet Daemons“ ist ein verbreiteter Fall. Daraus folgt jedoch nicht, dass jeder Linux-Rechner systemd verwenden muss oder dass alle Hintergrundprozesse automatisch Daemons sind.

## 3. Einfacher Vergleich aus dem Alltag

Ein Bereitschaftsdienst wartet auf bestimmte Anliegen. Du musst nicht für jeden einzelnen Auftrag zunächst eine Person an den Schreibtisch setzen. Wenn nichts anliegt, kann der Dienst auf das nächste Ereignis warten.

So kann ein Daemon längerfristig Funktionen bereitstellen. Die Grenze: Er trifft keine menschlichen Entscheidungen über unklare Anfragen. Sein Verhalten ist programmiert. Auch ist der Dienst nicht allein deshalb immer verfügbar, weil er als Hintergrundaufgabe vorgesehen ist. Er kann abstürzen, beendet werden oder wegen einer fehlenden Voraussetzung gar nicht starten.

## 4. Wie funktioniert das?

Traditionelle Daemons lösten sich häufig selbst von ihrer ursprünglichen Sitzung und regelten weitere Startdetails eigenständig. Die genannte Daemon-Dokumentation erklärt, dass viele dieser Schritte für neue, durch systemd verwaltete Dienste unnötig oder unpassend sind. Ein solches Programm kann im Vordergrund seines eigenen Prozesses bleiben, während der Dienstmanager die Beaufsichtigung übernimmt.

Eine [systemd-Service-Unit](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html) enthält Angaben zu einem verwalteten Dienst. Darin können unter anderem Start und Erkennung des Dienstzustands beschrieben werden. Die Programmeigenschaft „Daemon“ und die Verwaltungsbeschreibung sind deshalb zu trennen. Nicht jede Service-Unit bedeutet außerdem einen dauerhaft laufenden Prozess.

## 5. Wo begegnet mir das unter Linux?

Hintergrunddienste können beispielsweise Druckaufträge bearbeiten, zeitgesteuerte Arbeit unterstützen oder Funktionen für andere Anwendungen bereitstellen. Welche Daemons tatsächlich vorhanden sind, hängt von Distribution, Installation und Konfiguration ab. Ein Desktop benötigt nicht automatisch jeden in einer Anleitung genannten Dienst.

Ein Dienst kann unter einem dafür vorgesehenen Benutzer laufen, statt mit maximalen Rechten zu arbeiten. Ebenso kann eine Aktivierung erst bei Bedarf erfolgen. Aus dem fehlenden Anwendungsfenster lässt sich weder auf seinen Benutzer noch auf seine konkrete Aufgabe schließen.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses Gedankenbeispiel beschreibt einen fiktiven Dienst zum Verarbeiten eigener Aufträge. Es wurden weder ein Dienst eingerichtet noch Dateien überwacht oder Aufträge tatsächlich ausgeführt.

```text
Ein Dienstmanager startet das fiktive Programm auftragsdienst.
Das Programm meldet entsprechend seinem vorgesehenen Protokoll Betriebsbereitschaft.
Es wartet auf einen Auftrag, statt ununterbrochen aktiv zu rechnen.
Ein passender Auftrag wird verarbeitet und das Ergebnis zurückgemeldet.
Danach wartet das Programm auf weitere Arbeit.
Bei einem vorgesehenen Ende gibt es eigene Ressourcen geordnet frei.
```

Der Manager und das eigentliche Programm erfüllen unterschiedliche Aufgaben. Eine eventuelle Neustartregel müsste zusätzlich konfiguriert sein; sie entsteht nicht allein durch den Namen „Daemon“. Auch die Art, wie Aufträge eintreffen, ist eine Implementierungsentscheidung. Das Schema verspricht keine konkrete Netzwerk- oder Dateischnittstelle und ist keine gemessene Ablaufspur.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein beliebiger Hintergrundprozess kann nur eine kurze Berechnung ausführen und muss kein dauerhaft bereitgestellter Dienst sein. Ein Service beschreibt allgemeiner eine Funktion oder eine Verwaltungseinheit. Ein Daemon ist hier der diese Arbeit ausführende Dienstprozess. Eine grafische Anwendung kann Hintergrundarbeit verwenden, ohne insgesamt ein Daemon zu sein.

## 8. Häufige Missverständnisse

„Im Hintergrund“ bedeutet nicht unsichtbar für Verwaltungswerkzeuge. Ein Programm wird durch ein `&` in einer Shell auch nicht automatisch zu einem sauber verwalteten Systemdienst. Ein Name mit der Endung `d` kann auf einen Daemon hinweisen, ist aber keine verbindliche Klassifikation.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe bei realen Problemen den vorgesehenen Dienstmanager und die konkrete Dienstbeschreibung. Starte nicht ungeprüft eine zweite Instanz, wenn möglicherweise schon ein verwalteter Dienst arbeitet. Für das Verständnis genügt hier das Gedankenmodell; es werden keine vorhandenen Dienste gestartet, beendet oder umkonfiguriert.

## 10. Verwandte Begriffe

Ein [Prozess](it_0115.md) trägt die konkrete Ausführung. Der [Event Loop](it_0077.md) kann ein Muster zur Bearbeitung eintreffender Ereignisse sein. [logging](it_0103.md) kann den Betrieb nachvollziehbar machen, ersetzt aber nicht die Prüfung der eigentlichen Dienstfunktion.

# Logdatei

## 1. Kurzbeschreibung

Eine Logdatei hält ausgewählte Ereignisse eines Programms oder Systems fest. Sie kann beispielsweise Startmeldungen, Warnungen und Fehler enthalten. Solche Aufzeichnungen helfen bei der späteren Untersuchung eines Ablaufs. Welche Angaben enthalten sind und wie zuverlässig sie eine Frage beantworten, hängt von der erzeugenden Anwendung und ihrer Konfiguration ab.

## 2. Was bedeutet der Begriff?

„Log“ bedeutet hier Protokoll. Eine Logdatei ist eine Datei mit solchen Aufzeichnungen, nicht automatisch die vollständige Geschichte aller Vorgänge. Viele Programme schreiben lesbare Textzeilen; andere verwenden strukturierte Formate. Das Dateiformat muss zur Auswertung bekannt sein.

Für Python beschreibt die [offizielle FileHandler-Referenz](https://docs.python.org/3.13/library/logging.handlers.html#logging.FileHandler) eine Möglichkeit, Logereignisse in eine Datei zu schreiben. Standardmäßig wird dort angehängt. Das sagt jedoch nichts darüber aus, ob jede Anwendung denselben Modus, Namen oder Speicherort verwendet. Eine Endung `.log` allein garantiert kein bestimmtes Inhaltsformat.

## 3. Einfacher Vergleich aus dem Alltag

In einem Schichtbuch werden wichtige Ereignisse eingetragen: Arbeitsbeginn, eine Störung und deren Bearbeitung. Die nächste Schicht kann daraus Hinweise gewinnen, ohne beim gesamten vorherigen Ablauf anwesend gewesen zu sein.

Das erklärt den Nutzen einer Logdatei. Die Grenze: Was niemand eingetragen hat, lässt sich daraus nicht sicher rekonstruieren. Eine ungenaue oder falsche Meldung bleibt ungenau oder falsch. Technische Protokolle sind außerdem nicht automatisch manipulationsgeschützt oder eine unabhängige Begutachtung des Programms.

## 4. Wie funktioniert das?

Ein Programm erzeugt ein Ereignis mit einer Meldung und gegebenenfalls Zusatzangaben wie Schweregrad oder Zeitstempel. Ein Ausgabemechanismus formatiert und schreibt es. Wird angehängt, bleiben bestehende Inhalte normalerweise erhalten; bei einem ausdrücklich gewählten Überschreibmodus können sie verloren gehen.

Dauerhafte Protokolle benötigen außerdem eine Größen- und Aufbewahrungsstrategie. Die [offizielle logrotate-Handbuchseite](https://man7.org/linux/man-pages/man8/logrotate.8.html) beschreibt das Wechseln, Komprimieren und Entfernen von Logdateien nach konfigurierten Regeln. Rotation bedeutet nicht allein, dass eine Datei umbenannt wird: Das schreibende Programm und die gewählte Methode müssen dazu passen. Ohne passende Einrichtung kann ein gewöhnlicher FileHandler seine Datei unbegrenzt wachsen lassen.

## 5. Wo begegnet mir das unter Linux?

Das Katalogbeispiel nennt `/var/log`, einen häufigen Ort für Systemprotokolle. Daraus folgt nicht, dass jede Anwendung dort schreibt oder alle Dateien für jeden Benutzer lesbar sind. Benutzerprogramme können eigene Orte verwenden; manche Systeme sammeln Ereignisse zusätzlich oder stattdessen in einem Journal.

Bei einer Fehlersuche ist deshalb die Dokumentation der konkreten Anwendung wichtig. Ein leerer oder nicht auffindbarer Logpfad kann bedeuten, dass ein anderer Ausgabekanal konfiguriert ist. Es beweist nicht automatisch, dass keine Ereignisse aufgetreten sind.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Es schreibt ausschließlich selbst erzeugte Meldungen in eine eigene Datei und liest sie anschließend zurück.

```python
import logging
from pathlib import Path
import tempfile

with tempfile.TemporaryDirectory() as ordner:
    datei = Path(ordner) / "probe.log"
    logger = logging.Logger("glossar_datei", level=logging.INFO)
    handler = logging.FileHandler(datei, encoding="utf-8")
    handler.setFormatter(logging.Formatter("%(levelname)s:%(message)s"))
    logger.addHandler(handler)
    try:
        logger.info("Start Probe")
        logger.warning("Prüfung nötig")
        handler.flush()
    finally:
        logger.removeHandler(handler)
        handler.close()

    inhalt = datei.read_text(encoding="utf-8")
    assert inhalt == "INFO:Start Probe\nWARNING:Prüfung nötig\n"
    assert len(inhalt.splitlines()) == 2
    print(inhalt, end="")
```

Geprüfte Ausgabe:

```text
INFO:Start Probe
WARNING:Prüfung nötig
```

Der Handler verwendet ausdrücklich UTF-8. Nach dem Schreiben wird er geschlossen, bevor der Text zurückgelesen wird. Die Assertions vergleichen beide erwarteten Zeilen vollständig. Zeitstempel sind absichtlich nicht enthalten. Der Test prüft weder Rotation noch Verhalten bei Stromausfall, vollem Datenträger oder gleichzeitigen Schreibern.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Logdatei dokumentiert ausgewählte Ereignisse; eine Konfigurationsdatei legt Einstellungen fest. Eine Datensicherung bewahrt wiederherstellbare Datenbestände und wird durch Protokolle nicht ersetzt. Ein Journal kann Ereignisse anders speichern und abfragen als eine gewöhnliche Textdatei. Die gemeinsame Aufgabe „Protokollieren“ bedeutet kein identisches Dateiformat.

## 8. Häufige Missverständnisse

Die letzte Fehlermeldung muss nicht die ursprüngliche Ursache benennen. Eine hohe Anzahl von Meldungen bedeutet auch nicht automatisch eine hohe Fehleranzahl. Zeitangaben verschiedener Programme sind nur mit passender Uhrzeitbasis und Kontext sinnvoll vergleichbar. Ein fehlender Zeitstempel lässt sich nicht nachträglich aus dem bloßen Zeileninhalt herbeizaubern.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Bewahre für eine Diagnose den nötigen Zusammenhang. Entferne vertrauliche Angaben, bevor du Protokolle weitergibst. Plane Speicherbedarf und Aufbewahrung bewusst. Lösche keine Systemlogs als pauschale Problemlösung. Dieser Versuch greift nicht auf bestehende Protokolle zu und verändert keine Logrotation.

## 10. Verwandte Begriffe

[logging](it_0103.md) kann Protokollmeldungen erzeugen und ausgeben. [Debugging](it_0027.md) nutzt sie als Hinweise. Ein [Traceback](it_0092.md) kann Teil eines Fehlerprotokolls sein, ist aber nicht jede beliebige Logmeldung.

# logging

## 1. Kurzbeschreibung

`logging` ist ein Modul der Python-Standardbibliothek für Protokollmeldungen. Ein Programm kann damit Ereignisse unterschiedlich einstufen, gezielt ausgeben und passend formatieren. So lassen sich beispielsweise normale Betriebshinweise von Warnungen und Fehlern unterscheiden. Ob eine Meldung sichtbar wird und wohin sie gelangt, bestimmt die Konfiguration.

## 2. Was bedeutet der Begriff?

Ein Log ist eine Aufzeichnung von Ereignissen. `logging` bietet dafür benannte Logger, Schweregrade und Ausgabemechanismen. Zu den üblichen Graden gehören `DEBUG`, `INFO`, `WARNING`, `ERROR` und `CRITICAL`. Sie drücken aus, wie die Anwendung eine Meldung einordnet; sie beweisen nicht unabhängig, wie schwer ein Problem tatsächlich ist.

Das Katalogbeispiel `logging.info('Start')` muss keine sichtbare Ausgabe erzeugen. Der [offizielle einfache Einstieg](https://docs.python.org/3.13/howto/logging.html#a-simple-example) erklärt: Der voreingestellte Schwellwert ist `WARNING`, deshalb erscheint eine gewöhnliche `INFO`-Meldung ohne passende Konfiguration nicht. Ein bloßer Aufruf ist also noch keine Zusicherung einer gespeicherten Zeile.

## 3. Einfacher Vergleich aus dem Alltag

Eine Leitstelle erhält Meldungen mit Absender und Dringlichkeit. Eine Regel entscheidet, welche davon an welchen Schreibtisch weitergegeben werden. Der Schreibtisch kann sie anschließend in ein vereinbartes Formular übertragen.

So lassen sich Logger, Auswahl und Ausgabe auseinanderhalten. Die Grenze: `logging` ist keine menschlich urteilende Leitstelle. Es bewertet nicht selbst, ob ein Vorfall wirklich kritisch ist. Außerdem wird nicht jede Meldung unveränderbar archiviert; ein Ausgabekanal kann nur den Bildschirm oder einen Speicherpuffer bedienen.

## 4. Wie funktioniert das?

Ein Logger erzeugt beziehungsweise verarbeitet Protokollereignisse. Handler übernehmen deren Ausgabe, etwa in einen Stream oder eine Datei. Ein Formatter legt fest, wie die verfügbaren Angaben zu einer Ausgabezeichenkette werden. Die Referenzen zu [Logger](https://docs.python.org/3.13/library/logging.html#logging.Logger) und [Formatter](https://docs.python.org/3.13/library/logging.html#logging.Formatter) erklären diese getrennten Aufgaben.

Logger und Handler können jeweils Schwellwerte besitzen. Benannte Logger bilden außerdem eine Hierarchie; Meldungen können an übergeordnete Handler weitergereicht werden. Wenn eigene und übergeordnete Handler dasselbe Ereignis ausgeben, sind doppelte Zeilen möglich. Eine übersichtliche Konfiguration verhindert, dass jede Funktion ihre eigenen zufälligen Ausgaberegeln erfindet.

## 5. Wo begegnet mir das unter Linux?

Python-Anwendungen und Hilfsprogramme können damit Diagnose- und Betriebsmeldungen erzeugen. Ein gestarteter Prozess kann seine Logs beispielsweise über einen Ausgabestream weitergeben. Ob sie anschließend von einem Terminal, einer Datei oder einer anderen Infrastruktur gesammelt werden, hängt von Anwendung und Umgebung ab.

Das Python-Modul ist nicht mit einem Linux-Systemjournal gleichzusetzen. Es schreibt auch nicht automatisch alle Meldungen in einen bestimmten Systemordner. Der Quellbegriff „strukturierte Log-Ausgaben“ meint hier verfügbare Ereignisfelder und konfigurierbare Darstellung; automatisch erzeugtes JSON ist dadurch nicht zugesichert.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Ein eigener Logger schreibt ausschließlich in einen selbst erzeugten Speicherpuffer. Systemprotokolle und vorhandene Anwendungskonfigurationen werden nicht verändert.

```python
import io
import logging

puffer = io.StringIO()
logger = logging.Logger("glossar_probe", level=logging.INFO)
handler = logging.StreamHandler(puffer)
handler.setLevel(logging.INFO)
handler.setFormatter(logging.Formatter("%(levelname)s:%(message)s"))
logger.addHandler(handler)
try:
    logger.debug("Detail")
    logger.info("Start %s", "Probe")
    logger.warning("Prüfung nötig")
    erwartet = "INFO:Start Probe\nWARNING:Prüfung nötig\n"
    assert puffer.getvalue() == erwartet
    assert "Detail" not in puffer.getvalue()
    print(puffer.getvalue(), end="")
finally:
    logger.removeHandler(handler)
    handler.close()
    puffer.close()
```

Geprüfte Ausgabe:

```text
INFO:Start Probe
WARNING:Prüfung nötig
```

Der Schwellwert unterdrückt die Debug-Meldung. Die Info- und Warnmeldung werden im gewählten Format ausgegeben. Die Assertion vergleicht den gesamten Pufferinhalt. Anschließend werden die eigenen Objekte geschlossen. Dateiausgabe, Logrotation und das Systemjournal sind keine Bestandteile dieses Tests.

## 7. Abgrenzung zu ähnlichen Begriffen

`print` eignet sich für unmittelbare Ausgaben, besitzt aber nicht von selbst Logger-Hierarchie und Schweregrade. Ein Debugger untersucht den laufenden Programmzustand gezielt. Logging hält ausgewählte Ereignisse fest. Ein Test prüft erwartetes Verhalten; eine freundlich klingende Logzeile ersetzt diese Prüfung nicht.

## 8. Häufige Missverständnisse

Eine `ERROR`-Meldung wirft nicht automatisch eine Exception. Umgekehrt wird eine Exception nicht ohne passenden Aufruf überall protokolliert. Ein Loggername bestimmt auch keinen Dateinamen. Schließlich ist ein nicht sichtbares Ereignis nicht unbedingt ausgeblieben: Es kann durch einen Schwellwert oder Filter ausgeschlossen worden sein.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Wähle verständliche Meldungen und angemessene Schweregrade. Protokolliere keine Passwörter oder unnötigen persönlichen Daten. Für dauerhafte Dateilogs müssen Speicherbedarf und Aufbewahrung geplant werden. Konfiguriere Ausgaben an einer nachvollziehbaren Stelle, statt bestehende Regeln ungeprüft bei jedem Modulimport zu verändern.

## 10. Verwandte Begriffe

[Debugging](it_0027.md) kann Protokolle als Hinweise nutzen. Eine [Exception](it_0091.md) beschreibt einen anderen Mechanismus als eine Logmeldung. Ein [Modul](it_0086.md) kann einen eigenen benannten Logger verwenden und die zentrale Ausgabekonfiguration der Anwendung überlassen.

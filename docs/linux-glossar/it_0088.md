# Import

## 1. Kurzbeschreibung

Ein Import macht eine benannte Codeeinheit oder ausgewählte daraus bereitgestellte Namen für anderen Code verwendbar. Die Quelle nennt `import os` passend als Python-Beispiel. Importieren bedeutet nicht, den gesamten Quelltext als unabhängige Kopie in die aktuelle Datei einzufügen, und ist nicht dasselbe wie das Installieren einer Abhängigkeit.

## 2. Was bedeutet der Begriff?

Python trennt das Finden und Laden eines Moduls von den anschließend gebundenen Namen. Ein normaler Import bindet häufig einen Modulnamen, über den Attribute angesprochen werden. Eine `from`-Form kann dagegen einzelne bereitgestellte Werte an Namen des verwendenden Bereichs binden.

Die [offizielle Referenz zur import-Anweisung](https://docs.python.org/3.13/reference/simple_stmts.html#the-import-statement) erläutert diese Formen. Ein Alias ändert den lokal verwendeten Namen, nicht automatisch Herkunft oder Inhalt des Moduls. Die Bindung folgt weiterhin den jeweiligen Namensraumregeln.

## 3. Einfacher Vergleich aus dem Alltag

Du machst einen Werkzeugkasten unter einer Bezeichnung erreichbar oder legst einen bestimmten daraus stammenden Gegenstand unter einem lokalen Namen bereit. Das ist etwas anderes, als eine gesamte Werkstatt unabhängig neu aufzubauen.

Die Grenze des Vergleichs: Python kann beim Laden Anweisungen ausführen. Außerdem sind gebundene Namen und später veränderte Modulattribute nicht immer dieselbe fortlaufend synchronisierte Beziehung. Das Bild eines dauerhaft gleichbleibenden physischen Werkzeugs erklärt diese Bindungsdetails nicht vollständig.

## 4. Wie funktioniert das?

Python sucht die angeforderte Einheit nach seinen Importregeln. Ein Loader stellt das Modul bereit und führt die vorgesehene Initialisierung aus. Die [offizielle Ladebeschreibung](https://docs.python.org/3.13/reference/import.html#loading) erläutert diese Schritte und die Rolle des Modulobjekts.

Ein bereits erfolgreich geladenes Modul kann bei einem normalen erneuten Import aus dem Cache verwendet werden. Das verhindert nicht jede mögliche Nebenwirkung anderer Importformen oder manueller Eingriffe, beschreibt aber den üblichen Ablauf im selben Prozess.

Ein `from modul import wert` bindet den zu diesem Zeitpunkt erhaltenen Wert. Wird das Modulattribut später an ein anderes Objekt gebunden, muss die bereits vorhandene lokale Bindung nicht automatisch mitwechseln. Gemeinsame veränderliche Objekte sind wiederum gesondert zu betrachten.

## 5. Wo begegnet mir das unter Linux?

Python-Anwendungen importieren Standardmodule, eigene Projektmodule und gegebenenfalls installierte Bibliotheken. Ein Fehler kann an einem falschen Namen, ungeeigneten Suchpfad oder einer fehlenden Abhängigkeit liegen. Die erwartete Umgebung sollte deshalb bekannt sein.

Eine gleichnamige eigene Datei kann einen eigentlich vorgesehenen Modulnamen verdecken. Auch ist ein erfolgreicher Import noch kein Nachweis, dass sämtliche Funktionen einer Bibliothek unter den aktuellen Systembedingungen nutzbar sind. Zusätzliche Dienste oder Dateien können erst später benötigt werden.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel erzeugt und importiert ausschließlich eigenen temporären Code:

```python
from pathlib import Path
import subprocess
import sys
import tempfile

with tempfile.TemporaryDirectory() as ordner:
    datei = Path(ordner) / "glossar_import.py"
    datei.write_text('print("Laden")\nwert = 7\n', encoding="utf-8")
    code = (
        "import glossar_import as ganz\n"
        "from glossar_import import wert as einzeln\n"
        "import glossar_import as nochmal\n"
        "assert ganz is nochmal\n"
        "ganz.wert = 9\n"
        "assert einzeln == 7 and ganz.wert == 9\n"
        "print(einzeln, ganz.wert)\n"
    )
    ergebnis = subprocess.run([sys.executable, "-c", code], cwd=ordner,
                              capture_output=True, text=True, check=True, timeout=5)
    assert ergebnis.stdout == "Laden\n7 9\n"
    print(ergebnis.stdout, end="")
```

Die Ausgabe lautet:

```text
Laden
7 9
```

Die Modulinitialisierung meldet sich in diesem gewöhnlichen Ablauf einmal. Beide Modulaliasnamen erreichen dieselbe Einheit. Die früher einzeln gebundene Integerangabe bleibt sieben, während das Modulattribut neu gebunden wird. Das ist kein allgemeiner Test manuellen Nachladens oder aller Importer.

## 7. Abgrenzung zu ähnlichen Begriffen

Installation stellt Software für eine Umgebung bereit. Import verwendet eine erreichbare Einheit im Programm. Ein Modul ist das geladene Objekt beziehungsweise die Codeeinheit. Ein Alias ist ein verwendeter Name. Eine Quelltextkopie besitzt wiederum andere Pflege- und Identitätsregeln.

## 8. Häufige Missverständnisse

Ein Import installiert keine fehlenden Bibliotheken automatisch. `from` kopiert nicht grundsätzlich alle Daten tief. Wiederholter Import bedeutet nicht immer erneute Initialisierung. Ein vertrauter Name garantiert außerdem nicht die richtige Herkunft, wenn Suchpfade oder Dateien anders angeordnet sind.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe Namen und Umgebung, bevor du Abhängigkeiten veränderst. Beachte möglichen Initialisierungscode. Das Beispiel führt nur seinen selbst erzeugten Modultext aus; fremde Projektmodule, Installation und Netzwerkzugriffe werden nicht verwendet.

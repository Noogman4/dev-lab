# Shell

## 1. Kurzbeschreibung

Eine Shell ist ein Programm, das eine Befehlssprache verarbeitet. Unter Unix-artigen Systemen kann sie interaktiv Befehle entgegennehmen oder vorbereitete Skripte ausführen. Sie startet andere Programme und bietet eigene Sprachmittel, beispielsweise Variablen und Bedingungen. Eine Shell ist dabei vom Fenster oder Gerät zu unterscheiden, über das du mit ihr arbeitest.

## 2. Was bedeutet der Begriff?

„Shell“ bedeutet Hülle. Im hier gemeinten Zusammenhang stellt sie eine Befehlsschnittstelle zum Arbeiten mit Programmen bereit. Das [GNU-Bash-Handbuch zur Shell-Grundidee](https://www.gnu.org/software/bash/manual/html_node/What-is-a-shell_003f.html) beschreibt eine Unix-Shell sowohl als Befehlsinterpreter als auch als Programmiersprache.

Die Quellbeschreibung „Ein Programm zur Eingabe von Befehlen“ erfasst deshalb nur einen Teil. Eine Shell kann ebenso ohne menschliche Eingabe einen festgelegten Ablauf aus einer Datei verarbeiten. Bash ist ein bekanntes Beispiel, aber nicht die einzige Shell. Unterschiede zwischen ihren Sprachen und Erweiterungen sind bei übernommenen Skripten wichtig.

## 3. Einfacher Vergleich aus dem Alltag

Eine Arbeitsleitung liest Aufträge, ersetzt Platzhalter durch konkrete Angaben und verteilt Arbeit an passende Fachkräfte. Manche kleinen Aufgaben erledigt sie selbst. Ein vorbereiteter Auftragszettel kann dieselbe Arbeit auslösen wie eine mündliche Anweisung.

So verarbeitet eine Shell Befehle und ruft gegebenenfalls andere Programme auf. Die Grenze: Sie versteht keine Alltagssprache und prüft nicht selbst, ob ein Auftrag vernünftig ist. Schon Anführungszeichen oder Leerzeichen können die technische Bedeutung verändern. Außerdem wird nicht für jede Anweisung zwingend ein neues externes Programm gestartet.

## 4. Wie funktioniert das?

Die Shell liest Eingaben, erkennt Wörter und Operatoren, verarbeitet die vorgesehene Syntax und führt die daraus entstehenden Befehle aus. Dazu können Ersetzungen gehören, etwa das Einsetzen einer Variablen. Die [POSIX-Spezifikation der Shell-Befehlssprache](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html) beschreibt diese Schritte und die Regeln für die standardisierte Sprache.

Ein Befehl kann beispielsweise ein eingebauter Shell-Befehl oder ein externes Programm sein. Umleitungen beeinflussen Ein- und Ausgabekanäle, Pipelines verbinden Befehle. Das sind Regeln der Shell-Verarbeitung; ein gestartetes Programm erhält anschließend die daraus gebildeten Argumente. Es liest nicht zwangsläufig den ursprünglichen Eingabetext so, wie du ihn geschrieben hast.

## 5. Wo begegnet mir das unter Linux?

Häufig startet ein Terminalprogramm eine interaktive Shell. Du gibst dort Befehle ein und siehst deren Ausgaben. Shells werden aber auch in Skripten und automatisierten Abläufen eingesetzt, ohne dass ein sichtbares Terminalfenster geöffnet ist.

Der Name `sh` bezeichnet die entsprechende Shell-Schnittstelle, nicht auf jedem System dieselbe Implementierung. Ein Skript für Bash kann zusätzliche Sprachmittel verwenden, die nicht zu einer allgemeinen POSIX-Shell gehören. Dass ein Beispiel in einer Shell funktioniert, belegt daher nicht jede andere Kombination.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses vollständige Python-Prüfskript wurde in einem temporären Ordner ausgeführt. Es übergibt einer lokalen `/bin/sh` ausschließlich einen festen, selbst geschriebenen Text. Die Shell erzeugt nur eine Ausgabe; sie verändert keine Dateien oder Einstellungen.

```python
import subprocess

skript = '''name='zwei Wörter'
printf '[%s]\\n' "$name"
'''
ergebnis = subprocess.run(
    ["/bin/sh", "-c", skript],
    capture_output=True,
    text=True,
    timeout=5,
    check=True,
)
assert ergebnis.stdout == "[zwei Wörter]\n"
assert ergebnis.stderr == ""
print(ergebnis.stdout, end="")
```

Geprüfte Ausgabe:

```text
[zwei Wörter]
```

Die Shell verarbeitet zunächst die Zuweisung an `name`. Beim nächsten Befehl setzt sie den Wert ein. Die doppelten Anführungszeichen um `$name` halten dessen Leerzeichen innerhalb eines Arguments zusammen. `printf` formatiert die Ausgabe. Das Beispiel prüft diese konkrete lokale Shell-Verarbeitung, nicht sämtliche POSIX-Regeln und nicht einen interaktiven Dialog.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Terminal stellt die Umgebung für textuelle Ein- und Ausgabe bereit. Die Shell verarbeitet darin eine Befehlssprache. Ein beliebiges Kommandozeilenprogramm kann eigene Argumente verstehen, ohne selbst eine Shell zu sein. Der Kernel wiederum bietet grundlegende Betriebssystemleistungen und ist nicht der Befehlsinterpreter, den du am Prompt bedienst.

## 8. Häufige Missverständnisse

Ein Prompt ist eine Eingabeaufforderung, kein Bestandteil, der normalerweise in einen Beispielbefehl kopiert werden soll. Ein Shell-Fenster bedeutet außerdem nicht automatisch Administratorrechte. Schließlich können Zeichen wie `;`, `*` oder `$` eine besondere Bedeutung besitzen; sie sind je nach Schreibweise nicht einfach normale Textzeichen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lies einen Befehl vor dem Ausführen und prüfe die vorgesehene Shell. Übernimm fremde Eingaben nicht ungeprüft in ausführbaren Shell-Text. Für selbst erzeugte Daten und feste, kleine Aufgaben lässt sich die Wirkung leichter nachvollziehen. Das Beispiel greift weder auf Netzwerke noch auf Dienste oder Benutzerkonfigurationen zu.

## 10. Verwandte Begriffe

Eine [CLI](it_0065.md) ist eine allgemeine textuelle Bedienschnittstelle. Mit [subprocess](it_0101.md) kann Python Programme mit oder ohne ausdrücklich angeforderte Shell starten. Der [Kernel](it_0106.md) verarbeitet andere, grundlegende Aufgaben unterhalb der Benutzerprogramme.

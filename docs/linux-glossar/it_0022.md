# Kommentar

## 1. Kurzbeschreibung

Ein Kommentar ist eine für Menschen bestimmte Erläuterung im Quelltext. Er gehört gewöhnlich nicht zu den ausführbaren Programmanweisungen. In Python beginnt ein gewöhnlicher Kommentar mit `#` außerhalb eines String-Literals und endet am Ende der Zeile. Die Schreibweise hängt von der Sprache oder dem Dateiformat ab.

## 2. Was bedeutet der Begriff?

Ein Kommentar kann die Absicht hinter einer Entscheidung, eine Voraussetzung oder einen unerwarteten Sonderfall erklären. Besonders hilfreich ist er dort, wo der Code zwar zeigt, was passiert, aber nicht unmittelbar erkennen lässt, warum diese Variante gewählt wurde.

Die [Python-Referenz zu Kommentaren](https://docs.python.org/3.13/reference/lexical_analysis.html#comments) beschreibt, dass Kommentare von der Syntax ignoriert werden. Ein `#` innerhalb eines Strings beginnt dagegen keinen Kommentar. Außerdem können besondere Kommentarformen zusätzliche Bedeutung für Werkzeuge oder die Verarbeitung des Quelltexts besitzen, etwa eine Kodierungsdeklaration in den ersten Zeilen. „Nicht ausgeführt“ heißt deshalb nicht, dass jeder mögliche Kommentar für sämtliche Werkzeuge bedeutungslos wäre.

## 3. Einfacher Vergleich aus dem Alltag

Eine Randnotiz in einem Rezept kann erklären, warum der Teig eine bestimmte Ruhezeit braucht. Sie hilft beim Verstehen, ist aber nicht selbst die Tätigkeit des Knetens oder Backens.

Die Grenze des Vergleichs: Ein Programm liest nicht automatisch jede Randnotiz als Arbeitsauftrag. Eine veraltete Erläuterung kann vielmehr der tatsächlich ausgeführten Anweisung widersprechen. Bei speziell vereinbarten Werkzeughinweisen kann eine kommentarähnliche Zeile hingegen bewusst ausgewertet werden. Die genaue Rolle muss erkennbar bleiben.

## 4. Wie funktioniert das?

Python erkennt beim Lesen des Quelltexts, ob ein Hashzeichen zum Text eines Literals gehört oder einen Kommentar beginnt. Ein Kommentar kann eine eigene Zeile belegen oder auf eine Anweisung folgen. Er ersetzt weder benötigte Einrückung noch den Körper einer sonst leeren Anweisung.

Ein Docstring ist etwas anderes: ein String-Literal an einer vorgesehenen Dokumentationsposition, etwa am Beginn eines Funktionskörpers. Es kann als Dokumentation über das Objekt verfügbar sein. Diese Definition erläutert [PEP 257 zu Docstrings](https://peps.python.org/pep-0257/#what-is-a-docstring). Mehrzeilige Strings mit dreifachen Anführungszeichen sind deshalb nicht allgemein eine besondere Kommentarsyntax.

## 5. Wo begegnet mir das unter Linux?

In Python-Skripten können Kommentare Annahmen über Eingaben oder Einheiten erklären. In Konfigurationsdateien findet man oft Hinweise zu Optionen. Welche Zeichen dort Kommentare kennzeichnen, bestimmt jedoch das jeweilige Format; Regeln aus einer Shell-Datei gelten nicht automatisch für JSON oder andere Formate.

Bei einer Fehlersuche lohnt es sich, Kommentar und tatsächlichen Ablauf zu vergleichen. Eine Aussage wie „ändert keine Dateien“ kann falsch geworden sein, wenn später eine Schreiboperation ergänzt wurde. Die Anmerkung ist ein Hinweis, keine technische Absicherung.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel zeigt Kommentar, Stringinhalt und Docstring:

```python
def meldung():
    """Liefere einen festen Hinweistext."""
    # Das Hashzeichen soll im Ergebnis sichtbar bleiben.
    return "Status #1"

text = meldung()  # Die Funktion liefert einen String zurück.
assert text == "Status #1"
assert meldung.__doc__ == "Liefere einen festen Hinweistext."
print(text)
print(meldung.__doc__)
```

Die Ausgabe lautet:

```text
Status #1
Liefere einen festen Hinweistext.
```

Die eigentlichen Kommentare werden nicht ausgegeben. Das Hashzeichen im String bleibt erhalten. Der Docstring ist dagegen gezielt über `__doc__` abrufbar; das ist ein Beleg dafür, dass er nicht einfach mit einem gewöhnlichen Kommentar gleichgesetzt werden sollte.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Anweisung steuert die Ausführung. Ein Kommentar erläutert Quelltext. Ein String ist ein Datenwert. Ein Docstring ist eine besondere Verwendung eines solchen String-Literals zur Dokumentation. Ein Handbuch kann über mehrere Funktionen hinweg erklären, was ein einzelner kurzer Kommentar nicht leisten soll.

## 8. Häufige Missverständnisse

Ein Kommentar wird nicht allein durch besonders eindringliche Formulierungen wirksam. Auskommentierter Code ist nicht automatisch dauerhaft korrekt oder aktuell. Eine Zeile mit ausschließlich einem Kommentar genügt in Python nicht als notwendiger Funktionskörper. Zudem ist `#` nicht in jedem Dateiformat ein erlaubtes Kommentarzeichen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Beschreibe Absicht und wichtige Voraussetzungen. Aktualisiere Hinweise gemeinsam mit der betreffenden Logik. Schreibe keine Passwörter oder vertraulichen Diagnosedaten in Kommentare: Sie bleiben Teil der Quelldatei und können mit ihr weitergegeben werden. Das Beispiel enthält ausschließlich selbst gewählte harmlose Texte.

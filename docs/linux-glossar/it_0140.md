# IPv4

## 1. Kurzbeschreibung

IPv4 ist Version vier des Internet Protocol. Sie verwendet 32 Bit lange Adressen und regelt grundlegende Eigenschaften von IP-Paketen. Eine verbreitete Adressschreibweise besteht aus vier durch Punkte getrennten Dezimalzahlen. IPv4 ist weiterhin im Einsatz; die Bezeichnung „älter“ bedeutet nicht automatisch abgeschaltet oder auf jedem Netz durch IPv6 ersetzt.

## 2. Was bedeutet der Begriff?

Die Grundspezifikation [RFC 791](https://www.rfc-editor.org/rfc/rfc791.html) beschreibt das Internet Protocol dieser Version und seine 32-Bit-Adressfelder. Spätere Standards ergänzen und ändern verschiedene Einzelheiten. Der Grundstandard ist deshalb eine Quelle für das Grundmodell, keine vollständige heutige Betriebsanleitung für jedes Netz.

Das Katalogbeispiel `192.168.0.1` ist eine IPv4-Adresse in üblicher Textform. Die vier Zahlen repräsentieren jeweils acht Bit, also ein Oktett. Daraus ergeben sich pro Teil Werte von null bis 255. Die Punkte dienen der lesbaren Darstellung; sie sind keine zusätzlich übertragenen Adressbits.

## 3. Einfacher Vergleich aus dem Alltag

Eine kurze Kennnummer lässt sich in mehrere übersichtliche Gruppen schreiben. Die Gruppierung hilft Menschen beim Ablesen, ändert aber nicht die zugrunde liegende Information. Zusätzlich kann ein Plan festlegen, welcher vordere Teil für einen gemeinsamen Zustellbereich steht.

So lassen sich Adressdarstellung und Netzpräfix unterscheiden. Die Grenze: Ein IPv4-Netz wird nicht immer an einer sichtbaren Punktgrenze aufgeteilt. Ein Präfix kann eine andere Bitlänge besitzen. Außerdem sagt die Zahl allein nicht, welcher Dienst erreichbar ist oder ob die Adresse im konkreten Kontext überhaupt verwendet werden darf.

## 4. Wie funktioniert das?

Ein IPv4-Paket trägt Quell- und Zieladressinformationen. Systeme entscheiden anhand ihrer Regeln, wie es weitergeleitet oder lokal verarbeitet wird. Die Adresse selbst garantiert keine zuverlässige Ende-zu-Ende-Zustellung; weitere Protokolle können dafür zusätzliche Eigenschaften bereitstellen.

Für Netzbereiche ist die Schreibweise mit einer Präfixlänge wichtig. [RFC 4632 zu CIDR](https://www.rfc-editor.org/rfc/rfc4632.html) beschreibt die klassenlose Zuordnung und Zusammenfassung von IPv4-Adressbereichen. Bei `/24` gehören 24 der 32 Bit zum Präfix. Der gesamte Bereich enthält dann 256 Adresswerte. Das ist nicht automatisch die Zahl beliebig nutzbarer Einzelgeräte; reservierte Rollen und der konkrete Kontext sind zusätzlich zu beachten.

## 5. Wo begegnet mir das unter Linux?

Netzwerkverwaltung und Anwendungen können IPv4-Adressen verwenden. Ein System kann daneben auch IPv6 unterstützen. Ob beide Verfahren für einen bestimmten Weg funktionieren, hängt von Einrichtung und Gegenstelle ab. Ein erfolgreicher Aufruf über eine Version beweist nicht automatisch die Funktion der anderen.

Die Katalogadresse mit der Endung `.1` wird in manchen Heimnetzen für einen Router verwendet. Das ist eine häufige Wahl, keine allgemeine IPv4-Regel. Der Router muss nicht stets diese Zahl besitzen, und eine passende private Adresse ist noch keine Zugriffsberechtigung auf seine Verwaltung.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Es berechnet nur Adresswerte. `192.0.2.0/24` ist durch [RFC 5737](https://www.rfc-editor.org/rfc/rfc5737.html) für Dokumentation vorgesehen, nicht als real eingerichtetes Netz dieses Rechners.

```python
import ipaddress

adresse = ipaddress.IPv4Address("192.0.2.10")
netz = ipaddress.IPv4Network("192.0.2.0/24")
assert adresse.version == 4
assert len(adresse.packed) == 4
assert adresse.max_prefixlen == 32
assert adresse in netz
assert netz.num_addresses == 256
ungueltig = False
try:
    ipaddress.IPv4Address("192.0.2.300")
except ipaddress.AddressValueError:
    ungueltig = True
assert ungueltig
print(adresse)
print(adresse.max_prefixlen)
print(netz.num_addresses)
print("Ungültige Adresse erkannt:", ungueltig)
```

Geprüfte Ausgabe:

```text
192.0.2.10
32
256
Ungültige Adresse erkannt: True
```

Die [Python-Referenz zu IPv4Address](https://docs.python.org/3.13/library/ipaddress.html#ipaddress.IPv4Address) beschreibt die unterstützten Darstellungen und die Prüfung der vier Zahlen. Der Test bestätigt eine gültige Adresse, ihre vier Bytes und einen unzulässigen Wert 300. Er prüft keine Paketübertragung und keine reale Netzkonfiguration.

## 7. Abgrenzung zu ähnlichen Begriffen

IPv6 verwendet andere Adressgrößen und Protokollregeln. Ein Netzpräfix beschreibt einen Bereich, eine einzelne Adresse einen Wert darin. Eine textuelle Zahlengruppe ist außerdem kein Rechnername. Dienste verwenden zusätzlich weitere Schnittstelleninformationen, etwa die zum Transportprotokoll gehörende Endpunktadressierung.

## 8. Häufige Missverständnisse

Die letzte Zahl ist nicht immer eine frei wählbare Gerätenummer unabhängig vom Präfix. Vier Zahlen außerhalb des zulässigen Bereichs bilden keine gültige normale IPv4-Schreibweise. Auch eine syntaktisch gültige Adresse kann im konkreten Netz unpassend oder bereits anders verwendet sein.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Unterscheide beim Lesen Adresse, Präfix und tatsächliche Zuteilung. Kopiere keine Beispieladresse als vermeintliche Reparatur in eine Schnittstelle. Die Berechnungen hier nutzen ausschließlich eigene Zeichenketten und verändern weder Routen noch Adressen oder Geräte.

## 10. Verwandte Begriffe

Die [IP-Adresse](it_0139.md) erklärt den allgemeinen Zusammenhang. Ein [Netzwerk](it_0138.md) verbindet Teilnehmer. Ein [Socket](it_0129.md) kann IPv4 für konkrete Kommunikation verwenden. Ein [Integer](it_0008.md) hilft beim Verständnis der endlichen numerischen Adresswerte.

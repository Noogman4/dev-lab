# HTML

## 1. Kurzbeschreibung

HTML ist die Auszeichnungssprache für Struktur und Bedeutung von Webdokumenten. Elemente können beispielsweise Überschriften, Absätze, Links und Bedienelemente beschreiben. Der Browser verarbeitet das Dokument und stellt es mit weiteren Regeln dar. HTML ist weder nur eine Sammlung visueller Formatierungen noch allein die Programmlogik einer Anwendung.

## 2. Was bedeutet der Begriff?

Der Name steht für „Hypertext Markup Language“. Der [HTML Living Standard](https://html.spec.whatwg.org/multipage/introduction.html) beschreibt die Sprache im Zusammenhang der Webplattform. Hypertext umfasst dabei Verknüpfungen zwischen Informationen; Markup zeichnet Inhalte und ihre Rolle aus.

Das Katalogbeispiel eines Buttons zeigt ein echtes HTML-Element. Seine Semantik und Eigenschaften sind in der [offiziellen Beschreibung des button-Elements](https://html.spec.whatwg.org/multipage/form-elements.html#the-button-element) festgelegt. Ein Buttonname allein implementiert aber noch keine beliebige Fachaktion wie eine Netzprüfung oder das Speichern von Daten.

## 3. Einfacher Vergleich aus dem Alltag

Ein gut gegliedertes Dokument kennzeichnet Titel, Absätze und Handlungsstellen. Leser können dadurch erkennen, was eine Überschrift ist und wo eine Aktion vorgesehen ist. Die gemeinsame Struktur erleichtert Orientierung.

Die Grenze: Ein HTML-Element besitzt technische Bedeutung für Browser und weitere Werkzeuge, nicht nur eine bestimmte Optik. Ein groß dargestellter Text ist nicht allein dadurch eine semantische Überschrift. Ebenso wird ein frei beschrifteter Kasten nicht automatisch ein korrekt bedienbarer Button.

## 4. Wie funktioniert das?

Der Browser verarbeitet HTML zu einer Dokumentstruktur. Elemente können ineinander verschachtelt sein, Attribute ergänzen Eigenschaften. Die Darstellung wird zusätzlich von Stylesheets und Browserregeln beeinflusst. Skripte können unter den geltenden Regeln Verhalten ergänzen oder die Struktur verändern.

HTML hat eigene Syntax- und Fehlerbehandlungsregeln. Es ist nicht automatisch XML, auch wenn beide Auszeichnung verwenden. Dass ein Browser etwas anzeigt, bestätigt deshalb nicht jede formale oder fachliche Anforderung. Eine Prüfung der Struktur und eine Prüfung der Bedienbarkeit sind unterschiedliche Aufgaben.

Bei einem Button ist auch sein Typ wichtig. Im Beispiel wird `type="button"` ausdrücklich gesetzt, damit nicht stillschweigend eine andere formularbezogene Standardrolle vorausgesetzt wird. Die gewünschte weitergehende Aktion müsste gesondert definiert werden.

## 5. Wo begegnet mir das unter Linux?

Webbrowser unter Linux verarbeiten HTML genauso als Teil einer Webplattform. Auch lokale Dokumente oder in Anwendungen eingebettete Webansichten können HTML verwenden. Eine native Desktopoberfläche muss dagegen nicht aus HTML bestehen.

Der Dateiname oder die Quelle entscheidet nicht allein über die Qualität. Eine korrekt übertragene Seite kann unverständlich strukturiert sein. Ein verständlicher Inhalt kann wiederum durch ungeeignete Elementwahl für bestimmte Bedienweisen schlechter zugänglich werden. Deshalb gehört Semantik zur Gestaltung, nicht nur das sichtbare Ergebnis.

## 6. Konkretes Beispiel Schritt für Schritt

Dieser Textblock zeigt ein fiktives Dokumentfragment. Er wird hier nicht als aktive Webseite eingebunden und wurde nicht in einem Browser ausgeführt.

```text
<main>
  <h1>Eigene Probe</h1>
  <p>Hier könnte ein selbst gewählter Hinweis stehen.</p>
  <button type="button">Start</button>
</main>
```

Der äußere Bereich beschreibt hier den Hauptinhalt. Die Überschrift benennt den Abschnitt, der Absatz enthält Text und der Button ein Bedienelement. Das sind Rollen der Struktur, keine festgelegten Farben oder Abstände.

Beim Betätigen des Buttons ist im Fragment keine eigene Prüfaktion programmiert. Seine Beschriftung `Start` führt nicht automatisch eine Anwendung aus. Auch enthält der Ausschnitt weder ein vollständiges Dokumentgerüst noch eine behauptete Prüfung von Tastaturbedienung, Darstellung oder Barrierefreiheit. Er dient ausschließlich dem Lesen der Auszeichnung.

## 7. Abgrenzung zu ähnlichen Begriffen

CSS beschreibt Gestaltung. JavaScript kann programmatisches Verhalten bereitstellen. HTTP transportiert Nachrichten und kann HTML als Inhalt liefern. XML ist eine andere Auszeichnungssprache mit eigenen Regeln. Diese Techniken können zusammenwirken, erfüllen aber verschiedene Aufgaben.

## 8. Häufige Missverständnisse

HTML ist keine gewöhnliche Programmiersprache für beliebige Berechnungsabläufe. Ein sichtbares Element besitzt nicht automatisch die gewünschte Fachfunktion. Auch ein Browserbild beweist keine gültige Struktur. Die Wahl eines passenden Elements kann schließlich nicht durch bloße Farb- oder Größenanpassungen vollständig ersetzt werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Verwende Elemente nach ihrer Bedeutung und prüfe reale Bedienwege zusätzlich. Betrachte fremde Auszeichnung nicht als automatisch vertrauenswürdigen Anwendungsinhalt. Dieser Eintrag erzeugt keine aktive Seite, bindet keine Skripte ein und verändert weder Browser noch Anwendung oder Dienste.

## 10. Verwandte Begriffe

Eine [GUI](it_0064.md) kann webbasierte oder andere Technik verwenden. Ein [Button](it_0068.md) ist ein Bedienelement. [HTTP](it_0145.md) ist ein möglicher Transportzusammenhang. [XML](it_0177.md) erklärt eine andere Auszeichnung. Die [API](it_0169.md) kann zusätzlich Fachfunktionen bereitstellen.

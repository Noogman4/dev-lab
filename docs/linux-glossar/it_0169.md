# API

## 1. Kurzbeschreibung

API steht für „Application Programming Interface“, also eine Programmierschnittstelle. Sie legt fest, wie Software bestimmte Funktionen oder Daten anderer Software nutzen kann. Dazu gehören Eingaben, Ergebnisse und Fehlerbedingungen. Eine API kann innerhalb eines Prozesses, zwischen lokalen Komponenten oder über ein Netzwerk verwendet werden. Sie ist nicht automatisch eine Webseite oder REST-Schnittstelle.

## 2. Was bedeutet der Begriff?

Eine Schnittstelle beschreibt den vorgesehenen Zugang zu Funktionalität. Die interne Umsetzung kann dahinter anders organisiert sein. Nutzende Programme sollten sich auf die dokumentierten Zusagen stützen, nicht auf zufällig beobachtete Details einer Implementierung.

Ein konkretes Bibliotheksbeispiel ist [json.loads in Python](https://docs.python.org/3.13/library/json.html#json.loads): Die Dokumentation beschreibt akzeptierte Eingaben und die Umwandlung in Python-Objekte. Der Aufruf ist eine API-Nutzung, obwohl kein Server kontaktiert wird. Das Katalogbeispiel einer Wetter-App zeigt dagegen einen möglichen entfernten Dienstzugriff.

## 3. Einfacher Vergleich aus dem Alltag

Ein Bestellformular legt fest, welche Angaben eine Stelle annimmt und welche Leistung du damit anfordern kannst. Du musst nicht wissen, wie die Arbeit intern aufgeteilt wird. Fehlende oder unzulässige Angaben können eine definierte Rückmeldung auslösen.

Die Grenze: Eine API folgt technischen Regeln und errät keine Absicht. Auch reichen gleich benannte Felder nicht für gemeinsame Bedeutung. Eine Temperaturzahl benötigt etwa eine vereinbarte Einheit. Syntax, fachliche Bedeutung und Berechtigung müssen zusammenpassen.

## 4. Wie funktioniert das?

Ein Aufrufer verwendet die vereinbarte Form. Bei einer Bibliothek kann das ein Funktionsname mit Parametern sein. Bei einer Web-API gehören beispielsweise Ziel, Methode, Nachrichtenfelder und Datenformat dazu. Die [HTTP-Methodensemantik in RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#section-9) beschreibt einen Teil solcher HTTP-Zugriffe.

Die API legt außerdem fest, was als Erfolg oder Fehler gilt. Ein syntaktisch korrektes Dokument kann trotzdem die falsche Datenstruktur enthalten. Eine erfolgreiche Transportverbindung ist ebenfalls noch keine erfolgreiche Fachoperation. Versionen und Kompatibilitätszusagen sind deshalb wichtige Teile einer dokumentierten Schnittstelle.

## 5. Wo begegnet mir das unter Linux?

Python-Bibliotheken, Betriebssystemschnittstellen und entfernte Dienste bieten unterschiedliche APIs. Eine GUI-Anwendung kann mehrere davon benutzen, ohne dass Benutzer jeden internen Aufruf sehen. Die sichtbare Oberfläche und die Programmierschnittstelle sind verschiedene Zugänge.

Das Wetter-App-Beispiel benötigt im echten Einsatz zusätzlich eine erreichbare Gegenstelle und passende Nutzungsregeln. Die empfangenen Werte müssten geprüft werden. Für das Verständnis reicht hier eine eigene lokale Zeichenkette; sie enthält keine tatsächlichen Wetterdaten und stammt von keinem Dienst.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Es nutzt ausschließlich die lokale Bibliotheks-API und selbst geschriebene Daten.

```python
import json

text = '{"temperatur": 18, "einheit": "C"}'
daten = json.loads(text)
assert isinstance(daten, dict)
assert daten["temperatur"] == 18
assert daten["einheit"] == "C"
assert isinstance(json.loads("[]"), list)
fehler_erkannt = False
try:
    json.loads('{"temperatur":}')
except json.JSONDecodeError:
    fehler_erkannt = True
assert fehler_erkannt
print(f"{daten['temperatur']} {daten['einheit']}")
print("Ungültige Syntax erkannt:", fehler_erkannt)
```

Geprüfte Ausgabe:

```text
18 C
Ungültige Syntax erkannt: True
```

Die Funktion verarbeitet das gültige Dokument. Die Liste aus `[]` ist ebenfalls gültiges JSON, aber eine andere Datenstruktur als das erwartete Temperatur-Objekt. Die letzte Prüfung erkennt tatsächlich ungültige Syntax. Diese Unterschiede zeigen, warum „eingelesen“ und „fachlich passend“ verschiedene Aussagen sind. Es wurde keine Wetter-API abgefragt.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine GUI richtet sich unmittelbar an Menschen. Eine API richtet sich an aufrufende Software. Ein Datenformat wie JSON beschreibt eine Darstellung, nicht allein die vollständige Schnittstelle. HTTP ist ein Kommunikationsprotokoll. REST ist ein Architekturstil und nicht einfach ein anderes Wort für jede API.

## 8. Häufige Missverständnisse

Eine API muss nicht über das Internet erreichbar sein. JSON im Ergebnis macht eine Schnittstelle nicht automatisch REST-konform. Gleiche Methodennamen bedeuten auch nicht überall dieselben Nebenwirkungen. Außerdem kann eine unautorisierte Anfrage syntaktisch korrekt sein und trotzdem abgelehnt werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lies die Dokumentation zu Eingaben, Fehlern, Versionen und Berechtigungen. Prüfe externe Daten vor der weiteren Verwendung. Für Übungen sind eigene Daten übersichtlich. Dieses Beispiel installiert nichts und verändert weder Konten, Dienste noch Netzwerk- oder Anwendungskonfigurationen.

## 10. Verwandte Begriffe

Eine [Funktion](it_0017.md) kann Teil einer API sein. [HTTP](it_0145.md) ist ein möglicher Kommunikationsweg. Eine [Exception](it_0091.md) kann Fehler signalisieren. Der [Datentyp](it_0006.md) hilft beim Prüfen der Ergebnisstruktur. Ein [Service](it_0119.md) kann eine entfernte Schnittstelle anbieten.

# Mixin

## 1. Kurzbeschreibung

Ein Mixin ist eine Klasse, die ausgewählte wiederverwendbare Funktionalität für andere Klassen bereitstellt. Es beschreibt meist eine ergänzende Fähigkeit statt den vollständigen fachlichen Typ eines Objekts. Die Quelle nennt ein `LoggingMixin` passend als Beispiel. In Python ist Mixin kein besonderes Schlüsselwort, sondern eine Rolle im Entwurf.

## 2. Was bedeutet der Begriff?

Ein Mixin kann eine kleine Gruppe zusammengehöriger Methoden bündeln. Die verwendende Klasse übernimmt diese über Vererbung und stellt gegebenenfalls benötigte Daten oder Grundoperationen bereit. Diese Voraussetzungen gehören zur Schnittstelle und sollten dokumentiert sein.

Die Python-Bibliothek verwendet etwa bei Sammlungs-Basisklassen zusätzliche Methoden, die auf einer kleineren Zahl erforderlicher Operationen aufbauen. Die [offizielle Übersicht zu collections.abc](https://docs.python.org/3.13/library/collections.abc.html#collections-abstract-base-classes) führt erforderliche und als Mixin bereitgestellte Methoden auf. Das ist ein konkretes Beispiel für ergänzende Wiederverwendung, kein allgemeines Rezept für jede Klassenhierarchie.

## 3. Einfacher Vergleich aus dem Alltag

Ein Zusatzmodul kann mehreren passenden Maschinen eine gemeinsame Fähigkeit geben. Es ersetzt nicht die gesamte Maschine und benötigt geeignete Anschlüsse oder Voraussetzungen. Die Grundfunktion bleibt bei der jeweiligen Maschine.

Die Grenze des Vergleichs: Python-Vererbung steckt keine vollständig isolierten Bauteile zusammen. Namen und Zustände können sich überlagern. Ein Mixin kann auf Attribute seiner verwendenden Klasse zugreifen und diese verändern. Ohne klaren Vertrag entstehen dadurch versteckte Abhängigkeiten.

## 4. Wie funktioniert das?

Eine Klasse erbt die vorgesehenen Zusatzmethoden. Im einfachsten Fall reicht eine solche Basisklasse aus. Häufig werden Mixins zusammen mit weiteren Basisklassen verwendet. Dann entscheidet die Methodenauflösungsreihenfolge, welche gleichnamigen Bestandteile gefunden werden.

Das [Python-Tutorial zur Mehrfachvererbung](https://docs.python.org/3.13/tutorial/classes.html#multiple-inheritance) beschreibt die kooperative Auflösung und ihre Bedeutung. Die Reihenfolge der Basisklassen ist deshalb nicht bloß eine optische Anordnung. Auch Initialisierungen sollten zusammenpassen, wenn mehrere beteiligte Klassen eigene Schritte benötigen.

Ein Mixin muss nicht in jedem Sprachmodell technisch uninstanziierbar sein. Seine beabsichtigte ergänzende Rolle ist eine Entwurfsentscheidung. Ein abstrakter Mechanismus kann zusätzliche Einschränkungen liefern, ist aber nicht allein durch die Namensendung `Mixin` automatisch vorhanden.

## 5. Wo begegnet mir das unter Linux?

Python-Anwendungen können kleine gemeinsame Fähigkeiten wie Formatierung oder Diagnoseaufzeichnung in Mixins bündeln. Rahmenwerke verwenden sie teilweise für anpassbare Klassen. Die tatsächlich benötigten Attribute und Lebensdauerregeln müssen aus der jeweiligen Dokumentation hervorgehen.

Wenn ein Zusatzbaustein sehr viele fremde Attribute voraussetzt, kann Komposition verständlicher sein. Die Zahl wiederverwendeter Zeilen allein entscheidet nicht über die Qualität. Eine klare Grenze zwischen fachlicher Hauptaufgabe und zusätzlicher Fähigkeit bleibt wichtig.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel sammelt eigene Meldungen nur im Speicher:

```python
class LoggingMixin:
    def log(self, text):
        self.meldungen.append(text)

class Auftrag(LoggingMixin):
    def __init__(self):
        self.meldungen = []

    def starten(self):
        self.log("Start")

a = Auftrag()
b = Auftrag()
a.starten()
assert a.meldungen == ["Start"]
assert b.meldungen == []
assert a.meldungen is not b.meldungen
print(a.meldungen)
```

Die Ausgabe lautet:

```text
['Start']
```

Das Mixin stellt `log` bereit und erwartet ein Attribut `meldungen`. Die verwendende Klasse erzeugt diese Liste für jede Instanz. Der Test prüft die Zusatzmethode sowie getrennte Zustände. Es wird weder eine Datei geschrieben noch ein echter Auftrag gestartet; „Start“ ist lediglich ein gespeicherter Text.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine gewöhnliche Basisklasse kann eine fachliche Typbeziehung ausdrücken. Ein Mixin betont eine ergänzende Fähigkeit. Ein Interface beschreibt Erwartungen. Komposition delegiert an gesonderte Bestandteile. Eine Hilfsfunktion kann dieselbe Arbeit ohne Vererbung anbieten, wenn kein gemeinsamer Objektzustand benötigt wird.

## 8. Häufige Missverständnisse

Mixin ist keine magische Python-Funktion. Ein Klassenname allein erzwingt keine Voraussetzungen. Mehrere Mixins passen nicht automatisch konfliktfrei zusammen. Gemeinsame veränderliche Klassenattribute können außerdem unbeabsichtigt Zustände zwischen Instanzen teilen. Zusatzmethoden sind nicht von sich aus nebenwirkungsfrei.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Halte die Fähigkeit eng und dokumentiere benötigte Attribute. Prüfe Namenskonflikte und Initialisierung. Das Beispiel testet nur ein einzelnes einfaches Mixin mit zwei eigenen Instanzen. Komplexe Mehrfachvererbung und reale Protokollsysteme wurden nicht praktisch geprüft.

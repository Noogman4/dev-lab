# Widget

## 1. Kurzbeschreibung

Ein Widget ist ein Baustein einer Benutzeroberfläche. Es kann Informationen anzeigen, Eingaben annehmen oder andere Elemente enthalten. Die Quelle nennt Schaltflächen, Textanzeigen und Eingabefelder passend als Beispiele. Nicht jedes Widget ist selbst eine Eingabemöglichkeit oder ein eigenständiges Fenster.

## 2. Was bedeutet der Begriff?

Ein Toolkit stellt verschiedene Widget-Typen bereit. Ein Label zeigt beispielsweise Inhalt an, ein Button bietet eine aktivierbare Aktion, und ein Container gruppiert andere Elemente. Welche Eigenschaften, Ereignisse und Zustände ein Typ besitzt, legt die jeweilige Bibliothek fest.

Die [offizielle Qt-Widgets-Übersicht](https://doc.qt.io/qt-6/qtwidgets-index.html) beschreibt Anzeige, Eingabeverarbeitung und Gruppierung als Aufgaben. Das [Tkinter-Einstiegsbeispiel](https://docs.python.org/3.13/library/tkinter.html#a-hello-world-program) zeigt dieselben Grundrollen anhand eines Rahmens, eines Labels und einer Schaltfläche. Die konkreten Programmierschnittstellen sind trotzdem verschieden.

## 3. Einfacher Vergleich aus dem Alltag

Ein Bedienpult besteht aus einzelnen Anzeigen, Tasten und Bereichen, die diese zusammenhalten. Jeder Baustein besitzt eine überschaubare Rolle. Die Anordnung und ihr Zusammenspiel ergeben die gesamte Bedienoberfläche.

Die Grenze des Vergleichs: Softwareelemente können erzeugt, verborgen oder dynamisch verändert werden. Ein nicht sichtbares Widget muss nicht zerstört sein. Außerdem können rein logische Datenobjekte ähnliche Namen tragen, ohne überhaupt Teil einer tatsächlichen grafischen Oberfläche zu sein.

## 4. Wie funktioniert das?

Beim Erzeugen wird häufig ein übergeordnetes Element angegeben. Daraus entsteht eine Widget-Hierarchie. Layoutregeln bestimmen anschließend die Anordnung; das Erzeugen allein erklärt noch nicht die tatsächliche Darstellung und verfügbare Größe.

Eigenschaften beschreiben unter anderem Inhalt und Zustand. Ereignisse oder vorgesehene Aktionen verbinden die Oberfläche mit Programmverhalten. Ein Toolkit kann diese Aufgaben über unterschiedliche Mechanismen vermitteln. Die Namen eines anderen Toolkits dürfen deshalb nicht ungeprüft übernommen werden.

Auch Lebensdauer und Ressourcen sind zu beachten. Ein Objektverweis, ein erzeugtes Toolkit-Element und eine sichtbar bedienbare Darstellung sind unterschiedliche Nachweise. Für eine tatsächliche Bedienprüfung müssen zudem Ereignisablauf, Fokus und Benutzeraktionen untersucht werden.

## 5. Wo begegnet mir das unter Linux?

NetMons grafische Oberfläche besteht aus solchen Bausteinen. Andere Linux-Anwendungen können andere Toolkits oder Darstellungsmodelle verwenden. Die äußere Ähnlichkeit eines Buttons bedeutet nicht, dass seine technischen Eigenschaften identisch sind.

Bei Fehlern kann ein Element vorhanden, aber unpassend angeordnet oder deaktiviert sein. Eine reine Inhaltsprüfung beantwortet diese Darstellungsfragen nicht. Das folgende Beispiel untersucht deshalb ausdrücklich nur Erzeugung, Elternbeziehung und gespeicherte Beschriftung.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel benötigt Tk und einen Anzeigezugang. Es wurde unter dem vorhandenen virtuellen Bildschirm ausgeführt; das eigene Fenster bleibt verborgen:

```python
# GUI-Prüfung im virtuellen Bildschirm
import tkinter as tk
from tkinter import ttk

root = tk.Tk()
root.withdraw()
try:
    rahmen = ttk.Frame(root)
    text = ttk.Label(rahmen, text="Beispiel")
    taste = ttk.Button(rahmen, text="OK")
    assert text.master is rahmen
    assert taste.master is rahmen
    assert len(rahmen.winfo_children()) == 2
    assert text.cget("text") == "Beispiel"
    print(len(rahmen.winfo_children()))
    print(text.cget("text"))
finally:
    root.destroy()
```

Die Ausgabe lautet:

```text
2
Beispiel
```

Der Rahmen besitzt zwei erzeugte Kinder. Deren übergeordnete Beziehung und der Text werden tatsächlich abgefragt. Die eigene Tk-Instanz wird anschließend zerstört. Es wird kein Layout aufgebaut, kein Mausklick ausgeführt und keine visuelle Darstellung abgenommen.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Fenster kann Widgets enthalten und je nach Toolkit selbst eine besondere Widget-Art sein. Ein Layout ordnet Elemente an. Ein Datenmodell hält fachliche Informationen. Eine GUI umfasst das Zusammenspiel vieler Elemente, Zustände und Abläufe und ist nicht bloß ein einzelnes Widget.

## 8. Häufige Missverständnisse

Ein Widget muss nicht anklickbar sein. Ein vorhandenes Objekt beweist keine sichtbare oder bedienbare Darstellung. Ein verstecktes Element ist nicht automatisch gelöscht. Auch kann ein Kind-Element innerhalb eines Containers andere Größen- und Fokusregeln besitzen als ein selbstständiges Fenster.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe Inhalt, Hierarchie, Layout und Bedienung getrennt. Lies toolkitabhängige Lebensdauerregeln. Das Beispiel erzeugt ausschließlich eigene verborgene Tk-Elemente; NetMon, der Dokumentenreader und Qt wurden dabei nicht praktisch getestet.

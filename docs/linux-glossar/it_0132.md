# PATH

## 1. Kurzbeschreibung

`PATH` ist eine Umgebungsvariable mit Suchverzeichnissen für Programme. Wenn ein passender Programmaufruf keinen Verzeichnispfad enthält, können Shells und andere Startwerkzeuge diese Liste durchsuchen. Die Reihenfolge ist wichtig: Ein früher gefundener passender Eintrag kann einen späteren gleichnamigen Eintrag verdecken. PATH ist keine Liste aller installierten Programme.

## 2. Was bedeutet der Begriff?

Ein Pfad beschreibt einen Ort im Dateisystem. PATH enthält mehrere Verzeichnisangaben in einer Zeichenkette. Unter POSIX-Systemen werden sie durch Doppelpunkte getrennt. Die [POSIX-Definition der Umgebungsvariablen](https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/V1_chap08.html) erläutert diesen Suchmechanismus und seine Reihenfolge.

Die Quellaussage, bei einem nicht gefundenen Befehl fehle oft etwas im PATH, beschreibt eine mögliche Ursache. Es kann jedoch auch der Name falsch sein, das Programm gar nicht installiert oder die Datei nicht ausführbar sein. Ein Suchpfadproblem ist deshalb eine Diagnosemöglichkeit und keine automatische Erklärung jeder Fehlermeldung.

## 3. Einfacher Vergleich aus dem Alltag

Du suchst ein Werkzeug nach einer festgelegten Liste von Schränken. Sobald du ein passendes findest, verwendest du es. Liegt unter demselben Namen in einem früheren Schrank eine andere Ausführung, erreichst du die spätere möglicherweise gar nicht.

Das erklärt Suchreihenfolge und Überdeckung. Die Grenze: Ein Dateiname beweist nicht, dass der Inhalt das erwartete Werkzeug ist. Auch suchen Programme nicht zwangsläufig nach Alltagsmerkmalen, sondern nach konkreten Namen und Zugriffsregeln. Ein zusätzliches Verzeichnis kann daher nicht nur etwas auffindbar machen, sondern auch die Auswahl verändern.

## 4. Wie funktioniert das?

Eine Shell verarbeitet zunächst ihre eigenen Regeln, etwa für eingebaute Befehle oder Funktionen. Bei einer entsprechenden Suche nach einem externen Programm verwendet sie PATH. Enthält der Aufruf bereits einen Verzeichnisteil, gelten andere Suchbedingungen. Die [POSIX-Shell-Spezifikation](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html) beschreibt diese Einordnung.

Python bietet mit [shutil.which](https://docs.python.org/3.13/library/shutil.html#shutil.which) eine Suchfunktion für ausführbare Dateien. Ihr kann eine ausdrückliche Suchliste übergeben werden. Damit lässt sich die Reihenfolge untersuchen, ohne die tatsächliche Prozessumgebung zu ändern. Das ersetzt keine vollständige Simulation aller interaktiven Shell-Regeln.

## 5. Wo begegnet mir das unter Linux?

Du bemerkst PATH, wenn ein kurzer Programmname wie `python3` aufgelöst werden soll. Verschiedene Startumgebungen können unterschiedliche Listen erhalten. Deshalb kann ein Name im eigenen Terminal gefunden werden, aber in einem Dienst oder zeitgesteuerten Auftrag fehlen oder auf eine andere Datei zeigen.

Ein expliziter Pfad kann die Auswahl bestimmter machen, garantiert aber nicht von selbst die Vertrauenswürdigkeit seines Inhalts. Ebenso bedeutet eine ergänzte Suchliste nicht automatisch eine dauerhafte Änderung für alle schon laufenden Programme. PATH bleibt Teil der jeweiligen Prozessumgebung.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 unter Linux in einem temporären Ordner ausgeführt. Zwei eigene Dateien tragen denselben Namen. Sie werden nur für die Suche als ausführbar markiert und nicht gestartet.

```python
import os
from pathlib import Path
import shutil
import tempfile

with tempfile.TemporaryDirectory() as ordner:
    basis = Path(ordner)
    eins = basis / "eins"
    zwei = basis / "zwei"
    for verzeichnis in (eins, zwei):
        verzeichnis.mkdir()
        datei = verzeichnis / "glossar_probe"
        datei.write_text("#!/bin/sh\nexit 0\n", encoding="utf-8")
        datei.chmod(0o700)
    vorwaerts = os.pathsep.join(map(str, (eins, zwei)))
    rueckwaerts = os.pathsep.join(map(str, (zwei, eins)))
    fund_eins = shutil.which("glossar_probe", path=vorwaerts)
    fund_zwei = shutil.which("glossar_probe", path=rueckwaerts)
    assert fund_eins == str(eins / "glossar_probe")
    assert fund_zwei == str(zwei / "glossar_probe")
    fehlt = shutil.which("fehlt_test_0132", path=vorwaerts)
    assert fehlt is None
    print(Path(fund_eins).parent.name)
    print(Path(fund_zwei).parent.name)
    print(fehlt is None)
```

Geprüfte Ausgabe:

```text
eins
zwei
True
```

Die Reihenfolge allein verändert den gefundenen Dateipfad. Der dritte Fall findet in den beiden eigenen Verzeichnissen nichts Passendes. Die tatsächliche PATH-Variable wird weder gelesen noch überschrieben. Der Versuch beweist eine Dateisuche, keine erfolgreiche Ausführung der gefundenen Dateien.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein einzelner Dateipfad bezeichnet ein Ziel. PATH ist eine Suchliste für bestimmte Aufrufe. Das aktuelle Arbeitsverzeichnis ist ein anderer Prozesszustand und nicht automatisch mit jedem Suchverzeichnis identisch. Python-Imports verwenden außerdem eigene Regeln; PATH ist keine allgemeine Liste für alle Arten von Modulen oder Daten.

## 8. Häufige Missverständnisse

„Gefunden“ heißt nicht „richtige Version“. Ein neu eingefügtes frühes Verzeichnis kann bisherige Auswahl verändern. Ein nicht gefundenes Kommando wird auch nicht durch höhere Benutzerrechte automatisch installiert. Für die konkrete Fehlersuche müssen Name, Datei und Startumgebung getrennt betrachtet werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe die gewünschte Programmdatei und die Suchreihenfolge. Ergänze keine fremden oder unkontrollierbaren Verzeichnisse ungeprüft an vorderer Stelle. Für Lernversuche genügen eigene Suchlisten wie hier; keine Startdatei oder dauerhafte Umgebung muss geändert werden.

## 10. Verwandte Begriffe

Die [Umgebungsvariable](it_0131.md) erklärt die Weitergabe. Die [Shell](it_0107.md) kann externe Programme suchen. [pathlib](it_0102.md) verarbeitet einzelne Pfade. [Dateirechte](it_0112.md) beeinflussen, ob eine Datei als ausführbar betrachtet werden kann.

# subprocess

## 1. Kurzbeschreibung

`subprocess` ist ein Modul der Python-Standardbibliothek zum Starten und Begleiten anderer Programme. Es kann Argumente übergeben, Ausgaben auffangen und das Ende eines gestarteten Prozesses abwarten. Damit verbindet ein Python-Programm eigene Verarbeitung mit Aufgaben, die ein anderes Programm übernimmt.

## 2. Was bedeutet der Begriff?

Ein gestartetes Programm läuft hier als eigener Prozess. Sein Ergebnis besteht nicht zwingend nur aus angezeigtem Text: Auch ein Rückgabecode sowie getrennte Standardausgabe und Fehlerausgabe können wichtig sein. `subprocess` stellt dafür mehrere Schnittstellen bereit.

Für viele einfache Aufgaben empfiehlt die Dokumentation [subprocess.run](https://docs.python.org/3.13/library/subprocess.html#subprocess.run). Diese Funktion startet den angegebenen Aufruf, wartet auf dessen Abschluss und liefert ein `CompletedProcess`-Objekt. Das heißt auch: Während des Wartens erledigt der aufrufende Programmteil nicht automatisch andere Aufgaben. Ein Einsatz unmittelbar in einem GUI-Callback kann deshalb die Oberfläche aufhalten.

## 3. Einfacher Vergleich aus dem Alltag

Du gibst einer anderen Werkstatt einen klaren Auftrag und wartest auf deren Rückmeldung. Du legst fest, welche Angaben mitgehen und ob du das Ergebnis schriftlich zurückbekommen möchtest. Der Auftrag ist von deiner eigenen Arbeit getrennt.

Die Grenze des Vergleichs: Ein Prozess kennt keinen menschlichen Sinn deiner Bitte. Er erhält konkrete Argumente und besitzt technische Ein- und Ausgabekanäle. Ein Rückgabecode ist zudem eine vom Programm definierte Meldung, keine ausführliche Begründung. Der Wert muss zusammen mit der Dokumentation und gegebenenfalls der Ausgabe interpretiert werden.

## 4. Wie funktioniert das?

Eine Argumentliste wie `[programm, argument]` übergibt die einzelnen Bestandteile getrennt. Ohne ausdrücklich angeforderte Shell interpretiert `subprocess` daraus keine Shell-Syntax. Die [Sicherheitshinweise der Referenz](https://docs.python.org/3.13/library/subprocess.html#security-considerations) erklären den Unterschied zu `shell=True`. Auch getrennt übergebene Argumente müssen zum gewählten Programm passen; sie sind dadurch nicht automatisch fachlich ungefährlich.

Mit `capture_output=True` werden die beiden Ausgabekanäle aufgefangen, mit `text=True` als Text bereitgestellt. `check=True` macht einen Rückgabecode ungleich null zur Ausnahme. Ein `timeout` begrenzt die Wartezeit; die Dokumentation beschreibt dafür [TimeoutExpired](https://docs.python.org/3.13/library/subprocess.html#subprocess.TimeoutExpired). Eine solche Zeitgrenze ist keine Garantie, dass der gesamte Start auf jedem System exakt innerhalb dieser Zeit abgeschlossen wird.

## 5. Wo begegnet mir das unter Linux?

Python-Werkzeuge können andere lokale Programme aufrufen und deren Ergebnisse auswerten. Das Katalogbeispiel startet `ping`; seine Verfügbarkeit, Berechtigungen und Antworten hängen jedoch von der Umgebung ab. Für diesen Eintrag wird weder `ping` noch ein Netzwerkziel verwendet.

Auch auf Linux ist ein solcher Aufruf keine automatische Sicherheitsgrenze. Das gestartete Programm besitzt im gewöhnlichen Fall die Rechte des aufrufenden Benutzers. Deshalb sind das konkrete Programm und seine Argumente wichtiger als die bloße Tatsache, dass `subprocess` benutzt wird.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Es legt dort ein kleines eigenes Skript an und startet ausschließlich dieses mit demselben Python-Interpreter.

```python
from pathlib import Path
import subprocess
import sys
import tempfile

with tempfile.TemporaryDirectory() as ordner:
    skript = Path(ordner) / "probe.py"
    skript.write_text(
        "import sys\nprint(repr(sys.argv[1]))\n"
        "print('Hinweis', file=sys.stderr)\nsys.exit(3)\n",
        encoding="utf-8",
    )
    ergebnis = subprocess.run(
        [sys.executable, str(skript), "zwei Wörter; nichts ausführen"],
        capture_output=True,
        text=True,
        timeout=5,
        check=False,
        cwd=ordner,
    )
    assert ergebnis.returncode == 3
    assert ergebnis.stdout == "'zwei Wörter; nichts ausführen'\n"
    assert ergebnis.stderr == "Hinweis\n"
    print(ergebnis.returncode)
    print(ergebnis.stdout.strip())
```

Geprüfte Ausgabe:

```text
3
'zwei Wörter; nichts ausführen'
```

Leerzeichen und Semikolon bleiben Teil eines einzigen Arguments. Sie lösen hier keinen weiteren Shell-Aufruf aus. Der absichtlich gewählte Rückgabecode drei wird geprüft, nicht als erfolgreicher Unterprozess behauptet. Das äußere Beispiel selbst endet erfolgreich. Ein tatsächlicher Timeout und `check=True` wurden nicht praktisch ausgelöst.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein gewöhnlicher Funktionsaufruf bleibt im eigenen Python-Prozess. `subprocess` startet ein anderes Programm. Ein Import lädt dagegen Python-Module; er ist kein allgemeiner Ersatz für das Starten beliebiger Programme. Eine Shell bietet eine eigene Sprache mit zusätzlichen Auswertungsregeln.

## 8. Häufige Missverständnisse

`capture_output=True` zeigt die Ausgabe nicht automatisch im Terminal an. Ein Rückgabecode null beweist außerdem nicht jede gewünschte fachliche Eigenschaft. Das Auffangen sehr großer Ausgaben kann viel Speicher benötigen; für solche Fälle ist eine andere Ausgabeverarbeitung zu planen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Wähle das Programm bewusst, übergib Argumente getrennt und kontrolliere Rückgabecodes. Begrenze Wartezeiten passend zur Aufgabe. Baue keine fremden Eingaben ungeprüft in Shell-Befehlsstrings ein. Das Beispiel arbeitet ausschließlich mit selbst angelegten temporären Dateien und verändert weder Netzwerk noch Dienste.

## 10. Verwandte Begriffe

Ein [Rückgabewert](it_0020.md) ist vom Prozess-Rückgabecode zu unterscheiden. Ein [Callback](it_0078.md) sollte nicht unbedacht auf lange Unterprozesse warten. Eine [Exception](it_0091.md) kann bei misslungenem Start oder angeforderter Fehlerprüfung entstehen.

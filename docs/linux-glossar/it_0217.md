# Staging

## 1. Kurzbeschreibung

Staging bezeichnet in Git das Vorbereiten ausgewählter Inhalte im Index für den nächsten Commit. Die Staging Area ist keine weitere Bearbeitungsdatei, sondern ein vorgemerkter Zustand. Sie ermöglicht, zusammengehörige Änderungen bewusst auszuwählen. Bearbeiten, Vormerken und dauerhaftes Speichern in einem Commit sind getrennte Schritte.

## 2. Was bedeutet der Begriff?

Die Quelle nennt `git add` zum Aufnehmen von Dateien. Genau genommen werden dabei bestimmte Inhalte beziehungsweise Änderungen vorgemerkt. Mit geeigneten Optionen lassen sich auch Teile einer Datei auswählen. „Diese Datei wurde einmal hinzugefügt“ bedeutet daher nicht, dass jede spätere Bearbeitung automatisch im nächsten Commit enthalten ist.

Die [offizielle Dokumentation zu git add](https://raw.githubusercontent.com/git/git/master/Documentation/git-add.adoc) beschreibt den Index als Vorbereitung des nächsten Commits. Sie erklärt sowohl die Aufnahme ganzer Dateiinhalte als auch die interaktive Auswahl. Das folgende Beispiel bleibt bei einer ausdrücklich benannten Datei und führt keine interaktive Teilauswahl aus.

## 3. Einfacher Vergleich aus dem Alltag

Du stellst eine Mappe für die nächste verbindliche Ablage zusammen. Auf dem Schreibtisch liegen weitere Entwürfe. Was in die Mappe ausgewählt wurde, ist nicht zwangsläufig identisch mit allem, was gerade auf dem Tisch liegt. Nachträgliche Änderungen eines Entwurfs müssen erneut berücksichtigt werden.

Die Grenze: Git verwaltet technische Inhalte und Dateizustände, keine Papiermappe. Der Index erfüllt außerdem Aufgaben bei Zusammenführungen. Für den normalen Arbeitsablauf hilft der Vergleich bei der Auswahl, erklärt aber nicht jedes interne Detail des Werkzeugs.

## 4. Wie funktioniert das?

Das Arbeitsverzeichnis enthält die bearbeitbaren Dateien. Der Index beschreibt die vorgemerkte Fassung. Ein normaler Commit ohne abweichende Inhaltsoptionen übernimmt diesen vorbereiteten Stand. Neue Dateien können zunächst untracked sein, also noch nicht von Git erfasst. Eine gezielte Aufnahme einer anderen Datei ändert daran nichts.

Für die Kontrolle sind verschiedene Vergleiche nötig. Die [Dokumentation zu git diff](https://raw.githubusercontent.com/git/git/master/Documentation/git-diff.adoc) unterscheidet den Vergleich des Arbeitsverzeichnisses mit dem Index und den vorgemerkten Vergleich mit einem Commit. `--cached` beziehungsweise `--staged` zeigt im üblichen Ablauf die vorbereiteten Unterschiede. Ein gewöhnliches `git diff` zeigt dagegen nicht einfach dieselbe Auswahl.

Vor dem ersten Commit fehlt noch ein früherer gespeicherter Stand. Auch dann kann die vorgemerkte Auswahl geprüft werden. Im Beispiel wird die neue Datei gegen den leeren Ausgangszustand betrachtet. Die nicht erfasste zweite Datei erscheint nicht plötzlich als vorgemerkter Inhalt.

## 5. Wo begegnet mir das unter Linux?

Git-Oberflächen bieten oft getrennte Listen für vorgemerkte und nicht vorgemerkte Änderungen. Im Terminal werden Auswahl und Prüfung ausdrücklich aufgerufen. Beide Wege betreffen denselben grundlegenden Unterschied zwischen Arbeitsdateien und Index.

Eine pauschale Aufnahme sämtlicher Änderungen kann unerwünschte Dateien mitnehmen. Für überschaubare Beiträge ist eine gezielte Auswahl leichter zu prüfen. Das ist besonders relevant, wenn im selben Projekt andere offene Arbeiten vorhanden sind. Die Übung bleibt deshalb in einem neuen temporären Repository.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 und Git 2.52.0 ausgeführt. Es übernimmt keine Vorlagen und blendet persönliche sowie systemweite Git-Konfiguration nur für die Kindprozesse aus. Ein Commit oder eine Netzwerkübertragung ist nicht nötig.

```python
import os
from pathlib import Path
import subprocess
import tempfile

env = {k: v for k, v in os.environ.items() if not k.startswith("GIT_")}
env.update(GIT_CONFIG_GLOBAL="/dev/null", GIT_CONFIG_NOSYSTEM="1")
with tempfile.TemporaryDirectory() as ordner:
    repo = Path(ordner)
    def git(*args):
        return subprocess.run(
            ["git", *args], cwd=repo, env=env,
            check=True, capture_output=True, text=True
        ).stdout.strip()
    git("init", "--template=", "-b", "probe")
    a = repo / "a.txt"
    a.write_text("Ausgewählt\n", encoding="utf-8")
    (repo / "b.txt").write_text("Noch offen\n", encoding="utf-8")
    git("add", "a.txt")
    a.write_text("Später bearbeitet\n", encoding="utf-8")
    vorgemerkt = git("diff", "--cached", "--name-only")
    nicht_erfasst = git("ls-files", "--others", "--exclude-standard")
    assert vorgemerkt == "a.txt" and nicht_erfasst == "b.txt"
    assert git("show", ":a.txt") == "Ausgewählt"
    assert a.read_text() == "Später bearbeitet\n"
    assert git("diff", "--name-only") == "a.txt"
    print("Vorgemerkt:", vorgemerkt)
    print("Noch nicht erfasst:", nicht_erfasst)
```

Geprüfte Ausgabe:

```text
Vorgemerkt: a.txt
Noch nicht erfasst: b.txt
```

Die erste Datei besitzt zugleich eine vorgemerkte und eine spätere Arbeitsfassung. Die zweite bleibt untracked. Geprüft werden Dateiauswahl, Indexinhalt und offener Unterschied. Es wird nichts im bestehenden Projekt vorgemerkt; der temporäre Ordner wird entfernt.

## 7. Abgrenzung zu ähnlichen Begriffen

Speichern im Editor verändert eine Arbeitsdatei. Staging wählt deren Inhalt für die Vorbereitung aus. Commit speichert den vorbereiteten Projektstand. Push überträgt vorhandene Versionsarbeit. Eine Staging-Umgebung beim Bereitstellen einer Anwendung ist ein anderer Gebrauch des Worts.

## 8. Häufige Missverständnisse

`git add` erzeugt keinen Commit. Vormerken bedeutet keine automatische Aufnahme künftiger Bearbeitungen. Ein gewöhnliches Diff zeigt nicht alle neuen untracked Dateien als vollständige Unterschiede. Und eine Datei kann gleichzeitig vorgemerkte und offene Änderungen besitzen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe sowohl den allgemeinen Status als auch die konkrete vorgemerkte Auswahl. Nimm fremde offene Arbeit nicht unbeabsichtigt mit auf. Die Beispielprüfung bestätigt nur die eigenen zwei Textdateien und führt keine interaktive Patchauswahl oder Konfliktbehandlung aus.

## 10. Verwandte Begriffe

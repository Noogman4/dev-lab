# Async

## 1. Kurzbeschreibung

Async bezeichnet hier asynchrone Programmierung mit kooperativ geplanten Aufgaben. Eine Aufgabe kann an geeigneten Wartepunkten die Ausführung abgeben, damit andere Arbeit fortgesetzt wird. Das ist besonders bei vielen Wartevorgängen nützlich. Das Schlüsselwort allein macht jedoch keine blockierende Funktion automatisch passend und erzeugt keinen zusätzlichen Thread für jede Aufgabe.

## 2. Was bedeutet der Begriff?

Die Quelle nennt asyncio für viele Netzwerkaufgaben. Das ist ein möglicher Einsatz. Damit der Ablauf tatsächlich kooperativ funktioniert, müssen verwendete Schnittstellen zum asynchronen Modell passen. Eine lange gewöhnliche Berechnung in einer Coroutine kann den Event Loop trotzdem aufhalten.

Die [Python-Dokumentation zu Coroutines](https://docs.python.org/3.13/library/asyncio-task.html#coroutines) beschreibt `async def`, das Ausführen über einen Event Loop und das Planen von Tasks. Das bloße Aufrufen einer Coroutine-Funktion führt ihren Inhalt nicht bereits wie einen gewöhnlichen abgeschlossenen Funktionsaufruf aus. Der entstehende Ablauf muss tatsächlich ausgeführt oder erwartet werden.

## 3. Einfacher Vergleich aus dem Alltag

Eine Person nimmt mehrere Aufträge entgegen. Während sie bei einem Auftrag auf eine Antwort wartet, kann sie einen anderen bearbeiten. Dafür muss sie an geeigneten Stellen tatsächlich weitergeben, statt ununterbrochen bei einer blockierten Tätigkeit zu bleiben.

Die Grenze: Das Modell schafft nicht automatisch weitere gleichzeitig arbeitende Personen. Langes ununterbrochenes Rechnen kann weiterhin andere Aufträge verzögern. Ebenso muss feststehen, welche Ressourcen und Zustände die Aufgaben teilen. Nebenläufigkeit ist nicht pauschal dasselbe wie parallele CPU-Ausführung.

## 4. Wie funktioniert das?

Ein Event Loop verwaltet geplante Aufgaben und passende Ereignisse. Eine Coroutine erreicht einen Wartepunkt und kann dort anderen Aufgaben Gelegenheit geben. Später wird sie nach den Regeln des erwarteten Objekts fortgesetzt. Das Programm braucht einen nachvollziehbaren Weg für Ergebnisse und Fehler.

Eine für synchrone Arbeit geschriebene Funktion wird nicht allein durch einen Aufruf innerhalb von `async def` nichtblockierend. Die [Dokumentation zu asyncio.to_thread](https://docs.python.org/3.13/library/asyncio-task.html#asyncio.to_thread) beschreibt für passende I/O-geprägte Fälle eine Auslagerung in einen separaten Thread. Das ist eine zusätzliche Technik mit eigenen Grenzen, kein automatischer Bestandteil jedes Async-Aufrufs.

Auch Synchronisationsobjekte müssen zum Modell passen. Die [Dokumentation zu asyncio.Event](https://docs.python.org/3.13/library/asyncio-sync.html#asyncio.Event) beschreibt ein Signal für asyncio-Tasks und ausdrücklich keine allgemeine Threadsicherheit. Ein gleichnamiger Mechanismus aus einer anderen Bibliothek ist deshalb nicht beliebig austauschbar.

Aufgaben müssen außerdem beendet, erwartet oder passend abgebrochen werden. Ein bloß erzeugter Hintergrundtask liefert noch keine geprüfte Erfolgsaussage. Das folgende Beispiel wartet auf beide Ergebnisse und prüft einen bewusst kontrollierten Zwischenzustand vor ihrer Freigabe.

## 5. Wo begegnet mir das unter Linux?

Python-Anwendungen können viele geeignete Wartevorgänge über asyncio koordinieren. Dafür ist nicht zwingend ein Netzwerk nötig; auch eigene asynchrone Signale reichen für ein kleines Modell. Die Einbindung in eine GUI benötigt dagegen die passende Zusammenarbeit der jeweiligen Ereignisverarbeitung.

Dieses Glossar ersetzt keinen vorhandenen Event Loop und verändert keine Anwendung. Das Beispiel startet einen eigenen kurzen asyncio-Lauf im eigenen Skript. Es verwendet weder echte Netzwerkverbindungen noch einen GUI- oder Hintergrunddienst.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Arbeitsordner ausgeführt. Zwei eigene Tasks melden ihre Bereitschaft und warten auf ein gemeinsames Signal. Die Texte sind die einzigen bearbeiteten Nutzdaten.

```python
import asyncio

async def arbeiten(text, bereit, freigabe):
    bereit.put_nowait(text)
    await freigabe.wait()
    return text.upper()

async def main():
    bereit = asyncio.Queue()
    freigabe = asyncio.Event()
    tasks = [
        asyncio.create_task(arbeiten(text, bereit, freigabe))
        for text in ["alpha", "beta"]
    ]
    gemeldet = [await bereit.get(), await bereit.get()]
    assert sorted(gemeldet) == ["alpha", "beta"]
    assert all(not task.done() for task in tasks)
    freigabe.set()
    ergebnisse = await asyncio.gather(*tasks)
    assert sorted(ergebnisse) == ["ALPHA", "BETA"]
    assert all(task.done() for task in tasks)
    print("Beendete Tasks:", len(tasks))
    print("Ergebnisse:", ", ".join(sorted(ergebnisse)))

asyncio.run(main())
```

Geprüfte Ausgabe:

```text
Beendete Tasks: 2
Ergebnisse: ALPHA, BETA
```

Beide Tasks erreichen ihren Wartezustand, bevor die Freigabe erfolgt. Anschließend werden beide Ergebnisse erwartet und kontrolliert. Es werden keine zusätzlichen Worker-Threads angelegt und keine Geschwindigkeits- oder Netzwerkleistung gemessen. Der eigene Event Loop wird nach dem Ablauf geschlossen.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Thread ist ein eigener Ausführungsstrang. Multithreading verwendet mehrere davon. Async organisiert hier kooperativ geplante Aufgaben in einem Event Loop. Ein Queue Worker beschreibt eine Arbeitsrolle und kann je nach Entwurf auf unterschiedliche Weise umgesetzt werden.

## 8. Häufige Missverständnisse

`async def` macht nicht jeden Inhalt nichtblockierend. Ein Coroutine-Aufruf ist nicht automatisch ein bereits abgeschlossenes Ergebnis. Async bedeutet nicht ein Thread pro Aufgabe. Und Nebenläufigkeit liefert keinen pauschalen Beweis für CPU-Parallelität oder Beschleunigung.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Verwende passende asynchrone Schnittstellen und kläre Ergebnisse, Fehler sowie Beenden. Prüfe den tatsächlichen Umfang. Das Beispiel bearbeitet nur eigene Speicherwerte und verändert keine Prozesse fremder Anwendungen, Dienste oder Netzwerkeinstellungen.

# SQL

## 1. Kurzbeschreibung

SQL ist eine Sprache für die Arbeit mit relationalen Datenbanken. Sie kann unter anderem Daten auswählen, verändern und Strukturen beschreiben. Eine Anweisung legt häufig das gewünschte Ergebnis fest, während das Datenbanksystem den Ausführungsweg bestimmt. Einzelne Systeme unterstützen unterschiedliche Dialekte und Erweiterungen; ein Beispiel ist deshalb nicht automatisch überall unverändert ausführbar.

## 2. Was bedeutet der Begriff?

Der Name wird als „Structured Query Language“ ausgeschrieben. Die Sprache umfasst mehr als lesende Abfragen. Neben einer Auswahl können beispielsweise Einfügen, Ändern und das Anlegen einer Tabelle vorkommen. Berechtigungen und Transaktionen werden ebenfalls nach den Regeln des jeweiligen Systems behandelt.

Die [SQLite-Sprachübersicht](https://www.sqlite.org/lang.html) beschreibt ausdrücklich die von SQLite verstandenen Formen. Das ist die Grundlage des praktischen Beispiels, kein vollständiger Nachweis für andere SQL-Systeme. Das Katalogbeispiel `SELECT * FROM users` setzt außerdem eine vorhandene passende Tabelle voraus.

## 3. Einfacher Vergleich aus dem Alltag

Du gibst einem geordneten Archiv eine genaue Suchbeschreibung: Welche Einträge werden benötigt, welche Angaben sollen erscheinen und wie sollen sie sortiert sein? Die Archivverwaltung entscheidet, wie sie diese Auswahl effizient ermittelt.

Die Grenze: SQL versteht keine freie Alltagssprache. Namen, Werte und Operationen müssen korrekt formuliert sein. Außerdem sind Ergebnis und Ausführungsweg verschiedene Dinge. Zwei Systeme können denselben fachlichen Auftrag unterschiedlich verarbeiten, und eine passende Syntax garantiert noch keine richtigen Daten.

## 4. Wie funktioniert das?

Das Datenbanksystem verarbeitet eine Anweisung, prüft sie und führt die vorgesehene Operation aus. Bei einer Auswahl können Spalten, Bedingungen und Reihenfolge festgelegt werden. Die [SQLite-Dokumentation zu SELECT](https://www.sqlite.org/lang_select.html) erklärt diese Bestandteile.

Ohne passende Sortierung sollte keine feste Ergebnisreihenfolge vorausgesetzt werden. Auch `SELECT *` kann für dauerhaft stabile Schnittstellen ungeeignet sein, wenn sich die Tabellenstruktur verändert. Eine ausdrücklich gewählte Spaltenliste macht die benötigte Form klarer.

Werte müssen von SQL-Struktur getrennt bleiben. Die [Python-Anleitung zu sqlite3-Platzhaltern](https://docs.python.org/3.13/library/sqlite3.html#sqlite3-placeholders) zeigt Parameterbindung statt unsicherem Zusammenbauen aus Eingabetext. Platzhalter stehen dabei für Werte, nicht pauschal für beliebige Tabellen- oder Spaltennamen.

## 5. Wo begegnet mir das unter Linux?

Programme können SQL über Bibliotheken oder Datenbankdienste verwenden. Eine Desktopanwendung kann etwa SQLite einbetten. Ein anderes Programm verbindet sich mit einem eigenen Datenbankserver. Die Sprache allein entscheidet nicht über diese Betriebsform.

Eine SQL-Anweisung kann außerdem Daten verändern. Das Wort „Abfrage“ darf deshalb nicht dazu führen, jede an ein Werkzeug übergebene Zeichenkette als ungefährlich lesend zu behandeln. Der konkrete Auftrag und die Zugriffsrechte sind maßgeblich.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Arbeitsordner ausgeführt. Es erzeugt eine eigene Datenbank nur im Speicher. Alle Titel sind erfundene Testwerte.

```python
from contextlib import closing
import sqlite3

with closing(sqlite3.connect(":memory:")) as db:
    db.execute("CREATE TABLE notizen (id INTEGER PRIMARY KEY, titel TEXT NOT NULL)")
    db.executemany(
        "INSERT INTO notizen (titel) VALUES (?)",
        [("Probe",), ("O'Reilly",), ("Weiter",)],
    )
    treffer = db.execute("SELECT titel FROM notizen WHERE titel = ?", ("O'Reilly",)).fetchall()
    assert treffer == [("O'Reilly",)]
    fremdtext = "Probe' OR 1=1 --"
    assert db.execute("SELECT titel FROM notizen WHERE titel = ?", (fremdtext,)).fetchall() == []
    assert db.execute("SELECT COUNT(*) FROM notizen").fetchone() == (3,)
    assert db.execute("SELECT titel FROM notizen ORDER BY id").fetchall()[0] == ("Probe",)
    print(treffer[0][0])
    print("Unpassender Suchwert bleibt ohne Treffer")
```

Geprüfte Ausgabe:

```text
O'Reilly
Unpassender Suchwert bleibt ohne Treffer
```

Das Apostroph im Titel wird als Teil eines Werts behandelt. Auch der absichtlich SQL-ähnliche Suchtext verändert nicht die fest geschriebene Auswahlstruktur. Das prüft diese konkreten Parameterfälle, keine vollständige Sicherheit beliebiger Datenbankanwendungen. Es werden keine Benutzertabellen geöffnet.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Datenbank ist der verwaltete Bestand beziehungsweise das verwendete System. SQL ist eine Sprache dafür. Python kann diese Sprache über eine Bibliothek aufrufen. Ein Ergebnisdatensatz ist wiederum nicht dasselbe wie die Anweisung, die ihn ermittelt hat. Andere Datenbankmodelle müssen nicht dieselbe SQL-Schnittstelle anbieten.

## 8. Häufige Missverständnisse

SQL ist nicht bloß `SELECT`. Ein zulässiger Text kann trotzdem die falsche fachliche Frage stellen. Eine zufällig beobachtete Reihenfolge ist keine feste Zusage. Parameterbindung ersetzt außerdem nicht Berechtigungs- und Fachprüfungen; sie trennt zunächst Werte von der vorgesehenen Anweisungsstruktur.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Verwende passende Dokumentation zum konkreten System. Prüfe verändernde Operationen nur an eigenen Testbeständen und binde Werte über die vorgesehene Schnittstelle. Dieses Beispiel verändert keine vorhandene Datenbank, Anwendung, Dienste oder Konfigurationen.

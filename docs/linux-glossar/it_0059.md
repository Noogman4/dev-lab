# Polymorphismus

## 1. Kurzbeschreibung

Polymorphismus bedeutet, dass unterschiedliche Arten von Objekten über eine gemeinsame vorgesehene Schnittstelle verwendet werden können und dabei ihr jeweiliges Verhalten ausführen. Die Quelle nennt mehrere Widget-Typen mit einer `draw()`-Methode. Der gemeinsame Aufruf reicht jedoch nur dann aus, wenn Eingaben, Ergebnis und Bedeutung zur Erwartung des Aufrufers passen.

## 2. Was bedeutet der Begriff?

Der aufrufende Code konzentriert sich auf eine vereinbarte Fähigkeit statt auf jede einzelne konkrete Klasse. Eine Darstellungsfunktion könnte etwa jedes passende Objekt um seine Textdarstellung bitten. Wie das jeweilige Objekt diese erzeugt, bleibt seine Aufgabe.

Der Begriff umfasst verschiedene technische Formen. Hier wird vor allem die Verwendung unterschiedlich implementierter Objekte zur Laufzeit erklärt. Polymorphismus ist nicht auf Vererbung beschränkt. In Python kann passende Funktionalität auch ohne gemeinsame selbst definierte Basisklasse bereitgestellt werden.

## 3. Einfacher Vergleich aus dem Alltag

Du kannst verschiedene Drucker über denselben vorgesehenen Druckauftrag ansprechen. Die Geräte setzen ihn intern unterschiedlich um, während der Aufrufer eine gemeinsame Art von Auftrag verwendet.

Die Grenze des Vergleichs: Gleiche Beschriftungen garantieren keine vollständige Kompatibilität. Ein Gerät könnte andere Datenformate oder Einschränkungen besitzen. Entsprechend ist eine Methode mit demselben Namen noch kein Beweis, dass sie dieselben Anforderungen und Ergebnisse unterstützt.

## 4. Wie funktioniert das?

Bei einer Methodenanforderung wird das Verhalten des konkreten Objekts verwendet. Das kann durch überschreibende Methoden einer Vererbungshierarchie oder durch unabhängig passende Objekte geschehen. Der aufrufende Ablauf braucht eine klar definierte gemeinsame Erwartung.

Pythons [Glossar zu Duck Typing](https://docs.python.org/3.13/glossary.html#term-duck-typing) beschreibt die Orientierung an unterstütztem Verhalten statt allein am exakten Typ. Das ist keine Aufforderung, Fehlerfälle oder unterschiedliche Bedeutungen zu ignorieren. Die benötigten Operationen müssen tatsächlich passen.

Mit `typing.Protocol` können solche strukturellen Erwartungen für Typprüfer beschrieben werden. Die [offizielle Protocol-Referenz](https://docs.python.org/3.13/library/typing.html#typing.Protocol) erläutert diesen Zusammenhang. Eine statische Beschreibung ersetzt nicht automatisch eine vollständige Laufzeitprüfung oder fachliche Abnahme. Das folgende Beispiel verwendet keinen zusätzlichen Typprüfer.

## 5. Wo begegnet mir das unter Linux?

Eine Python-Anwendung kann unterschiedliche Ausgabewege, Ergebnisformate oder Oberflächenmodelle über passende Methoden verwenden. So muss der Aufrufer nicht für jede Klasse denselben Ablauf erneut ausschreiben.

Das Quellbeispiel mit Widgets ist eine mögliche Anwendung. Eine echte GUI-Bibliothek kann aber eigene Zeichenkontexte, Lebensdauerregeln und Ereignisabläufe verlangen. Zwei beliebige `draw`-Methoden sind nicht allein wegen ihres Namens mit dieser Bibliothek austauschbar.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel verwendet zwei unabhängige Klassen mit bewusst vereinbarter Text-Rückgabe:

```python
class Label:
    def draw(self):
        return "Status"

class Button:
    def draw(self):
        return "[OK]"

def darstellen(element):
    return element.draw()

ergebnisse = [darstellen(element) for element in [Label(), Button()]]
assert ergebnisse == ["Status", "[OK]"]
for text in ergebnisse:
    print(text)
```

Die Ausgabe lautet:

```text
Status
[OK]
```

Derselbe aufrufende Code verwendet zwei Implementierungen. Eine eigene gemeinsame Basisklasse ist dafür hier nicht erforderlich. Vereinbart ist ausdrücklich eine einfache Zeichenkette als Rückgabe. Es wird keine grafische Darstellung erzeugt; die Namen beziehen sich nur auf das kleine Lernmodell.

## 7. Abgrenzung zu ähnlichen Begriffen

Vererbung beschreibt eine Beziehung zwischen Klassen. Polymorphismus beschreibt die Verwendung über eine passende gemeinsame Schnittstelle. Ein Interface kann diese Erwartung ausdrücken. Eine gleichnamige Funktion mit unvereinbarer Bedeutung erfüllt den Vertrag nicht allein durch ihre Schreibweise.

## 8. Häufige Missverständnisse

Polymorphismus bedeutet nicht, dass sämtliche Objekte austauschbar sind. Eine gemeinsame Basisklasse ist nicht in jeder Sprache oder Form zwingend nötig. Gleichnamige Methoden garantieren weder gleiche Parameter noch gleiche Fehlerregeln. Unterschiedliche Implementierung entbindet nicht von gemeinsamen fachlichen Zusicherungen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Beschreibe Eingaben, Ergebnis und relevante Nebenwirkungen der gemeinsamen Operation. Prüfe jede konkrete Umsetzung gegen diese Erwartungen. Das Beispiel testet ausschließlich zwei eigene reine Textmethoden. Echte Widget-Verträge und statische Protocol-Prüfung wurden nicht praktisch ausgeführt.

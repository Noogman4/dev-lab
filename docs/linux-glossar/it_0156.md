# DHCP

## 1. Kurzbeschreibung

DHCP, das Dynamic Host Configuration Protocol, ermöglicht die automatische Bereitstellung von Netzwerkparametern. Dazu kann eine IP-Adresse gehören, aber auch Information über weitere Einstellungen. Der hier beschriebene typische Ablauf betrifft IPv4. Eine erfolgreich erhaltene Konfiguration bedeutet noch nicht, dass jede entfernte Anwendung erreichbar ist.

## 2. Was bedeutet der Begriff?

Statt sämtliche Werte von Hand einzutragen, kann ein Client sie bei einem passenden Server anfordern. [RFC 2131](https://www.rfc-editor.org/rfc/rfc2131.html) beschreibt das grundlegende IPv4-Verfahren und verschiedene Arten der Adresszuteilung. Die Quellbeschreibung erfasst somit einen wichtigen Teil, aber nicht alle übertragenen Informationen.

Das Katalogbeispiel nennt den Heimrouter als DHCP-Server. Diese Kombination ist verbreitet, jedoch keine notwendige Identität der Rollen. Ein Server kann auf einem anderen System arbeiten. Auch bedeutet „automatisch“ nicht, dass jedes beliebige Angebot fachlich passend oder vertrauenswürdig wäre.

## 3. Einfacher Vergleich aus dem Alltag

Bei der Ankunft in einem gemeinsam verwalteten Gebäude erhältst du einen zeitweise nutzbaren Arbeitsplatz und Hinweise zu den zuständigen Einrichtungen. Du musst nicht selbst eine freie Nummer erraten. Nach Ablauf der Vereinbarung muss die Nutzung gegebenenfalls erneuert werden.

Das erklärt Zuteilung und zeitliche Bindung. Die Grenze: DHCP verwendet genaue Protokollnachrichten und Zustände. Nicht jede Zuteilung ist zwingend zeitlich begrenzt, und die Rolle des Servers ist nicht automatisch eine persönliche Identitätsprüfung. Der Vergleich ist daher keine vollständige Beschreibung aller möglichen Konfigurationen.

## 4. Wie funktioniert das?

Ein häufiger anfänglicher IPv4-Ablauf besteht aus Suche, Angebot, Anforderung und Bestätigung. Der Client entscheidet sich dabei für ein Angebot und wartet auf dessen Bestätigung. Spätere Erneuerung oder Wiederverwendung einer bekannten Konfiguration kann andere Abläufe verwenden. Nicht jeder Start muss deshalb exakt vier neue Nachrichten umfassen.

Eine dynamische Zuteilung wird gewöhnlich als Lease mit einer Laufzeit behandelt. Der Client muss deren Bedingungen berücksichtigen. Zusätzlich definiert [RFC 2132](https://www.rfc-editor.org/rfc/rfc2132.html) Optionen, etwa für Router und DNS-Server. Das Protokoll ist damit mehr als eine Antwort mit einer einzelnen Zahl.

## 5. Wo begegnet mir das unter Linux?

Netzwerkverwaltung kann einen DHCP-Client einsetzen, wenn eine Verbindung automatisch eingerichtet werden soll. Die erhaltenen Werte beeinflussen beispielsweise, welche Wege und Namensdienste verfügbar werden. Manuell festgelegte Parameter sind ein anderes Einrichtungsmodell und können bei unpassender Kombination Konflikte verursachen.

IPv6 besitzt eigene Mechanismen. Insbesondere beschreibt [RFC 4861](https://www.rfc-editor.org/rfc/rfc4861.html) Router Advertisements und Nachbarschaftsfunktionen. Der gezeigte IPv4-DHCP-Ablauf darf daher nicht ungeprüft als vollständiger IPv6-Einrichtungsablauf gelesen werden. Eine Bezeichnung wie „automatisch“ verbirgt unterschiedliche technische Verfahren.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses fiktive Modell zeigt einen üblichen anfänglichen Ablauf. Es wird kein DHCP-Client gestartet und keine Adresse angefordert.

```text
DHCPDISCOVER: Der Client sucht ein geeignetes Angebot.
DHCPOFFER: Ein Server bietet eine Konfiguration an.
DHCPREQUEST: Der Client fordert die ausgewählte Zuteilung an.
DHCPACK: Der Server bestätigt sie unter den mitgeteilten Bedingungen.
```

Eine angebotene Beispielkonfiguration könnte Adresse, Präfixinformation, Router, DNS-Server und Leasezeit enthalten. Diese Werte müssten zum Netz passen. Der Text nennt bewusst keine tatsächlich vergebenen Werte dieses Rechners.

Auch nach einer Bestätigung bleibt die Funktion einzelner Dienste gesondert zu beurteilen. Ein später nicht erreichbarer Webserver beweist nicht automatisch einen fehlgeschlagenen DHCP-Ablauf. Umgekehrt ersetzt eine erhaltene Adresse keine Prüfung der weiteren benötigten Voraussetzungen. Das Modell ist keine mitgeschnittene Kommunikation und keine vollständige Zustandsmaschine.

## 7. Abgrenzung zu ähnlichen Begriffen

DNS stellt Namensinformationen bereit; DHCP kann mitteilen, welcher DNS-Dienst verwendet werden soll. Ein Router leitet Pakete weiter; DHCP kann einen passenden Router nennen. ARP behandelt lokale Adresszuordnungen. Dieselbe Hardware kann mehrere Rollen anbieten, aber die Verfahren erledigen verschiedene Aufgaben.

## 8. Häufige Missverständnisse

Eine automatisch erhaltene Adresse ist nicht zwingend dauerhaft. Die gleiche MAC-Adresse ist außerdem nicht die einzig denkbare Grundlage jeder Clientzuordnung. Eine erfolgreiche Zuteilung bedeutet nicht „das Internet funktioniert“. Auch darf eine DHCP-Antwort nicht mit einer DNS-Antwort verwechselt werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Unterscheide bei Fehlern Angebot, bestätigte Zuteilung und spätere Anwendungsfunktion. Starte keine zusätzlichen DHCP-Server oder Adresserneuerungen ohne konkreten Zweck. Dieser Eintrag verändert weder Leasezustände, Adressen, Router noch Resolvereinstellungen und untersucht keine vorhandenen Netzwerkprofile.

## 10. Verwandte Begriffe

Die [IP-Adresse](it_0139.md) ist ein möglicher Zuteilungswert. Ein [Router](it_0151.md) kann mehrere Netzrollen bündeln. [DNS](it_0148.md) bleibt für Namen zuständig. Die [MAC-Adresse](it_0154.md) gehört zu einem anderen Adresskontext. Das [Subnetz](it_0152.md) beschreibt einen Bereich.

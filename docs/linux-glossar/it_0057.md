# Konstruktor

## 1. Kurzbeschreibung

Ein Konstruktor bezeichnet je nach Sprache einen vorgesehenen Mechanismus zum Aufbau neuer Objekte. Dabei sind Erzeugung und Initialisierung zu unterscheiden. Die Quelle nennt `__init__` den Python-Konstruktor. Das ist eine verbreitete Vereinfachung: Genauer erzeugt in Python `__new__` die Instanz, während `__init__` die anschließend vorgesehene Initialisierung übernimmt.

## 2. Was bedeutet der Begriff?

Beim Aufbau eines Objekts müssen passende Anfangsbedingungen hergestellt werden. Eine Auftragsinstanz könnte etwa einen Namen und einen Anfangsstatus erhalten. Welche Methode beteiligt ist und wann sie aufgerufen wird, bestimmt das Sprachmodell.

Die [offizielle Referenz zu object.__new__](https://docs.python.org/3.13/reference/datamodel.html#object.__new__) beschreibt das Erzeugen einer neuen Instanz und den zurückgelieferten Objektwert. Die [Referenz zu object.__init__](https://docs.python.org/3.13/reference/datamodel.html#object.__init__) beschreibt die Initialisierung nach der Erzeugung. Beide Schritte gehören zum Verständnis eines gewöhnlichen Python-Klassenaufrufs, sind aber nicht dieselbe Methode.

## 3. Einfacher Vergleich aus dem Alltag

Eine leere Karte wird zunächst bereitgestellt und anschließend mit den vorgesehenen Angaben ausgefüllt. Bereitstellen und Ausfüllen gehören zum gesamten Aufbau, besitzen aber unterschiedliche Aufgaben.

Die Grenze des Vergleichs: Objekterzeugung folgt technischen Regeln und kann angepasst werden. Ein Klassenaufruf muss nicht in jedem Spezialfall genau eine neue unabhängige Einheit nach demselben Muster erzeugen. Außerdem können Erzeugung oder Initialisierung fehlschlagen; ein gewünschter Anfangszustand ist nicht allein durch den Namen einer Methode garantiert.

## 4. Wie funktioniert das?

Beim gewöhnlichen Python-Aufruf einer Klasse wird `__new__` mit der Klasse und passenden Argumenten verwendet. Es liefert die vorgesehene Instanz. Wird ein geeignetes Objekt dieses Typs zurückgegeben, erfolgt anschließend die entsprechende Initialisierung mit `__init__`.

`__init__` arbeitet an der bereits bereitgestellten Instanz. Es soll keinen neuen Objektwert zurückgeben. Ein anderer Rückgabewert als `None` ist dort unzulässig. Häufig genügt es, nur diese Initialisierung zu definieren und die geerbte Erzeugung unverändert zu nutzen.

Eine eigene Implementierung von `__new__` wird für viele alltägliche Datenklassen nicht benötigt. Das folgende Beispiel überschreibt sie nur, damit die zwei Schritte beobachtbar werden. Es ist keine Empfehlung, jede einfache Klasse mit zusätzlicher Erzeugungslogik auszustatten.

## 5. Wo begegnet mir das unter Linux?

Python-Anwendungen initialisieren Einstellungen, Ergebnisse oder Ansichtsmodelle beim Klassenaufruf. Fehler können dabei durch ungültige Eingaben oder fehlende Voraussetzungen entstehen. Eine gut verständliche Schnittstelle legt fest, welche Zustände nach erfolgreichem Aufbau gelten.

Wenn eine Initialisierung zusätzlich Dateien öffnet oder Verbindungen herstellt, ist der Ablauf nicht mehr nur eine einfache Datenzuweisung. Solche Nebenwirkungen und ihre Fehlerbehandlung müssen dokumentiert sein. Das Lernbeispiel führt bewusst keine äußeren Aktionen aus.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel protokolliert beide Schritte in einer eigenen Liste:

```python
schritte = []

class Probe:
    def __new__(cls, name):
        schritte.append("__new__")
        return super().__new__(cls)

    def __init__(self, name):
        schritte.append("__init__")
        self.name = name

objekt = Probe("Test")
assert schritte == ["__new__", "__init__"]
assert objekt.name == "Test"
print(schritte)
print(objekt.name)
```

Die Ausgabe lautet:

```text
['__new__', '__init__']
Test
```

Der erste Schritt liefert über die normale Basiserzeugung eine Instanz. Der zweite setzt deren Namen. Die gespeicherte Reihenfolge macht die Trennung sichtbar. Die Initialisierung erzeugt nicht selbst einen zweiten Rückgabegegenstand, und es wird kein GUI-Fenster aufgebaut.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Klasse beschreibt einen Typ. Ein Klassenaufruf verwendet dessen Erzeugungsregeln. Ein Initialisierer setzt Anfangsdaten. Eine Fabrikfunktion kann ebenfalls Objekte liefern, muss aber keine spezielle Sprachmethode sein. Ein gewöhnlicher Methodenaufruf an einer bestehenden Instanz ist nicht automatisch eine erneute Erzeugung.

## 8. Häufige Missverständnisse

`__init__` ist nicht die eigentliche Python-Speichererzeugungsmethode. Ein ausdrücklicher manueller Aufruf von `__init__` erzeugt nicht automatisch eine neue Instanz. Ein veränderlicher Standardparameter kann außerdem zwischen Aufrufen geteilt sein. Die Regeln anderer Sprachen sollten nicht allein anhand desselben Wortes übertragen werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Halte Anfangszustände und Eingabeanforderungen klar. Vermeide unnötige äußere Aktionen beim Aufbau einfacher Datenobjekte. Das Beispiel prüft nur eine eigene Klasse und Liste; besondere Erzeugungsfälle, Fremdbibliotheken oder Ressourceninitialisierung wurden nicht praktisch getestet.

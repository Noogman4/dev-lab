# localhost

## 1. Kurzbeschreibung

`localhost` ist ein besonderer Name für den lokalen Loopback-Zusammenhang. Damit kann ein Programm eine passende lokale Gegenstelle ansprechen, ohne einen entfernten Rechner zu meinen. Bekannt sind die IPv4-Adresse `127.0.0.1` und die IPv6-Adresse `::1`. Ob dort ein gewünschter Dienst tatsächlich erreichbar ist, bleibt eine gesonderte Frage.

## 2. Was bedeutet der Begriff?

„Local host“ bedeutet örtlich der eigene Host. [RFC 6761 zu localhost](https://www.rfc-editor.org/rfc/rfc6761.html#section-6.3) beschreibt die besondere Behandlung dieses Namens durch Anwendungen und Namensauflösung. Er ist kein gewöhnlicher frei gewählter öffentlicher Domainname, dessen Adresse man beliebig bei einem entfernten zuständigen Server suchen sollte.

Das Katalogbeispiel mit `127.0.0.1` trifft eine bekannte Verwendung. Es sollte aber nicht als vollständige Definition verstanden werden: IPv4 reserviert den Loopback-Bereich `127.0.0.0/8`, wie [RFC 1122](https://www.rfc-editor.org/rfc/rfc1122.html) beschreibt. Für IPv6 nennt [RFC 4291](https://www.rfc-editor.org/rfc/rfc4291.html) `::1` als Loopback-Adresse.

## 3. Einfacher Vergleich aus dem Alltag

Du benutzt eine interne Hauspost, um einen lokalen Arbeitsplatz zu erreichen. Die Nachricht muss dafür nicht über die öffentliche Straße zu einem anderen Gebäude transportiert werden. Trotzdem muss an der vorgesehenen Stelle jemand den passenden Auftrag annehmen.

Die Grenze: Loopback ist eine technische Netzfunktion, keine beliebige Abkürzung zur gerade gewünschten Anwendung. Adresse, Port und laufender Dienst müssen zusammenpassen. Außerdem kann die lokale Sicht in einer abgegrenzten Umgebung eine andere sein als die des gesamten physischen Rechners.

## 4. Wie funktioniert das?

Ein Programm verwendet einen lokalen Endpunkt über die vorgesehenen Netzwerkschnittstellen. Die Verwendung eines Loopback-Ziels bedeutet dabei keinen normalen Weg zu einem entfernten Gerät. Ein Dienst muss aber am passenden Endpunkt eingerichtet und betriebsbereit sein.

Linux kann Netzressourcen über Namensräume trennen. Die [offizielle Übersicht zu Netzwerk-Namensräumen](https://man7.org/linux/man-pages/man7/network_namespaces.7.html) beschreibt die Isolation unter anderem von Netzwerkgeräten, Protokollstapeln und Ports. `localhost` in einem Container bedeutet deshalb nicht automatisch den lokalen Dienst des Hostsystems außerhalb dieses Kontexts.

## 5. Wo begegnet mir das unter Linux?

Entwicklungswerkzeuge und lokale Dienste können Loopback für Kommunikation innerhalb ihrer Umgebung verwenden. Eine Anwendung kann beispielsweise eine lokale HTTP-Schnittstelle anbieten. Ein erfolgreicher Zugriff darauf sagt nichts über eine Erreichbarkeit von einem anderen Rechner aus.

Auch die Wahl zwischen IPv4 und IPv6 ist relevant. Ein nur für eine Version eingerichteter Dienst antwortet nicht allein aufgrund desselben Namens automatisch über beide. Die konkrete Einrichtung wird in diesem Eintrag weder abgefragt noch verändert.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Es prüft ausschließlich selbst gewählte Adresswerte. Es wird kein Socket geöffnet und keine Namensauflösung aufgerufen.

```python
import ipaddress

faelle = [
    ("127.0.0.1", True),
    ("127.0.0.2", True),
    ("::1", True),
    ("192.0.2.1", False),
]
for text, erwartet in faelle:
    adresse = ipaddress.ip_address(text)
    assert adresse.is_loopback is erwartet
    print(f"{adresse}: {adresse.is_loopback}")
```

Geprüfte Ausgabe:

```text
127.0.0.1: True
127.0.0.2: True
::1: True
192.0.2.1: False
```

Die [Python-Referenz zu is_loopback](https://docs.python.org/3.13/library/ipaddress.html#ipaddress.IPv4Address.is_loopback) beschreibt diese Klassifikation. Der Versuch zeigt insbesondere eine weitere IPv4-Loopback-Adresse und IPv6. Er beweist weder, wohin ein reales Programm den Namen auflöst, noch ob an einer dieser Adressen ein Dienst lauscht.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein normaler Hostname kann auf entfernte Adressen führen. Eine private IPv4-Adresse ist nicht automatisch Loopback. Ein Netzwerk-Namensraum beschreibt einen Ausführungskontext. Die Bindung einer Anwendung an beliebige Schnittstellen ist ebenfalls eine andere Entscheidung als eine Beschränkung auf einen lokalen Loopback-Endpunkt.

## 8. Häufige Missverständnisse

`localhost` heißt nicht „der andere Rechner im Heimnetz“. Die bekannte Zahl `127.0.0.1` ist außerdem nicht die gesamte IPv4-Loopback-Definition. Ein lokaler Dienst ist nicht allein durch seinen Ort automatisch ohne Zugriffsregeln sicher. Auch eine lokale Namensauflösung ersetzt keine passende Dienstkonfiguration.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Nenne bei einer Diagnose Adressversion, Port und den betroffenen Ausführungskontext. Verwechsle die Sicht eines Containers nicht mit der Hostumgebung. Dieses Beispiel verarbeitet nur Adresswerte und verändert weder Dienste, Bindungen, Namensräume noch Netzwerkparameter.

## 10. Verwandte Begriffe

Der [Hostname](it_0167.md) erklärt gewöhnliche Namenskontexte. Die [IP-Adresse](it_0139.md) ist ein Wert. Ein [Port](it_0142.md) ergänzt den Endpunkt. [IPv4](it_0140.md) und [IPv6](it_0141.md) besitzen unterschiedliche Loopback-Darstellungen. Ein [Service](it_0119.md) muss trotzdem tatsächlich arbeiten.

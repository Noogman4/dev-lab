# Assertion

## 1. Kurzbeschreibung

Eine Assertion ist eine ausdrückliche Prüfbehauptung: Eine bestimmte Bedingung soll an einer Stelle erfüllt sein. In Tests verbindet sie das beobachtete Ergebnis mit einer Erwartung. Schlägt sie fehl, muss das als Abweichung erkennbar werden. Sprach-Anweisungen und Prüffunktionen eines Testframeworks besitzen dabei eigene Regeln und dürfen nicht ungeprüft gleichgesetzt werden.

## 2. Was bedeutet der Begriff?

Die Quelle nennt `assert result == True`. Damit wird in Python eine Vergleichsbedingung geprüft. Welche Bedingung richtig ist, hängt vom Vertrag ab. Gleichheit, Wahrheitswert und Identität sind verschiedene Fragen. Beispielsweise ist die Zahl 1 bei einem Gleichheitsvergleich nicht zwingend vom booleschen Wert True unterschieden.

Die [Python-Sprachreferenz zur assert-Anweisung](https://docs.python.org/3.13/reference/simple_stmts.html#the-assert-statement) beschreibt die Auslösung von AssertionError und ausdrücklich den Einfluss des optimierten Modus. Die Aussage dieses Eintrags ist daher versions- und sprachbezogen auf das hier verwendete Python zu lesen. Andere Sprachen und Werkzeuge können andere Regeln besitzen.

## 3. Einfacher Vergleich aus dem Alltag

Vor dem Abschluss einer Inventur steht auf einer Prüfliste: „Die Zahl der erfassten Gegenstände entspricht der erwarteten Zahl.“ Wird die Behauptung nicht erfüllt, muss die Abweichung untersucht werden. Ein bloßes Abhaken ohne Vergleich liefert keinen Nachweis.

Die Grenze: Eine Softwareprüfung braucht eine technisch auswertbare Bedingung. Außerdem kann eine falsch gewählte Erwartung die eigentliche Anforderung verfehlen. Und eine nur für Entwicklungsprüfungen vorgesehene Kontrolle darf nicht stillschweigend die einzige unverzichtbare Zugangskontrolle sein.

## 4. Wie funktioniert das?

Eine Prüfung erhält eine Bedingung oder zwei zu vergleichende Werte. Beim Erfolg wird der vorgesehene Ablauf fortgesetzt. Bei einer Abweichung meldet der Mechanismus einen Fehlschlag oder löst eine entsprechende Ausnahme aus. Aussagekräftige Vergleiche erleichtern die Diagnose.

Die [unittest-Dokumentation zu assertEqual](https://docs.python.org/3.13/library/unittest.html#unittest.TestCase.assertEqual) erklärt den Vergleich erwarteter und tatsächlicher Werte und geeignete Meldungen für verschiedene Typen. Andere Methoden prüfen beispielsweise Identität oder erwartete Ausnahmen. Eine passende Methode beschreibt die Anforderung genauer als eine unklare pauschale Wahrheitsprüfung.

Bei Pythons eigener `assert`-Anweisung ist die Optimierung entscheidend: Wird Code mit `-O` kompiliert beziehungsweise ausgeführt, kann die Anweisung entfallen. Ihre Bedingung darf deshalb keine unverzichtbare produktive Aktion enthalten. Eine Rechte- oder Eingabeprüfung, die unter allen vorgesehenen Betriebsbedingungen wirken muss, braucht einen dafür geeigneten ausdrücklichen Programmablauf.

Auch eine ständig aktive Prüfung ist nur so gut wie ihre Erwartung. Wer denselben Fehler in Berechnung und erwartetes Ergebnis kopiert, kann eine Abweichung verdecken. Konkrete begründete Beispiele und passende Grenzfälle helfen, den Vertrag unabhängig zu beschreiben.

## 5. Wo begegnet mir das unter Linux?

Python-Skripte und Testframeworks verwenden Assertions auf unterschiedliche Weise. Ein Projekt muss wissen, welche Interpreteroptionen und Werkzeuge tatsächlich laufen. Ein grüner Testbericht kann nicht losgelöst von diesem Umfang beurteilt werden.

Für den folgenden Versuch wird ausschließlich ein eigenes minimales Skript erstellt. Es enthält absichtlich eine falsche Entwicklungsbehauptung. Die beiden Ausführungen werden kontrolliert beobachtet. Es werden weder Anwendungscode noch vorhandene Sicherheitsprüfungen verändert.

## 6. Konkretes Beispiel Schritt für Schritt

Das Beispiel startet in einem temporären Arbeitsordner nur den selbst erzeugten Quelltext. Die Kindprozesse ignorieren Python-Umgebungsoptionen durch `-E`. Einer verwendet zusätzlich `-O`. Der Elternprozess prüft beide Ergebnisse mit `if`, sodass seine Prüfungen auch unter `-O` ausgeführt werden. [Python-Kommandozeilenoptionen](https://docs.python.org/3.13/using/cmdline.html#cmdoption-O)

```python
from pathlib import Path
import subprocess
import sys
import tempfile

with tempfile.TemporaryDirectory() as ordner:
    datei = Path(ordner) / "eigene_assertion.py"
    datei.write_text('assert False, "Eigene Probe"\n', encoding="utf-8")
    normal = subprocess.run(
        [sys.executable, "-E", str(datei)],
        capture_output=True, text=True, timeout=5
    )
    optimiert = subprocess.run(
        [sys.executable, "-E", "-O", str(datei)],
        capture_output=True, text=True, timeout=5
    )
    assertion_gemeldet = normal.returncode == 1 and "AssertionError" in normal.stderr
    assertion_uebersprungen = optimiert.returncode == 0
    if not assertion_gemeldet or not assertion_uebersprungen:
        raise RuntimeError("Die Kindprozesse lieferten unerwartete Ergebnisse")
    print("Normaler Lauf meldet AssertionError:", assertion_gemeldet)
    print("Optimierter Lauf überspringt die Assertion:", assertion_uebersprungen)
```

Geprüfte Ausgabe:

```text
Normaler Lauf meldet AssertionError: True
Optimierter Lauf überspringt die Assertion: True
```

Der normale Lauf scheitert erwartungsgemäß. Der optimierte Lauf führt dieselbe Behauptung nicht als Prüfung aus. Das demonstriert genau diese Sprachregel, keine Fehlersicherheit beliebiger Testframeworks. Die eigene Datei wird anschließend entfernt.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Test-Assertion vergleicht Erwartungen. Eine produktive Validierung entscheidet über zulässige Eingaben. Eine Exception ist ein Mechanismus für abweichenden Kontrollfluss. Ein Testframework kann Assertion-Funktionen anbieten, die nicht bloß syntaktische Varianten der Sprach-Anweisung sind.

## 8. Häufige Missverständnisse

Wahrheit, Gleichheit und Identität sind nicht dasselbe. Python-assert muss nicht in jedem Betriebsmodus aktiv sein. Eine wichtige Aktion gehört nicht nur in eine wegoptimierbare Bedingung. Und viele Behauptungen garantieren keine richtigen Erwartungen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Formuliere die benötigte Eigenschaft genau. Verwende passende Prüffunktionen und halte produktive Sicherheitsentscheidungen ausdrücklich wirksam. Das Beispiel startet nur eigene harmlose Kindprozesse und verändert weder Dateien außerhalb seines Bereichs noch Konten oder Dienste.

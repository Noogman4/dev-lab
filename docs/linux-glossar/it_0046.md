# Knoten

## 1. Kurzbeschreibung

Ein Knoten ist ein einzelnes Element eines Beziehungsmodells, beispielsweise eines Baums oder Graphen. Verbindungen verknüpfen ihn mit anderen Knoten. Er kann Daten oder Eigenschaften tragen, muss aber kein physisches Gerät sein. Das Quellbeispiel eines Ordners passt zu einer gewählten Baumdarstellung eines Dateibestands.

## 2. Was bedeutet der Begriff?

Ein Datenmodell legt fest, was als Knoten gelten soll: ein Ordner, ein Zustand, eine Person oder ein erfundener Arbeitsschritt. Dieselbe reale Situation kann je nach Fragestellung unterschiedlich modelliert werden. Die Wahl beeinflusst, welche Beziehungen später sinnvoll abgefragt werden können.

Kennung, Beschriftung und gespeicherter Inhalt sind zu trennen. Zwei Knoten können denselben Anzeigenamen besitzen und trotzdem unterschiedliche Elemente darstellen. Umgekehrt können mehrere Verweise denselben Knoten meinen. Ein Name allein muss deshalb keine geeignete eindeutige Kennung sein.

## 3. Einfacher Vergleich aus dem Alltag

Auf einer Landkarte können Orte durch Punkte dargestellt sein. Der Punkt steht für einen ausgewählten Ort, Linien beschreiben bestimmte Verbindungen. Zwei Orte dürfen denselben Namen tragen, ohne dadurch derselbe Ort zu werden.

Die Grenze des Vergleichs: Ein technischer Knoten kann auch einen abstrakten Zustand statt eines geografischen Ortes bezeichnen. Die Lage auf einer Zeichnung muss zudem keine Bedeutung im eigentlichen Modell besitzen. Eine Linie kann Abhängigkeit, Richtung oder Erreichbarkeit ausdrücken und nicht zwangsläufig eine Straße.

## 4. Wie funktioniert das?

Ein Programm kann Knoten über Kennungen verwalten und Eigenschaften gesondert speichern. Die Graphbibliothek NetworkX akzeptiert etwa geeignete hashbare Python-Objekte als Knoten und zusätzliche Attribute als Eigenschaften. Ihre [offizielle Dokumentation zu add_node](https://networkx.org/documentation/stable/reference/classes/generated/networkx.Graph.add_node.html) beschreibt diese Trennung. Das ist eine konkrete Schnittstelle, keine Pflicht für alle Knotentypen.

Auch technische Objektidentität und gleiche Inhalte sind unterschiedlich. Das [Python-Datenmodell](https://docs.python.org/3.13/reference/datamodel.html#objects-values-and-types) unterscheidet Identität, Typ und Wert eines Objekts. Für ein eigenes Knotenmodell muss zusätzlich festgelegt werden, ob die fachliche Identität durch eine Nummer, einen Schlüssel oder eine andere Regel bestimmt wird.

## 5. Wo begegnet mir das unter Linux?

Verzeichnisansichten, Abhängigkeitsdarstellungen und Netzwerkdiagramme können Knoten verwenden. Ein Programm könnte einen Prozess oder eine Datei als Knoten darstellen, wenn das für seine Frage sinnvoll ist. Es darf dabei nicht allein aus einer gleichen Beschriftung auf dieselbe reale Entität schließen.

Ein Knoten in einer grafischen Ansicht ist außerdem nicht automatisch der zugrunde liegende Dateisystem-Inode. Solche Betriebssystembegriffe besitzen eigene technische Bedeutungen. Die abstrakte Darstellung und die tatsächlich abgefragte Systeminformation sollten getrennt dokumentiert werden.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel verwendet zwei eigene Knotendatensätze mit gleichem Namen:

```python
knoten = {
    1: {"name": "Ordner"},
    2: {"name": "Ordner"},
}
verbindungen = [(1, 2)]
assert len(knoten) == 2
assert knoten[1]["name"] == knoten[2]["name"]
assert knoten[1] is not knoten[2]
assert all(a in knoten and b in knoten for a, b in verbindungen)
for kennung, daten in knoten.items():
    print(kennung, daten["name"])
```

Die Ausgabe lautet:

```text
1 Ordner
2 Ordner
```

Die Zahlen unterscheiden die Knoten. Die Beschriftungen dürfen gleich sein. Die Verbindung verweist nur auf vorhandene Kennungen. Die Datensätze sind eigenständige Objekte. Es werden keine echten Ordner angelegt und keine Netzwerkverbindungen untersucht; NetworkX wird für dieses kleine Modell nicht benötigt.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Knoten ist ein Element, eine Kante eine Beziehung zwischen Elementen. Ein Attribut beschreibt Eigenschaften. Eine Kennung macht einen Knoten innerhalb des gewählten Modells unterscheidbar. Ein Graph umfasst Knoten und Beziehungen; ein Baum schränkt deren Struktur zusätzlich ein.

## 8. Häufige Missverständnisse

Ein Knoten muss weder einen Rechner noch eine Datei darstellen. Gleiche Anzeigenamen beweisen keine Identität. Auch muss die Zahl angeschlossener Beziehungen nicht in jedem Modell gleich interpretiert werden: Bei gerichteten Beziehungen sind eingehende und ausgehende Verbindungen zu unterscheiden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lege Identität, erlaubte Attribute und gültige Verbindungsziele fest. Prüfe beim Zusammenführen von Daten doppelte Kennungen und veraltete Verweise. Das Beispiel prüft ausschließlich die selbst angelegten Datensätze; keine reale Datei- oder Geräteidentität und keine NetworkX-Ausführung wurden getestet.

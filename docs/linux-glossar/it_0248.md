# Integrationstest

## 1. Kurzbeschreibung

Ein Integrationstest prüft das Zusammenwirken mehrerer tatsächlicher Komponenten innerhalb einer bewusst gewählten Grenze. Dazu können beispielsweise Verarbeitung und Datenbankzugriff gehören. Er untersucht damit Wechselwirkungen, die eine einzelne isolierte Prüfung nicht vollständig abdeckt. Sein Erfolg bedeutet trotzdem nicht automatisch, dass jeder vollständige Nutzerablauf oder jede produktive Umgebung geprüft wurde.

## 2. Was bedeutet der Begriff?

Die Quelle nennt GUI und Netzwerkmodul als mögliche beteiligte Teile. Das wäre ein sinnvoll zu definierender Umfang. Für diesen Eintrag wird jedoch keine bestehende Oberfläche gestartet und kein Netz angesprochen. Das eigene Beispiel verbindet eine kleine Verarbeitung mit SQLite und einem temporären Dateisystempfad.

Die [Microsoft-Dokumentation zu Integrationstests in ASP.NET Core 10](https://learn.microsoft.com/en-us/aspnet/core/test/integration-tests?view=aspnetcore-10.0) beschreibt das gemeinsame Prüfen von Komponenten einschließlich Infrastruktur. Ihre konkreten Webhost- und Frameworkwerkzeuge sind .NET-spezifisch. Die Frage nach einer passenden gemeinsamen Prüfgrenze ist allgemeiner und lässt sich auch auf Python übertragen.

## 3. Einfacher Vergleich aus dem Alltag

Ein Wasserhahn und ein Schlauch können jeweils für sich unbeschädigt sein. Erst die gemeinsame Prüfung zeigt, ob ihr Anschluss dicht zusammenpasst. Dabei werden Eigenschaften sichtbar, die bei der getrennten Betrachtung nicht geprüft wurden.

Die Grenze: Ein dichtes Anschlussstück beweist noch keine korrekte gesamte Hausinstallation. Ebenso muss ein Integrationstest benennen, welche Komponenten und Bedingungen beteiligt waren. Eine andere Datenbank oder ein anderer Betriebsmodus kann zusätzliche Wechselwirkungen erzeugen.

## 4. Wie funktioniert das?

Zunächst werden die beteiligten Teile und ihre Umgebung festgelegt. Dann werden eigene Ausgangsdaten vorbereitet und ein relevanter gemeinsamer Ablauf ausgeführt. Das Ergebnis muss an einer geeigneten Stelle beobachtet werden. Nur zu prüfen, dass ein Aufruf keine Ausnahme ausgelöst hat, kann für die gewünschte Aussage zu wenig sein.

Bei einer Datenbankintegration sind beispielsweise Datentypen, Parameterübergabe und Transaktionsgrenzen relevant. Die [Python-Dokumentation zu sqlite3.connect](https://docs.python.org/3.13/library/sqlite3.html#sqlite3.connect) beschreibt den Zugriff auf eine Datei oder eine Speicherdatenbank. Das Beispiel wählt eine echte eigene Datei und liest sie nach dem Schließen über eine neue Verbindung erneut.

Diese zweite Verbindung verhindert, dass lediglich ein noch vorhandener Python-Wert für das gespeicherte Ergebnis gehalten wird. Der bestätigte Inhalt muss tatsächlich wieder aus SQLite gelesen werden. Trotzdem prüft der Versuch keinen Stromausfall und keine Zuverlässigkeit eines fremden Datenbankservers.

Welche äußeren Teile ersetzt bleiben, gehört ebenfalls zum Bericht. Ein Test mit SQLite liefert keine automatische Freigabe derselben Anwendung unter einem anderen Datenbanksystem. Auch eine echte lokale Speicherintegration ist noch kein GUI- oder Netzwerk-End-to-End-Test.

## 5. Wo begegnet mir das unter Linux?

Projekte prüfen das Zusammenspiel mit Dateisystem, Datenbanken oder lokalen Schnittstellen. Dabei sind eigene begrenzte Testressourcen wichtig. Eine zufällig vorhandene persönliche Datenbank ist keine geeignete Grundlage für eine reproduzierbare Prüfung.

Für dieses Glossar wird ausschließlich eine neu erzeugte temporäre Datei verwendet. Es werden keine Projektmodule importiert und keine bestehenden Anwendungstests geändert. Die vorhandene SQLite-Bibliothek genügt; es wird nichts installiert und kein Server gestartet.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 und SQLite 3.46.1 ausgeführt. Es normalisiert einen eigenen Titel, speichert ihn bestätigt und liest ihn nach dem Verbindungswechsel wieder ein.

```python
from contextlib import closing
from pathlib import Path
import sqlite3
import tempfile

def speichern(datei, text):
    titel = text.strip()
    if not titel:
        raise ValueError("Titel fehlt")
    with closing(sqlite3.connect(datei)) as db:
        db.execute("CREATE TABLE notizen (id INTEGER PRIMARY KEY, titel TEXT NOT NULL)")
        db.execute("INSERT INTO notizen (titel) VALUES (?)", (titel,))
        db.commit()

def laden(datei):
    with closing(sqlite3.connect(datei)) as db:
        return db.execute("SELECT titel FROM notizen ORDER BY id").fetchall()

with tempfile.TemporaryDirectory() as ordner:
    datei = Path(ordner) / "eigene_probe.sqlite"
    speichern(datei, " Probe ")
    assert datei.is_file()
    ergebnis = laden(datei)
    assert ergebnis == [("Probe",)]
    print("Neu eingelesener Titel:", ergebnis[0][0])
    print("Bestätigte Datensätze:", len(ergebnis))
```

Geprüfte Ausgabe:

```text
Neu eingelesener Titel: Probe
Bestätigte Datensätze: 1
```

Die Speicherfunktion ist hier bewusst für eine frisch erzeugte Beispieldatei geschrieben, nicht als allgemeine wiederholt aufrufbare Datenbankverwaltung. Beide Verbindungen werden geschlossen. Danach entfernt der temporäre Bereich seine eigene Datei. Getestet wird genau der gezeigte gemeinsame Erfolgspfad, keine konkurrierenden Zugriffe oder GUI-Aktion.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Unit Test wählt eine kleinere Vertragsgrenze. Ein Integrationstest beobachtet die Zusammenarbeit mehrerer Teile. Ein vollständiger Nutzerablauf kann weitere Oberflächen und Dienste umfassen. Der Dateiname eines Tests oder das verwendete Framework bestimmt diese Grenze nicht allein.

## 8. Häufige Missverständnisse

Eine echte Datenbankverbindung prüft nicht automatisch alle Betriebsfälle. SQLite ist kein stellvertretender Beweis für jedes andere System. Keine Ausnahme bedeutet nicht immer richtige Daten. Und ein erfolgreiches gemeinsames Teilstück ist noch keine gesamte Anwendungsabnahme.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Dokumentiere beteiligte Komponenten, reale und ersetzte Teile sowie aufgeräumte Ressourcen. Prüfe die passende beobachtbare Wirkung. Die Übung verändert ausschließlich ihre eigene temporäre Datei und keine Anwendung, Testsuite, Abhängigkeiten oder Dienste.

## 10. Verwandte Begriffe

[Test](it_0246.md) erklärt Erwartungen. [Unit Test](it_0247.md) wählt eine kleinere Grenze. [SQLite](it_0193.md) führt die Speicherarbeit aus. [Transaktion](it_0202.md) bestätigt Änderungen. [Architektur](it_0218.md) ordnet die beteiligten Teile.

# Config

## 1. Kurzbeschreibung

Config ist eine Kurzform für Konfiguration. Gemeint sind Einstellungen, mit denen eine Anwendung ihr vorgesehenes Verhalten anpasst. Sie können beispielsweise Anzeigeoptionen oder Grenzwerte enthalten. Konfiguration ist weder zwingend eine einzelne Datei noch automatisch vertrauenswürdig oder fachlich gültig. Einlesen, Auswählen und Prüfen gehören zu einem vollständigen Umgang damit.

## 2. Was bedeutet der Begriff?

Die Quelle nennt eine Datei mit DNS-Servern und Optionen. Das ist ein mögliches Beispiel. Andere Programme erhalten Einstellungen über Aufrufargumente, Umgebungsvariablen, eine grafische Oberfläche oder gespeicherte Daten. Welche Quelle Vorrang besitzt, legt die Anwendung fest.

Auch das Dateiformat ist nicht universell. Python bietet beispielsweise Parser für INI-artige Daten und TOML. Die [Dokumentation zu tomllib.load](https://docs.python.org/3.13/library/tomllib.html#tomllib.load) beschreibt das Einlesen von TOML samt Umwandlung seiner Typen. Das ist eine konkrete Formatunterstützung, keine Zusage, dass jede beliebige Konfigurationsdatei damit lesbar ist.

## 3. Einfacher Vergleich aus dem Alltag

Ein Gerät kann eine Einstellung für Lautstärke und Anzeigehelligkeit besitzen. Die Einstellungen beeinflussen seine Arbeit, ohne dass für jede Änderung ein neues Gerät gebaut wird. Ein gespeicherter Wert kann beim nächsten Start wieder verwendet werden.

Die Grenze: Softwarekonfiguration kann sehr unterschiedliche Reichweite haben. Eine Einstellung verändert nur die Darstellung, eine andere beeinflusst Zugriffe oder Datenverarbeitung. Außerdem ist ein eingetragener Wert nicht automatisch sinnvoll. „Lautstärke sehr laut“ wird nicht allein durch das Aufschreiben zu einer gültigen technischen Zahl.

## 4. Wie funktioniert das?

Eine Anwendung bestimmt zuerst ihre unterstützten Einstellungen und Standardwerte. Danach werden vorhandene Quellen gelesen. Wenn mehrere Quellen denselben Schlüssel angeben, braucht es eine ausdrückliche Vorrangregel. Ein Name wie „Config“ legt diese Reihenfolge nicht fest.

Anschließend werden Werte in die benötigten Typen überführt und fachlich geprüft. Die [Python-Dokumentation zu ConfigParser-Datentypen](https://docs.python.org/3.13/library/configparser.html#supported-datatypes) erläutert, dass Werte dort zunächst als Zeichenketten vorliegen. `getint` und `getboolean` führen dafür passende Umwandlungen aus. Insbesondere ist `bool("false")` nicht die gewünschte Auswertung eines ausgeschalteten Schalters: Die Zeichenkette ist nicht leer und damit in dieser allgemeinen Prüfung wahr.

Typprüfung und Fachprüfung sind unterschiedliche Schritte. Eine gültige Ganzzahl kann trotzdem außerhalb des erlaubten Bereichs liegen. Ebenso muss geklärt werden, was bei fehlenden oder unbekannten Schlüsseln geschieht. Eine Anwendung sollte nicht stillschweigend Erfolg behaupten, wenn eine wesentliche Einstellung abgelehnt wurde.

## 5. Wo begegnet mir das unter Linux?

Programme speichern persönliche und systemweite Einstellungen an verschiedenen Orten. Die genauen Pfade und Regeln hängen vom jeweiligen Programm ab. Ein Dateiname allein sagt nicht, ob eine Einstellung sofort, nach erneutem Laden oder erst nach einem Neustart wirkt.

Dieses Glossar ändert keine solchen Dateien. Für das Beispiel genügt selbst erzeugter Text im Arbeitsspeicher. Damit lassen sich Syntax und Wertumwandlung prüfen, ohne DNS, Geräte, Dienste oder Netzwerkkonfiguration anzufassen.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Arbeitsordner ausgeführt. Es verwendet eine eigene INI-artige Zeichenkette. Die Interpolation ist für dieses kleine Modell ausdrücklich abgeschaltet; vorhandene Dateien werden weder geöffnet noch geschrieben.

```python
from configparser import ConfigParser

config = ConfigParser(interpolation=None)
config.read_string("[anzeige]\nzeilen = 25\naktiv = false\n")
zeilen = config.getint("anzeige", "zeilen")
aktiv = config.getboolean("anzeige", "aktiv")
assert 1 <= zeilen <= 1000
assert zeilen == 25 and aktiv is False

ungueltig = ConfigParser(interpolation=None)
ungueltig.read_string("[anzeige]\nzeilen = viele\n")
abgelehnt = False
try:
    ungueltig.getint("anzeige", "zeilen")
except ValueError:
    abgelehnt = True
assert abgelehnt
print("Zeilen:", zeilen)
print("Aktiv:", aktiv)
print("Ungültige Zahl abgelehnt:", abgelehnt)
```

Geprüfte Ausgabe:

```text
Zeilen: 25
Aktiv: False
Ungültige Zahl abgelehnt: True
```

Die Zahl wird umgewandelt und zusätzlich auf den selbst gewählten Bereich geprüft. Der Schalter wird als boolescher Wert gelesen. Ein nicht numerischer Text wird abgelehnt. Das Beispiel prüft keine Vorrangfolge mehrerer Quellen, keine Schreibfunktion und kein erneutes Laden einer laufenden Anwendung.

## 7. Abgrenzung zu ähnlichen Begriffen

Programmcode legt Verarbeitung fest. Konfiguration wählt vorgesehene Varianten und Werte. Laufzeitstatus beschreibt die aktuelle Situation. Nutzdaten sind der eigentliche bearbeitete Inhalt. Diese Rollen können technisch ähnlich gespeichert werden, bleiben aber fachlich unterscheidbar.

## 8. Häufige Missverständnisse

Eine lesbare Datei enthält nicht automatisch gültige Werte. Eine Zeichenkette mit „false“ ist nicht durch jeden Wahrheitsaufruf ausgeschaltet. Eine gespeicherte Änderung wirkt nicht zwingend sofort. Und es gibt keine universelle Vorrangregel für alle Programme.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Dokumentiere Typen, Grenzen, Standardwerte und wirksame Quelle. Vertrauliche Einstellungen sollten nicht beiläufig in Beispiele oder Versionshistorien geraten. Hier werden ausschließlich harmlose eigene Anzeigedaten verarbeitet und keinerlei bestehende Einstellungen verändert.

# Abstraktion

## 1. Kurzbeschreibung

Abstraktion bedeutet, für eine bestimmte Aufgabe wesentliche Eigenschaften hervorzuheben und andere Details vorerst auszublenden. Eine passende vereinfachte Sicht erleichtert Verständnis und Verwendung. Die Quelle nennt eine Klasse, die Scandetails versteckt. Eine Klasse ist dafür ein mögliches Werkzeug; Abstraktion ist jedoch nicht auf Klassen oder das bloße Verstecken von Code beschränkt.

## 2. Was bedeutet der Begriff?

Ein Modell kann beispielsweise eine Datei über einen Pfad behandeln, ohne bei jeder Operation die interne Datenträgerorganisation zu erklären. Die gewählte Sicht muss zur Frage passen. Für das Zusammensetzen eines Pfads ist die tatsächliche Speicherbelegung meist nebensächlich; für eine Wiederherstellung beschädigter Daten könnte sie entscheidend sein.

Eine Abstraktion lässt daher bewusst Details weg, beseitigt sie aber nicht. Sie sollte ihre Grenzen erkennen lassen. Wenn sich Bedingungen ändern, können zuvor ausgeblendete Eigenschaften wichtig werden, etwa Zugriffsrechte, Netzwerkfehler oder Plattformunterschiede.

## 3. Einfacher Vergleich aus dem Alltag

Ein Linienplan zeigt Haltestellen und Verbindungen, ohne jedes Gebäude oder die exakte Straßenbreite einzuzeichnen. Für die Auswahl einer Umsteigeverbindung ist das hilfreich. Für die Planung einer Baustelle würde derselbe Plan nicht genügen.

Die Grenze des Vergleichs: Softwareabstraktionen können ausführbare Operationen bereitstellen und Fehler melden. Ihre Vereinfachungen müssen als Vertrag verstanden werden. Eine bequem aussehende Methode darf nicht stillschweigend als Zusicherung sämtlicher denkbarer äußerer Bedingungen gelesen werden.

## 4. Wie funktioniert das?

Eine Schnittstelle bietet geeignete Begriffe und Operationen für den gewählten Zweck. Python unterscheidet beispielsweise reine Pfadoperationen von konkreten Dateisystemzugriffen. `PurePath`-Arten bearbeiten Pfaddarstellungen ohne Dateisystemzugriff; das erklärt die [offizielle pathlib-Dokumentation](https://docs.python.org/3.13/library/pathlib.html#pure-paths).

SQL bietet ein anderes Beispiel. Eine Anfrage beschreibt gewünschte Daten, während die Datenbank einen passenden Ausführungsweg auswählt. Die [SQLite-Erklärung zur Abfrageplanung](https://www.sqlite.org/queryplanner.html) trennt ausdrücklich das gewünschte Ergebnis vom internen Vorgehen. Daraus folgt keine Garantie, dass alle Abfragen unabhängig von Datenmenge und Indizes dieselben Kosten besitzen.

Die Qualität einer Abstraktion zeigt sich daran, ob sie passende Aufgaben verständlich ausdrückt und relevante Grenzen dokumentiert. Eine zusätzliche Schicht ohne klaren Nutzen ist nicht automatisch eine Verbesserung.

## 5. Wo begegnet mir das unter Linux?

Dateipfade, Bibliotheksschnittstellen und Datenbankanfragen abstrahieren verschiedene technische Einzelheiten. Ein Diagnoseprogramm kann Ergebnisse vereinheitlichen, obwohl verschiedene Werkzeuge sie erheben. Dabei müssen Unterschiede erhalten bleiben, wenn sie für die Interpretation wichtig sind.

Die Klasse `NetworkScanner` aus der Quelle könnte eine solche Sicht bereitstellen. Ihr Name beweist aber weder vollständige Erfassung noch gleiche Fähigkeiten aller zugrunde liegenden Verfahren. Das Dokument führt deshalb keinen echten Netzwerkscan durch.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel verwendet reine POSIX-Pfade ohne Dateisystemprüfung:

```python
from pathlib import PurePosixPath

pfad = PurePosixPath("berichte") / "probe.txt"
assert pfad.name == "probe.txt"
assert pfad.suffix == ".txt"
assert str(pfad.parent) == "berichte"
assert str(pfad) == "berichte/probe.txt"
print(pfad)
```

Die Ausgabe lautet:

```text
berichte/probe.txt
```

Das Objekt stellt Pfadbestandteile bereit, ohne manuell jedes Trennzeichen bearbeiten zu müssen. Es behauptet nicht, dass die Datei existiert oder gelesen werden darf. Genau diese Trennung macht den Zweck der Abstraktion verständlich: Hier geht es um die Darstellung eines Pfads, nicht um einen nachgewiesenen Dateiinhalt.

## 7. Abgrenzung zu ähnlichen Begriffen

Kapselung ordnet interne Zuständigkeiten und Zugriffe. Ein Interface beschreibt die zugängliche Vereinbarung. Abstraktion wählt die relevante Sicht. Eine Implementierung führt die Operationen konkret aus. Diese Begriffe ergänzen sich, sind aber nicht austauschbare Namen für dieselbe Technik.

## 8. Häufige Missverständnisse

Abstraktion bedeutet nicht einfach möglichst wenig Code zu zeigen. Eine bequemere Schnittstelle entfernt keine physikalischen oder betrieblichen Grenzen. Auch macht eine neue Klasse ein Problem nicht automatisch einfacher. Ein Modell kann für einen Zweck gut und für einen anderen ungeeignet sein.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Nenne Zweck, Zusicherungen und ausgelassene Details. Prüfe, wann Kosten oder Fehler der darunterliegenden Ebene sichtbar werden. Das Beispiel erzeugt nur einen eigenen reinen Pfadwert. Weder Dateien noch Datenbanken oder Netzwerke wurden dafür geöffnet oder verändert.

## 10. Verwandte Begriffe

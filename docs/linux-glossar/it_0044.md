# Queue

## 1. Kurzbeschreibung

Eine Queue ist eine Warteschlange. Im gewöhnlichen FIFO-Modell wird das zuerst eingereihte Element zuerst entnommen: „First In, First Out“. Die Quelle beschreibt dieses Prinzip passend. Genau genommen garantiert die Reihenfolge der Entnahme aber nicht automatisch die Reihenfolge, in der mehrere gleichzeitig laufende Bearbeitungen abgeschlossen werden.

## 2. Was bedeutet der Begriff?

Eine Warteschlange trennt das Erzeugen von Aufgaben von ihrer späteren Verarbeitung. Neue Elemente kommen hinten an, ältere werden vorn entnommen. Die konkrete Schnittstelle bestimmt, was bei leerer oder voller Schlange geschieht und ob ein Zugriff warten kann.

Nicht jede Struktur mit dem Wort Queue arbeitet ausschließlich FIFO. Eine Prioritätswarteschlange wählt nach einer anderen Regel. Für die Beurteilung eines Systems muss deshalb das tatsächlich vereinbarte Verhalten bekannt sein, nicht lediglich der Klassenname oder die sichtbare Form eines Warteschlangenfensters.

## 3. Einfacher Vergleich aus dem Alltag

An einer Kasse wird üblicherweise zuerst bedient, wer zuerst anstand. Neue Kunden stellen sich hinten an. Solange eine Person nach der anderen vollständig bedient wird, erscheinen Beginn und Abschluss in derselben Reihenfolge.

Der Vergleich hat Grenzen: Bei mehreren Bearbeitern kann ein später gestarteter kurzer Auftrag früher fertig sein. Auch können technische Warteschlangen begrenzt sein, Aufträge verwerfen oder auf freien Platz warten. Diese Regeln müssen ausdrücklich beschrieben werden; sie ergeben sich nicht allein aus der Alltagserwartung an Fairness.

## 4. Wie funktioniert das?

Für eine lokale FIFO-Verarbeitung eignet sich Pythons `collections.deque`: hinten anfügen mit `append`, vorn entnehmen mit `popleft`. Die [offizielle deque-Referenz](https://docs.python.org/3.13/library/collections.html#collections.deque) erläutert effiziente Operationen an beiden Enden. Eine `deque` kann auch anders verwendet werden; die FIFO-Disziplin entsteht durch die ausgewählten Operationen.

Bei koordinierter Verarbeitung bietet `queue.Queue` zusätzliche Warte- und Kapazitätsregeln. Eine vorherige Abfrage mit `empty()` garantiert jedoch nicht, dass ein späteres Entnehmen ohne Warten gelingt. Diesen Punkt nennt die [Queue-Dokumentation ausdrücklich](https://docs.python.org/3.13/library/queue.html#queue.Queue.empty). Zwischen zwei getrennten Operationen kann sich der gemeinsam verwendete Zustand ändern.

## 5. Wo begegnet mir das unter Linux?

Eine Anwendung kann selbst erzeugte Arbeitsaufträge sammeln und nacheinander abarbeiten. Ein Diagnosewerkzeug könnte etwa mehrere ausgewählte Dateien einreihen. Ob echte Dateizugriffe erfolgen und wie Fehler behandelt werden, bestimmt die nachfolgende Verarbeitung.

Warteschlangen lösen nicht automatisch Überlastung: Wenn länger mehr Arbeit ankommt als erledigt wird, wächst der Rückstand oder eine Kapazitätsgrenze wird erreicht. Eine sinnvolle Anzeige unterscheidet daher wartende, entnommene und tatsächlich abgeschlossene Aufgaben.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel verwendet nur erfundene Auftragsnamen und einen einzelnen Ablauf:

```python
from collections import deque

wartend = deque(["A", "B"])
wartend.append("C")
reihenfolge = []
while wartend:
    reihenfolge.append(wartend.popleft())
assert reihenfolge == ["A", "B", "C"]
assert len(wartend) == 0
print(reihenfolge)
```

Die Ausgabe lautet:

```text
['A', 'B', 'C']
```

A und B sind anfangs eingereiht. C wird hinten angehängt. Die Entnahme vorn erhält die Reihenfolge. Die Schleife endet bei leerer Schlange. Sie ist hier unproblematisch, weil kein anderer Ablauf die Struktur gleichzeitig verändert. Das Beispiel behauptet keine entsprechende Sicherheit für beliebige nebenläufige Prüf-und-Entnahme-Folgen.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Stack entnimmt das zuletzt abgelegte Element zuerst. Eine Liste erlaubt allgemeine Positionsoperationen. Eine `deque` unterstützt beide Enden und kann mehrere Zugriffsmuster umsetzen. Eine Prioritätsstruktur entscheidet nach Wichtigkeit statt ausschließlich nach Ankunft. Eine Queue ist außerdem noch kein ausführender Arbeiter.

## 8. Häufige Missverständnisse

Ein gereihter Auftrag ist noch nicht erledigt. FIFO garantiert nicht jeden Aspekt von Fairness oder Abschlussreihenfolge. Auch verhalten sich Kapazitätsgrenzen verschiedener Typen unterschiedlich: Eine begrenzte `deque` kann beim Anhängen ältere Elemente am Gegenende verwerfen, statt wie eine blockierende Queue auf Platz zu warten.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lege fest, ob Warten, Ablehnen oder Verwerfen erlaubt ist. Prüfe leere und volle Zustände sowie einen möglichen Abbruch. Das Beispiel startet keine Hintergrundarbeiter und bearbeitet keine echten Dateien. Warteverhalten und konkurrierende Zugriffe wurden nicht praktisch getestet.

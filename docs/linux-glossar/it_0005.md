# Konstante

## 1. Kurzbeschreibung

Eine Konstante ist eine Größe, deren Wert im vorgesehenen Zusammenhang unverändert bleiben soll oder durch Sprachregeln unverändert gehalten wird. Sie kann etwa eine feste Umrechnung, eine voreingestellte Grenze oder eine Protokollkennung ausdrücken. Welche Absicherung tatsächlich besteht, hängt von der Programmiersprache und der konkreten Schreibweise ab.

## 2. Was bedeutet der Begriff?

Die Glossarquelle formuliert bewusst „nicht geändert werden soll“. Für einen normalen Python-Namen ist diese Absicht entscheidend: `MAX_USERS = 100` kann eine Konstante darstellen, doch Python verbietet allein wegen der Großschreibung keine spätere Zuweisung.

Der Python-Stilleitfaden [PEP 8 zu Konstanten](https://peps.python.org/pep-0008/#constants) empfiehlt vollständig großgeschriebene Namen mit Unterstrichen, üblicherweise auf Modulebene. Module sind hier zusammengehörende Python-Codeeinheiten, häufig einzelne Dateien. Die Schreibweise dient Menschen und Werkzeugen als Hinweis. Sie ist weder ein Zugriffsschutz noch ein Beweis, dass ein Programm den Wert niemals verändert.

## 3. Einfacher Vergleich aus dem Alltag

Auf einer Spielregelkarte steht: „Eine Runde dauert fünf Minuten.“ Während der Runde verwenden alle dieselbe Grenze. Du musst die Zahl nicht bei jedem Spielzug neu festlegen.

Die Grenze des Vergleichs: Eine gedruckte Regel verhindert nicht körperlich, dass jemand eine andere Dauer benutzt. Ebenso kann eine Programmierkonvention missachtet werden. Manche Sprachen erzwingen bestimmte unveränderliche Bindungen; Python braucht für entsprechende Prüfhinweise zusätzliche Mittel. Auch eine bewusst feste Zahl kann fachlich falsch gewählt sein.

## 4. Wie funktioniert das?

Ein Name erhält bei der Einrichtung des Programms seinen Wert, und der übrige Code liest ihn. Eine spätere Produktversion darf einen anderen Standard festlegen, ohne dass das dem Zweck der Konstante widerspricht. „Konstant“ beschreibt hier die beabsichtigte Verwendung im jeweiligen Programmzusammenhang, nicht eine unveränderliche Naturzahl für alle Zeiten.

Python bietet zusätzlich `typing.Final` an. Das ist eine Typannotation, also ein Hinweis an Prüfwerkzeuge über die beabsichtigte Verwendung eines Namens. Ein Typprüfer kann eine spätere Neuzuweisung beanstanden. Die [Dokumentation zu Final](https://docs.python.org/3.13/library/typing.html#typing.Final) betont ausdrücklich, dass diese Eigenschaft zur Laufzeit nicht geprüft wird. `Final` ist seit Python 3.8 verfügbar; das folgende einfache Beispiel benötigt es nicht.

## 5. Wo begegnet mir das unter Linux?

Ein Python-Hilfsprogramm kann eine feste Kennzeichnung für sein Dateiformat oder eine voreingestellte Obergrenze zentral benennen. Ein verständlicher Name macht die Bedeutung einer sonst rätselhaften Zahl sichtbar. Mehrere Stellen können denselben Wert verwenden, ohne ihn unabhängig voneinander zu wiederholen.

Ob eine Größe wirklich fest sein sollte, ist eine Entwurfsentscheidung. Eine Benutzereinstellung wie die gewünschte Schriftgröße ist meist konfigurierbar. Eine im Code benannte Standardgröße kann dennoch konstant bleiben, während die tatsächliche Einstellung getrennt gespeichert wird. Standard und aktueller Zustand sollten nicht verwechselt werden.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses vollständige Python-3-Beispiel übernimmt die Grenze aus dem Katalog. Es verwaltet keine echten Konten:

```python
MAX_USERS = 100
aktuelle_nutzer = 99
aufnahme_erlaubt = aktuelle_nutzer < MAX_USERS
assert MAX_USERS == 100
assert aufnahme_erlaubt is True
print(MAX_USERS)
print(aufnahme_erlaubt)
```

Die Ausgabe lautet:

```text
100
True
```

Der Name `MAX_USERS` erklärt den Zweck der Zahl. Der Vergleich fragt, ob noch ein Platz frei ist. Bei einer bereits erreichten Grenze von hundert wäre die Bedingung falsch. Im Beispiel wird die Konstante ausschließlich gelesen. Die erfolgreiche Ausführung beweist diese konkrete Berechnung, aber keine technische Sperre gegen spätere Zuweisungen.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine unveränderliche Bindung und ein unveränderliches Objekt sind nicht dasselbe. Ein Listenobjekt kann verändert werden, obwohl der darauf zeigende Name nicht neu gebunden wird. Zahlenobjekte sind in Python unveränderlich, normale Namen können dennoch an andere Zahlen gebunden werden. Diesen Unterschied beschreibt das [Python-Datenmodell zu veränderlichen Objekten](https://docs.python.org/3.13/reference/datamodel.html#objects-values-and-types).

Ein Literal ist eine direkte Wertschreibweise im Code, etwa `100`. Der benannte Zusammenhang entsteht erst durch seine Verwendung, hier als Wert von `MAX_USERS`.

## 8. Häufige Missverständnisse

Großbuchstaben machen einen Python-Namen nicht schreibgeschützt. Eine Konstante garantiert außerdem keine richtige Einheit: `TIMEOUT = 5` lässt offen, ob Sekunden oder Millisekunden gemeint sind. Auch eine Annotation mit `Final` macht eine enthaltene Liste nicht automatisch unveränderlich.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Wähle Namen mit klarer Bedeutung und bei Bedarf einer Einheit. Prüfe Grenzen an ihren Übergängen, besonders bei Vergleichen mit `<` oder `<=`. Das Beispiel arbeitet nur im Speicher. Eine echte Kontenbegrenzung müsste zusätzlich gleichzeitige Anfragen und Berechtigungen berücksichtigen; die einzelne Vergleichszeile wäre dafür keine vollständige Schutzmaßnahme.

## 10. Verwandte Begriffe

[Variable](it_0004.md) erklärt Namensbindungen und ihre Veränderung. [Integer](it_0008.md) ist der hier verwendete Zahlentyp. Ein [Boolean](it_0010.md) hält das Ergebnis des Grenzvergleichs fest; [Datentyp](it_0006.md) erklärt die Eigenschaften beteiligter Werte.

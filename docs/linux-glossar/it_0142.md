# Port

## 1. Kurzbeschreibung

Ein Port ist bei Transportprotokollen wie TCP und UDP eine numerische Angabe für die Zuordnung von Kommunikation zu Endpunkten. Er ergänzt die IP-Adresse. Eine Portnummer allein bezeichnet weder ein bestimmtes Gerät noch zuverlässig die dort laufende Anwendung. Zu ihrer Bedeutung gehören mindestens der Protokoll- und Adresskontext.

## 2. Was bedeutet der Begriff?

Das Wort lässt sich mit Anschluss oder Zugang vergleichen. Im hier gemeinten Netzwerkzusammenhang geht es um eine logische Nummer, nicht um eine physische USB- oder Netzwerkbuchse. TCP und UDP verwenden jeweils 16 Bit für ihre Portfelder; möglich sind Zahlen von null bis 65535.

[RFC 6335](https://www.rfc-editor.org/rfc/rfc6335.html) beschreibt die Verwaltung von Dienstnamen und Transportportnummern. Registrierte Zuordnungen erleichtern gemeinsame Konventionen. Sie erzwingen aber nicht, dass jede tatsächlich unter dieser Nummer erreichbare Anwendung genau dem registrierten Dienst entspricht. Auch reservierte Werte dürfen nicht pauschal als frei wählbare Serverports behandelt werden.

## 3. Einfacher Vergleich aus dem Alltag

Eine Gebäudeadresse führt zu einem Haus, eine zusätzliche Durchwahl zu einer zuständigen Stelle. Dieselbe Durchwahl kann in einem anderen Gebäude etwas anderes bedeuten. Auch eine Beschriftung am Anschluss beweist nicht, wer einen Anruf tatsächlich beantwortet.

So erklärt der Vergleich die zusätzliche Unterscheidung. Die Grenze: Netzwerkendpunkte folgen technischen Regeln und können viele gleichzeitige Verbindungen bearbeiten. Ein Port ist nicht immer genau ein Mensch oder ein einzelner Prozess. Für die Abgrenzung einzelner Verbindungen kommen weitere Angaben hinzu.

## 4. Wie funktioniert das?

Transportdaten enthalten Quell- und Zielports. Ein Server stellt gewöhnlich einen bekannten Zugang bereit; ein Client verwendet für seinen eigenen Endpunkt häufig eine vorübergehend ausgewählte Nummer. Die Details der Auswahl gehören zum Betriebssystem und zur Anwendung.

TCP beschreibt eine Verbindung über zwei Endpunkte, nicht nur über den Serverport. Die [TCP-Spezifikation RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html) erläutert diese Identifikation. Deshalb können viele Clients gleichzeitig denselben Webserverport verwenden. TCP-Port 80 und UDP-Port 80 gehören außerdem zu unterschiedlichen Transportkontexten; aus der gleichen Zahl folgt keine identische Kommunikation.

## 5. Wo begegnet mir das unter Linux?

Anwendungen können einen lokalen Socket an einen passenden Endpunkt binden oder eine Gegenstelle ansprechen. Ob ein Zugriff gelingt, hängt unter anderem von laufender Anwendung, gebundener Adresse und Zugriffsregeln ab. Eine Portangabe in einer Konfiguration beweist keinen tatsächlich erreichbaren Dienst.

Das Katalogbeispiel ist passend: Für das URI-Schema `http` ist TCP-Port 80 der Standard, wenn kein anderer Port angegeben wird. Das definiert [RFC 9110 zum http-Schema](https://www.rfc-editor.org/rfc/rfc9110.html#section-4.2.1). Ein ausdrücklich gewählter anderer Port ist möglich. Die Nummer selbst fügt weder Verschlüsselung noch eine Berechtigung hinzu.

## 6. Konkretes Beispiel Schritt für Schritt

Diese Tabelle enthält fiktive Endpunkte mit einer Dokumentationsadresse. Es wird kein Socket geöffnet und kein Port geprüft.

| Adresse | Transport | Port | Betrachtung |
| --- | --- | --- | --- |
| 192.0.2.10 | TCP | 80 | Ein möglicher HTTP-Zugang |
| 192.0.2.10 | TCP | 8080 | Ein anderer TCP-Endpunkt |
| 192.0.2.10 | UDP | 80 | Eigenständiger UDP-Kontext |

Die ersten beiden Zeilen unterscheiden sich durch ihre Zielnummer. Die erste und dritte besitzen dieselbe Zahl, aber unterschiedliche Transportprotokolle. Keine Zeile behauptet, dass tatsächlich eine Anwendung erreichbar ist. Selbst beim ersten Eintrag wäre das Protokoll durch eine passende Gegenstelle zu bestätigen.

Eine reale Fehlersuche müsste daher den vollständigen gewünschten Kontext nennen. „Port 80 geht nicht“ lässt etwa Adresse, Transport und beobachteten Fehler offen. Das Gedankenbeispiel ersetzt weder einen Verbindungstest noch eine Sicherheitsprüfung.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine IP-Adresse beschreibt die Adressierung im Netz. Ein Socket ist ein konkreter Kommunikationsendpunkt beziehungsweise dessen Programmierschnittstelle. Ein Service bietet eine fachliche Funktion. Ein physischer Anschluss ist wiederum Hardware. Diese Bedeutungen teilen anschauliche Wörter, aber nicht ihre technischen Regeln.

## 8. Häufige Missverständnisse

Eine bekannte Portnummer beweist keine bekannte Anwendung. Ein geschlossener TCP-Port sagt nicht automatisch etwas über UDP derselben Zahl. Ebenso bedeutet eine eingerichtete Freigabe nicht, dass ein Programm tatsächlich lauscht. Ein Serverport muss auch nicht für jeden Client neu als andere Nummer eingerichtet werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Dokumentiere Adresse, Transport und Port gemeinsam. Ändere keine Freigaben allein aufgrund einer vermuteten Standardnummer. Der Eintrag enthält keine Scans, Listener, Firewalländerungen oder Verbindungsversuche. Alle genannten Endpunkte sind ausschließlich ein erklärendes Modell.

## 10. Verwandte Begriffe

Die [IP-Adresse](it_0139.md) liefert den Adresskontext. Ein [Socket](it_0129.md) kann einen Port verwenden. Ein [Service](it_0119.md) stellt die eigentliche Funktion bereit. Das [Netzwerk](it_0138.md) bildet den Kommunikationszusammenhang.

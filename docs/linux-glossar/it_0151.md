# Router

## 1. Kurzbeschreibung

Ein Router leitet IP-Pakete zwischen Netzen weiter. Er entscheidet anhand seiner Weiterleitungsregeln, wohin ein Paket als Nächstes gelangen soll. Ein Heimrouter bündelt häufig weitere Aufgaben wie Funkzugang, Adressvergabe oder Zugriffskontrolle. Diese zusätzlichen Funktionen sind jedoch nicht die Definition des Routings.

## 2. Was bedeutet der Begriff?

„Route“ bedeutet Weg. Der Router kennt Wege zu bestimmten Zielbereichen und verwendet sie für die Weiterleitung. [RFC 1812](https://www.rfc-editor.org/rfc/rfc1812.html) beschreibt Anforderungen an IPv4-Router und grenzt sie von Hosts ab, die nicht zwingend Pakete für andere Teilnehmer weiterleiten.

Ein Router muss kein eigenes kleines Kunststoffgerät sein. Auch ein geeignet eingerichteter Rechner kann diese Rolle übernehmen. Umgekehrt wird ein Rechner mit mehreren Netzwerkanschlüssen nicht allein durch deren Anzahl zu einem funktionsfähigen Router. Die Weiterleitung und passende Regeln müssen tatsächlich vorhanden sein.

## 3. Einfacher Vergleich aus dem Alltag

Ein Verteilzentrum schaut auf das Ziel einer Sendung und wählt den nächsten Transportweg. Es muss nicht selbst das endgültige Ziel sein. Auf einer längeren Strecke können mehrere Zentren beteiligt sein.

Das erklärt den nächsten Hop. Die Grenze: Die Auswahl folgt technischen Tabellen und Regeln, nicht einer freien Ortskenntnis. Ein Router kennt auch nicht automatisch den vollständigen Zustand jeder späteren Strecke. Eine vorgesehene Weiterleitung kann deshalb vorhanden sein, obwohl das endgültige Ziel gerade nicht erreichbar ist.

## 4. Wie funktioniert das?

Ein empfangenes Paket wird im vorgesehenen Kontext geprüft. Für die Weiterleitung wird eine geeignete Route ausgewählt. Im einfachen zielbasierten Modell spielt das am genauesten passende Präfix eine Rolle. RFC 1812 beschreibt außerdem Fehlerbehandlung und die Begrenzung der Paketlebensdauer.

Bei IPv4 wird die TTL bei der Weiterleitung entsprechend verringert. Ist ihr zulässiger Bereich verbraucht, darf das Paket nicht unbegrenzt weiterkreisen. Eine Routerkette ist deshalb nicht einfach eine grenzenlose Weitergabe derselben Daten ohne Verwaltungsinformationen.

Adressübersetzung ist eine getrennte Funktion. [RFC 3022](https://www.rfc-editor.org/rfc/rfc3022.html) beschreibt traditionelle NAT- und Portübersetzungsverfahren. Ein Gerät kann Routing und solche Übersetzungen kombinieren; Routing setzt NAT aber nicht als allgemeine Pflicht voraus.

## 5. Wo begegnet mir das unter Linux?

Ein Linux-Rechner kann einen Router als Gateway benutzen oder selbst in einer Routerrolle arbeiten. Die konkrete Einrichtung hängt von Schnittstellen, Weiterleitung, Routen und weiteren Regeln ab. Für diese Begriffserklärung ist keine Änderung solcher Einstellungen erforderlich.

Das Katalogbeispiel „Der Heimrouter verbindet LAN und Internet“ beschreibt eine typische Anordnung. Das Gerät kann dabei zugleich einen WLAN-Zugang oder andere lokale Funktionen anbieten. Ein funktionierendes WLAN-Signal beweist dennoch keine erfolgreiche Weiterleitung bis zu einem entfernten Internetdienst.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses fiktive Modell beschreibt nur eine IPv4-Weiterleitung. Es wurde kein Paket gesendet und kein Gerät abgefragt.

```text
Ein Rechner möchte das Ziel 198.51.100.20 erreichen.
Seine passende Route nennt den Router 192.0.2.1 als nächsten Hop.
Der Router empfängt das Paket und prüft seine eigene Weiterleitungsentscheidung.
Bei reiner Weiterleitung bleibt die entfernte Zieladresse maßgeblich.
Der Router gibt das Paket über den gewählten nächsten Weg weiter.
```

Die Beispieladressen behaupten keine reale Einrichtung. Der Router wird nicht dadurch zum endgültigen Empfänger einer Webanfrage, dass das Paket zuerst über ihn läuft. Eine mögliche Adressübersetzung oder ein Anwendungsproxy wären zusätzliche, hier nicht modellierte Funktionen.

Auch die erfolgreiche Annahme am ersten Router würde nicht die Antwort des entfernten Dienstes beweisen. Auf der weiteren Strecke könnten andere Regeln oder Störungen wirken. Das Gedankenmodell ist keine vollständige Simulation von Paketprüfung und Fehlerfällen.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Gateway beschreibt hier die Rolle als Übergang für einen Teilnehmer. Ein Switch vermittelt typischerweise innerhalb eines anderen Netzwerkzusammenhangs auf der Verbindungsebene. Ein Access Point stellt Funkzugang bereit. Eine Firewall regelt zulässigen Verkehr. Ein Heimgerät kann alle diese Aufgaben bündeln, ohne dass sie identisch werden.

## 8. Häufige Missverständnisse

Router bedeutet nicht automatisch WLAN. NAT und Routing sind nicht dasselbe. Auch die Adresse eines Routers muss nicht mit einer bestimmten letzten Zahl enden. Eine erreichbare Verwaltungsseite sagt schließlich nicht, dass jede Weiterleitung korrekt arbeitet.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Trenne bei einer Diagnose Zugang, Weiterleitung und Zielanwendung. Ändere Routerregeln nicht ohne konkreten Zweck, da bestehende Verbindungen betroffen sein können. Dieser Eintrag meldet sich an keinem Gerät an und verändert weder Routen noch Freigaben oder Schnittstellen.

## 10. Verwandte Begriffe

Das [Gateway](it_0150.md) bezeichnet einen möglichen Übergang. Die [IP-Adresse](it_0139.md) beschreibt das Ziel. Das [Netzwerk](it_0138.md) stellt den Zusammenhang bereit. Der [Port](it_0142.md) betrifft die Transportendpunkte, nicht allein die Auswahl des IP-Wegs.

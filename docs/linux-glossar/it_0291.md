# Compiler

## 1. Kurzbeschreibung

Ein Compiler übersetzt Programmcode in eine andere Darstellung. Das Ergebnis kann Maschinencode, eine Zwischenform oder eine andere Programmiersprache sein. Der Zielcode muss dabei die vorgesehenen Regeln der Quellsprache und die Bedingungen des Zielsystems berücksichtigen.

## 2. Was bedeutet der Begriff?

Bei C unter Linux kann ein Aufruf über GCC mehrere Werkzeuge koordinieren. Die [GCC-Referenz zu den Verarbeitungsstufen](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html) nennt Vorverarbeitung, eigentliche Kompilierung, Assemblierung und Linken. Wenn jemand vom „Compiler“ spricht, kann er also entweder die Übersetzung selbst oder den gesamten angestoßenen Ablauf meinen.

## 3. Einfacher Vergleich aus dem Alltag

Ein Übersetzer überträgt eine Arbeitsanweisung in eine andere Sprache. Der Empfänger muss sie verstehen können. Beim Kompilieren gelten zusätzlich präzise Regeln zu Typen und Rechenoperationen. Unterschiedliche Zielmaschinen benötigen oft unterschiedliche Ausgaben.

## 4. Wie funktioniert das?

Ein Compiler liest die Struktur des Codes und prüft Eigenschaften wie die Verwendung bestimmter Typen. Er kann eine Zwischenrepräsentation erzeugen und sie umformen, bevor er Zielcode ausgibt. Die [Clang-Dokumentation zu den Stufen](https://clang.llvm.org/docs/CommandGuide/clang.html) beschreibt Analyse, Codeerzeugung und Optimierung anhand eines konkreten Werkzeugs.

Der Assembler kann anschließend Anweisungen in eine Objektdatei überführen. Ein Linker verbindet Objektdateien und benötigte Bibliotheken. Dabei werden etwa Verweise auf Funktionen aufgelöst. Ein Fehler beim Linken kann auftreten, obwohl die Übersetzung einzelner Quelltexte erfolgreich war.

## 5. Wo begegnet mir das unter Linux?

Unter Linux begegnest du Compilern bei Systemsoftware und in vielen Sprachwerkzeugen. Die Zielausgabe kann für denselben Rechner oder für ein anderes System vorgesehen sein. Ein Buildsystem koordiniert dabei Aufrufe und Abhängigkeiten.

## 6. Konkretes Beispiel Schritt für Schritt

Gedankenbeispiel ohne Ausführung. Zwei kleine C-Dateien sollen zusammen eine Beispielrechnung ausführen.

1. Die erste Datei ruft eine Funktion aus der zweiten auf.
2. Der Compilerablauf erzeugt für jede Datei eine Objektdatei.
3. Ein Linker verbindet beide, wodurch der Funktionsaufruf seiner Definition zugeordnet werden kann.
4. Wenn eine Objektdatei fehlt, kann der Link-Schritt wegen der fehlenden Definition scheitern. Erst ein Testaufruf des fertigen Programms würde die Beispielrechnung prüfen.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Interpreter führt Code oder eine Zwischenform zur Laufzeit aus. Manche Systeme kombinieren Übersetzung und Interpretation. Ein [Build](it_0032.md) umfasst je nach Projekt weitere Aufgaben wie das Zusammenführen von Ressourcen oder das Erzeugen eines Pakets.

## 8. Häufige Missverständnisse

Ein erfolgreicher Compilerlauf beweist keine fachlich richtige Rechnung. Optimierung verändert unter den Regeln der Sprache die Darstellung des Programms. Eine bestimmte Option garantiert noch keine schnellere Ausführung in jeder Umgebung.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lies in einer Diagnose zuerst, welche Stufe fehlgeschlagen ist. Gib Zielarchitektur, Werkzeugversion und Optionen an, wenn sich ein Problem nur in einem bestimmten Build zeigt.

## 10. Verwandte Begriffe

# Float

## 1. Kurzbeschreibung

Ein Float ist eine Gleitkommazahl: ein Zahlentyp mit begrenzter Genauigkeit und einem großen, aber begrenzten darstellbaren Bereich. Er eignet sich beispielsweise für viele Mess- und Näherungsrechnungen. Die Quellbeschreibung „eine Zahl mit Nachkommastellen“ ist zu eng. Auch `3.0` ist in Python ein Float, während nicht jede Dezimalzahl exakt darstellbar ist.

## 2. Was bedeutet der Begriff?

Gleitkommazahlen speichern eine Zahl vereinfacht aus Vorzeichen, Ziffernanteil und einer Größenordnung. Der Name bedeutet nicht, dass im Speicher ein gedrucktes Komma herumgeschoben wird. Bei verbreiteten binären Formaten arbeiten diese Bestandteile mit Zweierpotenzen statt mit Zehnerpotenzen.

Python verwendet für `float` gewöhnlich den C-Typ `double`. Fast alle heutigen Plattformen setzen dafür das IEEE-754-Format binary64 ein. Die tatsächlichen Eigenschaften sind plattformabhängig und über `sys.float_info` feststellbar. Diese Einordnung steht in der [Referenz zu numerischen Typen](https://docs.python.org/3.13/library/stdtypes.html#numeric-types-int-float-complex). Das konkrete Ausgabe-Beispiel unten setzt die dort übliche binäre Darstellung mit 53 Bit Genauigkeit voraus und prüft diese Voraussetzung.

## 3. Einfacher Vergleich aus dem Alltag

Ein Lineal mit Millimeterstrichen kann eine Länge nicht in beliebig kleinen Schritten ablesen. Du notierst einen passenden Näherungswert. Ähnlich muss ein Float viele gewünschte Zahlen auf einen darstellbaren Wert abbilden.

Der Vergleich hat eine wichtige Grenze: Ein gewöhnliches Lineal hat gleichmäßige Abstände. Bei binären Gleitkommazahlen werden die Abstände benachbarter darstellbarer Werte bei größeren Größenordnungen größer. Außerdem sind Darstellungsfehler im Computer nicht dieselbe Unsicherheit wie ein ungenau gemessener Gegenstand. Beide können in einer Rechnung zusammentreffen, müssen aber getrennt beurteilt werden.

## 4. Wie funktioniert das?

Endlich viele Binärstellen können manche Dezimalbrüche nicht exakt ausdrücken. Das gilt etwa für `0.1`, ähnlich wie eine endliche Dezimalschreibweise ein Drittel nicht exakt wiedergibt. Der gespeicherte Wert ist eine nahe binäre Näherung. Weitere Rechenschritte können erneut runden. Das [Python-Tutorial zum Darstellungsfehler](https://docs.python.org/3.13/tutorial/floatingpoint.html#representation-error) leitet den Fall `0.1` ausführlich her.

Für Vergleiche gibt es `math.isclose`. Dabei bestimmst du eine relative und/oder absolute Toleranz, also eine erlaubte Abweichung. Die [Dokumentation zu isclose](https://docs.python.org/3.13/library/math.html#math.isclose) erklärt die Vergleichsregel und die besondere Bedeutung einer absoluten Toleranz nahe null. Eine passende Toleranz folgt aus der Aufgabe; sie sollte nicht nur so lange vergrößert werden, bis ein Test besteht.

## 5. Wo begegnet mir das unter Linux?

Programme können Zeitabstände, Übertragungsraten oder Mittelwerte als Float verarbeiten. Solche Werte werden oft gerundet angezeigt. Eine Anzeige mit zwei Nachkommastellen beweist aber weder die Messgenauigkeit noch eine intern exakt gespeicherte Dezimalzahl.

Für Stückzahlen passen häufig Integer besser. Bei Geldbeträgen können je nach Anforderungen ganze kleinste Einheiten oder eine ausdrücklich dezimale Rechenart geeigneter sein. Das ist keine pauschale Entscheidung gegen Floats: Es kommt darauf an, welche Genauigkeit und Rundungsregel die Aufgabe verlangt.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel prüft die Darstellungsannahme und rechnet mit festen Testwerten:

```python
import math
import sys

assert sys.float_info.radix == 2
assert sys.float_info.mant_dig == 53
wert = 3.14
summe = 0.1 + 0.2
assert type(wert) is float
assert summe != 0.3
assert math.isclose(summe, 0.3, rel_tol=0.0, abs_tol=1e-12)
print(wert)
print(summe)
print(summe == 0.3)
print(math.isclose(summe, 0.3, rel_tol=0.0, abs_tol=1e-12))
```

Die Ausgabe lautet auf der geprüften Plattform:

```text
3.14
0.30000000000000004
False
True
```

`3.14` übernimmt das Beispiel der Quelle. Die Addition macht anschließend einen kleinen Unterschied zur gespeicherten Näherung von `0.3` sichtbar. Der exakte Gleichheitsvergleich scheitert; der Vergleich mit der hier ausdrücklich gewählten absoluten Toleranz gelingt. Die Toleranz `1e-12` bedeutet ein Billionstel der verwendeten Einheit und ist nur für dieses Lernbeispiel festgelegt.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Integer repräsentiert ganze Zahlen. Ein Float kann auch einen ganzzahligen Wert darstellen, hat dadurch aber keinen Integer-Typ. Ein Dezimaltext wie `"3.14"` ist zunächst ein String. Eine formatierte Ausgabe verändert außerdem nur die Darstellung und macht die zugrunde liegende Rechnung nicht nachträglich dezimal exakt.

## 8. Häufige Missverständnisse

Nicht jede Float-Rechnung ist ungenau: Manche Werte und Ergebnisse sind exakt darstellbar. Umgekehrt bedeutet eine kurze Ausgabe nicht, dass keine Näherung vorliegt. Mehr angezeigte Nachkommastellen erhöhen weder die Genauigkeit einer Messung noch die Zahl intern verfügbarer Stellen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lege Einheit, erlaubte Abweichung und Rundungsregel vor der Bewertung fest. Prüfe bei externen Daten auch Sonderwerte wie Unendlich oder `NaN`, einen Wert für bestimmte ungültige numerische Ergebnisse. Das Beispiel verarbeitet keine Messgeräte und verändert keine Daten außerhalb seines Arbeitsspeichers.

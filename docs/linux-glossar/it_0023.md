# Syntax

## 1. Kurzbeschreibung

Syntax bezeichnet die formalen Schreib- und Aufbauvorschriften einer Sprache. Sie legen fest, welche Folgen von Zeichen und Sprachbestandteilen gültige Ausdrücke oder Anweisungen bilden. In Python gehört beispielsweise ein Doppelpunkt zum Kopf einer `if`-Anweisung. Gültige Syntax ist eine Voraussetzung für die Verarbeitung, aber kein Beweis für ein fachlich richtiges Programm.

## 2. Was bedeutet der Begriff?

Eine Programmiersprache besitzt eine Grammatik. Diese beschreibt, wie Namen, Operatoren, Klammern und andere Bestandteile zusammengesetzt werden dürfen. Ein Parser prüft solche Strukturen; er ist der Teil der Sprachverarbeitung, der den Aufbau erkennt.

Das [Python-Tutorial zu Syntaxfehlern](https://docs.python.org/3.13/tutorial/errors.html#syntax-errors) erklärt, dass die markierte Stelle die Position der Erkennung zeigt. Der eigentliche Grund kann davor liegen, beispielsweise bei einer fehlenden Klammer oder einem fehlenden Doppelpunkt. Eine Fehlermeldung sollte deshalb zusammen mit den benachbarten Zeilen gelesen werden.

## 3. Einfacher Vergleich aus dem Alltag

Eine Postadresse hat eine erwartete Form: Name, Straße und Hausnummer sowie Ort müssen verständlich angeordnet sein. Eine unvollständige oder widersprüchliche Struktur erschwert schon das Lesen, bevor geprüft wird, ob die Anschrift tatsächlich existiert.

Der Vergleich hat Grenzen. Menschen können manche unordentliche Adresse noch erschließen. Ein Parser folgt wesentlich genaueren Regeln. Außerdem kann eine formal richtige Adresse auf den falschen Empfänger zeigen. Entsprechend kann ein syntaktisch richtiges Programm die falsche Aufgabe erledigen.

## 4. Wie funktioniert das?

Python verwendet Schlüsselwörter und Satzzeichen zum Erkennen der Struktur. Bei mehrzeiligen zusammengesetzten Anweisungen kennzeichnet Einrückung die zugehörigen Blöcke. Die [Referenz zu zusammengesetzten Anweisungen](https://docs.python.org/3.13/reference/compound_stmts.html#compound-statements) beschreibt Kopf, Doppelpunkt und den dazugehörigen Anweisungsblock.

Syntaxregeln hängen von Sprache und Version ab. Eine Schreibweise aus einem neueren Python kann in einem älteren Interpreter ungültig sein. Ebenso ist ein gültiger Python-Ausdruck nicht automatisch ein gültiger Shell-Ausdruck. Eine reine Syntaxprüfung führt zudem nicht sämtliche Programmpfade aus und prüft keine realen Geräte oder Dienste.

## 5. Wo begegnet mir das unter Linux?

Beim Bearbeiten von Skripten, Konfigurationen oder strukturierten Textdateien können formale Fehler auftreten. Die zuständige Grammatik ist jeweils eine andere: Python, Shell und JSON haben nicht dieselben Kommentar-, Klammer- und Blockregeln.

Ein Editor kann solche Fehler früh hervorheben. Das ersetzt aber nicht die Prüfung mit dem tatsächlich vorgesehenen Werkzeug und seiner Version. Ein Programm kann außerdem erst während der Ausführung an einem fehlenden Namen oder einer ungeeigneten Operation scheitern, obwohl sein Aufbau vorher akzeptiert wurde.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel untersucht absichtlich fehlerhaften, selbst erzeugten Text. Er wird nur kompiliert, nicht ausgeführt:

```python
quelle = "if True\n    print('Hallo')\n"
fehler_erkannt = False
try:
    compile(quelle, "beispiel.py", "exec")
except SyntaxError:
    fehler_erkannt = True
    print("SyntaxError erkannt")
assert fehler_erkannt is True
if True:
    print("vollständige Anweisung")
```

Die Ausgabe lautet:

```text
SyntaxError erkannt
vollständige Anweisung
```

Im untersuchten Text fehlt der Doppelpunkt. `compile` erkennt diesen Strukturfehler. Die zweite, tatsächlich ausgeführte `if`-Anweisung besitzt Doppelpunkt und eingerückten Körper. Das komplette Lernskript wurde praktisch ausgeführt; der absichtlich ungültige Text dagegen ausschließlich einer Syntaxprüfung unterzogen.

## 7. Abgrenzung zu ähnlichen Begriffen

Syntax beschreibt den Aufbau. Semantik beschreibt die Bedeutung und Wirkung. Ein Laufzeitfehler tritt während einer Ausführung auf. Ein fachlicher Fehler kann sogar ohne Fehlermeldung bestehen bleiben, etwa wenn ein gültiger Vergleich die falsche Grenze verwendet. Formatierung und Syntax überschneiden sich in Python bei Einrückungen, sind aber nicht insgesamt dasselbe.

## 8. Häufige Missverständnisse

Eine markierte Fehlerposition muss nicht die Ursache sein. Eine bestandene Syntaxprüfung bedeutet nicht, dass Namen vorhanden, Eingaben gültig oder Ergebnisse richtig sind. Auch darf eine vertraut aussehende Zeichenfolge nicht ohne Prüfung zwischen Dateiformaten übernommen werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe zuerst die konkrete Meldung und anschließend den umgebenden Aufbau. Behalte Sprache und Version im Blick. Verändere bei der Fehlersuche möglichst nur eine nachvollziehbare Stelle. Das Beispiel verarbeitet ausschließlich fest vorgegebenen Text; fremde Inhalte werden nicht ausgeführt und vorhandene Dateien bleiben unberührt.

## 10. Verwandte Begriffe

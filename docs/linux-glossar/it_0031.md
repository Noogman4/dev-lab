# Runtime

## 1. Kurzbeschreibung

Runtime kann die Laufzeitumgebung einer Software oder die Zeit ihrer Ausführung bezeichnen. In der ersten Bedeutung geht es um die Komponenten, die Code ausführen und benötigte Funktionen bereitstellen. In der zweiten Bedeutung geht es um den Zeitraum oder die Dauer eines konkreten Ablaufs. Der Zusammenhang muss erkennen lassen, welche Bedeutung gemeint ist.

## 2. Was bedeutet der Begriff?

Eine Python-Anwendung benötigt einen geeigneten Python-Interpreter und ihre vorgesehenen Bibliotheken. Je nach Anwendung kommen Betriebssystemfunktionen oder weitere externe Komponenten hinzu. Der Quelltext allein stellt diese Voraussetzungen nicht automatisch bereit.

„Zur Laufzeit“ grenzt hingegen den Ausführungszeitpunkt von früheren Schritten wie Schreiben oder Prüfen des Quelltexts ab. „Die Laufzeit beträgt zwei Sekunden“ ist wiederum eine Dauerangabe. Diese Verwendungen hängen zusammen, beantworten aber unterschiedliche Fragen über dieselbe Software.

## 3. Einfacher Vergleich aus dem Alltag

Eine Theateraufführung braucht Bühne, Licht und geeignete Mitwirkende; das ähnelt einer Ausführungsumgebung. Die Dauer der Aufführung ist eine andere Eigenschaft. Ein vorhandenes Skript erklärt noch nicht, ob die Bühne bereitsteht oder wie lange die Aufführung dauert.

Der Vergleich hat Grenzen: Technische Laufzeitumgebungen besitzen genaue Schnittstellen und Versionen. Außerdem kann eine Ausführungsdauer von Eingaben, Auslastung und Wartezeiten abhängen. Sie ist nicht notwendig so stabil wie die geplante Länge einer einstudierten Aufführung.

## 4. Wie funktioniert das?

Die Laufzeitumgebung verarbeitet den Code nach den Regeln ihrer Implementierung. Bei Python sollte zwischen Sprachversion und Interpreterimplementierung unterschieden werden. `sys.implementation` enthält Informationen zur verwendeten Implementierung, beispielsweise den Namen `cpython`; die [offizielle Referenz](https://docs.python.org/3.13/library/sys.html#sys.implementation) erklärt, dass deren Versionsangabe nicht in jeder Implementierung dieselbe Bedeutung wie die Sprachversion hat.

Zum Messen einer kurzen verstrichenen Zeitspanne bietet Python `time.perf_counter`. Sinnvoll ist die Differenz zweier Ablesungen, nicht ihr einzelner absoluter Wert. Die [Dokumentation zu perf_counter](https://docs.python.org/3.13/library/time.html#time.perf_counter) beschreibt auch, dass Wartezeiten eingeschlossen sind. Das ist nicht dasselbe wie ausschließlich verbrauchte CPU-Zeit.

## 5. Wo begegnet mir das unter Linux?

Ein Skript kann mit einem anderen Interpreter gestartet werden als erwartet, etwa außerhalb seiner vorgesehenen virtuellen Umgebung. Fehlende Bibliotheken sind dann ein Problem der Ausführungsumgebung, nicht zwangsläufig ein Syntaxfehler im Anwendungscode.

Bei einer langsamen Diagnose muss außerdem unterschieden werden, ob tatsächlich gerechnet oder auf eine Antwort gewartet wird. Eine lange verstrichene Dauer beweist keine hohe Prozessorlast. Vergleichbare Messungen brauchen deshalb gleiche Eingaben und ausreichend bekannte Bedingungen; eine einzelne kurze Probe ist noch kein belastbarer Leistungsbenchmark.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel wurde mit CPython geprüft. Es nennt die Implementierung und misst eine kleine Berechnung:

```python
import sys
import time

start = time.perf_counter()
summe = sum(range(10))
dauer = time.perf_counter() - start
assert summe == 45
assert dauer >= 0
assert sys.implementation.name == "cpython"
print("Summe:", summe)
print("Runtime:", sys.implementation.name)
print("Zeitspanne nichtnegativ:", dauer >= 0)
```

Die Ausgabe lautet auf der geprüften Implementierung:

```text
Summe: 45
Runtime: cpython
Zeitspanne nichtnegativ: True
```

Die konkrete Dauer wird bewusst nicht als feste Erwartung ausgegeben. Sie hängt von den Ausführungsbedingungen ab. Geprüft werden das Rechenergebnis, eine nichtnegative Zeitspanne und die ausdrücklich genannte Implementierungsannahme. Andere Python-Implementierungen können einen anderen Namen liefern; das wäre kein allgemeiner Sprachfehler.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Betriebssystem stellt grundlegende Dienste bereit, ist aber nicht mit jeder sprachspezifischen Runtime identisch. Ein Interpreter ist ein zentraler Teil vieler Ausführungsumgebungen. Ein Build erzeugt Softwareartefakte; eine Runtime verwendet die dafür vorgesehene ausführbare Form. Eine Dauerangabe beschreibt einen konkreten Ablauf, keine installierte Komponente.

## 8. Häufige Missverständnisse

Eine installierte Python-Version garantiert nicht, dass alle Abhängigkeiten einer Anwendung vorhanden sind. Gleicher Quelltext bedeutet außerdem nicht automatisch gleiche Ausführungsdauer. Eine gemessene Gesamtzeit darf nicht ohne Weiteres als reine Rechenzeit ausgegeben werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Notiere Interpreter, relevante Versionen und Eingaben, wenn du Probleme vergleichst. Behaupte aus kleinen Einzelmessungen keine allgemeinen Geschwindigkeitsvorteile. Das Beispiel fragt nur die eigene Interpreterinformation ab und rechnet mit zehn eigenen Zahlen; es verändert keine installierten Laufzeitumgebungen.

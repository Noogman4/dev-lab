# Null

## 1. Kurzbeschreibung

Null bezeichnet hier einen besonderen Wert für das Fehlen eines gewöhnlichen Werts. Gemeint ist das Programmierkonzept, nicht die Zahl null. In Python übernimmt `None` häufig diese Rolle. Damit kann ein Programm etwa unterscheiden, ob eine Messung den Wert null geliefert hat oder noch gar kein Messergebnis vorliegt.

## 2. Was bedeutet der Begriff?

Die Bedeutung eines fehlenden Werts muss die jeweilige Schnittstelle erklären: Er kann „nicht angegeben“, „nicht gefunden“ oder „noch nicht ermittelt“ bedeuten. Diese Zustände sind nicht automatisch gleichbedeutend. Wenn die Anwendung sie unterscheiden muss, braucht sie zusätzliche Informationen oder getrennte Zustandswerte.

Python beschreibt `None` als Objekt, das häufig die Abwesenheit eines Werts repräsentiert. Es ist die einzige Instanz des Typs `NoneType`. Der Name kann nicht neu zugewiesen werden; das erläutert die [Referenz zu eingebauten Konstanten](https://docs.python.org/3.13/library/constants.html#None). Ein Python-Name mit dem Wert `None` existiert also durchaus. Er ist nicht dasselbe wie ein noch nie definierter Name.

## 3. Einfacher Vergleich aus dem Alltag

Ein leeres Feld auf einem Messbogen kann heißen: „Hier wurde noch nichts eingetragen.“ Ein eingetragenes `0` kann dagegen eine tatsächlich gemessene Menge beschreiben. Beides vorschnell gleichzusetzen würde die Aussage des Bogens verändern.

Der Vergleich hat Grenzen. Papier verrät ohne Erklärung nicht, ob jemand die Messung vergessen hat oder ob sie technisch unmöglich war. Auch ein Nullwert erklärt seinen Grund nicht von selbst. Ein Programm muss festlegen, welche Bedeutung in dem betreffenden Feld vereinbart ist.

## 4. Wie funktioniert das?

Ein Programm kann einen Namen zunächst an `None` binden und später einen passenden Messwert zuweisen. Mit `is None` wird geprüft, ob genau das besondere Objekt vorliegt. Ein gewöhnlicher Test auf wahr oder falsch wäre für viele Aufgaben zu ungenau, weil auch die Zahl `0` und ein leerer String in Python als falsch gelten können.

In JSON heißt der entsprechende Wert `null`. Der Standarddecoder der Python-Bibliothek übersetzt ihn in `None`; umgekehrt wird `None` als `null` kodiert. Die genaue Zuordnung steht in der [Dokumentation zu JSON-Decodern und -Encodern](https://docs.python.org/3.13/library/json.html#encoders-and-decoders). Das ist eine Übersetzungsregel dieser Schnittstelle. Daraus folgt keine universelle Identität mit Nullzeigern oder Datenbankregeln anderer Systeme.

## 5. Wo begegnet mir das unter Linux?

Ein Diagnoseprogramm kann einen noch nicht verfügbaren Sensorwert als fehlend kennzeichnen. Ein JSON-Bericht kann ein ausdrücklich unbekanntes Feld enthalten, statt eine erfundene Zahl zu speichern. Für Benutzer sollte die Oberfläche dann etwa „nicht ermittelt“ anzeigen, wenn genau das der vereinbarten Bedeutung entspricht.

Auch ein komplett fehlendes JSON-Feld und ein vorhandenes Feld mit `null` können unterschiedliche Aussagen transportieren. Welche davon gilt, entscheidet das Datenformat der Anwendung. Eine automatisch eingesetzte Standardzahl darf diesen Unterschied nicht unbeabsichtigt verdecken.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel verwendet ausschließlich selbst erzeugten JSON-Text:

```python
import json

bericht = json.loads('{"temperatur": null, "fehlerzahl": 0}')
assert bericht["temperatur"] is None
assert bericht["fehlerzahl"] == 0
assert bericht["fehlerzahl"] is not None
meldung = "nicht ermittelt" if bericht["temperatur"] is None else "vorhanden"
assert json.dumps(None) == "null"
print(meldung)
print(bericht["fehlerzahl"])
```

Die Ausgabe lautet:

```text
nicht ermittelt
0
```

Der Decoder erzeugt für `temperatur` einen vorhandenen Eintrag mit dem Wert `None`. Die Fehlerzahl bleibt eine echte Zahl. Die ausdrückliche Prüfung auf `None` verhindert, dass diese null gezählten Fehler ebenfalls als fehlende Information behandelt werden. Die abschließende Zusicherung kontrolliert auch die umgekehrte JSON-Übersetzung.

## 7. Abgrenzung zu ähnlichen Begriffen

Der Integer `0` ist eine Zahl. `False` ist ein Wahrheitswert. Der String `"None"` enthält vier Zeichen und ist kein fehlender Wert. Ein leerer String ist gültiger Text. Diese Fälle sollten nur dann zusammengefasst werden, wenn die Anwendung das ausdrücklich verlangt.

## 8. Häufige Missverständnisse

Ein Nullwert bedeutet nicht automatisch einen Fehler. Ebenso bedeutet er nicht automatisch „unbekannt“ in jeder Schnittstelle. Python schreibt `None` mit großem Anfangsbuchstaben; das JSON-Wort `null` ist kein entsprechendes Python-Schlüsselwort.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Dokumentiere die Bedeutung optionaler Felder. Rechne nicht mit einem fehlenden Messwert, als wäre er null; das könnte Mittelwerte oder Grenzprüfungen verfälschen. Das Beispiel liest keine echten Protokolle und greift auf keinen Sensor zu. Es prüft die Datenzuordnung im Speicher, nicht das Verhalten eines realen Messsystems.

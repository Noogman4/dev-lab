# Referenz

## 1. Kurzbeschreibung

Eine Referenz ist ein Verweis auf ein Objekt oder einen Speicherbereich nach den Regeln einer bestimmten Sprache. Mehrere Verweise können dasselbe Objekt bezeichnen. Die Quelle nennt diesen Fall passend. Eine Referenz ist jedoch nicht allgemein dasselbe wie eine frei verwendbare rohe Speicheradresse oder eine unabhängige Kopie des bezeichneten Inhalts.

## 2. Was bedeutet der Begriff?

Die Bedeutung hängt vom Sprachmodell ab. Python-Namen sind an Objekte gebunden; mehrere Namen können dasselbe Objekt erreichen. Das [Python-Datenmodell](https://docs.python.org/3.13/reference/datamodel.html#objects-values-and-types) unterscheidet Objektidentität, Typ und Wert. Das Gleichsein zweier Inhalte beweist dabei nicht, dass beide Zugriffe dasselbe Objekt meinen.

Rust beschreibt Referenzen als Zugriffe auf anderweitig besessene Daten mit bestimmten Gültigkeits- und Ausleihregeln. Diese erklärt das [offizielle Kapitel zu Referenzen und Borrowing](https://doc.rust-lang.org/book/ch04-02-references-and-borrowing.html). Solche Zusicherungen dürfen nicht ungeprüft auf jede Verwendung des Wortes Referenz in anderen Sprachen übertragen werden.

## 3. Einfacher Vergleich aus dem Alltag

Zwei Personen können denselben Aktenordner über unterschiedliche Vermerke finden. Wird ein Blatt im gemeinsamen Ordner ergänzt, sehen beide anschließend denselben geänderten Bestand. Das Weitergeben des Vermerks hat keine zweite unabhängige Akte erzeugt.

Die Grenze des Vergleichs: Ein technischer Verweis besitzt Sprachregeln für Gültigkeit und Zugriff. Ob Änderungen erlaubt sind und wie lange ein Objekt erreichbar bleibt, entscheidet nicht der Vergleich mit einem Papiervermerk. Auch kann eine Kopie einer äußeren Sammlung weiterhin gemeinsame innere Objekte enthalten.

## 4. Wie funktioniert das?

Bei `b = a` wird in Python der Name `b` an dasselbe Objekt gebunden, das `a` bezeichnet. Wird dieses veränderliche Objekt bearbeitet, ist die Änderung über beide Namen sichtbar. Wird `b` dagegen an ein anderes Objekt neu gebunden, ändert das nicht automatisch die Bindung von `a`.

Eine ausdrückliche Kopieroperation kann ein neues Objekt erzeugen. Dabei muss unterschieden werden, ob nur die äußere Struktur kopiert oder auch weiter enthaltene veränderliche Daten vervielfältigt werden. „Neue Liste“ bedeutet nicht automatisch „vollständig unabhängiger gesamter Objektbestand“.

Erreichbarkeit und Scope sind ebenfalls verschieden. Ein Objekt kann über einen anderen Verweis weiter erreichbar bleiben, nachdem ein lokaler Name weggefallen ist. Die konkrete Speicherfreigabe sollte nicht ohne passende Sprachzusicherung zu einem bestimmten Zeitpunkt vorausgesetzt werden.

## 5. Wo begegnet mir das unter Linux?

Eine Python-Anwendung kann dieselbe Sammlung zwischen Berechnung und Ansicht teilen. Das ist oft zweckmäßig, kann aber unerwartete Wechselwirkungen erzeugen, wenn beide Teile sie verändern. Eine vermeintliche Kopie sollte deshalb auf ihre tatsächliche Unabhängigkeit geprüft werden.

Beim Aufruf einer C-Bibliothek können zusätzliche Lebensdauer- und Eigentumsregeln gelten. Python-Namensbindungen erklären diese Fremdschnittstelle nicht vollständig. Auch symbolische Dateilinks sind Verweise in einem anderen technischen Zusammenhang und keine Python-Objektreferenzen.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel verwendet nur eine eigene Liste mit Integern:

```python
a = [1]
b = a
assert b is a
b.append(2)
assert a == [1, 2]
c = a.copy()
assert c is not a
assert c == a
c.append(3)
assert a == [1, 2]
assert c == [1, 2, 3]
print(a)
print(c)
```

Die Ausgabe lautet:

```text
[1, 2]
[1, 2, 3]
```

`a` und `b` erreichen zunächst dieselbe Liste. Die Änderung über `b` ist deshalb über `a` sichtbar. `copy` erzeugt anschließend eine neue äußere Liste. Weil dieses Beispiel nur unveränderliche Integer enthält, genügt diese Kopie für den gezeigten unabhängigen Anfügevorgang. Verschachtelte veränderliche Objekte werden damit nicht geprüft.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Kopie soll einen neuen Bestand erzeugen; ein zusätzlicher Verweis kann denselben Bestand erreichen. Ein Pointer besitzt die Regeln seiner Sprache für Speicherzugriffe. Ein Name ist die sprachliche Bezeichnung einer Bindung. Identität und Wertgleichheit beantworten unterschiedliche Fragen.

## 8. Häufige Missverständnisse

Eine Zuweisung kopiert in Python nicht automatisch den Inhalt. Gleiche Werte beweisen keine gemeinsame Identität. Ein Verweis erlaubt außerdem nicht zwingend eine Veränderung; manche Sprachen oder Schnittstellen begrenzen den Zugriff. Das Löschen eines Namens zerstört nicht grundsätzlich sofort jedes zuvor bezeichnete Objekt.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Dokumentiere gemeinsam verwendete veränderliche Daten und Kopiergrenzen. Prüfe bei Fremdschnittstellen Lebensdauer und Zuständigkeit. Das Beispiel bearbeitet ausschließlich eigene Listen. Rust-Ausleihregeln und C-Speicherzugriffe wurden nicht praktisch ausgeführt.

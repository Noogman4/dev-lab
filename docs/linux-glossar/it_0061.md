# Interface

## 1. Kurzbeschreibung

Ein Interface ist eine festgelegte Schnittstelle zwischen Beteiligten. Im objektorientierten Kontext beschreibt sie etwa erwartete Methoden, Eingaben und Ergebnisse. Die Quelle nennt ein Plugin-Interface als Beispiel. Ein Methodenname allein reicht für einen verlässlichen Vertrag nicht aus: Bedeutung, Fehlerfälle und relevante Nebenwirkungen gehören ebenfalls zur Vereinbarung.

## 2. Was bedeutet der Begriff?

Eine Schnittstelle ermöglicht Zusammenarbeit, ohne jede interne Einzelheit offenlegen zu müssen. Ein aufrufendes Programm muss wissen, was es übergeben darf und was es zurückerhält. Eine Implementierung darf innen unterschiedlich arbeiten, solange die vorgesehenen Zusicherungen eingehalten werden.

Nicht jede Sprache verwendet dafür ein eigenes Schlüsselwort `interface`. Python kann beispielsweise strukturelle Erwartungen mit `typing.Protocol` beschreiben. Die [offizielle Protocol-Referenz](https://docs.python.org/3.13/library/typing.html#typing.Protocol) erläutert dies für statische Typprüfer. Diese Beschreibung ist nicht automatisch eine vollständige Laufzeitprüfung oder eine fachliche Abnahme.

## 3. Einfacher Vergleich aus dem Alltag

Eine Steckverbindung legt Form und Belegung fest. Zwei Geräte können intern unterschiedlich aufgebaut sein und trotzdem passend zusammenarbeiten, wenn sie denselben Vertrag erfüllen. Eine ähnlich aussehende Buchse allein reicht dagegen nicht.

Die Grenze des Vergleichs: Eine Softwareschnittstelle umfasst oft wesentlich mehr als die Form eines Anschlusses. Sie kann Fehlerarten, Reihenfolgen, erlaubte Zustände und Lebensdauern festlegen. Gleich benannte Funktionen sind deshalb nicht zwangsläufig miteinander kompatibel.

## 4. Wie funktioniert das?

Der Entwurf legt benötigte Operationen und ihre Bedeutung fest. Implementierungen stellen diese bereit. Aufrufer verwenden die dokumentierte Vereinbarung. Änderungen dieser Vereinbarung können bestehende Nutzer betreffen, selbst wenn die interne Umsetzung nur klein verändert wurde.

Python bietet auch abstrakte Basisklassen. Eine mit `abstractmethod` markierte Methode muss für eine gewöhnlich instanziierbare konkrete Unterklasse entsprechend umgesetzt werden. Das beschreibt die [offizielle abstractmethod-Dokumentation](https://docs.python.org/3.13/library/abc.html#abc.abstractmethod). Diese technische Vorgabe beweist aber noch nicht, dass eine Umsetzung richtige Ergebnisse liefert oder dieselben fachlichen Bedingungen akzeptiert.

Strukturelle Protokolle und abstrakte Basisklassen sind unterschiedliche Werkzeuge. Ihre Eignung hängt davon ab, ob vorhandenes Verhalten beschrieben, eine ausdrückliche Typbeziehung vorgesehen oder bestimmte Erzeugung eingeschränkt werden soll.

## 5. Wo begegnet mir das unter Linux?

Ein Plugin-System kann festlegen, wie Erweiterungen Ergebnisse erzeugen. Bibliotheken stellen eigene aufrufbare Schnittstellen bereit. Auch Kommandozeilenprogramme oder Datendateien besitzen Vereinbarungen, obwohl sie nicht dieselbe Methodenform wie eine Python-Klasse verwenden.

Für echte Plugins müssen neben Methoden gegebenenfalls Versionszuordnung und vertrauenswürdiger Ausführungskontext betrachtet werden. Das Vorhandensein eines passenden Namens macht unbekannten Code nicht automatisch geeignet oder sicher. Das folgende Beispiel lädt deshalb keine Erweiterungen.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel beschreibt und implementiert einen kleinen Textvertrag:

```python
from abc import ABC, abstractmethod

class Ausgabe(ABC):
    @abstractmethod
    def darstellen(self, wert):
        pass

class TextAusgabe(Ausgabe):
    def darstellen(self, wert):
        return "Wert: " + str(wert)

abgelehnt = False
try:
    Ausgabe()
except TypeError:
    abgelehnt = True
assert abgelehnt
text = TextAusgabe().darstellen(3)
assert text == "Wert: 3"
print(text)
```

Die Ausgabe lautet:

```text
Wert: 3
```

Die noch abstrakte Klasse lässt sich hier nicht als fertige Ausgabe verwenden. Die konkrete Unterklasse stellt die Methode bereit. Zusätzlich wird ihr Ergebnis für einen eigenen Wert geprüft. Die Ablehnung der Basisklasse und die fachliche Ergebnisprüfung sind zwei getrennte Nachweise.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Implementierung führt den Vertrag aus. Eine Klasse kann dabei ein Werkzeug sein. Ein Protokoll kann Erwartungen strukturell beschreiben. Vererbung stellt eine Typbeziehung her. Eine API ist eine Programmierschnittstelle, die auch aus Funktionen statt Klassenmethoden bestehen kann.

## 8. Häufige Missverständnisse

Gleiche Methodennamen garantieren keine Kompatibilität. Eine Typannotation ersetzt nicht automatisch Laufzeitvalidierung. Ein erfolgreich erzeugtes Objekt beweist keine vollständige Vertragserfüllung. Auch müssen Schnittstellen nicht zwangsläufig jeden internen technischen Schritt sichtbar machen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Dokumentiere Eingaben, Ergebnisse und Fehlerbedingungen. Prüfe Implementierungen mit gemeinsamen Erwartungsfällen. Das Beispiel verwendet ausschließlich eigene Klassen; es lädt keine Plugins und führt keinen statischen Typprüfer oder reale Erweiterungsschnittstelle aus.

# Umgebungsvariable

## 1. Kurzbeschreibung

Eine Umgebungsvariable ist ein benannter Textwert in der Umgebung eines Prozesses. Programme können solche Werte als zusätzliche Eingaben verwenden, beispielsweise für Suchpfade oder Einstellungen. Die Umgebung gehört nicht zu einer einzigen automatisch gemeinsamen Variablentabelle aller Programme. Beim Start können Prozesse eine passende Umgebung an ihre Kinder weitergeben.

## 2. Was bedeutet der Begriff?

Typisch ist die Form `NAME=Wert`. Unter Linux sind Namen grundsätzlich groß- und kleinschreibungsempfindlich; Großschreibung ist eine verbreitete Konvention, keine allgemeine Bedeutungsgarantie. Welche Namen ein Programm auswertet und was sie bedeuten, legt dessen Schnittstelle fest.

Die [Linux-Handbuchseite environ](https://man7.org/linux/man-pages/man7/environ.7.html) beschreibt die Prozessumgebung und ihre Weitergabe. Die Quellbeschreibung „Eine Variable des Betriebssystems für Prozesse“ wird damit genauer: Ein Prozess besitzt seine Umgebung. Eine Änderung darin setzt nicht automatisch denselben Wert in bereits laufenden anderen Prozessen.

## 3. Einfacher Vergleich aus dem Alltag

Eine Arbeitsgruppe erhält zusammen mit einem Auftrag ein Blatt mit Einstellungen. Für eine Unteraufgabe kann sie eine Kopie mitgeben und dort einen bestimmten Hinweis ergänzen. Dadurch ändert sich das ursprüngliche Blatt der übergeordneten Stelle nicht automatisch.

Das erklärt Weitergabe und getrennte Umgebungen. Die Grenze: Ein Programm muss den jeweiligen Hinweis auch tatsächlich lesen und verstehen. Ein frei erfundener Variablenname hat keine magische Wirkung. Außerdem handelt es sich um Textwerte, nicht automatisch um geprüfte Zahlen, sichere Geheimnisse oder dauerhaft gespeicherte Konfiguration.

## 4. Wie funktioniert das?

Beim Start eines Programms kann dessen Umgebung festgelegt werden. Bei einer gewöhnlichen Vererbung stammen die Werte aus der Umgebung des Elternprozesses. Ein Startwerkzeug kann sie ergänzen, entfernen oder ersetzen. Shell-Variablen gehören dabei nicht allein durch ihre Existenz automatisch zur Umgebung gestarteter Programme; entsprechende Exportregeln sind relevant.

Python stellt mit [os.environ](https://docs.python.org/3.13/library/os.html#os.environ) eine Zuordnung für die Prozessumgebung bereit. Mit dem `env`-Argument von [subprocess.run](https://docs.python.org/3.13/library/subprocess.html#subprocess.run) lässt sich eine ausdrücklich zusammengestellte Umgebung für einen Kindprozess übergeben. Dafür muss die Elternumgebung nicht geändert werden.

## 5. Wo begegnet mir das unter Linux?

`PATH` ist ein bekanntes Beispiel: Es enthält Suchverzeichnisse für bestimmte Programmaufrufe. Andere Werte können etwa von einer konkreten Bibliothek oder Anwendung als Einstellungen ausgewertet werden. Der wirkliche Effekt ergibt sich jeweils aus deren Dokumentation und Startumgebung.

Ein Programm, das aus einem Terminal gestartet wird, kann andere Werte erhalten als dasselbe Programm über einen Desktopstarter oder Dienstmanager. Deshalb ist „im Terminal funktioniert es“ kein Beweis für identische Voraussetzungen bei jedem Startweg. Eine dauerhafte Änderung an einer Startdatei ist außerdem eine eigene Konfigurationsaktion, nicht derselbe Vorgang wie eine Umgebung nur für einen Versuch zusammenzustellen.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Es verwendet einen eigenen Testnamen und ändert nur eine Kopie der Umgebung für einen selbst gestarteten Kindprozess.

```python
import os
import subprocess
import sys

name = "NETMON_GLOSSAR_TEST_0131"
vorher = os.environ.get(name)
kind_umgebung = os.environ.copy()
kind_umgebung[name] = "Probe"
kindcode = "import os; print(os.environ['NETMON_GLOSSAR_TEST_0131'])"
ergebnis = subprocess.run(
    [sys.executable, "-c", kindcode],
    env=kind_umgebung,
    capture_output=True,
    text=True,
    timeout=5,
    check=True,
)
assert ergebnis.stdout == "Probe\n"
assert ergebnis.stderr == ""
assert os.environ.get(name) == vorher
print(ergebnis.stdout, end="")
print("Elternumgebung unverändert:", os.environ.get(name) == vorher)
```

Geprüfte Ausgabe:

```text
Probe
Elternumgebung unverändert: True
```

Der Kindprozess liest den ausdrücklich mitgegebenen Wert. Die letzte Assertion bestätigt, dass die Zuordnung im Elternprozess unverändert geblieben ist. Es werden keine bestehenden Umgebungswerte ausgegeben. Das Beispiel bearbeitet weder Shell-Startdateien noch Desktop- oder Dienstkonfigurationen.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine gewöhnliche Python-Variable ist Teil des Python-Programms und wird nicht automatisch eine Umgebungsvariable. Ein Kommandozeilenargument ist ein anderer Eingabekanal. Eine Konfigurationsdatei kann dauerhaft auf einem Datenträger liegen; die Prozessumgebung ist nicht automatisch eine solche Datei. Die Reihenfolge, in der eine Anwendung diese Eingaben berücksichtigt, ist anwendungsspezifisch.

## 8. Häufige Missverständnisse

Ein gesetzter Name verändert nichts, wenn das Programm ihn nicht auswertet. Eine Textzahl wird nicht von selbst als Integer geprüft. Änderungen in einem Kindprozess wandern außerdem nicht automatisch in den Elternprozess zurück. Auch ein großer Vorrat an Umgebungsvariablen macht einen Start nicht automatisch reproduzierbar.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Verwende dokumentierte Namen und prüfe Werte vor ihrer Nutzung. Gib nicht unnötig vertrauliche Umgebungsinhalte in Protokollen aus. Für gezielte Tests ist eine eigene Kindumgebung übersichtlich. Der Versuch verändert keine globalen oder dauerhaften Systemeinstellungen.

## 10. Verwandte Begriffe

Der [Prozess](it_0115.md) besitzt die Umgebung. Die [Shell](it_0107.md) kann Werte exportieren. [subprocess](it_0101.md) kann eine Kindumgebung festlegen. Ein [String](it_0007.md) ist der hier verwendete Werttyp und muss bei Bedarf fachlich interpretiert werden.

# Graph

## 1. Kurzbeschreibung

Ein Graph beschreibt Elemente und Beziehungen zwischen ihnen. Die Elemente heißen Knoten, die Beziehungen Kanten. Graphen können etwa Verbindungen, Abhängigkeiten oder mögliche Zustandswechsel modellieren. Das Quellbeispiel eines Netzwerks ist passend, aber ein Graph ist zunächst ein Datenmodell und keine automatisch gemessene reale Netzwerktopologie.

## 2. Was bedeutet der Begriff?

Bei einem ungerichteten Graphen besitzt eine Kante keine vorgegebene Richtung. Bei einem gerichteten Graphen führt sie von einem Ausgangsknoten zu einem Zielknoten. Ob außerdem Schleifen eines Knotens zu sich selbst oder mehrere Kanten zwischen denselben Knoten erlaubt sind, legt die konkrete Graphart fest.

Die Bibliothek NetworkX trennt beispielsweise `Graph` für ungerichtete und `DiGraph` für gerichtete Strukturen. Die [Graph-Referenz](https://networkx.org/documentation/stable/reference/classes/graph.html#networkx.Graph) und die [DiGraph-Referenz](https://networkx.org/documentation/stable/reference/classes/digraph.html#networkx.DiGraph) beschreiben diese Schnittstellen. Ihre Regeln für parallele Kanten sind Eigenschaften dieser Typen, keine allgemeine Definition sämtlicher Graphmodelle.

## 3. Einfacher Vergleich aus dem Alltag

Ein Verkehrsplan zeigt Orte und Verbindungen. Für Einbahnstraßen ist die Richtung wichtig: Eine Verbindung von A nach B bedeutet nicht automatisch eine erlaubte Fahrt von B nach A. Abgelegene Orte können im betrachteten Ausschnitt ohne Verbindung erscheinen.

Der Vergleich hat Grenzen. Ein Graph kann auch rein logische Abhängigkeiten darstellen. Die Position eines Punkts auf dem Bildschirm muss dann keine Entfernung ausdrücken. Selbst bei Verkehrsmodellen braucht eine Aussage über Fahrtzeit oder Kapazität zusätzliche Daten und passende Regeln.

## 4. Wie funktioniert das?

Ein Programm kann für jeden Knoten seine erreichbaren Nachbarn speichern. Eine Kantenliste ist eine andere mögliche Darstellung. Zusätzliche Attribute können beispielsweise Kosten oder Beschriftungen enthalten. Die Bedeutung solcher Attribute ergibt sich aus dem Modell, nicht aus einer gezeichneten Linie allein.

Beim Durchlaufen muss mit möglichen Kreisen gerechnet werden. Ein Verzeichnis besuchter Knoten verhindert, dass dieselben Beziehungen endlos erneut verfolgt werden. Für gerichtete Modelle ist zusätzlich zu klären, ob ausgehende, eingehende oder beide Verbindungsarten betrachtet werden sollen.

## 5. Wo begegnet mir das unter Linux?

Paketabhängigkeiten und Verbindungsübersichten können als Graphen dargestellt werden. Für unterschiedliche Fragestellungen entstehen unterschiedliche Knotenarten: Pakete, Prozesse oder Rechner. Ein gemeinsames Bild macht sie nicht automatisch zu derselben Art von Beziehung.

Eine Erreichbarkeitsdarstellung kann außerdem nur den Stand ihrer Datenerhebung abbilden. Ein gespeicherter Weg beweist nicht, dass eine reale Verbindung aktuell funktioniert oder erlaubt ist. Dafür wären gesonderte Messungen und eine passende Interpretation erforderlich.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel durchläuft einen eigenen gerichteten Graphen mit einem Kreis und einem isolierten Knoten:

```python
from collections import deque

graph = {"A": ["B"], "B": ["C"], "C": ["A"], "D": []}
wartend = deque(["A"])
besucht = set()
while wartend:
    aktuell = wartend.popleft()
    if aktuell in besucht:
        continue
    besucht.add(aktuell)
    wartend.extend(graph[aktuell])
assert besucht == {"A", "B", "C"}
assert "D" not in besucht
print(sorted(besucht))
```

Die Ausgabe lautet:

```text
['A', 'B', 'C']
```

A führt nach B, B nach C und C zurück nach A. Die Besuchsmenge verhindert eine endlose Wiederholung. D gehört zum Modell, wird von A aus aber nicht erreicht. Die Sortierung dient allein der stabilen Ausgabe und ist nicht die Besuchsreihenfolge.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Baum ist eine eingeschränkte Graphstruktur. Eine Liste besitzt einen linearen Ablauf. Eine Zeichnung ist nur eine mögliche Ansicht eines Graphen. Eine Messung liefert Informationen, aus denen ein Modell entstehen kann; sie ist nicht dasselbe wie das Modell selbst.

## 8. Häufige Missverständnisse

Graph bedeutet nicht automatisch Kurvendiagramm einer mathematischen Funktion. Ein Graph muss weder zusammenhängend noch kreisfrei sein. Eine Linie garantiert keine bidirektionale Verbindung. Zwei nahe gezeichnete Knoten müssen keine nahe Beziehung im modellierten System besitzen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Definiere Knotenarten, Richtung und Bedeutung der Kanten. Prüfe Kreise, fehlende Ziele und getrennte Teilstrukturen. Das Beispiel verarbeitet ausschließlich feste eigene Daten; keine Rechner werden kontaktiert und NetworkX wurde nicht praktisch verwendet.

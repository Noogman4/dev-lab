# Hash

## 1. Kurzbeschreibung

Ein Hashwert ist ein berechneter Kennwert von Daten nach einem festgelegten Verfahren. Er kann beim Vergleichen von Inhalten oder beim schnellen Zuordnen von Objekten helfen. Unterschiedliche Anwendungen benötigen unterschiedliche Eigenschaften. Ein Hash für eine interne Tabelle ist nicht automatisch eine geeignete kryptografische Prüfsumme für eine heruntergeladene Datei.

## 2. Was bedeutet der Begriff?

Bei SHA-256 besitzt das Ergebnis 256 Bit; als hexadezimaler Text wird es mit 64 Zeichen dargestellt. Für dieselben Eingabebytes entsteht mit demselben Verfahren derselbe Wert. Schon ein anderes Zeilenende gehört zu anderen Bytes, auch wenn ein Text optisch ähnlich aussieht.

Pythons `hashlib` stellt unter anderem SHA-256 bereit. Das [offizielle Verwendungsbeispiel](https://docs.python.org/3.13/library/hashlib.html#usage) unterscheidet die Bytefolge des Ergebnisses von ihrer lesbaren Hexdarstellung. Ein Hash ist keine Verschlüsselung, die mit einem Schlüssel wieder zum ursprünglichen Text entschlüsselt werden soll.

## 3. Einfacher Vergleich aus dem Alltag

Ein Kennzeichen auf einer Probe hilft, sie mit einer erwarteten Kennzeichnung zu vergleichen. Stimmen die Kennzeichnungen nicht überein, liegt ein Unterschied vor. Die Kennzeichnung ersetzt jedoch nicht die gesamte Probe.

Die Grenze des Vergleichs: Ein endlicher Hashraum kann nicht beliebig viele mögliche Eingaben eindeutig unterscheiden. Zwei verschiedene Eingaben können denselben Hashwert besitzen; das heißt Kollision. Für kryptografische Anwendungen soll es bei einem geeigneten Verfahren praktisch sehr schwer sein, eine passende Kollision gezielt zu finden. Eine mathematische Einzigartigkeitsgarantie entsteht dadurch nicht.

## 4. Wie funktioniert das?

Eine Dateiprüfung berechnet den Hash aus den tatsächlichen Bytes und vergleicht ihn mit einem erwarteten Wert. Bei unterschiedlichen Ergebnissen stimmen die geprüften Inhalte nicht überein. Bei gleichen Ergebnissen hängt die Aussagekraft vom Verfahren und vom Vertrauen in den erwarteten Wert ab.

Pythons allgemeines `hash()` verfolgt dagegen die Zuordnung in Strukturen wie Dictionaries und Sets. Die [Dokumentation zu object.__hash__](https://docs.python.org/3.13/reference/datamodel.html#object.__hash__) erklärt die Kopplung an Gleichheitsregeln und Implementierungsdetails. Insbesondere sind manche Objekt-Hashes zwischen Prozessen absichtlich verschieden. Sie eignen sich nicht als beständige allgemeine Datei-Prüfsumme.

## 5. Wo begegnet mir das unter Linux?

Downloadseiten können Prüfsummen anbieten. Werkzeuge können damit prüfen, ob eine Datei zum erwarteten Stand passt. Auch Versionsverwaltung und Datensammlungen verwenden Hashkonzepte, allerdings mit jeweils eigenen Verfahren und Zusicherungen.

Eine neben derselben manipulierten Datei angebotene Prüfsumme beweist keine vertrauenswürdige Herkunft. Dafür muss der erwartete Wert aus einer geeigneten Quelle stammen oder anderweitig authentisiert sein. Integritätsvergleich und Herkunftsnachweis sind unterschiedliche Aufgaben.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel verändert nur eine eigene Datei in einem neu angelegten temporären Ordner:

```python
import hashlib
from pathlib import Path
import tempfile

with tempfile.TemporaryDirectory() as ordner:
    datei = Path(ordner) / "probe.txt"
    datei.write_bytes(b"NetMon-Test\n")
    vorher = hashlib.sha256(datei.read_bytes()).hexdigest()
    datei.write_bytes(b"NetMon-Test!\n")
    nachher = hashlib.sha256(datei.read_bytes()).hexdigest()
    assert len(vorher) == len(nachher) == 64
    assert vorher != nachher
    print(len(vorher))
    print(vorher == nachher)
```

Die Ausgabe lautet:

```text
64
False
```

Die erste Berechnung dient als Ausgangsvergleich für die selbst gewählte Probe. Danach kommt ein Ausrufezeichen hinzu. Die Ergebnisse unterscheiden sich. Das demonstriert diesen konkreten Änderungsfall, nicht die Behauptung, dass jede denkbare unterschiedliche Eingabe zwangsläufig einen anderen Hash erzeugt.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Prüfsumme kann ebenfalls Datenunterschiede erkennen, besitzt aber nicht notwendigerweise kryptografische Eigenschaften. Eine digitale Signatur kann zusätzliche Aussagen zur Urheberschaft ermöglichen. Eine Verschlüsselung schützt den Inhalt vor unberechtigtem Lesen. Hashen allein macht eine Datei nicht geheim.

## 8. Häufige Missverständnisse

Ein gleicher Hash ist keine mathematische Garantie identischer Eingaben. Ein anderer Hash beweist nicht, warum die Daten verändert wurden. Groß geschriebene Verfahrensnamen sagen allein nichts über den Vertrauensweg der Vergleichswerte. Auch darf `hash()` nicht ungeprüft statt `hashlib` für dauerhafte Vergleiche verwendet werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Notiere das konkrete Verfahren und prüfe die tatsächlichen Bytes. Beurteile den Ursprung erwarteter Werte gesondert. Das Beispiel kontaktiert keine Downloadquelle und verändert keine bestehende Projektdatei; es entfernt nach der Prüfung nur den selbst angelegten temporären Bereich.

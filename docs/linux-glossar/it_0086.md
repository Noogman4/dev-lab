# Modul

## 1. Kurzbeschreibung

Ein Modul ist eine benannte Einheit von Code und weiteren Definitionen. In Python kann es häufig durch eine `.py`-Datei dargestellt werden. Die Quelle nennt `dns_utils.py` als Beispiel. Es gibt jedoch auch eingebaute oder anders implementierte Module; der Begriff ist nicht auf gewöhnliche Python-Textdateien beschränkt.

## 2. Was bedeutet der Begriff?

Zusammengehörige Funktionen und Werte können in einem Modul gebündelt werden. Anderer Code verwendet diese Einheit über einen vorgesehenen Import und die bereitgestellten Namen. Das kann Wiederverwendung und überschaubare Zuständigkeiten erleichtern.

Das [offizielle Python-Tutorial zu Modulen](https://docs.python.org/3.13/tutorial/modules.html#modules) beschreibt Dateien mit Definitionen und Anweisungen. Ein Modul besitzt einen eigenen Namensraum. Ein dort definierter Name ist nicht allein deshalb automatisch ein gleichnamiger lokaler Name an jeder verwendenden Stelle.

## 3. Einfacher Vergleich aus dem Alltag

Ein beschrifteter Werkzeugkasten bündelt passende Werkzeuge. Andere Aufgaben können denselben Kasten verwenden, ohne seinen gesamten Inhalt erneut zusammenstellen zu müssen. Die Beschriftung hilft, den passenden Bestandteil zu finden.

Die Grenze des Vergleichs: Ein Import kann Initialisierungscode ausführen und einen gemeinsam verwendeten Zustand bereitstellen. Ein Modul ist kein garantiert unveränderlicher Vorratsbehälter. Auch kann ein unpassender Suchpfad dazu führen, dass eine andere Einheit mit demselben Namen geladen wird.

## 4. Wie funktioniert das?

Python sucht und lädt ein Modul nach seinen Importregeln. Bei erfolgreicher Verarbeitung entsteht ein Modulobjekt mit zugänglichen Attributen. Enthaltene Anweisungen können beim Laden ausgeführt werden; ein Import ist deshalb nicht grundsätzlich eine rein passive Textzuordnung.

Die [offizielle Erklärung des Modulcaches](https://docs.python.org/3.13/reference/import.html#the-module-cache) beschreibt die Rolle von `sys.modules`. Ein normaler erneuter Import desselben bereits geladenen Namens verwendet in demselben Prozess gewöhnlich den vorhandenen Eintrag. Er ist nicht automatisch ein neues unabhängiges Ausführen aller Definitionen.

Diese Aussage ist keine allgemeine Garantie für manuelles Nachladen, veränderte Cache-Einträge oder verschiedene Prozesse. Suchpfad, Modulname und die gewählte Ladeschnittstelle gehören zum betrachteten Ablauf.

## 5. Wo begegnet mir das unter Linux?

Python-Projekte gliedern Funktionen in Module für Auswertung, Darstellung oder Hilfsaufgaben. Ein Modulname sollte zu seiner dokumentierten Aufgabe passen. Eine Datei namens `dns_utils.py` muss jedoch nicht automatisch eine gültige oder vollständige DNS-Prüfung enthalten.

Für eine Diagnose ist außerdem wichtig, welcher Modulstand tatsächlich verwendet wird. Ein anderer Interpreter oder Suchpfad kann andere Dateien finden. Das Bearbeiten einer erwarteten Datei beweist deshalb noch nicht, dass ein bereits laufender Prozess sie neu eingelesen hat.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel erzeugt nur ein eigenes Modul in einem temporären Ordner und importiert es in einem eigenen Prozess:

```python
from pathlib import Path
import subprocess
import sys
import tempfile

with tempfile.TemporaryDirectory() as ordner:
    datei = Path(ordner) / "glossar_probe.py"
    datei.write_text(
        "def normalisieren(text):\n    return text.strip().lower()\n",
        encoding="utf-8",
    )
    code = (
        "import sys\n"
        "sys.path.insert(0, sys.argv[1])\n"
        "import glossar_probe as a\n"
        "import glossar_probe as b\n"
        "assert a is b\n"
        "print(a.normalisieren(' Beispiel '))\n"
        "print(a is b)\n"
    )
    ergebnis = subprocess.run(
        [sys.executable, "-I", "-B", "-c", code, ordner],
        cwd=ordner,
        capture_output=True,
        text=True,
        check=True,
        timeout=5,
    )
    assert ergebnis.stdout == "beispiel\nTrue\n"
    print(ergebnis.stdout, end="")
```

Die Ausgabe lautet:

```text
beispiel
True
```

Die Moduldatei stellt eine reine Textfunktion bereit. Der Kindprozess startet im [isolierten Python-Modus](https://docs.python.org/3.13/using/cmdline.html#cmdoption-I) und fügt den eigenen Testordner ausdrücklich zum Suchpfad hinzu. So ist der Import unabhängig davon, ob Python das Arbeitsverzeichnis automatisch durchsucht. Zwei Importe erreichen dasselbe Modulobjekt. Der Test prüft dessen Identität und das Funktionsergebnis.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Funktion ist ein kleinerer aufrufbarer Baustein. Ein Modul ist eine benannte Organisationseinheit. Eine Bibliothek kann aus mehreren solchen Einheiten bestehen. Ein Import ist der verwendete Mechanismus, nicht das Modul selbst. Eine Datei ist eine mögliche Repräsentation, aber keine vollständige Definition des Begriffs.

## 8. Häufige Missverständnisse

Nicht jedes Modul liegt als `.py`-Datei vor. Erneutes Importieren erzeugt nicht zwangsläufig einen frischen Zustand. Gleiche Namen beweisen nicht dieselbe Herkunft. Ein Import kann außerdem Fehler oder unerwünschte Initialisierungswirkungen verursachen, wenn der geladene Code sie enthält.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Gliedere nach verständlichen Aufgaben und beachte Suchpfade. Vermeide unbeabsichtigte Namen, die wichtige Module verdecken. Das Beispiel schreibt nur eigene temporäre Dateien und prüft einen eigenen Prozess; Projektmodule und Fremdimporte wurden nicht ausgeführt.

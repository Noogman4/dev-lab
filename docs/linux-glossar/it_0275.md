# Wheel

## 1. Kurzbeschreibung

Ein Wheel ist ein fertiges Distributionsartefakt für Python. Die Dateiendung lautet `.whl`. Installationswerkzeuge können ein passendes Wheel verwenden, ohne das Projekt beim Installieren aus seiner Quelldistribution bauen zu müssen.

## 2. Was bedeutet der Begriff?

„Binäres Distributionsformat“ ist die Bezeichnung der [Wheel-Spezifikation](https://packaging.python.org/en/latest/specifications/binary-distribution-format/). Ein Wheel ist technisch ein ZIP-Archiv mit festgelegtem Aufbau. Es kann reine Python-Dateien enthalten oder native, bereits übersetzte Erweiterungen. Diese Möglichkeit macht den Inhalt abhängig vom konkreten Paket.

## 3. Einfacher Vergleich aus dem Alltag

Ein montierter Schreibtischeinsatz ist schon für den Einbau vorbereitet. Seine Maße müssen dennoch zur Schublade passen. Bei einem Wheel stehen vergleichbare Kompatibilitätsangaben im Dateinamen. Ein Installer muss außerdem die Metadaten im Inneren nach den Formatregeln verarbeiten.

## 4. Wie funktioniert das?

Der Dateiname enthält neben Projekt und Version auch Tags für Python, ABI und Plattform. Eine ABI ist die binäre Schnittstelle, über die kompilierte Bestandteile zusammenarbeiten. Die [Spezifikation der Kompatibilitäts-Tags](https://packaging.python.org/en/latest/specifications/platform-compatibility-tags/) erklärt, welche Kombinationen eine Umgebung unterstützen kann. `py3-none-any` beschreibt ein Beispiel ohne spezifische Plattform oder ABI. Weitere Beschränkungen können trotzdem in den Projektmetadaten stehen.

Ein Wheel enthält im Verzeichnis `.dist-info` die Pflichtdatei `RECORD`. Dort führt sie die Dateien des Archivs auf. Historische Signaturdateien sind von dieser Liste ausgenommen. Bei der Installation legt das Werkzeug die Dateien nach seinem Installationsschema ab und aktualisiert `RECORD` mit den installierten Pfaden. [PyPA-Spezifikation zum Wheel-Format](https://packaging.python.org/en/latest/specifications/binary-distribution-format/#the-dist-info-directory)

## 5. Wo begegnet mir das unter Linux?

Unter Linux sind manche Wheels plattformneutral, andere auf Architektur und Laufzeitumgebung zugeschnitten. Zwei Rechner mit derselben Python-Hauptversion können deshalb unterschiedliche Wheels benötigen. Für Linux-Plattform-Tags können beispielsweise die Anforderungen an Systembibliotheken eine Rolle spielen.

## 6. Konkretes Beispiel Schritt für Schritt

Das Beispiel liest ausschließlich einen erfundenen Dateinamen aus. Die drei letzten Komponenten entsprechen im Modell Python, ABI und Plattform.

```python
name = "notizbeispiel-0.1.0-py3-none-any.whl"
assert name.endswith(".whl")
_, python_tag, abi_tag, platform_tag = name[:-4].rsplit("-", 3)
assert (python_tag, abi_tag, platform_tag) == ("py3", "none", "any")
print(python_tag, abi_tag, platform_tag)
```

Die erwartete Ausgabe ist `py3 none any`. Der Code analysiert diesen Namen. Ob eine echte Datei dem Format entspricht, würde eine separate Prüfung erfordern.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Quelldistribution liefert Quellen und Angaben für einen späteren Build. Ein Wheel liefert ein vorbereitetes Ergebnis für eine passende Python-Umgebung. Ein Debian-Paket hat ein eigenes Format und richtet sich an die Paketverwaltung des Systems.

## 8. Häufige Missverständnisse

„Any“ im Plattform-Tag beseitigt weder zusätzliche Projektanforderungen noch externe Systemvoraussetzungen. Auch der Dateiname allein belegt weder Integrität noch Herkunft. Beim Umbenennen ändert sich der Inhalt nicht.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Achte auf Herkunft und die für deine Umgebung vorgesehenen Tags. Unterscheide Projektname, Version und Zielumgebung. Bei einem unerwarteten Build lohnt ein Blick darauf, ob für genau diese Plattform ein passendes Wheel verfügbar war.

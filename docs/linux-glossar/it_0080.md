# Frame

## 1. Kurzbeschreibung

Ein Frame ist im hier gemeinten GUI-Kontext ein Container für andere Oberflächenelemente. Er kann zusammengehörige Einstellungen oder Aktionen gruppieren. Die Quelle nennt Netzwerkeinstellungen als Beispiel. Ein Frame muss dafür keinen sichtbaren Rahmen zeichnen und ist nicht automatisch ein eigenständiges Fenster.

## 2. Was bedeutet der Begriff?

Eine Oberfläche kann in kleinere Bereiche unterteilt werden. Jeder Bereich enthält passende Kinder und kann eigene Anordnungsregeln besitzen. Dadurch müssen nicht alle Elemente auf derselben Ebene des Hauptfensters verwaltet werden.

Die [offizielle Python-Referenz zu ttk.Frame](https://docs.python.org/3.13/library/tkinter.ttk.html#tkinter.ttk.Frame) beschreibt den Widget-Typ. Das [Tk-Handbuch zum Frame](https://raw.githubusercontent.com/tcltk/tk/core-8-6-branch/doc/ttk_frame.n) erläutert seine Containerrolle. Das ist eine bestimmte Toolkit-Ausprägung; andere Bibliotheken können ähnliche Gruppierungen unter anderen Namen anbieten.

## 3. Einfacher Vergleich aus dem Alltag

Ein Sortierkasten gruppiert zusammengehörige Teile in Bereichen. Die Trennung erleichtert Zuständigkeit und Orientierung. Die einzelnen Teile bleiben trotzdem eigene Gegenstände mit jeweils eigenen Aufgaben.

Die Grenze des Vergleichs: Ein Softwarecontainer besitzt technische Elternbeziehungen und Lebensdauerregeln. Ein äußerlich unsichtbarer Bereich kann weiterhin existieren. Auch entscheidet eine Gruppierung allein nicht, wie viel Platz ihre Kinder erhalten oder ob sie bedienbar angeordnet sind.

## 4. Wie funktioniert das?

Beim Erzeugen eines Kind-Widgets wird sein übergeordnetes Element angegeben. Ein Frame kann wiederum Kind eines anderen Containers sein. Dadurch entsteht eine Hierarchie. Ein Layoutmanager ordnet anschließend die Kinder innerhalb ihrer jeweiligen Zuständigkeit an.

Hierarchie und Layout sind getrennt: Ein Kind kann korrekt zugeordnet, aber noch nicht passend sichtbar angeordnet sein. Ebenso macht eine verschachtelte Struktur zusätzliche Zeilen- und Spaltenregeln nicht automatisch richtig. Zu viele Ebenen können die Größenverteilung schwer verständlich machen.

Bei Tk entfernt `destroy` ein Fenster beziehungsweise Widget und seine Nachfahren. Das beschreibt das [offizielle destroy-Handbuch](https://raw.githubusercontent.com/tcltk/tk/core-8-6-branch/doc/destroy.n). Weiter vorhandene Python-Verweise sind deshalb kein Beweis, dass die zugehörigen Toolkit-Elemente noch existieren oder normal weiterverwendet werden können.

## 5. Wo begegnet mir das unter Linux?

Tkinter-Anwendungen können Eingabefelder, Beschriftungen und Aktionen in Frames gruppieren. Ein Bereich für Netzwerkeinstellungen kann so eine eigene interne Anordnung erhalten. Diese Gruppierung ändert selbst keine Netzwerkeinstellung.

Ein Frame ist außerdem nicht dasselbe wie ein Netzwerkframe oder ein einzelnes Bild einer Videofolge. Dasselbe Wort besitzt in anderen Fachgebieten andere Bedeutungen. Die Quellkategorie und der Anwendungskontext legen hier die GUI-Rolle fest.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel prüft nur eine eigene verborgene Tk-Hierarchie unter dem virtuellen Bildschirm:

```python
# GUI-Prüfung im virtuellen Bildschirm
import tkinter as tk
from tkinter import ttk

root = tk.Tk()
root.withdraw()
try:
    aussen = ttk.Frame(root)
    innen = ttk.Frame(aussen)
    text = ttk.Label(innen, text="Eigene Probe")
    assert innen.master is aussen
    assert text.master is innen
    assert len(innen.winfo_children()) == 1
    print(len(innen.winfo_children()))
    innen.destroy()
    assert text.winfo_exists() == 0
    assert aussen.winfo_exists() == 1
    print(text.winfo_exists())
finally:
    root.destroy()
```

Die Ausgabe lautet:

```text
1
0
```

Der innere Frame enthält das eigene Label. Danach wird dieser Frame zerstört, und das Kind existiert auf Toolkit-Ebene nicht mehr. Der äußere Frame bleibt vorhanden. Es werden keine realen Einstellungen entfernt; das Beispiel untersucht nur seine selbst erzeugten Oberflächenelemente.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Layoutmanager berechnet Anordnung und Größen. Ein Frame stellt einen Container bereit. Ein Label zeigt Inhalt. Ein eigenständiges Fenster besitzt zusätzliche Fenstermanagerregeln. Ein Frame mit Titel oder besonderer Umrandung kann in einer Bibliothek wiederum ein eigener Typ sein.

## 8. Häufige Missverständnisse

Ein Frame muss keinen sichtbaren Rand haben. Die Containerzugehörigkeit garantiert kein fertiges Layout. Ein verstecktes Element ist nicht dasselbe wie ein zerstörtes. Ein weiterhin gebundener Python-Name garantiert nicht die Lebensdauer eines zugrunde liegenden Toolkit-Widgets.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Gruppiere nach verständlichen Zuständigkeiten und prüfe Layout sowie Lebensdauer getrennt. Achte auf Verweise zu bereits zerstörten Kindern. Das Beispiel prüft nur eigene Hierarchie und Zerstörung; sichtbare Größenverteilung und NetMons Container wurden nicht praktisch abgenommen.

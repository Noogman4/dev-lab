# tshark

## 1. Kurzbeschreibung

`tshark`, auch TShark genannt, ist ein Netzwerkprotokollanalysator mit Kommandozeilenschnittstelle aus dem Wireshark-Projekt. Es kann gespeicherte Mitschnitte lesen, Protokollfelder ausgeben und unter passenden Voraussetzungen Verkehr erfassen. Die Beschreibung als Kommandozeilen-Version von Wireshark ist ein guter Einstieg, bedeutet aber nicht, dass jede grafische Funktion identisch bedient wird.

## 2. Was bedeutet der Begriff?

Das Werkzeug verwendet die Protokollauswertung des Projekts und macht sie für textuelle Abläufe zugänglich. Das [offizielle TShark-Handbuch](https://www.wireshark.org/docs/man-pages/tshark.html) beschreibt Lesen, Ausgabe und Erfassung. Damit eignet es sich beispielsweise für eine gezielte Auswertung eigener Testdateien.

Wichtig ist der Startmodus. Mit `-r` wird eine bestimmte Datei gelesen. Ohne entsprechende Dateiangabe kann ein normaler Aufruf dagegen eine Live-Erfassung beginnen. Ein kurzer Programmname allein ist deshalb noch keine eindeutige Beschreibung einer rein lesenden Dateianalyse.

## 3. Einfacher Vergleich aus dem Alltag

Ein Messgerät kann einen vorhandenen Prüfbericht gezielt als Tabelle ausgeben, statt alle Ansichten eines grafischen Arbeitsplatzes zu öffnen. Du legst fest, welche Spalten dich interessieren. Ein anderer Betriebsmodus könnte dagegen neue Messungen aufnehmen.

Die Grenze: TShark wertet technische Daten und Felder aus. Es ersetzt nicht die Entscheidung, ob die vorhandenen Daten zur Diagnosefrage passen. Eine leere Spalte oder fehlende Zeile ist ohne Kenntnis von Format, Filtern und Protokollkontext nicht eindeutig zu interpretieren.

## 4. Wie funktioniert das?

Beim Dateilesen erkennt TShark unterstützte Mitschnittformate und zerlegt enthaltene Daten mit den verfügbaren Dissectoren. Ein Display-Filter kann die ausgewählte Menge begrenzen. `-T fields` fordert eine Feldausgabe an, während wiederholtes `-e` die gewünschten Felder benennt. Diese Optionen stehen im Handbuch.

Die [offizielle IPv4-Feldreferenz](https://www.wireshark.org/docs/dfref/i/ip.html) beschreibt unter anderem `ip.src` und `ip.dst`. Diese Namen beziehen sich auf IPv4. Fehlt ein Feld in einem Datensatz, ist eine leere Ausgabe nicht automatisch eine fehlende Gegenstelle. Möglicherweise gehört der Eintrag zu einer anderen Protokollversion oder enthält nicht die erwartete Ebene.

## 5. Wo begegnet mir das unter Linux?

TShark kann bei wiederholbaren Auswertungen und kontrollierten Testabläufen helfen. Eine Kommandozeilenausgabe lässt sich leichter gezielt speichern oder weiterverarbeiten. Dafür müssen jedoch Ausgabeformat, Version und erwartete Felder bewusst gewählt werden.

In dieser Umgebung wurde `tshark` nicht im Suchpfad gefunden. Es wird nicht installiert. Das folgende Muster wurde deshalb nicht ausgeführt, und es gibt keine als echt ausgegebene Ergebnisdatei. Die Erklärung beschreibt die dokumentierte Schnittstelle, keine praktische TShark-Abnahme.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses nicht ausgeführte Muster setzt eine zuvor selbst erzeugte passende Testdatei voraus. Eine solche Datei wird hier nicht behauptet oder geöffnet.

```text
tshark -r eigene-probe.pcapng -Y "tcp.port == 443" -T fields -e frame.number -e ip.src -e ip.dst
```

`-r` bezeichnet die Eingabedatei. `-Y` wählt Einträge mit der genannten TCP-Portbedingung. Die folgenden Optionen verlangen drei Felder. Die Rahmenummer ist eine Nummer innerhalb des betrachteten Mitschnitts, keine allgemeine TCP-Sequenznummer. Die beiden `ip`-Felder betreffen IPv4-Adressen.

Ein passender TCP-Eintrag über IPv6 könnte daher zur Filterbedingung gehören, ohne Werte in diesen IPv4-Spalten zu liefern. Auch enthält der Filter nicht automatisch HTTP/3-Verkehr über UDP. Solche Unterschiede müssen bereits bei der Frage und Feldauswahl berücksichtigt werden.

Das Muster erzeugt keine beispielhaften Ergebniswerte in diesem Text. Es behauptet weder eine vorhandene Datei noch erfolgreiche Protokollerkennung. Für einen echten Versuch wären eine kontrollierte eigene Datei und ein installiertes Werkzeug mit bekannter Version erforderlich.

## 7. Abgrenzung zu ähnlichen Begriffen

Wireshark bietet eine grafische Oberfläche. TShark arbeitet über die Kommandozeile. dumpcap konzentriert sich auf die Erfassung. Ein Display-Filter beschreibt eine Auswertungsbedingung; eine Firewallregel verändert dagegen die Behandlung realen Verkehrs. Eine Textausgabe ist außerdem keine vollständige Kopie aller ursprünglichen Paketbytes.

## 8. Häufige Missverständnisse

Ein Dateiname allein bestimmt nicht das tatsächliche Mitschnittformat. Eine gefilterte Ausgabe ist keine vollständige Bestandsliste. `ip.src` steht nicht für jede mögliche Adressart. Schließlich darf eine fehlende Ausgabe nicht ohne Prüfung als Beweis für „keine Kommunikation“ behandelt werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Verwende beim Lernen explizites Dateilesen und eigene kleine Testdaten. Lege Ausgabefelder bewusst fest und prüfe Fehlermeldungen. Dieser Eintrag startet keine Erfassung, öffnet keine Mitschnitte und verändert weder Rechte noch Netzwerk- oder Anwendungsdaten.

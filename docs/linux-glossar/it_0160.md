# NAT

## 1. Kurzbeschreibung

NAT steht für „Network Address Translation“ und bezeichnet die Übersetzung von IP-Adressen zwischen Adressbereichen. In einer verbreiteten erweiterten Form werden zusätzlich Transportports zugeordnet. So können beispielsweise mehrere innere Teilnehmer einen gemeinsamen äußeren Adresszugang verwenden. NAT ist aber weder automatisch Verschlüsselung noch gleichbedeutend mit einer vollständigen Firewall.

## 2. Was bedeutet der Begriff?

Die Katalogbeschreibung nennt die Übersetzung privater zu öffentlichen IP-Adressen. Das ist ein wichtiger Anwendungsfall, jedoch keine vollständige Definition. [RFC 2663](https://www.rfc-editor.org/rfc/rfc2663.html) beschreibt NAT-Begriffe und verschiedene Übersetzungsmodelle. Adressräume können aus unterschiedlichen Gründen miteinander verbunden werden.

[RFC 3022](https://www.rfc-editor.org/rfc/rfc3022.html) unterscheidet grundlegende Adressübersetzung von Network Address Port Translation, kurz NAPT. Im Alltag wird häufig beides pauschal NAT genannt. Für die Fehlersuche ist wichtig, ob nur Adressen oder auch Portzuordnungen betroffen sind.

## 3. Einfacher Vergleich aus dem Alltag

Eine zentrale Poststelle nimmt Sendungen mehrerer interner Arbeitsplätze unter einer gemeinsamen äußeren Anschrift entgegen. Zusätzliche Zuordnungen helfen ihr, Antworten wieder an den richtigen Arbeitsplatz zu verteilen.

Das erklärt die Vermittlung mehrerer Teilnehmer. Die Grenze: NAT arbeitet mit konkreten Paketfeldern, Protokollzuständen und Zeitbedingungen. Eine Zuordnung bleibt nicht zwangsläufig unbegrenzt erhalten. Außerdem versteht die Übersetzung nicht automatisch jedes Anwendungsformat, das selbst Adressen in seinen Nutzdaten enthält.

## 4. Wie funktioniert das?

Beim Durchlaufen einer entsprechenden Übersetzungsstelle werden ausgewählte Adressinformationen geändert. Bei NAPT können Transportports hinzukommen. Passende Informationen müssen für den vorgesehenen Rückweg berücksichtigt werden, damit Antworten wieder dem richtigen Zusammenhang zugeordnet werden.

Das genaue Verhalten hängt von Verfahren und Einrichtung ab. Nicht jede Verbindung erhält zwingend einen veränderten Port, und nicht jedes NAT-System verhält sich bei unerwartet eingehendem Verkehr identisch. Die beiden genannten RFCs beschreiben Grundmodelle und Einschränkungen, keine universelle Konfiguration jedes heutigen Routers.

Adressübersetzung und Wegwahl sind verschiedene Aufgaben. Ein Router kann ohne NAT zwischen passend eingerichteten Netzen weiterleiten. Ebenso macht eine Übersetzung ein fehlerhaftes Anwendungsprotokoll nicht automatisch kompatibel mit jeder Umgebung.

## 5. Wo begegnet mir das unter Linux?

Ein Heimrouter verwendet häufig NAPT für mehrere innere Geräte. Das Katalogbeispiel ist dafür passend. Linux kann entsprechende Funktionen ebenfalls bereitstellen, wenn sie eingerichtet sind. Für diese Begriffserklärung werden keine solchen Funktionen aktiviert oder untersucht.

Ein beobachteter äußerer Adresswert kann dadurch nicht ohne Weiteres als eindeutige Identität eines bestimmten inneren Geräts gelesen werden. Umgekehrt beweist der Einsatz von NAT keine vollständige Abschottung. Filterregeln, bestehende Zuordnungen und weitere Funktionen müssen getrennt betrachtet werden.

Die inneren Teilnehmer verwenden im Beispiel dieselbe Ausgangsportnummer. Die angenommene Übersetzung unterscheidet sie außen durch verschiedene Ports. Eine passende Antwort müsste anhand der tatsächlichen Zuordnung wieder richtig verarbeitet werden.

Die Tabelle ist bewusst unvollständig: Reale Zustände können zusätzliche Gegenstellen- und Protokollangaben sowie Zeitbedingungen berücksichtigen. Sie beschreibt keine allgemeine vollständige NAT-Implementierung. Es wurde kein Paket verändert, keine Verbindung aufgebaut und keine Übersetzungstabelle eines Rechners abgefragt.

## 7. Abgrenzung zu ähnlichen Begriffen

Routing wählt einen Weg. NAT verändert bestimmte Adressinformationen. Eine Firewall setzt eine Zugriffsrichtlinie um. Ein Proxy vermittelt auf einer anderen Ebene Anwendungsanfragen. Ein Heimgerät kann diese Aufgaben kombinieren; daraus folgt keine technische Gleichheit der Funktionen.

## 8. Häufige Missverständnisse

NAT bedeutet nicht zwingend nur privat zu öffentlich. Mehrere Teilnehmer hinter einer Adresse sind nicht automatisch dieselbe Identität. Eine Übersetzung verschlüsselt auch keine Nutzdaten. Die Annahme, jeder eingehende Zugriff sei grundsätzlich unmöglich, wäre ohne Kenntnis der konkreten Zuordnungen und Regeln ebenfalls zu pauschal.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Unterscheide bei Problemen innere Sicht, äußere Sicht und betroffene Protokolle. Änderungen können bestehende Kommunikation beeinflussen. Richte keine Portweiterleitung allein zur Begriffserklärung ein. Dieser Text verändert weder NAT-Zustände noch Firewallregeln, Adressen oder Geräte.

## 10. Verwandte Begriffe

Die [Firewall](it_0159.md) erfüllt eine getrennte Kontrollaufgabe. Der [Router](it_0151.md) übernimmt Weiterleitung. Ein [Port](it_0142.md) kann Teil einer NAPT-Zuordnung sein. Die [IP-Adresse](it_0139.md) ist ein übersetzter Wert, aber kein sicherer Personen- oder Gerätenachweis.

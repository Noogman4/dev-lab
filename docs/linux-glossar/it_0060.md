# Kapselung

## 1. Kurzbeschreibung

Kapselung bedeutet, zusammengehörige Daten und Verhalten hinter einer vorgesehenen Schnittstelle zu ordnen. Aufrufer sollen wichtige Zustandsregeln verwenden können, ohne die interne Speicherung kennen zu müssen. Die Quelle nennt das Verbergen interner Details. In Python ist dies jedoch nicht automatisch eine unüberwindbare Zugriffssperre gegen anderen Code im selben Prozess.

## 2. Was bedeutet der Begriff?

Eine Klasse kann festlegen, wie ihr Zustand sinnvoll verändert werden soll. Eine Zählerklasse könnte nur nichtnegative Erhöhungen akzeptieren. Die Methode prüft dann diese Voraussetzung und hält die entsprechende Regel ein. Eine solche stets gewünschte Zustandsregel wird auch Invariante genannt.

Die Aussage der Quelle, ein Objekt ändere seinen Zustand nur über Methoden, beschreibt ein mögliches Entwurfsziel. Sie ist keine allgemeine Garantie des Python-Modells. Entscheidend ist, welche Zugriffe die Schnittstelle vorsieht und welche zusätzlichen technischen Einschränkungen tatsächlich vorhanden sind.

## 3. Einfacher Vergleich aus dem Alltag

Ein Ausgabeschalter bietet eine geregelte Bedienung für eine Maschine. Nutzer sollen nicht für jede Aktion die inneren Bauteile umstecken müssen. Die Bedienung kann Voraussetzungen prüfen und ein verständliches Ergebnis liefern.

Die Grenze des Vergleichs: Python-Namenskonventionen entsprechen keinem abgeschlossenen Gehäuse mit physischer Sicherung. Ein wissentlich umgangener interner Zugriff kann weiterhin möglich sein. Kapselung verbessert Zuständigkeit und Verständlichkeit, ersetzt aber keine Sicherheitsgrenze für fremden vertrauenswidrigen Code.

## 4. Wie funktioniert das?

Ein Objekt stellt geeignete öffentliche Operationen bereit und kennzeichnet interne Bestandteile. In Python zeigt ein führender Unterstrich üblicherweise an, dass ein Name nicht zur öffentlichen Schnittstelle gehört. Die [Dokumentation zu privaten Variablen](https://docs.python.org/3.13/tutorial/classes.html#private-variables) erklärt, dass es keine vollständig unzugänglichen privaten Instanzvariablen in diesem einfachen Sinn gibt.

Auch die Umbenennung bei doppeltem führendem Unterstrich dient vor allem dem Vermeiden unbeabsichtigter Namenskonflikte. Sie ist keine allgemeine Schutzmaßnahme gegen gezielten Zugriff.

Eine Property kann lesenden Zugriff oder kontrollierte Änderungen vermitteln. Die [offizielle property-Referenz](https://docs.python.org/3.13/library/functions.html#property) beschreibt Getter und Setter. Dadurch lässt sich eine stabile öffentliche Sicht anbieten, während die interne Darstellung später verändert werden kann.

## 5. Wo begegnet mir das unter Linux?

Python-Bibliotheken können interne Zwischenspeicher oder Zustände hinter dokumentierten Methoden verwalten. Anwendungen verwenden die vereinbarte Schnittstelle, statt sich auf private Details zu verlassen. Das erleichtert nachvollziehbare Weiterentwicklung.

Eine GUI könnte beispielsweise einen Status über eine Methode aktualisieren lassen, die auch zugehörige Anzeigen konsistent hält. Direkte Änderungen eines internen Werts könnten diese Nebenarbeiten umgehen. Die konkreten Auswirkungen müssen aus der jeweiligen Bibliothek hervorgehen.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel prüft eine vorgesehene Zählerschnittstelle mit kleinen Integerbeträgen:

```python
class Zaehler:
    def __init__(self):
        self._wert = 0

    @property
    def wert(self):
        return self._wert

    def erhoehen(self, betrag):
        if betrag < 0:
            raise ValueError("negativer Betrag")
        self._wert += betrag

zaehler = Zaehler()
zaehler.erhoehen(2)
abgelehnt = False
try:
    zaehler.erhoehen(-1)
except ValueError:
    abgelehnt = True
assert abgelehnt and zaehler.wert == 2
print(zaehler.wert)
```

Die Ausgabe lautet:

```text
2
```

Die gültige Erhöhung verändert den Zustand. Die negative Eingabe wird vor der Änderung abgelehnt. Der öffentliche Lesezugriff liefert danach weiterhin zwei. Geprüft wird die vereinbarte Methode; der Unterstrich verhindert keinen absichtlichen direkten Zugriff auf `_wert`.

## 7. Abgrenzung zu ähnlichen Begriffen

Abstraktion betont die relevante vereinfachte Sicht. Kapselung ordnet Zuständigkeiten und Zugriffe. Zugriffskontrolle ist ein eigener technischer Schutzmechanismus. Eine Typannotation beschreibt beabsichtigte Typen, erzwingt aber in Python allein normalerweise keine vollständige Laufzeitprüfung.

## 8. Häufige Missverständnisse

Ein Unterstrich macht Daten nicht sicher geheim. Eine lesbare Property friert nicht den gesamten erreichbaren Objektbestand ein. Eine Methode ist nicht automatisch korrekt, nur weil sie öffentlich vorgesehen ist. Zusätzliche Zugriffsmethoden sind außerdem nur dann hilfreich, wenn sie sinnvolle Regeln oder stabile Verträge vermitteln.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Dokumentiere erlaubte Eingaben und zugesicherte Zustände. Verlasse dich nicht auf private Namen als Schutz für Geheimnisse. Das Beispiel prüft nur kleine eigene Integerfälle; es behauptet keine vollständige Eingabevalidierung oder Sicherheitsisolation.

# Editor

## 1. Kurzbeschreibung

Ein Texteditor bearbeitet Textdateien wie Quellcode, Einstellungen und Markdown-Dokumente. Er kann Funktionen wie Suche, Zeilennummern und farbliche Hervorhebung bereitstellen. Gespeichert wird die Datei im gewählten Textformat.

## 2. Was bedeutet der Begriff?

Nano ist laut [Nano-Handbuch](https://www.nano-editor.org/dist/latest/nano.html) ein Texteditor für das Terminal. Vim ist ein weiteres Beispiel aus dieser Umgebung. VS Code bietet eine grafische Oberfläche und kann mit Erweiterungen zusätzliche Sprachfunktionen anbieten. Die [VS-Code-Dokumentation zu Grundfunktionen](https://code.visualstudio.com/docs/editor/codebasics) zeigt Bearbeitungshilfen wie das Ein- und Ausklappen von Textbereichen.

## 3. Einfacher Vergleich aus dem Alltag

Ein Schreibblock nimmt Wörter auf. Ein farbiger Marker kann unterschiedliche Arten von Notizen hervorheben. Ähnlich zeigt ein Editor Code farbig an und speichert ihn weiterhin als Text. Ein Programm, das den Code verarbeitet, beurteilt ihn nach eigenen Regeln.

## 4. Wie funktioniert das?

Beim Öffnen übersetzt der Editor Dateibytes anhand einer Zeichenkodierung in sichtbare Zeichen. Beim Speichern schreibt er die gewählte Kodierung und Zeilenenden zurück. Darum kann eine Einstellung den Diff verändern, obwohl der Text auf dem Bildschirm fast gleich aussieht.

Zusatzfunktionen können Dateien automatisch formatieren, Zeichen ersetzen oder neue Zeilen einfügen. Bei Projekten mit Vorgaben kann das erwünscht sein. Bei einer gezielten Änderung lohnt es sich, die tatsächlichen Auswirkungen nachzusehen.

## 5. Wo begegnet mir das unter Linux?

Auf einem Server ohne Desktop ist ein Terminaleditor praktisch. In einer grafischen Sitzung kannst du mehrere Dateien mit Vorschau und Seitennavigation bearbeiten. Beide Wege können dieselbe UTF-8-Datei erzeugen.

## 6. Konkretes Beispiel Schritt für Schritt

Gedankenbeispiel. Eine fiktive README enthält einen Tippfehler in einem Linktext.

1. Öffne die Datei im Editor deiner Wahl und suche die genaue Zeile.
2. Ändere nur den Linktext. Lasse die Zieladresse bestehen, wenn sie korrekt ist.
3. Speichere die Datei in der vom Projekt erwarteten Kodierung.
4. Prüfe im Diff, ob nur diese Textstelle geändert wurde. Zeigt der Diff viele Änderungen, kontrolliere Zeilenenden und automatische Formatierung.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Textverarbeitung speichert häufig zusätzlich Layoutinformationen in einem eigenen Dokumentformat. Der Editor arbeitet mit dem eigentlichen Text. Eine [IDE](it_0294.md) kann einen Editor mit Tests und Laufzeitsteuerung verbinden.

## 8. Häufige Missverständnisse

Farbliche Hervorhebung zeigt, welche Bedeutung ein Editor anhand seiner Regeln vermutet. Sie belegt weder eine korrekte Programmsyntax noch ein richtiges Dateischema. Auch eine leere Vorschau kann an der Darstellung liegen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Ändere Systemdateien nur mit klarer Kenntnis ihrer Auswirkungen. Bei Projektdateien helfen eine gezielte Änderung und der Diff. Achte darauf, ob ein Editor vor dem Speichern automatisch Erweiterungen ausführt.

## 10. Verwandte Begriffe

[Quellcode](it_0030.md) ist ein häufiger Dateityp. [Markdown](it_0284.md) lässt sich als Text bearbeiten. [Config](it_0228.md) beschreibt, was viele Einstellungen bedeuten.

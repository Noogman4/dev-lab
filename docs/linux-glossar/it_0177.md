# XML

## 1. Kurzbeschreibung

XML ist ein textbasiertes Format zur strukturierten Auszeichnung von Daten. Elemente, Attribute und Text bilden eine Baumstruktur. Die verwendeten Elementnamen können durch ein bestimmtes Datenmodell festgelegt werden. XML gibt nicht automatisch die fachliche Bedeutung jedes selbst gewählten Namens vor und ist keine allgemeine Programmiersprache.

## 2. Was bedeutet der Begriff?

Der Name steht für „Extensible Markup Language“. Die [W3C-Spezifikation XML 1.0](https://www.w3.org/TR/xml/) beschreibt die grundlegende Syntax. „Extensible“ bedeutet unter anderem, dass verschiedene Anwendungen eigene Vokabulare auf dieser Grundlage definieren können.

Das Katalogbeispiel eines Elements mit dem Namen `name` ist ein einfacher Einstieg. Ein passender Name und Text ergeben aber noch keine vollständige Anwendungsschnittstelle. Dafür müssen zusätzlich Struktur, erlaubte Werte und ihre Bedeutung vereinbart werden. Auch ist Wohlgeformtheit von einer Gültigkeitsprüfung gegen ein konkretes Schema zu unterscheiden.

## 3. Einfacher Vergleich aus dem Alltag

Ein gegliedertes Formular enthält Abschnitte, Unterabschnitte und ergänzende Merkmale. Die Gliederung kann von verschiedenen Stellen für unterschiedliche Inhalte verwendet werden. Die gemeinsame Form allein erklärt noch nicht, welche Fachregeln gelten.

Die Grenze: XML-Struktur folgt exakten Zeichenregeln. Verschachtelungen müssen passen, und Namen werden nicht frei nach menschlichem Verständnis korrigiert. Zwei ähnlich aussehende Dokumente können deshalb unterschiedliche Strukturen oder Bedeutungen besitzen. Ein Textwert wie `true` wird auch nicht allein durch seine Schreibweise automatisch zu einem Python-Boolean.

## 4. Wie funktioniert das?

Elemente werden mit passenden Begrenzungen geschrieben und können weitere Elemente oder Text enthalten. Attribute ergänzen benannte Angaben. Ein XML-Dokument besitzt ein Dokumentelement als Wurzel. Namen sind grundsätzlich groß- und kleinschreibungsempfindlich.

Ein Parser prüft und verarbeitet die Struktur. Er kann daraus beispielsweise einen Baum erzeugen, in dem ein Programm gezielt Elemente und Attribute abfragt. Die verwendete Bibliothek und ein mögliches Schema bestimmen, welche weiteren Prüfungen stattfinden. Ein erfolgreich aufgebauter Baum bestätigt daher nicht automatisch alle fachlichen Anforderungen.

Python stellt in ElementTree die Funktion [fromstring](https://docs.python.org/3.13/library/xml.etree.elementtree.html#xml.etree.ElementTree.fromstring) bereit. Sie liest hier einen eigenen Text und liefert das Wurzelelement. Dieser konkrete Bibliothekszugang ist nicht gleichbedeutend mit jeder möglichen XML-Verarbeitung.

## 5. Wo begegnet mir das unter Linux?

Anwendungen können XML für Austauschdaten, Dokumente oder bestimmte Einstellungen verwenden. Die Dateiendung allein verrät jedoch nicht das konkrete Vokabular. Ein Importwerkzeug kann zusätzliche Regeln verlangen, obwohl die Datei syntaktisch wohlgeformt ist.

Bei fremden Eingaben sind außerdem Parserfunktionen und Sicherheitsgrenzen relevant. Die [Python-Dokumentation zur XML-Sicherheit](https://docs.python.org/3.13/library/xml.html#xml-vulnerabilities) beschreibt mögliche Probleme abhängig von Bibliothek und Version. Der folgende Versuch verwendet deshalb ausschließlich kleine eigene Daten ohne externe Verweise.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Es verarbeitet nur selbst erzeugte Zeichenketten und liest keine Dateien oder entfernten Quellen.

```python
from xml.etree import ElementTree as ET

text = '<notiz id="7"><name>Probe</name><aktiv>true</aktiv></notiz>'
wurzel = ET.fromstring(text)
assert wurzel.tag == "notiz"
assert wurzel.attrib == {"id": "7"}
assert wurzel.findtext("name") == "Probe"
assert wurzel.findtext("aktiv") == "true"
assert isinstance(wurzel.findtext("aktiv"), str)
fehler_erkannt = False
try:
    ET.fromstring("<a><b></a>")
except ET.ParseError:
    fehler_erkannt = True
assert fehler_erkannt
print(wurzel.tag)
print(wurzel.findtext("name"))
print("Verschachtelungsfehler erkannt:", fehler_erkannt)
```

Geprüfte Ausgabe:

```text
notiz
Probe
Verschachtelungsfehler erkannt: True
```

Die Assertions prüfen Elementnamen, Attribut und Text. Der Wert `true` bleibt in diesem Zugriff ein String. Die zweite Zeichenkette besitzt eine unpassende Verschachtelung und wird abgelehnt. Es findet keine Schema- oder Anwendungsvalidierung statt. Der erfolgreiche erste Parse ist ebenso wenig ein Nachweis sicherer Verarbeitung beliebiger fremder Dokumente.

## 7. Abgrenzung zu ähnlichen Begriffen

JSON und YAML sind andere Datenformate. Ein konkretes XML-Vokabular legt zusätzliche Namen und Regeln fest. Eine API beschreibt einen Zugang zu Funktionalität und kann XML als eine Darstellung verwenden. Ein ElementTree-Objekt ist dagegen eine Datenstruktur im laufenden Python-Programm.

## 8. Häufige Missverständnisse

XML ist nicht automatisch eine Webseite. Ein passendes Wurzelelement bestätigt noch keine Pflichtfelder. Lesbarer Text bedeutet auch nicht, dass alle Inhalte ungeprüft verwendet werden dürfen. Schließlich ersetzen selbst gewählte Tags keine gemeinsame Vereinbarung mit dem empfangenden Programm.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe bei echten Importen Format, Vokabular und fachliche Grenzen. Verwende geeignete gepflegte Parser und begrenze Eingaben. Dieser Versuch verarbeitet keine externen Entitäten, verändert keine Konfiguration und erzeugt keine Netzwerk- oder Gerätezugriffe.

## 10. Verwandte Begriffe

[JSON](it_0175.md) und [YAML](it_0176.md) bieten andere Darstellungen. Ein [String](it_0007.md) enthält zunächst nur Text. Die [API](it_0169.md) definiert weitere Vertragsbedingungen. Ein [Datentyp](it_0006.md) hilft, Parserergebnisse richtig einzuordnen.

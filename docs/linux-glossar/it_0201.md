# Migration

## 1. Kurzbeschreibung

Eine Datenbankmigration ist eine geplante, nachvollziehbare Überführung eines Datenbestands oder seiner Struktur in einen neuen Zustand. Im Anwendungsalltag meint das häufig eine versionierte Schemaänderung. Dazu können auch Anpassungen vorhandener Werte gehören. Das bloße Austauschen einer Programmdatei erledigt eine notwendige Datenbankänderung nicht automatisch.

## 2. Was bedeutet der Begriff?

Das Katalogbeispiel fügt eine neue Spalte hinzu. Dabei stellen sich praktische Fragen: Was sollen bestehende Zeilen dort enthalten? Verträgt die bisherige Programmversion das neue Schema? Woran erkennt das Programm, dass die Änderung schon erfolgt ist? Eine Migration umfasst deshalb mehr als eine beliebig wiederholte SQL-Anweisung.

Die [SQLite-Dokumentation zu ALTER TABLE](https://www.sqlite.org/lang_altertable.html) beschreibt unterstützte Strukturänderungen und ihre Grenzen. Beim Hinzufügen einer Spalte gelten konkrete Einschränkungen, etwa für bestimmte Bedingungen und Standardwerte. Möglichkeiten anderer Systeme sollten nicht ungeprüft auf SQLite übertragen werden. Im weiteren Sprachgebrauch kann Migration außerdem einen Wechsel zwischen Datenbanksystemen oder Speicherorten meinen; das ist hier nicht die ausgeführte Aufgabe.

## 3. Einfacher Vergleich aus dem Alltag

Ein Karteikartenformular bekommt eine neue Rubrik. Für neue Karten ist das schnell beschlossen. Für die vorhandenen Karten muss zusätzlich geklärt werden, was dort einzutragen ist und ob alte Arbeitsanweisungen weiter funktionieren.

Die Grenze: Eine Datenbank kann viele abhängige Strukturen und gleichzeitig arbeitende Programme besitzen. Ein einfaches neues Formular erklärt weder technische Sperren noch vollständige Rückkehrmöglichkeiten. Und wenn Informationen beim Umbau gelöscht wurden, entstehen sie durch ein leeres altes Formular nicht wieder.

## 4. Wie funktioniert das?

Typischerweise werden Ausgangszustand, Zielzustand und notwendige Schritte festgelegt. Ein Migrationswerkzeug kann bereits angewandte Versionen protokollieren und eine Reihenfolge vorgeben. Welche Funktionen es bietet, hängt vom jeweiligen Werkzeug ab. Nicht jede SQL-Datei ist deshalb automatisch eine vollständige Migrationsverwaltung.

Die Änderung muss zum vorhandenen Datenbestand passen. Eine verpflichtende neue Spalte braucht beispielsweise eine sinnvolle Behandlung älterer Zeilen. Ein technischer Standardwert kann eine Möglichkeit sein, ersetzt aber keine fachliche Entscheidung über dessen Bedeutung.

Transaktionen können unterstützte Änderungen gemeinsam bestätigen oder zurücknehmen. Die [SQLite-Dokumentation zur Transaktionssteuerung](https://www.sqlite.org/lang_transaction.html) erklärt COMMIT und ROLLBACK. Das ist keine Zusage, dass jede Migration jedes Systems vollständig rückwärts ausführbar wäre. Externe Wirkungen, bereits bestätigte Schritte oder verlorene Informationen brauchen eine gesonderte Betrachtung.

## 5. Wo begegnet mir das unter Linux?

Anwendungsaktualisierungen können ein neues Datenbankschema benötigen. Alte und neue Programmstände müssen deshalb zusammen mit ihren Datenformaten betrachtet werden. Ein Neustart allein beweist nicht, dass eine Migration korrekt stattgefunden hat.

Vor produktiven Änderungen sind eine geeignete Sicherung und ein geprüfter Wiederherstellungsweg wichtig. Das folgende Beispiel ist wesentlich kleiner: Es verwendet nur eine neu erzeugte Speicherdatenbank. Es testet keine Sicherung, keinen Versionswechsel von NetMon und kein Migrationswerkzeug.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 und SQLite 3.46.1 in einem temporären Arbeitsordner ausgeführt. Die Transaktionssteuerung wird ausdrücklich gewählt; ihre Bedeutung beschreibt die [Python-Dokumentation zu autocommit](https://docs.python.org/3.13/library/sqlite3.html#transaction-control-via-the-autocommit-attribute).

```python
from contextlib import closing
import sqlite3

with closing(sqlite3.connect(":memory:", autocommit=False)) as db:
    db.execute("CREATE TABLE kontakte (id INTEGER PRIMARY KEY, name TEXT)")
    db.execute("INSERT INTO kontakte VALUES (1, 'Probe')")
    db.commit()
    aenderung = "ALTER TABLE kontakte ADD COLUMN aktiv INTEGER NOT NULL DEFAULT 1"
    db.execute(aenderung)
    assert db.execute("SELECT aktiv FROM kontakte").fetchone() == (1,)
    db.rollback()
    spalten = [zeile[1] for zeile in db.execute("PRAGMA table_info(kontakte)")]
    assert spalten == ["id", "name"]
    print("Schemaänderung zurückgenommen:", True)
    db.execute(aenderung)
    db.commit()
    datensatz = db.execute("SELECT id, name, aktiv FROM kontakte").fetchone()
    assert datensatz == (1, "Probe", 1)
    print("Bestätigter neuer Wert:", datensatz[2])
```

Geprüfte Ausgabe:

```text
Schemaänderung zurückgenommen: True
Bestätigter neuer Wert: 1
```

Zuerst wird genau diese SQLite-Schemaänderung zurückgenommen und die alte Spaltenliste kontrolliert. Danach wird sie erneut vorgenommen und bestätigt. Ein zweites Hinzufügen derselben Spalte zum bereits geänderten Schema wäre keine sinnvolle Wiederholung. Eine Versionsverwaltung für Migrationen ist hier nicht implementiert.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Migration verändert einen Datenzustand nach einem Plan. Eine Transaktion begrenzt zusammengehörige Datenbankarbeit. Eine Sicherung ermöglicht unter geeigneten Voraussetzungen die Wiederherstellung eines gesicherten Zustands. Ein Programmupdate kann eine Migration benötigen, ist mit ihr aber nicht identisch.

## 8. Häufige Missverständnisse

Neue Spalten erhalten nicht automatisch fachlich richtige Werte. Ein Rückwärts-Skript kann gelöschte Informationen nicht herbeizaubern. Ein erfolgreicher Einzelbefehl beweist keine Kompatibilität mit allen Programmständen. Und eine bereits angewandte Migration sollte nicht blind wiederholt werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Dokumentiere Voraussetzungen, Zielzustand und Wiederherstellung. Prüfe Änderungen an geeigneten eigenen Testdaten. Die gezeigte Rücknahme gilt für den ausgeführten SQLite-Fall; eine allgemeine Freigabe produktiver Schemaänderungen ergibt sich daraus nicht.

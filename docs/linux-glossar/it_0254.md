# Linting

## 1. Kurzbeschreibung

Linting ist die regelbasierte Untersuchung von Quellcode auf bestimmte Auffälligkeiten. Dazu können unbenutzte Importe, fragwürdige Konstruktionen und Stilregeln gehören. Ein Linter kann viele Hinweise liefern, ohne den gesamten Anwendungsablauf auszuführen. Welche Probleme er erkennt, hängt von Werkzeug, aktivierten Regeln und Konfiguration ab. Fehlerfreiheit ist damit nicht allgemein bewiesen.

## 2. Was bedeutet der Begriff?

Die Quelle nennt Ruff und Flake8 für Python. Diese Werkzeuge prüfen nach ihren jeweiligen Regeln. Ein Hinweis kann einen echten Fehler, eine unnötige Stelle oder eine bewusst zu begründende Ausnahme betreffen. Der Regelcode hilft, die konkrete Aussage zu verstehen.

Die [offizielle Ruff-Dokumentation zum Linter](https://raw.githubusercontent.com/astral-sh/ruff/main/docs/linter.md) beschreibt `ruff check` und die Regelauswahl. Ruff bietet daneben weitere Funktionen. Das Vorhandensein desselben Programms bedeutet daher nicht, dass jeder Aufruf dieselbe Art von Prüfung ausführt. Version und gewählte Optionen gehören zum Ergebnis.

## 3. Einfacher Vergleich aus dem Alltag

Eine redaktionelle Prüfliste findet doppelte Wörter, uneinheitliche Schreibweisen oder fehlende Angaben. Das hilft bei der Durchsicht, ersetzt aber nicht das Verständnis des gesamten Textinhalts. Eine formal saubere Beschreibung kann weiterhin sachlich falsch sein.

Die Grenze: Ein Linter arbeitet mit technischen Regeln und teilweise Codeanalyse. Er liest nicht wie ein Mensch jede Anforderung zwischen den Zeilen. Ein fehlender Hinweis beweist deshalb nicht automatisch, dass Netzwerkverhalten, Benutzeroberfläche oder fachliche Berechnung stimmen.

## 4. Wie funktioniert das?

Das Werkzeug liest Quelltext und untersucht relevante Strukturen. Regeln prüfen daraus bestimmte Eigenschaften. Eine Meldung enthält typischerweise Regelkennung und Fundstelle. Danach muss entschieden werden, ob die Stelle geändert oder eine begründete Ausnahme vorgesehen wird.

Die [Ruff-Regelbeschreibung und Implementierung zu unbenutzten Importen](https://raw.githubusercontent.com/astral-sh/ruff/main/crates/ruff_linter/src/rules/pyflakes/rules/unused_import.rs) dokumentiert das hier verwendete Problem. Im Beispiel ist der importierte Name `math` tatsächlich ohne Verwendung. Das ist etwas anderes als ein allgemeiner Nachweis, dass jede Importentfernung in jedem Projekt folgenlos wäre.

Werkzeuge können zusätzliche automatische Korrekturen anbieten. Deren Umfang und Sicherheit müssen nach den jeweiligen Regeln beurteilt werden. Eine Änderung kann mehr betreffen als reine Leerzeichen. Das Beispiel führt deshalb nur eine Prüfung aus und kontrolliert, dass der eigene Quelltext unverändert bleibt.

Auch Konfiguration verändert die Aussage. Wenn nur eine Regel aktiviert ist, ist ein sauberer Lauf keine Prüfung aller verfügbaren Regeln. Ausnahmen, ausgeschlossene Dateien und Versionen müssen beim Interpretieren eines Berichts berücksichtigt werden. Eine erfolgreiche Syntaxprüfung allein ist ebenfalls kein vollständiges Linting.

## 5. Wo begegnet mir das unter Linux?

Python-Projekte können Linter lokal, im Editor und in automatisierten Abläufen verwenden. Unterschiedliche Konfigurationen können unterschiedliche Meldungen erzeugen. Ein vergleichbarer Aufruf erleichtert die Zusammenarbeit.

In dieser Umgebung ist Ruff 0.17.5 bereits vorhanden. Für das Beispiel wird nur eine neu erzeugte temporäre Datei geprüft, ohne Projektkonfiguration zu übernehmen oder einen Cache anzulegen. Es werden keine bestehenden Python-Dateien und keine Anwendungs- oder Testkonfigurationen geändert.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 und vorhandenem Ruff 0.17.5 ausgeführt. `RUFF_BIN` zeigte auf das vorhandene Werkzeug; andernfalls sucht das Skript im Suchpfad. Es enthält keine Installationsanweisung und aktiviert gezielt nur F401.

```python
# Ruff-Prüfung mit vorhandenem Werkzeug
import json
import os
from pathlib import Path
import shutil
import subprocess
import tempfile

ruff = os.environ.get("RUFF_BIN") or shutil.which("ruff")
if ruff is None:
    raise RuntimeError("Ein vorhandenes Ruff-Werkzeug wird benötigt")
with tempfile.TemporaryDirectory() as ordner:
    datei = Path(ordner) / "eigene_probe.py"
    quelle = "import math\n\nwert = 2\n"
    compile(quelle, str(datei), "exec")
    datei.write_text(quelle, encoding="utf-8")
    lauf = subprocess.run(
        [ruff, "check", "--isolated", "--no-cache", "--select", "F401",
         "--output-format", "json", str(datei)],
        capture_output=True, text=True, timeout=5
    )
    meldungen = json.loads(lauf.stdout)
    assert lauf.returncode == 1
    assert len(meldungen) == 1 and meldungen[0]["code"] == "F401"
    assert datei.read_text(encoding="utf-8") == quelle
    print("Erkannte Regel:", meldungen[0]["code"])
    print("Quelldatei unverändert:", True)
```

Geprüfte Ausgabe:

```text
Erkannte Regel: F401
Quelldatei unverändert: True
```

Der Text ist syntaktisch kompilierbar, enthält aber den gezielt erkannten unbenutzten Import. Exitcode 1 ist hier die erwartete Meldung eines Regelverstoßes, kein unbemerkter Erfolg. Der Quelltext wird nicht ausgeführt oder automatisch korrigiert. Die eigene Datei wird danach entfernt.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Formatter vereinheitlicht Darstellung. Linting untersucht ausgewählte Auffälligkeiten. Ein Test führt Verhalten unter bestimmten Bedingungen aus. Eine Typprüfung untersucht wiederum andere Verträge. Ein Werkzeug kann mehrere Aufgaben anbieten, ohne dass sie dieselbe Aussage liefern.

## 8. Häufige Missverständnisse

Keine Meldung bedeutet nicht fehlerfrei. Ein syntaktisch gültiges Programm kann Lint-Hinweise besitzen. Eine einzelne aktivierte Regel deckt nicht alle Regeln ab. Und eine automatische Korrektur sollte nicht ohne Blick auf ihren Umfang übernommen werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Verwende nachvollziehbare Versionen und Regeln. Prüfe Hinweise im Kontext und begründe Ausnahmen. Die Ausführung installiert nichts, verändert keine Projektdatei und nimmt keine automatische Anwendungskorrektur vor.

## 10. Verwandte Begriffe

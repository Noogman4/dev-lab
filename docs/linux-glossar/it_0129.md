# Socket

## 1. Kurzbeschreibung

Ein Socket ist ein Kommunikationsendpunkt eines Programms. Über passende Socket-Schnittstellen können Daten gesendet und empfangen werden. Manche Sockets kommunizieren über ein Netzwerk, andere ausschließlich lokal zwischen Prozessen. Der Begriff bedeutet deshalb weder automatisch Internetverbindung noch einen bestimmten Netzwerkport.

## 2. Was bedeutet der Begriff?

Ein Socket gehört zu einer Adressfamilie und besitzt einen Typ. Diese Angaben bestimmen mit, wie Kommunikation adressiert wird und welche Eigenschaften gelten. Die [Linux-Übersicht der Socket-Schnittstelle](https://man7.org/linux/man-pages/man7/socket.7.html) unterscheidet beispielsweise Familien und Typen wie Stream- und Datagramm-Sockets.

Ein Programm verwendet einen Socket über einen vom Betriebssystem bereitgestellten Zugriff. Dazu gehören je nach Ablauf Erzeugen, Verbinden, Senden, Empfangen und Schließen. Nicht jede Art benötigt denselben Verbindungsaufbau. Die Vorstellung eines stets identischen Telefonanrufs würde daher wichtige Unterschiede verdecken.

## 3. Einfacher Vergleich aus dem Alltag

Ein Anschluss in einer Kommunikationsanlage ist ein Ort, an dem Nachrichten ein- und ausgehen können. Zwei passende Anschlüsse ermöglichen einen Austausch, wenn die beteiligten Seiten die vereinbarten Regeln verstehen.

So hilft der Begriff Endpunkt beim Einstieg. Die Grenze: Ein Socket allein legt kein fachliches Nachrichtenformat fest. Zwei Programme müssen zusätzlich vereinbaren, welche Bytes welche Bedeutung haben. Auch sagt ein erfolgreicher Transport nicht, dass der Empfänger eine Nachricht fachlich akzeptiert oder dauerhaft gespeichert hat.

## 4. Wie funktioniert das?

Für lokale Kommunikation bietet Linux unter anderem Unix-Domain-Sockets der Familie `AF_UNIX`. Die [offizielle Unix-Socket-Handbuchseite](https://man7.org/linux/man-pages/man7/unix.7.html) beschreibt benannte, unbenannte und Linux-spezifische abstrakte Varianten. Ein Socket muss also nicht immer eine normale sichtbare Pfaddatei besitzen.

Ein Stream-Socket liefert einen geordneten Bytestrom, aber keine automatisch erhaltenen Anwendungsnachrichtengrenzen. Ein Empfangsaufruf kann weniger Bytes liefern als die Anwendung insgesamt erwartet. Ein Datagramm-Modell hat andere Eigenschaften. Das Anwendungsprotokoll muss deshalb zum gewählten Typ passen und beispielsweise Länge oder Trennzeichen regeln.

## 5. Wo begegnet mir das unter Linux?

Lokale Programme können über Unix-Sockets miteinander sprechen, ohne eine entfernte Netzwerkadresse anzusprechen. Netzwerkprogramme nutzen andere Familien, beispielsweise für IPv4 oder IPv6. Berechtigungen, Adressierung und Fehlerfälle hängen vom konkreten Weg ab.

Python bietet mit [socket.socketpair](https://docs.python.org/3.13/library/socket.html#socket.socketpair) zwei bereits miteinander verbundene Socket-Objekte. Das eignet sich hier für einen kleinen lokalen Versuch. Beide Endpunkte können dabei im selben Prüfprozess liegen; daraus folgt kein getesteter Mehrprozess- oder Netzwerkbetrieb einer Anwendung.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 unter Linux in einem temporären Arbeitsordner ausgeführt. Es verwendet ausdrücklich lokale Unix-Stream-Sockets, keinen Port, keine DNS-Abfrage und keinen fremden Dienst.

```python
import socket


def empfange(sock, anzahl):
    daten = b""
    while len(daten) < anzahl:
        teil = sock.recv(anzahl - len(daten))
        if not teil:
            raise RuntimeError("Unerwartetes Ende")
        daten += teil
    return daten


links, rechts = socket.socketpair(socket.AF_UNIX, socket.SOCK_STREAM)
with links, rechts:
    links.settimeout(2)
    rechts.settimeout(2)
    links.sendall(b"Probe")
    anfrage = empfange(rechts, 5)
    assert anfrage == b"Probe"
    rechts.sendall(anfrage.upper())
    antwort = empfange(links, 5)
    assert antwort == b"PROBE"
    print(antwort.decode("ascii"))
```

Geprüfte Ausgabe:

```text
PROBE
```

Die kleine Empfangsfunktion sammelt die ausdrücklich vereinbarte Bytezahl. Sie setzt nicht voraus, dass ein einzelnes `recv` stets alles liefert. Die Rückantwort nutzt denselben verbundenen Kanal in Gegenrichtung. Beide Endpunkte werden anschließend geschlossen. Das Beispiel prüft keine Authentifizierung, Netzwerkübertragung oder Robustheit eines vollständigen Protokolls.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Port ist eine Adressangabe bestimmter Netzwerkprotokolle und nicht der Socket selbst. Eine gewöhnliche Datei speichert Inhalte; ein Socket ermöglicht Kommunikation. Ein Service kann über Sockets erreichbar sein, besteht aber zusätzlich aus fachlichem Verhalten. Die Kommunikationsmöglichkeit allein ist noch kein Dienst.

## 8. Häufige Missverständnisse

Ein Socket bedeutet nicht automatisch TCP. Auch „lokal“ bedeutet nicht ohne weitere Regeln „für alle ungefährlich“. Ein gesendeter Datenblock ist bei einem Stream nicht garantiert genau ein späterer Empfangsblock. Schließlich darf eine leere Empfangsantwort nicht beliebig als vollständige Nutzdaten interpretiert werden; bei Stream-Kommunikation kann sie das Ende anzeigen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Definiere Nachrichtenformat, Fehlerbehandlung und passende Zeitgrenzen. Schließe eigene Endpunkte zuverlässig. Prüfe bei echten Anwendungen auch Berechtigungen und Gegenstellen. Dieser Versuch verändert keine Netzwerkkonfiguration und baut keine Verbindung zu vorhandenen lokalen oder entfernten Diensten auf.

## 10. Verwandte Begriffe

Ein [Prozess](it_0115.md) kann einen Endpunkt verwenden. Ein [Service](it_0119.md) kann darüber Anfragen bearbeiten. Ein [Event Loop](it_0077.md) kann mehrere Kommunikationsereignisse koordinieren. Ein [String](it_0007.md) muss für einen Bytekanal passend kodiert werden.

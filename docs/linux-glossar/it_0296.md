# Debugger

## 1. Kurzbeschreibung

Ein Debugger hilft, den Zustand eines Programms während seiner Ausführung zu untersuchen. Du kannst das Programm anhalten, Variablen betrachten und einzelne Schritte verfolgen. Dadurch lässt sich prüfen, wann sich das tatsächliche Verhalten von einer Erwartung entfernt.

## 2. Was bedeutet der Begriff?

Die [Python-Dokumentation zu pdb](https://docs.python.org/3.13/library/pdb.html) nennt Haltepunkte, Einzelschritte, Stack-Untersuchung und Debugging nach einem Fehler. Der Stack zeigt hierbei die Kette der aktiven Funktionsaufrufe. Im [GDB-Handbuch](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Breakpoints.html) werden ähnliche Aufgaben für Programme und Zielumgebungen beschrieben, die GDB unterstützt.

## 3. Einfacher Vergleich aus dem Alltag

Bei einer Uhr beobachtest du, an welchem Zahnrad eine Bewegung verloren geht. Mit einem Debugger kannst du einen Programmablauf ebenfalls an ausgewählten Stellen betrachten. Die Beobachtung selbst kann bei zeitabhängigen Vorgängen den Ablauf beeinflussen.

## 4. Wie funktioniert das?

Ein Debugger kann einen eigenen Prozess starten oder je nach System und Berechtigungen an einen laufenden Prozess angebunden werden. Wenn das Ziel anhält, kannst du beispielsweise den aktuellen Aufruf oder lokale Variablen ansehen. Ein Einzelschritt kann in eine Funktion hineinführen, während ein Schritt über den Aufruf hinweg danach anhält.

Bei nativem Code beeinflussen Debug-Informationen und Optimierungen, welche Quellzeilen und Variablen sinnvoll angezeigt werden. In einem Python-Programm gelten andere Werkzeuge und Laufzeitregeln. Auch dort kann das Auswerten eigener Ausdrücke Seiteneffekte haben.

## 5. Wo begegnet mir das unter Linux?

Unter Linux gibt es Terminaldebugger und IDE-Oberflächen. Ihr Einsatz hängt davon ab, welche Programmsprache und welcher Prozess untersucht werden. Das Anbinden an einen fremden Prozess unterliegt besonderen Systemgrenzen.

## 6. Konkretes Beispiel Schritt für Schritt

Gedankenbeispiel. Ein eigenes Programm berechnet drei Packungen mit je zwei Stiften und zeigt fälschlich fünf an.

1. Formuliere das erwartete Ergebnis sechs und reproduziere fünf mit derselben Eingabe.
2. Halte im Modell in der Mengenfunktion an. Prüfe, ob drei und zwei dort tatsächlich ankommen.
3. Untersuche den Rechenschritt. Eine Addition würde genau fünf liefern.
4. Nach einer Korrektur würde ein Test mit mehreren Eingaben absichern, dass das beabsichtigte Verhalten erhalten bleibt.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Protokoll sammelt Beobachtungen, während ein Programm weiterläuft. Ein Debugger ermöglicht eine interaktive Momentaufnahme. Ein Test vergleicht Ergebnisse anhand definierter Erwartungen und kann später denselben Fehler erneut erkennen.

## 8. Häufige Missverständnisse

Ein angezeigter Wert beweist nur den Zustand an der beobachteten Stelle. Bei einem Zeitproblem kann ein Halten das Verhalten verändern. Eine im Debugger kurzfristig geänderte Variable ist außerdem keine Korrektur am Quelltext.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Untersuche zuerst eigene reproduzierbare Prozesse. Gehe sorgfältig mit lokalen Variablen um, weil sie Zugangsdaten oder persönliche Daten enthalten können. Halte Eingaben und konkrete Beobachtungen fest.

## 10. Verwandte Begriffe

[IDE](it_0294.md) kann eine Bedienoberfläche bereitstellen. [Test](it_0246.md) wiederholt eine erwartete Prüfung. [Prozess](it_0115.md) ist ein mögliches Untersuchungsziel.

# pathlib

## 1. Kurzbeschreibung

`pathlib` ist ein Modul der Python-Standardbibliothek zum Umgang mit Dateisystempfaden. Es stellt Pfade als Objekte dar. Damit lassen sich beispielsweise Teilnamen verbinden, Dateiendungen abfragen und Dateien lesen. Ein dargestellter Pfad bedeutet zunächst nur eine mögliche Adresse, nicht automatisch eine vorhandene Datei.

## 2. Was bedeutet der Begriff?

Ein Pfad beschreibt, wo ein Eintrag im Dateisystem liegt oder liegen könnte. Mit `Path` bietet `pathlib` eine zur aktuellen Plattform passende Darstellung samt Dateisystemoperationen. Aus einem solchen Objekt können weitere Pfade abgeleitet werden, ohne Trennzeichen mühsam von Hand zusammenzufügen.

Das Modul unterscheidet dabei reine Pfadberechnungen und konkrete Zugriffe. Die [Dokumentation zu reinen Pfaden](https://docs.python.org/3.13/library/pathlib.html#pure-paths) erklärt Klassen, die Namen bearbeiten, ohne das Dateisystem anzusprechen. Ein `Path`-Objekt kann zusätzlich Operationen wie Lesen oder Verzeichnisprüfung durchführen. Nicht jede Methode verursacht daher dieselbe Art von Arbeit.

## 3. Einfacher Vergleich aus dem Alltag

Eine Adresse auf einem Zettel kann aus Ort, Straße und Hausnummer zusammengesetzt werden. Du kannst die Hausnummer ablesen, ohne das Gebäude zu besuchen. Erst eine tatsächliche Zustellung prüft die reale Situation vor Ort.

Entsprechend ist das Verbinden eines Verzeichnisnamens mit einem Dateinamen noch kein Dateizugriff. Die Grenze des Vergleichs: Pfade haben technische Regeln, etwa für absolute Namen und symbolische Links. Sie sind außerdem keine Besitznachweise und versprechen keine Zugriffsrechte. Eine korrekt geschriebene Adresse kann auf etwas zeigen, das gerade nicht existiert.

## 4. Wie funktioniert das?

`Path("daten") / "probe.txt"` erzeugt einen zusammengesetzten Pfad. Der Operator `/` verbindet hier Pfadbestandteile; er führt keine numerische Division aus. Eigenschaften wie `name`, `stem` und `suffix` liefern den letzten Namen, dessen Stamm und die letzte Endung.

`read_text` öffnet dagegen eine Datei, liest ihren Text und schließt sie wieder. Die [Referenz zu read_text und write_text](https://docs.python.org/3.13/library/pathlib.html#pathlib.Path.read_text) beschreibt diese Zugriffe und weist darauf hin, dass `write_text` eine vorhandene gleichnamige Datei überschreibt. Eine ausdrücklich angegebene Textkodierung macht den beabsichtigten Umgang mit Umlauten nachvollziehbar.

## 5. Wo begegnet mir das unter Linux?

Python-Werkzeuge verwenden Pfade für Konfigurationsdateien, eigene Ergebnisse und Anwendungsdaten. Unter Linux entstehen normalerweise POSIX-Pfade. Relative Pfade beziehen sich bei Zugriffen auf das aktuelle Arbeitsverzeichnis; sie zeigen nicht automatisch neben das gerade ausgeführte Skript.

Das Katalogbeispiel [Path.home](https://docs.python.org/3.13/library/pathlib.html#pathlib.Path.home) liefert einen Pfad zum aufgelösten Benutzerverzeichnis. Es gibt keinen für alle Benutzer festen Wert. Kann dieses Verzeichnis nicht aufgelöst werden, dokumentiert Python einen Fehler. Der folgende Versuch verwendet bewusst nur einen selbst angelegten temporären Ordner.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 ausgeführt. Seine einzige Datei wird innerhalb eines temporären Ordners erzeugt und danach zusammen mit diesem aufgeräumt.

```python
from pathlib import Path
import tempfile

with tempfile.TemporaryDirectory() as ordner:
    datei = Path(ordner) / "probe.txt"
    assert not datei.exists()
    assert datei.name == "probe.txt"
    assert datei.stem == "probe"
    assert datei.suffix == ".txt"

    datei.write_text("Grüße\n", encoding="utf-8")
    assert datei.is_file()
    assert datei.read_text(encoding="utf-8") == "Grüße\n"
    print(datei.name)
    print(datei.read_text(encoding="utf-8").strip())
```

Geprüfte Ausgabe:

```text
probe.txt
Grüße
```

Zunächst existiert nur das Pfadobjekt. Erst `write_text` erzeugt die Datei. Die Assertions prüfen Namensbestandteile, das tatsächliche Vorhandensein einer Datei und den gelesenen Inhalt. Die Ausgabe enthält absichtlich keinen wechselnden absoluten Temporärpfad. `Path.home` wird hier nicht aufgerufen und kein Benutzerverzeichnis verändert.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein String kann einen Pfadtext enthalten, bietet aber nicht dieselben Pfadmethoden. Ein geöffnetes Dateiobjekt repräsentiert einen laufenden Zugriff, während ein `Path` zunächst eine Adresse beschreibt. Eine Dateiendung wie `.txt` ist Teil des Namens und beweist nicht, dass der Inhalt tatsächlich passenden Text enthält.

## 8. Häufige Missverständnisse

Das Anlegen eines `Path` erzeugt keine Verzeichnisse. Ein absoluter zusätzlicher Pfadbestandteil kann vorherige Bestandteile verdrängen; bloßes Verbinden ist deshalb keine sichere Begrenzung fremder Eingaben auf einen Zielordner. Auch `exists` reserviert eine Datei nicht: Zwischen Prüfung und späterem Zugriff kann sich die Situation ändern.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Arbeite bei Schreibversuchen zuerst in einem eigenen Testordner. Prüfe bewusst, ob Überschreiben erlaubt ist, und behandle mögliche Zugriffsfehler. Verwende für fremde Dateinamen eine passende Eingabeprüfung. Pfadmethoden heben Dateirechte nicht auf und bieten allein keine Sicherheitsgrenze gegen unerwünschte Ziele.

## 10. Verwandte Begriffe

Ein [String](it_0007.md) kann die textuelle Pfadangabe liefern. Ein [Objekt](it_0053.md) verbindet hier Werte mit passenden Operationen. Eine [Exception](it_0091.md) kann beim fehlgeschlagenen Dateizugriff auftreten; eine syntaktisch plausible Adresse verhindert das nicht.

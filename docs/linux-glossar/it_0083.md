# Theme

## 1. Kurzbeschreibung

Ein Theme ist eine zusammengehörige Gestaltungsvorgabe für eine Oberfläche. Es kann Farben, Formen, Abstände und zustandsabhängige Darstellungen beeinflussen. Die Quelle nennt Dark Mode als Beispiel. Ein dunkler Modus kann eine Theme-Variante sein; er beschreibt aber nicht automatisch die gesamte Gestaltung oder eine bestimmte technische Implementierung.

## 2. Was bedeutet der Begriff?

Eine Anwendung soll zusammengehörig wirken, statt jedes Element unabhängig zu gestalten. Ein Theme bündelt dafür passende Regeln. Welche Regeln es tatsächlich umfasst und ob sie vom Betriebssystem übernommen werden, hängt vom Toolkit und der Anwendung ab.

Das [offizielle Tk-Handbuch zu ttk::style](https://raw.githubusercontent.com/tcltk/tk/core-8-6-branch/doc/ttk_style.n) unterscheidet den Stil eines Widgets von einem Theme als Sammlung entsprechender Elemente und Stile. Eine einzelne Textfarbe ist deshalb noch nicht zwingend ein vollständiges Theme.

## 3. Einfacher Vergleich aus dem Alltag

Eine Einrichtungslinie legt passende Farben und Formen für mehrere Möbel fest. Die einzelnen Gegenstände behalten ihre Aufgabe, wirken aber nach gemeinsamen Vorgaben gestaltet.

Die Grenze des Vergleichs: Softwareelemente besitzen Zustände wie deaktiviert oder ausgewählt. Die Gestaltung muss diese Unterschiede weiterhin erkennbar machen. Außerdem können Textgrößen und Abstände die Bedienbarkeit beeinflussen. Ein optischer Wechsel ist daher nicht immer unabhängig von Platzbedarf und Lesbarkeit.

## 4. Wie funktioniert das?

Ein Toolkit verwaltet Stile und verwendet sie beim Zeichnen. Anwendungen können einen vorhandenen Stil auswählen, ergänzen oder ein eigenes Theme ableiten. Nicht jede Plattform erlaubt dabei dieselben sichtbaren Anpassungen.

Pythons `ttk.Style.theme_create` kann ein Theme mit einem vorhandenen Theme als Grundlage erzeugen. Die [offizielle Referenz](https://docs.python.org/3.13/library/tkinter.ttk.html#tkinter.ttk.Style.theme_create) beschreibt das Erben von Stilen, Elementen und Layouts. Das ist eine konkrete Tk-Schnittstelle und keine universelle Theme-Dateiform für andere Bibliotheken.

Ein Wechsel sollte auch Sonderzustände berücksichtigen. Eine im Normalzustand gut lesbare Farbe kann auf einer Auswahlfläche unpassend sein. Ein erfolgreicher Konfigurationszugriff beweist deshalb nicht, dass sämtliche Zustandskombinationen sinnvoll dargestellt werden.

## 5. Wo begegnet mir das unter Linux?

Desktopumgebungen und Anwendungen bieten oft helle, dunkle oder kontrastreiche Darstellungen. Eine Anwendung kann eigene Regeln besitzen oder Teile der Systemgestaltung übernehmen. Ein Wechsel an einer Stelle muss deshalb nicht jedes Programm identisch verändern.

NetMons Gestaltung kann solche Konzepte verwenden. Dieses Dokument verändert jedoch keine vorhandenen Anwendungs- oder Systemeinstellungen. Das folgende Beispiel erzeugt nur ein eigenes kurzlebiges Tk-Theme im isolierten Beispielprozess.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel wurde unter dem vorhandenen virtuellen Bildschirm ausgeführt. Das eigene Fenster bleibt verborgen:

```python
# GUI-Prüfung im virtuellen Bildschirm
import tkinter as tk
from tkinter import ttk

root = tk.Tk()
root.withdraw()
try:
    stil = ttk.Style(root)
    basis = stil.theme_use()
    stil.theme_create("GlossarProbe", parent=basis, settings={
        "Probe.TLabel": {"configure": {"foreground": "#224466"}}
    })
    stil.theme_use("GlossarProbe")
    assert stil.theme_use() == "GlossarProbe"
    assert stil.lookup("Probe.TLabel", "foreground") == "#224466"
    print(stil.theme_use())
    print(stil.lookup("Probe.TLabel", "foreground"))
finally:
    root.destroy()
```

Die Ausgabe lautet:

```text
GlossarProbe
#224466
```

Das neue Theme baut auf dem aktuellen eigenen Tk-Theme auf. Geprüft werden Auswahl und gespeicherte Stiloption. Es wird keine Farbe auf einem Bildschirm beurteilt. Die Hexangabe ist ein eigener Testwert, keine Empfehlung für ausreichenden Kontrast in allen Zuständen.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Stil kann einzelne Widget-Regeln beschreiben. Ein Theme bündelt Gestaltung. Ein Layout ordnet Elemente an. Ein Dark Mode bezeichnet eine dunkle Darstellungsweise. Fachliche Funktion und Berechtigung sind davon getrennt: Eine dunkle Oberfläche arbeitet nicht automatisch sicherer oder richtiger.

## 8. Häufige Missverständnisse

Dark Mode ist kein überall einheitliches Theme. Eine gesetzte Farbe garantiert keine Lesbarkeit. Ein Theme-Wechsel betrifft nicht zwingend alle Programme. Auch können benutzerdefinierte Regeln die Wirkung eines neuen Themes teilweise überlagern.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe Text, Auswahl, deaktivierte Zustände und geänderte Größen gesondert. Vermeide alleinige Farbcodierung wichtiger Aussagen. Das Beispiel testet nur eigene Tk-Konfiguration; NetMons Erscheinungsbild, Systemtheme und visuelle Zugänglichkeit wurden nicht praktisch abgenommen.

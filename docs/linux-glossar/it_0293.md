# Transpiler

## 1. Kurzbeschreibung

Ein Transpiler übersetzt Quellcode in anderen Quellcode. Die Ausgabe kann eine andere Sprache oder eine andere Fassung derselben Sprache sein. Ein verbreitetes Beispiel ist die Ausgabe von JavaScript aus TypeScript.

## 2. Was bedeutet der Begriff?

Die [TypeScript-Einführung](https://www.typescriptlang.org/docs/handbook/typescript-from-scratch.html) beschreibt TypeScript als statisches Typprüfsystem für JavaScript und erläutert die Rolle der Übersetzung. Typannotationen können beim Erzeugen von JavaScript entfallen. Die für das Programmverhalten nötigen Anweisungen werden entsprechend der Zielsprache ausgegeben.

## 3. Einfacher Vergleich aus dem Alltag

Ein Text wird für Leser einer anderen Ausgabe desselben Nachschlagewerks angepasst. Die Aussage soll erhalten bleiben, obwohl sich die Ausdrucksmittel ändern. Bei Code muss der Übersetzer zusätzlich auf Regeln wie Sichtbarkeit und Auswertungsreihenfolge achten.

## 4. Wie funktioniert das?

Ein TypeScript-Werkzeug verarbeitet Struktur und Typinformationen des Quelltextes. Die Typprüfung kann vor der Laufzeit viele unstimmige Verwendungen finden. Die eigentliche JavaScript-Ausgabe richtet sich unter anderem nach `target`. Die [TSConfig-Referenz zu target](https://www.typescriptlang.org/tsconfig/target.html) erklärt, welche JavaScript-Konstrukte unverändert bleiben oder für ältere Ziele umgeschrieben werden.

Die Umformung von Syntax stellt keine fehlenden Plattformfunktionen bereit. Wenn ein Browser eine benötigte Funktion seiner Umgebung nicht bietet, sind beispielsweise geprüfte Ersatzimplementierungen oder ein anderes Ziel nötig.

## 5. Wo begegnet mir das unter Linux?

Unter Linux läuft ein solcher Übersetzungsschritt häufig lokal und in der automatisierten Buildprüfung. Der erzeugte JavaScript-Code kann anschließend in einem Browser oder einer geeigneten Laufzeit gestartet werden. Beide Umgebungen können unterschiedliche bereitgestellte Funktionen haben.

## 6. Konkretes Beispiel Schritt für Schritt

Gedankenbeispiel ohne Compileraufruf. Eine Datei enthält diese Anweisung.

```typescript
const anzahl: number = 3;
```

1. Das Übersetzungswerkzeug kann prüfen, dass der Wert zum angegebenen Typ passt.
2. Bei einem modernen Ziel könnte die Ausgabe die Deklaration als `const anzahl = 3;` enthalten. Die Typannotation gehört nicht zur entsprechenden JavaScript-Syntax.
3. Die JavaScript-Laufzeit verarbeitet später die erzeugte Deklaration.
4. Ein anderes Ziel könnte eine andere Deklarationsform erzeugen. Das Beispiel behauptet keinen exakten Ausgabe- oder Funktionstest.

## 7. Abgrenzung zu ähnlichen Begriffen

[Compiler](it_0291.md) ist der umfassendere Begriff. Transpiler betont die textuelle Zielausgabe. Ein Bündelungswerkzeug sammelt Module und kann zusätzlich eine Übersetzung anstoßen. Beide Aufgaben können im selben Build auftreten.

## 8. Häufige Missverständnisse

Eine Typannotation wird nicht automatisch zu einer Laufzeitprüfung externer Daten. Eine erfolgreiche Übersetzung beweist weder das gewünschte Verhalten noch die Verfügbarkeit aller eingesetzten APIs.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe das Ziel gegen die vorgesehenen Laufzeitumgebungen. Verwende bei Fehlern die ursprünglichen Quellen und gegebenenfalls die Zuordnung zwischen Original- und Ausgabeposition. Dokumentiere Optionen, die das Ergebnis beeinflussen.

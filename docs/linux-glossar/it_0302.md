# Garbage Collection

## 1. Kurzbeschreibung

Garbage Collection ist automatische Speicherbereinigung für nicht mehr benötigte Objekte. Die Laufzeit entscheidet anhand ihrer Verwaltungsregeln, wann sie Speicher eines Objekts wiederverwenden kann. Zeitpunkt und Verfahren unterscheiden sich zwischen Sprachen und Implementierungen.

## 2. Was bedeutet der Begriff?

Ein Objekt ist erreichbar, wenn es über noch aktive Referenzen gefunden werden kann. Ein Name, eine Liste oder ein anderes Objekt kann eine solche Referenz enthalten. Das [Python-Datenmodell](https://docs.python.org/3.13/reference/datamodel.html) beschreibt, dass nicht mehr erreichbare Objekte für eine Sammlung infrage kommen. Die genaue zeitliche Freigabe ist für Python allgemein nicht garantiert.

## 3. Einfacher Vergleich aus dem Alltag

Wenn eine Gruppe Arbeitsunterlagen gemeinsam nutzt, darf eine Mappe erst weggeräumt werden, sobald niemand sie mehr braucht. Zwei darin liegende Listen können weiterhin aufeinander verweisen. Für die Software ist entscheidend, ob irgendein aktiver Weg von außen zu diesen Objekten führt. Die Laufzeit erkennt dabei technische Erreichbarkeit und nicht die Absicht des Entwicklers.

## 4. Wie funktioniert das?

CPython verwendet Referenzzählung. Bei gewöhnlichen Objekten kann die letzte freigegebene starke Referenz zur unmittelbaren Freigabe führen. Zyklen sind ein Sonderfall. Wenn sich zwei Objekte gegenseitig halten, bleiben ihre Referenzzähler positiv, obwohl der übrige Code beide verloren hat. Der in [gc](https://docs.python.org/3.13/library/gc.html) dokumentierte Zyklensammler ergänzt die Referenzzählung.

Offene Dateien und ähnliche Ressourcen sollten einen ausdrücklich geregelten Lebenszyklus haben. Ein Kontextmanager mit `with` kann für die Datei einen klaren Bereich vorgeben und sie beim Verlassen schließen.

## 5. Wo begegnet mir das unter Linux?

Unter Linux läuft der Python-Sammler innerhalb des Prozesses. Speicher, der dort zur Wiederverwendung frei wird, erscheint nicht zwangsläufig sofort als geringerer Verbrauch in einer Systemanzeige. Diese Anzeige misst eine andere Ebene.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses Beispiel richtet zwei zyklisch verbundene Objekte im eigenen Python-Prozess ein. Es hält zur Beobachtung nur schwache Referenzen zurück.

```python
import gc
import weakref

class Knoten:
    pass

automatisch = gc.isenabled()
gc.disable()
try:
    links, rechts = Knoten(), Knoten()
    links.partner, rechts.partner = rechts, links
    refs = (weakref.ref(links), weakref.ref(rechts))
    del links, rechts
    assert all(ref() is not None for ref in refs)
    gc.collect()
    assert all(ref() is None for ref in refs)
    print("Zyklus freigegeben")
finally:
    if automatisch:
        gc.enable()
```

Die erwartete Ausgabe ist `Zyklus freigegeben`. Der Lauf ist ein kontrolliertes CPython-Beispiel.

## 7. Abgrenzung zu ähnlichen Begriffen

Referenzzählung und Zyklensammlung sind verschiedene Techniken. Ein [Memory Leak](it_0301.md) kann trotz Sammlung auftreten, wenn das Programm eine Referenz unbeabsichtigt weiter hält.

## 8. Häufige Missverständnisse

`del` entfernt im Beispiel die lokalen Namen. Es garantiert für sich genommen keine Freigabe der Objekte. Eine manuelle Sammlung ersetzt auch keine saubere Verwaltung dauerhaft gehaltener Daten.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Verlasse dich für zeitkritische Ressourcen nicht auf einen späteren Sammlungslauf. Prüfe bei Speicherproblemen zunächst, welche Objekte erreichbar bleiben und ob der beobachtete Verbrauch zur Aufgabenlast passt.

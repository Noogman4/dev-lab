# Regression

## 1. Kurzbeschreibung

Eine Regression ist eine Verschlechterung eines zuvor funktionierenden Verhaltens nach einer Änderung. Das kann ein erneut auftretender bekannter Fehler sein, aber auch ein neu verursachter Fehler in einem bisher korrekten Fall. Regressionstests sollen wichtige bestehende Erwartungen wiederholt prüfen. Sie verhindern nicht automatisch jede Verschlechterung, können passende Fälle aber früh sichtbar machen.

## 2. Was bedeutet der Begriff?

Die Quelle nennt einen schon behobenen Bug, der zurückkehrt. Dieser Fall ist besonders anschaulich: Ein zugehöriger Test hält fest, welches Verhalten nach der Korrektur erwartet wird. Spätere Änderungen sollen diese Eigenschaft nicht unbemerkt verlieren.

Python dokumentiert mit seinem [eigenen Regressionstestpaket test](https://docs.python.org/3.13/library/test.html) eine konkrete große Testsammlung. Dieses Paket dient der Python-Entwicklung und ist nicht die allgemeine Grundlage, die Anwendungsprojekte einfach übernehmen sollen. Das Beispiel dieses Glossars importiert es nicht und führt keine Tests des Interpreters aus.

## 3. Einfacher Vergleich aus dem Alltag

Nach einer Reparatur schließt eine Tür wieder zuverlässig. Beim späteren Einbau eines neuen Schlosses darf diese Eigenschaft nicht unbemerkt verloren gehen. Eine erneute Funktionsprüfung zeigt, ob die frühere Zusage weiterhin erfüllt ist.

Die Grenze: Nicht jede Änderung am Verhalten ist ein Fehler. Eine bewusst geänderte Anforderung kann eine andere Türfunktion verlangen. Dann müssen Erwartung und Entscheidung nachvollziehbar angepasst werden. Eine alte Prüfung darf nicht allein deshalb als richtig gelten, weil sie schon lange existiert.

## 4. Wie funktioniert das?

Zunächst wird eine relevante bestehende Eigenschaft beschrieben. Ein Test verwendet passende Eingaben und eine begründete Erwartung. Nach Änderungen wird derselbe Vertrag erneut geprüft. Ein Fehlschlag zeigt eine Abweichung, deren Ursache anschließend untersucht werden muss.

Die [unittest-Dokumentation zur Organisation von Tests](https://docs.python.org/3.13/library/unittest.html#organizing-test-code) erläutert selbstständige Szenarien und ihre Prüfung. Für eine Regression ist diese Wiederholbarkeit wichtig: Ein Fall sollte nicht nur zufällig nach einem anderen Test funktionieren. Eigene Ausgangsdaten helfen, die erwartete Eigenschaft klar zu erkennen.

Ein bestehender Test ist keine Garantie gegen jeden neuen Fehler. Er prüft nur seine Eingaben und Beobachtungen. Auch reine Ausführung ohne passende Erwartung reicht nicht aus. Wenn beispielsweise nur geprüft wird, dass eine Funktion irgendetwas zurückgibt, kann ein fachlich falscher Text unbemerkt bleiben.

Eine Regression kann außerdem andere Eigenschaften betreffen, etwa Laufzeit oder Ressourcenbedarf. Dafür sind geeignete Messbedingungen und Erwartungen nötig. Ein kleiner funktionaler Vergleich ist keine automatische Leistungsprüfung. Ebenso kann ein Fehlschlag durch eine geänderte Umgebung entstehen, statt durch die zuletzt betrachtete Codezeile.

## 5. Wo begegnet mir das unter Linux?

Softwareprojekte verwenden wiederholte Prüfungen vor und nach Änderungen. Bibliotheks- oder Umgebungswechsel können dabei zusätzliche Unterschiede erzeugen. Zur Diagnose muss daher der tatsächlich getestete Stand bekannt sein.

Für eine vermutete Regression ist ein möglichst kleiner nachvollziehbarer Fall hilfreich. Er darf die fachliche Anforderung nicht nur durch ein internes Implementierungsdetail ersetzen. Dieses Glossar verändert keine vorherige Anwendungsversion und behauptet keinen tatsächlich gefundenen NetMon-Fehler.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Arbeitsordner ausgeführt. Beide Funktionen sind eigens für die Erklärung erzeugt. Die zweite enthält bewusst eine Verschlechterung: Sie entfernt zusätzlich alle gewöhnlichen inneren Leerzeichen.

```python
def vorher(text):
    return text.strip()

def nachher_mit_fehler(text):
    return text.strip().replace(" ", "")

eingabe = " Probe A "
erwartet = "Probe A"
alt_passt = vorher(eingabe) == erwartet
neu_passt = nachher_mit_fehler(eingabe) == erwartet
assert alt_passt and not neu_passt
assert nachher_mit_fehler(eingabe) == "ProbeA"
print("Vorher erfüllt den Vertrag:", alt_passt)
print("Geänderte Fassung erfüllt den Vertrag:", neu_passt)
```

Geprüfte Ausgabe:

```text
Vorher erfüllt den Vertrag: True
Geänderte Fassung erfüllt den Vertrag: False
```

Die Erwartung verlangt entfernte Randabstände und erhaltene innere Worttrennung. Die neue Fassung verletzt genau diesen bisher erfüllten Fall. Der Versuch zeigt die Erkennung der absichtlich eingebauten Abweichung. Er ändert keine Repository-Funktion und behauptet keine umfassende Regressionstestsuite.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Bug kann bereits im ursprünglichen Stand bestehen. Eine Regression bezieht sich auf eine Verschlechterung gegenüber früherem Verhalten. Eine bewusst beschlossene Anforderungsänderung ist davon zu unterscheiden. Ein Testfehlschlag ist zunächst eine Beobachtung, deren Ursache noch geprüft werden muss.

## 8. Häufige Missverständnisse

Eine Regression muss nicht exakt derselbe alte Bug sein. Ein grüner Altbestand deckt nicht jede neue Situation ab. Ein fehlgeschlagener Test beweist nicht automatisch die vermutete Ursache. Und absichtlich geänderte Anforderungen sollten nicht durch blindes Festhalten an alten Erwartungen blockiert werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Halte wichtige Fehlerfälle als nachvollziehbare Erwartungen fest. Prüfe Abweichungen mit bekanntem Ausgangsstand und eigenen Daten. Das Beispiel enthält nur eigene Textfunktionen und verändert weder Anwendung, Testsuite, Abhängigkeiten noch reale Betriebsdaten.

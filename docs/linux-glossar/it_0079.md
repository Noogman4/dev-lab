# Layout

## 1. Kurzbeschreibung

Layout bezeichnet die Anordnung und Größenverteilung von Oberflächenelementen. Die Quelle nennt Reihen und Spalten als Beispiel. Zu einem brauchbaren Layout gehören aber auch Abstände, Ausrichtung, Platzanforderungen und das Verhalten bei veränderter verfügbarer Größe. Es ist mehr als die zufällige Position einzelner Knöpfe beim ersten Start.

## 2. Was bedeutet der Begriff?

Eine Oberfläche besitzt Beziehungen zwischen ihren Elementen. Eine Beschriftung soll zum passenden Feld gehören, zusammengehörige Aktionen sollten erkennbar gruppiert sein. Die Anordnung unterstützt diese Bedeutung und beeinflusst, ob Inhalte erreichbar und lesbar bleiben.

Ein Layoutmanager berechnet Positionen und Größen anhand von Regeln. Die [offizielle Qt-Dokumentation zum Layoutmanagement](https://doc.qt.io/qt-6/layout.html) beschreibt die automatische Anordnung von Kind-Widgets und Reaktionen auf veränderten Platz oder Inhalt. Diese Hilfe garantiert nicht von selbst, dass jede Anwendung bei beliebig kleiner Größe sinnvoll bedienbar bleibt.

## 3. Einfacher Vergleich aus dem Alltag

Auf einer Arbeitsfläche werden Werkzeuge und Unterlagen so angeordnet, dass zusammengehörige Dinge erreichbar bleiben. Verändert sich die verfügbare Fläche, muss die Anordnung gegebenenfalls angepasst werden.

Die Grenze des Vergleichs: Software kann Größen rechnerisch verteilen und auf Schrift- oder Inhaltsänderungen reagieren. Feste Koordinaten bilden dabei nicht automatisch die tatsächlichen Platzanforderungen ab. Übersetzte Beschriftungen oder andere Skalierung können eine zunächst passende Anordnung überfordern.

## 4. Wie funktioniert das?

Ein Toolkit verwaltet die Beziehungen innerhalb eines Containers. Regeln können Zeilen, Spalten, Ausrichtung und die Verteilung zusätzlichen Platzes beschreiben. Kind-Elemente besitzen eigene Größenanforderungen, die bei der Anordnung berücksichtigt werden müssen.

Tk bietet dafür unter anderem `grid`. Das [offizielle grid-Handbuch](https://raw.githubusercontent.com/tcltk/tk/core-8-6-branch/doc/grid.n) beschreibt Zeilen und Spalten sowie zugehörige Optionen. Mit Gewichten lässt sich zusätzlicher Platz verteilen. Die Ausrichtung eines Elements innerhalb seiner Zelle ist wiederum eine gesonderte Einstellung.

Regeln wirken auf der jeweiligen Container-Ebene. Ein dehnbares Feld kann nicht automatisch den gesamten Fensterplatz nutzen, wenn seine übergeordneten Bereiche keinen passenden Platz erhalten. Auch unterschiedliche Layoutverfahren besitzen eigene Regeln und sollten nicht unbedacht im selben Zuständigkeitsbereich gemischt werden.

## 5. Wo begegnet mir das unter Linux?

Einstellungsdialoge, Dateimanager und NetMons Ansichten benötigen Layouts. Lange Ergebnislisten und kleine Fenster stellen andere Anforderungen als kurze Startansichten. Ein sichtbarer Anfangszustand ist deshalb nur ein Teil der Prüfung.

Für eine tatsächliche Abnahme sind mehrere Größen, Schriftbedingungen und Inhalte relevant. Ein im Toolkit gespeicherter Zeilenwert beweist noch nicht, dass eine Beschriftung auf dem Bildschirm vollständig lesbar oder ein Bedienelement erreichbar ist.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel prüft eigene Tk-Anordnungsvorgaben unter dem virtuellen Bildschirm. Das Fenster bleibt verborgen:

```python
# GUI-Prüfung im virtuellen Bildschirm
import tkinter as tk
from tkinter import ttk

root = tk.Tk()
root.withdraw()
try:
    rahmen = ttk.Frame(root)
    rahmen.grid(row=0, column=0, sticky="nsew")
    rahmen.columnconfigure(1, weight=1)
    text = ttk.Label(rahmen, text="Name")
    feld = ttk.Entry(rahmen)
    text.grid(row=0, column=0, sticky="w")
    feld.grid(row=0, column=1, sticky="ew")
    info = feld.grid_info()
    assert info["row"] == 0 and info["column"] == 1
    assert info["sticky"] == "ew"
    assert rahmen.columnconfigure(1)["weight"] == 1
    print(info["row"], info["column"])
    print(rahmen.columnconfigure(1)["weight"])
finally:
    root.destroy()
```

Die Ausgabe lautet:

```text
0 1
1
```

Beschriftung und Feld liegen in derselben Zeile. Das Feld erhält eine seitliche Ausrichtung und seine Spalte ein Gewicht. Geprüft werden diese tatsächlich gespeicherten Vorgaben. Pixelgrößen, reale Größenänderung und sichtbare Lesbarkeit sind nicht Bestandteil dieses Beispiels.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Container gruppiert Elemente. Ein Layout ordnet sie an. Ein Theme gestaltet das Erscheinungsbild nach weiteren Regeln. Eine Widget-Hierarchie beschreibt Elternbeziehungen, nicht allein die sichtbare räumliche Anordnung. Eine feste Mindestgröße ist ebenfalls keine vollständige Layoutstrategie.

## 8. Häufige Missverständnisse

Ein wachsendes Fenster macht nicht jedes Kind automatisch größer. Zeilen und Spalten sortieren Inhalte nicht fachlich. Ein ausgeführter Layoutmanager garantiert keine vollständige Bedienbarkeit. Außerdem kann ein Layout mit kurzen Beispieltexten gut aussehen und mit langen realen Inhalten scheitern.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe Hierarchie, Größenverteilung und Inhalte gemeinsam. Berücksichtige kleine Fenster und geänderte Schriftgrößen. Das Beispiel testet nur eigene grid-Konfiguration; keine visuelle NetMon-/Reader-, Skalierungs- oder Tastaturabnahme wurde durchgeführt.

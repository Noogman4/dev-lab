# Codebase

## 1. Kurzbeschreibung

Eine Codebase ist die zusammengehörende Sammlung von Quellcode eines Projekts oder Produkts. Dazu können mehrere Programme, Bibliotheken und Tests gehören. Die Quelle nennt NetMons Python-Dateien als Beispiel. Das beschreibt einen wichtigen Teil seiner Codebasis; eine Codebase muss jedoch weder nur eine Sprache noch nur eine einzige Anwendung enthalten.

## 2. Was bedeutet der Begriff?

Der Begriff bezeichnet einen fachlich zusammengehörenden Bestand, keine spezielle Datei und kein fest vorgeschriebenes Verzeichnisformat. Ein Team muss klären, welche Teile es darunter versteht: eigener Anwendungscode, Testcode, Build-Hilfen und gegebenenfalls eingebundener fremder Code können unterschiedliche Verantwortlichkeiten haben.

Nicht alles im Projektordner ist automatisch eigener Quellcode. Dokumentation, Konfigurationsbeispiele, Bilder und erzeugte Pakete können dazugehören, ohne dieselbe Rolle zu besitzen. Ein Verzeichnis mit vielen Dateien sagt für sich allein wenig darüber aus, wie die Software aufgebaut oder wartbar ist.

## 3. Einfacher Vergleich aus dem Alltag

Die Codebase ähnelt den zusammengehörenden Bauplänen einer Werkstatt: Verschiedene Blätter beschreiben einzelne Teile, zusammen ermöglichen sie die Arbeit am Produkt. Eine Änderung an einem Teil kann andere Pläne betreffen.

Die Grenze des Vergleichs: Software ist ausführbar und besitzt überprüfbare Abhängigkeiten. Außerdem können Teile an mehreren Orten liegen oder von anderen Projekten geliefert werden. Ein einziger Ablageordner muss deshalb nicht die vollständige fachliche Grenze darstellen, und eine kopierte Datei erklärt noch nicht ihre Herkunft oder Lizenz.

## 4. Wie funktioniert das?

Eine wachsende Anwendung wird häufig in kleinere Einheiten gegliedert. Python unterstützt beispielsweise Module, deren Definitionen aus anderen Modulen genutzt werden können. Das [offizielle Tutorial zu Modulen](https://docs.python.org/3.13/tutorial/modules.html#modules) erklärt diese Aufteilung und die Wiederverwendung ohne bloßes Kopieren von Funktionsdefinitionen.

Versionsverwaltung zeichnet Änderungen auf. Ein Git-Repository enthält dafür eigene Verwaltungsstrukturen und kann einen zugehörigen Arbeitsbaum besitzen. Die [offizielle Git-Dokumentation zum Repository-Aufbau](https://raw.githubusercontent.com/git/git/master/Documentation/gitrepository-layout.adoc) beschreibt auch Repositories ohne Arbeitsbaum. Codebase und Repository sind daher keine identischen Begriffe: Das eine beschreibt den Codebestand, das andere eine konkrete Verwaltungsstruktur.

## 5. Wo begegnet mir das unter Linux?

Beim Entwickeln einer Python-Anwendung arbeitest du oft in einem Checkout mit Quelltext, Tests und Begleitdateien. Vor einer Änderung solltest du Einstiegspunkte und Zuständigkeiten verstehen: Welche Dateien bauen die Oberfläche, welche berechnen Daten, welche prüfen das Verhalten?

Eine installierte Anwendung ist nicht automatisch eine vollständige bearbeitbare Codebase. Sie kann erzeugte oder zusammengestellte Dateien enthalten und Entwicklungsunterlagen auslassen. Auch ein ausgecheckter Stand benötigt möglicherweise zusätzliche dokumentierte Abhängigkeiten, bevor sich Programme starten oder Tests ausführen lassen.

## 6. Konkretes Beispiel Schritt für Schritt

Das folgende Gedankenbeispiel beschreibt ein erfundenes kleines Projekt, keine tatsächlich angelegte Dateistruktur:

```text
mini-monitor/
    anzeige.py
    auswertung.py
    tests/
        test_auswertung.py
    README.md
```

Zuerst ordnest du die Rollen zu: `anzeige.py` soll Ergebnisse darstellen, `auswertung.py` die fachliche Berechnung bündeln. Die Testdatei beschreibt Erwartungen an diese Berechnung. `README.md` soll die Verwendung erklären.

Danach stellst du eine Änderungsfrage: Soll lediglich der Meldungstext anders aussehen, ist eine Änderung der Berechnungsregeln möglicherweise unnötig. Soll sich die Berechnung ändern, müssen zugehörige Erwartungen geprüft werden. Die Aufteilung ermöglicht also gezieltes Arbeiten; sie garantiert diese Trennung nicht automatisch.

Dieses Strukturbeispiel wurde nicht als Projekt angelegt, importiert oder getestet. Aus den gezeigten Dateinamen allein wird kein lauffähiges Programm behauptet.

## 7. Abgrenzung zu ähnlichen Begriffen

Quellcode ist der eigentliche Programmtext. Eine Codebase fasst zusammengehörige Quelltexte zusammen. Ein Repository verwaltet einen bestimmten Bestand und seine Historie. Ein Arbeitsbaum ist ein ausgecheckter Dateistand. Ein Paket oder installiertes Produkt kann aus diesem Bestand erzeugt werden, ohne mit ihm identisch zu sein.

## 8. Häufige Missverständnisse

Eine Codebase ist nicht zwingend ein einziges Git-Repository. Viele Dateien bedeuten nicht automatisch hohe Qualität oder schlechte Struktur. Auch sind Dokumentation und Tests keine unwichtigen Reste: Sie helfen, den Codebestand richtig zu verändern, selbst wenn das Wort Codebase je nach Team enger verwendet wird.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lies Projektanleitungen und lokale Arbeitsregeln. Bewahre fremde Änderungen und unterscheide eigene Quelldateien von generierten Ergebnissen. Kopiere fremde Bestandteile nicht ohne Herkunfts- und Lizenzprüfung. Das Gedankenbeispiel erfordert keine Installation oder Änderung vorhandener Verzeichnisse.

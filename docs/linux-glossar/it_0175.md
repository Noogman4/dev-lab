# JSON

## 1. Kurzbeschreibung

JSON ist ein textbasiertes Format zum Austausch strukturierter Daten. Es kann Objekte, Arrays, Zeichenketten, Zahlen, Wahrheitswerte und `null` darstellen. Ein JSON-Dokument beschreibt Daten, keine auszuführende Programmlogik. Ob sein Inhalt zu einer Anwendung passt, muss zusätzlich zur Syntax geprüft werden.

## 2. Was bedeutet der Begriff?

Der Name steht für „JavaScript Object Notation“. Trotz dieser Herkunft ist das Format sprachunabhängig. [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259.html) definiert seine Syntax und Hinweise für den interoperablen Austausch. Das Katalogbeispiel `{"name": "NetMon"}` ist ein JSON-Objekt mit einem benannten Stringwert.

Ein JSON-Wert muss nicht immer ein Objekt sein. Auch ein Array, eine Zahl oder eine einzelne Zeichenkette kann ein gültiger vollständiger JSON-Text sein. Das erwartete Schema einer API kann trotzdem ein bestimmtes Objekt mit Pflichtfeldern verlangen. Standardformat und Anwendungsvertrag sind verschiedene Anforderungen.

## 3. Einfacher Vergleich aus dem Alltag

Ein Formularsystem erlaubt klar abgegrenzte Felder, Listen und Werte. Die gemeinsame Schreibweise erleichtert das Weiterreichen zwischen verschiedenen Stellen. Sie sagt aber nicht allein, ob die eingetragenen Angaben sinnvoll oder vollständig sind.

Die Grenze: JSON besitzt genaue Zeichen- und Typregeln. Anführungszeichen sind nicht bloß Dekoration. Außerdem können zwei syntaktisch korrekte Dokumente fachlich Unterschiedliches bedeuten, wenn Einheiten oder Feldnamen nicht vereinbart sind. Ein lesbarer Text ist deshalb noch keine sichere oder richtige Eingabe.

## 4. Wie funktioniert das?

Objekte enthalten benannte Werte; die Namen werden als Strings geschrieben. Arrays ordnen mehrere Werte in einer Folge an. Strings verwenden doppelte Anführungszeichen und definierte Escape-Regeln. Die Wörter `true`, `false` und `null` sind kleingeschrieben. Kommentare und nachgestellte Kommas gehören nicht zur Standardsyntax.

JSON-Zahlen umfassen keine Standardwerte `NaN` oder Unendlichkeit. Manche Bibliotheken erlauben Erweiterungen. Die [Python-Dokumentation zur Standardkonformität](https://docs.python.org/3.13/library/json.html#standard-compliance-and-interoperability) beschreibt beispielsweise entsprechende Voreinstellungen. „Mein Parser nimmt es an“ ist daher nicht automatisch ein Beweis für standardkonformes JSON.

Für vorhersehbaren Austausch sollten Objektnamen eindeutig sein. Die Bedeutung einer Anwendung sollte nicht von ihrer zufälligen Reihenfolge abhängen. Bei Arrays ist die Reihenfolge dagegen Teil der Daten. Auch Zahlenbereiche und Genauigkeit müssen zwischen beteiligten Implementierungen berücksichtigt werden.

## 5. Wo begegnet mir das unter Linux?

JSON erscheint in APIs, eigenen Datensammlungen und manchen Konfigurationen. Programme lesen den Text in passende Datenstrukturen ein und können ihn wieder ausgeben. Python stellt dafür unter anderem [json.dumps](https://docs.python.org/3.13/library/json.html#json.dumps) bereit.

Python-Werte und JSON-Schreibweisen sind nicht identisch: `True` wird zu `true`, `None` zu `null`. JSON ist außerdem keine allgemeine Speicherung beliebiger Python-Objekte. Ein Programm muss geeignete darstellbare Daten und gegebenenfalls eigene Umwandlungsregeln wählen.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Alle Daten sind selbst erzeugt; es werden keine Dateien oder APIs eingelesen.

```python
import json

original = {"name": "Probe", "aktiv": True, "wert": None}
text = json.dumps(original, ensure_ascii=False, allow_nan=False, sort_keys=True)
assert json.loads(text) == original
assert '"aktiv": true' in text
assert '"wert": null' in text
abgelehnt = False
try:
    json.dumps(float("nan"), allow_nan=False)
except ValueError:
    abgelehnt = True
assert abgelehnt
print(text)
print("NaN zurückgewiesen:", abgelehnt)
```

Geprüfte Ausgabe:

```text
{"aktiv": true, "name": "Probe", "wert": null}
NaN zurückgewiesen: True
```

Die Daten lassen sich hier zurücklesen. Die sortierte Ausgabe macht das Beispiel reproduzierbar, erklärt aber keine fachliche Schlüsselreihenfolge. `allow_nan=False` verhindert ausdrücklich die nicht standardkonforme Ausgabe des geprüften Sonderwerts. Daraus entsteht noch kein vollständiger Schema- oder Sicherheitsvalidator für beliebige Eingaben.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine API ist eine Schnittstelle; JSON kann eines ihrer Datenformate sein. Ein Python-Dictionary ist eine Sprachdatenstruktur. Eine Response kann JSON enthalten, muss es aber nicht. Ein String mit JSON-Text ist außerdem noch nicht dasselbe wie die bereits geparste Objektstruktur.

## 8. Häufige Missverständnisse

Einfache Anführungszeichen ersetzen nicht die vorgeschriebenen JSON-Anführungszeichen. Ein gültiges leeres Objekt enthält nicht automatisch alle Pflichtfelder. Ein erfolgreiches Parsing bestätigt auch keine Berechtigung oder richtige Fachwerte. Erweiterungen einzelner Parser dürfen nicht stillschweigend als allgemeiner Standard vorausgesetzt werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe nach dem Einlesen Struktur, Datentypen und fachliche Grenzen. Begrenze reale Eingaben angemessen. Verwende einen passenden Parser statt Text als Programmcode auszuführen. Das Beispiel arbeitet nur mit kleinen eigenen Werten und verändert keine Konfiguration oder Anwendung.

## 10. Verwandte Begriffe

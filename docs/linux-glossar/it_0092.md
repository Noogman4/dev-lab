# Traceback

## 1. Kurzbeschreibung

Ein Traceback beschreibt bei Python den zu einer Ausnahme gehörenden Verlauf von Aufrufstellen. In einer Fehlerausgabe hilft er zu erkennen, welche Funktionen und Quellzeilen beteiligt waren. Die Quelle nennt Datei, Zeile und Fehlertyp. Genauer gehören die Aufrufinformationen zum Traceback; Ausnahmeart und Meldung sind ergänzende Bestandteile der üblichen formatierten Ausgabe.

## 2. Was bedeutet der Begriff?

Eine Funktion kann eine weitere aufrufen, in der ein besonderer Fall entsteht. Der Traceback verbindet die entsprechenden Stellen. Dadurch kann ein Entwickler den Weg bis zur Ausnahme nachvollziehen, statt nur die letzte Meldung isoliert zu sehen.

Das [offizielle Python-Tutorial zu Ausnahmen](https://docs.python.org/3.13/tutorial/errors.html#exceptions) erklärt den Kontext der üblichen Fehlerausgabe. Die zuletzt sichtbare Stelle bezeichnet jedoch nicht automatisch die ursprüngliche fachliche Ursache. Eine ungeeignete Eingabe kann bereits deutlich früher entstanden sein.

## 3. Einfacher Vergleich aus dem Alltag

Eine Vorgangsliste zeigt, über welche Stationen ein Auftrag weitergereicht wurde, bis eine Stelle ihn nicht fortsetzen konnte. Sie hilft bei der Rückverfolgung, enthält aber nicht automatisch die vollständige Erklärung aller vorausgegangenen Entscheidungen.

Die Grenze des Vergleichs: Ein Traceback ist kein lückenloses Protokoll jeder jemals ausgeführten Zeile. Er bezieht sich auf den erfassten Ausnahme- und Aufrufkontext. Andere Abläufe, Threads oder bereits beendete Arbeitsschritte können zusätzliche Informationen benötigen.

## 4. Wie funktioniert das?

Python verknüpft eine Ausnahme mit einem Traceback-Objekt. Formatierungswerkzeuge können daraus eine lesbare Darstellung erzeugen. Das Standardmodul `traceback` kann die beteiligten Stellen auch als strukturierte Zusammenfassung bereitstellen.

Die [offizielle Referenz zu extract_tb](https://docs.python.org/3.13/library/traceback.html#traceback.extract_tb) beschreibt Informationen wie Dateiname, Zeilennummer und Funktionsname. Diese Daten helfen, konkrete Quellstellen aufzusuchen. Sie sind keine automatische Reparaturanweisung.

Mehrere Ausnahmen können außerdem miteinander verknüpft sein. Bei der Behandlung kann etwa eine neue Ausnahme entstehen. Eine Diagnose muss dann den tatsächlichen Zusammenhang lesen, statt lediglich den letzten sichtbaren Satz als vollständige Ursache auszugeben.

## 5. Wo begegnet mir das unter Linux?

Python-Skripte können Tracebacks im Terminal oder in Diagnoseprotokollen zeigen. Grafische Anwendungen können sie intern erfassen und eine verständlichere Benutzerinformation bereitstellen. Die technische Rückverfolgung bleibt für Entwicklung und Support nützlich.

Eine im Traceback genannte Bibliotheksdatei ist nicht allein deshalb fehlerhaft. Möglicherweise wurde ihre Schnittstelle falsch verwendet oder eine äußere Voraussetzung fehlte. Fehlertyp, Meldung, Kontext und reproduzierbare Eingabe müssen gemeinsam betrachtet werden.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel erzeugt und untersucht ausschließlich eine eigene absichtliche Ausnahme:

```python
import traceback

def innen():
    raise ValueError("Probe")

def aussen():
    innen()

try:
    aussen()
except ValueError as fehler:
    stellen = traceback.extract_tb(fehler.__traceback__)
    namen = [stelle.name for stelle in stellen]
    assert namen[-2:] == ["aussen", "innen"]
    assert all(stelle.lineno > 0 for stelle in stellen)
    print(" -> ".join(namen[-2:]))
    print(type(fehler).__name__ + ": " + str(fehler))
```

Die Ausgabe lautet:

```text
aussen -> innen
ValueError: Probe
```

Die äußere Funktion ruft die innere auf. Dort entsteht die festgelegte Ausnahme. Das Beispiel prüft die letzten beiden Aufrufstellen und gültige Zeilennummern. Ausgegeben wird bewusst nur eine eigene Auswahl der Informationen, kein vollständiger fremder Traceback und keine realen Dateipfade.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Exception ist das signalisierte Sonderereignis samt Objekt. Ein Traceback beschreibt zugehörige Aufrufstellen. Ein Log kann weitere Ereignisse über längere Zeit enthalten. Ein aktueller Aufrufstapel muss nicht dieselbe historische Situation wie ein bereits gespeicherter Traceback darstellen.

## 8. Häufige Missverständnisse

Die letzte Zeile erklärt nicht zwangsläufig die gesamte Ursache. Ein Traceback zeigt nicht jede zuvor durchlaufene Anweisung. Eine Bibliotheksstelle beweist keinen Bibliotheksbug. Das Weglassen der sichtbaren Ausgabe behebt außerdem keine zugrunde liegende Ausnahme oder fehlerhafte Verarbeitung.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Bewahre relevanten Kontext und die passende Quellversion. Prüfe Protokolle vor Weitergabe auf vertrauliche Pfade oder Inhalte. Das Beispiel nutzt nur eigene Funktionen und einen festen Meldungstext; reale Anwendungsprotokolle und sensible Daten wurden nicht untersucht.

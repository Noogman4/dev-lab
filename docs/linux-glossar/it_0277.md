# Flatpak

## 1. Kurzbeschreibung

Flatpak verteilt Linux-Anwendungen zusammen mit den Angaben zu ihrer Laufzeit und ihren Berechtigungen. Eine Anwendung läuft dabei in einer Sandbox. Das ist eine Umgebung, die Zugriffe auf Ressourcen des Hostsystems nach konfigurierten Regeln einschränkt.

## 2. Was bedeutet der Begriff?

Flatpak verwendet App-IDs und versionierte Runtimes. Eine Runtime bündelt häufig benötigte Bibliotheken, auf die mehrere Apps zurückgreifen können. Die [Flatpak-Grundbegriffe](https://docs.flatpak.org/en/latest/basic-concepts.html) erklären, wie sich App, Runtime und Sandbox zueinander verhalten. Eine App kann weitere Bibliotheken selbst mitbringen.

## 3. Einfacher Vergleich aus dem Alltag

In einer Werkstatt erhalten Teams einen eigenen Raum und nutzen gemeinsame Ausrüstung. Wer Material aus einem anderen Raum braucht, kann es über eine Ausgabe anfordern. Im Rechner werden solche Regeln auf konkrete Schnittstellen angewandt. Eine breite Freigabe kann den Schutz für den betreffenden Bereich erheblich verringern.

## 4. Wie funktioniert das?

Flatpak lädt Apps und Runtimes aus eingerichteten Quellen, den Remotes. Der Bezug aus einer bestimmten Quelle und die Rechte der gestarteten App sind eigene Fragen. Die [Dokumentation zu Sandbox-Berechtigungen](https://docs.flatpak.org/en/latest/sandbox-permissions.html) beschreibt statische Freigaben und Portale. Ein Portal vermittelt etwa einen Dateiauswahldialog. Die App kann dann eine ausgewählte Datei erhalten, sofern sie diese Schnittstelle verwendet und das System ein passendes Portal bereitstellt.

Berechtigungen können auch ganze Verzeichnisse oder Netzwerkzugang umfassen. Deshalb lohnt es sich, die tatsächlich erteilten Rechte einer konkreten App zu betrachten. Der Pakettyp allein verrät sie nicht.

## 5. Wo begegnet mir das unter Linux?

In Linux-Softwareverwaltungen können Flatpak-Apps neben Distributionspaketen erscheinen. Installation pro Nutzer und Installation für das System sind je nach Konfiguration möglich. Mehrere Apps können dieselbe geeignete Runtime nutzen, während andere eine andere Version benötigen.

## 6. Konkretes Beispiel Schritt für Schritt

Gedankenbeispiel ohne Installation. Du möchtest ein eigenes Foto in einer hypothetischen Flatpak-App zuschneiden.

1. Du prüfst, aus welcher Quelle die App angeboten wird und welche Rechte sie verlangt.
2. Der Öffnen-Dialog verwendet in diesem Modell ein Portal. Du wählst nur das gewünschte Testfoto aus.
3. Der Zugriff auf diese Datei folgt aus der Auswahl. Daraus lässt sich kein allgemeiner Zugriff auf dein ganzes persönliches Verzeichnis ableiten.
4. Wenn die App einen anderen Verzeichnispfad eigenständig durchsuchen möchte, hängen mögliche Zugriffe von ihren Sandbox-Rechten ab.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Distributionspaket ordnet Dateien typischerweise der Systempaketverwaltung zu. Flatpak verwaltet Anwendungen und Runtimes in seinem eigenen System. [AppImage](it_0276.md) setzt auf eine bündelnde Datei und bringt allein dadurch keine entsprechenden Sandbox-Regeln mit.

## 8. Häufige Missverständnisse

Eine Sandbox macht eine App weder vertrauenswürdig noch automatisch vollständig abgeschottet. Eine lokal installierte App kann je nach Rechteprofil umfangreiche Zugriffe haben. Ein Portal erteilt Zugriffe im Rahmen seines jeweiligen Vorgangs.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe Berechtigungen und Herkunft getrennt. Wenn ein Dateidialog nicht wie erwartet funktioniert, prüfe zuerst, ob App und Desktop eine passende Portal-Schnittstelle verwenden. Eine breite dauerhafte Dateifreigabe verändert, was die App lesen oder schreiben kann.

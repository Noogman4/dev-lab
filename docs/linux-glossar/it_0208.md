# Branch

## 1. Kurzbeschreibung

Ein Branch ist in Git ein benannter Entwicklungszweig. Technisch verweist ein gewöhnlicher lokaler Branch auf einen Commit. Beim weiteren Arbeiten kann dieser Verweis auf neue Commits fortschreiten. Ein Branch ist keine vollständige zweite Dateikopie und sein Name allein erzeugt noch keine eigenen Änderungen.

## 2. Was bedeutet der Begriff?

Der Katalog nennt `feature/dns-guard` als möglichen Namen. Solche Namen helfen, den Zweck einer Entwicklung zu erkennen. Ihre Bedeutung wird vom Projekt festgelegt. Der Schrägstrich macht aus dem Branch keine besondere technische Art von Funktion, und der Name garantiert weder fertigen Code noch eine bestandene Prüfung.

Die [offizielle Dokumentation zu git branch](https://raw.githubusercontent.com/git/git/master/Documentation/git-branch.adoc) beschreibt das Auflisten und Anlegen von Branches. Das bloße Anlegen mit `git branch` wechselt nicht automatisch auf den neuen Zweig. Anlegen, Wechseln und Weiterentwickeln sind unterscheidbare Schritte.

## 3. Einfacher Vergleich aus dem Alltag

Ein bewegliches Lesezeichen markiert den aktuellen Stand einer Arbeitslinie. Zwei Lesezeichen können zunächst auf derselben Seite liegen. Wenn eine Linie weiterentwickelt wird, rückt nur deren Lesezeichen vor. Die bisherigen Seiten verschwinden dadurch nicht.

Die Grenze: Git speichert keine lineare Buchfolge für alle Entwicklungen. Seine Historie kann sich verzweigen und wieder zusammenlaufen. Außerdem bezeichnet ein Branch nicht automatisch eine Person oder ein Arbeitsverzeichnis. Mehrere Personen können an derselben benannten Entwicklung arbeiten.

## 4. Wie funktioniert das?

Nach einem vorhandenen Commit kann ein neuer Branch zunächst genau auf denselben Stand zeigen wie der bisherige. Ein Wechsel stellt den ausgewählten Stand im Arbeitsverzeichnis bereit und ordnet die weitere Arbeit dem gewählten Branch zu. Ein neuer Commit lässt dessen Spitze fortschreiten.

Die [Dokumentation zu git switch](https://raw.githubusercontent.com/git/git/master/Documentation/git-switch.adoc) erläutert Wechsel und Aktualisierung von Arbeitsverzeichnis und Index. Offene Änderungen sind ein eigener Zustand: Ein Wechsel muss nicht immer einen vollständig sauberen Arbeitsstand voraussetzen. Würden lokale Änderungen verloren gehen, verweigert Git den normalen Wechsel jedoch gegebenenfalls. Daraus folgt keine Empfehlung, Schutzprüfungen zu umgehen.

Ein lokaler Branch und ein entfernter Branch sind getrennte Referenzen. Ein ähnlicher Name bedeutet keine laufende automatische Synchronisierung. Auch eine konfigurierte Zuordnung regelt nicht selbstständig jeden Austausch. Das Speichern und Übertragen von Commits bleiben bewusste Vorgänge.

## 5. Wo begegnet mir das unter Linux?

Editoren und Terminalanzeigen zeigen häufig den aktuellen Branch. Vor einer Änderung hilft diese Information, die Arbeit dem richtigen Zweig zuzuordnen. Ein Name wie `main` ist eine verbreitete Konvention, aber kein zwingender Git-Standardname für jedes Repository.

Für Experimente ist ein eigener kleiner Übungsbereich geeignet. Ein neuer Branch im produktiven Projekt wäre dagegen eine tatsächliche Änderung seiner Referenzen. Das Beispiel bleibt vollständig in einem neu angelegten temporären Repository.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses vollständige Beispiel wurde mit Python 3.13 und Git 2.52.0 ausgeführt. Es verwendet keine Repository-Vorlagen und blendet persönliche sowie systemweite Git-Konfiguration für die Kindprozesse aus. Die Identität gilt nur für deren Aufrufe.

```python
import os
from pathlib import Path
import subprocess
import tempfile

env = {k: v for k, v in os.environ.items() if not k.startswith("GIT_")}
env.update(GIT_CONFIG_GLOBAL="/dev/null", GIT_CONFIG_NOSYSTEM="1")
with tempfile.TemporaryDirectory() as ordner:
    repo = Path(ordner)
    def git(*args):
        return subprocess.run(
            ["git", "-c", "user.name=Glossar", "-c",
             "user.email=glossar@example.invalid", "-c",
             "commit.gpgsign=false", *args],
            cwd=repo, env=env, check=True, capture_output=True, text=True
        ).stdout.strip()
    git("init", "--template=", "-b", "basis")
    (repo / "notiz.txt").write_text("Basis\n", encoding="utf-8")
    git("add", "notiz.txt")
    git("commit", "-m", "Basis")
    anfang = git("rev-parse", "basis")
    git("branch", "versuch")
    assert git("branch", "--show-current") == "basis"
    assert git("rev-parse", "versuch") == anfang
    git("switch", "versuch")
    (repo / "notiz.txt").write_text("Versuch\n", encoding="utf-8")
    git("add", "notiz.txt")
    git("commit", "-m", "Eigener Versuch")
    assert git("rev-parse", "basis") == anfang
    assert git("rev-parse", "versuch") != anfang
    print("Aktueller Branch:", git("branch", "--show-current"))
    print("Basis unverändert:", True)
```

Geprüfte Ausgabe:

```text
Aktueller Branch: versuch
Basis unverändert: True
```

Das Anlegen allein wechselt nicht den Branch. Erst nach dem ausdrücklichen Wechsel wird der neue Commit auf `versuch` erstellt. `basis` verweist weiterhin auf den ursprünglichen Commit. Es gibt keinen Remote-Austausch; der temporäre Bereich wird anschließend entfernt.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Commit ist ein gespeichertes Objekt. Ein Branch verweist beweglich auf einen Stand. Das Arbeitsverzeichnis enthält gerade bereitgestellte Dateien. Ein Branch ist auch keine Zugriffsberechtigung: Sein Name entscheidet nicht allein, wer Änderungen übertragen darf.

## 8. Häufige Missverständnisse

Ein Branch enthält nicht automatisch einen eigenen vollständigen Ordner. Anlegen bedeutet nicht immer Wechseln. Ein neuer Name kann zunächst denselben Commit bezeichnen. Und das Löschen eines Branchnamens ist nicht pauschal mit dem sofortigen Löschen aller zugehörigen Objekte gleichzusetzen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe vor dem Arbeiten Branch und offenen Status. Nutze eindeutige Namen und bewusste Austauschschritte. Erzwinge keinen Wechsel, um ungeklärte lokale Änderungen zu übergehen. Die Übung verändert keine Referenzen des bestehenden Projekts.

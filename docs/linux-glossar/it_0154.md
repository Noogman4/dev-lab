# MAC-Adresse

## 1. Kurzbeschreibung

Eine MAC-Adresse dient der Adressierung auf der Verbindungsebene bestimmter Netzwerktechniken, etwa Ethernet. Häufig handelt es sich um einen 48 Bit langen Wert für eine Schnittstelle. Die Bezeichnung „Hardwareadresse“ ist verbreitet, darf aber nicht als Garantie einer unveränderlichen, dauerhaft eindeutigen Geräteidentität verstanden werden. Software und Konfiguration können die verwendete Adresse beeinflussen.

## 2. Was bedeutet der Begriff?

MAC steht für „Media Access Control“. Eine übliche Schreibweise enthält sechs hexadezimale Zweiergruppen, etwa `02:00:00:00:00:01`. Jede Gruppe beschreibt ein Byte. Die [IETF-Übersicht zu IEEE-802-Parametern in RFC 9542](https://www.rfc-editor.org/rfc/rfc9542.html) erläutert unter anderem 48-Bit-Adressen und besondere Bits des ersten Oktetts.

Das Katalogbeispiel einer Netzwerkkarte ist damit ein passender Ausgangspunkt. Ein Gerät kann aber mehrere Schnittstellen besitzen. Außerdem sind werkseitige Zuordnung und tatsächlich verwendete Adresse unterschiedliche Fragen. Eine Adressanzeige identifiziert daher nicht zuverlässig eine Person oder einen unveränderlichen physischen Gegenstand.

## 3. Einfacher Vergleich aus dem Alltag

Innerhalb eines Betriebsgeländes werden Sendungen an gekennzeichnete Übergabestellen gebracht. Diese lokalen Kennzeichnungen helfen bei der Verteilung auf dem jeweiligen Abschnitt. Für eine Sendung über mehrere Standorte braucht es zusätzlich andere Adressinformationen.

Das erklärt die Verbindungsebene. Die Grenze: MAC-Adressen sind keine beliebigen beschrifteten Briefkästen und nicht für jede Netzwerktechnik gleich aufgebaut. Sie sind außerdem keine kryptografischen Identitätsnachweise. Ein bekannter Wert allein beweist weder den rechtmäßigen Absender noch die Zulässigkeit seines Zugriffs.

## 4. Wie funktioniert das?

Bei passenden Technologien enthalten Rahmen Adressinformationen für die Kommunikation auf dem betreffenden Verbindungsabschnitt. Beim Weiterleiten über Router entstehen andere Verbindungsabschnitte. Die MAC-Adresse des endgültigen entfernten Servers ist deshalb nicht einfach die allgemeine Zielangabe jedes lokalen Rahmens.

Bestimmte Bits unterscheiden unter anderem Einzel- und Gruppenadressierung sowie universell und lokal administrierte Adressen. RFC 9542 beschreibt diese Bedeutung. Ein gesetztes lokales Bit ist dabei kein Beweis, auf welche Weise die Adresse ausgewählt wurde; es kennzeichnet eine Adressklasse, nicht automatisch einen bestimmten Zufallsgenerator.

## 5. Wo begegnet mir das unter Linux?

Netzwerkverwaltung kann permanente und zugewiesene Adressen unterscheiden. Die [offizielle NetworkManager-Dokumentation für WLAN-Einstellungen](https://www.networkmanager.dev/docs/api/latest/settings-802-11-wireless.html) beschreibt beispielsweise zugewiesene beziehungsweise geklonte Adressen und Varianten wie `random` oder `stable`.

Welche Möglichkeiten tatsächlich funktionieren, hängt von Technik, Treiber und Konfiguration ab. Dieser Beleg bedeutet nicht, dass jede Linux-Schnittstelle immer zufällige Adressen verwendet. Er zeigt aber, warum „Hardwareadresse“ keine allgemeine Unveränderlichkeitsgarantie ist. Hier wird keine reale Adresse ausgelesen oder geändert.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Der Wert ist selbst gewählt und wird keiner Schnittstelle zugewiesen. Es handelt sich nur um eine lokale Bitprüfung.

```python
mac = bytes.fromhex("02 00 00 00 00 01")
assert len(mac) == 6
assert len(mac) * 8 == 48
lokal = bool(mac[0] & 0x02)
gruppe = bool(mac[0] & 0x01)
assert lokal is True
assert gruppe is False
text = ":".join(f"{teil:02x}" for teil in mac)
assert text == "02:00:00:00:00:01"
print(text)
print("Lokal administriert:", lokal)
```

Geprüfte Ausgabe:

```text
02:00:00:00:00:01
Lokal administriert: True
```

Die Assertions bestätigen Länge, Darstellung und die beiden betrachteten Bits. Sie beweisen nicht, dass dieser Wert in irgendeinem Netz verfügbar, eindeutig oder sinnvoll konfiguriert wäre. Auch wird weder ein Hersteller ermittelt noch die Identität eines Geräts geprüft.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine IP-Adresse gehört zu einem anderen Adressierungskontext. Ein Port bezeichnet einen Transportendpunkt. Ein Schnittstellenname ist eine lokale Betriebssystembezeichnung. Diese Angaben können gemeinsam in einer Diagnose erscheinen, bleiben aber technisch verschiedene Werte und besitzen unterschiedliche Gültigkeitsbereiche.

## 8. Häufige Missverständnisse

Eine MAC-Adresse ist nicht zwingend unveränderlich. Ein Herstellerpräfix beweist nicht zuverlässig die Identität des aktuell verwendeten Geräts. Gleichheit eines Wertes ist außerdem kein Ersatz für Authentifizierung. Eine übliche 48-Bit-Darstellung darf schließlich nicht als universelles Format jeder denkbaren Netzwerkadresse behandelt werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Nutze MAC-Werte nur im passenden lokalen Kontext. Berücksichtige zugewiesene oder randomisierte Adressen bei einer Diagnose. Ändere keine laufende Schnittstelle nur für einen Lernversuch. Dieses Beispiel verarbeitet ausschließlich eigene Bytes und verändert weder Geräte noch Netzwerkprofile.

## 10. Verwandte Begriffe

Die [IP-Adresse](it_0139.md) beschreibt einen anderen Adressbereich. Ein [Router](it_0151.md) verbindet Netze. Das [Netzwerk](it_0138.md) liefert den Zusammenhang. Ein [Integer](it_0008.md) hilft beim Verständnis der einzelnen Bitmasken des Beispiels.

# Performance

## 1. Kurzbeschreibung

Performance bezeichnet die Leistungsfähigkeit eines Systems bei einer bestimmten Arbeit. Dazu zählen Reaktionszeit, Durchsatz und Ressourcenbedarf. Welche Größe wichtig ist, ergibt sich aus dem Einsatz. Eine Oberfläche kann beispielsweise schnell reagieren, obwohl ein Hintergrundvorgang mehrere Sekunden dauert.

## 2. Was bedeutet der Begriff?

Latenz ist die Zeit zwischen einer Anforderung und dem betrachteten Ergebnis. Durchsatz beschreibt, wie viele Aufgaben in einer Zeitspanne abgeschlossen werden. Auch Spitzen beim Speicherbedarf oder eine sehr lange Verzögerung bei wenigen Aufrufen können relevant sein. Eine einzelne Durchschnittszahl verdeckt solche Unterschiede.

## 3. Einfacher Vergleich aus dem Alltag

An einem Schalter können viele Anträge pro Stunde bearbeitet werden, während einzelne Besucher lange warten. Beide Beobachtungen stimmen gleichzeitig. Bei einem Programm müssen wir deshalb angeben, ob die Statistik eine einzelne Wartezeit, mehrere Abschlüsse pro Sekunde oder etwas anderes erfasst.

## 4. Wie funktioniert das?

Viele grafische Oberflächen bearbeiten Eingabe und Zeichnen in einer Ereignisschleife. Wenn ein langer Schritt denselben Ausführungsort belegt, warten weitere Ereignisse. Die [Tkinter-Dokumentation zum Threading-Modell](https://docs.python.org/3.13/library/tkinter.html) beschreibt die Auswirkung von langen Ereignishandlern. Die [asyncio-Hinweise zu blockierendem Code](https://docs.python.org/3.13/library/asyncio-dev.html) erläutern ein ähnliches Problem für eine andere Ereignisschleife.

Ein Werkerschritt oder eine Aufteilung in kurze Abschnitte kann die Oberfläche reaktionsfähig halten. Die Berechnung selbst wird dadurch nicht zwangsläufig kürzer. Übergaben, Synchronisation und Begrenzung gleichzeitig gestarteter Arbeiten brauchen eine passende Gestaltung.

## 5. Wo begegnet mir das unter Linux?

Unter Linux können Rechenzeit, Datenträger und Netzwerk die beobachtete Dauer unterschiedlich beeinflussen. Wenn ein Programm in einer bestimmten Aktion stockt, miss genau diese Aktion. Ein allgemeiner CPU-Wert kann eine Wartezeit auf Eingaben oder Datenträger nicht alleine erklären.

## 6. Konkretes Beispiel Schritt für Schritt

Gedankenbeispiel ohne Ausführung. Eine fiktive Oberfläche prüft eine Reihe selbst angelegter Einträge.

1. Miss getrennt die Zeit bis zur sichtbaren Fortschrittsmeldung und bis zum letzten Ergebnis.
2. Im ersten Entwurf erledigt der Klickhandler die ganze Prüfung. Eingaben können dadurch länger warten.
3. Ein zweiter Entwurf meldet den Start sofort, koordiniert die Prüfung außerhalb des langen Handlers und übergibt das Ergebnis an die Oberfläche zurück.
4. Vergleiche in einer späteren Prüfung gleiche Eingaben und beobachte neben Gesamtdauer auch Bedienbarkeit und Fehlerfälle.

## 7. Abgrenzung zu ähnlichen Begriffen

[Benchmark](it_0299.md) beschreibt die Vergleichsmessung. [Profiling](it_0298.md) hilft bei der Suche nach zeit- oder speicherintensiven Stellen. Performance ist die beobachtete Eigenschaft, die damit untersucht wird.

## 8. Häufige Missverständnisse

CPU-Last, Benutzerwartezeit und Durchsatz beantworten unterschiedliche Fragen. Auch die schnellste Variante für einen einzelnen Testdatensatz kann bei größerer Last andere Ergebnisse liefern.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lege eine nutzerbezogene Zielgröße fest, bevor du an der Umsetzung änderst. Vergleiche unter passenden Bedingungen und prüfe weiterhin korrekte Ergebnisse. Eine reaktionsfähige GUI braucht außerdem eine nachvollziehbare Behandlung von Abbruch und Fehlern.

## 10. Verwandte Begriffe

[GUI](it_0064.md) ist das Beispiel. [Blocking](it_0268.md) erklärt blockierende Aufrufe. [Thread](it_0259.md) kann bei der Werkerausführung eine Rolle spielen.

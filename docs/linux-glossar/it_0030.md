# Quellcode

## 1. Kurzbeschreibung

Quellcode ist Programmtext in einer für die jeweilige Programmiersprache vorgesehenen Form. Er beschreibt Daten, Berechnungen und Abläufe, aus denen Software ausgeführt oder erzeugt werden kann. Die Quelle nennt eine Python-Datei als Beispiel. Nicht jeder beliebige Text in einer Datei mit der Endung `.py` ist dadurch schon gültiger oder vertrauenswürdiger Python-Code.

## 2. Was bedeutet der Begriff?

Menschen schreiben und lesen Quelltext, doch er kann auch von Werkzeugen erzeugt werden. „Vom Menschen geschrieben“ ist deshalb eine typische Entstehungsgeschichte, keine zwingende Definition. Entscheidend sind die Rolle als Programmquelle und die Regeln der betreffenden Sprache.

Quellcode ist von seiner Ausgabe zu unterscheiden. Die Anweisung zum Anzeigen einer Meldung ist nicht dieselbe Datei wie ein später erzeugtes Protokoll mit dieser Meldung. Ebenso sind übersetzte Programmformen nicht einfach eine andere Textansicht des ursprünglichen Dokuments.

## 3. Einfacher Vergleich aus dem Alltag

Ein Rezept beschreibt, wie ein Gericht zubereitet werden soll. Das geschriebene Rezept entspricht eher dem Quelltext, das tatsächlich zubereitete Gericht eher einem Ergebnis des Ablaufs. Lesen und Ausführen sind verschiedene Handlungen.

Der Vergleich hat Grenzen: Programmtext unterliegt präzisen Sprachregeln und kann auch unerwartete oder schädliche Aktionen beschreiben. Ein vertrauter Dateiname sagt nichts über seine Wirkung aus. Außerdem können Programme Daten verarbeiten, neue Programme erzeugen oder wiederholt weiterlaufen, statt ein einziges fertiges Ergebnis herzustellen.

## 4. Wie funktioniert das?

Eine Sprachimplementierung liest den Quelltext, prüft seinen Aufbau und verarbeitet ihn nach den Sprachregeln. Welche Zwischenformen entstehen und wann sie ausgeführt werden, hängt von Sprache und Implementierung ab. Die einfache Gegenüberstellung „Quelltext oder fertiges Programm“ erklärt deshalb nicht jeden Verarbeitungsschritt.

Bei Python kann Programmtext in Skripten und Modulen liegen. Das [offizielle Modultutorial](https://docs.python.org/3.13/tutorial/modules.html#modules) beschreibt Dateien mit Definitionen und Anweisungen sowie ihre Nutzung aus anderem Code. Eine Endung ist dabei eine Konvention und Teil der Werkzeugzuordnung, keine Sicherheitsprüfung.

Text benötigt außerdem eine Zeichenkodierung. Python 3 verwendet ohne abweichende Deklaration für Quelltext UTF-8. Die [Referenz zu Kodierungsdeklarationen](https://docs.python.org/3.13/reference/lexical_analysis.html#encoding-declarations) erläutert diese Regel und ihre Ausnahmen. Das betrifft das Lesen des Programmtexts, nicht automatisch die Kodierung sämtlicher von ihm geöffneten Datendateien.

## 5. Wo begegnet mir das unter Linux?

Bei einem Python-Projekt kannst du `.py`-Dateien in einem Texteditor untersuchen. Auch Shell-Skripte sind Quelltext ihrer jeweiligen Sprache. Ein installiertes Paket kann Quelltexte, übersetzte Bestandteile und Ressourcen kombinieren; der vollständige Entwicklungsstand muss deshalb nicht am Installationsort liegen.

Vor Änderungen solltest du die maßgebliche Quelle kennen. Eine erzeugte Datei kann beim nächsten Build überschrieben werden. Eine bearbeitete Arbeitskopie verändert zudem nicht automatisch jede bereits installierte Version derselben Anwendung.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel erzeugt und startet ausschließlich ein eigenes Miniscript in einem neu angelegten temporären Ordner:

```python
from pathlib import Path
import subprocess
import sys
import tempfile

quelle = "print('Hallo aus Quellcode')\n"
with tempfile.TemporaryDirectory() as ordner:
    datei = Path(ordner) / "beispiel.py"
    datei.write_text(quelle, encoding="utf-8")
    assert datei.read_text(encoding="utf-8") == quelle
    ergebnis = subprocess.run(
        [sys.executable, str(datei)],
        check=True, capture_output=True, text=True, timeout=5,
    )
    assert ergebnis.stdout == "Hallo aus Quellcode\n"
    print(ergebnis.stdout, end="")
```

Die Ausgabe lautet:

```text
Hallo aus Quellcode
```

Zuerst entsteht der Programmtext als String. Er wird in eine eigene Datei geschrieben und mit demselben Python-Interpreter ausgeführt. Die zurückgelesenen Quelldaten und die Ausgabe werden getrennt geprüft. Beim Verlassen des temporären Bereichs werden ausschließlich dessen eigene Testdateien wieder entfernt.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Codebase fasst zusammengehörige Quelltexte zusammen. Ein ausführbares Artefakt ist ein Ergebnis oder eine bereitgestellte Form von Software. Eine Konfiguration liefert Einstellungen, ohne notwendigerweise allgemeinen Programmcode darzustellen. Ein Protokoll hält beobachtete Ereignisse fest und ist keine automatisch ausführbare Beschreibung dieser Ereignisse.

## 8. Häufige Missverständnisse

Lesbarer Quelltext ist nicht automatisch harmlos oder korrekt. Eine Datei wird nicht allein durch Umbenennen in `.py` gültig. Auch kann generierter Quellcode weiterhin Quellcode sein. Das Vorliegen einzelner Dateien beweist zudem keine vollständige oder reproduzierbare Entwicklungsumgebung.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lies unbekannten Code vor dem Start und prüfe Herkunft sowie vorgesehene Ausführungsumgebung. Sichere vorhandene Änderungen. Das Beispiel führt ausschließlich den fest vorgegebenen eigenen Meldungstext aus; fremde Inhalte, Projektdateien oder Systemdienste werden nicht gestartet oder verändert.

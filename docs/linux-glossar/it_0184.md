# Server

## 1. Kurzbeschreibung

Ein Server stellt anderen Beteiligten eine Leistung bereit. Im Protokollzusammenhang ist damit vor allem das entsprechende Programm gemeint. Im Alltag wird auch der Rechner, auf dem solche Programme laufen, Server genannt. Diese Bedeutungen sollten getrennt werden: Ein Rechner kann mehrere Dienste anbieten und zugleich selbst andere Leistungen anfordern.

## 2. Was bedeutet der Begriff?

Das Wort beschreibt die bereitstellende Rolle. Die [HTTP-Spezifikation zu Clients und Servern](https://www.rfc-editor.org/rfc/rfc9110.html#section-3.3) definiert einen HTTP-Server als Programm, das Verbindungen annimmt und Anfragen durch Antworten bedient. Andere Protokolle besitzen andere technische Abläufe.

Das Katalogbeispiel eines Webservers ist richtig. Ein Webserver kann statische Dateien oder Ergebnisse weiterer Verarbeitung liefern. Daraus folgt aber nicht, dass jedes Serverprogramm Webseiten ausgibt oder einen Browser benötigt. Auch lokale Programme können untereinander eine Client-Server-Beziehung verwenden.

## 3. Einfacher Vergleich aus dem Alltag

Eine Ausgabestelle nimmt passende Anliegen entgegen und stellt die vereinbarte Leistung bereit. Sie kann mehrere Anfragende bedienen, ohne dass diese die gesamte interne Organisation kennen müssen. Dieselbe Organisation kann ihrerseits Leistungen bei anderen Stellen anfordern.

Die Grenze: Software versteht nur die implementierten Protokoll- und Fachregeln. Die Rolle sagt nicht, ob eine bestimmte Anfrage erlaubt ist. Ebenso ist eine erreichbare Ausgabestelle noch kein Beweis, dass jede angebotene Leistung im aktuellen Zustand vollständig funktioniert.

## 4. Wie funktioniert das?

Ein Serverprogramm stellt einen vorgesehenen Zugang bereit und verarbeitet eingehende Kommunikation. Je nach Verfahren gehören Annahme von Verbindungen, Lesen von Nachrichten, Prüfung und Erzeugung einer Antwort dazu. Die Fachfunktion kann weitere Komponenten verwenden.

Mehrere Anfragen erfordern klare Zuständigkeiten und einen passenden Umgang mit gemeinsamem Zustand. Daten verschiedener Benutzer dürfen nicht unbeabsichtigt vermischt werden. Auch Fehler und begrenzte Ressourcen müssen nach dem gewählten Vertrag behandelt werden. Der Rollenbegriff allein liefert dafür keine fertige Implementierung.

Die [Python-Dokumentation zu http.server](https://docs.python.org/3.13/library/http.server.html) zeigt einen konkreten einfachen HTTP-Serverbaustein. Sie weist ausdrücklich darauf hin, dass er nicht für den allgemeinen Produktionseinsatz empfohlen wird. Ein kleines Beispielwerkzeug darf daher nicht ohne weitere Prüfung als vollständig geeigneter Betriebsserver beschrieben werden.

## 5. Wo begegnet mir das unter Linux?

Ein Linux-Rechner kann Web-, Datei- oder andere Dienste bereitstellen. Der Betrieb kann über einen Dienstmanager organisiert sein, muss aber zur konkreten Software passen. „Serverprogramm“ und „systemd-Service“ sind deshalb nicht automatisch dieselbe Beschreibungsebene.

Ein bereitgestellter Netzwerkzugang hängt unter anderem von Adresse, Port, Programmzustand und erlaubten Wegen ab. Eine installierte Programmdatei oder vorhandene Dienstbeschreibung beweist noch keine tatsächlich laufende und erreichbare Funktion. Umgekehrt muss ein Server nicht für das gesamte Internet zugänglich sein.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses Gedankenmodell betrifft einen fiktiven HTTP-Dienst. Es wurde kein Programm gestartet, keine Datei freigegeben und kein Port geöffnet.

```text
Ein Serverprogramm besitzt einen vorgesehenen Zugang.
Ein Client sendet eine passende Statusanfrage.
Das Programm prüft Anfrage und notwendige Berechtigung.
Die Fachverarbeitung liefert einen Status oder einen definierten Fehler.
Der Server sendet eine dazu passende Antwort.
```

Die Serverrolle entsteht durch das Bereitstellen der Leistung. Die eigentliche Statusberechnung kann in einer getrennten Komponente liegen. Damit ist ein Unterschied zwischen Kommunikationszugang und fachlicher Verarbeitung sichtbar, ohne zwei bestimmte Rechner vorauszusetzen.

Eine reale Prüfung müsste außerdem den Betrieb, Fehlerfälle und zulässige Zugriffe untersuchen. Das Modell ist keine erfolgreiche Verbindungsmessung und keine Bereitstellung einer Anwendung. Es enthält keine tatsächlich erreichbare Adresse dieses Rechners.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Client fordert Leistungen an. Ein Backend beschreibt eine Verarbeitungsschicht. Ein Service ist eine bereitgestellte oder verwaltete Funktion. Ein Daemon ist ein Hintergrunddienstprozess. Ein Server kann mehrere dieser Eigenschaften verbinden, ohne dass die Begriffe in jedem Zusammenhang austauschbar wären.

## 8. Häufige Missverständnisse

Server bedeutet nicht zwingend ein großer eigener Rechner. Ein gestarteter Prozess bietet auch nicht automatisch einen korrekt erreichbaren Dienst. Eine Antwort `200` beweist keine umfassende Betriebssicherheit. Die Bezeichnung „lokaler Server“ ersetzt schließlich keine notwendigen Zugriffsregeln.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Beschreibe bei einer Diagnose Programm, Zugang, erwartete Leistung und beobachtete Antwort. Prüfe Betriebsanforderungen getrennt von einem kleinen Demonstrationsbeispiel. Dieser Text installiert oder startet keinen Server und verändert weder Dienste, Freigaben, Konten noch Netzwerkparameter.

## 10. Verwandte Begriffe

Der [Client](it_0183.md) übernimmt die anfragende Rolle. Das [Backend](it_0182.md) kann Fachverarbeitung liefern. Ein [Service](it_0119.md) beschreibt eine Funktion. Der [Port](it_0142.md) gehört zu bestimmten Zugängen. Die [Response](it_0173.md) ist eine mögliche Antwort.

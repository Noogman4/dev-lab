# chown

## 1. Kurzbeschreibung

`chown` ändert die Eigentümerzuordnung von Dateien oder Verzeichnissen. Je nach Angabe kann es auch deren Gruppenzuordnung ändern. Das ist von einer Änderung der gewöhnlichen Lese-, Schreib- und Ausführungsbits zu unterscheiden. Unter Linux benötigt insbesondere die Übertragung an einen anderen Eigentümer eine entsprechende besondere Berechtigung.

## 2. Was bedeutet der Begriff?

Der Name leitet sich von „change owner“ ab. Eine Datei wird technisch einer Benutzerkennung und einer Gruppenkennung zugeordnet. Werkzeuge können diese Kennungen als bekannte Namen darstellen. Die Zuordnung ist Teil der Metadaten, nicht der Textinhalt einer Datei.

Der [POSIX-Standard für chown](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/chown.html) beschreibt die Form `owner[:group] file`. Ohne angegebenen Gruppenteil soll die Gruppenzuordnung dabei unverändert bleiben. Das Quellbeispiel `chown user:user file.txt` nennt beide Teile: einen Eigentümer und eine Gruppe. Der gleiche ausgeschriebene Name bedeutet nicht, dass Benutzerkonto und Gruppe dasselbe technische Objekt wären.

## 3. Einfacher Vergleich aus dem Alltag

Ein Gegenstand wird in der Inventarliste einer bestimmten Person und einer zuständigen Abteilung zugeordnet. Ändert sich die Zuständigkeit, wird der Eintrag angepasst. Der Gegenstand selbst bleibt zunächst derselbe.

So verändert `chown` eine Zuordnung, ohne dafür den Dateiinhalt umschreiben zu müssen. Die Grenze: Technische Eigentümerschaft ist keine rechtliche Eigentumserklärung. Außerdem kann eine andere Zuordnung die Auswertung von Zugriffsregeln beeinflussen. Es handelt sich daher nicht um eine bloß dekorative Beschriftung ohne Auswirkungen.

## 4. Wie funktioniert das?

Das Programm löst die angegebenen Identitäten auf und veranlasst die passende Änderung am Dateisystemeintrag. Der Kernel prüft, ob diese Änderung zulässig ist. Die [Linux-Handbuchseite der chown-Systemaufrufe](https://man7.org/linux/man-pages/man2/chown.2.html) erklärt: Zum Ändern des Eigentümers ist eine passende privilegierte Fähigkeit erforderlich. Ein Eigentümer kann die Gruppe unter bestimmten Bedingungen auf eine eigene Gruppe ändern.

Rechtebits und Eigentümerzuordnung hängen bei der späteren Zugriffsprüfung zusammen. Dennoch ist `chown` kein Ersatz für `chmod`. Bei bestimmten Dateien können Eigentümer- oder Gruppenänderungen außerdem besondere Sicherheitsmerkmale zurücksetzen. Das genaue Verhalten ist daher mehr als ein einfacher Austausch eines angezeigten Namens.

## 5. Wo begegnet mir das unter Linux?

Der Befehl erscheint etwa in Verwaltungsanleitungen zur Einrichtung gemeinsam genutzter Daten oder zur Korrektur einer falschen Dateizuordnung. Ob eine Änderung nötig ist, muss jedoch aus der konkreten Aufgabe folgen. Eine Zugriffsfehlermeldung allein ist keine ausreichende Begründung.

Auch für Anwendungsdaten sollte geklärt sein, welcher Benutzer sie tatsächlich benötigt. Eine Datei pauschal einem besonders privilegierten Konto zuzuordnen macht eine Anwendung nicht automatisch besser nutzbar. Umgekehrt kann eine falsche Zuordnung dafür sorgen, dass der vorgesehene Prozess seine eigenen Daten nicht mehr bearbeiten kann.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses Gedankenbeispiel verwendet ausschließlich fiktive Namen. Es wurde nicht ausgeführt. Es werden weder Konten angelegt oder abgefragt noch Datei-Eigentümer geändert.

```text
Eine fiktive Datei bericht.txt ist dem Benutzer lea zugeordnet.
Eine Verwaltungsaufgabe verlangt künftig eine andere Zuständigkeit.
Zuerst prüfen: Welcher Benutzer soll Eigentümer sein, welche Gruppe ist nötig?
Dann prüfen: Ist die Änderung erlaubt und auf genau diese Datei begrenzt?
Nach einer tatsächlichen Änderung wären Zuordnung und benötigter Zugriff zu prüfen.
```

Das Katalogmuster `chown user:user file.txt` wäre erst mit real passenden Identitäten und einem bewusst ausgewählten Ziel sinnvoll. Es ist hier keine Ausführungsanweisung. Die geplante Kontrolle muss außerdem mehr umfassen als den angezeigten Namen: Entscheidend bleibt, ob der vorgesehene Arbeitsablauf mit den resultierenden Rechten funktioniert.

## 7. Abgrenzung zu ähnlichen Begriffen

`chmod` ändert Modusbits. `chown` ändert Eigentümer und gegebenenfalls Gruppe. Das Anlegen oder Ändern eines Benutzerkontos ist nochmals eine andere Aufgabe. Auch das Verschieben einer Datei ist nicht allgemein dasselbe wie eine Eigentümerübertragung; der konkrete Vorgang und das beteiligte Dateisystem sind zu betrachten.

## 8. Häufige Missverständnisse

Eine eigene Datei darf unter Linux nicht automatisch beliebig an andere Eigentümer verschenkt werden. Gleiche Benutzer- und Gruppennamen bezeichnen unterschiedliche Kennungsarten. Rekursion ist außerdem keine harmlose Abkürzung: Sie kann sehr viele Einträge erfassen, deren bisherige Zuordnung absichtlich verschieden war.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Bestimme Ziel, Eigentümer und Gruppe vor einer tatsächlichen Änderung genau. Beachte bei Verzeichnisbäumen auch symbolische Links und die gewählten Optionen. Verwende keine weitreichende Übertragung als pauschale Reparatur einer Anwendung. Für das Verständnis dieses Begriffs sind keine privilegierten Versuche nötig; alle konkreten Eigentümeränderungen bleiben hier unausgeführt.

## 10. Verwandte Begriffe

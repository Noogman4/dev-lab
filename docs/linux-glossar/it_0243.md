# Escaping

## 1. Kurzbeschreibung

Escaping behandelt besondere Zeichen so, dass sie in einem bestimmten Verarbeitungskontext als vorgesehene Daten verstanden werden. Welche Zeichen wie dargestellt werden müssen, hängt von der jeweiligen Sprache und Einbettung ab. Eine universelle Funktion, die beliebige Eingaben für alle Zwecke sicher macht, gibt es daraus nicht. Der Kontext gehört immer zur Entscheidung.

## 2. Was bedeutet der Begriff?

Die Quelle nennt Shell-Argumente. Ein Dateiname kann Leerzeichen oder Zeichen enthalten, die eine Shell sonst als Syntax deutet. Soll er als ein einzelner Datenwert vorkommen, braucht der gewählte Aufrufweg eine passende Behandlung.

Die [Python-Dokumentation zu shlex.quote](https://docs.python.org/3.13/library/shlex.html#shlex.quote) beschreibt die Darstellung als einzelnes Shell-Wort und begrenzt den Anspruch auf passende Unix- beziehungsweise POSIX-Shell-Kontexte. Eine solche Ausgabe ist keine allgemeine Lösung für Windows-Befehlszeilen, SQL, HTML oder beliebig verschachtelte Interpreter.

## 3. Einfacher Vergleich aus dem Alltag

In einem Formular markieren Anführungszeichen, dass ein bestimmter Ausdruck wörtlich gemeint ist. Die Leserin soll die Zeichen als Teil der Angabe verstehen, statt daraus eine neue Anweisung abzuleiten. Dafür müssen beide Seiten dieselben Schreibregeln verwenden.

Die Grenze: In Software ist die genaue Grammatik entscheidend. Derselbe Text kann in einem Kontext korrekt und in einem anderen weiterhin gefährlich oder schlicht falsch sein. Auch ein zusätzlicher Verarbeitungsschritt kann eine neue Bedeutung erzeugen. „Schon einmal behandelt“ ist deshalb keine universelle Eigenschaft eines Werts.

## 4. Wie funktioniert das?

Zunächst wird geklärt, wo der Wert eingefügt wird. Für HTML-Text erklärt [html.escape](https://docs.python.org/3.13/library/html.html#html.escape) die Umsetzung besonderer Zeichen in Zeichenreferenzen. Mit der entsprechenden Option werden auch Anführungszeichen behandelt, was bei passend begrenzten Attributwerten helfen kann. Das ist keine vollständige Prüfung eines ganzen HTML-Dokuments oder beliebiger URL-, Skript- und Stilkontexte.

Bei externen Programmaufrufen ist eine getrennte Argumentliste häufig der geeignetere Weg, wenn keine Shell benötigt wird. Die [Sicherheitshinweise zu subprocess](https://docs.python.org/3.13/library/subprocess.html#security-considerations) erklären die ausdrückliche Entscheidung über Shell-Verwendung. Eine solche Liste soll nicht zusätzlich so behandelt werden, als würde sie als ganze Zeichenkette von einer Shell zerlegt. Die Regeln des aufgerufenen Programms für Optionen bleiben trotzdem wichtig.

Für SQL-Werte sollte die vorgesehene Parameterbindung verwendet werden, statt selbst Anführungszeichen zu ersetzen. Daten und Anweisungsstruktur bleiben dadurch über die passende Schnittstelle getrennt. Ein Escaping-Verfahren für eine andere Sprache ist dafür kein Ersatz.

Mehrfaches Behandeln oder späteres Rückumwandeln kann ebenfalls die Darstellung verändern. Deshalb sollte die Anwendung nachvollziehbar halten, ob ein Wert noch rohe Daten oder bereits eine Darstellung für einen bestimmten Ausgabepunkt ist. Die passende Behandlung erfolgt am konkreten Übergang.

## 5. Wo begegnet mir das unter Linux?

Programme zeigen fremde Texte an oder übergeben Werte an andere Werkzeuge. Ein gewöhnlicher Name mit Leerzeichen und Apostrophen ist nicht grundsätzlich ungültig. Er braucht die zum Ziel passende Darstellung beziehungsweise Schnittstelle.

Auch unter Linux verwenden nicht alle Oberflächen dieselbe Grammatik. Eine Python-Zeichenkette, eine Shell-Zeile und HTML sind verschiedene Kontexte. Dieses Dokument erzeugt nur eigene Textdarstellungen; es führt keine zusammengesetzte Befehlszeile aus und lädt keine Webseite.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Arbeitsordner ausgeführt. Es zeigt die Behandlung eigener Zeichenketten. Die Shell-Darstellung wird nur mit dem passenden Python-Parser zurückgelesen, nicht durch eine echte Shell ausgeführt.

```python
import html
import shlex

roh = 'Probe & "Text" <Ansicht>'
html_text = html.escape(roh, quote=True)
assert html_text == 'Probe &amp; &quot;Text&quot; &lt;Ansicht&gt;'
assert html.unescape(html_text) == roh

argument = "eigene datei; probe.txt"
shell_wort = shlex.quote(argument)
assert shlex.split(shell_wort) == [argument]
print("HTML:", html_text)
print("Als einzelnes Shell-Wort zurückgelesen:", True)
```

Geprüfte Ausgabe:

```text
HTML: Probe &amp; &quot;Text&quot; &lt;Ansicht&gt;
Als einzelnes Shell-Wort zurückgelesen: True
```

Die HTML-Darstellung und die Shell-Darstellung lösen unterschiedliche Aufgaben. Der erfolgreiche Rückvergleich ist ein begrenzter Test mit den eigenen Werten. Er beweist keine allgemeine Sicherheit einer Webseite, einer Befehlsintegration oder eines anderen Interpreters. Es werden keine Programme oder Netzwerkanfragen gestartet.

## 7. Abgrenzung zu ähnlichen Begriffen

Input Validation prüft fachliche Anforderungen. Escaping behandelt eine konkrete syntaktische Einbettung. Parameterbindung ist eine Datenbankschnittstelle. Verschlüsselung schützt Vertraulichkeit. HTML-Zeichenreferenzen oder Shell-Anführungszeichen sind keine Verschlüsselung und keine Zugriffsberechtigung.

## 8. Häufige Missverständnisse

Ein Wert ist nicht allgemein „sicher escaped“. HTML-Behandlung schützt nicht automatisch JavaScript oder SQL. Shell-Quoting gehört nicht blind in getrennte Argumentlisten. Und erlaubte Zeichen sind nicht zwingend auf eine kleine Menge einfacher Buchstaben beschränkt.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Bestimme Kontext und nachfolgende Verarbeitung ausdrücklich. Nutze dafür vorgesehene Bibliotheksfunktionen und Schnittstellen. Prüfe Grenzfälle mit eigenen Werten. Das Beispiel führt keine Shell, externe Befehle, Dateien oder vorhandenen Anwendungen aus.

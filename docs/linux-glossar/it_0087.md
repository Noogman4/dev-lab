# Paket

## 1. Kurzbeschreibung

Im Python-Kontext ist ein Paket eine Einheit für hierarchisch organisierte Importnamen. Es kann Module und weitere Pakete enthalten. Die Quelle nennt eine Sammlung von Modulen mit meist vorhandener `__init__.py`. Das passt zu regulären dateibasierten Paketen, ist aber keine vollständige Definition aller Python-Paketarten.

## 2. Was bedeutet der Begriff?

Ein Name wie `werkzeug.auswertung` drückt eine Zugehörigkeit aus: Der zweite Bestandteil liegt im Namensbereich des ersten. Dadurch können zusammengehörige Einheiten unter einem gemeinsamen Präfix organisiert werden.

Die [offizielle Erklärung zu Paketen](https://docs.python.org/3.13/reference/import.html#packages) beschreibt Pakete als besondere Module mit dem Attribut `__path__`. Nicht jedes Modul ist deshalb ein Paket. Auch muss die Hierarchie nicht immer einer einzigen gewöhnlichen Verzeichnisstruktur entsprechen.

## 3. Einfacher Vergleich aus dem Alltag

Ein beschrifteter Ordner kann mehrere zusammengehörige Unterlagen und weitere Unterordner enthalten. Ein vollständiger Ablageweg macht deutlich, welcher gleichnamige Unterbestand gemeint ist.

Die Grenze des Vergleichs: Python kann Namen auch aus anderen Quellen als gewöhnlichen Dateien bereitstellen. Außerdem wird beim Import möglicherweise Initialisierungscode ausgeführt. Eine Ablagehierarchie allein beschreibt weder alle technischen Suchregeln noch die Wirkung ihrer Verwendung.

## 4. Wie funktioniert das?

Ein reguläres dateibasiertes Paket besitzt typischerweise eine `__init__.py`. Sie kann leer sein oder Definitionen und Initialisierung enthalten. Untergeordnete Module werden über die vorgesehene Importstruktur gefunden.

Namespace-Pakete bilden eine andere Variante. Sie können aus mehreren Teilbereichen bestehen und benötigen keine entsprechende gemeinsame `__init__.py`. Das erläutert die [offizielle Namespace-Paketbeschreibung](https://docs.python.org/3.13/reference/import.html#namespace-packages). Die Regel „jedes Paket braucht diese Datei“ wäre daher falsch.

Zusätzlich bezeichnet Paket oft eine installierbare Distribution. Die [PyPA-Erklärung zu Distribution und Importpaket](https://raw.githubusercontent.com/pypa/packaging.python.org/main/source/discussions/distribution-package-vs-import-package.rst) trennt diese Begriffe. Ein Installationsname muss nicht exakt dem später importierten Namen entsprechen, und eine Distribution kann mehrere Importbestandteile bereitstellen.

## 5. Wo begegnet mir das unter Linux?

Python-Projekte und Bibliotheken verwenden Pakete für ihre innere Organisation. Ein Linux-Paketmanager verwaltet dagegen eigene Distributionspakete mit Dateien, Abhängigkeiten und weiteren Regeln. Das ist nicht dieselbe Schnittstelle wie ein Python-Import.

Vor einer Installation oder Fehlersuche sollte deshalb klar sein, welche Bedeutung gemeint ist. Ein fehlender Import beweist nicht allein, dass ein gleichnamiges Linux-Paket benötigt wird. Interpreter, Importpfad und dokumentierte Projektanforderungen gehören zur Diagnose.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel erzeugt ein eigenes reguläres Paket ausschließlich in einem temporären Ordner:

```python
from pathlib import Path
import subprocess
import sys
import tempfile

with tempfile.TemporaryDirectory() as ordner:
    paket = Path(ordner) / "glossar_paket"
    paket.mkdir()
    (paket / "__init__.py").write_text('kennung = "Probe"\n', encoding="utf-8")
    (paket / "rechnen.py").write_text(
        "def addieren(a, b):\n    return a + b\n", encoding="utf-8"
    )
    code = (
        "import glossar_paket\n"
        "from glossar_paket import rechnen\n"
        "assert hasattr(glossar_paket, '__path__')\n"
        "assert rechnen.addieren(2, 3) == 5\n"
        "print(glossar_paket.kennung)\n"
        "print(rechnen.addieren(2, 3))\n"
    )
    ergebnis = subprocess.run([sys.executable, "-c", code], cwd=ordner,
                              capture_output=True, text=True, check=True, timeout=5)
    assert ergebnis.stdout == "Probe\n5\n"
    print(ergebnis.stdout, end="")
```

Die Ausgabe lautet:

```text
Probe
5
```

Die Initialisierungsdatei stellt eine Kennzeichnung bereit, das Untermodul eine Rechenfunktion. Beides wird im eigenen Kindprozess verwendet. Es erfolgt keine Installation und kein Zugriff auf fremde Paketdateien.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Modul ist eine benannte Codeeinheit. Ein Importpaket organisiert einen hierarchischen Bereich. Eine Distribution ist installierbare Software. Ein Debian-Paket gehört zum Linux-Paketformat. Ein Build kann solche Artefakte erzeugen, ist aber nicht selbst der Importmechanismus.

## 8. Häufige Missverständnisse

Nicht jedes Python-Paket benötigt `__init__.py`. Installationsname und Importname müssen nicht identisch sein. Ein Verzeichnis mit Dateien ist außerdem nicht automatisch über jeden Interpreter erreichbar. Die gleiche Bezeichnung Paket kann verschiedene Verwaltungsebenen meinen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lies die vorgesehene Paket- und Importstruktur des Projekts. Vermeide Eingriffe in fremde Installationen zur bloßen Namenskorrektur. Das Beispiel prüft nur ein eigenes reguläres Paket; Namespace-Verteilung und reale Paketinstallation wurden nicht praktisch getestet.

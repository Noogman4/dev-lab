# PID

## 1. Kurzbeschreibung

PID steht für „Process ID“ und bezeichnet die Kennung eines Prozesses. Unter Linux ist sie eine Zahl, mit der ein Prozess innerhalb eines bestimmten PID-Namensraums identifiziert wird. Eine PID ist kein Programmname und keine dauerhaft reservierte Seriennummer. Nach dem Ende eines Prozesses kann seine Zahl später erneut verwendet werden.

## 2. Was bedeutet der Begriff?

Wenn mehrere Instanzen desselben Programms laufen, benötigen sie unterscheidbare Kennungen. Die PID hilft, eine konkrete Instanz anzusprechen oder anzuzeigen. Die [Linux-Referenz zu getpid](https://man7.org/linux/man-pages/man2/getpid.2.html) beschreibt das Auslesen der eigenen Kennung und unterscheidet davon `getppid`, die Kennung des Elternprozesses.

Die Quellbeschreibung nennt die PID „eindeutig“. Dazu gehört der Gültigkeitsbereich: Die [Dokumentation zu PID-Namensräumen](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html) erklärt, dass verschiedene Namensräume eigene Nummernbereiche besitzen. In unterschiedlichen Namensräumen kann dieselbe Zahl deshalb verschiedene Prozesse bezeichnen. Ein Container und sein Host müssen denselben Prozess nicht unter derselben sichtbaren PID darstellen.

## 3. Einfacher Vergleich aus dem Alltag

Eine Wartemarke mit Nummer 42 unterscheidet dich gerade von anderen Wartenden in derselben Ausgabestelle. In einer anderen Filiale kann gleichzeitig ebenfalls eine Nummer 42 vergeben sein. Am nächsten Tag kann eine neue Person dieselbe Nummer erhalten.

Das erklärt räumlich und zeitlich begrenzte Eindeutigkeit. Die Grenze: Prozesse sind keine Menschen, und ein Namensraum ist nicht einfach ein Gebäude. Technische Beziehungen können mehrere Sichtweisen auf denselben Prozess ermöglichen. Eine PID liefert außerdem keine vollständige Beschreibung seiner Berechtigungen oder seines aktuellen Arbeitszustands.

## 4. Wie funktioniert das?

Bei der Prozesserzeugung vergibt das System eine Kennung im passenden Bereich. Werkzeuge können sie zusammen mit weiteren Angaben anzeigen. Ein Elternprozess besitzt eine eigene PID; ein Kindprozess erhält eine andere. Dass beide denselben Programmcode verwenden, ändert daran nichts.

Bestimmte Schnittstellen verwenden die PID zum gezielten Ansprechen. Die [Linux-Referenz des kill-Systemaufrufs](https://man7.org/linux/man-pages/man2/kill.2.html) beschreibt das Senden von Signalen und die erforderlichen Rechte. Besondere Zahlenwerte können dort andere Bedeutungen als eine einzelne positive Prozesskennung haben. Deshalb dürfen solche Argumente nicht unbesehen aus fremden Beispielen übernommen werden.

## 5. Wo begegnet mir das unter Linux?

Prozessanzeigen und Fehlersuchwerkzeuge nennen häufig PIDs, um konkrete Instanzen zu unterscheiden. Auch eine Anwendung kann ihre eigene PID protokollieren. Eine Zahl aus einer alten Logzeile ist jedoch nur eine historische Angabe; inzwischen kann der zugehörige Prozess beendet oder die Nummer neu vergeben sein.

Das Katalogbeispiel `kill 1234` wird hier nicht ausgeführt. Die [Handbuchseite des kill-Befehls](https://man7.org/linux/man-pages/man1/kill.1.html) erklärt, dass ohne ausdrücklich gewähltes Signal gewöhnlich `TERM` gesendet wird. Dessen übliche Wirkung ist Beenden, aber ein Prozess kann es behandeln. Erfolg beim Senden ist daher nicht gleichbedeutend mit bestätigtem, sofortigem Prozessende.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses Gedankenbeispiel verwendet erfundene Nummern. Es ist keine Ausgabe eines realen Prozesswerkzeugs und keine Aufforderung, eine der Zahlen anzusprechen.

```text
Zeitpunkt A: Prozess „Auswertung“ besitzt im betrachteten Namensraum PID 2401.
Zeitpunkt A: Eine zweite Instanz besitzt dort PID 2402.
Die erste Instanz beendet sich.
Zu einem späteren Zeitpunkt kann PID 2401 neu vergeben werden.
Ein alter Notizzettel mit „Auswertung: 2401“ identifiziert dann nichts zuverlässig.
```

Die beiden anfangs gleich benannten Instanzen sind nicht derselbe Prozess. Die spätere Wiederverwendung zeigt außerdem, warum eine PID ohne aktuellen Zusammenhang keine dauerhafte Identität liefert. Das Beispiel misst keine tatsächliche Nummernvergabe und beschreibt keinen garantierten zeitlichen Abstand bis zur Wiederverwendung.

Für einen konkreten Eingriff müsste die aktuelle Zielinstanz erneut zuverlässig bestimmt werden. Gerade bei einer Verzögerung zwischen Auswahl und Aktion sind veraltete Nummern problematisch. Das Verständnis dieses Zusammenhangs erfordert hier keinen Signalversuch.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Programmname beschreibt nicht eindeutig eine laufende Instanz. Die PPID bezeichnet den Elternprozess. Prozessgruppen besitzen wiederum eigene Kennungen und können bei Signaloperationen eine Rolle spielen. Eine Benutzerkennung ordnet Rechte zu und ist keine Prozesskennung.

## 8. Häufige Missverständnisse

Eine kleine PID bedeutet nicht automatisch ein wichtigeres Programm. Eine bekannte Nummer garantiert keinen bestimmten Benutzer. Auch ein Befehl namens `kill` ist kein allgemeiner Nachweis einer erfolgreichen Beendigung: Ziel, Signal, Berechtigung und spätere Reaktion müssen auseinandergehalten werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Verwende keine erfundene Beispiel-PID für einen realen Eingriff. Prüfe bei einer tatsächlichen Diagnose die aktuelle Instanz und ihren Kontext. Bevorzuge zum normalen Beenden die vorgesehene Anwendungsschnittstelle. In diesem Eintrag wurden keine Prozessliste gelesen, keine Signale gesendet und keine vorhandenen Prozesse verändert.

## 10. Verwandte Begriffe

Der [Prozess](it_0115.md) ist die identifizierte Instanz. [logging](it_0103.md) kann eine PID als Kontext festhalten. [subprocess](it_0101.md) kann eigene Kindprozesse starten und deren Lebensdauer gezielt begleiten.

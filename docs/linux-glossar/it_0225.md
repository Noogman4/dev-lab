# Factory

## 1. Kurzbeschreibung

Eine Factory kapselt das Erzeugen oder Bereitstellen passender Objekte hinter einer vereinbarten Schnittstelle. Der aufrufende Code beschreibt beispielsweise die gewünschte Variante, während die Factory die konkrete Klasse auswählt. Das kann die Verwendung von den Einzelheiten der Erzeugung trennen. Nicht jede Factory ist dabei dasselbe konkrete Entwurfsmuster.

## 2. Was bedeutet der Begriff?

Die Quelle nennt die Erzeugung passender Scanner-Objekte. Eine Factory könnte anhand einer Auswahl ein geeignetes Objekt liefern. Welche Auswahlwerte erlaubt sind und wie ein unbekannter Wert behandelt wird, muss Teil des Vertrags sein. Der Begriff allein garantiert weder erfolgreiche Erzeugung noch ein für jede Situation brauchbares Ergebnis.

Ein konkretes Beispiel ist [QStyleFactory::create in Qt](https://doc.qt.io/qt-6/qstylefactory.html#create): Die Funktion liefert zu einem Schlüssel ein passendes Stilobjekt oder einen Nullzeiger, wenn kein passender Stil gefunden wird. Das ist eine Qt-spezifische Schnittstelle. Andere Factorys können einen Fehler auslösen oder andere Rückgaberegeln besitzen.

## 3. Einfacher Vergleich aus dem Alltag

An einer Ausgabestelle bestellst du eine bestimmte Art von Arbeitsmappe. Du brauchst nicht selbst die Lagerfächer und den Zusammenbau zu kennen. Die Ausgabestelle liefert eine passende Mappe nach ihrem Angebot.

Die Grenze: Eine Factory ist kein unbegrenzter Wunschautomat. Sie kann nur unterstützte Varianten nach ihren Regeln bereitstellen. Außerdem muss klar sein, ob du ein neues Objekt erhältst oder etwas gemeinsam Verwendetes. Der Name „Factory“ allein beantwortet diese Lebensdauerfrage nicht.

## 4. Wie funktioniert das?

Eine einfache Factory kann eine Funktion mit einer Auswahlentscheidung sein. Aufrufer erhalten ein Objekt, das eine vereinbarte Fähigkeit anbietet. Dadurch müssen sie die konkreten Klassen nicht an vielen Stellen selbst auswählen. Die Auswahl wird an einer überschaubaren Stelle gebündelt.

Daneben gibt es spezifischere Muster wie Factory Method und Abstract Factory. Diese organisieren die Erzeugung auf unterschiedliche Weise, etwa über überschreibbare Methoden oder zusammengehörige Objektfamilien. Eine gewöhnliche Auswahlfunktion sollte nicht automatisch als vollständige Umsetzung jedes dieser Muster bezeichnet werden.

Auch Python verwendet den Begriff für aufrufbare Erzeuger. Die [Dokumentation zu setLogRecordFactory](https://docs.python.org/3.13/library/logging.html#logging.setLogRecordFactory) beschreibt eine austauschbare Funktion zum Erzeugen von LogRecord-Objekten. Deren konkrete Signatur gehört zur Logging-Schnittstelle. Das folgende Beispiel verändert sie nicht, sondern zeigt eine eigene kleine Auswahlfunktion.

## 5. Wo begegnet mir das unter Linux?

Bibliotheken können passende Oberflächenelemente, Verbindungen oder Verarbeitungsobjekte über Factorys liefern. Welche Betriebssystemfunktionen dabei verwendet werden, hängt vom jeweiligen Objekt ab. Eine Factory ist deshalb weder automatisch eine Netzwerkoperation noch ein eigener Hintergrunddienst.

Für die Fehlersuche lohnt der Blick auf Auswahlwerte, Rückgabe und Fehlervertrag. Ein unbekannter Schlüssel sollte nicht stillschweigend eine fachlich falsche Variante erzeugen. Ob ein Standard sinnvoll ist, muss bewusst entschieden werden. Hier wird ausschließlich eigener Text im Speicher verarbeitet.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Arbeitsordner ausgeführt. Es erzeugt zwei Arten von Darstellungsobjekten. Für die zweite Variante verwendet es [json.dumps](https://docs.python.org/3.13/library/json.html#json.dumps), das einen JSON-Text zurückgibt, ohne eine Datei zu schreiben.

```python
import json

class TextDarstellung:
    def formatieren(self, titel):
        return titel

class JsonDarstellung:
    def formatieren(self, titel):
        return json.dumps(titel, ensure_ascii=False)

def erzeugen(art):
    if art == "text":
        return TextDarstellung()
    if art == "json":
        return JsonDarstellung()
    raise ValueError("Unbekannte Darstellung")

text = erzeugen("text").formatieren("Probe")
json_text = erzeugen("json").formatieren("Probe")
assert text == "Probe" and json.loads(json_text) == "Probe"
abgelehnt = False
try:
    erzeugen("unbekannt")
except ValueError:
    abgelehnt = True
assert abgelehnt
print("Text:", text)
print("JSON:", json_text)
print("Unbekannte Variante abgelehnt:", abgelehnt)
```

Geprüfte Ausgabe:

```text
Text: Probe
JSON: "Probe"
Unbekannte Variante abgelehnt: True
```

Beide Objekte bieten dieselbe verwendete Methode, aber unterschiedliche Darstellungen. Die Factory bündelt ihre Auswahl. In diesem Beispiel werden neue Objekte erzeugt. Es gibt keine automatische Pluginsuche, keinen Scanneraufruf und keine Speicherung. Der Fehlerfall ist ausdrücklich geprüft.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Konstruktor initialisiert eine konkrete Instanz nach den Regeln der Sprache. Eine Factory kann die Auswahl davor kapseln. Dependency Injection übergibt benötigte Fähigkeiten. Ein Singleton betrifft die vorgesehene Wiederverwendung einer Instanz. Eine Factory kann mit solchen Entscheidungen zusammenarbeiten, ist aber nicht damit identisch.

## 8. Häufige Missverständnisse

Nicht jede Factory erzeugt immer ein neues Objekt. Nicht jeder unbekannte Schlüssel hat einen sinnvollen Standard. Eine Auswahlfunktion ist nicht automatisch eine Abstract Factory. Und ein gleich benannter Rückgabewert garantiert noch keine passende fachliche Schnittstelle.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Dokumentiere Varianten, Ergebnis und Fehlerfälle. Halte die Auswahl nachvollziehbar. Prüfe die bereitgestellten Fähigkeiten mit eigenen Eingaben. Das Beispiel verändert keine Bibliotheksregistrierung und erzeugt keine Ressourcen außerhalb seiner eigenen Speicherobjekte.

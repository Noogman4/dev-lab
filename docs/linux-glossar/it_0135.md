# Symlink

## 1. Kurzbeschreibung

Ein Symlink ist ein symbolischer Link: ein Dateisystemeintrag, der auf einen anderen Pfad verweist. Beim üblichen Zugriff auf seinen Inhalt wird der Verweis aufgelöst. Das Ziel kann eine Datei oder ein Verzeichnis sein und auch fehlen. Ein Symlink ist deshalb keine automatisch mitgeführte Kopie der Zieldaten.

## 2. Was bedeutet der Begriff?

„Symlink“ ist die Kurzform von „symbolic link“. Die [Linux-Handbuchseite zur Behandlung symbolischer Links](https://man7.org/linux/man-pages/man7/symlink.7.html) erklärt ihre Bedeutung und die Abgrenzung zu harten Links. Ein Symlink enthält eine Pfadangabe. Diese kann absolut oder relativ sein.

Das Katalogbeispiel vergleicht den Link mit einer Verknüpfung. Das hilft beim Einstieg, sollte aber nicht mit einer speziellen Desktop-Verknüpfungsdatei gleichgesetzt werden. Ein Symlink wird von der Dateisystem-Pfadauflösung behandelt. Eine Desktopdatei kann dagegen eigene Informationen und Startregeln einer Oberfläche besitzen.

## 3. Einfacher Vergleich aus dem Alltag

An einem Ablageplatz liegt ein Hinweis „Die Unterlagen liegen im Schrank nebenan“. Wer die Unterlagen benötigt, folgt dem Hinweis. Der Hinweis selbst enthält nicht nochmals alle Dokumente.

So verweist ein Symlink auf ein Ziel. Die Grenze: Der Zielpfad wird nach technischen Regeln aufgelöst, nicht nach menschlicher Orientierung. Ein relativer Zieltext bezieht sich auf den Ort des Links, nicht einfach auf das aktuelle Arbeitsverzeichnis des Benutzers. Wird das Ziel verschoben oder anders benannt, kann der Hinweis ins Leere führen.

## 4. Wie funktioniert das?

Eine Operation kann dem Link folgen und das Ziel bearbeiten oder ausdrücklich den Link selbst untersuchen. Diese Unterscheidung ist wichtig für Größenangaben, Metadaten und Änderungen. Ein nicht erreichbares Ziel macht den Link nicht automatisch unsichtbar oder zu einer gewöhnlichen leeren Datei.

Python bietet [Path.symlink_to](https://docs.python.org/3.13/library/pathlib.html#pathlib.Path.symlink_to) zum Erzeugen eines Links. Dabei ist das Path-Objekt der anzulegende Link, das Argument sein Ziel. Die Dokumentation betont die Argumentrichtung. Welche Funktionen Links verfolgen, muss jeweils geprüft werden; ein vertraut klingender Methodenname ist keine allgemeine Sicherheitsgarantie.

## 5. Wo begegnet mir das unter Linux?

Symlinks können alternative Zugriffspfade oder Verweise zwischen Verzeichnissen bereitstellen. Paketverwaltungen und Systemeinrichtungen nutzen sie ebenfalls, aber ihre konkrete Funktion hängt vom jeweiligen Ziel und Programm ab. Ein Link selbst verschiebt die Zieldatei nicht.

Auch ein Verweis über Dateisystemgrenzen hinweg ist möglich, weil ein Pfad gespeichert wird. Wird ein dafür benötigtes Dateisystem gerade nicht eingehängt, kann das Ziel unzugänglich sein. Das bedeutet nicht zwingend, dass der Link beschädigt oder die ursprüngliche Datei endgültig gelöscht ist.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 unter Linux ausgeführt. Alle Dateien und Links entstehen in einem eigenen temporären Ordner. Keine vorhandenen Verknüpfungen werden geändert.

```python
from pathlib import Path
import tempfile

with tempfile.TemporaryDirectory() as ordner:
    basis = Path(ordner)
    ziel = basis / "ziel.txt"
    ziel.write_text("Probe\n", encoding="utf-8")
    link = basis / "verweis.txt"
    link.symlink_to("ziel.txt")
    assert link.is_symlink()
    assert link.readlink() == Path("ziel.txt")
    assert link.read_text(encoding="utf-8") == "Probe\n"
    assert link.samefile(ziel)

    ohne_ziel = basis / "offener-verweis"
    ohne_ziel.symlink_to("fehlt.txt")
    assert ohne_ziel.is_symlink()
    assert not ohne_ziel.exists()
    print(link.read_text(encoding="utf-8").strip())
    print("Link ohne Ziel vorhanden:", ohne_ziel.is_symlink())
```

Geprüfte Ausgabe:

```text
Probe
Link ohne Ziel vorhanden: True
```

Der erste Link speichert einen relativen Namen. [Path.samefile](https://docs.python.org/3.13/library/pathlib.html#pathlib.Path.samefile) prüft, ob der Link und der direkte Zielpfad dieselbe Datei bezeichnen. Das funktioniert auch, wenn der temporäre Ordner selbst über einen Symlink erreicht wird. Beim zweiten Link findet `exists()` kein vorhandenes Ziel. `is_symlink()` erkennt trotzdem den Link selbst.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein harter Link verweist auf dasselbe zugrunde liegende Dateiobjekt, nicht über einen gespeicherten Zielpfad. Eine Kopie besitzt eigene Daten. Ein Mount bindet einen Bestand in eine Hierarchie ein und ist ein anderer Mechanismus. Ein Symlink ersetzt außerdem keine Datensicherung seines Ziels.

## 8. Häufige Missverständnisse

Ein Link kann auf etwas zeigen, das gerade nicht vorhanden ist. Das Löschen eines gewöhnlichen Symlink-Eintrags ist nicht automatisch das Löschen seiner Zieldatei; andere Operationen können jedoch bewusst dem Ziel folgen. Ebenso erzeugt ein Link keine neuen Zugriffsrechte auf das Ziel.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe vor Änderungen, ob ein Programm den Link oder das Ziel bearbeitet. Sei besonders bei rekursiven Aktionen und fremd kontrollierten Pfaden aufmerksam. Für Übungen genügen eigene temporäre Links. Dieser Versuch verändert keine Systemverweise, Einbindungen oder bestehenden Dateirechte.

## 10. Verwandte Begriffe

[pathlib](it_0102.md) bietet Methoden zur Untersuchung. Ein [Mount](it_0134.md) kann beeinflussen, ob ein Zielpfad erreichbar ist. [Dateirechte](it_0112.md) bleiben beim Zugriff relevant. Ein [Home-Verzeichnis](it_0133.md) ist ein möglicher Pfadkontext, aber keine notwendige Grundlage jedes relativen Links.

# Await

## 1. Kurzbeschreibung

`await` erwartet in Python das Ergebnis eines dafür geeigneten Objekts innerhalb einer Coroutine. Muss dieses Ergebnis noch entstehen, kann die Coroutine dabei aussetzen. Das bedeutet nicht, dass jedes `await` zwangsläufig eine Pause mit Ausführung anderer Tasks erzeugt. Ein bereits verfügbares Ergebnis kann unmittelbar weiterverarbeitet werden.

## 2. Was bedeutet der Begriff?

Die Quelle nennt `await fetch()`. Ob dieser Ausdruck sinnvoll ist, hängt davon ab, was `fetch()` zurückgibt. Es muss ein passendes Awaitable sein. Ein gewöhnlicher synchroner Funktionsaufruf wird durch das davor gesetzte Schlüsselwort nicht automatisch in eine geeignete asynchrone Operation verwandelt.

Die [Python-Sprachreferenz zum await-Ausdruck](https://docs.python.org/3.13/reference/expressions.html#await-expression) beschreibt die Verwendung innerhalb einer Coroutine. Das Schlüsselwort gehört zu einer bestimmten Sprachmechanik. Es ist weder ein universeller Wartebefehl für beliebige Objekte noch eine automatische Aufforderung, einen neuen Thread anzulegen.

## 3. Einfacher Vergleich aus dem Alltag

Du fragst eine Auskunft nach einem Ergebnis. Ist die Antwort noch in Arbeit, kannst du nach dem vereinbarten Ablauf später fortfahren. Liegt sie schon auf dem Tisch, kannst du sie unmittelbar verwenden. Die Frage allein garantiert keine längere Unterbrechung.

Die Grenze: Python entscheidet nach dem Vertrag des erwarteten Objekts und der Ausführungsumgebung. Ein menschliches „Warte kurz“ beschreibt diese Mechanik nicht vollständig. Auch wird nicht automatisch jede andere Aufgabe zuerst erledigt, nur weil eine Coroutine ein Ergebnis erwartet.

## 4. Wie funktioniert das?

Die [asyncio-Dokumentation zu Awaitables](https://docs.python.org/3.13/library/asyncio-task.html#awaitables) unterscheidet insbesondere Coroutines, Tasks und Futures. Eine Coroutine kann direkt erwartet werden. Ein Task ist zusätzlich für die Ausführung geplant. Ein Future kann ein noch ausstehendes oder bereits festgelegtes Ergebnis repräsentieren.

Mehrere nacheinander direkt erwartete Operationen sind nicht allein dadurch gleichzeitig geplant. Soll eine passende Gruppe nebenläufig laufen, müssen Aufgaben nach dem vorgesehenen Verfahren geplant und anschließend kontrolliert erwartet werden. Der Einsatz von `await` ersetzt diese Entwurfsentscheidung nicht.

Ein Future kann bereits abgeschlossen sein. Die [Dokumentation zu Future.set_result](https://docs.python.org/3.13/library/asyncio-future.html#asyncio.Future.set_result) beschreibt das Festlegen eines Ergebnisses und den abgeschlossenen Zustand. Das Beispiel prüft, dass das Erwarten eines solchen eigenen Futures im unveränderten Standardablauf keine Gelegenheit für einen anderen Task erzwingt.

Fehler und Abbruch sind weitere mögliche Ergebnisse eines erwarteten Ablaufs. `await` ist deshalb kein allgemeiner Erfolgsgarant. Die aufrufende Coroutine muss mit dem vorgesehenen Vertrag umgehen. Ebenso kann blockierender synchroner Code vor dem tatsächlichen Wartepunkt den Event Loop weiterhin aufhalten.

## 5. Wo begegnet mir das unter Linux?

Python-Anwendungen verwenden `await` bei geeigneten asynchronen Bibliotheken und eigenen Coroutines. Ein vorhandener Event Loop einer Oberfläche oder Laufzeit muss dabei berücksichtigt werden. Ein neues `asyncio.run` gehört nicht beliebig in jeden bereits laufenden asynchronen Kontext.

Dieses Beispiel wird als eigenes vollständiges Skript ausgeführt. Es besitzt seinen eigenen asyncio-Lauf und verändert keine bestehende Anwendung oder Ereignisverarbeitung. Es enthält keine Netzwerkabfrage und keine Wartezeit auf einen realen Dienst.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Arbeitsordner ausgeführt. Es verwendet den unveränderten Standard-Task-Ablauf dieses eigenen asyncio-Laufs. Eine besondere Eager-Task-Factory wird nicht eingerichtet.

```python
import asyncio

async def main():
    markierungen = []
    async def andere_aufgabe():
        markierungen.append("anderer Task")

    task = asyncio.create_task(andere_aufgabe())
    fertig = asyncio.get_running_loop().create_future()
    fertig.set_result(42)
    ergebnis = await fertig
    vorher = list(markierungen)
    assert ergebnis == 42 and vorher == []
    await task
    assert markierungen == ["anderer Task"] and task.done()
    print("Bereits fertiges Ergebnis:", ergebnis)
    print("Anderer Task lief schon vorher:", bool(vorher))
    print("Anderer Task danach beendet:", task.done())

asyncio.run(main())
```

Geprüfte Ausgabe:

```text
Bereits fertiges Ergebnis: 42
Anderer Task lief schon vorher: False
Anderer Task danach beendet: True
```

Das fertige Ergebnis wird direkt übernommen. Die andere Aufgabe ist zu diesem Beobachtungspunkt noch nicht gelaufen. Erst das anschließende Erwarten ihres Tasks führt den gezeigten Ablauf zu Ende. Die Prüfung betrifft diese eigenen Standardbedingungen, keine beliebig angepasste Task-Factory oder fremde Ereignisschleife.

## 7. Abgrenzung zu ähnlichen Begriffen

Async beschreibt ein Programmiermodell. Await ist ein Sprachbestandteil für geeignete Ergebnisse. Ein Thread ist ein anderer Ausführungsbaustein. Eine feste Schlafzeit wartet nach einem anderen Vertrag und beweist nicht, dass eine fachliche Aufgabe tatsächlich abgeschlossen ist.

## 8. Häufige Missverständnisse

Nicht jeder Funktionsrückgabewert ist awaitbar. `await` erzeugt nicht automatisch einen neuen Thread. Ein fertiges Ergebnis muss keine andere Task-Ausführung dazwischenschieben. Und mehrere direkte Warteausdrücke sind nicht automatisch nebeneinander geplante Aufgaben.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lies den Vertrag des erwarteten Objekts und plane Ergebnisse sowie Fehler ausdrücklich. Prüfe angepasste Laufzeitbedingungen gesondert. Das Beispiel beendet seinen eigenen Task und verändert weder Dateien, Dienste noch Netzwerk- oder GUI-Konfiguration.

# List Comprehension

## 1. Kurzbeschreibung

Eine List Comprehension ist eine Python-Schreibweise zum Erzeugen einer neuen Liste aus durchlaufbaren Ausgangswerten. Sie verbindet die Auswahl und gegebenenfalls Umformung der Werte in einem Ausdruck. Besonders gut passt sie zu kurzen Aufgaben wie „Quadrate aller positiven Zahlen bilden“.

## 2. Was bedeutet der Begriff?

Der englische Name lässt sich ungefähr als „Listenbeschreibung“ verstehen. Statt eine leere Liste anzulegen und in einer ausgeschriebenen Schleife Werte anzuhängen, beschreibst du direkt, welche Elemente das Ergebnis enthalten soll. Die äußeren eckigen Klammern kennzeichnen hier eine Liste.

Das [offizielle Python-Tutorial](https://docs.python.org/3.13/tutorial/datastructures.html#list-comprehensions) zeigt diese Form für Umformungen und Auswahlen. Der Ausdruck `[x * x for x in nums]` aus der Quelle ergibt die Quadrate der nacheinander durchlaufenen Zahlen. Er ändert `nums` dabei nicht. Was mit einem einzelnen Wert geschieht, hängt allerdings vom verwendeten Ausdruck ab.

## 3. Einfacher Vergleich aus dem Alltag

Du hast einen Korb mit Äpfeln. Für jeden ausreichend großen Apfel legst du eine beschriftete Karte in eine neue Schachtel. Die Anweisung beschreibt drei Dinge: welchen Korb du durchgehst, welche Äpfel du auswählst und was du jeweils in die Schachtel legst.

Dieser Vergleich erklärt Reihenfolge, Filter und neues Ergebnis. Er suggeriert aber keine unabhängigen Kopien aller Ausgangsobjekte. Wenn die List Comprehension vorhandene veränderbare Objekte unverändert übernimmt, können Ausgangssammlung und neue Liste auf dieselben Objekte verweisen.

## 4. Wie funktioniert das?

Bei `[ausdruck for element in quelle if bedingung]` wird die Quelle durchlaufen. Für jedes Element wird zuerst die Bedingung geprüft. Ist sie wahr, wird der Ausdruck berechnet und dessen Wert in die neue Liste aufgenommen. Ohne `if` werden alle durchlaufenen Elemente berücksichtigt.

Die Ergebnisliste wird bei der Auswertung aufgebaut, nicht erst beim späteren Lesen einzelner Elemente. Die [Sprachreferenz zu Comprehensions](https://docs.python.org/3.13/reference/expressions.html#displays-for-lists-sets-and-dictionaries) beschreibt außerdem ihren eigenen Gültigkeitsbereich für die Schleifenvariablen. Mehrere `for`-Teile sind möglich, müssen aber sorgfältig von links nach rechts gelesen werden.

## 5. Wo begegnet mir das unter Linux?

Python-Skripte verwenden List Comprehensions etwa für vorbereitete Tabellenwerte, ausgewählte Namen oder kleine Berechnungsergebnisse. Im Programm für eine grafische Oberfläche könnte man aus bereits vorhandenen Datensätzen passende Beschriftungen bilden.

Das ist Python-Syntax und keine besondere Funktion des Linux-Terminals. Eine List Comprehension führt auch keine Verarbeitung automatisch parallel aus. Ein darin aufgerufener langsamer Ausdruck bleibt Teil der normalen Auswertung und kann den aufrufenden Programmteil entsprechend beschäftigen.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Alle Eingaben sind selbst gewählt; es werden keine Dateien gelesen.

```python
zahlen = [-2, 0, 3, 4]
original = zahlen.copy()
quadrate = [zahl * zahl for zahl in zahlen if zahl > 0]

vergleich = []
for zahl in zahlen:
    if zahl > 0:
        vergleich.append(zahl * zahl)

assert quadrate == [9, 16]
assert quadrate == vergleich
assert zahlen == original
assert quadrate is not zahlen
assert [zahl * zahl for zahl in []] == []
print(quadrate)
print(zahlen)
```

Geprüfte Ausgabe:

```text
[9, 16]
[-2, 0, 3, 4]
```

Die negative Zahl und die Null erfüllen `zahl > 0` nicht. Nur Drei und Vier tragen Quadrate bei. Die ausgeschriebene Schleife bestätigt denselben Inhalt und dieselbe Reihenfolge. Weitere Assertions prüfen eine unveränderte Ausgangsliste, ein eigenständiges Listenobjekt und den leeren Eingabefall. Eine Laufzeitmessung findet nicht statt.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein [Generator](it_0094.md) kann Werte erst bei Bedarf liefern. Eine List Comprehension baut dagegen ihre Ergebnisliste während der Auswertung auf. Ein bloßes Listenliteral wie `[2, 3, 4]` zählt seine Elemente direkt auf. Eine gewöhnliche Schleife bietet mehr Platz für mehrere Arbeitsschritte, verständliche Zwischennamen und eine gezielte Fehlerbehandlung.

## 8. Häufige Missverständnisse

Die kürzeste Schreibweise ist nicht immer die verständlichste. Lange Verschachtelungen können eine einfache Aufgabe unnötig schwer lesbar machen. Die Auswahlbedingung am Ende entscheidet außerdem, ob ein Element aufgenommen wird; sie ersetzt nicht automatisch einen anderen Wert für ausgeschlossene Elemente.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Nutze die Form, wenn das Erzeugen einer Liste der eigentliche Zweck ist. Für bloße Nebenwirkungen, etwa viele Ausgaben ohne benötigtes Ergebnis, ist eine ausgeschriebene Schleife oft klarer. Bei großen oder endlosen Eingaben ist ein vollständiger Listenaufbau ungeeignet; prüfe dann eine begrenzte Verarbeitung oder schrittweise Weitergabe.

## 10. Verwandte Begriffe

Eine [Schleife](it_0015.md) beschreibt die wiederholte Verarbeitung. Ein [Ausdruck](it_0003.md) berechnet jeweils das neue Element. Der [Boolean](it_0010.md) hilft, die Wirkung einer Filterbedingung zu verstehen. Diese Bausteine bleiben auch in der kompakten Schreibweise erkennbar.

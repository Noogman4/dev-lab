# Shebang

## 1. Kurzbeschreibung

Ein Shebang ist eine besondere erste Skriptzeile, die mit `#!` beginnt und einen Interpreter benennt. Unter Linux kann das Betriebssystem beim direkten Start eines entsprechenden Skripts damit das passende Ausführungsprogramm auswählen. Die Zeile ersetzt weder gültigen Skriptcode noch benötigte Ausführungsrechte oder einen tatsächlich verfügbaren Interpreter.

## 2. Was bedeutet der Begriff?

„Shebang“ ist eine gebräuchliche Bezeichnung für die Zeichenfolge und die darauf folgende Interpreterangabe. Eine typische Form ist `#!/usr/bin/python3`. Das ist keine Dateiendung, sondern Inhalt am Anfang der Datei.

Die [Linux-Referenz von execve](https://man7.org/linux/man-pages/man2/execve.2.html) beschreibt Interpreter-Skripte und die Übergabe an den angegebenen Interpreter. Die Regel gehört zur Ausführung solcher Dateien unter Linux und ähnlichen Systemen. Sie darf nicht ungeprüft als identische Startregel jeder Plattform oder jeder grafischen Dateizuordnung behandelt werden.

## 3. Einfacher Vergleich aus dem Alltag

Auf dem Deckblatt eines Arbeitsauftrags steht, welche Fachstelle ihn bearbeiten soll. Die Annahmestelle leitet ihn dorthin weiter. Die Fachstelle muss anschließend weiterhin die eigentliche Anweisung verstehen.

So benennt der Shebang das benötigte Ausführungsprogramm. Die Grenze: Es gibt keine freie Sprachinterpretation. Ein falscher Pfad kann den Start verhindern, und ein vorhandener Interpreter kann ungeeigneten Code trotzdem ablehnen. Der Hinweis garantiert außerdem nicht, dass alle benötigten Bibliotheken installiert sind.

## 4. Wie funktioniert das?

Beim direkten Start prüft Linux das Dateiformat. Bei einem ausführbaren Skript mit `#!` startet der Kernel den angegebenen Interpreter und übergibt ihm den Skriptpfad als Aufrufargument. Die Standardeingabe bleibt ein eigener Kanal. Andere Systeme können das optionale Argument hinter dem Interpreterpfad anders behandeln.

Das [offizielle Python-Tutorial zu ausführbaren Skripten](https://docs.python.org/3.13/tutorial/appendix.html#executable-python-scripts) nennt ausdrücklich die ersten beiden Zeichen `#!` und den ausführbaren Dateimodus. Auch Zeilenenden können relevant sein. Ein zusätzliches Zeichen vor der Kennung kann deshalb mehr sein als eine bloße Darstellungsfrage.

## 5. Wo begegnet mir das unter Linux?

Python-, Shell- und andere Skripte können eine solche Zeile besitzen. Das Katalogbeispiel `#!/usr/bin/env python3` ist eine verbreitete Variante. Hier wird zunächst `env` unter dem angegebenen Pfad angesprochen. Dieses Werkzeug sucht und startet anschließend `python3` nach den geltenden Regeln. Der [POSIX-Standard zu env](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/env.html) beschreibt dessen Programmaufruf.

Damit ist die gewählte Python-Ausführung von der Umgebung abhängig. Das kann erwünscht sein, etwa für eine aktivierte Projektumgebung, ist aber keine Garantie für eine bestimmte Version. Ein direkter Interpreterpfad macht eine andere Festlegung und muss auf dem Zielsystem tatsächlich vorhanden sein.

## 6. Konkretes Beispiel Schritt für Schritt

Das Beispiel erzeugt unter Linux ein temporäres Skript und startet dessen Pfad direkt. Die erste Zeile verwendet den Interpreter des Prüfskripts. Für diese Variante braucht `sys.executable` einen absoluten Interpreterpfad ohne Leerzeichen und Tabulatoren. Linux liest solche Zeichen in der Shebang-Zeile als Trennzeichen. Das temporäre Verzeichnis muss die direkte Ausführung erlauben.

```python
from pathlib import Path
import subprocess
import sys
import tempfile

interpreter = Path(sys.executable)
if not interpreter.is_absolute() or any(c.isspace() for c in str(interpreter)):
    raise SystemExit("Für das Beispiel ist ein absoluter Python-Pfad ohne Leerraum nötig.")

with tempfile.TemporaryDirectory() as ordner:
    skript = Path(ordner) / "eigene_probe"
    skript.write_text(
        f"#!{interpreter}\nprint('Probe')\n",
        encoding="utf-8",
    )
    skript.chmod(0o700)
    ergebnis = subprocess.run(
        [str(skript)],
        capture_output=True,
        text=True,
        timeout=5,
        check=True,
    )
    assert skript.read_bytes().startswith(b"#!")
    assert ergebnis.stdout == "Probe\n"
    assert ergebnis.stderr == ""
    print(ergebnis.stdout, end="")
```

Geprüfte Ausgabe:

```text
Probe
```

Der Startaufruf nennt keinen Interpreter als separates Argument. Die eigene Datei besitzt auch keine notwendige `.py`-Endung. Der erfolgreiche direkte Start prüft hier die Kombination aus passender erster Zeile, vorhandenem Interpreter und Modusbits. Die `env`-Variante des Katalogs wird nicht ausgeführt.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Dateiendung kann Anwendungen als Hinweis dienen, ist aber nicht der Shebang. Wer einen Interpreter ausdrücklich mit einer Skriptdatei als Argument startet, trifft die Interpreterwahl bereits im Aufruf. Ein gewöhnlicher Kommentar erklärt Code für Leser; die erste `#!`-Zeile besitzt beim hier beschriebenen direkten Start zusätzlich eine Systemfunktion.

## 8. Häufige Missverständnisse

Ein Shebang macht ein Skript nicht automatisch ausführbar. Ein gesetztes Ausführungsbit repariert wiederum keinen falschen Interpreterpfad. Die Bezeichnung `python3` legt außerdem nicht überall dieselbe Haupt-Unterversion oder dieselbe Paketumgebung fest.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Wähle die Interpreterstrategie bewusst für den vorgesehenen Startweg. Achte auf erste Zeichen, Zeilenenden und passende Rechte. Der Test verwendet ausschließlich ein selbst geschriebenes temporäres Skript und verändert keine vorhandenen Startdateien, Interpreterinstallationen oder Suchpfade.

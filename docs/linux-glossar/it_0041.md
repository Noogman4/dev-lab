# Map

## 1. Kurzbeschreibung

Eine Map ist eine Zuordnung von Schlüsseln zu Werten. Über einen Schlüssel lässt sich der dazugehörige Wert nachschlagen, etwa eine Benutzerkennung über einen Namen. Die Quelle verwendet den Begriff in diesem Sinn. Das gleich geschriebene Python-Werkzeug `map()` bezeichnet dagegen eine andere Aufgabe: das Anwenden einer Funktion auf mehrere Eingaben.

## 2. Was bedeutet der Begriff?

Eine Zuordnung beantwortet Fragen wie „Welcher Wert gehört zu diesem Schlüssel?“. Innerhalb derselben Map besitzt ein Schlüssel nur einen zugeordneten Wert. Mehrere verschiedene Schlüssel können dagegen denselben Wert besitzen. Eine eindeutige Zuordnung in einer Richtung ist deshalb keine automatisch umkehrbare Beziehung.

Python bezeichnet solche Strukturen allgemein als Mapping. Das [offizielle Glossar](https://docs.python.org/3.13/glossary.html#term-mapping) nennt `dict` als konkretes Beispiel. Die allgemeine Schnittstelle beschreibt Nachschlagen über Schlüssel; eine veränderliche Zuordnung erlaubt zusätzlich entsprechende Änderungen. Eigenschaften wie Sortierung und erlaubte Schlüssel hängen vom konkreten Typ ab.

## 3. Einfacher Vergleich aus dem Alltag

Eine beschriftete Fächerkartei ordnet jeder Kennung einen Inhalt zu. Du suchst nach der Kennung, statt dich auf die zufällige Position der Karte zu verlassen. Zwei Kennungen könnten dieselbe Abteilung als Inhalt nennen.

Der Vergleich endet bei den technischen Regeln: Eine Map kann andere Schlüssel als Text verwenden und benötigt genaue Gleichheitsregeln. Außerdem können Inhalte selbst veränderliche Objekte sein. Eine Karteikopie entspricht daher nicht automatisch einer tiefen unabhängigen Kopie aller gespeicherten Daten.

## 4. Wie funktioniert das?

Die Datenstruktur speichert Schlüssel-Wert-Beziehungen und stellt Nachschlageoperationen bereit. Unterschiedliche Implementierungen können dafür beispielsweise Hashverfahren oder Suchbäume verwenden. Aus dem Namen Map allein folgt keine bestimmte Speicheranordnung oder garantierte Sortierung.

Pythons `map()` erzeugt dagegen einen Iterator, der eine Funktion auf aufeinanderfolgende Eingaben anwendet. Das erläutert die [Referenz zur eingebauten Funktion map](https://docs.python.org/3.13/library/functions.html#map). Das Ergebnis ist nicht automatisch ein Dictionary. Beide Bedeutungen verwenden die Vorstellung einer Abbildung, besitzen aber verschiedene Schnittstellen und Zwecke.

## 5. Wo begegnet mir das unter Linux?

Ein Verwaltungswerkzeug kann interne Namen auf Kennungen oder Einstellungen abbilden. Eine Auswertung kann zu jeder selbst erfassten Kategorie einen Zähler verwalten. Das sind mögliche Verwendungen einer Map, ohne dass dafür eine bestimmte Programmiersprache vorgeschrieben wäre.

Das Speichern einer Zuordnung zwischen Namen und Zahlen erstellt keine Betriebssystemkonten. Ebenso beweist ein passender Name keinen authentifizierten Benutzer. Eine interne Datentabelle und eine tatsächliche Berechtigungsentscheidung sollten nicht verwechselt werden.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel verwendet erfundene Namen und Kennungen sowie einen getrennten `map()`-Aufruf:

```python
kennungen = {"beispiel_a": 101, "beispiel_b": 102}
assert kennungen["beispiel_a"] == 101
kennungen["beispiel_a"] = 103
assert len(kennungen) == 2
verdoppelt = list(map(lambda zahl: zahl * 2, [1, 2, 3]))
assert verdoppelt == [2, 4, 6]
print(kennungen["beispiel_a"])
print(verdoppelt)
```

Die Ausgabe lautet:

```text
103
[2, 4, 6]
```

Das Dictionary bildet eine Map im Sinn der Quelle. Die Neuzuweisung ersetzt einen Wert unter einem vorhandenen Schlüssel. Der zweite Teil verarbeitet dagegen eine Folge mit einer Funktion. Erst `list` sammelt die dabei gelieferten Ergebnisse als Liste; es entsteht keine Benutzerzuordnung.

## 7. Abgrenzung zu ähnlichen Begriffen

Dictionary ist der Name einer konkreten Mapping-Art in Python. Eine Liste verwendet Positionen. Eine Funktion kann Werte rechnerisch abbilden, ohne alle Beziehungen als Tabelle zu speichern. Pythons `map()` ist ein Verarbeitungswerkzeug und nicht der allgemeine Datentyp für Schlüssel-Wert-Sammlungen.

## 8. Häufige Missverständnisse

Maps sind nicht überall alphabetisch sortiert. Werte müssen nicht eindeutig sein. Eine Rückwärtssuche nach einem Wert kann mehrere passende Schlüssel ergeben. Auch sind Eigenschaften eines Python-Dictionarys nicht automatisch Eigenschaften jeder Map in anderen Sprachen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lege Schlüsseltypen und Verhalten bei fehlenden Einträgen fest. Prüfe, ob eine Änderung bestehende Werte ersetzen darf. Verarbeite echte Benutzerzuordnungen entsprechend ihrer Vertraulichkeit. Das Beispiel enthält nur erfundene Daten und verändert keine Konten oder Systemdateien.

# Objekt

## 1. Kurzbeschreibung

Ein Objekt ist eine konkrete Einheit von Daten und gegebenenfalls zugehörigem Verhalten im Modell einer Programmiersprache. Die Quelle beschreibt es als Instanz einer Klasse. Das passt zum klassenorientierten Blick; in Python sind aber auch Zahlen, Texte, Funktionen und Klassen selbst Objekte. Der Begriff ist nicht auf sichtbare Fenster oder selbst definierte Klassen beschränkt.

## 2. Was bedeutet der Begriff?

Python beschreibt jedes Objekt anhand von Identität, Typ und Wert. Die Identität unterscheidet es von gleichzeitig vorhandenen anderen Objekten. Der Typ bestimmt wichtige Eigenschaften und erlaubte Operationen. Der Wert beschreibt seinen Inhalt oder Zustand. Diese Grundlagen stehen im [offiziellen Datenmodell](https://docs.python.org/3.13/reference/datamodel.html#objects-values-and-types).

Ein Name bezeichnet ein Objekt, ist aber nicht mit ihm identisch. Mehrere Namen können dieselbe Einheit erreichen. Auch können verschiedene Objekte gleichwertige Inhalte besitzen. Deshalb sind die Fragen „Sind die Werte gleich?“ und „Ist es dasselbe Objekt?“ getrennt zu beantworten.

## 3. Einfacher Vergleich aus dem Alltag

Zwei beschriftete Aufbewahrungsboxen können denselben Inhalt besitzen und trotzdem zwei verschiedene Boxen sein. Zwei Personen können außerdem über unterschiedliche Vermerke dieselbe Box meinen. Eine Änderung betrifft dann die gemeinsam gemeinte Box.

Die Grenze des Vergleichs: Nicht alle Python-Objekte sind veränderliche Behälter. Zahlen und Strings sind unveränderlich. Die Laufzeitumgebung kann außerdem gleiche unveränderliche Werte intern gemeinsam verwenden. Aus einer zufälligen Beobachtung der Identität darf deshalb keine allgemeine Regel über alle gleich aussehenden Werte abgeleitet werden.

## 4. Wie funktioniert das?

Ein Programm erzeugt oder erhält Objekte und führt passende Operationen darauf aus. Attribute erlauben bei vielen Objektarten den Zugriff auf benannte Bestandteile. Eine Klasseninstanz kann eigene Datenattribute und zugehörige Methoden bereitstellen; das erläutert die [Python-Einführung zu Instanzobjekten](https://docs.python.org/3.13/tutorial/classes.html#instance-objects).

Mit `==` wird nach den Regeln der beteiligten Typen verglichen. `is` prüft Identität. Beides ist nicht austauschbar. Bei einer Änderung muss außerdem zwischen dem Bearbeiten eines veränderlichen Objekts und dem Neubinden eines Namens unterschieden werden.

Die Speicherverwaltung gehört zur jeweiligen Implementierung. Ein im Code nicht mehr sichtbarer lokaler Name ist kein sicherer Beweis, dass jedes zuvor bezeichnete Objekt sofort verschwunden ist; andere Verweise können es weiterhin erreichbar halten.

## 5. Wo begegnet mir das unter Linux?

Python-Werkzeuge verarbeiten Objekte für Texte, Dateiinformationen, Einstellungen und Ergebnisse. Manche davon vertreten äußere Ressourcen wie Dateien oder Fenster. Das Objekt und die reale Ressource sind dennoch unterschiedliche Ebenen, deren Lebensdauer gesonderte Regeln besitzen kann.

Das Quellbeispiel eines Fensters ist deshalb eine mögliche Anwendung. Ein einfacher Datensatz kann aber ebenfalls ein Objekt sein, ohne ein Betriebssystemfenster zu öffnen. Für die Wirkung ist die tatsächliche Schnittstelle entscheidend, nicht eine anschauliche Beschriftung.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel verwendet zwei eigene Dictionary-Objekte als reine Zustandsdaten:

```python
a = {"titel": "Status"}
b = {"titel": "Status"}
verweis = a
assert a == b
assert a is not b
assert verweis is a
verweis["titel"] = "Geändert"
assert a["titel"] == "Geändert"
assert b["titel"] == "Status"
print(a["titel"])
print(b["titel"])
```

Die Ausgabe lautet:

```text
Geändert
Status
```

Anfangs stimmen die Inhalte überein, die Objekte sind trotzdem getrennt. Der zusätzliche Name `verweis` erreicht dagegen das erste Objekt. Seine Änderung ist deshalb über `a` sichtbar, nicht über `b`. Geprüft wird Objektidentität bei diesen bewusst erzeugten veränderlichen Dictionaries, nicht das Verhalten aller möglichen Typen.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Klasse beschreibt eine Art von Instanzen und ist in Python selbst ein Objekt. Eine Variable ist eine benannte Bindung. Eine Referenz ermöglicht einen Zugriff. Ein Wert ist ein Merkmal des Objekts. Ein äußeres Fenster kann durch ein Objekt vertreten werden, ist aber nicht mit jedem gespeicherten Fensterdatensatz identisch.

## 8. Häufige Missverständnisse

Ein Objekt muss nicht selbst programmiert oder sichtbar sein. Gleicher Inhalt beweist keine Identität. Ein neuer Variablenname garantiert kein neues Objekt. Umgekehrt bedeutet ein unveränderlicher Wert nicht, dass ein Name niemals an etwas anderes gebunden werden darf.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Verwende Wertvergleiche und Identitätsprüfungen entsprechend ihrer Bedeutung. Beachte gemeinsam veränderte Daten und Ressourcenlebensdauern. Das Beispiel verändert ausschließlich eigene Dictionaries und öffnet weder Dateien noch Fenster oder Netzwerkverbindungen.

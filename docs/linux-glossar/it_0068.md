# Button

## 1. Kurzbeschreibung

Ein Button ist eine Schaltfläche, über die eine vorgesehene Aktion aktiviert werden kann. Die Quelle nennt einen Start-Button für einen Scan. Das ist eine mögliche Anwendung; ein Button muss jedoch nicht ausschließlich mit der Maus bedient werden. Tastatur- und programmatische Aktivierung hängen von Toolkit und Anwendung ab.

## 2. Was bedeutet der Begriff?

Eine Schaltfläche verbindet Beschriftung, Zustand und Handlung. Die Beschriftung soll erklären, was die Aktivierung bewirkt. Der Zustand kann anzeigen, ob die Aktion aktuell verfügbar ist. Der aufgerufene Code führt die vorgesehene Arbeit aus oder stößt sie an.

Das [offizielle Tk-Handbuch für ttk::button](https://raw.githubusercontent.com/tcltk/tk/core-8-6-branch/doc/ttk_button.n) beschreibt Text oder Bild sowie die bei Aktivierung ausgeführte Aktion. Diese Regeln gehören zu dieser Widget-Art. Andere Toolkits können ähnliche Rollen mit anderen Eigenschaften und Ereignisschnittstellen bereitstellen.

## 3. Einfacher Vergleich aus dem Alltag

Eine Taste an einem Bedienpult löst eine bestimmte Funktion aus. Eine erkennbare Beschriftung verhindert, dass die Person den inneren Schaltplan kennen muss. Ein nicht verfügbarer Zustand sollte sichtbar von einer möglichen Aktion unterscheidbar sein.

Die Grenze des Vergleichs: Eine Softwareaktion kann länger dauern, fehlschlagen oder nur einen Auftrag einreihen. Die Aktivierung ist daher nicht automatisch der erfolgreiche Abschluss. Auch können wiederholte Aktivierungen dieselbe Arbeit mehrfach auslösen, wenn die Anwendung das nicht geeignet behandelt.

## 4. Wie funktioniert das?

Eine Anwendung verbindet die Schaltfläche mit einem Callback, also einem passend aufrufbaren Baustein. Bei der vorgesehenen Aktivierung wird dieser ausgeführt. Das Bereitstellen des Callbacks ist von seinem sofortigen Aufruf beim Einrichten zu unterscheiden.

Pythons `ttk.Button.invoke` kann die zugehörige Aktion programmatisch auslösen; das beschreibt die [offizielle Python-Referenz](https://docs.python.org/3.13/library/tkinter.ttk.html#tkinter.ttk.Button.invoke). Das folgende Beispiel prüft zusätzlich, dass die Aktion im deaktivierten Zustand der hier verwendeten Tk-Schaltfläche nicht ausgeführt wird. Eine solche programmgesteuerte Prüfung ist nützlich, ersetzt aber keinen vollständigen Nachweis von Tastatur-, Maus- und Fokusverhalten.

Der Button sollte den tatsächlichen Anwendungszustand sinnvoll vermitteln. Ein deaktiviertes Element erklärt allerdings nur dann genug, wenn die Person auch verstehen kann, warum die Aktion derzeit nicht möglich ist. Die fachliche Prüfung darf nicht ausschließlich von einer optischen Sperre abhängen.

## 5. Wo begegnet mir das unter Linux?

Dateidialoge, Einstellungen und NetMons Aktionsbereiche verwenden Schaltflächen. Sie können lesende Vorgänge, Änderungen oder den Start längerer Aufgaben auslösen. Die konkrete Wirkung muss aus Kontext und Beschriftung erkennbar sein.

Ein Name wie „Start“ beweist keinen erfolgreichen Scan und keine passende Berechtigung. Bei einer laufenden Aufgabe benötigt die Oberfläche zusätzlich eine angemessene Rückmeldung. Das folgende Beispiel zählt stattdessen ausschließlich eigene Callback-Aufrufe.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel wurde mit Tk unter dem vorhandenen virtuellen Bildschirm geprüft:

```python
# GUI-Prüfung im virtuellen Bildschirm
import tkinter as tk
from tkinter import ttk

root = tk.Tk()
root.withdraw()
try:
    aufrufe = []
    button = ttk.Button(root, text="Zählen", command=lambda: aufrufe.append("Aufruf"))
    button.invoke()
    assert aufrufe == ["Aufruf"]
    button.state(["disabled"])
    button.invoke()
    assert aufrufe == ["Aufruf"]
    button.state(["!disabled"])
    button.invoke()
    assert len(aufrufe) == 2
    print(len(aufrufe))
finally:
    root.destroy()
```

Die Ausgabe lautet:

```text
2
```

Zunächst wird die eigene Aktion einmal ausgelöst. Die deaktivierte Schaltfläche führt sie nicht erneut aus. Nach dem Aktivieren folgt ein zweiter Aufruf. Es wird kein echter Scan gestartet und kein menschlicher Klick simuliert; das Fenster bleibt verborgen.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Label zeigt Inhalt an, ohne allein dadurch dieselbe Aktionsrolle zu besitzen. Eine Checkbox repräsentiert typischerweise eine Auswahl. Eine Methode ist Programmverhalten; ein Button ist ein Oberflächenelement, das passendes Verhalten vermittelt. Ein Auftrag kann nach der Aktivierung unabhängig weiterlaufen.

## 8. Häufige Missverständnisse

Ein sichtbar gedrückter Button beweist keinen Erfolg. Ein deaktivierter Button ersetzt keine fachliche Zugriffskontrolle. Eine gleich benannte Methode ist noch kein Widget. Auch kann ein bereits beim Einrichten ausgeführter Callback das gewünschte spätere Verhalten verfehlen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Benutze eindeutige Aktionsnamen und berücksichtige Wiederholungen, laufende Zustände und Fehler. Das Beispiel prüft nur programmgesteuerte Tk-Aktivierung und Deaktivierung. Layout, Barrierefreiheit, echte Eingaben und NetMon-Aktionen wurden nicht praktisch abgenommen.

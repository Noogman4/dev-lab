# Statuscode

## 1. Kurzbeschreibung

Ein HTTP-Statuscode ist eine dreistellige Zahl in einer Antwort. Sie beschreibt die Einordnung der Anfrage und die Bedeutung der Antwort im HTTP-Kontext. Beispiele sind `200 OK` und `404 Not Found`. Der Code ist weder ein Prozess-Exit-Code noch ein vollständiges Urteil über die fachliche Richtigkeit aller zurückgegebenen Daten.

## 2. Was bedeutet der Begriff?

Die erste Ziffer bestimmt die Statusklasse. [RFC 9110 zu Statuscodes](https://www.rfc-editor.org/rfc/rfc9110.html#section-15) definiert den gültigen Bereich von 100 bis 599 und die fünf Klassen. Die beiden übrigen Ziffern dürfen nicht beliebig als zusätzliche hierarchische Kategorien interpretiert werden.

Das Katalogbeispiel ist für den Einstieg richtig. „Nicht gefunden“ ist bei `404` jedoch eine Aussage innerhalb der HTTP-Kommunikation. Der Code beweist weder, dass überhaupt kein Server existiert, noch dass eine Ressource weltweit oder dauerhaft verschwunden ist.

## 3. Einfacher Vergleich aus dem Alltag

Ein Bearbeitungsschreiben trägt eine vereinbarte Kennziffer: angekommen, erfolgreich behandelt, weiterer Schritt erforderlich oder Problem. Die Zahl erleichtert eine gemeinsame Einordnung, ohne den ganzen Text frei interpretieren zu müssen.

Die Grenze: Der Server muss die Kennziffer passend verwenden. Eine falsche Implementierung kann widersprüchliche Daten liefern. Auch ist eine Fehlerrückmeldung immer noch eine empfangene Antwort, während bei einem gescheiterten Verbindungsaufbau möglicherweise gar kein HTTP-Status vorliegt.

## 4. Wie funktioniert das?

Die Klassen bilden einen groben Rahmen:

| Klasse | Grundgedanke |
| --- | --- |
| 1xx | Information zum laufenden Austausch |
| 2xx | Erfolgreiche Behandlung im HTTP-Kontext |
| 3xx | Weitere Verarbeitung, etwa Weiterleitung oder Cachebezug |
| 4xx | Anfrage kann in dieser Form oder Situation nicht erfüllt werden |
| 5xx | Serverseite kann die betreffende Anfrage nicht erfüllen |

Für die genaue Bedeutung muss der einzelne Code betrachtet werden. Nicht jede 2xx-Antwort enthält einen Körper. Eine 3xx-Antwort ist ebenfalls nicht einfach in jedem Fall dieselbe Art von Adresswechsel. Methode, Felder und Inhalt bleiben wichtig.

[RFC 9110 zur Bedeutung von 404](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.5.5) nennt sowohl eine nicht gefundene aktuelle Darstellung als auch die Möglichkeit, deren Existenz nicht offenzulegen. Der Status ist daher kein uneingeschränkter Existenznachweis über den internen Datenbestand.

## 5. Wo begegnet mir das unter Linux?

Browser, Kommandozeilenwerkzeuge und Anwendungen werten HTTP-Antworten aus. Je nach Bibliothek wird ein Status direkt bereitgestellt oder bestimmte Werte werden zusätzlich als Ausnahme behandelt. Die konkrete Schnittstelle muss deshalb bekannt sein.

Python bietet mit [http.HTTPStatus](https://docs.python.org/3.13/library/http.html#http.HTTPStatus) benannte Werte und erklärende Texte. Das ist eine Hilfe beim Umgang mit bekannten Codes, kein Kontakt zu einem Server. Die vorhandene Menge gehört zur jeweiligen Python-Version und ist nicht automatisch eine Abfrage der neuesten Registry.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Es verarbeitet ausschließlich selbst gewählte Zahlen; es gibt keine echte HTTP-Antwort.

```python
from http import HTTPStatus

werte = [HTTPStatus(200), HTTPStatus(404)]
assert werte[0] == HTTPStatus.OK
assert werte[1] == HTTPStatus.NOT_FOUND
assert werte[0].value // 100 == 2
assert werte[1].value // 100 == 4
for status in werte:
    print(f"{status.value} {status.phrase}")
```

Geprüfte Ausgabe:

```text
200 OK
404 Not Found
```

Die Assertions prüfen Zuordnung und Klassen dieser zwei Werte. Sie beweisen weder, dass ein Endpoint erfolgreich erreicht wurde, noch dass eine reale Ressource fehlt. Die verwendeten englischen Bezeichnungen stammen aus der Python-Bibliothek. Eine serverseitige Fachantwort wird nicht nachgebildet oder bewertet.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Exit-Code beschreibt den Abschluss eines Prozesses. Eine Exception ist ein Fehler- oder Kontrollmechanismus einer Programmierschnittstelle. Ein HTTP-Status gehört zu einer Antwort. JSON beschreibt wiederum ein mögliches Inhaltsformat. Diese Angaben können gemeinsam auftreten, haben aber verschiedene Bedeutungen.

## 8. Häufige Missverständnisse

`200` garantiert keine richtigen Fachwerte. `404` bedeutet nicht „kein Netzwerk“. Die Klasse 4xx ist außerdem nicht automatisch ein persönlicher Fehler des Benutzers; Konfiguration und Zugriffssituation können beteiligt sein. Ohne Antwort darf kein empfangener Statuscode erfunden werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Bewahre bei einer Diagnose Status, relevante Felder und konkrete Operation zusammen auf. Behandle Wiederholungen nach dem API-Vertrag. Der Versuch hier ruft keinen Dienst auf, verarbeitet keine echten Serverdaten und verändert keine Anwendung oder Netzwerkverbindung.

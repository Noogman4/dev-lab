# CLI

## 1. Kurzbeschreibung

CLI steht für Command Line Interface, also Kommandozeilenschnittstelle. Ein Programm erhält Aufträge über Namen, Argumente und Optionen und gibt Ergebnisse oder Meldungen zurück. Die Quelle beschreibt die Bedienung über Terminalbefehle. Eine CLI kann aber auch aus einem Skript oder einem anderen Programm verwendet werden, ohne interaktiv in ein Terminal zu tippen.

## 2. Was bedeutet der Begriff?

Eine Kommandozeile beschreibt einen Aufruf. Die Schnittstelle legt fest, welche Angaben erforderlich, optional oder ungültig sind. Ein Argument kann etwa einen Eingabewert bezeichnen; eine Option wählt eine Einstellung. Die genaue Syntax bestimmt das jeweilige Programm.

Eine Shell ist dagegen ein Kommandointerpreter mit eigener Sprache. Das [GNU-Bash-Handbuch](https://www.gnu.org/software/bash/manual/html_node/What-is-a-shell_003f.html) erklärt ihre Rolle beim Ausführen und Kombinieren von Befehlen. Shell, Terminalfenster und aufgerufenes CLI-Programm sind deshalb unterschiedliche Bestandteile.

## 3. Einfacher Vergleich aus dem Alltag

Ein schriftlicher Auftrag kann Ziel und Zusatzangaben in einer festgelegten Form nennen. Der Empfänger muss die Angaben nicht durch einzelne Rückfragen ermitteln. Ein anderer Auftrag mit anderen Werten kann denselben Ablauf erneut verwenden.

Die Grenze des Vergleichs: Eine technische Kommandozeile besitzt genaue Regeln für Trennung, Zeichen und Verarbeitung. Eine Shell kann bestimmte Zeichen bereits interpretieren, bevor das Programm seine Argumente erhält. Ein scheinbar ähnlicher geschriebener Text muss deshalb nicht dieselben Argumentwerte erzeugen.

## 4. Wie funktioniert das?

Ein Programm verarbeitet seine Argumentliste und entscheidet über den vorgesehenen Ablauf. Python bietet dafür unter anderem `argparse`. Die [offizielle parse_args-Referenz](https://docs.python.org/3.13/library/argparse.html#argparse.ArgumentParser.parse_args) beschreibt die Umwandlung von Argumenttexten in strukturierte Angaben anhand vorher definierter Regeln.

Viele Programme bieten Hilfe und einen Exitstatus. Dieser Status ist von den ausgegebenen Texten zu unterscheiden. Ein leerer Ausgabekanal ist nicht automatisch Erfolg; eine sichtbare Meldung muss nicht das fachliche Ergebnis sein. Für automatisierte Verwendung sind diese Schnittstellen besonders wichtig.

## 5. Wo begegnet mir das unter Linux?

Paketwerkzeuge, Diagnoseprogramme und eigene Skripte können CLIs bereitstellen. Wiederholbare Aufrufe lassen sich automatisieren. Dabei muss bekannt sein, welche Befehle nur lesen und welche Daten oder Konfigurationen verändern.

Das Ping-Beispiel der Quelle ist ein CLI-Aufruf, erzeugt aber echten Netzwerkverkehr. Für diese Dokumentation wird stattdessen ein eigenes ungefährliches Programm verwendet. Es kontaktiert keine Adresse und ändert keine Netzwerkeinstellungen.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel erstellt eine eigene kleine CLI in einem temporären Ordner und startet sie ohne Shell:

```python
from pathlib import Path
import subprocess
import sys
import tempfile

quelle = (
    "import argparse\n"
    "p = argparse.ArgumentParser()\n"
    "p.add_argument('--name', required=True)\n"
    "p.add_argument('--anzahl', type=int, default=1)\n"
    "a = p.parse_args()\n"
    "for _ in range(a.anzahl): print('Hallo', a.name)\n"
)
with tempfile.TemporaryDirectory() as ordner:
    datei = Path(ordner) / "gruss.py"
    datei.write_text(quelle, encoding="utf-8")
    aufruf = [sys.executable, str(datei)]
    ergebnis = subprocess.run(
        aufruf + ["--name", "Sven", "--anzahl", "2"],
        capture_output=True, text=True, check=True, timeout=5,
    )
    assert ergebnis.stdout == "Hallo Sven\nHallo Sven\n"
    hilfe = subprocess.run(aufruf + ["--help"], capture_output=True, text=True, timeout=5)
    assert hilfe.returncode == 0 and "--name" in hilfe.stdout
    print(ergebnis.stdout, end="")
```

Die Ausgabe lautet:

```text
Hallo Sven
Hallo Sven
```

Die eigene CLI erhält ihren Namen und eine Anzahl als getrennte Argumente. Der Parser wandelt die Anzahl in einen Integer um. Zusätzlich wird die Hilfeschnittstelle tatsächlich aufgerufen und geprüft. Die äußere Beispielausführung zeigt nur die fachliche Ausgabe; Hilfe wurde separat erfasst.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine GUI bietet grafische Bedienelemente. Eine CLI verarbeitet Kommandoaufrufe. Eine Shell kann solche Aufrufe interpretieren und verbinden. Ein Terminal vermittelt Ein- und Ausgabe. Ein Python-Funktionsaufruf besitzt wiederum eine andere direkte Argumentschnittstelle.

## 8. Häufige Missverständnisse

CLI bedeutet nicht automatisch Administratorrechte. Ein Terminal ist nicht die Shell selbst. Die Texteingabe ist nicht allein aufgrund fehlender Grafik ungefährlich. Auch können Argumente sensible Daten enthalten und in Prozessinformationen oder Protokollen sichtbar werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lies Hilfetext und Wirkungen vor einem unbekannten Aufruf. Übergib Daten passend zur verwendeten Aufrufschnittstelle. Das Beispiel startet ausschließlich seinen selbst erzeugten Grußcode und verändert keine Projektdateien oder Systemdienste.

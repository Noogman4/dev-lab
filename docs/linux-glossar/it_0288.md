# How-to

## 1. Kurzbeschreibung

Ein How-to ist eine Anleitung für eine konkrete Aufgabe. Es führt vom beschriebenen Ausgangszustand zu einem überprüfbaren Ergebnis. Die Leserin weiß bereits ungefähr, was sie erreichen möchte, und braucht einen verlässlichen Ablauf.

## 2. Was bedeutet der Begriff?

Die [Diátaxis-Beschreibung von How-to-Guides](https://diataxis.fr/how-to-guides/) stellt reale Aufgaben in den Mittelpunkt. Eine Anleitung zur Paketierung könnte genau ein Ziel verfolgen, etwa ein Testpaket für eine festgelegte Debian-Version vorzubereiten. Die nötigen Vorkenntnisse, Werkzeuge und Einschränkungen gehören an den Anfang.

## 3. Einfacher Vergleich aus dem Alltag

Ein Rezept für ein bestimmtes Gericht sagt, welche Zutaten du brauchst und wann etwas fertig ist. Bei Software gibt es oft verschiedene Ausgangszustände. Eine gute Anleitung benennt deshalb Abzweigungen und sagt, wann ein Schritt auf die eigene Umgebung nicht passt.

## 4. Wie funktioniert das?

Ein typischer Aufbau beginnt mit Ziel, Voraussetzungen und erwarteter Ausgabe. Danach folgen Schritte in ausführbarer Reihenfolge. Wenn ein Schritt etwa ein Artefakt erzeugt, beschreibe, wie Leser dessen Existenz und Inhalt prüfen können. Ein Fehlerhinweis gehört dorthin, wo er beim Ablauf gebraucht wird.

Für das Paketbeispiel legt das [Debian Policy Manual zu Binärpaketen](https://www.debian.org/doc/debian-policy/ch-binary.html) Anforderungen an das konkrete Format fest. Ein How-to sollte auf eine solche Referenz verweisen, wenn Details zu Namen, Abhängigkeiten oder anderen Metadaten für die Aufgabe wichtig sind.

## 5. Wo begegnet mir das unter Linux?

Unter Linux können How-tos von einer reinen Benutzeraufgabe bis zu Paketbau und Administration reichen. Die Voraussetzungen wechseln mit Distribution, Rechtebedarf und installierten Werkzeugen. Eine allgemeine Anleitung gewinnt durch Angaben zur getesteten Umgebung.

## 6. Konkretes Beispiel Schritt für Schritt

Gedankenbeispiel für den Aufbau einer Anleitung.

1. Definiere das Ziel als ein lokal prüfbares Paketartefakt für eine bestimmte Testumgebung.
2. Nenne die vorausgesetzte Projektstruktur und beschreibe, welche Paketmetadaten ergänzt werden müssten.
3. Erkläre, wie der Leser das gebaute Artefakt erkennen und dessen Metadaten prüfen würde.
4. Halte eine Installation als gesonderten, ausdrücklich vorbereiteten Prüfschritt fest.

Dieses Beispiel liefert eine Gliederung. Es enthält keinen ausgeführten Paketbau und keine Installationsanweisungen für ein echtes Projekt.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Tutorial führt Lernende durch ein ausgewähltes Beispiel und erklärt Grundlagen unterwegs. Ein How-to löst eine konkrete Aufgabe. Eine Referenz hält die Details zu einer Schnittstelle für gezieltes Nachschlagen bereit.

## 8. Häufige Missverständnisse

Eine Folge von Befehlen allein ist keine vollständige Anleitung. Ohne Informationen zu Eingabe, Ziel und erwarteter Wirkung kann der Leser einen Fehler kaum erkennen. Mehr Schritte sind nur hilfreich, wenn sie zum Ziel beitragen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Kennzeichne Schritte mit Datenänderungen dort, wo sie auftreten. Gib bei unklarer Ausgangslage eine überprüfbare Bedingung an. Führe Tests mit selbst angelegten Daten durch, wenn das Beispiel echte Dateien verändert.

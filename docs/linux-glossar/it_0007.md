# String

## 1. Kurzbeschreibung

Ein String ist eine Zeichenkette, also ein Textwert. Er kann einen Namen, eine Fehlermeldung oder auch nur eine einzelne Ziffer enthalten. In Python heißt der Typ `str`. Das Quellbeispiel `'NetMon'` ist ein String; die Anführungszeichen kennzeichnen im Programmtext den Textwert und gehören hier nicht zu seinem Inhalt.

## 2. Was bedeutet der Begriff?

Strings sind geordnete Folgen von Textelementen. Die genaue technische Definition unterscheidet sich zwischen Sprachen. Python 3 definiert `str` als unveränderliche Folge von Unicode-Codepunkten. Unicode ordnet Zeichen und weiteren Textelementen nummerierte Positionen, die Codepunkte, zu. Das steht in der [Python-Dokumentation zum Texttyp str](https://docs.python.org/3.13/library/stdtypes.html#text-sequence-type-str).

Ein Codepunkt ist nicht in jedem Fall ein vollständig sichtbares Zeichen. Ein Buchstabe mit kombinierter Betonung kann aus mehreren Codepunkten bestehen. Die Länge eines Python-Strings beschreibt daher weder grundsätzlich seine Bildschirmbreite noch seine Dateigröße. Für einfache Texte mit lateinischen Grundbuchstaben fällt dieser Unterschied oft noch nicht auf.

## 3. Einfacher Vergleich aus dem Alltag

Du kannst dir eine Zeichenkette als beschriftetes Namensschild vorstellen. Du kannst den Text ablesen, nach einem Bestandteil suchen oder ein neues Schild mit einem ergänzten Text anfertigen.

Die Grenze des Vergleichs: Ein echtes Schild könntest du übermalen. Einen vorhandenen Python-String veränderst du nicht Zeichen für Zeichen. Eine Bearbeitungsoperation liefert einen anderen String oder verwendet einen bereits passenden unveränderlichen Wert. Außerdem unterscheidet das Papierbild nicht zwischen Text und seiner technischen Speicherung als Bytes.

## 4. Wie funktioniert das?

Mit `+` lassen sich zwei Strings zusammenfügen. Über einen Index, also eine Positionsnummer, kannst du auf ein Element zugreifen; Python beginnt bei null. `len` liefert bei einem String die Anzahl seiner Codepunkte. Diese Operationen beziehen sich auf den Textwert, nicht auf eine bestimmte Datei.

Zum Speichern oder Übertragen muss Text in Bytes übersetzt werden. Diese Übersetzungsregel heißt Zeichenkodierung. UTF-8 ist eine solche Kodierung; sie verwendet je nach Codepunkt unterschiedlich viele Bytes. Das [offizielle Unicode HOWTO zu Kodierungen](https://docs.python.org/3.13/howto/unicode.html#encodings) erklärt diesen Zusammenhang. Die Gegenrichtung übersetzt eine Bytefolge anhand der gewählten Kodierung wieder in Text.

## 5. Wo begegnet mir das unter Linux?

Dateinamen in einer Oberfläche, Meldungen in einem Protokoll und eingegebene Suchbegriffe werden häufig als Text verarbeitet. Ein Python-Hilfsprogramm kann solche Texte durchsuchen oder für die Anzeige zusammensetzen. Eine Zeichenkette wird dabei nicht automatisch als Befehl ausgeführt.

Beim Austausch von Dateien ist eine vereinbarte Kodierung wichtig. Ein korrekt gespeicherter Text kann falsch aussehen, wenn ein anderes Programm seine Bytes mit einer unpassenden Kodierung interpretiert. Für eigene UTF-8-Dateien ist es deshalb sinnvoll, die Kodierung beim Lesen und Schreiben ausdrücklich festzulegen; diese Aussage ist keine Garantie über die Kodierung sämtlicher Linux-Dateien.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel arbeitet nur im Speicher:

```python
name = "NetMon"
meldung = name + " hilft"
text = "Grüße"
daten = text.encode("utf-8")
assert name[0] == "N"
assert meldung == "NetMon hilft"
assert len(text) == 5
assert len(daten) == 7
assert daten.decode("utf-8") == text
print(meldung)
print(len(text), len(daten))
```

Die Ausgabe lautet:

```text
NetMon hilft
5 7
```

Die erste Rechnung verbindet zwei Texte. Das Wort `Grüße` enthält in dieser konkreten Schreibweise fünf Codepunkte. In UTF-8 benötigen `ü` und `ß` jeweils zwei Bytes, die übrigen drei Buchstaben jeweils eines. Deshalb ergibt die kodierte Bytefolge sieben Bytes. Die Rückübersetzung wird ebenfalls geprüft. Es wird weder eine Datei angelegt noch eine Netzwerkverbindung hergestellt.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein String ist Text; eine Bytefolge ist eine Folge von Bytewerten. Die Ziffernfolge `"42"` ist als String keine ganze Zahl. Erst eine passende Umwandlung erzeugt beispielsweise den Integer `42`. Ein Dateipfad kann als String dargestellt werden, doch der Text allein beweist nicht, dass die betreffende Datei existiert.

## 8. Häufige Missverständnisse

Einfache und doppelte Anführungszeichen können in Python beide String-Literale begrenzen. Ein String muss außerdem nicht mindestens ein Zeichen enthalten: Der leere String ist ein gültiger Textwert. Die Länge einer Zeichenkette ist nicht automatisch gleich ihrer Größe auf einem Datenträger.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Behandle eingegebenen Text als Daten. Soll ein Programm damit einen externen Prozess starten, braucht es eine gesonderte sichere Übergabe; bloßes Zusammenkleben zu einer Shell-Zeile kann unbeabsichtigte Befehle ermöglichen. Diese Gefahr entsteht durch die spätere Interpretation, nicht durch das Vorhandensein eines Strings. Das Beispiel interpretiert seinen Text ausschließlich als Text.

# Input Validation

## 1. Kurzbeschreibung

Input Validation bedeutet Eingabeprüfung. Sie entscheidet, ob Daten die vorgesehenen Anforderungen einer Anwendung erfüllen. Dazu gehören Form, Typ und fachliche Regeln. Eine gültige Eingabe ist nicht automatisch vertrauenswürdig für jeden späteren Kontext und verleiht keine Berechtigung. Prüfung, sichere Verarbeitung und Zugriffskontrolle ergänzen sich.

## 2. Was bedeutet der Begriff?

Die Quelle nennt eine IP-Adresse, die vor der Verwendung geprüft wird. Dafür muss feststehen, was erwartet wird: ein IPv4-Literal, ein IPv6-Literal, ein Hostname oder vielleicht ein Netzwerkbereich. Diese Formen sind nicht dasselbe. Ein Hostname kann fachlich erlaubt sein, obwohl ein Parser für reine IP-Adressliterale ihn zu Recht ablehnt.

Der [OWASP-Leitfaden zur Eingabeprüfung](https://raw.githubusercontent.com/OWASP/CheatSheetSeries/master/cheatsheets/Input_Validation_Cheat_Sheet.md) unterscheidet syntaktische und semantische Anforderungen. Eine korrekte Datumsform genügt beispielsweise nicht, wenn ein Enddatum fachlich vor dem Startdatum liegt. Entsprechend beweist eine korrekt geschriebene IP-Adresse weder Erreichbarkeit noch Eignung für einen bestimmten Zugriff.

## 3. Einfacher Vergleich aus dem Alltag

Ein Formular verlangt eine Anzahl von 1 bis 20. „Viele“ passt nicht zur Zahlenform. Die Zahl 100 ist zwar eine Zahl, liegt aber außerhalb des erlaubten Bereichs. Beide Fälle werden aus unterschiedlichen Gründen abgelehnt.

Die Grenze: Software verarbeitet genaue Darstellungen und Typen. Eine menschlich erkennbare Absicht muss nicht eindeutig technisch umsetzbar sein. Automatisches Korrigieren kann den Sinn verändern. Ein System sollte deshalb bewusst entscheiden, was es normalisiert, akzeptiert oder zurückweist.

## 4. Wie funktioniert das?

Zunächst wird der Eingabevertrag definiert. Dazu können zulässige Typen, Längen, Wertebereiche und Kombinationen gehören. Danach wird ein passender Parser verwendet und das Ergebnis fachlich geprüft. Wo eine feste Menge von Möglichkeiten vorgesehen ist, kann eine ausdrückliche Auswahl leichter verständlich sein als eine Liste einiger verbotener Zeichen.

Für IP-Literale beschreibt die [Python-Dokumentation zu ip_address](https://docs.python.org/3.13/library/ipaddress.html#ipaddress.ip_address) die Rückgabe eines IPv4Address- oder IPv6Address-Objekts und Fehler bei ungültigen Adressen. Das ist eine lokale Darstellungskontrolle. Der Aufruf führt keine DNS-Auflösung und keinen Erreichbarkeitstest aus.

Die Anwendung muss anschließend weiter entscheiden. Eine gültige Adresse kann beispielsweise auf einen lokalen oder besonderen Bereich zeigen. Ob das für die gewünschte Operation erlaubt ist, gehört zu zusätzlichen Regeln. Der allgemeine Parser kann diese fachliche Entscheidung nicht für jede Anwendung vorwegnehmen.

Auch geprüfte Daten brauchen im späteren Kontext eine geeignete Schnittstelle. Ein zulässiger Name kann ein Apostroph enthalten. Für eine SQL-Abfrage bleibt deshalb Parameterbindung wichtig. Eine frühe Eingabeprüfung macht beliebiges Zusammenbauen von Befehlen nicht automatisch sicher.

## 5. Wo begegnet mir das unter Linux?

Anwendungen lesen Daten aus Feldern, Dateien, Aufrufargumenten und anderen Prozessen. Auch gespeicherte Angaben können fehlerhaft oder für eine neue Verwendung ungeeignet sein. Eine grafische Vorprüfung hilft bei Rückmeldungen, ersetzt aber nicht jede Prüfung am maßgeblichen Verarbeitungspunkt.

Fehlermeldungen sollten verständlich erklären, welche Anforderung verletzt wurde, ohne daraus Erfolg vorzutäuschen. Dieses Dokument prüft nur eigene Zeichenketten. Es verbindet sich nicht mit einer der beispielhaft genannten Adressen und verändert keine Netzwerkoptionen.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Arbeitsordner ausgeführt. Der selbst gewählte Vertrag akzeptiert IP-Adressliterale als Text. Die gültigen Beispiele stammen aus Dokumentationsbereichen.

```python
from ipaddress import ip_address

v4 = ip_address("192.0.2.1")
v6 = ip_address("2001:db8::1")
assert v4.version == 4 and v6.version == 6
assert str(v4) == "192.0.2.1"
assert str(v6) == "2001:db8::1"
abgelehnt = 0
for text in ["999.0.0.1", "beispiel.invalid", "192.0.2.001"]:
    try:
        ip_address(text)
    except ValueError:
        abgelehnt += 1
assert abgelehnt == 3
print("Erste Adressversion:", v4.version)
print("Zweite Adressversion:", v6.version)
print("Abgelehnte Eingaben:", abgelehnt)
```

Geprüfte Ausgabe:

```text
Erste Adressversion: 4
Zweite Adressversion: 6
Abgelehnte Eingaben: 3
```

Die erste ungültige Eingabe enthält einen zu großen IPv4-Teilwert. Die zweite ist kein IP-Literal. Die dritte Schreibweise mit führenden Nullen wird in der hier verwendeten Python-Version abgelehnt. Das ist keine Behauptung über jeden historischen Parser. Es wird keine Adresse aufgelöst oder kontaktiert.

## 7. Abgrenzung zu ähnlichen Begriffen

Normalisierung bringt Daten in eine gewählte Darstellung. Validierung prüft Anforderungen. Kontextgerechte Ausgabe und Parameterbindung schützen eine bestimmte Weiterverwendung. Autorisierung entscheidet über erlaubte Aktionen. Diese Aufgaben können denselben Wert betreffen, sind aber nicht austauschbar.

## 8. Häufige Missverständnisse

Syntaktisch gültig bedeutet nicht erreichbar oder erlaubt. Ein Hostname ist kein IP-Literal. Eine Prüfung in der Oberfläche genügt nicht automatisch für alle anderen Zugriffswege. Und eine kurze Liste verbotener Zeichen ist keine universelle Eingabepolitik.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Definiere den Vertrag vor der Implementierung und verwende passende Parser. Prüfe gültige Fälle, Grenzwerte und Ablehnungen mit eigenen Daten. Die Übung führt keine Verbindungen, Installationen oder Änderungen an Geräten, Diensten und Netzwerkkonfiguration aus.

# IP-Adresse

## 1. Kurzbeschreibung

Eine IP-Adresse ist eine Adresse für Kommunikation mit dem Internet Protocol. Sie wird in einem bestimmten Netzkontext verwendet, damit Daten passend zugestellt werden können. Die kurze Formulierung „Adresse eines Geräts“ ist praktisch, aber ungenau: Ein Gerät kann mehrere Schnittstellen und mehrere IP-Adressen besitzen. Die Adresse ist keine unveränderliche Seriennummer des Geräts oder seines Benutzers.

## 2. Was bedeutet der Begriff?

Es gibt unterschiedliche Protokollversionen, insbesondere IPv4 und IPv6, mit unterschiedlichen Adressgrößen und Schreibweisen. Im jeweiligen Modell müssen Gültigkeitsbereich und Zuordnung betrachtet werden. Eine beliebige Zeichenfolge mit Punkten oder Doppelpunkten ist noch keine gültige Adresse.

Die [IPv6-Adressarchitektur in RFC 4291](https://www.rfc-editor.org/rfc/rfc4291.html) ordnet Adressen Schnittstellen zu und beschreibt mehrere Adressen je Schnittstelle sowie unterschiedliche Adressarten. Diese Details gehören zu IPv6. Sie zeigen, warum eine allgemeine Regel „jedes Gerät hat genau eine weltweit eindeutige IP-Adresse“ nicht trägt.

## 3. Einfacher Vergleich aus dem Alltag

Eine größere Einrichtung kann mehrere Eingänge und Zustelladressen besitzen. Eine Adresse hilft bei der Zustellung, identifiziert aber nicht automatisch eine bestimmte Person im Gebäude. Wird die Einrichtung verlegt, kann sich die Adresse ändern.

So hilft die Vorstellung beim Trennen von Erreichbarkeit und dauerhafter Identität. Die Grenze: Netzwerkadressen folgen formalen Regeln und können je nach Art verschiedene Zustellmodelle besitzen. Außerdem bedeutet eine passende Adresse nicht, dass jede Anwendung dort erreichbar ist oder Anfragen annehmen darf.

## 4. Wie funktioniert das?

Ein IP-Paket enthält Adressinformationen. Die beteiligten Systeme verwenden sie zusammen mit Weiterleitungsregeln. Für eine konkrete Anwendungsfunktion kommen weitere Angaben und Protokolle hinzu. Das Format einer IP-Adresse allein liefert weder eine Berechtigung noch eine fachlich erfolgreiche Antwort.

Das Katalogbeispiel `192.168.1.10` liegt im privaten IPv4-Bereich `192.168.0.0/16`. [RFC 1918](https://www.rfc-editor.org/rfc/rfc1918.html) reserviert solche Bereiche für private Netze. Sie dürfen in voneinander getrennten Netzen wiederverwendet werden. „Privat“ bedeutet hier eine Adresskategorie, nicht automatische Verschlüsselung oder eine Garantie, dass keine anderen lokalen Teilnehmer erreichbar sind.

## 5. Wo begegnet mir das unter Linux?

Netzwerkverwaltung und Anwendungen arbeiten mit Adressen von Schnittstellen oder Gegenstellen. Ein Linux-Rechner kann beispielsweise gleichzeitig über verschiedene Zugänge verfügen. Welche Adresse für einen bestimmten Weg verwendet wird, hängt von seiner Einrichtung und den Weiterleitungsentscheidungen ab.

Eine Adressanzeige ist deshalb nur ein Teil einer Diagnose. Eine vorhandene Adresse beweist weder einen funktionierenden DNS-Dienst noch eine erreichbare Webanwendung. Auch ein Wechsel des Netzes kann die Zuordnung verändern. Dieser Eintrag fragt keine reale Schnittstelle ab und richtet keine Adresse ein.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Es verarbeitet nur selbst gewählte Texte. Die IPv6-Adresse stammt aus dem durch [RFC 3849](https://www.rfc-editor.org/rfc/rfc3849.html) für Dokumentation vorgesehenen Bereich `2001:db8::/32`.

```python
import ipaddress

v4 = ipaddress.ip_address("192.168.1.10")
v6 = ipaddress.ip_address("2001:db8::10")
langform = ipaddress.ip_address("2001:0db8:0000:0000:0000:0000:0000:0010")
assert v4.version == 4
assert v4.max_prefixlen == 32
assert v4 in ipaddress.ip_network("192.168.0.0/16")
assert v6.version == 6
assert v6.max_prefixlen == 128
assert v6 == langform
print(f"IPv{v4.version}: {v4}")
print(f"IPv{v6.version}: {v6}")
```

Geprüfte Ausgabe:

```text
IPv4: 192.168.1.10
IPv6: 2001:db8::10
```

Die [Python-Referenz zu ip_address](https://docs.python.org/3.13/library/ipaddress.html#ipaddress.ip_address) beschreibt die Umwandlung in passende Adressobjekte. Die Assertions prüfen Version, Bitlänge, einen IPv4-Bereich und zwei gleichwertige IPv6-Schreibweisen. Sie prüfen keine reale Vergabe, Erreichbarkeit oder zulässige Nutzung auf diesem Rechner.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Rechnername ist nicht dieselbe Darstellung wie eine IP-Adresse und kann über eigene Auflösungsverfahren zu Adressen führen. Ein Port unterscheidet bestimmte Kommunikationsendpunkte zusätzlich. Eine MAC-Adresse gehört zu einem anderen Adressierungskontext. Diese Angaben dürfen nicht beliebig gegeneinander ausgetauscht werden.

## 8. Häufige Missverständnisse

Eine private Adresse gehört nicht exklusiv nur einem einzigen Heimnetz weltweit. Eine Adresse beweist auch keine Personenidentität. Zwei Schreibweisen können bei IPv6 dieselbe Adresse beschreiben. Umgekehrt sind ähnlich aussehende Adressen nicht automatisch im gleichen für einen Zugriff relevanten Netzbereich.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Kläre bei Problemen Protokollversion, Schnittstelle und gewünschten Dienst. Verwende Dokumentationsadressen für veröffentlichte Beispiele, sofern kein bestimmter privater Bereich erklärt werden soll. Die Tests hier senden keine Pakete, verändern keine Schnittstellen und greifen auf keine Gegenstelle zu.

## 10. Verwandte Begriffe

Das [Netzwerk](it_0138.md) stellt den Kommunikationszusammenhang bereit. Ein [Socket](it_0129.md) kann eine Adresse für einen konkreten Austausch verwenden. Ein [String](it_0007.md) ist zunächst nur die textuelle Darstellung und muss vor der Verarbeitung geprüft werden.

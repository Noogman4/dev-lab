# Prozess

## 1. Kurzbeschreibung

Ein Prozess ist eine vom Betriebssystem verwaltete Ausführungsinstanz. Die kurze Erklärung „ein laufendes Programm“ ist für den Einstieg hilfreich, aber unvollständig: Derselbe Programmcode kann in mehreren Prozessen arbeiten. Ein Prozess besitzt einen Zustand, eine Identität und zugeordnete Ressourcen und muss nicht in jedem Augenblick auf der CPU rechnen.

## 2. Was bedeutet der Begriff?

Ein Programm kann als Datei mit Anweisungen vorliegen. Ein Prozess ist dagegen Teil des laufenden Systems. Er hält den für seine Ausführung benötigten Zusammenhang, etwa Speicher, offene Dateizugriffe und Sicherheitsmerkmale. Ein Programm zweimal zu starten kann daher zwei getrennte Ausführungsinstanzen erzeugen.

Die [Linux-Handbuchseite zu fork](https://man7.org/linux/man-pages/man2/fork.2.html) beschreibt die Erzeugung eines Kindprozesses und dessen Trennung vom Elternprozess. Beide erhalten insbesondere getrennte Speicherbereiche. Das ist eine konkrete Linux-Schnittstelle zur Prozesserzeugung, keine Behauptung, dass jedes Startwerkzeug intern immer genau diesen Aufruf verwendet.

## 3. Einfacher Vergleich aus dem Alltag

Ein Rezept beschreibt, wie ein Kuchen gebacken wird. Zwei Küchen können nach demselben Rezept unabhängig arbeiten. Sie haben jeweils einen eigenen Arbeitsstand, eigene Zutaten und gerade benutzte Geräte.

So kann ein Programm mehreren Prozessen zugrunde liegen. Die Grenze des Vergleichs: Prozesse können bewusst Ressourcen teilen oder miteinander kommunizieren. Außerdem können Teile eines Programms gleichzeitig innerhalb desselben Prozesses arbeiten. Es gilt deshalb nicht pauschal „eine Aufgabe, ein Programmname, ein Prozess“.

## 4. Wie funktioniert das?

Das Betriebssystem verwaltet ausführbare und wartende Aufgaben und teilt ihnen Ressourcen zu. Ein Prozess kann beispielsweise auf Eingabe warten, während ein anderer rechnet. Auf einem System mit mehreren Prozessorkernen ist tatsächlich gleichzeitige Arbeit möglich; ansonsten kann zeitliche Abwechslung einen flüssigen Gesamteindruck erzeugen.

Ein vorhandener Prozess kann auch ein anderes Programm laden. Die [Dokumentation von execve](https://man7.org/linux/man-pages/man2/execve.2.html) beschreibt die Ersetzung des bisherigen Programmbildes. Dabei entsteht nicht allein wegen dieses Austauschs ein neuer Prozess mit neuer Prozesskennung. Programm und Prozess sind daher eng verbunden, aber keine austauschbaren Begriffe.

## 5. Wo begegnet mir das unter Linux?

Desktopanwendungen, Shells und Hintergrundprogramme arbeiten als Prozesse oder nutzen mehrere davon. Ein sichtbares Fenster muss nicht genau einem Prozess entsprechen. Umgekehrt kann ein Prozess ohne Fenster arbeiten. Der Katalog nennt `ps` als Werkzeug zur Prozessanzeige; dessen Ausgabe ist eine Momentaufnahme nach den gewählten Auswahlregeln.

Python kann mit [subprocess.run](https://docs.python.org/3.13/library/subprocess.html#subprocess.run) einen eigenen Unterprozess starten und dessen Ende abwarten. Der Elternprozess kann anschließend Rückgabecode und Ausgaben prüfen. Ein ordnungsgemäß beendeter Kindprozess und ein weiterhin laufender Elternprozess sind dabei verschiedene Zustände.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Es startet ausschließlich eigenen kurzen Code mit dem vorhandenen Python-Interpreter. Es liest keine Prozessliste und verändert keine fremden Prozesse.

```python
import os
import subprocess
import sys

kindcode = (
    "import os\n"
    "print(os.getpid())\n"
    "print(os.getppid())\n"
    "print(2 + 3)\n"
)
ergebnis = subprocess.run(
    [sys.executable, "-c", kindcode],
    capture_output=True,
    text=True,
    timeout=5,
    check=True,
)
kind_pid, eltern_pid, summe = map(int, ergebnis.stdout.splitlines())
assert kind_pid > 0
assert kind_pid != os.getpid()
assert eltern_pid == os.getpid()
assert summe == 5
assert ergebnis.returncode == 0
assert ergebnis.stderr == ""
print("Eigener Kindprozess:", kind_pid != os.getpid())
print("Ergebnis:", summe)
```

Geprüfte Ausgabe:

```text
Eigener Kindprozess: True
Ergebnis: 5
```

Die tatsächlichen Kennungen werden verglichen, aber wegen ihrer veränderlichen Werte nicht als feste Beispielzahlen ausgegeben. Der Kindprozess beendet sich nach seiner Berechnung selbst. Das Skript prüft die Elternbeziehung und das Ergebnis; es misst weder gleichzeitige Ausführung noch Speicherisolation.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Programm ist der auszuführende Code, ein Prozess seine konkrete Ausführungsinstanz. Ein Thread ist ein Ausführungsstrang innerhalb eines Prozesses und teilt typischerweise Ressourcen mit anderen Threads desselben Prozesses. Ein Dienst beschreibt eine bereitgestellte Funktion und kann je nach Aufbau einen oder mehrere Prozesse verwenden.

## 8. Häufige Missverständnisse

„Laufend“ bedeutet nicht ununterbrochen rechnend. Gleiche Programmnamen bedeuten nicht dieselbe Instanz. Eine Prozesskennung bezeichnet außerdem nicht für immer dieselbe Arbeit: Nach dem Ende können Kennungen später erneut vergeben werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Untersuche bei Fehlern die konkrete Instanz und ihren Zustand. Ein wahlloses Beenden ähnlich benannter Prozesse kann andere Aufgaben unterbrechen und ungesicherte Daten verlieren lassen. Der Versuch hier wartet nur auf seinen eigenen kurzlebigen Kindprozess; er sendet keine Signale an vorhandene Prozesse.

## 10. Verwandte Begriffe

[subprocess](it_0101.md) stellt Python-Schnittstellen zum Programmstart bereit. Der [Kernel](it_0106.md) verwaltet grundlegende Ressourcen. Eine [Runtime](it_0031.md) kann Teil der Umgebung sein, in der ein Programm innerhalb eines Prozesses arbeitet.

# Gateway

## 1. Kurzbeschreibung

Ein Gateway ist allgemein ein Übergang zwischen Kommunikationsbereichen. Im üblichen IP-Kontext bezeichnet das Wort häufig einen nächsten Router, über den andere Netze erreichbar werden. Ein Standard-Gateway ist dabei eine mögliche Auffangroute, nicht automatisch der Weg für jedes Ziel. Die tatsächlich gewählte Route hängt von den vorhandenen Regeln ab.

## 2. Was bedeutet der Begriff?

Das englische Wort lässt sich mit Tor oder Übergang übersetzen. In anderen technischen Zusammenhängen kann ein Gateway auch Protokolle oder Anwendungsformate vermitteln. Dieser Text konzentriert sich auf den verbreiteten Netzwerkgebrauch als Weiterleitungszugang.

[RFC 1812](https://www.rfc-editor.org/rfc/rfc1812.html) beschreibt die Aufgaben von IPv4-Routern und die Auswahl geeigneter Routen. Ein Rechner kann einen solchen Router als nächsten Hop verwenden. Der Router ist dann eine Zwischenstation, nicht zwangsläufig der endgültige Empfänger der Anwendungsdaten.

## 3. Einfacher Vergleich aus dem Alltag

Ein Gebäude besitzt einen allgemeinen Ausgang zur Straße und möglicherweise einen besonderen Übergang zu einem Nachbarhaus. Für ein Ziel im Nachbarhaus ist der spezielle Übergang sinnvoller als der allgemeine Ausgang.

So hilft der Vergleich, spezielle und standardmäßige Wege auseinanderzuhalten. Die Grenze: Routing folgt technischen Regeln und muss nicht dem räumlich kürzesten Weg entsprechen. Ein Gateway ist zudem keine Garantie, dass der gesamte weitere Weg funktioniert. Es stellt zunächst einen vorgesehenen nächsten Schritt dar.

## 4. Wie funktioniert das?

Ein System ordnet Zielbereiche passenden Routen zu. Eine Route kann direkt über eine Schnittstelle führen oder einen nächsten Router benennen. Im vereinfachten zielbasierten Modell hat ein genauer passendes längeres Präfix Vorrang vor einer allgemeineren Route. RFC 1812 beschreibt diese längste Präfixübereinstimmung für IPv4.

Eine Standardroute deckt Ziele ab, für die keine geeignetere Auswahl vorliegt. Die [Linux-Handbuchseite zu ip route](https://man7.org/linux/man-pages/man8/ip-route.8.html) erläutert Zielpräfixe, nächste Hops und `default`. Reale Linux-Konfigurationen können zusätzliche Regeln und Tabellen verwenden. Die einfache Darstellung ist deshalb ein Einstieg, keine vollständige Beschreibung jeder möglichen Routingentscheidung.

## 5. Wo begegnet mir das unter Linux?

Bei einer üblichen Heimnetzeinrichtung übernimmt der Heimrouter häufig die Rolle des Standard-Gateways. Das Katalogbeispiel ist damit plausibel. Es legt aber weder eine bestimmte Routeradresse noch eine allgemeine Regel für jedes Linux-System fest.

Ein Rechner kann mehrere Schnittstellen, spezielle Routen oder getrennte Netzkontexte besitzen. Ein lokales Ziel muss möglicherweise gar nicht über das Standard-Gateway erreicht werden. Ebenso ist der DNS-Resolver eine andere Rolle, auch wenn ein Heimrouter beides auf demselben Gerät anbietet.

## 6. Konkretes Beispiel Schritt für Schritt

Die Tabelle ist ein fiktives IPv4-Modell. Die Bereiche sind Dokumentationsbereiche nach [RFC 5737](https://www.rfc-editor.org/rfc/rfc5737.html). Es wird keine echte Routingtabelle gelesen oder geändert.

| Zielbereich | Nächster Schritt | Vereinfachte Bedeutung |
| --- | --- | --- |
| 192.0.2.0/24 | direkt | Lokal erreichbarer Bereich |
| 198.51.100.0/24 | 192.0.2.1 | Besonderer Übergang |
| 0.0.0.0/0 | 192.0.2.254 | Standardweg |

Für `198.51.100.20` passt im Modell die zweite Zeile genauer als die Standardroute. Ein Ziel `203.0.113.20` würde dagegen den Standardweg verwenden, weil keine speziellere Zeile vorhanden ist. Ein lokales Ziel im ersten Bereich braucht nach diesem Modell keinen der beiden angegebenen Router als nächsten Hop.

Diese Auswahl ist keine gemessene Kernelentscheidung. Weitere reale Regeln, Erreichbarkeit der nächsten Station und deren eigene Weiterleitung fehlen bewusst. Auch sind die beiden Routeradressen ausschließlich erfunden. Es werden keine Pakete gesendet und keine Geräte kontaktiert.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Router leitet IP-Pakete zwischen Netzen weiter. „Gateway“ beschreibt hier seine Rolle als Übergang für einen anderen Teilnehmer. Ein Resolver beschafft Namensinformationen. Eine Firewall entscheidet über zulässigen Verkehr. Ein Gerät kann mehrere Rollen bündeln; die Aufgaben bleiben verschieden.

## 8. Häufige Missverständnisse

Das Standard-Gateway muss nicht dieselbe Adresse wie der DNS-Server besitzen. Es hat auch nicht zwingend die letzte Zahl eins. Ein erreichbares Gateway beweist keine erfolgreiche Verbindung bis zum entfernten Dienst. Umgekehrt kann lokale Kommunikation funktionieren, obwohl ein Weg nach außen fehlt.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Beschreibe bei einer Diagnose Ziel, Schnittstelle und erwarteten Weg. Ein ungeprüfter Wechsel der Standardroute kann bestehende Zugriffe unterbrechen. Für die Begriffserklärung ist das nicht nötig. Dieser Eintrag verändert weder Routen noch Geräte-, Dienst- oder Netzwerkeinstellungen.

## 10. Verwandte Begriffe

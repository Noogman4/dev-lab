# Unit Test

## 1. Kurzbeschreibung

Ein Unit Test prüft eine kleine, klar abgegrenzte Einheit der Software. Das kann eine Funktion, Klasse oder passend gewählte Gruppe sein. Die Prüfung soll verständlich zeigen, ob deren vereinbarter Vertrag erfüllt wird. Der Begriff legt nicht zwingend eine einzige Zeile oder eine universelle technische Größenregel fest.

## 2. Was bedeutet der Begriff?

Die Quelle nennt eine isoliert getestete Funktion. Besonders gut lässt sich das bei Verarbeitung ohne äußere Wirkungen zeigen: Eigene Eingaben werden übergeben, Ergebnisse und erwartete Fehler geprüft. Reale Netzwerkdienste oder persönliche Dateien sind dafür oft nicht nötig.

Das [Grundbeispiel der Python-unittest-Dokumentation](https://docs.python.org/3.13/library/unittest.html#basic-example) zeigt Testmethoden und Vergleiche mit erwarteten Ergebnissen. Das Framework unterstützt den Ablauf. Ob eine konkrete Prüfgrenze sinnvoll gewählt ist, bleibt eine Entwurfsfrage. Ein Test wird nicht allein deshalb fachlich gut, weil seine Klasse einen passenden Namen besitzt.

## 3. Einfacher Vergleich aus dem Alltag

Du prüfst eine einzelne Schere mit einem vorgesehenen Material, statt gleichzeitig die ganze Werkstatt in Betrieb zu nehmen. So lässt sich ein Problem leichter dieser Aufgabe zuordnen. Die erwartete Schnittkante ergibt sich aus der Anforderung.

Die Grenze: Dass die Schere allein funktioniert, beweist nicht den gesamten Arbeitsablauf mit Maschine, Materialzufuhr und Bedienung. Ebenso liefert ein Unit Test keine automatische Aussage über reale Datenbankverbindungen oder eine vollständige Benutzeroberfläche. Der begrenzte Umfang ist Teil seiner Aussage.

## 4. Wie funktioniert das?

Zuerst wird der Vertrag der Einheit beschrieben. Danach werden eigene Daten vorbereitet, die relevante Operation aufgerufen und ihre beobachtbaren Ergebnisse geprüft. Ein Test sollte möglichst nicht davon abhängen, welche nicht zugesicherten internen Hilfsschritte die Implementierung gerade verwendet.

Fehlerfälle gehören ebenfalls dazu. Die [Dokumentation zu assertRaises](https://docs.python.org/3.13/library/unittest.html#unittest.TestCase.assertRaises) erklärt das Prüfen einer erwarteten Ausnahme. Wird keine oder eine andere Ausnahme ausgelöst, ist das nicht derselbe erfolgreiche Nachweis. Eine absichtlich erwartete Ablehnung kann also ein bestandener Testfall sein.

Abhängigkeiten können je nach Grenze durch geeignete eigene Ersatzobjekte bereitgestellt werden. Das ist nicht für jede einfache Funktion erforderlich. Wo ein Ersatz verwendet wird, muss seine begrenzte Aussage bekannt sein. Ein solcher Test beweist nicht automatisch, dass der echte Dienst dieselben Bedingungen erfüllt.

Auch die Erwartung soll nicht bloß dieselbe Berechnung unter anderem Namen wiederholen. Konkrete Beispiele aus dem Vertrag helfen: Welche Randzeichen werden entfernt, was bleibt erhalten und welche Eingaben sind verboten? So kann eine Abweichung erkennbar werden, statt nur interne Details zu bestätigen.

## 5. Wo begegnet mir das unter Linux?

Python-Projekte verwenden häufig unittest, pytest oder andere Werkzeuge. Kleine lokale Prüfungen können schnell Rückmeldung geben, ohne dafür eine GUI oder einen Dienst zu starten. Welche Werkzeuge vorhanden sind, muss in der Umgebung geprüft werden; das Beispiel verwendet nur die Standardbibliothek.

Für dieses Glossar wird keine bestehende Testsuite erweitert. Der gesamte Beispielcode wird als eigenes Skript in einem temporären Bereich ausgeführt. Er importiert keine Anwendungsteile und verwendet keinen vorhandenen Datenbestand.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 ausgeführt. Der eigene Vertrag lautet: Randabstände entfernen, innere Abstände erhalten und einen danach leeren Titel ablehnen. Andere Eingabetypen sind nicht Gegenstand dieser kleinen Prüfung.

```python
import io
import unittest

def titel_vorbereiten(text):
    titel = text.strip()
    if not titel:
        raise ValueError("Titel fehlt")
    return titel

class TitelTest(unittest.TestCase):
    def test_randabstaende(self):
        self.assertEqual(titel_vorbereiten(" \tProbe A\n"), "Probe A")

    def test_leerer_titel(self):
        with self.assertRaises(ValueError):
            titel_vorbereiten(" \t\n")

suite = unittest.defaultTestLoader.loadTestsFromTestCase(TitelTest)
bericht = io.StringIO()
ergebnis = unittest.TextTestRunner(stream=bericht, verbosity=0).run(suite)
assert ergebnis.testsRun == 2 and ergebnis.wasSuccessful(), bericht.getvalue()
print("Ausgeführte Testfälle:", ergebnis.testsRun)
print("Erfolgreich:", ergebnis.wasSuccessful())
```

Geprüfte Ausgabe:

```text
Ausgeführte Testfälle: 2
Erfolgreich: True
```

Der erste Fall prüft zugleich die erhaltene innere Worttrennung. Der zweite verlangt ausdrücklich die Ablehnung. Der Runner-Bericht bleibt im eigenen Speicher; bei einem Fehlschlag würde er zur Diagnose verfügbar. Ein erfolgreicher Lauf bestätigt nur diese Fälle, keine allgemeine Unicode- oder Anwendungsabnahme.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Unit Test wählt eine kleine Grenze. Ein Test mehrerer echter zusammenarbeitender Teile betrachtet andere Wechselwirkungen. Ein vollständiger Nutzerablauf hat wiederum weiteren Umfang. Eine produktive Eingabeprüfung ist Teil des Programms und wird durch einen Test nicht ersetzt.

## 8. Häufige Missverständnisse

Unit bedeutet nicht zwingend eine einzelne Methode. Ein Ersatzobjekt ist nicht immer nötig. Viele Testzeilen garantieren keine sinnvolle Erwartung. Und ein grüner Unit-Testlauf beweist keine korrekte gesamte Anwendung.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Wähle die Grenze nach dem Vertrag und halte Eingaben nachvollziehbar. Prüfe wichtige Erfolgs- und Ablehnungsfälle. Die Ausführung verwendet ausschließlich eigene Speicherwerte und verändert keine Anwendung, Tests, Abhängigkeiten, Dateien oder Dienste.

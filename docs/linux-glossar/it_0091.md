# Exception

## 1. Kurzbeschreibung

Eine Exception ist eine Ausnahme, die den normalen Ablauf eines Programms unterbrechen und an eine passende Behandlung weitergegeben werden kann. Die Quelle nennt ein abfangbares Laufzeitproblem. Viele Ausnahmen melden solche Probleme; manche dienen aber auch vorgesehenen Kontrollabläufen. Eine Exception ist deshalb nicht automatisch der Beweis eines Programmdefekts.

## 2. Was bedeutet der Begriff?

Bei einer Operation kann ein Sonderfall auftreten, für den kein gewöhnliches Ergebnis bereitsteht. Das Programm kann dann eine Ausnahme auslösen. Aufrufender Code kann gezielt darauf reagieren, eine verständliche Meldung erzeugen oder die Ausnahme weitergeben.

Python verwendet dafür Klassen von Ausnahmeobjekten. Die [offizielle Ausnahmehierarchie](https://docs.python.org/3.13/library/exceptions.html#exception-hierarchy) zeigt ihre Beziehungen. `Exception` ist zugleich ein bestimmter Klassenname. Nicht jede von `BaseException` abgeleitete Ausnahme gehört zu dieser engeren Klasse; Unterbrechungs- und Beendigungsfälle brauchen besondere Beachtung.

## 3. Einfacher Vergleich aus dem Alltag

Eine Arbeitsstelle meldet: „Dieser Auftrag kann unter den gegebenen Voraussetzungen nicht normal erledigt werden.“ Eine zuständige Stelle entscheidet dann, ob eine Alternative möglich ist oder die Meldung weitergereicht werden muss.

Die Grenze des Vergleichs: Softwarebehandlung folgt genauen Typ- und Ablaufregeln. Eine beliebige beruhigende Ersatzantwort repariert die Ursache nicht. Auch kann das pauschale Abfangen wichtiger Abbruchsignale verhindern, dass ein Programm wie erwartet beendet werden kann.

## 4. Wie funktioniert das?

Python führt Anweisungen in einem `try`-Block aus. Bei einer passenden Ausnahme wird eine vorgesehene `except`-Behandlung verwendet. Ohne passende Behandlung wird die Ausnahme an aufrufende Ebenen weitergegeben. Das [offizielle Tutorial zur Ausnahmebehandlung](https://docs.python.org/3.13/tutorial/errors.html#handling-exceptions) erklärt diesen Ablauf.

Die gewählte Ausnahmeart ist wichtig. Ein `ValueError` bei einer Zahlenumwandlung bedeutet etwas anderes als ein fehlgeschlagener Dateizugriff. Eine enge Behandlung macht deutlich, mit welchem Sonderfall gerechnet wird. Ein weiter gefasster Fang kann dagegen auch unerwartete Fehler verdecken.

Das Fehlen einer angezeigten Ausnahme beweist keine fachliche Richtigkeit. Umgekehrt kann ein bewusst behandelter ungültiger Eingabewert zu einer korrekt funktionierenden Anwendung gehören. Fehlersignal, Ursache und Ergebnis der Behandlung sind getrennte Fragen.

## 5. Wo begegnet mir das unter Linux?

Python-Werkzeuge können ungültige Eingaben, fehlende Dateien oder gescheiterte Bibliotheksoperationen als Ausnahmen erhalten. Anwendungen sollten daraus passende Rückmeldungen ableiten, statt technische Details unkontrolliert zu verlieren oder jeden Fall als denselben Fehler zu behandeln.

Auch manche regulären Sprachprotokolle verwenden Ausnahmen intern. Ein Beispiel ist das signalisierte Ende einer Iteration. Das macht die Ausnahme nicht automatisch zu einem Absturz oder Sicherheitsvorfall. Die konkrete Schnittstelle erklärt ihre Bedeutung.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel verarbeitet nur eigene Texte und behandelt genau die erwartete Umwandlungsausnahme:

```python
ergebnisse = []
for text in ["3", "keine", "0"]:
    try:
        zahl = int(text)
    except ValueError:
        ergebnisse.append("ungültig")
    else:
        ergebnisse.append(zahl)
assert ergebnisse == [3, "ungültig", 0]
assert ergebnisse[2] == 0
print(ergebnisse)
```

Die Ausgabe lautet:

```text
[3, 'ungültig', 0]
```

Die gültigen Texte werden zu Zahlen. Der ungeeignete Text löst den vorgesehenen `ValueError` aus und erhält eine ausdrücklich vereinbarte Kennzeichnung. Null bleibt ein gültiges Ergebnis. Das Beispiel prüft keine beliebigen anderen Eingabetypen und fängt sie nicht pauschal als denselben Fall ab.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Bug ist ein Defekt. Eine Exception ist ein Mechanismus zum Signalisieren und Weitergeben eines besonderen Falls. Ein Traceback beschreibt zugehörige Aufrufstellen. Ein gewöhnlicher Rückgabewert verwendet die normale Ergebnisschnittstelle. Eine Meldung ist nur eine mögliche sichtbare Darstellung.

## 8. Häufige Missverständnisse

Abfangen bedeutet nicht automatisch Beheben. Eine Exception muss nicht das gesamte Programm beenden. Ein pauschaler Fang ist nicht grundsätzlich robuster. Auch kann ein Programm ohne Ausnahme das falsche fachliche Ergebnis liefern.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Behandle erwartete Sonderfälle gezielt und bewahre nötigen Kontext. Unterdrücke Abbruchsignale nicht unbedacht. Das Beispiel verarbeitet nur feste eigene Strings; keine Dateien, Dienste oder realen Benutzerunterbrechungen wurden getestet.

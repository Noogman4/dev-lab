# Cache

## 1. Kurzbeschreibung

Ein Cache ist ein Zwischenspeicher, der bereits beschaffte oder berechnete Ergebnisse für spätere Verwendung bereithält. Ein passender Treffer kann erneute Arbeit ersparen. Dafür muss klar sein, welche Anfrage zu welchem Eintrag gehört und wann ein Ergebnis noch verwendet werden darf. Ein Cache kann veraltete Werte liefern, wenn Aktualisierung und Gültigkeit nicht passend geregelt sind.

## 2. Was bedeutet der Begriff?

Die Quelle nennt einen DNS-Cache mit kürzlich aufgelösten Namen. Dabei gehört zur Wiederverwendung mehr als nur der Name: DNS-Datensatzart und weitere Regeln sind relevant. Die [DNS-Grundspezifikation RFC 1035 zum Datensatzformat](https://www.rfc-editor.org/rfc/rfc1035.html#section-3.2.1) beschreibt unter anderem die TTL als Zeitangabe für die zulässige Zwischenspeicherung. Das Beispiel unten führt jedoch keine DNS-Abfrage aus.

Andere Caches besitzen andere Regeln. Manche speichern Funktionsergebnisse innerhalb eines Prozesses, andere Antworten auf Datenträgern. Ein Cache ist deshalb weder grundsätzlich flüchtig noch grundsätzlich dauerhaft. Seine konkrete Ausgestaltung muss geprüft werden.

## 3. Einfacher Vergleich aus dem Alltag

Du notierst dir eine häufig benötigte Auskunft auf einem Zettel. Beim nächsten Mal liest du den Zettel, statt die Auskunft erneut einzuholen. Das spart Arbeit, solange die Notiz noch zur Frage passt und ausreichend aktuell ist.

Die Grenze: Eine Software braucht technische Schlüssel, Platzregeln und einen Umgang mit veralteten Angaben. Ein ähnlicher Schlüssel kann eine andere Frage bedeuten. Außerdem kann eine gespeicherte Auskunft durch eine spätere Änderung der Quelle falsch werden. Die bloße Existenz des Zettels beweist keine Aktualität.

## 4. Wie funktioniert das?

Bei einer Anfrage wird nach einem passenden Eintrag gesucht. Bei einem Treffer kann dieser nach den geltenden Regeln verwendet werden. Bei einem Fehltreffer wird die eigentliche Quelle oder Berechnung benötigt. Das Ergebnis kann anschließend wieder aufgenommen werden.

Gültigkeit und Speicherverdrängung sind unterschiedliche Fragen. Eine Größenbegrenzung entscheidet, wie viele Einträge Platz haben. Eine Ablaufzeit oder erneute Prüfung kann dagegen bestimmen, ob ein vorhandener Eintrag noch brauchbar ist. Die [HTTP-Cache-Spezifikation RFC 9111 zur Frische](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.2) erklärt dafür konkrete HTTP-Regeln. Diese dürfen nicht pauschal als Verhalten jedes Python-Caches verstanden werden.

Pythons [functools.lru_cache](https://docs.python.org/3.13/library/functools.html#functools.lru_cache) merkt sich Ergebnisse anhand aufrufbezogener Schlüssel und kann die Zahl gespeicherter Einträge begrenzen. Er bietet keine allgemeine automatische Kenntnis darüber, dass eine anderweitig verwendete Datenquelle verändert wurde. Das Beispiel zeigt genau diese Grenze und leert den Cache ausdrücklich.

## 5. Wo begegnet mir das unter Linux?

Programme und Bibliotheken verwenden Zwischenspeicher für verschiedene Zwecke. Ein sichtbarer alter Wert kann aus einem Cache stammen, muss es aber nicht. Vor dem Löschen vermeintlicher Cachedateien sollte deshalb geklärt werden, welcher Speicher tatsächlich beteiligt ist und welche Folgen eine Entfernung hat.

Ein Cache ersetzt auch keine unabhängige Sicherung. Je nach Anwendung kann sein Inhalt entbehrlich oder für den laufenden Betrieb wichtig sein. Dieses Dokument löscht keine vorhandenen System- oder Anwendungsdateien. Es verwendet nur einen eigenen Funktionscache im Testprozess.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Arbeitsordner ausgeführt. Die „Quelle“ ist ein eigenes Wörterbuch. Es gibt keinen Datei-, DNS- oder Netzwerkzugriff und keine Zeitmessung.

```python
from functools import lru_cache

quelle = {"titel": "Alt"}
zugriffe = 0

@lru_cache(maxsize=2)
def laden(schluessel):
    global zugriffe
    zugriffe += 1
    return quelle[schluessel]

assert laden("titel") == "Alt"
assert laden("titel") == "Alt" and zugriffe == 1
quelle["titel"] = "Neu"
vor_leeren = laden("titel")
assert vor_leeren == "Alt" and zugriffe == 1
laden.cache_clear()
nach_leeren = laden("titel")
assert nach_leeren == "Neu" and zugriffe == 2
print("Vor dem Leeren:", vor_leeren)
print("Nach dem Leeren:", nach_leeren)
print("Quellzugriffe:", zugriffe)
```

Geprüfte Ausgabe:

```text
Vor dem Leeren: Alt
Nach dem Leeren: Neu
Quellzugriffe: 2
```

Wiederholte gleiche Anfragen sparen hier Quellzugriffe. Eine Änderung des Wörterbuchs allein invalidiert den gespeicherten Rückgabewert nicht. Erst nach dem ausdrücklichen Leeren wird erneut gelesen. Die Prüfung zeigt weder eine Zeitablaufregel noch einen messbaren Geschwindigkeitsvorteil oder eine allgemeine Nebenläufigkeitsgarantie.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Datenbank hält verwaltete Datenbestände. Ein Cache bewahrt Ergebnisse zur Wiederverwendung auf. Ein Puffer sammelt Daten beispielsweise für eine Übertragung oder Verarbeitung. Die Aufgaben können sich technisch berühren, sind aber nicht gleichbedeutend. Eine Sicherung dient wiederum einem gesonderten Wiederherstellungsziel.

## 8. Häufige Missverständnisse

Ein Treffer ist nicht automatisch aktuell. Größenbegrenzung ist keine Ablaufzeit. Mehr Cache bedeutet nicht für jede Aufgabe mehr Geschwindigkeit. Und das Leeren eines eigenen Funktionscaches ist nicht dasselbe wie das Zurücksetzen aller Caches eines Systems.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Dokumentiere Schlüssel, Gültigkeit und Aktualisierungsweg. Prüfe Treffer, Fehltreffer und Änderungen der Quelle. Verwende veraltete Werte nur nach den vorgesehenen Regeln. Das Beispiel entfernt ausschließlich eigene Speicherergebnisse innerhalb seines Testprozesses.

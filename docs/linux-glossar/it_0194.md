# Tabelle

## 1. Kurzbeschreibung

Eine Tabelle organisiert Daten in einem relationalen Datenbanksystem nach Zeilen und benannten Spalten. Die Definition beschreibt, welche Angaben vorgesehen sind und welche Regeln gelten. Die vorhandenen Zeilen bilden den aktuellen Bestand. Eine SQL-Tabelle ist jedoch nicht automatisch eine geordnete Liste mit eindeutigen Namen oder eine grafische Ansicht wie in einer Tabellenkalkulation.

## 2. Was bedeutet der Begriff?

Die [PostgreSQL-Einführung zu Tabellen](https://www.postgresql.org/docs/current/ddl-basics.html) erklärt feste Spaltendefinitionen und eine veränderliche Menge von Zeilen. Sie weist auch darauf hin, dass ohne zusätzliche Regeln gleiche Zeilen möglich sind und keine feste Zeilenreihenfolge zugesichert ist.

Das Katalogbeispiel einer Tabelle `stations` für Radiosender ist plausibel. Welche Angaben ein Sender benötigt, legt aber das Datenmodell fest. Eine Tabelle mit diesem Namen besitzt nicht automatisch eine bestimmte Bedeutung oder Verbindung zu einem tatsächlich laufenden Radiodienst.

## 3. Einfacher Vergleich aus dem Alltag

Ein Karteiformular legt fest, welche Rubriken jeder Eintrag besitzt. Im Archiv können viele ausgefüllte Karten mit dieser Struktur liegen. Regeln können verlangen, dass eine bestimmte Rubrik ausgefüllt oder eine Kennung eindeutig ist.

Die Grenze: SQL-Tabellen folgen technischen Regeln statt der räumlichen Anordnung eines Karteikastens. Eine sichtbar erste Zeile hat nicht automatisch einen besonderen dauerhaften Platz. Auch muss eine fachliche Bezeichnung nicht eindeutig sein, solange dies nicht ausdrücklich durch den Entwurf verlangt wird.

## 4. Wie funktioniert das?

Eine Tabellendefinition enthält Spalten und gegebenenfalls Bedingungen. Anweisungen fügen passende Daten ein, wählen sie aus oder verändern sie. Die Definition und die aktuell gespeicherten Daten sind dabei verschiedene Aspekte.

Die [SQLite-Dokumentation zu CREATE TABLE](https://www.sqlite.org/lang_createtable.html) beschreibt unter anderem Typangaben und Constraints. Ein `NOT NULL` kann einen fehlenden Wert ausschließen. Daraus folgt nicht automatisch, dass jeder nicht fehlende Text fachlich gültig ist. Ein leerer String und ein fehlender Wert sind unterschiedliche Fälle.

Auch Eindeutigkeit muss zu den gewünschten Angaben passen. Zwei Datensätze dürfen beispielsweise denselben Anzeigenamen besitzen, während ihre ausgewählte Kennung verschieden ist. Eine Anwendung sollte Namen deshalb nicht ohne Vertrag als sichere Identifikation verwenden.

## 5. Wo begegnet mir das unter Linux?

Anwendungen können strukturierte Bestände in Tabellen ablegen. Eine Oberfläche zeigt möglicherweise nur einen gefilterten oder anders zusammengesetzten Ausschnitt. Die sichtbare Bildschirmtabelle muss daher nicht exakt einer einzigen gespeicherten Datenbanktabelle entsprechen.

Bei einem Fehler ist zu unterscheiden, ob die Struktur nicht passt, eine Regel verletzt wird oder die Auswahl falsch formuliert ist. Ein unbekannter Tabellenname beweist außerdem nicht, dass alle Datenbanken des Rechners beschädigt sind. Der konkrete Bestand und seine Schnittstelle sind maßgeblich.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Arbeitsordner ausgeführt. Es erzeugt nur eine eigene In-Memory-Tabelle. Die beiden gleichen Namen sind absichtlich gewählt.

```python
from contextlib import closing
import sqlite3

with closing(sqlite3.connect(":memory:")) as db:
    db.execute("CREATE TABLE stations (id INTEGER PRIMARY KEY, name TEXT NOT NULL)")
    db.executemany("INSERT INTO stations VALUES (?, ?)", [(1, "Probe"), (2, "Probe")])
    auswahl = db.execute("SELECT id, name FROM stations ORDER BY id")
    assert [feld[0] for feld in auswahl.description] == ["id", "name"]
    zeilen = auswahl.fetchall()
    assert zeilen == [(1, "Probe"), (2, "Probe")]
    abgelehnt = False
    try:
        db.execute("INSERT INTO stations VALUES (?, ?)", (3, None))
    except sqlite3.IntegrityError:
        abgelehnt = True
    assert abgelehnt
    assert db.execute("SELECT COUNT(*) FROM stations").fetchone() == (2,)
    print(len(zeilen))
    print("Fehlender Name abgelehnt:", abgelehnt)
```

Geprüfte Ausgabe:

```text
2
Fehlender Name abgelehnt: True
```

Die Auswahl hat die ausdrücklich genannten Spalten. Gleiche Anzeigenamen sind erlaubt, der fehlende Name wird nach der gewählten Regel abgelehnt. Das prüft diese konkrete SQLite-Struktur. Es bestätigt weder ein vollständiges Radiosender-Datenmodell noch eine bestehende Anwendungstabelle oder einen Netzwerkdienst.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Datenbank kann viele Tabellen und andere Objekte enthalten. Eine Abfrage kann ein Ergebnis liefern, das von der gespeicherten Struktur abweicht. Eine Tabellenkalkulation besitzt eine andere Bedien- und Berechnungsumgebung. Ein Python-Tupel aus einer Auswahl ist wiederum eine Programmdarstellung eines Ergebnisses.

## 8. Häufige Missverständnisse

Ein Tabellenname garantiert keine bestimmte Fachsemantik. Eine Zeile ist nicht automatisch durch ihren Platz identifiziert. Gleiche Namen sind nicht überall verboten. Eine erfolgreich angelegte Struktur bedeutet auch nicht, dass jede spätere Eingabe den fachlichen Anforderungen genügt.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Definiere Regeln nach dem tatsächlichen Datenmodell. Prüfe Strukturänderungen zuerst mit eigenen Beständen. Der Versuch öffnet keine Anwendungsdateien und verändert weder gespeicherte Sender, Dienste noch Datenbankschemata vorhandener Programme.

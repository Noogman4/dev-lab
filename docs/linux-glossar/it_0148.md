# DNS

## 1. Kurzbeschreibung

DNS, das Domain Name System, ist ein verteiltes Namenssystem. Es ordnet Namen strukturierte Informationen zu, darunter IP-Adressen und Angaben für andere Dienste. Die bekannte Erklärung „übersetzt Namen in IP-Adressen“ beschreibt einen wichtigen Anwendungsfall, aber nicht alle Funktionen. Ein Name kann mehrere Einträge verschiedener Typen besitzen.

## 2. Was bedeutet der Begriff?

Domainnamen bilden eine Hierarchie. Zuständige Server verwalten Teile dieser Struktur, während andere Komponenten Anfragen bearbeiten und Ergebnisse zwischenspeichern. [RFC 1034](https://www.rfc-editor.org/rfc/rfc1034.html) beschreibt das Grundmodell. Es ist eine Basisspezifikation, die durch spätere Standards erweitert wurde, keine vollständige Aufzählung aller heutigen DNS-Funktionen.

Die Daten heißen Resource Records, also Ressourceneinträge. Ihr Typ bestimmt die Bedeutung. Ein `A`-Eintrag enthält im Internet-Kontext eine IPv4-Adresse. Weitere Typen können beispielsweise andere Namen oder Zuständigkeiten beschreiben. Der Name allein sagt deshalb noch nicht, welche Art von Antwort angefragt wird.

## 3. Einfacher Vergleich aus dem Alltag

Ein verteiltes Verzeichnis nennt Ansprechpartner und Zuständigkeiten. Eine Auskunftsstelle kann bekannte Antworten bereithalten oder bei zuständigen Stellen nachfragen. Ein Eintrag kann mehrere Kontaktmöglichkeiten enthalten.

Das erklärt Verteilung und Zwischenspeicherung. Die Grenze: DNS ist kein frei formulierter Telefonbucheintrag. Typen, Antwortregeln und Gültigkeitszeiten sind technisch definiert. Eine erhaltene Adresse beweist außerdem nicht, dass dort der gewünschte Dienst funktioniert oder die Kommunikation ausreichend geschützt ist.

## 4. Wie funktioniert das?

Eine Anfrage bezeichnet unter anderem einen Namen und einen gewünschten Typ. Das Ergebnis kann passende Einträge, weitere Verweise oder einen Fehler enthalten. [RFC 1035](https://www.rfc-editor.org/rfc/rfc1035.html) spezifiziert grundlegende Nachrichten und Datentypen.

Die Gültigkeitszeit TTL gibt an, wie lange ein Eintrag nach den vorgesehenen Regeln zwischengespeichert werden darf. Sie ist kein Versprechen, dass sich Daten niemals früher ändern. Eine Änderung beim zuständigen Server löscht auch nicht automatisch sämtliche bereits vorhandenen gültigen Kopien in entfernten Caches.

Für IPv6 definiert [RFC 3596](https://www.rfc-editor.org/rfc/rfc3596.html) den Typ `AAAA`. Die DNS-Anfrageart und das zum Übertragen verwendete IP-Protokoll sind zu unterscheiden: Ein IPv6-Adresswert in einer Antwort bedeutet nicht automatisch, dass schon die Anfrage über IPv6 transportiert wurde.

## 5. Wo begegnet mir das unter Linux?

Browser und andere Anwendungen lassen Namen auflösen, bevor sie bestimmte Gegenstellen ansprechen. Die eingesetzte Auflösung kann mehrere lokale Komponenten und entfernte Resolver einbeziehen. Nicht jede Namensauflösung muss ausschließlich aus einer aktuellen entfernten DNS-Anfrage bestehen.

Das Katalogbeispiel mit `example.com` veranschaulicht die Richtung Name zu Adresse. Es garantiert weder einen bestimmten heutigen Adresswert noch genau eine Antwort. Dieser Eintrag löst den Namen nicht auf und untersucht keine vorhandene Resolverkonfiguration.

## 6. Konkretes Beispiel Schritt für Schritt

Die Tabelle enthält fiktive DNS-Daten. Sie wurde nicht abgefragt und ist keine aktuelle Veröffentlichung eines realen Dienstes.

| Name | Typ | Beispielwert |
| --- | --- | --- |
| hilfe.beispiel.invalid. | A | 192.0.2.20 |
| hilfe.beispiel.invalid. | AAAA | 2001:db8::20 |

Der gleiche Name besitzt hier Werte für zwei Adressversionen. Eine Anwendung kann abhängig von Anfrage, Ergebnis und eigener Auswahlregeln unterschiedliche Wege versuchen. Aus der Tabelle folgt nicht, dass beide Wege erreichbar sind.

Der Punkt am Ende kennzeichnet in dieser Darstellung den vollständigen Namen. Er ist kein weiterer Teil einer IP-Adresse. Die Werte dienen nur zur Erklärung. Es werden keine DNS-Pakete versendet und keine Cacheeinträge oder Zonen geändert.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine IP-Adresse ist ein Adresswert. Ein Domainname ist eine anders strukturierte Bezeichnung. Eine vollständige Webadresse kann zusätzlich Schema, Pfad und weitere Teile enthalten; DNS löst nicht einfach diese gesamte Zeichenkette als Domain auf. Ein Resolver ist eine Komponente der Auflösung, nicht das gesamte DNS.

## 8. Häufige Missverständnisse

DNS kennt nicht nur `A`-Einträge. Ein erfolgreicher Namensabruf beweist keine funktionierende Webseite. Keine passende Antwort für einen bestimmten Typ bedeutet auch nicht in jedem Fall, dass der Name überhaupt nicht existiert. Fehlerart und angefragter Typ müssen gemeinsam betrachtet werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Nenne bei einer Diagnose Namen, Typ und konkrete Antwort. Berücksichtige Zwischenspeicherung, bevor du Änderungen als wirkungslos deutest. Ungeprüft einen anderen Resolver einzutragen verändert die Einrichtung und ist keine notwendige Lernübung. Dieser Text fragt keine Namen ab und verändert keine Netzparameter.

## 10. Verwandte Begriffe

Die [IP-Adresse](it_0139.md) ist ein möglicher DNS-Wert. [IPv4](it_0140.md) und [IPv6](it_0141.md) benötigen unterschiedliche Adresstypen. [HTTP](it_0145.md) verwendet Namen im Anwendungskontext. Ein [Service](it_0119.md) muss nach der Auflösung trotzdem erreichbar sein.

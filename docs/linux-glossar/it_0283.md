# README

## 1. Kurzbeschreibung

Eine README ist ein Einstiegsdokument für ein Projekt oder Verzeichnis. Sie hilft dir, Zweck, Voraussetzungen und den passenden nächsten Schritt zu finden. In einem Repository heißt sie häufig `README.md`, wobei die Endung für Markdown steht.

## 2. Was bedeutet der Begriff?

Die [GitHub-Dokumentation zu READMEs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes) nennt typische Inhalte wie Zweck, Einstieg und Hilfe. Die [GitLab-Referenz zu Repository-Dateien](https://docs.gitlab.com/user/project/repository/files/) beschreibt die Anzeige von README-Dateien auf dieser Plattform. Automatische Darstellung und Auswahl hängen vom jeweiligen Dienst und Dateipfad ab.

## 3. Einfacher Vergleich aus dem Alltag

Eine Orientierungstafel am Eingang zeigt, wo die wichtigsten Dinge liegen. Eine README übernimmt diese Aufgabe für den Projektordner. Sie kann in die Tiefe verlinken. Ihre Informationen müssen stimmen, weil viele Leser weder den Quellcode noch frühere Entscheidungen kennen.

## 4. Wie funktioniert das?

Beginne mit dem Nutzen des Projekts und ordne seine Zielgruppe ein. Beschreibe den kleinsten sinnvollen Einstieg, einschließlich notwendiger Voraussetzungen. Verweise anschließend zu vertiefenden Informationen, etwa Bedienung, Konfiguration, Beitragsregeln und Lizenz. Relative Links können innerhalb des Repositories mit dem jeweiligen Branch aufgelöst werden.

Ein Unterverzeichnis kann eine eigene README bekommen. Dann sollte deutlich werden, welche Informationen nur für dieses Modul gelten und wie du zur Projektübersicht zurückkommst.

## 5. Wo begegnet mir das unter Linux?

Unter Linux kannst du die Datei als Klartext lesen oder von einem Markdown-fähigen Werkzeug darstellen lassen. In Quellen und Paketdokumentation können verschiedene README-Dateien liegen. Ein Verweis auf einen Entwicklungsbefehl im Quellrepository ist nicht automatisch eine Anleitung für das systemweit installierte Paket.

## 6. Konkretes Beispiel Schritt für Schritt

Gedankenbeispiel. Eine fiktive Anwendung für persönliche Notizzettel erhält eine README.

1. Der erste Absatz erklärt, dass die Anwendung Textnotizen lokal sammelt.
2. Der Einstieg nennt die unterstützte Umgebung und verlinkt eine Anleitung, die mit einem eigenen Testdokument beginnt.
3. Ein Abschnitt zur Mitarbeit verweist auf getrennte Hinweise zu Tests und Fehlermeldungen.
4. Vor einer Veröffentlichung prüft das Team die Pfade aus Sicht eines frischen Checkouts und liest die Startanleitung mit einer Testumgebung nach.

Damit kann eine neue Leserin die passende Route wählen, ohne zuerst die Projektstruktur zu kennen.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Installationsanleitung beschreibt den Vorgang bis zu einem überprüfbaren Ergebnis. Ein Änderungsprotokoll nennt Unterschiede zwischen Versionen. Die README kann auf beide verweisen und ihren eigenen Schwerpunkt auf die Orientierung legen.

## 8. Häufige Missverständnisse

Der Dateiname verspricht weder aktuelle Angaben noch einen funktionierenden Startweg. Selbst wenn der Hostingdienst die Datei schön rendert, können lokale Linkpfade oder Anweisungen fehlerhaft sein.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Nutze Befehle nur mit ihren Voraussetzungen und erkennbaren Auswirkungen. Halte Geheimnisse aus Beispielen heraus. Bei Änderungen an Dateipfaden prüfe relative Links mitsamt Groß- und Kleinschreibung.

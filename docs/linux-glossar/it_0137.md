# Exit-Code

## 1. Kurzbeschreibung

Ein Exit-Code ist eine numerische Rückmeldung eines beendeten Programms an den aufrufenden Zusammenhang. Null steht üblicherweise für erfolgreichen Abschluss. Andere Werte können Fehler oder andere dokumentierte Ergebnisse kennzeichnen. Für die genaue Bedeutung muss die Schnittstelle des betreffenden Programms bekannt sein; sichtbarer Ausgabetext und Exit-Code sind getrennte Informationen.

## 2. Was bedeutet der Begriff?

Ein Programm kann beim Ende einen Status zurückgeben, den beispielsweise eine Shell oder ein Elternprozess auswertet. Damit können weitere Schritte davon abhängen, ob die vorherige Aufgabe wie vorgesehen abgeschlossen wurde. Dieser Status ist kein gewöhnlicher Funktionsrückgabewert innerhalb derselben Programmiersprache.

Die [Python-Referenz zum Unterprozess-Rückgabecode](https://docs.python.org/3.13/library/subprocess.html#subprocess.CompletedProcess.returncode) beschreibt null als typischen Erfolg. Das Katalogbeispiel sagt entsprechend vorsichtig „meistens“. Eine konkrete Anwendung kann mehrere unterschiedliche Zustände definieren. Die Bedeutung entsteht durch diese Vereinbarung, nicht allein durch die Größe der Zahl.

## 3. Einfacher Vergleich aus dem Alltag

Eine Arbeitsstation meldet nach einem Auftrag eine vereinbarte Kennziffer zurück: erledigt, nichts Passendes gefunden oder Ausführung gescheitert. Die nächste Station kann darauf reagieren, ohne einen langen Bericht frei interpretieren zu müssen.

Das erklärt die maschinenlesbare Rückmeldung. Die Grenze: Die Kennziffer ist keine unabhängige Qualitätskontrolle. Ein Programm kann einen ungeeigneten Status liefern oder trotz null ein fachlich falsches Ergebnis berechnen. Ohne dokumentierte Zuordnung weiß die nächste Station außerdem nicht, was eine bestimmte Zahl bedeutet.

## 4. Wie funktioniert das?

Der Elternprozess kann das Ende eines Kindes abwarten und dessen Status erhalten. Werkzeuge stellen diesen Status in ihrer eigenen Schnittstelle dar. Bei Python enthält etwa das Ergebnis von `subprocess.run` ein `returncode`-Attribut. Mit `check=False` wird ein nichtnuller Wert nicht allein deshalb zu einer Python-Ausnahme.

Ein Beispiel für eine wichtige Mehrdeutigkeit ist `grep`. Der [POSIX-Standard](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/grep.html) unterscheidet ausgewählte Zeilen, keine ausgewählten Zeilen und Fehler. „Kein Treffer“ ist ein sinnvolles Suchergebnis und nicht automatisch ein Programmdefekt. Aufrufender Code sollte solche vorgesehenen Ergebnisse gezielt behandeln.

## 5. Wo begegnet mir das unter Linux?

Shell-Skripte und Automatisierung können anhand von Statuswerten weitere Schritte wählen. Die [POSIX-Shell-Spezifikation](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html) beschreibt entsprechende Auswertungsregeln. Nachfolgende Befehle können einen zuvor betrachteten Status jedoch ersetzen; der relevante Wert muss zum richtigen Zeitpunkt berücksichtigt werden.

Bei Pipelines sind zusätzliche Regeln wichtig. Der Gesamtstatus ist nicht automatisch eine vollständige Liste der Ergebnisse aller beteiligten Programme. Auch eine lange sichtbare Ausgabe kann mit einem Fehlerstatus enden, während ein erfolgreiches Programm gar nichts ausgeben muss.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Zwei eigene Kindprozesse prüfen ausschließlich eine feste Zeichenkette. Ihre selbst definierte Vereinbarung lautet: null für enthaltenen Suchtext, eins für fehlenden Suchtext.

```python
import subprocess
import sys

kindcode = (
    "import sys\n"
    "text = 'Eigene Probe'\n"
    "sys.exit(0 if sys.argv[1] in text else 1)\n"
)
for suchtext, erwartet in [("Probe", 0), ("Fehlt", 1)]:
    ergebnis = subprocess.run(
        [sys.executable, "-c", kindcode, suchtext],
        capture_output=True,
        text=True,
        timeout=5,
        check=False,
    )
    assert ergebnis.returncode == erwartet
    assert ergebnis.stdout == ""
    assert ergebnis.stderr == ""
    print(f"{suchtext}: {ergebnis.returncode}")
```

Geprüfte Ausgabe:

```text
Probe: 0
Fehlt: 1
```

Beide Kindprogramme arbeiten nach ihrer dokumentierten Vereinbarung. Der zweite Status eins wird erwartet und geprüft, nicht als misslungener Test verschwiegen. Die Kinder erzeugen selbst keinen Ausgabetext. Der äußere Prüflauf endet erfolgreich. Das Beispiel führt `grep` nicht aus und sendet keine Signale.

## 7. Abgrenzung zu ähnlichen Begriffen

Standardausgabe transportiert Daten oder Meldungen. Standardfehlerausgabe ist ein weiterer Kanal. Ein Exit-Code ist die Abschlussrückmeldung. Eine Python-Exception ist nochmals ein anderer Mechanismus. Bei signalbedingtem Prozessende verwendet Python auf POSIX-Systemen negative `returncode`-Werte; das ist eine Darstellungsregel dieser Schnittstelle und kein universeller normaler Exit-Code aller Werkzeuge.

## 8. Häufige Missverständnisse

Nichtnull bedeutet nicht immer Bug. Null beweist nicht jedes gewünschte fachliche Ergebnis. Ebenso darf eine Fehlermeldung auf einem Ausgabekanal nicht ohne Kenntnis der Anwendung mit einem bestimmten Status gleichgesetzt werden. Die drei Informationen sollten gemeinsam betrachtet werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lies die dokumentierten Statuswerte und behandle erwartete Sonderfälle ausdrücklich. Prüfe bei eigenen Werkzeugen sowohl Ergebnisdaten als auch Abschlussstatus. Das Beispiel startet nur eigene kurzlebige Prozesse und liest keine fremden Dateien, Prozesslisten oder Systemprotokolle.

## 10. Verwandte Begriffe

Ein [Prozess](it_0115.md) liefert den Abschlussstatus. [subprocess](it_0101.md) macht ihn Python zugänglich. Eine [Pipe](it_0130.md) kann mehrere Prozesse verbinden. Eine [Exception](it_0091.md) ist von einem bloß nichtnullen Unterprozessstatus zu unterscheiden.

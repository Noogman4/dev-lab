# Home-Verzeichnis

## 1. Kurzbeschreibung

Das Home-Verzeichnis ist das einem Benutzer zugeordnete persönliche Verzeichnis. Dort können eigene Dokumente und benutzerspezifische Einstellungen liegen. Ein Pfad wie `/home/sven` ist auf Linux-Desktops üblich, aber nicht vorgeschrieben. Welcher Ort tatsächlich zu einem Konto gehört und welche Zugriffe möglich sind, hängt von dessen Einrichtung ab.

## 2. Was bedeutet der Begriff?

„Home“ bedeutet Zuhause. Technisch ist damit hier eine Zuordnung zwischen einem Benutzerkonto und einem Verzeichnispfad gemeint. Die [Linux-Handbuchseite zum passwd-Format](https://man7.org/linux/man-pages/man5/passwd.5.html) beschreibt unter anderem ein Feld für das Benutzerverzeichnis. Das erklärt die Kontenzuordnung, ohne vorauszusetzen, dass alle Konten ausschließlich über dieselbe lokale Datei verwaltet werden.

Die Umgebungsvariable `HOME` kann einem gestarteten Programm einen entsprechenden Pfad mitteilen. Sie ist trotzdem eine Eingabe aus der Prozessumgebung und kein unfehlbarer Nachweis über Eigentümerschaft oder Zugriffsrechte. Eine Anwendung muss unterscheiden, ob sie eine mitgegebene Einstellung oder die konfigurierte Kontenzuordnung benötigt.

## 3. Einfacher Vergleich aus dem Alltag

Eine Person hat eine persönliche Ablage im Büro. Sie kann gerade in einem anderen Raum arbeiten und trotzdem dieselbe persönliche Ablage behalten. Der Aufenthaltsort und der zugeordnete Ablageort sind unterschiedliche Angaben.

So trennt der Vergleich Home und aktuelles Arbeitsverzeichnis. Seine Grenze: Ein Verzeichnis ist nicht automatisch privat, nur weil es persönlich zugeordnet ist. Tatsächliche Zugriffsrechte entscheiden mit. Der Ort kann außerdem auf einem anderen Datenträger oder über eine besondere Systemeinrichtung bereitgestellt werden; er ist nicht zwingend ein einzelner lokaler Schrank.

## 4. Wie funktioniert das?

Beim Anmelden oder Starten einer Sitzung werden passende Voraussetzungen für Programme eingerichtet. Viele Werkzeuge kennen eine Abkürzung zum Home-Verzeichnis. In der Shell kann etwa eine unquotierte Tilde am Anfang eines geeigneten Wortes entsprechend expandiert werden. Die [POSIX-Shell-Spezifikation](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html) beschreibt die Regeln dieser Tilde-Ersetzung.

Eine Tilde ist deshalb nicht in jeder Datei oder Programmiersprache automatisch derselbe Platzhalter. Python stellt beispielsweise [Path.home](https://docs.python.org/3.13/library/pathlib.html#pathlib.Path.home) für einen aufgelösten Home-Pfad bereit. Die Dokumentation nennt auch den Fehlerfall einer nicht möglichen Auflösung. Ein Programm sollte also weder einen universellen Pfad zusammensetzen noch jede Auflösung als garantiert behandeln.

## 5. Wo begegnet mir das unter Linux?

Ein Dateimanager kann das persönliche Verzeichnis als Startort anbieten. Anwendungen legen dort häufig benutzerspezifische Daten oder Einstellungen in passenden Unterverzeichnissen ab. Ein Name, der mit einem Punkt beginnt, kann in üblichen Dateimanageransichten ausgeblendet sein. Das ist eine Darstellungsregel und kein Schutz der Inhalte.

Das Katalogbeispiel `/home/sven` ist damit ein plausibles Beispiel, keine festgestellte Eigenschaft des Lesersystems. Auch Root besitzt üblicherweise ein anders gelegenes Home-Verzeichnis. Andere Konten können besondere Pfade oder Einschränkungen haben. Der Kontoname allein ist keine vollständige Bauanleitung für den tatsächlichen Ort.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses Gedankenbeispiel benutzt zwei erfundene Pfade. Es liest weder Benutzerkonten noch persönliche Dateien und verändert kein Verzeichnis.

```text
Zugeordnetes Home: /home/beispiel
Aktuelles Arbeitsverzeichnis: /tmp/eigene-uebung
Relativer Dateiname: probe.txt
Bei einem gewöhnlichen relativen Dateizugriff liegt das Ziel im Arbeitsverzeichnis.
Das Home bleibt davon unabhängig /home/beispiel.
```

Eine Anwendung, die nur `probe.txt` öffnet, verwendet nicht automatisch das Home als Grundlage. Sie braucht einen ausdrücklich passenden Zielpfad oder eine dokumentierte Regel. Ebenso ändert das bloße Bestimmen des Home-Pfades nicht schon das Arbeitsverzeichnis.

Die Pfade sind nur ein Modell. Es wird nicht behauptet, dass sie auf diesem Rechner existieren. Ein tatsächlicher Test persönlicher Daten wäre für diese Unterscheidung unnötig. Der Eintrag führt deshalb weder `Path.home` noch einen Verzeichniswechsel aus.

## 7. Abgrenzung zu ähnlichen Begriffen

Das Wurzelverzeichnis `/` ist die Spitze der betrachteten Dateisystemhierarchie, nicht das persönliche Home. Das aktuelle Arbeitsverzeichnis ist die Basis vieler relativer Pfade. Ein Projektverzeichnis gehört zu einer Aufgabe und muss nicht direkt im Home liegen. Ein Benutzerkonto wiederum umfasst mehr als nur einen Verzeichnispfad.

## 8. Häufige Missverständnisse

Das Home liegt nicht immer unter `/home`. Ein versteckter Ordner ist nicht automatisch verschlüsselt. Auch eine geänderte Variable `HOME` verschiebt keine Dateien und überträgt keine Eigentümerschaft. Das Löschen unbekannter Konfigurationsordner ist deshalb keine folgenlose Aufräumaktion.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Speichere eigene Daten an einem bewusst gewählten Ort und sichere wichtige Inhalte. Vermeide fest eingebaute Benutzernamen in Programmen. Prüfe vor dem Weitergeben persönlicher Verzeichnisse auch versteckte Einstellungen und vertrauliche Daten. Dieser Text greift nicht auf reale Home-Inhalte zu und ändert keine Konten oder Umgebungswerte.

## 10. Verwandte Begriffe

[pathlib](it_0102.md) kann Pfade verarbeiten. Eine [Umgebungsvariable](it_0131.md) kann einen Home-Pfad mitteilen. [Dateirechte](it_0112.md) regeln tatsächliche Zugriffe. [Root](it_0111.md) bezeichnet eine Benutzerrolle und nicht allgemein das persönliche Verzeichnis jedes Benutzers.

# Scope

## 1. Kurzbeschreibung

Scope bedeutet Gültigkeits- oder Sichtbarkeitsbereich eines Namens im Programm. Er bestimmt, welche Bindung verwendet wird, wenn Code auf einen Namen zugreift. Der Begriff beschreibt damit eine Regel für Namensauflösung. Er ist nicht einfach die Speicherstelle oder die Lebensdauer des bezeichneten Objekts.

## 2. Was bedeutet der Begriff?

Zwei Funktionen können jeweils einen lokalen Namen `ergebnis` verwenden, ohne damit zwangsläufig denselben Zustand zu bezeichnen. Auch ein Name innerhalb einer Funktion kann eine gleichnamige äußere Bindung verdecken. Welche Bedeutung beim Zugriff gilt, hängt vom betreffenden Gültigkeitsbereich ab.

Ein Namensraum ist eine Zuordnung von Namen zu Objekten. Der Scope legt fest, welche solchen Zuordnungen an einer Stelle ohne zusätzliche Qualifizierung erreichbar sind. Das [Python-Tutorial zu Scopes und Namensräumen](https://docs.python.org/3.13/tutorial/classes.html#python-scopes-and-namespaces) erklärt diesen Unterschied. „Global“ meint in Python normalerweise den Modulnamensraum, nicht automatisch einen einzigen gemeinsamen Namensraum aller Programme.

## 3. Einfacher Vergleich aus dem Alltag

Zwei Büros können jeweils eine Schublade mit der Aufschrift „Eingang“ besitzen. Wer im einen Büro davon spricht, meint nicht automatisch die Schublade des anderen. Der örtliche Zusammenhang klärt die Bezeichnung.

Die Grenze des Vergleichs: Programmiersprachen besitzen genaue Suchregeln für solche Zusammenhänge. Sie richten sich nicht einfach nach dem zuletzt betretenen Raum oder nach dem direkten Aufrufer einer Funktion. Außerdem kann ein Objekt weiter existieren, obwohl ein bestimmter lokaler Name nicht mehr erreichbar ist.

## 4. Wie funktioniert das?

Für gewöhnliche verschachtelte Python-Funktionen beginnt die Suche nach einem Namen lokal, setzt sich in umschließenden Funktionsbereichen fort und berücksichtigt anschließend den Modulbereich sowie eingebaute Namen. Eine lokale Zuweisung beeinflusst dabei die Einordnung des Namens im gesamten Funktionsblock.

Wird ein als lokal eingeordneter Name vor seiner Bindung benutzt, kann `UnboundLocalError` entstehen. Ist überhaupt keine passende Bindung vorhanden, entsteht ein Namensfehler. Diese Regeln und die ausdrücklich möglichen Änderungen durch `global` oder `nonlocal` erläutert die [Referenz zur Namensauflösung](https://docs.python.org/3.13/reference/executionmodel.html#resolution-of-names). Klassenkörper und weitere Sprachkonstruktionen besitzen Besonderheiten; die vereinfachte Funktionsregel ist keine vollständige Beschreibung aller Python-Bereiche.

## 5. Wo begegnet mir das unter Linux?

Beim Lesen eines Python-Hilfsskripts kann ein gleichnamiger Zähler an mehreren Stellen auftauchen. Vor einer Änderung solltest du feststellen, welcher Bereich tatsächlich gemeint ist. Sonst wird möglicherweise nur ein lokaler Zwischenwert verändert, obwohl du einen gemeinsam verwendeten Zustand erwartet hast.

Scope-Regeln gehören zur jeweiligen Sprache. Eine Bash-Variable und ein lokaler Python-Name werden nicht allein deshalb gleich behandelt, weil beide „Variable“ heißen. Für Linux-Entwicklung ist daher wichtig, den Gültigkeitsbereich innerhalb des gerade verwendeten Programms zu verstehen.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel zeigt einen lokalen und einen gleichnamigen äußeren Wert:

```python
meldung = "außen"

def vorbereiten():
    meldung = "innen"
    nur_lokal = 7
    return meldung, nur_lokal

ergebnis = vorbereiten()
assert ergebnis == ("innen", 7)
assert meldung == "außen"
assert "nur_lokal" not in globals()
print(ergebnis[0])
print(meldung)
```

Die Ausgabe lautet:

```text
innen
außen
```

Die Zuweisung im Körper erzeugt hier eine lokale Bindung. Sie ersetzt die äußere Bindung nicht. Der Rückgabewert kann die berechneten Daten dennoch nach außen transportieren. Die Zusicherung mit `globals` prüft zusätzlich, dass der nur lokal verwendete Name nicht im Modulnamensraum angelegt wurde.

## 7. Abgrenzung zu ähnlichen Begriffen

Der Scope betrifft Sichtbarkeit und Auflösung eines Namens. Ein Namensraum enthält konkrete Zuordnungen. Die Lebensdauer eines Objekts beschreibt etwas anderes: Es kann etwa über einen zurückgegebenen Wert weiterhin erreichbar bleiben. Eine Variable bezeichnet in Python eine Bindung, nicht automatisch einen überall sichtbaren Speicherplatz.

## 8. Häufige Missverständnisse

Gleich geschriebene Namen müssen nicht dieselbe Bindung haben. Eine Zuweisung innerhalb einer Funktion verändert nicht automatisch einen gleichnamigen Modulnamen. Umgekehrt kann eine Funktion auf ein äußeres veränderliches Objekt zugreifen und dessen Inhalt bearbeiten, ohne den äußeren Namen neu zu binden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Bevorzuge klar übergebene Eingaben und ausdrückliche Rückgaben, wenn dadurch Abhängigkeiten verständlicher werden. Vermeide unnötiges Verdecken wichtiger Namen. Das Beispiel erzeugt ausschließlich eigene Bindungen; es verändert keine Prozessumgebung oder Systemeinstellungen.

# Modularisierung

## 1. Kurzbeschreibung

Modularisierung ist die Aufteilung einer Software in überschaubare Teile mit klaren Aufgaben und vereinbarten Schnittstellen. Zusammengehörige Verarbeitung soll verständlich gebündelt werden. Zwischen den Teilen sollen unnötige Abhängigkeiten vermieden werden. Das erleichtert Änderungen und Tests, garantiert aber nicht allein durch zusätzliche Dateien eine gute Struktur oder beliebige Austauschbarkeit.

## 2. Was bedeutet der Begriff?

Die Quelle nennt die Aufteilung in kleinere, austauschbare Teile und einen eigenen Bereich für DNS-Code. Dabei ist wichtig, was dieser Bereich nach außen anbietet und welche Voraussetzungen er benötigt. Eine Datei mit einem passenden Namen kann weiterhin eng mit vielen anderen Teilen verflochten sein.

Das [Python-Tutorial zu Modulen](https://docs.python.org/3.13/tutorial/modules.html) beschreibt die Aufteilung von Definitionen auf Dateien und deren Verwendung über Importe. Das ist eine konkrete Sprachmöglichkeit. Modularisierung als Entwurfsaufgabe ist allgemeiner: Andere Sprachen und Systeme haben andere technische Bausteine, müssen aber ebenfalls Verantwortlichkeiten und Beziehungen klären.

## 3. Einfacher Vergleich aus dem Alltag

Ein Werkzeugkasten besitzt Fächer für zusammengehörige Aufgaben. Jedes Werkzeug hat einen erkennbaren Zweck und einen Griff, über den du es verwendest. Du musst nicht bei jeder Nutzung seinen inneren Aufbau verändern.

Die Grenze: Softwaremodule sind nicht automatisch unabhängig wie lose Werkzeuge. Ein Teil kann intern auf globale Zustände oder andere Komponenten zugreifen. Ein äußerlich passender Ersatz kann sich bei Fehlern oder Seiteneffekten anders verhalten. Ein Name oder ein Steckplatz allein genügt daher nicht als Vertrag.

## 4. Wie funktioniert das?

Zuerst wird eine zusammengehörige Verantwortung festgelegt. Danach wird entschieden, welche Funktionen und Daten andere Teile verwenden dürfen. Die Schnittstelle umfasst neben Parametern und Ergebnissen auch Fehlerfälle und relevante Seiteneffekte. Interne Details sollen nicht unnötig nach außen gelangen.

In Python stellt ein Modul einen eigenen Namensraum bereit. Importieren kann allerdings auch Anweisungen auf Modulebene ausführen. Eine Moduldatei sollte deshalb nicht allein für eine einfache Hilfsfunktion überraschend einen Dienst starten oder fremde Dateien ändern. Die Sprachmechanik verhindert solche Seiteneffekte nicht automatisch.

Austauschbarkeit muss überprüfbar gemeint sein. Zwei Implementierungen brauchen passende Zusagen, nicht nur gleichnamige Funktionen. Auch zyklische Abhängigkeiten können die Struktur erschweren. Ein weiterer Dateiumzug löst das Problem nicht, wenn die tatsächlichen Beziehungen unverändert kreuz und quer verlaufen.

## 5. Wo begegnet mir das unter Linux?

Python-Anwendungen verwenden Module und Pakete, um beispielsweise Verarbeitung, Darstellung und Speicherung zu ordnen. Ein eigenes DNS-Modul könnte fachlich sinnvoll sein, wenn seine Grenzen passen. Dieses Glossar prüft jedoch keine konkrete DNS-Struktur und führt keine Netzwerkabfragen dafür aus.

Bei kleinen Hilfsfunktionen hilft eine schmale Schnittstelle besonders: Sie kann mit selbst erzeugten Eingaben geprüft werden, ohne eine grafische Oberfläche oder einen laufenden Dienst zu starten. Das folgende Beispiel zeigt genau eine solche begrenzte Verantwortung.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Arbeitsordner ausgeführt. Es erzeugt und lädt ausschließlich eine eigene Moduldatei. Die [Python-Dokumentation zu spec_from_file_location](https://docs.python.org/3.13/library/importlib.html#importlib.util.spec_from_file_location) beschreibt die hier verwendete gezielte Dateizuordnung; sie ist keine notwendige Form jedes gewöhnlichen Imports.

```python
import importlib.util
from pathlib import Path
import tempfile

with tempfile.TemporaryDirectory() as ordner:
    datei = Path(ordner) / "titelprobe.py"
    datei.write_text(
        'def normalisiere(text):\n'
        '    ergebnis = text.strip()\n'
        '    if not ergebnis:\n'
        '        raise ValueError("Titel fehlt")\n'
        '    return ergebnis\n',
        encoding="utf-8"
    )
    spec = importlib.util.spec_from_file_location("eigene_titelprobe", datei)
    assert spec is not None and spec.loader is not None
    modul = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(modul)
    assert modul.normalisiere(" Probe ") == "Probe"
    assert modul.normalisiere("\tProbe\n") == "Probe"
    abgelehnt = False
    try:
        modul.normalisiere("   ")
    except ValueError:
        abgelehnt = True
    assert abgelehnt
    print("Normalisiert:", modul.normalisiere(" Probe "))
    print("Leerer Titel abgelehnt:", abgelehnt)
```

Geprüfte Ausgabe:

```text
Normalisiert: Probe
Leerer Titel abgelehnt: True
```

Die definierte Funktion bündelt eine kleine Regel und kann mit verschiedenen Texteingaben verwendet werden. Der Fehlerfall gehört zum beobachteten Vertrag. Das Beispiel prüft keine allgemeine Namensvalidierung, keinen Implementierungsaustausch und keine bestehende Anwendung. Die eigene Datei und gegebenenfalls erzeugte Importdaten werden mit dem temporären Ordner entfernt.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Modul ist ein technischer oder logischer Baustein. Modularisierung ist die bewusste Aufteilung. Architektur betrachtet wesentliche Beziehungen im Gesamtsystem. Ein eigener Prozess oder Dienst ist eine zusätzliche Betriebsgrenze und für ein einzelnes Modul nicht zwingend erforderlich.

## 8. Häufige Missverständnisse

Mehr Dateien bedeuten nicht automatisch weniger Abhängigkeiten. Gleichnamige Funktionen sind nicht zwingend austauschbar. Ein Import muss nicht frei von Seiteneffekten sein. Und das Auslagern einer Funktion beseitigt ihre fachlichen Voraussetzungen nicht.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Wähle Grenzen nach Aufgaben und erwarteten Änderungen. Dokumentiere Ergebnisse, Fehler und Seiteneffekte. Prüfe die öffentliche Schnittstelle mit eigenen Eingaben. Die Übung importiert nur den selbst erzeugten harmlosen Quelltext und installiert kein Paket.

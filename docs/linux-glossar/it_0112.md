# Dateirechte

## 1. Kurzbeschreibung

Dateirechte regeln, welche Zugriffe auf Dateien und Verzeichnisse erlaubt sind. Im klassischen Unix-Modell werden Lesen, Schreiben und Ausführen für Eigentümer, Gruppe und andere Benutzer unterschieden. Die Bedeutung hängt dabei vom Eintragstyp ab. Ein Verzeichnis benötigt andere Betrachtungen als eine gewöhnliche Textdatei.

## 2. Was bedeutet der Begriff?

Die bekannten Kürzel sind `r` für Lesen, `w` für Schreiben und `x` für Ausführen beziehungsweise den Zugriff durch ein Verzeichnis. Die [GNU-Dokumentation zum Aufbau der Modusbits](https://www.gnu.org/software/coreutils/manual/html_node/Mode-Structure.html) erklärt diese Rechte und die drei Benutzerklassen.

Eine Datei besitzt außerdem einen Eigentümer und eine Gruppenzuordnung. Bei der klassischen Prüfung werden die zur Identität passenden Regeln betrachtet; man addiert nicht einfach beliebig günstige Bits aller drei Klassen. Darüber hinaus können unter Linux weitere Mechanismen wie Zugriffslisten oder besondere Prozessberechtigungen relevant sein. Die neun gewöhnlichen Bits sind deshalb eine wichtige Grundlage, aber nicht das vollständige Sicherheitsmodell.

## 3. Einfacher Vergleich aus dem Alltag

In einem Büro gibt es Regeln für persönliche Unterlagen, gemeinsame Teamunterlagen und allgemein zugängliche Informationen. Eine Regel kann Lesen erlauben, ohne Änderungen zu gestatten. Für den Zugang zum Raum kann zusätzlich ein eigener Schlüssel erforderlich sein.

Das erklärt Benutzerklassen und unterschiedliche Zugriffsmöglichkeiten. Der Vergleich endet bei der technischen Auswertung: Ein Dateisystem entscheidet nicht anhand einer informellen Teamzugehörigkeit, sondern anhand konkreter Kennungen und Regeln. Auch ein erlaubter Zugriff auf eine einzelne Datei genügt nicht unbedingt, wenn der Weg durch übergeordnete Verzeichnisse gesperrt ist.

## 4. Wie funktioniert das?

Bei gewöhnlichen Dateien erlaubt `r` das Lesen des Inhalts, `w` dessen Änderung und `x` den Versuch einer direkten Programmausführung. Ein gesetztes Ausführungsbit macht ungeeigneten Inhalt nicht zu einem gültigen Programm.

Bei Verzeichnissen betrifft `r` das Auflisten von Namen, `w` das Verändern von Verzeichniseinträgen und `x` das Durchsuchen beziehungsweise den Zugriff auf benannte Einträge. Die [Linux-Dokumentation zur Pfadauflösung](https://man7.org/linux/man-pages/man7/path_resolution.7.html) erläutert insbesondere die benötigten Suchrechte entlang eines Pfades. Für eine tatsächliche Aktion können mehrere Rechte zusammen erforderlich sein.

## 5. Wo begegnet mir das unter Linux?

Dateirechte werden relevant, wenn eine Anwendung Daten lesen, Ergebnisse speichern oder ein Skript direkt starten soll. Eine Meldung „Zugriff verweigert“ kann sich auf den Inhalt, ein Verzeichnis im Pfad oder weitere Sicherheitsregeln beziehen.

Das Katalogbeispiel nennt `chmod 755 script.sh`. Die drei Ziffern stehen im üblichen oktalen Modell für Eigentümer, Gruppe und andere. Sieben bedeutet Lesen, Schreiben und Ausführen; fünf bedeutet Lesen und Ausführen. Das ist kein geeigneter pauschaler Standard für jede Datei, insbesondere nicht für vertrauliche Daten.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 unter Linux ausgeführt. Es verändert ausschließlich die Rechte einer selbst erzeugten Datei in einem temporären Ordner. Keine bestehenden Datei- oder Verzeichnisrechte werden angefasst.

```python
import os
from pathlib import Path
import stat
import tempfile

with tempfile.TemporaryDirectory() as ordner:
    datei = Path(ordner) / "probe.txt"
    datei.write_text("Eigene Testdaten\n", encoding="utf-8")
    os.chmod(datei, 0o640)
    modus = stat.S_IMODE(datei.stat().st_mode)
    assert modus == 0o640
    assert modus & stat.S_IRUSR
    assert modus & stat.S_IWUSR
    assert modus & stat.S_IRGRP
    assert not modus & stat.S_IWGRP
    assert not modus & stat.S_IRWXO
    print(f"{modus:03o}")
```

Geprüfte Ausgabe:

```text
640
```

Die sechs erlaubt Eigentümer-Lesen und -Schreiben, die vier Gruppen-Lesen und die null keines der drei gewöhnlichen Rechte für andere. Geprüft werden tatsächlich gespeicherte Modusbits. Der Versuch wechselt keine Benutzeridentität und behauptet deshalb keinen praktischen Zugriffstest als ein anderer Benutzer. Besondere Rechte des ausführenden Prozesses werden damit ebenfalls nicht untersucht.

## 7. Abgrenzung zu ähnlichen Begriffen

Dateirechte sind von der Dateieigentümerschaft zu unterscheiden. Ein gesetztes Leserecht bedeutet nicht, dass ein Programm den Inhalt fachlich versteht. Verschlüsselung schützt Daten auf andere Weise und wird durch diese Bits nicht ersetzt. Auch die Möglichkeit, einen Eintrag zu löschen, hängt insbesondere vom umgebenden Verzeichnis ab, nicht nur vom Schreibrecht der Datei.

## 8. Häufige Missverständnisse

Ein Schreibschutz für den Dateiinhalt ist kein allgemeiner Löschschutz. `x` hat bei Verzeichnissen eine andere Bedeutung als bei Programmen. Alle Rechte für alle Benutzer freizugeben ist außerdem keine sachgerechte Diagnose eines unbekannten Zugriffsproblems.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Wähle Rechte passend zum benötigten Zugriff. Prüfe bei Fehlern auch die Verzeichnisse im Pfad. Übe mit eigenen temporären Dateien, bevor du wichtige Daten bearbeitest. Rekursive oder weitreichende Änderungen an bestehenden Verzeichnisbäumen sind kein Bestandteil dieses Beispiels.

## 10. Verwandte Begriffe

[Root](it_0111.md) und besondere Prozessrechte beeinflussen die Zugriffsbetrachtung. [pathlib](it_0102.md) beschreibt Pfade, gewährt aber keine zusätzlichen Rechte. Eine [Exception](it_0091.md) kann einen fehlgeschlagenen Zugriff an Python-Code melden.

# pip

## 1. Kurzbeschreibung

pip ist ein Werkzeug zum Installieren und Verwalten von Python-Distributionen in einer vorgesehenen Umgebung. Die Quelle nennt `pip install requests` als Beispiel. Dieser Aufruf fordert eine Installation an; er garantiert nicht, dass etwas neu heruntergeladen wird oder dass anschließend jede gewünschte Anwendung funktioniert.

## 2. Was bedeutet der Begriff?

Installierbare Distribution und späterer Importname sind zu unterscheiden. pip verarbeitet Anforderungen an Software und ihre Abhängigkeiten. Es ersetzt nicht den eigentlichen Python-Import und ist kein allgemeiner Paketmanager für sämtliche Linux-Systemkomponenten.

Die [offizielle pip-Benutzeranleitung im Projektquelltext](https://raw.githubusercontent.com/pypa/pip/main/docs/html/user_guide.rst) beschreibt den Aufruf über einen ausgewählten Python-Interpreter. `python -m pip` verwendet pip für genau diesen Interpreter. Ein bloßer ausführbarer Name `pip` kann dagegen auf eine andere Umgebung zeigen als erwartet.

## 3. Einfacher Vergleich aus dem Alltag

Ein Beschaffungswerkzeug stellt benötigte Bausteine für eine bestimmte Werkstatt bereit. Es berücksichtigt dabei, welche weiteren Teile ein gewünschter Baustein benötigt. Entscheidend ist, welche Werkstatt tatsächlich beliefert wird.

Die Grenze des Vergleichs: Eine Softwareinstallation kann vorhandene Dateien und Versionen verändern. Abhängigkeiten besitzen genaue Versionsregeln. Das erfolgreiche Bereitstellen von Bausteinen beweist außerdem nicht, dass die fachliche Anwendung richtig zusammengesetzt oder unter allen Bedingungen nutzbar ist.

## 4. Wie funktioniert das?

Eine Installationsanforderung nennt eine Distribution und gegebenenfalls Versionsbedingungen. pip ermittelt passende Kandidaten, berücksichtigt Abhängigkeiten und bereitet die vorgesehenen Dateien für die Zielumgebung vor.

Die [offizielle Beschreibung von pip install](https://raw.githubusercontent.com/pypa/pip/main/docs/html/cli/pip_install.rst) unterscheidet Anforderungsverarbeitung, Abhängigkeitsauflösung, gegebenenfalls Wheel-Erzeugung und Installation. Bereits passende installierte Stände werden nicht allein durch jeden erneuten Aufruf zwangsläufig ersetzt.

Paketquellen und vorhandene Umgebung beeinflussen das Ergebnis. Ein fester Paketname ohne dokumentierten Stand ist deshalb noch keine vollständige reproduzierbare Einrichtung. Auch kann das Verarbeiten von Quellpaketen Build-Schritte ausführen; Installation ist keine allgemeine Garantie rein passiven Dateikopierens.

## 5. Wo begegnet mir das unter Linux?

Python-Projekte dokumentieren ihre zusätzlichen Abhängigkeiten häufig für eine projektbezogene Umgebung. Dort kann pip die benötigten Distributionen bereitstellen. Betriebssystempakete werden dagegen nach den Regeln der Distribution verwaltet.

Ein fehlender Import sollte zuerst anhand von Interpreter, Umgebung und Anforderungen untersucht werden. Ungezielte Installation in irgendeine erreichbare Python-Umgebung kann das eigentliche Problem verfehlen. Eine vom Betriebssystem verwaltete Installation ist nicht automatisch der geeignete Ort für Projektänderungen.

## 6. Konkretes Beispiel Schritt für Schritt

Die folgenden Aufrufe sind ausschließlich erläutert und wurden für diesen Schreibauftrag nicht ausgeführt:

```text
python -m pip --version
python -m pip install requests
```

Zuerst wäre festzustellen, welcher vorgesehene Interpreter mit `python` gemeint ist. Der erste Aufruf würde Informationen zum dort verwendeten pip liefern. Er ist noch keine Installation und auch kein Nachweis, dass `requests` vorhanden ist.

Der zweite Aufruf würde für diese Umgebung die Anforderung an die Distribution `requests` verarbeiten. Je nach Zustand könnte sie bereits erfüllt sein oder Änderungen erfordern. Erfolgsmeldung, tatsächlicher installierter Stand und anschließender funktionaler Import müssten gesondert geprüft werden.

Hier wurde weder dieser Installationsbefehl ausgeführt noch sein Ergebnis behauptet. Die Beispiele erklären nur die Zuordnung von Interpreter und Aktion. Das entspricht der Vorgabe, für die Glossararbeit keine Abhängigkeiten zu installieren oder zu verändern.

## 7. Abgrenzung zu ähnlichen Begriffen

Python ist die Sprache und Laufzeitgrundlage. pip verwaltet installierbare Distributionen. Ein Import verwendet erreichbare Module im Programm. Ein Linux-Paketmanager verwaltet eigene Systempakete. Eine virtuelle Umgebung legt einen geeigneten Projektkontext fest, ist aber nicht selbst pip.

## 8. Häufige Missverständnisse

pip und Python sind nicht dasselbe Werkzeug. Ein erfolgreicher Installationsaufruf garantiert keinen richtigen Import im anderen Interpreter. Installationsname und Importname müssen nicht übereinstimmen. Auch aktualisiert eine einfache wiederholte Anforderung nicht zwangsläufig sämtliche vorhandenen Abhängigkeiten auf neueste Stände.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Verwende die dokumentierte Projektumgebung und nachvollziehbare Quellen. Prüfe gewünschte Versionsänderungen bewusst. Verändere nicht ungeprüft gemeinsam verwendete Installationen. Für dieses Dokument wurden keine Pakete installiert, entfernt, aktualisiert oder aus fremdem Quelltext gebaut.

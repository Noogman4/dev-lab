# Bash

## 1. Kurzbeschreibung

Bash ist eine konkrete Shell und damit ein Befehlsinterpreter mit einer eigenen Programmiersprache. Sie kann interaktive Eingaben verarbeiten und Skripte ausführen. Unter Linux wird sie häufig eingesetzt, ist aber weder mit Linux selbst noch mit jedem Terminalprogramm gleichzusetzen. Andere Shells können andere Regeln und Erweiterungen besitzen.

## 2. Was bedeutet der Begriff?

Der Name steht für „Bourne-Again SHell“ und spielt auf die ältere Bourne-Shell an. Die [offizielle GNU-Einführung](https://www.gnu.org/software/bash/manual/html_node/What-is-Bash_003f.html) beschreibt Bash als Shell des GNU-Systems, die weitgehend mit `sh` kompatibel ist und zusätzliche Funktionen anbietet.

Das Quellbeispiel „Bash führt Shell-Skripte aus“ ist richtig. Entscheidend ist jedoch die vorgesehene Sprache des Skripts. Nicht jede Datei mit Shell-Befehlen benötigt Bash, und nicht jede Bash-Erweiterung funktioniert unter einer anderen Shell. Auch der Dateiname allein erzwingt nicht, dass ein Skript mit der richtigen Implementierung ausgeführt wird.

## 3. Einfacher Vergleich aus dem Alltag

Mehrere Menschen können eine gemeinsame Grundsprache sprechen und daneben unterschiedliche Fachausdrücke oder Dialektformen verwenden. Eine einfache Anweisung verstehen alle, eine besondere Formulierung möglicherweise nur einzelne.

So teilt Bash viele Grundlagen mit anderen Unix-Shells und besitzt zugleich eigene Erweiterungen. Die Grenze des Vergleichs: Eine Shell errät keine unbekannte Schreibweise. Eine unpassende Konstruktion kann sofort fehlschlagen oder anders verarbeitet werden. Ein Skript sollte deshalb seine benötigte Sprache klar festlegen, statt auf ungefähr ähnliche Verständigung zu hoffen.

## 4. Wie funktioniert das?

Bash liest Befehle, erkennt ihre Syntax, verarbeitet Ersetzungen und führt passende Aktionen aus. Das können eingebaute Befehle, Funktionen oder externe Programme sein. Variablen, Bedingungen und Schleifen ermöglichen wiederholbare Abläufe.

Ein Beispiel für zusätzliche Sprachmittel sind Arrays. Die [offizielle Array-Dokumentation](https://www.gnu.org/software/bash/manual/html_node/Arrays.html) erläutert indizierte und assoziative Arrays. Bei einem indizierten Array können mehrere Werte unter demselben Namen über Zahlenindizes angesprochen werden. Eine passende Quotierung ist nötig, damit ein Element mit Leerzeichen bei einer Weitergabe nicht versehentlich in mehrere Wörter zerfällt.

## 5. Wo begegnet mir das unter Linux?

Bash kann in einem Terminal als interaktive Shell laufen oder von einem Werkzeug für ein Skript gestartet werden. Sie muss aber nicht die voreingestellte Shell jedes Benutzers sein. Ein Terminalfenster verrät deshalb nicht allein, welche Sprache gerade Eingaben verarbeitet.

Auch Startdateien hängen vom Aufruf ab. Das [GNU-Kapitel zu Bash-Startdateien](https://www.gnu.org/software/bash/manual/html_node/Bash-Startup-Files.html) unterscheidet unter anderem Login-, interaktive und nichtinteraktive Shells. Insbesondere kann bei einem gewöhnlichen nichtinteraktiven Start `BASH_ENV` eine Datei benennen, deren Inhalt verarbeitet wird. Nur `--norc` zu setzen erklärt daher nicht pauschal alle möglichen Startdateien für jeden Modus.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Prüfskript wurde in einem temporären Ordner ausgeführt. Es startet die vorhandene lokale Bash mit einem festen, selbst geschriebenen Text. Es installiert nichts und verändert keine Benutzerkonfiguration.

```python
import os
import subprocess

skript = '''werte=('Alpha' 'zwei Wörter')
printf '[%s]\\n' "${werte[@]}"
'''
umgebung = os.environ.copy()
umgebung.pop("BASH_ENV", None)
umgebung.pop("ENV", None)
ergebnis = subprocess.run(
    ["/bin/bash", "--noprofile", "--norc", "-c", skript],
    capture_output=True,
    text=True,
    timeout=5,
    check=True,
    env=umgebung,
)
assert ergebnis.stdout == "[Alpha]\n[zwei Wörter]\n"
assert ergebnis.stderr == ""
print(ergebnis.stdout, end="")
```

Geprüfte Ausgabe:

```text
[Alpha]
[zwei Wörter]
```

Das Array enthält zwei Elemente. Die quotierte Form `"${werte[@]}"` übergibt jedes als eigenes Argument; das zweite bleibt trotz Leerzeichen zusammen. Die Assertions prüfen die vollständige Ausgabe und einen leeren Fehlerkanal. Die entfernten Variablen fehlen nur in der Umgebung dieses Unterprozesses; bestehende Einstellungen und Dateien werden nicht geändert.

## 7. Abgrenzung zu ähnlichen Begriffen

„Shell“ ist der Oberbegriff, Bash eine konkrete Ausprägung. `sh` kann auf eine andere Implementierung verweisen. Ein Terminalemulator stellt die textuelle Interaktion bereit. Ein Bash-Skript ist wiederum ein Programmtext, den Bash verarbeitet, nicht eine selbstständige neue Betriebssystemkomponente.

## 8. Häufige Missverständnisse

Eine Datei mit der Endung `.sh` ist kein Beweis für POSIX-Kompatibilität. Ebenso sind Bash-Arrays keine automatisch verfügbaren Sprachmittel jeder Shell. Wer einen Befehl kopiert, muss außerdem zwischen einer angezeigten Eingabeaufforderung und dem tatsächlich auszuführenden Text unterscheiden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Verwende Anleitungen für den tatsächlich gewählten Interpreter. Behandle Quotierung als Teil der Bedeutung, nicht als Dekoration. Starte fremde Skripte nicht allein deshalb, weil sie kurz aussehen. Für Übungen helfen feste eigene Eingaben; das Beispiel führt keine Netzwerk-, Geräte- oder Dienstaktionen aus.

## 10. Verwandte Begriffe

Die [Shell](it_0107.md) erklärt das allgemeine Konzept. Das [Terminal](it_0108.md) kann die Interaktion darstellen. Ein [Array](it_0037.md) beschreibt allgemein eine Sammlung mit Indizes; die konkrete Bash-Ausprägung besitzt eigene Regeln.

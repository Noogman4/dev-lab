# Textfeld

## 1. Kurzbeschreibung

Ein Textfeld ist ein Oberflächenelement, in dem Text eingegeben oder bearbeitet werden kann. Je nach Typ unterstützt es eine oder mehrere Zeilen. Die Quelle nennt eine eingegebene IP-Adresse. Das Feld liefert dabei zunächst Zeichen, nicht automatisch eine gültige Adresse oder eine tatsächlich erreichbare Gegenstelle.

## 2. Was bedeutet der Begriff?

Ein Textfeld besitzt Inhalt und Bearbeitungszustand. Cursor, Auswahl und gegebenenfalls Eingabebeschränkungen helfen bei der Bedienung. Die konkrete Schnittstelle legt fest, wie Text gelesen, eingefügt, entfernt oder gegen Bearbeitung gesperrt wird.

Pythons `ttk.Entry` ist ausdrücklich ein einzeiliges Textelement, wie die [offizielle Entry-Referenz](https://docs.python.org/3.13/library/tkinter.ttk.html#tkinter.ttk.Entry) beschreibt. Mehrzeilige Bearbeitung benötigt einen dafür geeigneten Typ. Die allgemeine Bezeichnung Textfeld erklärt deshalb noch nicht sämtliche verfügbaren Funktionen eines bestimmten Widgets.

## 3. Einfacher Vergleich aus dem Alltag

Ein Formularfeld bietet Platz für eine Angabe. Die Person kann Zeichen eintragen, aber das Papier entscheidet nicht automatisch, ob die Angabe fachlich richtig ist. Ein ausgefülltes Feld und eine geprüfte Angabe sind verschiedene Zustände.

Die Grenze des Vergleichs: Software kann Eingaben sofort prüfen, formatieren oder zurückweisen. Diese Funktionen müssen aber bewusst eingerichtet sein. Ein technisch bearbeitbarer Text ist nicht allein deshalb vertrauenswürdig, nur weil er in einem vorgesehenen Feld steht.

## 4. Wie funktioniert das?

Eine Anwendung liest den Inhalt über die passende Widget-Schnittstelle oder eine gebundene Variable. Danach kann sie ihn nach den Regeln der Aufgabe validieren. Das [offizielle Tk-Handbuch für ttk::entry](https://raw.githubusercontent.com/tcltk/tk/core-8-6-branch/doc/ttk_entry.n) beschreibt Bearbeitung, Inhalt und Validierungsmechanismen.

Für eine IP-Adresse kann ein spezieller Parser verwendet werden. Pythons [ip_address-Referenz](https://docs.python.org/3.13/library/ipaddress.html#ipaddress.ip_address) beschreibt die Erzeugung passender Adressobjekte und die Ausnahme bei ungültigen Eingaben. Das prüft die Adressdarstellung, nicht Erreichbarkeit, Eigentümerschaft oder erlaubte Nutzung.

Validierung und Rückmeldung sollten zusammenpassen. Ein Fehlerhinweis erklärt möglichst konkret das Problem. Automatisches Verändern der Eingabe muss ebenfalls nachvollziehbar bleiben, damit die Person weiß, welcher Wert tatsächlich verwendet wird.

## 5. Wo begegnet mir das unter Linux?

Suchfelder, Dateidialoge und Einstellungsfenster verwenden Textfelder. Eine Anwendung kann darin Adressen, Namen oder Filterausdrücke entgegennehmen. Je nach Aufgabe gelten andere Syntax- und Sicherheitsregeln.

Das Übernehmen eines Texts führt noch keine passende Systemaktion aus. Eine eingegebene IP-Adresse ändert keine Verbindung. Ein Pfad muss nicht existieren. Auch sollte Text nicht ohne geeignete Übergabe als Shell-Code interpretiert werden. Der nachfolgende Verwendungszweck ist entscheidend.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel wurde unter dem vorhandenen virtuellen Bildschirm geprüft. Es bearbeitet nur eigene Texte:

```python
# GUI-Prüfung im virtuellen Bildschirm
import ipaddress
import tkinter as tk
from tkinter import ttk

root = tk.Tk()
root.withdraw()
try:
    feld = ttk.Entry(root)
    feld.insert(0, "192.0.2.1")
    adresse = ipaddress.ip_address(feld.get())
    assert adresse.version == 4
    assert str(adresse) == "192.0.2.1"
    print(adresse)
    feld.delete(0, tk.END)
    feld.insert(0, "keine-ip")
    abgelehnt = False
    try:
        ipaddress.ip_address(feld.get())
    except ValueError:
        abgelehnt = True
    assert abgelehnt and feld.get() == "keine-ip"
    print("Ungültig erkannt")
finally:
    root.destroy()
```

Die Ausgabe lautet:

```text
192.0.2.1
Ungültig erkannt
```

Das Feld speichert beide Texte. Erst der getrennte Parser akzeptiert die erste Darstellung und lehnt die zweite ab. Der ungültige Text bleibt im Feld erhalten; die Ablehnung ist kein automatisches Löschen. Keine der Adressen wird kontaktiert.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Label zeigt Inhalt hauptsächlich an. Ein Button vermittelt eine Aktion. Ein Textfeld ermöglicht Bearbeitung. Ein String ist der Datenwert, kein Widget. Ein Parser beurteilt eine vereinbarte Darstellung und ist nicht dasselbe wie die Eingabeoberfläche.

## 8. Häufige Missverständnisse

Ein ausgefülltes Feld muss nicht gültig sein. Einzeilige und mehrzeilige Widgets sind nicht austauschbar. Ein gültiger Adresstext beweist keine erreichbare Verbindung. Eine verdeckte Passwortdarstellung macht den gespeicherten Inhalt außerdem nicht automatisch geheim oder sicher weiterverarbeitet.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lege erwartetes Format, Länge und Fehlerrückmeldung fest. Unterscheide Rohtext, geprüften Wert und tatsächliche Aktion. Das Beispiel testet programmgesteuerte Bearbeitung und Adresssyntax. Tastatureingabe, Fokus, Layout, Zugänglichkeit und NetMons Felder wurden nicht praktisch abgenommen.

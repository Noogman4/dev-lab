# AppImage

## 1. Kurzbeschreibung

AppImage ist ein Format, in dem Linux-Anwendungen als einzelne ausführbare Datei verteilt werden können. Eine Anwendung bündelt dabei viele ihrer Bestandteile. Der direkte Start hängt trotzdem davon ab, ob das System zur Datei passt.

## 2. Was bedeutet der Begriff?

Die [AppImage-Einführung](https://docs.appimage.org/introduction/concepts.html) beschreibt die Idee, eine Anwendung als eine Datei zu verteilen. Die empfangende Person behält diese Datei meist an einem selbst gewählten Ort. Sie kann die App starten, ohne sie zuvor als distributionsspezifisches Systempaket einzurichten.

## 3. Einfacher Vergleich aus dem Alltag

Eine Reisetasche kann Werkzeug und Material für eine Tätigkeit enthalten. Strom, Arbeitsplatz und Regeln des Gebäudes kommen vom Zielort. So bündelt ein AppImage Anwendungsbestandteile, setzt aber Eigenschaften des Hostsystems voraus. Die Tasche bietet auch keinen Schutz gegen den Zugriff ihres Inhalts auf den Arbeitsplatz.

## 4. Wie funktioniert das?

Die Laufzeit eines Type-2-AppImage versucht, das eingebettete Dateisystem über FUSE schreibgeschützt einzuhängen. Gelingt das, führt sie im eingehängten Abbild den Einstiegspunkt `AppRun` aus. FUSE stellt Dateisysteme über Programme im Benutzerraum bereit. Welche Voraussetzungen gelten, hängt vom konkreten AppImage und vom Hostsystem ab. [AppImage-Architektur](https://docs.appimage.org/reference/architecture.html) · [AppImage-Hilfe zu FUSE](https://docs.appimage.org/user-guide/troubleshooting/fuse.html)

Im Normalfall startet die Anwendung mit den Rechten des aktuellen Nutzers. Eigene Einstellungen oder Ausgaben können daneben im Benutzerprofil landen. Der Ablageort der ausführbaren Datei bestimmt den Ablageort dieser Nutzerdaten daher nicht.

## 5. Wo begegnet mir das unter Linux?

Auf einem Linux-Desktop kann eine AppImage-Datei im Dateimanager oder über eine Shell gestartet werden, wenn ihr Ausführungsrecht und ihre Umgebung das zulassen. Die Architektur muss passen. Auch Startmenüeinträge und automatische Aktualisierungen hängen von der Anwendung oder zusätzlicher Integration ab.

## 6. Konkretes Beispiel Schritt für Schritt

Gedankenbeispiel ohne Download oder Ausführung. Für ein erfundenes Bildprogramm werden Dateien für zwei Architekturen veröffentlicht.

1. Du vergleichst die Architektur deines Rechners mit der angebotenen Variante und prüfst die Herkunft.
2. Du stellst für die ausgewählte Datei fest, ob sie gestartet werden darf. Ein Ausführungsrecht ersetzt keine Prüfung des Inhalts.
3. Würde der Start an FUSE scheitern, wäre die Fehlermeldung ein Hinweis auf eine Laufzeitvoraussetzung. Eine Meldung zur Architektur hätte eine andere Ursache.
4. Bei erfolgreichem Start würdest du mit einem eigenen Testbild prüfen, ob die gewünschte Funktion verfügbar ist.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Debian-Paket wird von der Systempaketverwaltung geführt. Bei AppImage bildet die ausführbare Datei häufig die Einheit, die du selbst ablegst und austauschst. Ein Anwendungsformat mit eigenen Sandbox-Regeln regelt zusätzlich, auf welche Ressourcen die Anwendung zugreifen darf.

## 8. Häufige Missverständnisse

„Portabel“ bedeutet eine vereinfachte Verteilung über passende Systeme hinweg. Ein AppImage für eine andere Prozessorarchitektur startet dadurch nicht. FUSE dient dem Dateizugriff und beschränkt die Rechte der gestarteten Anwendung nicht automatisch.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Arbeite mit einer Datei aus vertrauenswürdiger Herkunft und prüfe die Angaben des Herausgebers. Berücksichtige, dass das Löschen der AppImage-Datei gespeicherte Einstellungen oder Nutzerdaten möglicherweise zurücklässt.

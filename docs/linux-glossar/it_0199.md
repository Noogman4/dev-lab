# Index Datenbank

## 1. Kurzbeschreibung

Ein Datenbankindex ist eine zusätzliche Suchstruktur für gespeicherte Daten. Er kann passende Zeilen schneller auffindbar machen oder bestimmte Sortierarbeit erleichtern. Ob eine konkrete Abfrage davon profitiert, hängt von ihrer Form, den Daten und dem gewählten Ausführungsplan ab. Ein Index ist keine pauschale Beschleunigung jeder Arbeit mit einer Tabelle.

## 2. Was bedeutet der Begriff?

Das Katalogbeispiel nennt einen Index auf `name`. Er kann eine Suche nach Namen unterstützen. Daraus folgt jedoch nicht, dass jede Suche mit diesem Spaltennamen schneller wird. Ein passender Vergleich, eine Suche nach beliebigen enthaltenen Zeichen und eine vollständige Ausgabe aller Zeilen können unterschiedliche Anforderungen haben.

Die [SQLite-Erläuterung zur Abfrageplanung](https://www.sqlite.org/queryplanner.html) zeigt verschiedene Such- und Sortierverfahren mit und ohne Indizes. Die Anwendung beschreibt in SQL das gewünschte Ergebnis. Der Planer wählt einen Weg zur Berechnung. Ein vorhandener Index ist eine mögliche Grundlage dieser Entscheidung, keine Anweisung, ihn immer zu benutzen.

## 3. Einfacher Vergleich aus dem Alltag

Ein Namensregister am Ende eines Buchs führt von einem Namen zu passenden Seiten. Bei der Suche nach einer bestimmten Person kann es viel Blättern ersparen. Willst du dagegen das ganze Buch lesen, hilft der Umweg über das Register kaum.

Die Grenze: Eine Datenbank pflegt ihre Suchstrukturen nach technischen Regeln und kann mehrere Zugriffswege kombinieren. Das Register ist außerdem nicht kostenlos: Bei Änderungen müssen die Angaben aktuell bleiben. Der Vergleich erklärt die Suchidee, keine konkrete Laufzeit oder garantierte physische Anordnung.

## 4. Wie funktioniert das?

Ein Index ordnet ausgewählte Schlüsselwerte einer Suchstruktur zu. Details hängen vom Datenbanksystem und Indextyp ab. Ein mehrspaltiger Index berücksichtigt mehrere Angaben; deren Reihenfolge kann beeinflussen, welche Abfragen er gut unterstützt. Ein Index kann auch zusätzliche Arbeit bei Einfügungen, Änderungen und Löschungen verursachen und Speicher benötigen.

Die [SQLite-Dokumentation zu CREATE INDEX](https://www.sqlite.org/lang_createindex.html) beschreibt die Anlage und verschiedene Varianten. Ein gewöhnlicher Index erlaubt gleiche Werte. Erst eine entsprechende Eindeutigkeitsregel, beispielsweise `UNIQUE`, verhindert bestimmte Duplikate. Die Regeln für NULL müssen dabei gesondert betrachtet werden.

Ein Index definiert keine allgemeine Ausgabereihenfolge. Eine Abfrage, deren Ergebnisreihenfolge wichtig ist, braucht ein geeignetes `ORDER BY`. Sonst können Planänderungen auch eine zuvor zufällig beobachtete Reihenfolge verändern. Ebenso macht ein Index unpassende Datentypen oder ein fehlerhaftes Datenmodell nicht fachlich richtig.

## 5. Wo begegnet mir das unter Linux?

Anwendungen nutzen Datenbanken für Suchfunktionen, Listen und Zuordnungen. Bei wachsendem Datenbestand kann ein passender Index helfen. Der Linux-Kernel entscheidet aber nicht allein anhand eines Spaltennamens, welchen Datenbankindex eine SQL-Abfrage verwendet; das gehört zur Datenbankplanung.

Vor Änderungen an einer Anwendungsdatenbank sind Schema, reale Abfragen und Messungen wichtig. Ein einzelnes langsames Fenster beweist weder einen fehlenden Index noch dessen richtige Ausgestaltung. Dieses Beispiel öffnet keine vorhandenen Anwendungsdateien.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel lief mit Python 3.13 und SQLite 3.46.1 in einem temporären Arbeitsordner. Es legt eigene Speicherdaten und einen nicht eindeutigen Index an.

```python
from contextlib import closing
import sqlite3

with closing(sqlite3.connect(":memory:")) as db:
    db.execute("CREATE TABLE kontakte (id INTEGER PRIMARY KEY, name TEXT)")
    db.executemany("INSERT INTO kontakte VALUES (?, ?)", [
        (1, "Ada"), (2, "Berta"), (3, "Ada")
    ])
    sql = "SELECT id FROM kontakte WHERE name = ? ORDER BY id"
    vorher = db.execute(sql, ("Ada",)).fetchall()
    db.execute("CREATE INDEX kontakte_name ON kontakte(name)")
    angelegt = db.execute(
        "SELECT name FROM sqlite_schema WHERE type = 'index' AND name = ?",
        ("kontakte_name",)
    ).fetchall()
    nachher = db.execute(sql, ("Ada",)).fetchall()
    assert angelegt == [("kontakte_name",)]
    assert vorher == nachher == [(1,), (3,)]
    print("Index angelegt:", angelegt[0][0])
    print("Treffer unverändert:", len(nachher))
```

Geprüfte Ausgabe:

```text
Index angelegt: kontakte_name
Treffer unverändert: 2
```

Geprüft werden Anlage und Ergebnisgleichheit. Der doppelte Name bleibt zulässig. Eine tatsächliche Indexnutzung im Ausführungsplan oder ein Geschwindigkeitsgewinn werden hier nicht gemessen und nicht behauptet. Drei Datensätze wären dafür ohnehin keine belastbare Grundlage.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Primärschlüssel legt die bevorzugte eindeutige Identifikation fest. Ein Fremdschlüssel sichert Beziehungen. Ein Index unterstützt Zugriffswege und kann bei der Durchsetzung bestimmter Bedingungen beteiligt sein. Ein Suchmaschinenindex ist ein verwandtes Wort, aber nicht automatisch dieselbe Struktur wie ein SQL-Index.

## 8. Häufige Missverständnisse

Mehr Indizes bedeuten nicht immer mehr Geschwindigkeit. Ein Index ist nicht immer eindeutig. Seine Existenz beweist keine Benutzung. Und eine beobachtete Ergebnisreihenfolge ersetzt kein ausdrücklich formuliertes Sortierkriterium.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Beurteile Such- und Schreibarbeit zusammen. Prüfe reale Abfragen mit geeigneten Planinformationen und repräsentativen eigenen Testdaten, bevor du produktive Strukturen änderst. Solche Plan- und Leistungstests gehören hier nicht zum ausgeführten Beispiel.

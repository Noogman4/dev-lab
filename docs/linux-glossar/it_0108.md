# Terminal

## 1. Kurzbeschreibung

Ein Terminal ermöglicht textuelle Ein- und Ausgabe zwischen Menschen und Programmen. Auf einem Linux-Desktop ist damit häufig ein Terminalemulator gemeint: eine Anwendung, die diese Arbeitsumgebung in einem Fenster bereitstellt. Darin kann eine Shell laufen. Terminal und Shell sind jedoch verschiedene Bestandteile.

## 2. Was bedeutet der Begriff?

Historisch waren Terminals eigene Geräte mit Tastatur und Anzeige. Ein Terminalemulator bildet entsprechende Funktionen in Software nach. Er nimmt Eingaben entgegen und stellt die Ausgabe eines verbundenen Programms dar. Die Ausgabe besteht nicht nur aus gewöhnlichen Buchstaben: Auch vereinbarte Steuerfolgen können beispielsweise Farben oder die Cursorposition beeinflussen.

Die [offizielle Einführung von GNOME Terminal](https://help.gnome.org/gnome-terminal/introduction.html) beschreibt es als Terminalemulator zum Zugang zu einer Unix-Shell-Umgebung und nennt solche Steuerfolgen ausdrücklich. Die Shell ist dabei das Programm, das Befehle versteht. Das Terminalfenster stellt den Arbeitsraum bereit, interpretiert aber nicht automatisch dieselbe Befehlssprache.

## 3. Einfacher Vergleich aus dem Alltag

Ein Telefon stellt die Verbindung und die Ein- und Ausgabe bereit. Was dein Gesprächspartner mit einer Nachricht anfängt, ist eine andere Aufgabe. Ein anderer Gesprächspartner kann über dasselbe Gerät ganz anders reagieren.

Ähnlich kann ein Terminal mit einer Shell oder einem anderen interaktiven Programm zusammenarbeiten. Die Grenze des Vergleichs: Die Kommunikation besteht hier aus technischen Zeichenströmen und Steuerregeln. Das Terminal bildet Ausgaben aktiv nach diesen Regeln ab. Es ist weder ein bloßer Bildschirmausschnitt noch ein sprachverstehender Gesprächspartner.

## 4. Wie funktioniert das?

Ein grafischer Terminalemulator verbindet seine Fensterdarstellung mit der Ein- und Ausgabe eines Programms, auf Unix-artigen Systemen typischerweise über eine Pseudoterminal-Verbindung. Tasteneingaben können an das verbundene Programm gelangen; dessen Ausgaben werden dargestellt. Manche Tastenkombinationen verarbeitet bereits der Terminalemulator selbst.

[xterm beschreibt sich offiziell als Terminalemulator für das X Window System](https://invisible-island.net/xterm/xterm.html). Seine Dokumentation erläutert die Nachbildung bestimmter Terminaleigenschaften und die Zuordnung von Eingaben zum aktiven Fenster. Solche konkreten Eigenschaften gehören zur jeweiligen Implementierung. Nicht jede Terminalanwendung unterstützt alle gleichen Erweiterungen oder verwendet genau denselben Fenstersystem-Unterbau.

## 5. Wo begegnet mir das unter Linux?

Du öffnest beispielsweise GNOME Terminal oder eine andere Terminalanwendung und erhältst darin eine Shell-Eingabeaufforderung. Nach dem Start eines interaktiven Textprogramms kann stattdessen dieses die Eingaben verarbeiten. Eine textbasierte Vollbildoberfläche ist dabei weiterhin möglich, obwohl keine gewöhnlichen grafischen Buttons angezeigt werden.

Ein Terminalfenster ist nicht erforderlich, damit jeder Hintergrundprozess arbeiten kann. Auch die technische Linux-Konsole ist von einem grafischen Terminalemulator zu unterscheiden. Der Begriff wird im Alltag oft ungenau verwendet; für eine konkrete Hilfsanfrage ist der Name des Terminalprogramms hilfreich.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses Gedankenbeispiel beschreibt eine typische Rollenverteilung. Es wurde keine interaktive Sitzung gestartet und keine bestehende Sitzung verändert.

```text
Ein Terminalemulator zeigt die Ausgabe einer Shell an.
Die Shell wartet auf einen Befehl und erzeugt ihre Eingabeaufforderung.
Du gibst einen Befehl ein, der eine kurze Textmeldung ausgeben soll.
Die Shell verarbeitet den Befehl und lässt die Ausgabe entstehen.
Der Terminalemulator stellt die empfangenen Zeichen dar.
Die Shell meldet sich danach wieder mit ihrer Eingabeaufforderung.
```

Die Zuständigkeiten bleiben getrennt: Die Shell bestimmt die Bedeutung des Befehls, die Terminalanwendung dessen Darstellung. Würde im selben Terminal ein anderes interaktives Programm laufen, könnten identische Tasteneingaben eine andere Bedeutung haben. Das Beispiel ist keine aufgezeichnete Kommunikation und liefert kein Testergebnis für eine konkrete Terminalversion.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Shell verarbeitet eine Befehlssprache. Eine CLI ist allgemein eine textuelle Bedienschnittstelle und kann auch zu einem einzelnen Programm gehören. Eine TUI nutzt einen textorientierten Bildschirmbereich für eine umfangreichere Oberfläche. Ein Terminalemulator kann diese Interaktion darstellen, ohne selbst die fachliche Aufgabe des Programms zu übernehmen.

## 8. Häufige Missverständnisse

Ein schwarzer Hintergrund sagt weder aus, welche Shell läuft, noch welche Rechte du hast. Das Schließen eines Fensters ist außerdem nicht allgemein dasselbe wie das saubere Beenden aller darin beteiligten Arbeiten. Auch ein sichtbarer Text ist kein Beweis, dass eine bestimmte Datei bereits gespeichert wurde.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe vor dem Einfügen von Text, welches Programm gerade Eingaben erwartet. Enthält eingefügter Text Zeilenumbrüche, kann das je nach laufendem Programm unmittelbar eine Verarbeitung auslösen. Nutze für erste Übungen kurze, verstandene Beispiele. Dieser Eintrag verlangt keine Befehle, keine Profiländerung und keine Änderung laufender Prozesse.

## 10. Verwandte Begriffe

Die [Shell](it_0107.md) verarbeitet häufig die eingegebenen Befehle. Eine [CLI](it_0065.md) beschreibt die textuelle Bedienung. Eine [TUI](it_0066.md) kann umfangreiche Ansichten innerhalb eines Terminals bieten. Ein [Event](it_0076.md) hilft allgemein beim Verständnis eingehender Benutzeraktionen.

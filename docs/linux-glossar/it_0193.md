# SQLite

## 1. Kurzbeschreibung

SQLite ist eine SQL-Datenbankbibliothek, die unmittelbar in einer Anwendung arbeiten kann. Ein eigener Datenbankserverprozess ist dafür gewöhnlich nicht nötig. Daten können in einer lokalen Datei oder in besonderen Speicherformen liegen. Der geringe Einrichtungsaufwand bedeutet jedoch nicht, dass SQLite bloß ein Spielzeug oder für jede Aufgabe automatisch die passende Wahl ist.

## 2. Was bedeutet der Begriff?

Die [offizielle SQLite-Beschreibung](https://www.sqlite.org/about.html) erläutert das eingebettete, serverlose Modell. Anwendung und Bibliothek arbeiten im selben Prozesszusammenhang. Das unterscheidet sich von einer typischen Verbindung zu einem getrennten Datenbankdienst.

Die Quellbeschreibung „kleine dateibasierte SQL-Datenbank“ erfasst wichtige Eigenschaften, ist aber zu eng. Die Software hat eine kompakte Bereitstellung und kann trotzdem umfangreiche Funktionen anbieten. Auch ist Dateispeicherung nicht die einzige Möglichkeit. Welche Größen und Belastungen sinnvoll sind, hängt von Aufgabe und Umgebung ab.

## 3. Einfacher Vergleich aus dem Alltag

Ein Arbeitsplatz verfügt über ein eigenes eingebautes Archivsystem. Er braucht nicht für jede Ablage einen entfernten zentralen Schalter. Das kann Wege und Einrichtung vereinfachen.

Die Grenze: Das Archiv besitzt weiterhin genaue Regeln für Daten, Zugriffe und Änderungen. Eingebettet heißt nicht automatisch unbegrenzt parallel oder ohne Speicherbedarf. Außerdem können mehrere Programme auf einen gemeinsamen Bestand zugreifen wollen. Ein lokaler Dateipfad ersetzt deshalb keine passende Planung von Gleichzeitigkeit und Sicherung.

## 4. Wie funktioniert das?

Die Anwendung ruft Funktionen der Bibliothek auf. SQLite verarbeitet SQL-Anweisungen und verwaltet den gewählten Bestand. Die [Hinweise zu geeigneten Einsatzgebieten](https://www.sqlite.org/whentouse.html) beschreiben Stärken und Grenzen gegenüber einem getrennten Client-Server-System.

Eine bekannte Hauptdatei ist nicht in jedem Betriebszustand die gesamte relevante Speicherung. Die [WAL-Dokumentation](https://www.sqlite.org/wal.html) beschreibt einen Modus mit zusätzlichen Dateien und anderen Abläufen für Änderungen. Eine laufende Datenbank darf deshalb nicht ohne Kenntnis des Verfahrens wie ein beliebiger unveränderter Einzeltext behandelt werden.

Auch Transaktionen und Verbindungen haben eigene Lebensdauern. Das Schließen einer Verbindung ist von der vorherigen Übernahme einer Änderung zu unterscheiden. Ein Verbindungsobjekt allein sagt nicht, ob eine fachliche Operation bereits erfolgreich abgeschlossen wurde.

## 5. Wo begegnet mir das unter Linux?

Desktopprogramme und lokale Werkzeuge können SQLite für Einstellungen oder andere strukturierte Daten nutzen. Ob eine bestimmte Anwendung es verwendet, muss allerdings geprüft werden. Der Begriff liefert keine Aussage über einen tatsächlichen Speicherort im vorliegenden Projekt.

Die [SQLite-Dokumentation zu In-Memory-Datenbanken](https://www.sqlite.org/inmemorydb.html) beschreibt außerdem `:memory:`. Gewöhnliche getrennte Verbindungen mit diesem Namen besitzen getrennte private Bestände. Andere ausdrücklich gewählte Formen können andere Regeln haben. Das folgende Beispiel gilt nur für die gezeigten normalen Verbindungen.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Arbeitsordner ausgeführt. Es erzeugt zwei eigene Datenbanken nur im Speicher, ohne Anwendungsdateien zu öffnen.

```python
from contextlib import closing
import sqlite3

with closing(sqlite3.connect(":memory:")) as erste:
    erste.execute("CREATE TABLE probe (wert TEXT)")
    erste.execute("INSERT INTO probe VALUES (?)", ("eigene Daten",))
    erste.commit()
    assert erste.execute("SELECT wert FROM probe").fetchall() == [("eigene Daten",)]
    with closing(sqlite3.connect(":memory:")) as zweite:
        tabellen = zweite.execute(
            "SELECT name FROM sqlite_schema WHERE type = 'table' AND name = ?", ("probe",)
        ).fetchall()
        assert tabellen == []
        print("Erste Datenbank:", erste.execute("SELECT COUNT(*) FROM probe").fetchone()[0])
        print("Zweite Datenbank:", len(tabellen))
```

Geprüfte Ausgabe:

```text
Erste Datenbank: 1
Zweite Datenbank: 0
```

Der erste Bestand enthält einen eigenen Eintrag. Die zweite Verbindung besitzt diese Tabelle nicht. Das zeigt die Trennung dieser In-Memory-Verbindungen, keine Beschädigung oder fehlgeschlagene gemeinsame Nutzung. WAL, Dateispeicherung und parallele Schreiblast werden hier nicht getestet.

## 7. Abgrenzung zu ähnlichen Begriffen

SQL ist die verwendete Sprache, SQLite eine bestimmte Implementierung. Ein Datenbankserver ist ein anderes Bereitstellungsmodell. Eine gewöhnliche Konfigurationsdatei kann ebenfalls Einstellungen enthalten, besitzt aber nicht allein deshalb SQL- und Transaktionsfunktionen. Ein Python-Verbindungsobjekt ist wiederum nur ein Zugang zum gewählten Bestand.

## 8. Häufige Missverständnisse

Serverlos heißt nicht funktionslos. Ein Dateiname beweist keine alleinige Ein-Datei-Betriebsform. Zwei gewöhnliche `:memory:`-Verbindungen sind auch nicht automatisch derselbe Bestand. Beispiele anderer SQL-Systeme müssen schließlich wegen eigener Regeln nicht unverändert passen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Wähle das System nach tatsächlichen Anforderungen. Nutze dokumentierte Verfahren für Sicherung und gleichzeitige Zugriffe. Der Versuch verändert keine vorhandenen Datenbanken, SQLite-Versionen, Dienste oder Paketbestände und ist keine allgemeine Leistungs- oder Ausfallsicherheitsabnahme.

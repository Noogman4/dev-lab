# Dokumentation

## 1. Kurzbeschreibung

Dokumentation erklärt, wie Menschen Software verstehen, einsetzen oder weiterentwickeln können. Sie beantwortet Fragen zum Einstieg, zu konkreten Aufgaben, zu einzelnen Funktionen und zu den Gründen für bestimmte Entscheidungen.

## 2. Was bedeutet der Begriff?

Eine README kann einen ersten Überblick geben. Im Betrieb braucht dieselbe Anwendung möglicherweise eine Referenz zu Einstellungen und eine Anleitung zur Datenübernahme. [Diátaxis](https://diataxis.fr/) beschreibt vier Formen mit unterschiedlichen Zielen. Dazu gehören Lernanleitungen, Aufgabenanleitungen, Referenz und erklärende Texte. Die [GitHub-Dokumentation zur README](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes) nennt typische Einstiegsinformationen.

## 3. Einfacher Vergleich aus dem Alltag

Ein Stadtplan, eine Wegbeschreibung und die Geschichte eines Viertels helfen bei unterschiedlichen Fragen. Bei Software kann dieselbe Faktenlage mehrere Darstellungen brauchen. Ein Befehl in einer Referenz lässt sich etwa schnell nachschlagen, während eine Einführung seine Verwendung im Zusammenhang zeigt.

## 4. Wie funktioniert das?

Gute Dokumentation benennt zuerst die Situation des Lesers. Wer einen Backup-Pfad sucht, braucht die Einstellung, ihren Standardwert und ihre Wirkung. Wer zum ersten Mal eine Sicherung einrichtet, braucht eine sichere Reihenfolge und ein Beispiel mit erwarteten Ergebnissen.

Versionsbezug ist wichtig. Eine Option kann später eingeführt oder umbenannt worden sein. Die Dokumentation sollte erkennen lassen, für welche Version eine Aussage gilt und wie sich die tatsächliche Umgebung prüfen lässt.

## 5. Wo begegnet mir das unter Linux?

Unter Linux findest du Dokumentation etwa in Manpages, Projekt-Webseiten, Paketdateien und eingebauten Hilfedialogen. Welche Quelle passt, hängt vom Ziel ab. Für eine installierte Version ist eine mitgelieferte Referenz häufig näher am lokalen Stand als die neuste allgemeine Webseite.

## 6. Konkretes Beispiel Schritt für Schritt

Gedankenbeispiel. Ein fiktives Notizprogramm erhält eine Sicherungsfunktion.

1. Die README sagt, dass das Programm Notizen lokal speichert, und verlinkt den Einstieg.
2. Eine Anleitung erklärt, wie man eine selbst angelegte Testnotiz sichert und testweise wieder öffnet.
3. Die Referenz nennt den voreingestellten Speicherort und den zulässigen Wert der Pfadeinstellung.
4. Ein erklärender Text beschreibt, warum Konfiguration und Nutzerdaten verschiedene Lebenszyklen haben.

Leser können die jeweils passende Ebene erreichen. Weder die Referenz noch die Einführung muss alle anderen Teile wiederholen.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Spezifikation formuliert verbindliche Anforderungen an eine Schnittstelle. Eine Anleitung erklärt ein mögliches Vorgehen. Kommentare im Quellcode halten oft lokale Zusammenhänge fest. Diese Texte erfüllen jeweils einen anderen Zweck.

## 8. Häufige Missverständnisse

Länge und Vollständigkeit sind verschiedene Eigenschaften. Ein kurzer, präziser Hinweis kann eine konkrete Frage abdecken. Ein Beispiel kann trotz korrekter Syntax irreführen, wenn erwartete Voraussetzungen oder Auswirkungen fehlen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe Befehlsbeispiele mit begrenzten eigenen Daten und kennzeichne nicht ausgeführte Beispiele. Aktualisiere die betroffene Erklärung zusammen mit der geänderten Funktion. Besonders wichtig sind sichtbare Hinweise auf irreversible Schritte.

## 10. Verwandte Begriffe

[Config](it_0228.md) braucht häufig eine Referenz zu gültigen Werten. [Test](it_0246.md) kann Aussagen eines Beispiels praktisch prüfen. [Version](it_0035.md) bindet Angaben an den passenden Stand.

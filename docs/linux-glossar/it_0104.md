# Linux

## 1. Kurzbeschreibung

Linux bezeichnet im engeren technischen Sinn einen Betriebssystemkern. Dieser Kernel verwaltet grundlegende Ressourcen und vermittelt zwischen Programmen und Hardware. Im Alltag meint „Linux“ häufig ein vollständiges Betriebssystem, das diesen Kernel zusammen mit vielen weiteren Komponenten verwendet. Welche Bedeutung gemeint ist, ergibt sich aus dem Zusammenhang.

## 2. Was bedeutet der Begriff?

Der Kernel ist der zentrale, besonders privilegierte Teil eines Betriebssystems. Ein nutzbarer Arbeitsplatz benötigt zusätzlich etwa Systemprogramme, Bibliotheken und Anwendungen. Eine Distribution stellt solche Bestandteile in einer zusammengehörigen Form bereit.

Die [offizielle Kernel-Einführung](https://www.kernel.org/doc/html/latest/admin-guide/README.html) beschreibt Linux als Unix-artiges System mit Funktionen wie Mehrprozessbetrieb, Speicherverwaltung und Netzwerkunterstützung. Die [Debian-Projektübersicht](https://www.debian.org/intro/about) unterscheidet den Kernel von den übrigen Programmen des Betriebssystems. Diese Trennung erklärt, weshalb zwei „Linux-Systeme“ trotz verwandtem Kern sehr unterschiedliche Oberflächen und Verwaltungswerkzeuge haben können.

## 3. Einfacher Vergleich aus dem Alltag

Bei einem Auto sorgt der Motor für einen zentralen Teil der Funktion. Ein fahrbereites Fahrzeug benötigt aber auch weitere Baugruppen, Bedienelemente und eine passende Zusammenstellung. Unterschiedliche Fahrzeuge können verwandte Motoren verwenden und trotzdem verschieden zu bedienen sein.

Der Vergleich hilft, Kernel und vollständiges System auseinanderzuhalten. Er bildet die technischen Aufgaben jedoch nicht genau ab: Ein Kernel treibt nicht einfach nur etwas an. Er entscheidet unter anderem über Ressourcennutzung, Schutzgrenzen und die Bearbeitung bestimmter Anfragen. Zudem können Softwarekomponenten in anderer Weise austauschbar sein als Autoteile.

## 4. Wie funktioniert das?

Anwendungen laufen üblicherweise außerhalb des Kernels. Wenn sie bestimmte Leistungen benötigen, etwa Dateizugriffe oder Netzwerkkommunikation, nutzen sie dafür vorgesehene Schnittstellen. Der Kernel verarbeitet solche Anforderungen innerhalb seiner Zuständigkeit und arbeitet dafür mit Treibern und anderen Kernkomponenten zusammen.

Mehrere Programme teilen sich dabei Prozessorzeit und Speicher. Diese gemeinsame Nutzung muss organisiert werden; ein einzelnes Anwendungsfenster erledigt das nicht selbst für den gesamten Rechner. Welche Hardware und Funktionen verfügbar sind, hängt unter anderem von Kernelversion, Konfiguration und Treibern ab. Der Name Linux allein garantiert daher keine konkrete Geräteunterstützung.

## 5. Wo begegnet mir das unter Linux?

Auf einem Desktop kann Linux unter einer grafischen Umgebung arbeiten, ohne dass du ständig den Kernel bemerkst. In einem Terminal bedienst du zunächst Programme wie eine Shell. Auf einem Server kann ein System auch ohne grafische Desktopumgebung sinnvoll nutzbar sein.

Das Katalogbeispiel Zorin OS passt zur weiteren Alltagsbedeutung. Die [offizielle Zorin-OS-Seite](https://zorin.com/os/) nennt Ubuntu und Linux als Grundlage. Zorin OS ist also kein bloß umbenannter Kernel, sondern ein zusammengestelltes Betriebssystem mit weiteren Komponenten. Daraus folgt keine Aussage darüber, welches System auf dem Rechner eines Lesers installiert ist.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses Gedankenbeispiel ordnet die Bestandteile einer alltäglichen Aufgabe ein. Es wurde nicht als Systemversuch ausgeführt; es liest keine realen Dateien und verändert keine Installation.

```text
Du wählst im Texteditor eine eigene Textdatei zum Öffnen aus.
Der Editor organisiert Bedienung und Textdarstellung.
Bibliotheken und Systemschnittstellen vermitteln den Dateizugriff.
Der Kernel bearbeitet die zugehörigen Anforderungen.
Dateisystem- und Gerätetreiber wirken am tatsächlichen Zugriff mit.
Der Editor erhält Daten oder eine Fehlermeldung und reagiert darauf.
```

Die Schritte zeigen Verantwortlichkeiten, keine vollständige technische Ablaufspur. Zwischenspeicher können beispielsweise bewirken, dass nicht bei jedem Lesen erneut ein physischer Datenträger angesprochen wird. Auch ein Dialog zur Dateiauswahl ist eine Leistung der Oberfläche und nicht selbst der Kernel. Für eine echte Diagnose müsste man die konkrete Umgebung und die genaue Fehlermeldung untersuchen.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Distribution bündelt den Kernel mit weiteren Bestandteilen und eigenen Entscheidungen zur Auslieferung. Eine Desktopumgebung stellt eine grafische Arbeitsumgebung bereit. Eine Anwendung löst eine bestimmte Nutzeraufgabe. Unix ist außerdem nicht einfach ein anderer Name für jede Linux-Distribution; historische Herkunft, Schnittstellenähnlichkeit und konkrete Systembezeichnung müssen unterschieden werden.

## 8. Häufige Missverständnisse

Linux bedeutet nicht „nur Kommandozeile“. Eine grafische Oberfläche ist ebenso möglich. Freie Verfügbarkeit von Quellcode bedeutet auch nicht, dass jedes Gerät ohne zusätzliche Voraussetzungen funktioniert. Ebenso ist „kostenlos“ keine vollständige Erklärung freier Software: Nutzungsrechte und Lizenzbedingungen sind von einem Verkaufspreis zu unterscheiden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Nenne bei einer Hilfsanfrage die konkrete Distribution und relevante Versionen, statt nur „Linux“ zu schreiben. Verwende Anleitungen passend zu diesem System. Ein Befehl für eine bestimmte Paketverwaltung ist keine allgemeine Linux-Anweisung. Dieser Eintrag verlangt weder Kerneländerungen noch Installationen oder privilegierte Befehle.

## 10. Verwandte Begriffe

Eine [GUI](it_0064.md) kann den grafischen Zugang ermöglichen. Eine [CLI](it_0065.md) ist eine textbasierte Bedienschnittstelle. Eine [Runtime](it_0031.md) gehört zu den Voraussetzungen bestimmter Anwendungen und ist vom darunterliegenden Betriebssystemkern zu unterscheiden.

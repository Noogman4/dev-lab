# Type Hint

## 1. Kurzbeschreibung

Ein Type Hint ist eine Typangabe im Python-Code. Er beschreibt beispielsweise, welche Art von Argument eine Funktion erwartet und welchen Ergebnistyp sie liefern soll. Menschen und zusätzliche Prüfwerkzeuge können diese Angaben nutzen. Python erzwingt dadurch allein keine entsprechende Typkontrolle beim Aufruf.

## 2. Was bedeutet der Begriff?

„Hint“ bedeutet Hinweis. Bei `def add(a: int, b: int) -> int` stehen hinter den Parametern Hinweise auf ganze Zahlen; der Pfeil beschreibt den erwarteten Rückgabetyp. Solche Angaben heißen auch Annotationen. Auch Variablen können annotiert werden.

Die [Einführung des offiziellen typing-Moduls](https://docs.python.org/3.13/library/typing.html) sagt ausdrücklich, dass die Python-Laufzeit Funktions- und Variablenannotation nicht erzwingt. Ein Werkzeug zur statischen Typprüfung untersucht dagegen den Code anhand solcher Angaben, ohne dazu jeden vorgesehenen Programmablauf ausführen zu müssen. Ob ein Projekt ein solches Werkzeug verwendet, ist eine zusätzliche Entscheidung.

## 3. Einfacher Vergleich aus dem Alltag

Auf einem Ablagefach steht „Rechnungen“. Die Beschriftung hilft Menschen, Unterlagen richtig einzuordnen. Sie hindert aber niemanden mechanisch daran, eine Postkarte hineinzulegen.

Entsprechend macht `betrag: int` eine Absicht sichtbar, baut jedoch keine automatische Laufzeitsperre ein. Die Grenze des Vergleichs: Ein Typprüfer kann Beziehungen zwischen vielen Stellen im Code systematisch untersuchen, während ein einfaches Schild das nicht kann. Trotzdem beweist auch eine bestandene Typprüfung nicht die fachliche Richtigkeit aller Berechnungen.

## 4. Wie funktioniert das?

Die Typangabe ergänzt die Funktionsdefinition. Ein Prüfwerkzeug kann beispielsweise einen Aufruf mit einer Zeichenkette beanstanden, wenn eine ganze Zahl erwartet wird. Python kann denselben Aufruf zunächst zulassen; erst die tatsächlich ausgeführten Operationen entscheiden, ob und welches Ergebnis entsteht oder ein Fehler auftritt.

Das Grundkonzept von [PEP 484 und seinen Nichtzielen](https://peps.python.org/pep-0484/#non-goals) unterscheidet Typinformationen ausdrücklich von verpflichtender Laufzeitkontrolle. Für eine gezielte Prüfung tatsächlicher Eingaben braucht es eigenen Code oder ein dafür eingesetztes Werkzeug. Die Schreibweisen und Auswertung von Annotationen entwickeln sich außerdem zwischen Python-Versionen weiter. Dieses Beispiel bezieht sich auf Python 3.13.

## 5. Wo begegnet mir das unter Linux?

Python-Projekte können Typangaben für Hilfsfunktionen, Schnittstellen und Bibliotheken verwenden. Eine Entwicklungsumgebung kann daraus Vorschläge ableiten und problematische Aufrufe früher markieren. Das hilft auch bei der Arbeit an Linux-Anwendungen, gehört aber zur Sprache und ihren Werkzeugen, nicht zu einer besonderen Betriebssystemregel.

Typangaben installieren keine Bibliothek und verändern keine Projektumgebung. Ein Projekt muss sein Prüfwerkzeug und dessen Einstellungen gesondert festlegen. Ohne diese Einrichtung bedeutet eine vorhandene Annotation noch nicht, dass der Code tatsächlich statisch geprüft wurde.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Es verwendet nur selbst gewählte Werte und die Standardbibliothek.

```python
from typing import get_type_hints


def add(a: int, b: int) -> int:
    return a + b


hinweise = get_type_hints(add)
assert hinweise == {"a": int, "b": int, "return": int}
assert add(2, 3) == 5
text = add("2", "3")
assert text == "23"
assert isinstance(text, str)
print(add(2, 3))
print(repr(text))
```

Geprüfte Ausgabe:

```text
5
'23'
```

`get_type_hints` liest hier die Hinweise der eigenen Funktion. Der absichtlich unpassende zweite Aufruf wird von Python ausgeführt: Für zwei Strings bedeutet `+` Verkettung. Das Ergebnis widerspricht dem angegebenen Rückgabetyp. Genau dieser Versuch zeigt, warum die Annotation keine Laufzeitgarantie ist. Ein externer Typprüfer wurde weder installiert noch ausgeführt; dessen konkrete Diagnose wird deshalb nicht behauptet.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein [Docstring](it_0096.md) kann Zweck, Einheiten und fachliche Grenzen ausführlich erklären. Ein Type Hint beschreibt vor allem Typbeziehungen. Eine Laufzeitprüfung untersucht konkrete eingehende Werte während der Ausführung. Tests wiederum prüfen ausgewählte Erwartungen mit bestimmten Eingaben. Diese Hilfsmittel ergänzen sich, haben aber unterschiedliche Aufgaben.

## 8. Häufige Missverständnisse

Eine annotierte Funktion wird nicht automatisch schneller. Ebenso wenig wird eine Zeichenkette durch `: int` in eine Zahl umgewandelt. Selbst ein tatsächlich vorliegender Integer kann fachlich unzulässig sein, etwa als negative Anzahl. Der Typ allein beschreibt nicht jede gewünschte Einschränkung.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Beginne mit übersichtlichen Funktionsschnittstellen und passenden Projektkonventionen. Prüfe externe Eingaben dort, wo ihre Gültigkeit benötigt wird. `get_type_hints` ist kein Werkzeug zum gefahrlosen Untersuchen beliebigen fremden Codes: Das Auflösen von Annotationen kann Code ausführen, wie die typing-Referenz erläutert. Hier werden ausschließlich einfache Annotationen einer selbst definierten Funktion ausgewertet.

## 10. Verwandte Begriffe

Der [Datentyp](it_0006.md) beschreibt die Art eines Wertes. Eine [Funktion](it_0017.md) kann erwartete Typen annotieren. Eine [Exception](it_0091.md) entsteht weiterhin aus dem tatsächlichen Programmablauf und nicht automatisch aus einem widersprochenen Type Hint.

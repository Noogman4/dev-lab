# Tuple

## 1. Kurzbeschreibung

Ein Tuple, auf Deutsch häufig Tupel, ist eine geordnete Zusammenstellung von Elementen. In Python ist der Typ `tuple` eine unveränderliche Folge. Das Quellbeispiel `point = (10, 20)` kann zwei zusammengehörige Koordinaten darstellen. Ihre Reihenfolge ist bedeutsam; die beiden Zahlen werden nicht automatisch als benannte Felder behandelt.

## 2. Was bedeutet der Begriff?

Ein Tupel kann Werte gruppieren, die gemeinsam eine Information darstellen. Ein Paar kann etwa aus Kennung und Meldung bestehen. Die Bedeutung jeder Position gehört zur Vereinbarung der Anwendung. Ohne Erklärung weiß ein Programm nicht, ob die erste Zahl eine x-Koordinate, eine Breite oder etwas anderes meint.

Die [offizielle Python-Referenz zum Tupeltyp](https://docs.python.org/3.13/library/stdtypes.html#tuples) beschreibt Konstruktion und Folgeoperationen. Wichtig ist, dass in Python gewöhnlich das Komma das Tupel bildet, nicht allein die Klammern. Ein einzelnes Element benötigt deshalb ein entsprechendes Komma; leere Klammern bezeichnen dagegen das leere Tupel.

## 3. Einfacher Vergleich aus dem Alltag

Eine fest angeordnete Karte mit zwei Feldern kann ein zusammengehöriges Wertepaar darstellen. Die erste und die zweite Position haben vereinbarte Rollen. Du verwendest die Karte als Einheit, statt die Angaben unabhängig zu verteilen.

Die Grenze des Vergleichs: Die Unveränderlichkeit eines Python-Tupels betrifft die enthaltenen Objektverweise. Ein darin referenziertes veränderliches Objekt kann weiterhin verändert werden. Eine „versiegelte Karte“ wäre dafür ein zu starkes Bild, wenn sie suggeriert, dass jede erreichbare Information vollständig eingefroren sei.

## 4. Wie funktioniert das?

Auf Elemente kann über Indizes zugegriffen werden. Bestehende Tupel erlauben jedoch keine Ersetzung eines Elements an einer Position. Eine neue Kombination kann als neues Tupel erzeugt und an denselben Namen gebunden werden; das verändert nicht nachträglich das alte Objekt.

Enthält ein Tupel eine Liste, bleibt diese Liste veränderlich. Das [Python-Datenmodell zu Objekten und Veränderbarkeit](https://docs.python.org/3.13/reference/datamodel.html#objects-values-and-types) erklärt ausdrücklich diesen Unterschied zwischen unveränderlichem Container und darin erreichbaren veränderlichen Objekten. Auch die Eignung als Schlüssel hängt nicht allein am Namen `tuple`, sondern an den dafür nötigen Eigenschaften seiner Elemente.

## 5. Wo begegnet mir das unter Linux?

Python-Funktionen können zusammengehörige Angaben als Tupel zurückgeben. Eine Verarbeitung kann beispielsweise Position und Wert gemeinsam liefern. Dadurch lässt sich eine kleine feste Gruppe ohne eigene Klasse darstellen.

Bei vielen ähnlich aussehenden Feldern kann ein Zugriff über Namen verständlicher sein als über Positionsnummern. Das ist eine Entwurfsentscheidung: Ein einfaches Tupel erklärt seine fachlichen Rollen nicht selbst. Außerdem garantiert sein Typ keine bestimmte Anzahl, Einheit oder sinnvolle Werte, sofern die Anwendung das nicht prüft.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel übernimmt das Koordinatenpaar und prüft anschließend eine enthaltene Liste:

```python
point = (10, 20)
assert point[0] == 10
abgelehnt = False
try:
    point[0] = 99
except TypeError:
    abgelehnt = True
assert abgelehnt is True
assert point == (10, 20)
paket = ([1],)
paket[0].append(2)
assert paket[0] == [1, 2]
print(point)
print(paket[0])
```

Die Ausgabe lautet:

```text
(10, 20)
[1, 2]
```

Die direkte Ersetzung im Tupel wird abgelehnt. Das Ein-Element-Tupel `paket` enthält dagegen eine Liste, deren Inhalt erweitert werden darf. Der Verweis an seiner ersten Position bleibt derselbe. Das Beispiel prüft also sowohl die feste Tupelstruktur als auch die weiterhin veränderliche enthaltene Liste.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Python-Liste ist als Folge veränderlich. Ein Tupel ist unveränderlich, aber nicht automatisch tief eingefroren. Ein Array kann gemeinsame Elementtypen und andere Größenregeln verlangen. Eine benannte Struktur kann ihre Felder verständlicher ausdrücken, wenn Positionsnummern allein nicht ausreichend sind.

## 8. Häufige Missverständnisse

Klammern allein erzeugen kein allgemeines Ein-Element-Tupel. Unveränderlich bedeutet nicht, dass sämtliche erreichbaren Objekte unveränderlich sind. Ein Tupel ist außerdem nicht automatisch sortiert. Auch muss eine Neuzuweisung an den Variablennamen von einer Änderung am bisherigen Tupel unterschieden werden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Dokumentiere die Bedeutung der Positionen und die erwartete Länge. Prüfe bei gemeinsam verwendeten Daten auch enthaltene veränderliche Objekte. Das Lernbeispiel bearbeitet nur eigene Objekte im Speicher. Sein abgefangener Fehler ist absichtlich Teil der Prüfung und keine reale Anwendungsstörung.

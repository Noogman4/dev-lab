# Feature Flag

## 1. Kurzbeschreibung

Ein Feature Flag ist eine Einstellung, mit der eine Anwendung zwischen vorgesehenen Funktionsvarianten entscheidet. Häufig wird eine Funktion damit ein- oder ausgeschaltet. Das kann eine schrittweise Einführung oder eine kontrollierte Erprobung unterstützen. Der Schalter wählt vorhandenes Verhalten aus; er erzeugt weder den benötigten Code noch automatisch eine passende Berechtigung.

## 2. Was bedeutet der Begriff?

Die Quelle nennt einen möglichen Pro-Modus. Dabei müssen zwei Fragen getrennt bleiben: Welche Variante soll angezeigt oder verwendet werden, und wer darf eine geschützte Funktion tatsächlich nutzen? Eine selbst veränderbare Anzeigeeinstellung ist kein vollständiger Nachweis einer Zugriffs- oder Lizenzberechtigung.

Die [OpenFeature-Spezifikation zur Flag-Auswertung](https://openfeature.dev/specification/sections/flag-evaluation/) beschreibt typisierte Auswertungen mit Schlüssel, Standardwert und optionalem Auswertungskontext. Flags müssen also nicht nur ein einfacher globaler Ja-Nein-Wert sein. Welche Verfahren eine konkrete Anwendung unterstützt, hängt von ihrer Bibliothek und Konfiguration ab.

## 3. Einfacher Vergleich aus dem Alltag

Eine Redaktion entscheidet per Schalter, ob eine neue Seitengestaltung gezeigt wird. Die bisherige Gestaltung bleibt während der Erprobung verfügbar. Wird ein Problem entdeckt, kann zur vorgesehenen alten Darstellung zurückgekehrt werden.

Die Grenze: Ein Schalter beseitigt keine bereits erfolgten Wirkungen. Eine mit der neuen Funktion versandte Nachricht wird durch Ausschalten nicht zurückgeholt. Auch muss der alte Weg tatsächlich weiter funktionieren. Der Vergleich ist daher keine allgemeine Rückgängig-Garantie für Datenänderungen oder Veröffentlichungen.

## 4. Wie funktioniert das?

Die Anwendung fragt einen Wert ab und wählt danach einen implementierten Pfad. Eine einfache Variante liest einen booleschen Wert. Andere Systeme können Kontext, Zeitfenster oder Zielgruppen berücksichtigen. Das Ergebnis muss an den relevanten Stellen konsistent verwendet werden.

Die [Microsoft-Referenz zur Python-Featureverwaltung](https://learn.microsoft.com/en-us/azure/azure-app-configuration/feature-management-python-reference) beschreibt konkrete Flagdefinitionen und Filter. Diese Formate und Bibliotheksfunktionen sind produktspezifisch. Ein kleines lokales Programm kann stattdessen eine eigene einfache Einstellung verwenden. Das Beispiel installiert und verwendet keine solche Bibliothek.

Wichtig sind ein geeigneter Standardwert und das Verhalten bei nicht verfügbaren Informationen. Ein fehlender Wert sollte nicht zufällig einen ungeprüften Pfad aktivieren. Wie schnell geänderte Einstellungen sichtbar werden, hängt zudem von Laden, Zwischenspeicherung und Aktualisierung ab. Ein Flag garantiert nicht von selbst eine sofortige Änderung in jedem laufenden Prozess.

Jeder zusätzliche unabhängige Schalter kann weitere Kombinationen schaffen. Alte Schalter sollten deshalb nicht unbegrenzt ohne Zweck bestehen bleiben. Sonst wird schwerer erkennbar, welche Varianten noch unterstützt und geprüft werden müssen.

## 5. Wo begegnet mir das unter Linux?

Desktop- und Serveranwendungen können neue Oberflächen oder Verarbeitungspfade kontrolliert anbieten. Ein Feature Flag kann dabei eine gewöhnliche Konfigurationseinstellung sein. Ein entfernter Dienst ist dafür nicht zwingend notwendig.

Geschützte Aktionen brauchen trotzdem ihre fachlich maßgebliche Berechtigungsprüfung. Das bloße Verbergen eines Knopfs erfüllt diese Aufgabe nicht vollständig. Das folgende Beispiel modelliert die Entscheidung getrennt und verwendet nur selbst gesetzte Testwerte, keine tatsächlichen Konten oder Lizenzen.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Arbeitsordner ausgeführt. Es erzeugt nur zwei Darstellungen desselben eigenen Titels. Der Berechtigungswert ist eine Testvorgabe, kein implementiertes Anmelde- oder Lizenzsystem.

```python
def anzeigen(titel, *, berechtigt, neue_ansicht):
    if not berechtigt:
        raise PermissionError("Zugriff fehlt")
    if neue_ansicht:
        return titel.upper()
    return titel

klassisch = anzeigen("Probe", berechtigt=True, neue_ansicht=False)
neu = anzeigen("Probe", berechtigt=True, neue_ansicht=True)
assert klassisch == "Probe" and neu == "PROBE"
abgelehnt = False
try:
    anzeigen("Probe", berechtigt=False, neue_ansicht=True)
except PermissionError:
    abgelehnt = True
assert abgelehnt
print("Bisherige Ansicht:", klassisch)
print("Neue Ansicht:", neu)
print("Ohne Berechtigung abgelehnt:", abgelehnt)
```

Geprüfte Ausgabe:

```text
Bisherige Ansicht: Probe
Neue Ansicht: PROBE
Ohne Berechtigung abgelehnt: True
```

Der Darstellungsflag verändert den gewählten Textpfad. Er ersetzt nicht die gesonderte Prüfung davor. Das Beispiel bestätigt weder eine echte Autorisierung noch einen Dienst zur Flag-Auswertung, Zielgruppenregeln oder eine laufende Aktualisierung. Es verändert keine vorhandenen Benutzerrechte.

## 7. Abgrenzung zu ähnlichen Begriffen

Konfiguration ist der weitere Begriff für Einstellungen. Ein Feature Flag steuert eine vorgesehene Variante. Ein Branch trennt Entwicklung in Git. Ein Release bezeichnet einen bereitgestellten Stand nach den Projektregeln. Die Aktivierung einer vorhandenen Variante ist nicht automatisch eine neue Codeveröffentlichung.

## 8. Häufige Missverständnisse

Ein Flag installiert keinen fehlenden Code. Ein eingeschalteter Pro-Modus beweist keine Lizenz. Ausschalten macht nicht jede Wirkung rückgängig. Und eine Änderung des gespeicherten Flags wirkt nicht zwingend sofort in allen laufenden Prozessen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Dokumentiere Zweck, Standardwert und unterstützte Kombinationen. Prüfe ein- und ausgeschaltete Pfade sowie Fehlerfälle. Entferne überholte Varianten nach einem bewussten Verfahren. Die Übung arbeitet nur mit eigenen Speicherwerten und aktiviert keine bestehende Produktfunktion.

# PEP 8

## 1. Kurzbeschreibung

PEP 8 ist ein offizieller Stilratgeber für Python-Code. Er empfiehlt unter anderem eine einheitliche Einrückung, gut lesbare Namen und eine übersichtliche Anordnung des Quelltexts. Diese Konventionen helfen Menschen beim gemeinsamen Lesen und Bearbeiten. Sie beschreiben nicht vollständig, was Python syntaktisch erlaubt oder fachlich richtig berechnet.

## 2. Was bedeutet der Begriff?

PEP steht für „Python Enhancement Proposal“. Solche Dokumente behandeln unterschiedliche Vorschläge, Prozesse und Informationen rund um Python. Die Nummer 8 bezeichnet den „Style Guide for Python Code“, ursprünglich für den Python-Standardbibliothekscode gedacht und weit darüber hinaus verwendet.

Die [Einordnung zur Konsistenz in PEP 8](https://peps.python.org/pep-0008/#a-foolish-consistency-is-the-hobgoblin-of-little-minds) betont die Lesbarkeit und die Bedeutung des vorhandenen Projektstils. Es ist ausdrücklich kein Ziel, durch starres Befolgen einzelner Empfehlungen verständlicheren Code oder bestehende Kompatibilität zu beschädigen. In einem konkreten Repository gelten deshalb auch dessen dokumentierte Regeln und bewusst gewählte Ausnahmen.

## 3. Einfacher Vergleich aus dem Alltag

Eine gemeinsame Ablageordnung legt fest, wie Ordner beschriftet und Unterlagen einsortiert werden. Wer sie kennt, findet sich in den Unterlagen anderer schneller zurecht. Ein ungewohnt beschrifteter Ordner kann trotzdem die richtigen Dokumente enthalten.

Genauso erleichtert ein einheitlicher Codestil die Orientierung, ohne das Rechenergebnis zu beweisen. Die Grenze des Vergleichs: Einrückung hat in Python zusätzlich eine grammatische Bedeutung. Werden Anweisungen einem anderen Block zugeordnet, ändert sich möglicherweise das Verhalten. Nicht jede Änderung am sichtbaren Layout ist daher bloß Geschmack.

## 4. Wie funktioniert das?

PEP 8 empfiehlt beispielsweise [vier Leerzeichen pro Einrückungsebene](https://peps.python.org/pep-0008/#indentation). Für [Funktions- und Variablennamen](https://peps.python.org/pep-0008/#function-and-variable-names) sind in der Regel Kleinbuchstaben mit Unterstrichen zwischen Wörtern vorgesehen. Weitere Abschnitte behandeln Leerzeichen, Importe und andere Aspekte.

Ein Formatierer kann Teile der Darstellung vereinheitlichen. Ein Prüfwerkzeug kann ausgewählte Stilabweichungen melden. Beides benötigt eigene Regeln und Einstellungen; Python selbst führt beim normalen Programmstart keine vollständige PEP-8-Abnahme durch. Verständliche Begriffe oder eine geeignete Aufteilung der Aufgaben bleiben außerdem Entscheidungen der Schreibenden.

## 5. Wo begegnet mir das unter Linux?

Python-Projekte unter Linux können PEP 8 in ihren Beitragsregeln nennen und passende Werkzeuge in der Entwicklung einsetzen. Das hilft beim Lesen von Skripten, Bibliotheken und GUI-Code. Eine gemeinsam vereinbarte Darstellung vermindert unnötige Änderungen zwischen verschiedenen Bearbeitern.

Der Ratgeber gehört zur Python-Entwicklung, nicht zu einer bestimmten Linux-Distribution. Ob ein vorhandenes Programm funktioniert, lässt sich nicht daran ablesen, ob es alle Stilhinweise erfüllt. Umgekehrt wird fehlerhafte Programmlogik durch hübsche Formatierung nicht korrekt.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Zwei eigene Funktionen berechnen dieselbe Summe. Die erste ist absichtlich knapp und uneinheitlich benannt, die zweite verwendet einen verständlicheren Namen und übliche Abstände.

```python
def summeKurz(a,b):
    return a+b


def summe_berechnen(erster_wert, zweiter_wert):
    return erster_wert + zweiter_wert


for links, rechts in [(2, 3), (0, 0), (-4, 1)]:
    assert summeKurz(links, rechts) == summe_berechnen(links, rechts)

print(summeKurz(2, 3))
print(summe_berechnen(2, 3))
```

Geprüfte Ausgabe:

```text
5
5
```

Die erste Form ist ausführbar, obwohl Benennung und Abstände nicht den hier erläuterten Empfehlungen folgen. Die Assertions vergleichen beide Funktionen für drei Eingabepaare. Sie bestätigen nur diese Ergebnisse, keine vollständige Stilkonformität. Es wurden weder ein Formatierer noch ein Stilprüfer auf dieses Beispiel oder auf Projektdateien angewendet.

## 7. Abgrenzung zu ähnlichen Begriffen

Die Syntax legt fest, welche Sprachkonstruktionen gültig sind. PEP 8 empfiehlt die Darstellung gültigen Codes. Ein Algorithmus bestimmt den Lösungsweg, während Tests ausgewählte Verhaltensanforderungen prüfen. Ein Projekt kann zusätzlich eigene Vorgaben für Zeilenlängen oder Werkzeuge haben, die von einzelnen PEP-8-Empfehlungen abweichen.

## 8. Häufige Missverständnisse

Eine Stilwarnung bedeutet nicht automatisch einen Laufzeitfehler. Ein fehlender Syntaxfehler beweist umgekehrt keinen guten Stil. Außerdem macht nicht jede kurze Abkürzung einen Namen besser: Verständlichkeit hängt davon ab, ob Menschen die Aufgabe an dieser Stelle erkennen können.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lies zuerst die Regeln des Projekts und halte neue Änderungen dazu passend. Trenne umfangreiche reine Formatierungsänderungen von fachlichen Korrekturen, wenn das die Prüfung erleichtert. Bestehende öffentliche Namen sollten nicht allein wegen einer Stilpräferenz umbenannt werden: Andere Programmteile könnten sie bereits verwenden. Nach Änderungen bleibt eine passende Verhaltensprüfung nötig.

## 10. Verwandte Begriffe

Der [Algorithmus](it_0001.md) beschreibt den Lösungsweg unabhängig von seinem Stil. Eine [Funktion](it_0017.md) profitiert von klaren Namen. Ein [Docstring](it_0096.md) erläutert die Verwendung und ergänzt lesbaren Code um wichtige Angaben.

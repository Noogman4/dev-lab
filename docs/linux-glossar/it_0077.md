# Event Loop

## 1. Kurzbeschreibung

Eine Event Loop ist ein laufender Verarbeitungsablauf für Ereignisse und vorgesehene Rückrufe. In einer GUI unterstützt sie etwa Eingaben, Aktualisierungen und zeitgesteuerte Aktionen. Die Quelle nennt `mainloop()` passend für Tkinter. Ereignisschleifen gibt es aber auch außerhalb grafischer Anwendungen, beispielsweise für asynchrone Verarbeitung.

## 2. Was bedeutet der Begriff?

Statt alle möglichen Eingaben ständig durch eigenen Anwendungscode abzufragen, übergibt ein Programm Arbeit an einen passenden Ereignismechanismus. Die Schleife wartet oder prüft, welche Aufgaben bereit sind, und führt vorgesehene Reaktionen aus.

Die [offizielle Tkinter-Erklärung zum Threading-Modell](https://docs.python.org/3.13/library/tkinter.html#threading-model) beschreibt die ereignisgesteuerte Verarbeitung und die Bedeutung kurzer Handler. Die [asyncio-Dokumentation zum Starten und Stoppen](https://docs.python.org/3.13/library/asyncio-eventloop.html#running-and-stopping-the-loop) zeigt eine andere konkrete Schleifenschnittstelle. Beide dürfen nicht einfach als dieselbe austauschbare Laufzeit betrachtet werden.

## 3. Einfacher Vergleich aus dem Alltag

Eine Leitstelle nimmt eingehende Meldungen und fällige Aufgaben entgegen und verteilt die vorgesehenen Schritte. Sie muss handlungsfähig bleiben, um auch den nächsten Anlass bearbeiten zu können.

Die Grenze des Vergleichs: Eine Ereignisschleife arbeitet nach festgelegten technischen Regeln. Sie macht lange Berechnungen nicht von selbst parallel. Wenn ein aufgerufener Handler lange nicht zurückkehrt, können andere Aufgaben derselben Schleife warten, auch wenn der Prozess weiterhin läuft.

## 4. Wie funktioniert das?

Das Programm registriert passende Aktionen und startet den vorgesehenen Verarbeitungslauf. Ereignisse oder fällige Timer können anschließend Rückrufe auslösen. Nach deren Ende kann die Schleife weitere Aufgaben behandeln. Start, Beendigung und Aufräumen folgen dem jeweiligen Toolkitvertrag.

In Tkinter startet `mainloop` den üblichen GUI-Ereignislauf. Zeitgesteuerte Aufrufe können über die Toolkit-Schnittstelle geplant werden. Ein Zeitwert ist dabei keine Garantie für einen exakt gleich großen realen Ausführungsabstand: Andere Arbeit und Systembedingungen können die Verarbeitung beeinflussen.

Asynchrone Bibliotheken können andere Regeln für Aufgaben, Abbruch und Lebensdauer besitzen. Zwei Schleifen dürfen nicht ohne geeignete Integration einfach verschachtelt oder unabhängig als dieselbe Zuständigkeit verwendet werden. Auch wiederholtes manuelles Aktualisieren ist nicht automatisch gleichbedeutend mit einem gut strukturierten Hauptablauf.

## 5. Wo begegnet mir das unter Linux?

Tkinter- und andere GUI-Anwendungen verwenden Ereignisverarbeitung. Netzwerkprogramme können asynchrone Schleifen verwenden, ohne ein Fenster zu besitzen. Welche Reaktionen wo ausgeführt werden dürfen, gehört zur jeweiligen Bibliotheksdokumentation.

Ein gestarteter Hauptloop belegt allein keine fachlich funktionierende Anwendung. Er kann laufen, während ein Fehlerdialog wartet, ein benötigter Auftrag fehlt oder ein Handler unpassend lange arbeitet. Für eine Prüfung ist ein konkreter beobachtbarer Ablauf erforderlich.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel startet nur eine eigene verborgene Tk-Schleife unter dem virtuellen Bildschirm:

```python
# GUI-Prüfung im virtuellen Bildschirm
import tkinter as tk

root = tk.Tk()
root.withdraw()
beobachtet = []

def schritt():
    beobachtet.append("verarbeitet")
    root.quit()

wache = root.after(1000, root.quit)
try:
    root.after(0, schritt)
    assert beobachtet == []
    root.mainloop()
    assert beobachtet == ["verarbeitet"]
    print(beobachtet[0])
finally:
    root.after_cancel(wache)
    root.destroy()
```

Die Ausgabe lautet:

```text
verarbeitet
```

Vor dem Loop wurde der Rückruf noch nicht ausgeführt. Während der Verarbeitung setzt er den eigenen Beobachtungswert und beendet die Schleife. Die zusätzliche zeitgesteuerte Beendigung begrenzt das Lernbeispiel bei ausbleibendem Schritt. Es wird weder eine genaue Zeitdauer noch parallele Verarbeitung geprüft.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Ereignis ist ein Anlass. Ein Callback ist die Reaktion. Eine Queue kann bereite Aufgaben speichern. Ein Thread ist ein eigener Ausführungskontext; eine Schleife erzeugt nicht automatisch mehrere davon. Ein dauerhaft laufender Prozess muss nicht zugleich eine reagierende Oberfläche besitzen.

## 8. Häufige Missverständnisse

`mainloop()` erledigt keine fachlichen Aufgaben automatisch. Ein geplanter Timer ist keine garantierte Echtzeitfrist. Lange Handler laufen nicht allein wegen der Schleife im Hintergrund. Ein blockierter Bedienablauf ist außerdem nicht gleichbedeutend mit einem sofort beendeten Prozess.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Halte Ereignisreaktionen überschaubar und kläre Abbruch sowie Aufräumen. Prüfe echte Aufträge statt nur einen lebenden Prozess. Das Beispiel testet nur eine eigene Tk-Zeitplanung; asyncio, Threads und NetMons Hauptablauf wurden nicht praktisch abgenommen.

# Spalte

## 1. Kurzbeschreibung

Eine Spalte ist eine benannte Eigenschaft innerhalb einer Tabellendefinition. Jede Zeile besitzt dazu einen Wert beziehungsweise einen nach den Regeln zulässigen fehlenden Wert. Name, Datentyp und weitere Bedingungen beschreiben unterschiedliche Aspekte. Die kurze Quellformulierung „ein Feldtyp“ sollte deshalb nicht so verstanden werden, als wären Spalte und Datentyp dasselbe.

## 2. Was bedeutet der Begriff?

Das Katalogbeispiel `name` und `url` nennt mögliche Spalten für Senderdaten. Beide Namen sagen zunächst, welche Angaben gemeint sein könnten. Sie erzwingen allein weder einen gültigen Namen noch eine tatsächlich erreichbare URL. Dafür werden zusätzliche Regeln benötigt.

Die [PostgreSQL-Grundlagen zu Tabellen](https://www.postgresql.org/docs/current/ddl-basics.html) erläutern benannte Spalten und zugehörige Typdefinitionen. Die genaue Prüfung ist aber systemabhängig. Insbesondere sollten Beispiele einer Datenbank nicht ungeprüft als Verhalten jeder anderen Implementierung behandelt werden.

## 3. Einfacher Vergleich aus dem Alltag

Eine Formularrubrik trägt einen Namen und eine Angabe darüber, was eingetragen werden soll. Die Rubrik „Anzahl“ ist nicht dieselbe Sache wie der erlaubte Zahlentyp. Zusätzliche Regeln könnten negative Zahlen oder fehlende Angaben ausschließen.

Die Grenze: Eine Datenbank arbeitet nach technischen Speicher- und Prüfregeln. Eine bloße Beschriftung reicht nicht. Auch wird nicht jede fachliche Einschränkung automatisch durch einen passenden Typ ausgedrückt. Eine Zahl kann typmäßig korrekt sein und trotzdem außerhalb eines gewünschten Bereichs liegen.

## 4. Wie funktioniert das?

Eine Tabelle definiert die vorgesehenen Spalten. Abfragen können ausgewählte Spalten zurückgeben, eventuell in einer ausdrücklich gewählten Reihenfolge oder unter anderen Ergebnisnamen. Diese Ergebnisdarstellung ist nicht automatisch eine unveränderliche Beschreibung sämtlicher gespeicherter Eigenschaften.

Für gewöhnliche SQLite-Tabellen erklärt die [Dokumentation zu Datentypen](https://www.sqlite.org/datatype3.html) das flexible Typmodell und Affinitäten. Eine deklarierte Spalte ist dort nicht in jedem Fall eine starre Schranke gegen andere Speicherklassen. Das ist eine SQLite-Eigenschaft und keine allgemeine SQL-Regel.

SQLite unterstützt daneben [STRICT-Tabellen](https://www.sqlite.org/stricttables.html) seit Version 3.37.0. Diese besitzen strengere Typbedingungen, erlauben aber weiterhin bestimmte passende Konvertierungen. Auch sie sind kein allgemeiner Ersatz für fachliche Prüfungen oder eine Gleichsetzung mit Pythons exakten Objekttypen.

## 5. Wo begegnet mir das unter Linux?

Anwendungen speichern benannte Angaben und lesen sie über Datenbankbibliotheken. Ein unerwarteter Wert kann auf fehlende Fachprüfung oder ein anderes Typmodell zurückgehen. Der Spaltenname allein diagnostiziert keine Beschädigung.

Auch eine Ergebniszeile in Python muss nach ihrem tatsächlichen Inhalt geprüft werden. Ein String mit Ziffern und ein Integer sind nicht dieselbe Python-Darstellung. Welche Umwandlung sinnvoll ist, hängt vom Vertrag ab. Vorhandene Anwendungsstrukturen werden hier nicht untersucht oder angepasst.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 und SQLite 3.46.1 in einem temporären Arbeitsordner ausgeführt. Es erzeugt nur zwei eigene In-Memory-Tabellen und setzt die Unterstützung für STRICT voraus.

```python
from contextlib import closing
import sqlite3

assert sqlite3.sqlite_version_info >= (3, 37, 0)
with closing(sqlite3.connect(":memory:")) as db:
    db.execute("CREATE TABLE normal (wert INTEGER)")
    db.execute("CREATE TABLE streng (wert INTEGER) STRICT")
    db.execute("INSERT INTO normal VALUES (?)", ("keine Zahl",))
    speicherklasse = db.execute("SELECT typeof(wert) FROM normal").fetchone()[0]
    assert speicherklasse == "text"
    abgelehnt = False
    try:
        db.execute("INSERT INTO streng VALUES (?)", ("keine Zahl",))
    except sqlite3.IntegrityError:
        abgelehnt = True
    assert abgelehnt
    db.execute("INSERT INTO streng VALUES (?)", (42,))
    assert db.execute("SELECT wert FROM streng").fetchall() == [(42,)]
    print("Normale SQLite-Spalte:", speicherklasse)
    print("STRICT lehnt Text ab:", abgelehnt)
```

Geprüfte Ausgabe:

```text
Normale SQLite-Spalte: text
STRICT lehnt Text ab: True
```

Dasselbe Typwort verhält sich hier unter verschiedenen Tabellenregeln unterschiedlich. Das Beispiel zeigt keine allgemeine Erlaubnis, beliebige Typen in jede Datenbank zu schreiben. Es prüft genau diese SQLite-Fälle, keine Leistungs- oder Migrationsanforderungen. Die Tabellen werden nicht dauerhaft gespeichert.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Zeile enthält die zusammengehörigen Werte eines Eintrags. Eine Spalte beschreibt eine Eigenschaft über viele Zeilen. Ein Datentyp ist eine andere Ebene der Beschreibung. Ein berechneter Ergebnisausdruck muss wiederum nicht als eigene gespeicherte Spalte existieren.

## 8. Häufige Missverständnisse

Ein Spaltenname ist kein Datentyp. Ein Typ garantiert keine fachlich richtige URL oder positive Anzahl. Eine SQLite-Deklaration bedeutet auch nicht immer die strenge Prüfung anderer Systeme. Schließlich ist eine fehlende Angabe von einem vorhandenen leeren Text zu unterscheiden.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Dokumentiere Typmodell und weitere Bedingungen. Prüfe Daten vor Strukturänderungen an einem eigenen Bestand. Dieses Beispiel verändert weder Anwendungsdateien noch Schemata, Datenbanksysteme oder installierte Versionen und führt keine Migration aus.

## 10. Verwandte Begriffe

Die [Tabelle](it_0194.md) definiert die Struktur. Die [Zeile](it_0195.md) enthält Werte. Der [Datentyp](it_0006.md) betrifft ihre Verarbeitung. [SQLite](it_0193.md) besitzt die gezeigten besonderen Regeln. [Null](it_0011.md) erklärt fehlende Werte.

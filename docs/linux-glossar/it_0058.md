# Vererbung

## 1. Kurzbeschreibung

Vererbung ist eine Beziehung zwischen Klassen, bei der eine abgeleitete Klasse auf Verhalten und Eigenschaften von Basisklassen zurückgreifen kann. Sie kann Verhalten ergänzen oder überschreiben. Das Quellbeispiel `AdminUser` als Unterklasse von `User` ist ein mögliches Modell. Es verleiht jedoch allein durch seine Klassennamen keine realen Administratorrechte.

## 2. Was bedeutet der Begriff?

Vererbung beschreibt eine Typbeziehung und Regeln für die Suche nach Bestandteilen. Die Unterklasse muss nicht jede gemeinsam verwendete Methode erneut definieren. Ihre Instanzen können in passenden Zusammenhängen zugleich als Instanzen der Basisklasse behandelt werden.

Das [offizielle Python-Tutorial zur Vererbung](https://docs.python.org/3.13/tutorial/classes.html#inheritance) beschreibt Basisklassen, geerbte Attribute und überschreibende Methoden. Eine Unterklasse sollte die Erwartungen der vorgesehenen Basisschnittstelle sinnvoll erfüllen. Das bloße Wiederverwenden einiger Codezeilen ist noch kein ausreichender fachlicher Grund für jede denkbare Vererbungsbeziehung.

## 3. Einfacher Vergleich aus dem Alltag

Eine spezialisierte Formularart verwendet gemeinsame Felder eines Grundformulars und ergänzt weitere Angaben. Dadurch müssen die allgemeinen Vorgaben nicht auf jeder Variante unabhängig neu beschrieben werden.

Die Grenze des Vergleichs: Softwarevererbung kopiert nicht einfach ein Papierformular in eine neue Datei. Methoden werden nach festgelegten Suchregeln gefunden. Änderungen einer Basis können mehrere Unterklassen beeinflussen. Auch bedeutet eine Spezialisierung nicht, dass jede beliebige neue Regel mit den bisherigen Erwartungen vereinbar bleibt.

## 4. Wie funktioniert das?

In Python nennt die Klassendefinition ihre Basisklassen. Fehlt ein gesuchtes Attribut an der passenden Stelle, berücksichtigt die Auflösung die Vererbungsstruktur. Eine Unterklasse kann eine gleichnamige Methode definieren und damit die verwendete Implementierung beeinflussen.

Mit `super()` wird der nächste passende Zugriff gemäß Methodenauflösungsreihenfolge vermittelt. Das ist besonders bei Mehrfachvererbung nicht gleichbedeutend mit „rufe irgendeine fest gedachte Elternklasse auf“. Die [offizielle super-Referenz](https://docs.python.org/3.13/library/functions.html#super) erläutert diese kooperative Suche.

Überschreibt eine Unterklasse die Initialisierung, muss benötigte Basisinitialisierung bewusst berücksichtigt werden. Die Regel „alles wird automatisch vollständig übernommen“ wäre zu ungenau. Geerbte Schnittstellen und vorhandener Anfangszustand sind getrennt zu beurteilen.

## 5. Wo begegnet mir das unter Linux?

Python-Bibliotheken können gemeinsame Basisklassen für verwandte Ergebnisarten oder Oberflächenelemente bereitstellen. Eine Anwendung erweitert dann ausgewählte Operationen. Welche Methoden überschrieben werden dürfen und welche Zusicherungen bleiben müssen, sollte die Bibliothek dokumentieren.

Eine fachliche Benutzerrolle ist von Betriebssystemberechtigungen zu trennen. Auch wenn eine Instanz `AdminUser` heißt, hat der Prozess dadurch keine zusätzlichen Rechte. Solche Rechte werden durch eigene Systemmechanismen geregelt und nicht durch diese Python-Typbeziehung erzeugt.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel verwendet reine Namensdaten:

```python
class User:
    def __init__(self, name):
        self.name = name

    def beschreibung(self):
        return self.name

class AdminUser(User):
    def beschreibung(self):
        return "Modellrolle: " + super().beschreibung()

objekt = AdminUser("Beispiel")
assert isinstance(objekt, AdminUser)
assert isinstance(objekt, User)
assert objekt.name == "Beispiel"
assert objekt.beschreibung() == "Modellrolle: Beispiel"
print(objekt.beschreibung())
```

Die Ausgabe lautet:

```text
Modellrolle: Beispiel
```

Die Unterklasse verwendet die Basisinitialisierung und überschreibt die Beschreibung. Innerhalb dieser Methode wird die passende Basisbeschreibung weiterverwendet. Geprüft werden Typzugehörigkeit, übernommener Name und Ergebnistext. Es werden keine echten Konten oder Rechte verändert.

## 7. Abgrenzung zu ähnlichen Begriffen

Komposition stellt Objekte zusammen und delegiert Aufgaben an Bestandteile, ohne dieselbe Vererbungsbeziehung herzustellen. Kopieren vervielfältigt Daten oder Quelltext. Eine Schnittstelle beschreibt Erwartungen. Vererbung kann eine Schnittstelle unterstützen, garantiert allein aber keine fachlich passende Umsetzung.

## 8. Häufige Missverständnisse

Eine Unterklasse ist keine bloße Textkopie. `super()` bedeutet nicht in jedem Fall eine einzige direkte Elternklasse. Mehr Vererbungsebenen ergeben nicht automatisch eine bessere Struktur. Eine Unterklasse darf außerdem nicht unbemerkt wesentliche Erwartungen bestehender Aufrufer verletzen.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe gemeinsame Anforderungen und Alternativen wie Komposition. Dokumentiere überschriebenes Verhalten und benötigte Initialisierung. Das Beispiel testet nur einfache eigene Vererbung. Mehrfachvererbung, echte Rollenverwaltung und GUI-Bibliotheken wurden nicht praktisch geprüft.

# Fehler

## 1. Kurzbeschreibung

Ein Fehler ist eine Abweichung oder ein Problem im erwarteten Ablauf. In der Softwareentwicklung kann damit ein ungültiger Programmtext, ein fehlgeschlagener Zugriff oder ein fachlich falsches Ergebnis gemeint sein. Die genaue Art ist wichtig: Nicht jedes Problem hat dieselbe Ursache, und nicht jede Ursache liegt im Anwendungscode.

## 2. Was bedeutet der Begriff?

Ein Syntaxfehler verhindert, dass ein betroffener Programmtext nach den Sprachregeln verarbeitet wird. Ein Laufzeitproblem tritt dagegen während einer Ausführung auf. Ein fachlicher Fehler kann ohne technische Fehlermeldung bestehen bleiben, etwa wenn ein Programm die falsche Zahl berechnet.

Python verwendet Ausnahmen, um viele während der Ausführung auftretende Probleme zu signalisieren. Das [Tutorial zu Ausnahmen](https://docs.python.org/3.13/tutorial/errors.html#exceptions) zeigt unter anderem Division durch null und nicht gefundene Namen. Eine Ausnahme muss nicht zwingend das gesamte Programm beenden; eine vorgesehene Behandlung kann bestimmte Fälle gezielt auffangen.

## 3. Einfacher Vergleich aus dem Alltag

Wenn ein Zug nicht fährt, beschreibt das zunächst eine beobachtete Störung. Ursache könnten ein technischer Defekt, eine gesperrte Strecke oder eine falsch verstandene Fahrplanangabe sein. Dieselbe Beobachtung rechtfertigt nicht automatisch dieselbe Reparatur.

Der Vergleich hat Grenzen: Programme können bei identischen kleinen Testeingaben oft sehr genau untersucht werden. Trotzdem reicht eine Meldung allein nicht immer aus, um die auslösende Ursache zu kennen. Ein fehlender Dateipfad kann etwa durch einen Tippfehler, eine fehlende Berechtigung oder eine falsche Annahme entstehen.

## 4. Wie funktioniert das?

Bei einer Ausnahme unterbricht Python den normalen Ablauf an der betreffenden Stelle und sucht eine passende Behandlung. Ohne eine solche Behandlung wird häufig eine Rückverfolgung der Aufrufstellen angezeigt, ein sogenannter Traceback. Er enthält den Kontext, nicht automatisch eine fertige Diagnose.

Das Quellbeispiel mit einem Tippfehler im Variablennamen kann einen `NameError` auslösen. Die [Referenz zu NameError](https://docs.python.org/3.13/library/exceptions.html#NameError) beschreibt, dass ein unqualifizierter Name nicht gefunden wurde. Sie belegt nicht, dass jeder `NameError` zwingend ein Tippfehler ist. Ebenso kann ein falsch geschriebener Name zufällig bereits anderswo gebunden sein und dann ein falsches Ergebnis ohne diese Meldung verursachen.

## 5. Wo begegnet mir das unter Linux?

Ein Skript kann eine nicht vorhandene Eingabedatei erwarten oder eine nicht erreichbare Gegenstelle abfragen. Ein Werkzeug kann wegen ungültiger Argumente abbrechen. Eine grafische Anwendung kann eine Fehlermeldung zeigen oder lediglich ein unerwartetes Ergebnis darstellen.

Halte deshalb fest, was tatsächlich beobachtet wurde: ausgeführte Aktion, erwartetes Ergebnis, wirkliche Ausgabe und relevante Version. Solche Angaben erleichtern die Trennung zwischen Bedienfehler, fehlender Voraussetzung, Umgebungsproblem und Programmdefekt. Nicht jede fehlgeschlagene Aktion sollte durch Änderungen am Code beantwortet werden.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel erzeugt absichtlich einen falsch geschriebenen lokalen Zugriff und behandelt genau diesen Fehler:

```python
def pruefung():
    anzahl = 3
    erkannt = False
    try:
        ergebnis = anzhal + 1
    except NameError:
        erkannt = True
        print("NameError erkannt")
    assert erkannt is True
    ergebnis = anzahl + 1
    assert ergebnis == 4
    return ergebnis

print(pruefung())
```

Die Ausgabe lautet:

```text
NameError erkannt
4
```

`anzhal` ist nicht gebunden. Die passende Behandlung erkennt die Ausnahme; anschließend wird die Rechnung mit dem richtig geschriebenen Namen ausgeführt. Das Auffangen allein wäre keine Korrektur der fehlerhaften Zeile. Die absichtliche Störung dient hier ausschließlich der nachvollziehbaren Lernprüfung.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Fehlermeldung beschreibt eine Beobachtung des Systems. Eine Ausnahme ist ein sprachlicher Mechanismus. Ein Bug ist ein Defekt im Programm. Eine Warnung kann auf ein Problem hinweisen, ohne die Aktion abzubrechen. Ein fehlgeschlagener Test bedeutet zunächst, dass beobachtetes Verhalten und Test-Erwartung nicht übereinstimmen.

## 8. Häufige Missverständnisse

Die letzte sichtbare Meldung muss nicht die ursprüngliche Ursache sein. Eine Ausnahme zu unterdrücken repariert keine verlorenen Daten und macht kein Ergebnis richtig. Umgekehrt kann ein Programm trotz vollständig fehlender Fehlermeldungen fachlich falsch arbeiten.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Sichere wichtige Daten, bevor du Reparaturversuche unternimmst. Untersuche kleine reproduzierbare Fälle und veröffentliche keine geheimen Inhalte aus Protokollen. Das Beispiel verwendet ausschließlich eigene Zahlen und einen absichtlich fehlenden Namen; es verändert keine Geräte, Konten oder Dienste.

# Hashing

## 1. Kurzbeschreibung

Hashing berechnet aus Daten einen Hashwert. Hier geht es vor allem um kryptografische Hashfunktionen, die für dieselben Eingabebytes reproduzierbare Prüfwerte liefern. Daraus lässt sich ein kompakter Vergleichswert gewinnen. Ein Hash ist keine umkehrbare Verschlüsselung und keine mathematisch eindeutige Kennung aller möglichen Eingaben. Der Zweck bestimmt, welches Verfahren geeignet ist.

## 2. Was bedeutet der Begriff?

Die Quelle nennt einen Einweg-Prüfwert und die Speicherung von Passwörtern. Das sind verwandte, aber unterschiedlich anspruchsvolle Anwendungen. Eine schnelle Prüfsumme für eine Datei ist nicht automatisch ein geeignetes Verfahren für gespeicherte Passwörter.

Die [Python-Dokumentation zu hashlib](https://docs.python.org/3.13/library/hashlib.html) beschreibt kryptografische Hashalgorithmen, Ausgaben und auch bekannte Schwächen bestimmter Verfahren. Für SHA-256 beträgt die Ausgabe 256 Bit, also 32 Bytes. Ihre übliche hexadezimale Darstellung verwendet 64 Zeichen. Diese feste Länge ist eine Eigenschaft dieses Algorithmus; die Bibliothek bietet auch andere Ausgabeformen und Verfahren.

## 3. Einfacher Vergleich aus dem Alltag

Eine kurze Prüfnotiz zu einem Paket hilft festzustellen, ob der vorliegende Inhalt zur erwarteten Fassung passt. Du vergleichst die neu berechnete Notiz mit einer verlässlich erhaltenen Referenz, statt jede Einzelheit manuell zu lesen.

Die Grenze: Ein kurzer Prüfwert kann nicht alle denkbaren Inhalte eindeutig beschreiben. Unterschiedliche Eingaben können grundsätzlich denselben Wert besitzen. Bei geeigneten kryptografischen Verfahren soll es praktisch schwer sein, passende Kollisionen oder Vorgänger zu finden. Auch verrät ein übereinstimmender Wert allein nicht, wer die Referenz geliefert hat.

## 4. Wie funktioniert das?

Die Hashfunktion verarbeitet eine bestimmte Bytefolge nach festen Regeln. Gleiche Bytes und derselbe Algorithmus ergeben denselben Wert. Sichtbar ähnliche Texte können unterschiedliche Bytes besitzen, beispielsweise durch Zeilenenden oder eine andere Zeichenkodierung. Für einen verlässlichen Vergleich müssen daher Algorithmus und Datenfassung stimmen.

Ein Hashwert enthält keinen gewöhnlichen Entschlüsselungsschlüssel. Trotzdem können kurze oder vorhersehbare Eingaben durch Ausprobieren gefunden werden. „Einweg“ bedeutet nicht, dass niemand einen häufigen Passwortkandidaten berechnen und vergleichen könnte. Genau deshalb reicht ein schneller allgemeiner Hash für Passwörter nicht aus.

Der [OWASP-Leitfaden zur Passwortspeicherung](https://raw.githubusercontent.com/OWASP/CheatSheetSeries/master/cheatsheets/Password_Storage_Cheat_Sheet.md) empfiehlt dafür geeignete Verfahren wie Argon2id mit passenden Kostenparametern und eindeutigen Salts. Welche Lösung verwendet wird, muss zur etablierten Bibliothek und aktuellen Empfehlung passen. Das folgende SHA-256-Beispiel ist ausdrücklich keine Passwortspeicheranleitung.

Ein ungeschlüsselter Hash beweist außerdem keine Herkunft. Kann ein Angreifer sowohl Daten als auch die ungeschützte Referenz ersetzen, kann er einen neuen passenden Wert berechnen. Für Herkunft beziehungsweise authentisierte Integrität braucht es einen geeigneten vertrauenswürdigen Mechanismus über diesen bloßen Vergleich hinaus.

## 5. Wo begegnet mir das unter Linux?

Prüfsummen begleiten Downloads, Archive und Versionsprüfungen. Auch dieses Glossar hält tatsächliche SHA-256-Werte seiner Dokumente im Index fest. Damit können Byteänderungen gegenüber dem erfassten Stand erkannt werden. Die fachliche Richtigkeit eines Texts folgt daraus nicht.

Für eine fremde Datei ist die Herkunft der erwarteten Prüfsumme wichtig. Ein Vergleich mit einer selbst aus derselben unbekannten Datei erzeugten Referenz schafft keine unabhängige Vertrauensgrundlage. Hier werden nur eigene Bytes verarbeitet; bestehende Dateien bleiben unberührt.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Arbeitsordner ausgeführt. Die Referenz wird für diesen eigenen Test aus dem bekannten Original gebildet. Es werden keine Kennwörter und keine fremden Daten verwendet.

```python
import hashlib

original = b"Eigene Probe\n"
referenz = hashlib.sha256(original).hexdigest()
unveraendert = hashlib.sha256(bytes(original)).hexdigest() == referenz
geaendert = hashlib.sha256(b"Eigene andere Probe\n").hexdigest() == referenz
assert unveraendert and not geaendert
assert len(referenz) == 64
assert len(hashlib.sha256(original).digest()) == 32
print("Unverändert passt:", unveraendert)
print("Geändert passt:", geaendert)
print("Hexadezimale Zeichen:", len(referenz))
```

Geprüfte Ausgabe:

```text
Unverändert passt: True
Geändert passt: False
Hexadezimale Zeichen: 64
```

Die unveränderten Testbytes passen zur Referenz, die ausgewählte Änderung nicht. Das beweist keine allgemeine Kollisionsfreiheit und keine authentische Herkunft beliebiger Daten. Es ist ein Bytevergleichsmodell, kein Passworttest oder Kryptografieaudit.

## 7. Abgrenzung zu ähnlichen Begriffen

Verschlüsselung soll berechtigte Entschlüsselung ermöglichen. Ein kryptografischer Hash liefert einen Prüfwert. Eine digitale Signatur oder ein geeigneter Nachrichtenauthentisierungscode hat zusätzliche Vertrauensvoraussetzungen. Hashfunktionen für gewöhnliche Datenstrukturen sind wiederum nicht automatisch für kryptografische Prüfzwecke geeignet.

## 8. Häufige Missverständnisse

Ein Hash ist keine eindeutige Verschlüsselung. Einweg bedeutet nicht Schutz vor allen Passwortversuchen. SHA-256 allein ist kein zeitgemäßer Passwortspeicher. Und eine übereinstimmende ungeschützte Prüfsumme beweist keine vertrauenswürdige Herkunft.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Wähle Verfahren nach dem Zweck und dokumentiere die genaue Bytefassung. Beziehe Referenzwerte aus einem passenden vertrauenswürdigen Ablauf. Das Beispiel installiert keine Bibliothek, speichert keine Passwörter und verändert keine Dateien oder Konten.

# Dialog

## 1. Kurzbeschreibung

Ein Dialog ist eine abgegrenzte Oberfläche für eine bestimmte Rückfrage, Eingabe oder Mitteilung. Häufig erscheint er als zusätzliches Fenster. Die Quelle nennt ein kleines Fenster; die Größe ist jedoch kein entscheidendes Merkmal. Auch ein umfangreicher Einstellungsdialog kann dieselbe Rolle erfüllen.

## 2. Was bedeutet der Begriff?

Ein Dialog konzentriert sich auf einen begrenzten Arbeitsschritt. Er kann einen Wert erfragen, eine Aktion bestätigen lassen oder Details anzeigen. Wichtig sind der Bezug zur auslösenden Aufgabe und ein klarer Ausgang: bestätigt, abgebrochen oder auf andere Weise beendet.

Die [offizielle Qt-Beschreibung von QDialog](https://doc.qt.io/qt-6/qdialog.html) nennt zeitlich begrenzte Aufgaben und unterscheidet modale sowie nichtmodale Dialoge. Ein Dialog muss deshalb nicht zwangsläufig die weitere Arbeit in allen anderen Bereichen blockieren. Diese Bedienregel ist eine gesonderte Eigenschaft.

## 3. Einfacher Vergleich aus dem Alltag

Während einer Aufgabe wird eine gezielte Rückfrage gestellt, bevor ein bestimmter Schritt weitergeht. Die Rückfrage sollte erkennen lassen, worauf sie sich bezieht und was die Antwort bewirkt.

Die Grenze des Vergleichs: Eine Software kann ein Fenster schließen, ohne dass daraus eindeutig Zustimmung folgt. Unterschiedliche Tasten, Abbruch und das Fensterschließsymbol müssen passend interpretiert werden. Eine unklare Frage wird nicht allein durch die Form eines Dialogfensters zu einer verlässlichen Entscheidungshilfe.

## 4. Wie funktioniert das?

Die Anwendung erzeugt eine passende Oberfläche, stellt Kontext und Eingaben bereit und verarbeitet das Ergebnis nach dem vorgesehenen Vertrag. Ein bestätigter Eingabewert muss gegebenenfalls validiert werden, bevor eine weitere Aktion folgt.

Pythons `tkinter.simpledialog.Dialog` bietet eine Basis für eigene modale Dialoge. Die [offizielle Referenz](https://docs.python.org/3.13/library/dialog.html#tkinter.simpledialog.Dialog) beschreibt unter anderem Ergebnis, Validierung und Abbruch. Dort kann ein abgebrochener Vorgang `None` liefern. Andere APIs besitzen andere Rückgaberegeln; sie müssen vor der Verwendung gelesen werden.

Dialog und fachliche Aktion bleiben getrennt. Eine bestätigte Rückfrage beweist weder vorhandene Rechte noch den Erfolg der nachfolgenden Operation. Die Anwendung benötigt weiterhin passende Prüfung und Rückmeldung über deren Ausgang.

## 5. Wo begegnet mir das unter Linux?

Dateiauswahl, Einstellungen und Warnhinweise verwenden Dialoge. Bei einer möglicherweise verändernden oder aufwendigen Aktion sollte die Person das betroffene Ziel und die Konsequenzen verstehen können. Ein allgemeines „Fortfahren?“ ohne Kontext kann dafür zu wenig sein.

Das Quellbeispiel einer Rückfrage vor Paketmitschnitt beschreibt einen möglichen Ablauf. Es ersetzt keine fachlichen Voraussetzungen oder Zugriffskontrolle. Diese Dokumentation öffnet keine Mitschnittfunktion und prüft keine realen Netzwerkdaten.

## 6. Konkretes Beispiel Schritt für Schritt

Das folgende Gedankenbeispiel beschreibt einen erfundenen Dialog, keine ausgeführte Anwendung:

```text
Titel: Eigene Probe verwerfen
Kontext: Die noch nicht gespeicherte Beispielauswertung wird entfernt.
Aktionen: Probe verwerfen | Abbrechen
```

Zuerst wird klar, welche Daten betroffen sein sollen. Danach unterscheiden die Beschriftungen die verändernde Aktion vom Abbruch. Das Schließen ohne eindeutige Bestätigung darf im vorgesehenen Modell nicht stillschweigend als Zustimmung gelten.

Nach einer Bestätigung müsste die Anwendung prüfen, ob die gemeinte Probe noch dieselbe ist, und anschließend das tatsächliche Ergebnis melden. Beim Abbruch bleibt der Vorgang unverändert. Diese Regel muss implementiert und getestet werden; die Textskizze allein beweist sie nicht.

Das Beispiel wurde nicht als Fenster erzeugt oder bedient. Es wurden keine Daten verworfen und keine echte Bestätigungsentscheidung abgefragt.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Fenster ist eine allgemeinere Darstellungsform. Ein Dialog besitzt eine begrenzte Aufgabenrolle. Ein Hinweis innerhalb einer bestehenden Ansicht braucht nicht zwingend ein Zusatzfenster. Modalität beschreibt eine Bedienbeschränkung und ist nicht bereits mit dem Wort Dialog festgelegt.

## 8. Häufige Missverständnisse

Ein Dialog ist nicht immer klein oder modal. Das Schließen bedeutet nicht automatisch Zustimmung. Ein bestätigter Wert ist nicht zwingend fachlich gültig. Auch ersetzt ein Warnhinweis keine korrekte Umsetzung der nachfolgenden Aktion oder eine vollständige Fehlerbehandlung.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Nenne Ziel, Wirkung und verständliche Ausgänge. Vermeide unnötige Rückfragen für harmlose Alltagsaktionen, aber mache relevante Folgen nachvollziehbar. Das Gedankenbeispiel behauptet keine Modalitäts-, Fokus- oder Reader-Prüfung und verändert keine vorhandenen Daten.

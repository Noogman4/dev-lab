# Semantik

## 1. Kurzbeschreibung

Semantik bezeichnet die Bedeutung von Sprachbestandteilen und Programmen. Sie erklärt, was eine gültige Schreibweise bewirkt oder welchen Wert ein Ausdruck liefert. Die Quelle weist zu Recht darauf hin, dass syntaktisch gültiger Code trotzdem fachlich falsch sein kann. Formale Zulässigkeit und passende Wirkung beantworten unterschiedliche Fragen.

## 2. Was bedeutet der Begriff?

Wenn ein Ausdruck zwei Werte mit `+` verbindet, reicht es nicht, dass die Zeichenfolge erlaubt ist. Für das Verständnis muss auch feststehen, ob Zahlen addiert oder etwa Texte zusammengefügt werden. Die betreffende Sprache und die beteiligten Typen bestimmen diese Bedeutung.

Davon zu unterscheiden ist das Ziel der Anwendung. Eine Sprache kann einen Vergleich völlig eindeutig ausführen, obwohl der Entwickler den falschen Vergleich für die gewünschte Regel gewählt hat. Die Sprachsemantik kann also korrekt umgesetzt sein, während das Programm seine fachliche Anforderung verfehlt.

## 3. Einfacher Vergleich aus dem Alltag

Der Satz „Lege den roten Ordner auf den Tisch“ kann grammatisch richtig sein. Seine Bedeutung umfasst eine konkrete Handlung mit einem bestimmten Gegenstand. Wollte jemand eigentlich den blauen Ordner haben, war die formulierte Anweisung trotzdem die falsche für sein Ziel.

Der Vergleich hat Grenzen: Natürliche Sprache kann stark vom Gesprächskontext abhängen. Programmiersprachen legen viele Bedeutungen genauer fest. Dennoch bleiben Daten, Einheiten und Anforderungen außerhalb der bloßen Schreibweise entscheidend dafür, ob das Programm sinnvoll arbeitet.

## 4. Wie funktioniert das?

Die Sprachbeschreibung ordnet gültigen Konstruktionen Verhalten zu. In Python bezeichnet `>` einen streng größeren Wert, während `>=` Gleichheit einschließt. Die [Referenz zu Vergleichen](https://docs.python.org/3.13/reference/expressions.html#comparisons) beschreibt diese Regeln und ihre Verknüpfungen. Welche Grenze eine konkrete Aufgabe braucht, muss zusätzlich festgelegt werden.

Auch Typen beeinflussen die Bedeutung. `*` kann in Python Zahlen multiplizieren oder eine Folge mit einem Integer wiederholen. Die [Referenz zu binären Rechenoperationen](https://docs.python.org/3.13/reference/expressions.html#binary-arithmetic-operations) nennt die passenden Operandenkombinationen. Nur das sichtbare Zeichen zu kennen, genügt deshalb nicht für jede Rechnung.

Die Bedeutung eines Programms erschließt sich außerdem aus Reihenfolge, Zustand und möglichen Fehlerpfaden. Eine einzelne Zeile losgelöst vom umgebenden Code kann dafür zu wenig sein.

## 5. Wo begegnet mir das unter Linux?

Ein Diagnosewerkzeug kann einen Zähler technisch korrekt mit einer Grenze vergleichen und trotzdem die falsche Warnung anzeigen. Vielleicht wurde „mindestens“ mit „größer als“ verwechselt oder eine Zeit in Millisekunden als Sekunden interpretiert. Solche Fehler werden durch eine reine Syntaxprüfung nicht gefunden.

Beim Lesen fremder Skripte helfen deshalb Fragen wie: Welche Werte liegen vor? Welche Einheit besitzen sie? Was soll das Ergebnis ausdrücken? Die Bedeutung einer Shell-Konstruktion muss wiederum nach den Shell-Regeln beurteilt werden, nicht nach einer ähnlich aussehenden Python-Schreibweise.

## 6. Konkretes Beispiel Schritt für Schritt

Die festgelegte Lernregel lautet: „Achtzehn und größere Werte sollen akzeptiert werden.“ Das vollständige Python-3-Beispiel vergleicht zwei gültige Ausdrücke:

```python
alter = 18
streng = alter > 18
einschliesslich = alter >= 18
assert streng is False
assert einschliesslich is True
assert all((wert >= 18) == erwartet for wert, erwartet in [(17, False), (18, True), (19, True)])
print(streng)
print(einschliesslich)
```

Die Ausgabe lautet:

```text
False
True
```

Beide Vergleiche lassen sich ausführen. Nur der zweite passt zur genannten Regel. Die zusätzliche Zusicherung prüft drei Grenzfälle. Hier liegt kein Widerspruch in der Sprache vor, sondern eine mögliche Verwechslung zwischen gewünschter Regel und gewähltem Ausdruck. Das Beispiel ist keine tatsächliche Alters- oder Berechtigungsprüfung.

## 7. Abgrenzung zu ähnlichen Begriffen

Syntax beschreibt gültige Strukturen. Semantik beschreibt deren Bedeutung. Eine Anforderung beschreibt das gewünschte Verhalten einer Anwendung. Ein Test vergleicht beobachtetes Verhalten mit einer Erwartung. Diese Erwartung muss selbst aus einer verlässlichen Anforderung stammen und kann ebenfalls falsch gewählt sein.

## 8. Häufige Missverständnisse

Eine erfolgreiche Ausführung beweist nicht die fachliche Richtigkeit. Ebenso ist ein falsches Ergebnis nicht immer ein Syntaxfehler. Eine Programmbeschreibung wie „macht das Richtige“ reicht nicht aus, wenn die Bedeutung der Eingaben und der Grenzfälle unklar bleibt.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Formuliere vor der Umsetzung beobachtbare Erwartungen. Prüfe Einheiten, Grenzwerte und Sonderzustände. Besonders bei Schutzentscheidungen können formal gültige, aber fachlich falsche Vergleiche erhebliche Folgen haben. Das Lernbeispiel verwendet ausschließlich eigene Zahlen und hat keine Wirkung auf reale Konten oder Dienste.

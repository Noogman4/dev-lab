# Injection

## 1. Kurzbeschreibung

Injection bezeichnet das Einschleusen unbeabsichtigter Anweisungsbestandteile in einen verarbeitenden Kontext. Das Problem entsteht, wenn nicht vertrauenswürdige Daten als Teil einer Sprache oder eines Befehls interpretiert werden. SQL Injection ist ein bekannter Fall. Die passende Gegenmaßnahme hängt davon ab, welcher Interpreter oder welche Schnittstelle die Daten verarbeitet.

## 2. Was bedeutet der Begriff?

Die Quelle spricht von fremden Befehlen. Dafür muss nicht immer ein vollständiger zusätzlicher Befehl eingeschleust werden. Schon eine veränderte Bedingung kann die Bedeutung einer Datenbankabfrage unerlaubt ändern. Die entscheidende Grenze liegt zwischen vorgesehenen Anweisungen und variablen Daten.

Der [OWASP-Leitfaden zur Vermeidung von SQL Injection](https://raw.githubusercontent.com/OWASP/CheatSheetSeries/master/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.md) beschreibt diese Vermischung und empfiehlt getrennte SQL-Struktur und gebundene Werte. Daten können dabei auch aus gespeicherten Beständen oder anderen Diensten stammen. „Kam nicht direkt aus einem Eingabefeld“ ist deshalb kein ausreichender Vertrauensnachweis.

## 3. Einfacher Vergleich aus dem Alltag

Ein Formular enthält eine Rubrik für den Namen. Der eingetragene Text soll als Name behandelt werden, nicht als neue Arbeitsanweisung für die Sachbearbeitung. Problematisch wäre es, wenn ein Satz im Namensfeld plötzlich die Regeln des gesamten Vorgangs verändern könnte.

Die Grenze: Softwareinterpreten besitzen genaue Syntaxregeln. Ein allgemeines menschliches Verständnis genügt nicht, um alle Sonderfälle richtig zu behandeln. Außerdem unterscheiden sich Sprachen. Eine für SQL passende Behandlung lässt sich nicht ungeprüft auf eine Shell oder HTML übertragen.

## 4. Wie funktioniert das?

Eine gefährliche Konstruktion baut eine Anweisung aus festen Teilen und fremd beeinflussten Zeichenketten zusammen. Werden die variablen Teile dabei als Syntax ausgewertet, kann sich die beabsichtigte Bedeutung ändern. Ein geeigneter Ansatz hält den Anweisungsrahmen von den Datenwerten getrennt.

Bei SQL können Parameter Werte über die Datenbankschnittstelle binden. Das ersetzt nicht automatisch beliebige Tabellen- oder Spaltennamen. Solche Strukturentscheidungen sollten aus einer kontrollierten Menge anwendungseigener Möglichkeiten stammen. Das bloße Einfügen eines Fragezeichens an einer ungeeigneten Stelle löst nicht jedes dynamische SQL-Problem.

Für Betriebssystemaufrufe erläutert der [OWASP-Leitfaden zur Command-Injection-Abwehr](https://raw.githubusercontent.com/OWASP/CheatSheetSeries/master/cheatsheets/OS_Command_Injection_Defense_Cheat_Sheet.md) eigene Regeln. Wo möglich sollte die gewünschte Arbeit über eine passende Bibliothek statt über zusammengesetzte Befehle erfolgen. Auch getrennte Argumente brauchen einen sinnvollen fachlichen Vertrag: Ein Programm kann bestimmte Argumente selbst als Optionen oder weitere Anweisungen deuten.

Eingabeprüfung ergänzt die sichere Schnittstelle, ersetzt sie aber nicht. Ein pauschales Entfernen einiger vermeintlich gefährlicher Zeichen kann legitime Daten beschädigen und andere Fälle übersehen. Welche Eingaben fachlich gültig sind, ist eine eigene Frage.

## 5. Wo begegnet mir das unter Linux?

Programme lesen Texte und verwenden Datenbanken oder externe Werkzeuge. Jede Übergabe an einen Interpreter braucht die passende Trennung. Ein harmlos aussehender Anzeigename kann beispielsweise ein Apostroph enthalten und trotzdem ein vollständig legitimer Wert sein.

Die Auswirkungen hängen von der betroffenen Schnittstelle und deren Befugnissen ab. Least Privilege kann den möglichen Umfang begrenzen, ersetzt aber nicht die korrekte Datenübergabe. Das folgende Beispiel verwendet nur eine eigene Speicherdatenbank und keine Shell oder Netzwerkverbindung.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 und SQLite 3.46.1 in einem temporären Arbeitsordner ausgeführt. Es demonstriert ausschließlich die sichere Wertbindung. Eine unsichere Abfrage wird nicht ausgeführt; sämtliche Datensätze sind erfunden.

```python
from contextlib import closing
import sqlite3

with closing(sqlite3.connect(":memory:")) as db:
    db.execute("CREATE TABLE namen (id INTEGER PRIMARY KEY, name TEXT NOT NULL)")
    db.executemany("INSERT INTO namen VALUES (?, ?)", [
        (1, "Probe"), (2, "O'Reilly")
    ])
    sql = "SELECT name FROM namen WHERE name = ? ORDER BY id"
    normal = db.execute(sql, ("O'Reilly",)).fetchall()
    ungewoehnlich = db.execute(sql, ("' OR 1=1 --",)).fetchall()
    assert normal == [("O'Reilly",)]
    assert ungewoehnlich == []
    assert db.execute("SELECT COUNT(*) FROM namen").fetchone() == (2,)
    print("Legitimer Name:", normal[0][0])
    print("Treffer für den anderen Datenwert:", len(ungewoehnlich))
```

Geprüfte Ausgabe:

```text
Legitimer Name: O'Reilly
Treffer für den anderen Datenwert: 0
```

Das Apostroph im Namen bleibt ein zulässiger Datenbestandteil. Auch der zweite ungewöhnliche Text wird als Wert behandelt und verändert die Abfragelogik nicht. Beide ursprünglichen Zeilen bleiben vorhanden. Die Prüfung beweist keine allgemeine Sicherheit einer vorhandenen Anwendung oder anderer Interpreter.

## 7. Abgrenzung zu ähnlichen Begriffen

Inputprüfung beurteilt fachliche Zulässigkeit. Parameterbindung trennt Werte von SQL-Struktur. Kontextgerechtes Escaping behandelt besondere Zeichen nach einer bestimmten Syntax. Dependency Injection bezeichnet dagegen ein Entwurfsmuster zur Übergabe von Abhängigkeiten und ist kein solcher Angriff.

## 8. Häufige Missverständnisse

Nicht jede ungewöhnliche Eingabe ist ein Angriff. Das Verbieten weniger Zeichen ist kein universeller Schutz. SQL-Parameter ersetzen nicht jede dynamische Struktur. Und Daten aus einer Datenbank sind nicht allein wegen ihrer Speicherung für jeden anderen Interpreter vertrauenswürdig.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Nutze die vorgesehene Schnittstelle für den jeweiligen Kontext. Prüfe Grenzfälle mit eigenen Daten und begrenze Befugnisse. Das Beispiel versucht keinen Zugriff auf fremde Systeme und führt weder externe Befehle noch unsichere Varianten aus.

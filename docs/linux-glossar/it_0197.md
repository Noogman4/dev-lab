# Primärschlüssel

## 1. Kurzbeschreibung

Ein Primärschlüssel legt fest, woran eine Tabelle ihre einzelnen Datensätze eindeutig erkennt. Er kann aus einer Spalte oder mehreren Spalten gemeinsam bestehen. Standardkonforme Primärschlüssel erfordern eindeutige, vollständige Werte. Für fehlende Werte gibt es in SQLite eine historische Ausnahme, die Abschnitt 4 erläutert. Der Schlüssel ist weder automatisch eine laufende Nummer noch eine bestimmte Position in einer Ergebnisliste.

## 2. Was bedeutet der Begriff?

Das Katalogbeispiel `id` ist eine verbreitete Benennung. Entscheidend ist jedoch die festgelegte Bedingung, nicht der Spaltenname. Eine Spalte namens `id` ohne entsprechende Regeln garantiert keine Eindeutigkeit. Ebenso muss ein Primärschlüssel nicht so heißen und nicht numerisch sein.

Die [PostgreSQL-Dokumentation zu Primärschlüsseln](https://www.postgresql.org/docs/current/ddl-constraints.html#DDL-CONSTRAINTS-PRIMARY-KEYS) beschreibt die eindeutige, nicht fehlende Identifikation und ausdrücklich auch mehrteilige Schlüssel. Eine Tabelle besitzt höchstens eine Primärschlüsselbedingung. Diese kann trotzdem mehrere Spalten umfassen. Daneben sind weitere Eindeutigkeitsbedingungen möglich.

## 3. Einfacher Vergleich aus dem Alltag

Eine Platzreservierung kann durch Saal und Sitznummer gemeinsam bestimmt sein. Sitz 1 in Saal A ist ein anderer Platz als Sitz 1 in Saal B. Innerhalb desselben Saals darf derselbe Platz für denselben Vorstellungstermin nicht zweimal vergeben sein; der Termin müsste gegebenenfalls ebenfalls zum Schlüssel gehören.

Die Grenze des Vergleichs: Welche Angaben tatsächlich eindeutig sind, entscheidet das Datenmodell. Ein ungeeignet gewählter Schlüssel wird nicht dadurch fachlich richtig, dass die Datenbank ihn technisch durchsetzt. Veränderliche Namen oder unsicher zugeordnete Termine brauchen besondere Aufmerksamkeit.

## 4. Wie funktioniert das?

Beim Einfügen und Ändern prüft das Datenbanksystem die festgelegte Schlüsselkombination. Der gewöhnliche `INSERT` im SQLite-Beispiel wird bei einer Kollision abgelehnt. SQLite kann je nach gewählter Konfliktregel auch die Einfügung überspringen oder die vorhandene Zeile ersetzen. PostgreSQL unterstützt ebenfalls alternative Konfliktaktionen bei `INSERT`. [SQLite-Konfliktregeln](https://www.sqlite.org/lang_conflict.html) · [PostgreSQL `INSERT`](https://www.postgresql.org/docs/current/sql-insert.html#SQL-ON-CONFLICT)

Eindeutigkeit bezieht sich auf den Schlüssel. Zwei unterschiedliche Personen können beispielsweise denselben Anzeigenamen besitzen. In gewöhnlichen SQLite-Tabellen können Primärschlüsselspalten aus historischen Gründen `NULL` zulassen. Bei der Eindeutigkeitsprüfung behandelt SQLite zwei `NULL`-Werte als verschieden. Für `INTEGER PRIMARY KEY`, `STRICT`-Tabellen und `WITHOUT ROWID`-Tabellen gelten besondere Regeln. [SQLite-Primärschlüsselregeln](https://www.sqlite.org/lang_createtable.html#the_primary_key)

Das Beispiel legt für beide Schlüsselspalten ausdrücklich `NOT NULL` fest. Es ist damit unabhängig von dieser historischen Ausnahme. Eine automatische Nummernvergabe ist ein eigenes Thema und wird hier weder eingerichtet noch vorausgesetzt.

## 5. Wo begegnet mir das unter Linux?

Adressbücher, Paketverwaltungen und andere Anwendungen müssen Datensätze zuverlässig wiederfinden. Oft sieht man dabei technische Kennungen. Aus dem bloßen Namen einer angezeigten Spalte lässt sich aber nicht sicher auf deren Datenbankbedingungen schließen.

Eine Listenposition eignet sich nicht als Ersatz: Nach Sortieren oder Filtern kann derselbe Datensatz an anderer Stelle erscheinen. Auch ein Schlüssel ist nicht automatisch ein Geheimnis, eine Berechtigung oder eine weltweit eindeutige Kennung. Sein Geltungsbereich ergibt sich aus dem Modell.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses vollständige Beispiel wurde mit Python 3.13 und SQLite 3.46.1 in einem temporären Arbeitsordner ausgeführt. Die eigene Datenbank existiert nur im Arbeitsspeicher.

```python
from contextlib import closing
import sqlite3

with closing(sqlite3.connect(":memory:")) as db:
    db.execute("""CREATE TABLE plaetze (
        saal TEXT NOT NULL,
        nummer INTEGER NOT NULL,
        titel TEXT,
        PRIMARY KEY (saal, nummer)
    )""")
    db.executemany("INSERT INTO plaetze VALUES (?, ?, ?)", [
        ("A", 1, "Probe"), ("B", 1, "Probe")
    ])
    abgelehnt = 0
    for datensatz in [("A", 1, "Andere"), (None, 2, "Probe")]:
        try:
            db.execute("INSERT INTO plaetze VALUES (?, ?, ?)", datensatz)
        except sqlite3.IntegrityError:
            abgelehnt += 1
    anzahl = db.execute("SELECT COUNT(*) FROM plaetze").fetchone()[0]
    assert anzahl == 2 and abgelehnt == 2
    print("Gespeicherte Plätze:", anzahl)
    print("Abgelehnte Einfügungen:", abgelehnt)
```

Geprüfte Ausgabe:

```text
Gespeicherte Plätze: 2
Abgelehnte Einfügungen: 2
```

Die gleiche Nummer in verschiedenen Sälen ist zulässig. Dieselbe vollständige Kombination und ein fehlender Saal werden dagegen abgelehnt. Das Beispiel prüft keine konkurrierenden Zugriffe oder Reservierungsanwendung.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine gewöhnliche Spalte besitzt nicht automatisch eine Schlüsselrolle. Eine Eindeutigkeitsbedingung kann zusätzliche alternative Kennungen absichern. Ein Index dient als Suchstruktur und ist nicht begrifflich mit einem Primärschlüssel gleichzusetzen, auch wenn Datenbanken ihn zur Durchsetzung verwenden können.

## 8. Häufige Missverständnisse

Ein Primärschlüssel muss nicht `id` heißen. Er besteht nicht zwingend aus genau einer Spalte. Er sortiert keine Abfrage automatisch. Gleiche Anzeigenamen verletzen keinen Schlüssel, wenn die eigentliche Kennung verschieden ist.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Wähle stabile Kennungen und dokumentiere ihren Geltungsbereich. Eine spätere Schlüsseländerung kann bestehende Verweise betreffen. Das eigene Beispiel ersetzt keine Prüfung einer produktiven Struktur; vorhandene Datenbanken werden weder geöffnet noch geändert.

## 10. Verwandte Begriffe

Die [Tabelle](it_0194.md) definiert Bedingungen. Eine [Zeile](it_0195.md) wird identifiziert. Eine [Spalte](it_0196.md) kann am Schlüssel beteiligt sein. [SQLite](it_0193.md) besitzt besondere Regeln. [Null](it_0011.md) beschreibt fehlende Werte.

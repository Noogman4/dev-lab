# Query

## 1. Kurzbeschreibung

Eine Query ist im Datenbankkontext eine Abfrage. Sie beschreibt, welche Informationen aus den verfügbaren Daten ermittelt werden sollen. Eine typische SQL-Abfrage verwendet `SELECT`. Sie kann einzelne Werte, mehrere Zeilen, berechnete Angaben oder ein leeres Ergebnis liefern. Abfragetext, Ausführung und Ergebnis sind dabei unterschiedliche Dinge.

## 2. Was bedeutet der Begriff?

Der Katalog nennt `SELECT name FROM stations`. Damit werden die Werte der Spalte `name` aus einer Tabelle angefordert. Die Anweisung sagt noch nichts über eine gewünschte Sortierung oder eine Beschränkung auf bestimmte Sender. Auch liefert sie nicht automatisch sämtliche Spalten jedes Datensatzes.

Das [PostgreSQL-Tutorial zum Abfragen einer Tabelle](https://www.postgresql.org/docs/current/tutorial-select.html) erklärt Auswahlliste, Datenquelle und Auswahlbedingungen. Für dieses Glossar meint Query eine Datenbankabfrage. In anderen Zusammenhängen kann das Wort etwa eine Suchanfrage oder einen URL-Bestandteil bezeichnen. Manche Programmierschnittstellen verwenden ähnliche Bezeichnungen außerdem für weiter gefasste SQL-Operationen. Aus dem Wort allein folgt deshalb keine allgemeine Zusicherung, dass ein beliebiger Aufruf nur liest.

## 3. Einfacher Vergleich aus dem Alltag

Du bittest eine Auskunft: „Nenne mir die geöffneten Filialen, alphabetisch nach Namen.“ Darin stecken mehrere Entscheidungen: Welche Sammlung wird betrachtet? Welche Einträge passen? Welche Angaben sollen erscheinen? In welcher Reihenfolge möchtest du sie sehen?

Die Grenze: Eine Datenbank erschließt keine unausgesprochenen Absichten. „Die passenden Sender“ genügt nicht als präzise Bedingung. Außerdem kann sich der Datenbestand zwischen zwei Abfragen ändern. Derselbe Abfragetext garantiert deshalb nicht zu jedem Zeitpunkt dieselben Werte.

## 4. Wie funktioniert das?

Eine einfache SQL-Abfrage benennt hinter `SELECT` die gewünschten Ergebnisausdrücke und hinter `FROM` die Datenquelle. `WHERE` schränkt passende Zeilen ein. `ORDER BY` legt die gewünschte Sortierung fest. Weitere Möglichkeiten sind beispielsweise Zusammenfassungen oder Verknüpfungen mehrerer Quellen.

Die [SQLite-Dokumentation zu SELECT](https://www.sqlite.org/lang_select.html) beschreibt diese Verarbeitung und ihre Ergebnisse. Ohne eine entsprechende Sortierangabe ist die Zeilenreihenfolge nicht garantiert. Auch nach einem Sortierfeld können Gleichstände übrig bleiben. Das Beispiel ergänzt daher die eindeutige Kennung als weiteres Sortierkriterium.

Eine Anwendung übergibt variable Werte sinnvollerweise getrennt vom SQL-Text. Die [Python-Dokumentation zu Platzhaltern](https://docs.python.org/3.13/library/sqlite3.html#sqlite3-placeholders) erklärt die Wertbindung und warnt vor dem Zusammenbauen von SQL mit Zeichenkettenoperationen. Ein Platzhalter für einen Wert ersetzt allerdings nicht beliebig einen Tabellen- oder Spaltennamen.

## 5. Wo begegnet mir das unter Linux?

Eine Anwendung kann bei jedem Öffnen einer Liste passende Daten abfragen. Der Benutzer sieht meist nur das Ergebnis. Eine leere Liste kann dabei eine korrekt ausgeführte Abfrage ohne Treffer sein. Sie bedeutet nicht automatisch, dass die gesamte Datenbank leer oder beschädigt ist.

Für die Fehlersuche sind Quelle, Filterwerte und erwartete Ergebnisform wichtig. Auch Berechtigungen oder ein anderer Datenstand können eine Rolle spielen. Hier wird keine Datenbank eines installierten Programms geöffnet und kein laufender Dienst angesprochen.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 und SQLite 3.46.1 in einem temporären Arbeitsordner ausgeführt. Es erzeugt drei eigene Datensätze ausschließlich im Arbeitsspeicher.

```python
from contextlib import closing
import sqlite3

with closing(sqlite3.connect(":memory:")) as db:
    db.execute("""CREATE TABLE stations (
        id INTEGER PRIMARY KEY,
        name TEXT NOT NULL,
        aktiv INTEGER NOT NULL
    )""")
    db.executemany("INSERT INTO stations VALUES (?, ?, ?)", [
        (1, "Beta", 1), (2, "Alpha", 1), (3, "Gamma", 0)
    ])
    sql = "SELECT name FROM stations WHERE aktiv = ? ORDER BY name, id"
    ergebnis = db.execute(sql, (1,)).fetchall()
    assert ergebnis == [("Alpha",), ("Beta",)]
    assert db.execute(sql, (99,)).fetchall() == []
    assert db.execute("SELECT COUNT(*) FROM stations").fetchone() == (3,)
    print("Treffer:", len(ergebnis))
    for (name,) in ergebnis:
        print(name)
```

Geprüfte Ausgabe:

```text
Treffer: 2
Alpha
Beta
```

Der Filter wählt zwei Zeilen aus. Die Auswahlliste gibt nur deren Namen zurück. Die Sortierung bestimmt ihre Reihenfolge. Der zusätzliche Test mit 99 liefert keinen Treffer; die gespeicherten drei Zeilen bleiben vorhanden. Es wird keine Leistungsmessung durchgeführt.

## 7. Abgrenzung zu ähnlichen Begriffen

SQL ist die Sprache, in der hier die Query formuliert wird. Eine Tabelle ist eine Datenstruktur. Ein Index kann bei ihrer Ausführung helfen. Das Abfrageergebnis ist wiederum weder der SQL-Text noch automatisch eine neue dauerhaft gespeicherte Tabelle.

## 8. Häufige Missverständnisse

Eine Query liefert nicht zwingend genau einen Wert. Kein Treffer ist nicht dasselbe wie ein Ausführungsfehler. Die Reihenfolge einer früheren Ausgabe ist keine dauerhafte Garantie. Und ein Name wie „query“ in einer Schnittstelle ersetzt nicht das Lesen ihres Vertrags.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Formuliere Filter und Ergebnisform ausdrücklich. Binde variable Werte über die vorgesehene Schnittstelle. Prüfe insbesondere, ob du einen Datensatz oder viele erwartest. Das ausgeführte Beispiel beschränkt sich auf eigene Speicherdaten und prüft keine fremden Datenquellen.

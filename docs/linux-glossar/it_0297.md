# Breakpoint

## 1. Kurzbeschreibung

Ein Breakpoint ist ein Haltepunkt für einen Debugger. Er legt fest, an welcher Stelle oder unter welchen Bedingungen ein laufendes Programm anhalten soll. Im angehaltenen Zustand kannst du etwa lokale Variablen und die Kette der Funktionsaufrufe untersuchen.

## 2. Was bedeutet der Begriff?

Die [Python-Referenz zu pdb](https://docs.python.org/3.13/library/pdb.html) beschreibt Haltepunkte in Dateien und Funktionen sowie Bedingungen. Ein Haltepunkt kann in einer Debugger-Oberfläche gesetzt oder durch einen Aufruf im Code angestoßen werden. Ob er erreicht wird, hängt vom tatsächlichen Ausführungspfad und der Laufzeit ab.

## 3. Einfacher Vergleich aus dem Alltag

Auf einem Rundgang legst du vorher fest, an welcher Station die Gruppe stehen bleibt. Eine Bedingung kann den Stopp auf bestimmte Besuche beschränken. Ein Programm kann dieselbe Stelle allerdings sehr häufig ausführen. Eine ungeschickt gewählte Bedingung kann dann die Untersuchung verlangsamen.

## 4. Wie funktioniert das?

Der Debugger ordnet einen Haltepunkt einer ausführbaren Stelle zu. Er hält beim Erreichen an, wenn eine angegebene Bedingung erfüllt ist. Ein bedingter Haltepunkt hilft etwa, wenn ein Schleifenschritt nur beim Wert null interessant ist.

Das Anhalten wirkt auf den beobachteten Ablauf. Bei mehreren Threads hängt das Verhalten vom Debugger und seiner Einstellung ab. Ein Timingproblem kann beim Anhalten verschwinden oder anders auftreten.

## 5. Wo begegnet mir das unter Linux?

Unter Linux setzen IDEs und Terminaldebugger Haltepunkte über ihre jeweiligen Schnittstellen. Python bietet zusätzlich `breakpoint()`. Der Aufruf delegiert an einen Hook, also eine austauschbare Funktion. Standardmäßig kann daraus eine interaktive Debuggersitzung entstehen.

## 6. Konkretes Beispiel Schritt für Schritt

Das Beispiel ersetzt den Hook im eigenen Prozess durch eine Funktion mit sichtbarer Ausgabe. Der Aufruf prüft den Übergabepunkt. Danach wird der ursprüngliche Hook auch bei einem Fehler wiederhergestellt.

```python
import sys

original = sys.breakpointhook
try:
    sys.breakpointhook = lambda: print("Haltepunkt erreicht")
    breakpoint()
finally:
    sys.breakpointhook = original
```

Die Ausgabe lautet `Haltepunkt erreicht`. Diese Prüfung verifiziert die Delegation an den Hook und hält die Ausführung nicht interaktiv an.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Einzelschritt beginnt an der aktuellen Stelle. Ein Breakpoint lässt die Ausführung bis zum definierten Ziel weiterlaufen. Ein Watchpoint beobachtet nach den Regeln seines Werkzeugs einen Wert oder Speicherzugriff. Das [GDB-Handbuch](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Breakpoints.html) erläutert diese Möglichkeiten gemeinsam.

## 8. Häufige Missverständnisse

Eine Markierung am Zeilenrand garantiert keinen Stopp. Der betreffende Code muss erreicht und der Haltepunkt dem laufenden Programm zugeordnet werden. Eine reine Kommentarzeile besitzt möglicherweise keine ausführbare Entsprechung.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Entferne vor einer Veröffentlichung versehentlich im Programm belassene interaktive Haltepunkte. Im Debugger gezeigte Variablen können private Daten enthalten. Beobachte Zeit- oder Threadfehler zusätzlich mit einer Methode, die zu diesem Fehler passt.

# Frontend

## 1. Kurzbeschreibung

Das Frontend ist der Teil einer Anwendung, über den Menschen Inhalte wahrnehmen und mit dem System interagieren. Dazu gehören Oberflächen, Eingaben und deren Rückmeldungen. Der Ausdruck „sichtbarer Teil“ ist ein guter Einstieg, umfasst aber nicht alles: Auch Bedienlogik und zugängliche Ausgabeformen gehören zur Gestaltung dieses Zugangs.

## 2. Was bedeutet der Begriff?

„Front“ bezeichnet hier die dem Benutzer zugewandte Seite. Bei einer Webanwendung läuft ein Teil davon im Browser. HTML, CSS und JavaScript können dabei unterschiedliche Aufgaben übernehmen. Eine Desktopanwendung kann ihren Zugang mit anderen Oberflächentechniken umsetzen.

Die [Mozilla-Dokumentation zum Client-Server-Ablauf](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Server-side/First_steps/Client-Server_overview) beschreibt, wie Browserdarstellung und serverseitige Verarbeitung zusammenwirken. Die Grenze ist eine Architekturentscheidung, keine allgemeine Vorgabe einer bestimmten Programmiersprache. Das Katalogbeispiel mit Buttons und Formularfeldern nennt typische Bestandteile, nicht die ganze Definition.

## 3. Einfacher Vergleich aus dem Alltag

Ein Kundenschalter macht Leistungen einer Organisation zugänglich. Dort werden Informationen angezeigt, Anliegen aufgenommen und Rückmeldungen verständlich vermittelt. Die Arbeit im Hintergrund kann anders organisiert sein.

Die Grenze: Ein Frontend ist kein menschlicher Mitarbeiter, der fehlende Angaben beliebig ergänzt. Es verarbeitet definierte Ereignisse und Zustände. Außerdem darf ein freundlicher Schalter nicht die einzige Instanz sein, die Berechtigungen prüft. Eine Oberfläche kann falsche oder manipulierte Angaben erhalten.

## 4. Wie funktioniert das?

Das Frontend nimmt Eingaben entgegen, hält benötigten Darstellungszustand und zeigt Ergebnisse. Dazu kann es Anfragen an andere Komponenten senden. Während einer Anfrage muss es gegebenenfalls zwischen „noch nicht geladen“, „wird geladen“, „Ergebnis vorhanden“ und „fehlgeschlagen“ unterscheiden.

Eingabeprüfungen können Menschen unmittelbar helfen. Die [W3C-Anleitung zur Formularvalidierung](https://www.w3.org/WAI/tutorials/forms/validation/) erläutert verständliche Prüfungen und Fehlerhinweise. Eine Prüfung im Browser ersetzt aber keine notwendige serverseitige Kontrolle. Das Verstecken eines Buttons ist keine ausreichende Berechtigungsregel für die dahinterliegende Funktion.

## 5. Wo begegnet mir das unter Linux?

Browseranwendungen und native Desktopprogramme besitzen benutzerseitige Zugänge. Ein Frontend muss nicht ausschließlich eine grafische Webseite sein; der konkrete Begriff richtet sich nach der Architektur. Eine Textschnittstelle kann ebenfalls eine nutzernahe Zugangsschicht bilden.

Bei einer Diagnose muss außerdem unterschieden werden, ob Anzeige, Anfrage oder Fachverarbeitung betroffen sind. Eine leere Ergebnisansicht kann beispielsweise an einem noch laufenden Abruf liegen. Sie beweist nicht automatisch, dass der Datenbestand leer ist.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses Gedankenmodell beschreibt eine fiktive Statusansicht. Es wurde keine Oberfläche erstellt oder getestet.

```text
Ausgangszustand: Noch kein Ergebnis geladen.
Benutzer wählt „Aktualisieren“.
Frontend zeigt einen laufenden Abruf und verhindert widersprüchliche Rückmeldung.
Eine erfolgreiche Antwort wird geprüft und verständlich dargestellt.
Bei einem Fehler erscheint eine passende Erklärung statt eines erfundenen Ergebnisses.
```

Der letzte Schritt ist besonders wichtig: „Nicht ermittelt“ und „alles in Ordnung“ sind verschiedene Zustände. Die Oberfläche sollte sie nicht versehentlich gleich darstellen. Ebenso muss sie nicht zwangsläufig jede interne technische Meldung unverändert anzeigen; die Rückmeldung soll zur Aufgabe passen.

Das Modell legt keine konkrete Technik fest. Es enthält weder eine tatsächlich gemessene Antwort noch eine Reader- oder Bedienabnahme. Eine reale Prüfung müsste unter anderem Tastaturbedienung, Fehlersituationen und unterschiedliche verfügbare Größen berücksichtigen.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine GUI ist eine bestimmte grafische Bedienungsform. Das Frontend beschreibt eine Rolle in der Anwendung. Eine API ist ein programmatischer Zugang, den ein Frontend nutzen kann. Die fachliche Datenverarbeitung oder Speicherung kann in anderen Komponenten stattfinden. Diese Aufteilung muss nicht mit genau zwei Prozessen übereinstimmen.

## 8. Häufige Missverständnisse

Frontend bedeutet nicht bloß Dekoration. Ein ausgeblendetes Feld ist auch nicht automatisch vor einem manipulierten Aufruf geschützt. Eine schöne Anzeige bestätigt keine richtigen Daten. Umgekehrt muss ein Fehler in der Darstellung nicht bedeuten, dass die zugrunde liegende Fachoperation ebenfalls fehlgeschlagen ist.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Beschreibe Zustände und Rückmeldungen ausdrücklich. Prüfe reale Eingaben und Berechtigungen an den zuständigen Stellen. Dieser Eintrag verändert keine Oberfläche, Anwendung, API oder Tests und führt keine Benutzeraktion in einem echten System aus.

## 10. Verwandte Begriffe

[HTML](it_0178.md), [CSS](it_0179.md) und [JavaScript](it_0180.md) können Weboberflächen umsetzen. Die [GUI](it_0064.md) ist eine Bedienungsform. Eine [API](it_0169.md) vermittelt Programmanfragen. Ein [Request](it_0172.md) und eine [Response](it_0173.md) betreffen den Austausch.

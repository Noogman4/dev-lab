# Baum

## 1. Kurzbeschreibung

Ein Baum ist eine Datenstruktur, die Beziehungen ohne geschlossene Verbindungswege darstellen kann. In einer verwurzelten Darstellung steht ein Knoten als Wurzel am Anfang; darunter liegen Kinder und weitere Unterebenen. Das eignet sich für Hierarchien. Ein Baum muss nicht binär sein: Ein Knoten kann je nach Modell beliebig viele Kinder besitzen.

## 2. Was bedeutet der Begriff?

Mathematisch wird ein ungerichteter Baum als zusammenhängender Graph ohne Zyklen beschrieben. Ein Zyklus wäre ein geschlossener Weg über Verbindungen zurück zum Ausgangsknoten, ohne einfach dieselbe Kante zurückzugehen. Die [offizielle NetworkX-Dokumentation zu is_tree](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.tree.recognition.is_tree.html) nennt diese Definition und weist auf verschiedene Konventionen für gerichtete Bäume hin.

Eine Wurzel ist eine zusätzliche Festlegung für die hierarchische Sicht. Jeder andere Knoten besitzt dann einen eindeutigen Elternpfad zur Wurzel. Ein Blatt hat keine Kinder. Die Rollen ergeben sich aus den Beziehungen, nicht allein aus einem Namen oder einer Zeichnung.

## 3. Einfacher Vergleich aus dem Alltag

Ein übersichtliches Ordnerschema zeigt einen Hauptordner, Unterordner und darin abgelegte Inhalte. Du kannst einem Pfad von oben nach unten folgen. Die Darstellung hilft, Zugehörigkeit und Untergliederung zu verstehen.

Die Grenze des Vergleichs: Ein reales Dateisystem mit symbolischen Links oder mehreren Verweisen kann komplexer sein als ein einfacher Baum. Auch haben Knoten in technischen Strukturen nicht zwingend lesbare Dateinamen. Das Ordnerbild erklärt eine Hierarchie, aber nicht sämtliche Eigenschaften eines Betriebssystems.

## 4. Wie funktioniert das?

Ein Programm speichert Knoten und Beziehungen zwischen ihnen. Beim Durchlaufen werden von einem Ausgangspunkt aus Kinder besucht. Die gewählte Besuchsreihenfolge ist ein Algorithmus; sie wird nicht allein durch das Wort Baum festgelegt. Eine Suche nach Namen benötigt außerdem eine Regel für mögliche gleiche Namen.

XML-Dokumente werden häufig als Elementhierarchie verarbeitet. Pythons `ElementTree` kann über `Element` und `SubElement` eigene Elemente samt Unterelementen erzeugen. Das [offizielle Beispiel zum Aufbau von XML-Dokumenten](https://docs.python.org/3.13/library/xml.etree.elementtree.html#building-xml-documents) erläutert diese Schnittstelle. Das ist eine konkrete Anwendung des Hierarchiemodells, keine allgemeine Festlegung, dass jeder Baum XML enthalten müsse.

## 5. Wo begegnet mir das unter Linux?

Dateimanager zeigen Verzeichnisse häufig in Baumform. Konfigurationsdaten und Programmstrukturen können ebenfalls hierarchisch aufgebaut sein. Eine grafische Anwendung kann daraus aufklappbare Ansichten erzeugen.

Die sichtbare Darstellung muss vom vollständigen Datenmodell unterschieden werden. Ein zugeklappter Zweig ist nicht gelöscht. Eine Ansicht kann außerdem nur einen Ausschnitt oder eine gewählte Gruppierung zeigen. Für Aussagen über reale Dateien wären gesonderte Dateisystemprüfungen nötig.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel erzeugt ausschließlich eigene Elemente im Speicher:

```python
import xml.etree.ElementTree as ET

wurzel = ET.Element("wurzel")
ordner = ET.SubElement(wurzel, "ordner")
ET.SubElement(ordner, "datei")
hinweis = ET.SubElement(wurzel, "hinweis")
namen = [element.tag for element in wurzel.iter()]
assert list(wurzel) == [ordner, hinweis]
assert namen == ["wurzel", "ordner", "datei", "hinweis"]
assert len(list(ordner)) == 1
print(namen)
```

Die Ausgabe lautet:

```text
['wurzel', 'ordner', 'datei', 'hinweis']
```

Die Wurzel besitzt zwei direkte Kinder. Der Ordner besitzt ein weiteres Kind. Der Durchlauf besucht im Beispiel zunächst dessen Unterebene. Die Bezeichnungen sind nur Elementnamen: Es werden weder Ordner angelegt noch Dateien geöffnet oder ein echtes Verzeichnis untersucht.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein allgemeiner Graph kann Zyklen und zusätzliche Verbindungen enthalten. Ein Baum schränkt diese Struktur ein. Eine Liste besitzt eine lineare Reihenfolge statt einer verzweigten Hierarchie. Ein Suchbaum verwendet zusätzliche Ordnungsregeln; nicht jeder Baum eignet sich automatisch für schnelle Wertsuche.

## 8. Häufige Missverständnisse

Ein Baum ist nicht zwingend binär, sortiert oder ausgeglichen. Nicht jeder Baum besitzt von sich aus eine ausgezeichnete Wurzel. Ein gezeichneter Verweis kann eine zusätzliche Beziehung sein, die das einfache Baummodell verlässt. Auch garantieren tiefe Hierarchien keine effiziente Suche.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lege Elternbeziehungen, Besuchsreihenfolge und Behandlung zusätzlicher Verweise fest. Prüfe große Tiefe und unbeabsichtigte Kreise, wenn ein freies Datenmodell verwendet wird. Das Beispiel verarbeitet keine fremden XML-Dokumente und verfolgt keine realen Dateisystemlinks. NetworkX wurde nicht ausgeführt oder installiert.

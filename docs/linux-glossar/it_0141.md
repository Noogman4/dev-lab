# IPv6

## 1. Kurzbeschreibung

IPv6 ist Version sechs des Internet Protocol. Ihre Adressen sind 128 Bit lang. Sie bietet damit einen wesentlich größeren Adressraum als IPv4 und besitzt eigene Regeln für Pakete und Adressierung. IPv6 ist deshalb mehr als eine längere Schreibweise vorhandener IPv4-Adressen. Eine Anwendung und ihr Kommunikationsweg müssen die jeweilige Version unterstützen.

## 2. Was bedeutet der Begriff?

Die [IPv6-Grundspezifikation RFC 8200](https://www.rfc-editor.org/rfc/rfc8200.html) beschreibt das Protokoll und den Wechsel von 32 auf 128 Adressbits. Das Katalogbeispiel `2001:db8::1` zeigt eine verkürzte Textdarstellung. Der Bereich `2001:db8::/32` ist durch [RFC 3849](https://www.rfc-editor.org/rfc/rfc3849.html) für Dokumentation reserviert; die Beispieladresse ist keine festgestellte Gegenstelle dieses Rechners.

Eine größere Adressmenge bedeutet nicht automatisch schnellere Übertragung oder eine sichere Anwendung. Adressgröße, Leistungsfähigkeit und Zugriffsschutz sind getrennte Eigenschaften. Ebenso verschwindet IPv4 nicht allein dadurch, dass ein System zusätzlich IPv6 unterstützt.

## 3. Einfacher Vergleich aus dem Alltag

Ein größeres Adressbuch bietet mehr Platz für Einträge und kann anders gegliedert sein. Damit lassen sich mehr Ziele beschreiben. Ob ein Brief schnell oder vertraulich zugestellt wird, hängt trotzdem von anderen Regeln ab.

Der Vergleich erklärt den erweiterten Adressraum. Seine Grenze: IPv6 ändert auch technische Protokolldetails. Man kann nicht einfach längere Nummern in jedes IPv4-Programm einsetzen. Zudem erhält nicht automatisch jedes Gerät eine einzige unveränderliche Adresse, nur weil der Vorrat größer ist.

## 4. Wie funktioniert das?

Die vollständige hexadezimale Schreibweise besteht aus acht Gruppen mit jeweils 16 Bit. Führende Nullen einer Gruppe können entfallen. Eine zusammenhängende Folge von Nullgruppen kann einmal durch `::` verkürzt werden. Die [Adressarchitektur in RFC 4291](https://www.rfc-editor.org/rfc/rfc4291.html) beschreibt diese Formen und unterschiedliche Adressarten.

Für einheitliche Ausgaben empfiehlt [RFC 5952](https://www.rfc-editor.org/rfc/rfc5952.html) eine kanonische Schreibweise, etwa Kleinbuchstaben und bestimmte Verkürzungsregeln. Unterschiedlich geschriebene gültige Texte können dieselbe Adresse meinen. Ein reiner Zeichenkettenvergleich kann deshalb für eine Adressprüfung ungeeignet sein.

IPv6 unterscheidet unter anderem Unicast und Multicast. Die IPv4-Vorstellung eines Broadcasts wird nicht unverändert übernommen: RFC 4291 beschreibt ausdrücklich, dass IPv6 keine Broadcast-Adressen verwendet. Details einer konkreten Anwendung müssen zum passenden Modell passen.

## 5. Wo begegnet mir das unter Linux?

Ein Linux-System kann gleichzeitig IPv4- und IPv6-Adressen besitzen. Programme können je nach Einrichtung eine der beiden Versionen nutzen. Erfolgreiche IPv4-Kommunikation beweist deshalb nicht automatisch, dass auch der IPv6-Weg funktioniert.

Auch der Gültigkeitsbereich einer Adresse ist wichtig. Eine für einen lokalen Zusammenhang gedachte Adresse ist nicht automatisch ein weltweit erreichbares Ziel. Dieser Eintrag fragt keine realen Schnittstellen ab und verändert weder Adressen noch Weiterleitungsregeln.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Es bearbeitet ausschließlich selbst gewählte Adresszeichenketten und baut keine Verbindung auf.

```python
import ipaddress

kurz = ipaddress.IPv6Address("2001:db8::1")
lang = ipaddress.IPv6Address("2001:0db8:0000:0000:0000:0000:0000:0001")
assert kurz == lang
assert len(kurz.packed) == 16
assert kurz.max_prefixlen == 128
ungueltig = False
try:
    ipaddress.IPv6Address("2001::db8::1")
except ipaddress.AddressValueError:
    ungueltig = True
assert ungueltig
print(kurz)
print(kurz.max_prefixlen)
print("Doppelte Verkürzung zurückgewiesen:", ungueltig)
```

Geprüfte Ausgabe:

```text
2001:db8::1
128
Doppelte Verkürzung zurückgewiesen: True
```

Der Versuch prüft gleichwertige Schreibweisen, die 16 Byte lange Darstellung und eine unzulässige doppelte Verkürzung. Er beweist keine reale Zuteilung oder Erreichbarkeit. Ein passendes Adressobjekt ist zunächst nur ein korrekt verarbeiteter Wert.

## 7. Abgrenzung zu ähnlichen Begriffen

IPv4 verwendet ein anderes Adress- und Paketformat. Ein Netzpräfix beschreibt einen Adressbereich, nicht einen einzelnen Dienst. Ein Rechnername kann zu mehreren Adressen führen. IPv6 ist außerdem nicht gleichbedeutend mit Verschlüsselung; zusätzliche Sicherheitsverfahren haben eigene Aufgaben.

## 8. Häufige Missverständnisse

`::` darf in einer normalen Adresse nicht beliebig mehrfach eingesetzt werden. Die Anzahl sichtbarer Zeichen entspricht wegen der Verkürzung nicht der Bitlänge. Eine syntaktisch gültige Adresse bedeutet auch nicht, dass das gewünschte Programm dort lauscht oder ein Zugriff erlaubt ist.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Verwende zum Vergleichen und Prüfen geeignete Adressfunktionen. Nenne bei einer Diagnose Protokollversion und gewünschten Dienst. Kopiere keine Dokumentationsadresse in eine reale Netzkonfiguration. Die Beispielprüfung sendet keine Pakete und verändert kein Gerät.

## 10. Verwandte Begriffe

Die [IP-Adresse](it_0139.md) erklärt die allgemeine Zuordnung. [IPv4](it_0140.md) ist die andere verbreitete Version. Ein [Socket](it_0129.md) ermöglicht den programmgesteuerten Austausch. Das [Netzwerk](it_0138.md) stellt den jeweiligen Kommunikationszusammenhang bereit.

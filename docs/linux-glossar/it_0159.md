# Firewall

## 1. Kurzbeschreibung

Eine Firewall setzt Regeln für zulässigen Netzwerkverkehr um. Sie kann beispielsweise bestimmte Zugriffe erlauben, verwerfen oder zurückweisen. Welche Angaben ausgewertet werden, hängt vom System ab. Eine Firewall ersetzt weder sichere Anwendungen noch passende Anmeldung oder Verschlüsselung. Ihre Wirkung muss im Zusammenhang der tatsächlich geltenden Regeln betrachtet werden.

## 2. Was bedeutet der Begriff?

Der Name erinnert an eine Brandschutzwand, technisch geht es jedoch um kontrollierte Kommunikationswege. Regeln können etwa Adressen, Protokolle, Transportports, Richtung und Verbindungszustand berücksichtigen. Nicht jeder Verkehr besitzt überhaupt TCP- oder UDP-Ports; ICMP ist ein anderes Beispiel.

Ein konkretes Linux-Werkzeug ist firewalld. Die [offizielle Konzeptbeschreibung](https://firewalld.org/documentation/concepts.html) erklärt eine zustandsbehaftete, zonenbasierte Firewall und Richtlinien zwischen Bereichen. Das ist ein Implementierungsmodell, keine Behauptung, dass jede Firewall dieselben Zonen und Voreinstellungen verwendet.

## 3. Einfacher Vergleich aus dem Alltag

Eine Zugangskontrolle lässt bestimmte Lieferungen durch festgelegte Eingänge zu. Dabei können Herkunft, Ziel und Art der Lieferung eine Rolle spielen. Ein erlaubter Durchgang bedeutet aber nicht automatisch, dass der Inhalt jeder Kiste unbedenklich ist.

So erklärt der Vergleich die Auswahl von Verkehr. Die Grenze: Die technische Entscheidung folgt konfigurierten Merkmalen, nicht menschlicher Beurteilung. Verschlüsselte Inhalte sind außerdem nicht allein deshalb vollständig verständlich für eine gewöhnliche Paketregel. Eine offene Passage und eine sichere Anwendungsfunktion bleiben unterschiedliche Fragen.

## 4. Wie funktioniert das?

Verkehr wird an vorgesehenen Verarbeitungspunkten gegen passende Regeln geprüft. Unter Linux beschreibt die [nftables-Dokumentation der Netfilter-Hooks](https://wiki.nftables.org/wiki-nftables/index.php/Netfilter_hooks) unterschiedliche Wege: Eingaben für das lokale System, lokal erzeugte Ausgaben und weitergeleitete Pakete durchlaufen nicht einfach dieselbe einzige Prüfung.

Auch Reihenfolge und Verknüpfung der Regeln sind wichtig. Aus einer isoliert gelesenen Erlaubnis folgt nicht automatisch, dass alle anderen Verarbeitungsschritte ebenfalls zulassen. Zustandsbehaftete Filterung kann zusammengehörige Kommunikation berücksichtigen. Ein als zugehörig erkannter Rückverkehr ist aber keine allgemeine Identitätsprüfung eines Benutzers.

## 5. Wo begegnet mir das unter Linux?

Ein Rechner kann selbst filtern oder hinter einer weiteren Firewall liegen. Ein Heimrouter kann solche Funktionen zusätzlich zum Routing anbieten. Bei einem Zugriff können daher mehrere Regelwerke beteiligt sein.

Das Katalogbeispiel einer Sperre eingehender Ports ist ein häufiger Fall. „Eingehend“ muss allerdings zum betrachteten System und Weg passen. Ein Paket, das ein Linux-Router nur weiterleitet, ist nicht automatisch eine lokale Eingabe für eine Anwendung dieses Routers. Die Unterscheidung ist für Fehlersuche und Regelverständnis entscheidend.

## 6. Konkretes Beispiel Schritt für Schritt

Diese Tabelle beschreibt eine erfundene Richtlinie. Sie enthält keine ausführbaren Firewallbefehle und wurde nicht auf ein System angewendet.

| Verkehr | Fiktive Entscheidung | Betrachteter Bereich |
| --- | --- | --- |
| Neue TCP-Anfrage an lokalen Port 443 | Erlauben | Lokale Eingabe |
| Neue TCP-Anfrage an lokalen Port 22 | Verwerfen | Lokale Eingabe |
| Paket zu einem anderen Netz | Gesondert entscheiden | Weiterleitung |

Die Erlaubnis für Port 443 startet keinen Webserver. Eine passende Anwendung müsste vorhanden sein und am gewünschten Endpunkt arbeiten. Ebenso sagt die zweite Zeile nichts über jeden denkbaren ausgehenden SSH-Zugriff aus; Richtung und Kontext sind anders.

Die Weiterleitungszeile verhindert die falsche Annahme, alle auf einer Schnittstelle empfangenen Pakete hätten denselben Zweck. Ein reales Regelwerk müsste deutlich mehr Bedingungen und den vorgesehenen Rückverkehr berücksichtigen. Die Tabelle behauptet keine derzeitige Schutzwirkung dieses Rechners.

## 7. Abgrenzung zu ähnlichen Begriffen

Routing wählt einen Weiterleitungsweg. NAT verändert bestimmte Adress- oder Portangaben. Eine Firewall entscheidet über zulässigen Verkehr. Ein Programm kann trotz erlaubter Netzpassage eine Anmeldung verweigern. Dieselbe Software oder Hardware kann mehrere Funktionen bereitstellen, ohne dass ihre Bedeutungen identisch werden.

## 8. Häufige Missverständnisse

Eine Portfreigabe garantiert keinen erreichbaren Dienst. Ein blockierter Test beweist nicht allein, welche Firewall ihn verhindert hat. Auch schützt ein Regelwerk nicht automatisch vor jeder schädlichen Aktion innerhalb erlaubter Kommunikation. Das pauschale Abschalten aller Filter ist deshalb keine gezielte Erklärung eines Fehlers.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Bestimme Ziel, Protokoll, Richtung und betroffenen Verarbeitungspfad. Prüfe geplante Änderungen auf ihre Reichweite, besonders bei einem entfernten Zugang. Dieser Eintrag lädt keine Regeln, fragt keinen Systemstatus ab und verändert weder Dienste noch Freigaben oder Schnittstellen.

## 10. Verwandte Begriffe

Der [Router](it_0151.md) übernimmt Weiterleitung. Ein [Port](it_0142.md) ist ein mögliches Filtermerkmal. [TCP](it_0143.md) und [UDP](it_0144.md) sind unterschiedliche Transportkontexte. [HTTPS](it_0146.md) ergänzt Verbindungsschutz und ersetzt nicht die gesamte Zugriffskontrolle.

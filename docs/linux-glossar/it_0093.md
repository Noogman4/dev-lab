# Decorator

## 1. Kurzbeschreibung

Ein Decorator verarbeitet in Python eine Funktion oder Klasse und liefert das Objekt zurück, das anschließend unter ihrem Namen verwendet wird. Oft ergänzt er Verhalten, etwa eine Aufrufprotokollierung. Er muss aber weder zusätzliche Arbeit ausführen noch eine gewöhnliche Funktion zurückgeben. Das Zeichen `@` macht diese Verarbeitung an der Definition sichtbar.

## 2. Was bedeutet der Begriff?

Die Quellbeschreibung „Eine Funktion, die eine andere Funktion erweitert“ beschreibt einen verbreiteten Fall. Genauer ist ein Decorator ein aufrufbares Objekt, das auf das definierte Objekt angewendet wird. Bei `@dekorieren` vor einer Funktionsdefinition wird deren Name an das Ergebnis von `dekorieren(funktion)` gebunden. Die Python-Referenz erklärt diese Ersetzung und die Reihenfolge mehrerer Decorators unter [Funktionsdefinitionen](https://docs.python.org/3.13/reference/compound_stmts.html#function-definitions).

Die Verarbeitung geschieht beim Ausführen der Definition, beispielsweise während eines Imports. Davon zu unterscheiden ist zusätzliche Arbeit beim späteren Funktionsaufruf: Diese entsteht erst, wenn das zurückgegebene Objekt sie tatsächlich ausführt. Ein Decorator kann ebenso nur eine Funktion registrieren und unverändert zurückgeben.

## 3. Einfacher Vergleich aus dem Alltag

Eine Eingangstür bekommt einen Zähler vorgeschaltet. Menschen benutzen weiterhin denselben Eingang, doch jeder Durchgang wird zusätzlich gezählt. Die eigentliche Tür muss dazu nicht umgebaut werden.

Das entspricht einem häufigen Decorator mit einer umschließenden Funktion. Der Vergleich endet dort, wo Python einen Namen neu bindet: Es wird nicht zwingend das ursprüngliche Funktionsobjekt verändert. Manche Decorators liefern außerdem Objekte mit ganz anderen Eigenschaften zurück, die kein vorgeschalteter Zähler erklärt.

## 4. Wie funktioniert das?

Ein typischer Aufbau hat zwei Funktionen. Die äußere erhält die ursprüngliche Funktion. Die innere nimmt deren Aufruf entgegen, erledigt Zusatzarbeit und ruft das Original auf. Die äußere gibt diese innere Funktion zurück. Argumente und Rückgabewerte sollten dabei bewusst weitergegeben werden.

`functools.wraps` übernimmt unter anderem Namen und Dokumentation vom Original auf die umschließende Funktion und hinterlegt einen Verweis auf das Original. Das erleichtert Fehlersuche und Werkzeuge zur Untersuchung von Funktionen; beschrieben ist dies bei [wraps](https://docs.python.org/3.13/library/functools.html#functools.wraps). Es beseitigt keine Fehler im eigenen Decorator.

## 5. Wo begegnet mir das unter Linux?

Python-Projekte verwenden Decorators etwa für Zwischenspeicherung oder zur Registrierung von Funktionen. Das ist eine Eigenschaft des Python-Codes, keine besondere Linux-Funktion.

Das Quellbeispiel `@staticmethod` ist ebenfalls gültig. Es kennzeichnet innerhalb einer Klasse eine Methode, die kein automatisch übergebenes erstes Instanzargument erhält. Diese Bedeutung erklärt die offizielle [staticmethod-Referenz](https://docs.python.org/3.13/library/functions.html#staticmethod). Daraus folgt keine Beschleunigung und keine parallele Ausführung.

## 6. Konkretes Beispiel Schritt für Schritt

Dieses vollständige Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Es sammelt ausschließlich selbst erzeugte Funktionsnamen in einer Liste.

```python
from functools import wraps

aufrufe = []


def merken(funktion):
    @wraps(funktion)
    def huelle(*args, **kwargs):
        aufrufe.append(funktion.__name__)
        return funktion(*args, **kwargs)

    return huelle


@merken
def verdoppeln(zahl):
    return zahl * 2


assert aufrufe == []
assert verdoppeln(4) == 8
assert verdoppeln(zahl=0) == 0
assert verdoppeln.__name__ == "verdoppeln"
assert aufrufe == ["verdoppeln", "verdoppeln"]
print(aufrufe)
```

Geprüfte Ausgabe:

```text
['verdoppeln', 'verdoppeln']
```

Nach der Definition ist die Liste noch leer: Der Decorator hat die Hülle erzeugt, aber keinen Aufruf gezählt. Erst die beiden Aufrufe ergänzen Einträge. Die Assertions prüfen außerdem Rückgabewerte, ein benanntes Argument und den erhaltenen Funktionsnamen. Klassen und mehrere gestapelte Decorators werden hier nicht praktisch getestet.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine gewöhnliche Hilfsfunktion wird ausdrücklich aufgerufen. Die Decorator-Schreibweise setzt dagegen bereits an einer Definition an. Eine dekorierte Funktion kann anschließend wie gewohnt aufgerufen werden, sofern das zurückgegebene Objekt dies unterstützt. Vererbung ist ein anderer Mechanismus zur Gestaltung von Klassen und nicht erforderlich, um eine Funktion zu dekorieren.

## 8. Häufige Missverständnisse

`@` bedeutet nicht automatisch „vor jedem Aufruf ausführen“. Diese Wirkung muss die Implementierung herstellen. Ein fehlendes `return` in der Hülle kann den ursprünglichen Rückgabewert versehentlich durch `None` ersetzen. Mehrere Decorators lassen sich außerdem nicht beliebig vertauschen: Ihre Reihenfolge kann das Ergebnis verändern.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lies zuerst die Dokumentation eines fremden Decorators. Prüfe, ob Argumente, Fehler und Rückgabewerte erhalten bleiben oder absichtlich verändert werden. Protokollierungen sollten keine Passwörter oder andere vertrauliche Argumente sammeln. Für den Einstieg ist eine kleine, überprüfbare Zusatzfunktion leichter zu verstehen als mehrere ineinander verschachtelte Veränderungen.

## 10. Verwandte Begriffe

Eine [Funktion](it_0017.md) ist hier das bearbeitete Objekt und zugleich der häufigste Baustein des Decorators. Beim [Import](it_0088.md) können Definitionen und damit Decorators ausgeführt werden. Eine [Exception](it_0091.md) kann aus Original oder Hülle stammen; diese Unterscheidung hilft bei der Fehlersuche.

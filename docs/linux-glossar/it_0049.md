# Index

## 1. Kurzbeschreibung

Index kann eine Position innerhalb einer Folge oder eine zusätzliche Suchstruktur bezeichnen. Die Quelle nennt beide Bedeutungen. Bei einer Python-Liste steht Index null für das erste Element. Ein Datenbankindex unterstützt dagegen das Auffinden bestimmter Datensätze und ist keine laufende Positionsnummer derselben Art.

## 2. Was bedeutet der Begriff?

Ein Positionsindex beantwortet „Welches Element steht hier?“. Er muss zum gültigen Bereich der Folge passen. Das [Python-Handbuch zu Folgeoperationen](https://docs.python.org/3.13/library/stdtypes.html#common-sequence-operations) beschreibt den Ursprung bei null sowie Zugriffe und Ausschnitte. Eine angezeigte laufende Nummer ab eins kann davon abweichen.

Ein Suchindex beantwortet eine andere Frage: „Wie lassen sich passende Daten finden, ohne jedes Mal alle Einträge auf dieselbe Weise zu durchsuchen?“ Welche Werte er erfasst und welche Abfragen profitieren, hängt vom Aufbau und den Abfragen ab. Das Wort allein legt keine konkrete Datenstruktur fest.

## 3. Einfacher Vergleich aus dem Alltag

Die Seitenzahl eines Buchs bezeichnet eine Position. Das Stichwortverzeichnis ordnet dagegen Suchbegriffe den passenden Seiten zu. Beide erleichtern Orientierung, besitzen aber unterschiedliche Aufgaben.

Die Grenze des Vergleichs: Python-Indizes müssen nicht der aufgedruckten Zählweise eines Buchs entsprechen. Ein technischer Suchindex kann zudem automatisch aktualisiert werden und zusätzliche Kosten verursachen. Ein veraltetes Verzeichnis zeigt anschaulich das Problem, ist aber kein vollständiges Modell einer Datenbank.

## 4. Wie funktioniert das?

Eine Liste ordnet Elementen Positionen zu. Werden Elemente eingefügt oder entfernt, können sich spätere Positionen ändern. Eine Position eignet sich deshalb nicht automatisch als dauerhafte fachliche Kennung.

SQLite kann zusätzliche Indizes über Tabellenspalten oder Ausdrücke anlegen. Die [CREATE-INDEX-Dokumentation](https://www.sqlite.org/lang_createindex.html) beschreibt diese Zuordnung. Der Abfrageplaner entscheidet anhand der Abfrage und verfügbaren Informationen über geeignete Zugriffswege; die [offizielle Einführung zur Abfrageplanung](https://www.sqlite.org/queryplanner.html) erläutert ihre Wirkung. Ein vorhandener Index garantiert nicht, dass jede Abfrage schneller wird oder ihn überhaupt verwendet.

## 5. Wo begegnet mir das unter Linux?

Python-Skripte greifen über Indizes auf Listen oder Strings zu. Programme mit SQLite können Suchindizes verwenden. Suchdienste können außerdem eigene aufbereitete Verzeichnisse aus Dateiinhalten erstellen. Diese Beispiele sind verwandt, aber keine einheitliche Betriebssystemschnittstelle.

Ein Glossarindex wie dieses Projektverzeichnis ordnet Kennungen Dokumenten zu. Seine Aufgabe ist eine nachvollziehbare Zuordnung. Daraus folgt nicht, dass er dieselbe interne Arbeitsweise wie ein SQLite-Index besitzt oder eine bestimmte Suchgeschwindigkeit garantiert.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel prüft eine Listenposition und einen eigenen SQLite-Index ausschließlich im Speicher:

```python
from contextlib import closing
import sqlite3

werte = [10, 20, 30]
assert werte[1] == 20
with closing(sqlite3.connect(":memory:")) as db:
    db.execute("CREATE TABLE probe (wert INTEGER)")
    db.executemany("INSERT INTO probe VALUES (?)", [(10,), (20,), (30,)])
    db.execute("CREATE INDEX idx_wert ON probe(wert)")
    namen = [zeile[1] for zeile in db.execute("PRAGMA index_list(probe)")]
    assert "idx_wert" in namen
    treffer = db.execute("SELECT wert FROM probe WHERE wert = ?", (20,)).fetchall()
    assert treffer == [(20,)]
    print(werte[1])
    print(treffer)
```

Die Ausgabe lautet:

```text
20
[(20,)]
```

Die Listenposition eins liefert das zweite Element. In der getrennten Datenbank wird der Index tatsächlich angelegt und sein Vorhandensein geprüft. Die Anfrage liefert den erwarteten Datensatz. Eine Beschleunigung oder bestimmte Abfrageplanung wurde damit nicht gemessen.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Schlüssel identifiziert einen Eintrag gemäß einer Zuordnungsregel. Ein Positionsindex beschreibt einen Platz. Ein Suchindex unterstützt Zugriffe. Eine laufende Bildschirmnummer kann bloß eine Darstellungshilfe sein. Diese Rollen können zusammenhängen, sollten aber nicht ungeprüft vertauscht werden.

## 8. Häufige Missverständnisse

Die erste Python-Listenposition ist null, nicht eins. Ein Index bleibt nach Strukturänderungen nicht zwangsläufig beim selben Element. Mehr Datenbankindizes sind nicht automatisch besser: Sie benötigen Platz und müssen bei betroffenen Änderungen gepflegt werden. Ohne ausdrückliche Sortierregel ist auch eine Datenbankausgabe nicht durch Indexnamen festgelegt.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Prüfe gültige Positionsbereiche und verwende dauerhafte Kennungen für dauerhafte Beziehungen. Bewerte Suchindizes anhand echter Anforderungen. Das Beispiel legt keine Datenbankdatei an und verändert keine bestehenden Bestände; es führt keinen Leistungsbenchmark durch.

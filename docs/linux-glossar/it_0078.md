# Callback

## 1. Kurzbeschreibung

Ein Callback ist ein aufrufbarer Baustein, der anderem Code übergeben wird, damit dieser ihn zu einem vorgesehenen Anlass aufrufen kann. Die Quelle nennt eine Reaktion auf einen Buttonklick. Das ist passend, aber nicht die einzige Verwendung: Ein Callback kann auch unmittelbar während eines Funktionsaufrufs laufen und muss weder asynchron noch in einem anderen Thread ausgeführt werden.

## 2. Was bedeutet der Begriff?

Statt ein Verhalten fest einzubauen, nimmt eine Schnittstelle eine passende Reaktion entgegen. Der verarbeitende Code entscheidet nach seinem Vertrag, wann und mit welchen Angaben sie aufgerufen wird. Die übergebende Seite stellt das gewünschte Verhalten bereit.

Das [offizielle Python-Glossar zu Callbacks](https://docs.python.org/3.13/glossary.html#term-callback) beschreibt diese Rolle. In Python kommen neben gewöhnlichen Funktionen auch geeignete Methoden und andere aufrufbare Objekte infrage. Entscheidend ist, dass die Aufrufschnittstelle zu den erwarteten Argumenten und Ergebnissen passt.

## 3. Einfacher Vergleich aus dem Alltag

Du hinterlegst eine Anweisung, wen eine Stelle bei einem bestimmten Ergebnis benachrichtigen soll. Die Stelle muss dann nicht für jeden Auftrag selbst festlegen, was die empfangende Person damit tut.

Die Grenze des Vergleichs: „Rückruf“ bedeutet in Software nicht zwingend einen späteren separaten Vorgang. Der Callback kann noch vor der Rückkehr aus dem aktuellen Aufruf laufen. Auch benötigt die Reaktion die genau vereinbarten Eingaben; ein menschliches Nachfragen ist keine automatische Eigenschaft der Schnittstelle.

## 4. Wie funktioniert das?

Eine Funktion oder Methode wird als Wert weitergegeben, statt sofort ausgeführt zu werden. Die aufrufende Bibliothek oder eigene Verarbeitung verwendet diesen Wert anschließend nach den festgelegten Regeln. Eine Klammer an der falschen Stelle kann stattdessen bereits beim Einrichten die Funktion ausführen und nur deren Ergebnis weiterreichen.

Bei Tkinter-Bindings wird für passende Ereignisse eine Funktion mit einem Event-Objekt aufgerufen. Die [offizielle Bindings-Erklärung](https://docs.python.org/3.13/library/tkinter.html#bindings-and-events) beschreibt diese Konvention. Andere Callback-Schnittstellen können dagegen keine, andere oder mehrere Argumente übergeben. Es gibt keine universelle Callback-Signatur.

Fehler und Rückgabewerte brauchen ebenfalls klare Regeln. Eine Ausnahme kann weitergegeben oder vom Rahmenwerk behandelt werden. Der erwartete Rückgabewert kann relevant sein oder ignoriert werden. Das muss aus dem konkreten Vertrag hervorgehen.

## 5. Wo begegnet mir das unter Linux?

Python-Oberflächen verwenden Callbacks für Aktionen. Bibliotheken können sie außerdem für Ergebnisse oder anpassbare Verarbeitung annehmen. Die Schnittstelle kann dabei festlegen, in welchem Ausführungskontext die Reaktion läuft.

Ein Callback für eine echte Systemaktion besitzt dieselben möglichen Nebenwirkungen wie anderer Code. Seine Übergabe macht ihn nicht automatisch harmlos oder nebenläufig. Bei GUI-Code muss zudem geklärt sein, welche Oberflächenzugriffe im betreffenden Kontext erlaubt sind.

## 6. Konkretes Beispiel Schritt für Schritt

Das vollständige Python-3-Beispiel führt einen eigenen Callback bewusst unmittelbar und ohne GUI aus:

```python
def verarbeiten(text, bei_ergebnis):
    bereinigt = text.strip()
    return bei_ergebnis(bereinigt)

gesammelt = []
handler = gesammelt.append
assert gesammelt == []
rueckgabe = verarbeiten(" Beispiel ", handler)
assert gesammelt == ["Beispiel"]
assert rueckgabe is None
print(gesammelt)
```

Die Ausgabe lautet:

```text
['Beispiel']
```

Zuerst wird die gebundene Listenmethode gespeichert, ohne sie aufzurufen. Die Verarbeitung bereinigt den Text und ruft anschließend den übergebenen Handler mit einem Argument auf. Noch vor ihrer Rückkehr enthält die Liste das Ergebnis. `append` liefert hier `None`; das ist ein Merkmal dieses gewählten Callbacks.

## 7. Abgrenzung zu ähnlichen Begriffen

Ein Event ist ein möglicher Anlass. Eine Event Loop kann den Aufruf organisieren. Eine Funktion ist ein möglicher technischer Baustein. Callback bezeichnet dessen Rolle als weitergegebenes Verhalten. Ein bloß gespeicherter Name ist noch keine ausgeführte Reaktion.

## 8. Häufige Missverständnisse

Callbacks laufen nicht automatisch später oder parallel. Gleiche Namen garantieren keine passende Signatur. Das Übergeben eines Aufrufergebnisses ist nicht dasselbe wie das Übergeben der Funktion. Auch sagt die Registrierung allein nichts darüber aus, ob der vorgesehene Anlass jemals eintritt.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Lies Zeitpunkt, Argumente, Ergebnis und Fehlerregeln der Schnittstelle. Vermeide unnötige Annahmen über Threads oder Reihenfolge. Das Beispiel prüft nur einen unmittelbaren eigenen Callback mit Textdaten; GUI-Ereignisse und Hintergrundverarbeitung wurden dafür nicht ausgeführt.

# Generator

## 1. Kurzbeschreibung

Ein Generator liefert Werte schrittweise, sobald sie angefordert werden. In Python bezeichnet das Wort je nach Zusammenhang die Generatorfunktion oder das von ihr erzeugte Generatorobjekt. Ein solches Objekt merkt sich seinen Ausführungsstand zwischen den gelieferten Werten. Das ist nützlich, wenn Ergebnisse nacheinander verarbeitet werden sollen.

## 2. Was bedeutet der Begriff?

Eine Generatorfunktion sieht einer gewöhnlichen Funktion ähnlich, enthält in ihrem Funktionskörper jedoch `yield`. Ihr Aufruf liefert zunächst ein Generatorobjekt. Erst die Anforderung eines Wertes startet beziehungsweise setzt dessen Arbeit fort. Das offizielle [Python-Glossar](https://docs.python.org/3.13/glossary.html#term-generator) unterscheidet ausdrücklich Generatorfunktion und Generatoriterator, also das schrittweise durchlaufbare Ergebnisobjekt.

Die Quellbeschreibung konzentriert sich auf die Funktion. Für das Verständnis ist die Trennung wichtig: Die Funktion beschreibt die Herstellung; ein konkretes Generatorobjekt besitzt den gerade erreichten Zustand. Zwei Aufrufe derselben Generatorfunktion erzeugen voneinander getrennte Abläufe.

## 3. Einfacher Vergleich aus dem Alltag

Eine Bäckerei reicht dir Gebäckstücke einzeln über die Theke. Du forderst das nächste Stück an, statt sofort ein ganzes Tablett entgegenzunehmen. Zwischen den Anforderungen ist bekannt, welches Stück als Nächstes ansteht.

Anders als die Bäckerei arbeitet ein gewöhnlicher Python-Generator dabei nicht automatisch im Hintergrund weiter. Solange niemand den nächsten Wert anfordert, bleibt seine Ausführung an der Unterbrechungsstelle stehen. Auch eine unbegrenzte Vorratsmenge verspricht der Vergleich nicht: Ein Generator kann nach wenigen Werten enden.

## 4. Wie funktioniert das?

`next(objekt)` fordert den nächsten Wert an. Bei `yield wert` liefert der Generator diesen Wert nach außen und unterbricht seinen Ablauf. Lokale Variablen und die aktuelle Position bleiben erhalten. Beim nächsten Anfordern geht es hinter dieser Stelle weiter. Die genaue Semantik beschreibt die Referenz zu [yield-Ausdrücken](https://docs.python.org/3.13/reference/expressions.html#yield-expressions).

Erreicht die Generatorfunktion ihr Ende, signalisiert das Objekt Erschöpfung mit `StopIteration`. Eine `for`-Schleife behandelt dieses normale Ende selbst. Bei `next(objekt, ersatz)` erhält man stattdessen den angegebenen Ersatz, wenn kein Wert mehr vorhanden ist. Ein bereits erschöpftes Objekt beginnt nicht wieder von vorn.

## 5. Wo begegnet mir das unter Linux?

Python-Werkzeuge können Ergebnisse einer Auswertung stückweise weiterreichen, beispielsweise ausgewählte Zeilen aus einem Text oder berechnete Messwerte. Die nachfolgende Verarbeitung muss dann nicht auf eine vollständig aufgebaute Ergebnisliste warten.

Das spart jedoch nur den Speicher, den die konkrete Implementierung tatsächlich vermeidet. Wenn ein Generator intern zunächst eine riesige Liste erstellt, verschwindet diese nicht durch `yield`. Das Prinzip ist nicht an Linux gebunden und bedeutet weder einen eigenen Betriebssystemprozess noch einen separaten Ausführungsfaden.

## 6. Konkretes Beispiel Schritt für Schritt

Das folgende Beispiel wurde mit Python 3.13 in einem temporären Ordner ausgeführt. Es verwendet nur drei selbst gewählte Zahlen. Eine Hilfsliste macht sichtbar, wann die Berechnung tatsächlich stattfindet.

```python
berechnet = []


def quadrate():
    for zahl in (2, 3, 4):
        berechnet.append(zahl)
        yield zahl * zahl


werte = quadrate()
assert berechnet == []
assert next(werte) == 4
assert berechnet == [2]
rest = list(werte)
assert rest == [9, 16]
assert berechnet == [2, 3, 4]
assert next(werte, "Ende") == "Ende"
assert list(werte) == []
print(rest)
print(next(werte, "Ende"))
```

Geprüfte Ausgabe:

```text
[9, 16]
Ende
```

Die erste Assertion belegt: Das Erzeugen des Objekts berechnet noch kein Quadrat. `next` verarbeitet zunächst nur die Zwei. `list` verbraucht danach die übrigen Werte; sie enthält deshalb nicht noch einmal die Vier. Die letzten Prüfungen zeigen, dass dasselbe Objekt erschöpft bleibt. Gleichzeitige Verarbeitung und große Dateien werden hier nicht getestet.

## 7. Abgrenzung zu ähnlichen Begriffen

Eine Liste hält ihre enthaltenen Werte bereit und kann gewöhnlich mehrfach durchlaufen werden. Ein Generatorobjekt liefert seine Folge einmal schrittweise. Nicht jeder Iterator ist ein Generator: Auch andere Objekte können die erforderliche Schnittstelle für das Durchlaufen anbieten. Ein Generatorausdruck erzeugt ebenfalls ein Generatorobjekt, benötigt aber keine eigene benannte Funktion mit `yield`.

## 8. Häufige Missverständnisse

Ein Generator ist nicht automatisch schneller. Die Aufteilung kann vor allem Speicherbedarf und Zeitpunkt der Arbeit verändern. Seine Werte sind außerdem nicht beliebig per Listenindex abrufbar. Wer ihn zur Kontrolle vollständig ausgibt, hat ihn dabei meist bereits verbraucht.

## 9. Praktische Hinweise und gegebenenfalls Risiken

Überlege, wer die Werte anfordert und ob ein zweiter Durchlauf benötigt wird. Für kleine, mehrfach verwendete Ergebnisse kann eine Liste übersichtlicher sein. Hält ein Generator offene Ressourcen wie Dateien, muss deren Lebensdauer bewusst geregelt werden; frühes Abbrechen einer Verarbeitung ist kein allgemeiner Ersatz für sauberes Schließen.

## 10. Verwandte Begriffe

Die [Funktion](it_0017.md) beschreibt den Ablauf. Eine [Schleife](it_0015.md) kann die gelieferten Werte verarbeiten. Eine [Exception](it_0091.md) kann während einer späteren Wertanforderung auftreten, also zeitlich nach dem Erzeugen des Generatorobjekts.
